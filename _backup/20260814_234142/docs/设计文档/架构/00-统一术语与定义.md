# 00 统一术语与定义

**唯一术语源：** 本文件  
**使用原则：** 其他规范不得为下列术语重新定义含义；如需新术语，按 [EXC-007](00-规范例外与变更管理.md#exc-007-新增术语) 登记。

## 1. 领域术语

| ID | 术语 | 唯一定义 | 不得误用为 |
|---|---|---|---|
| TERM-001 | Mod | 一个可被 RimWorld 加载的内容、代码、资源和元数据发布单元 | 单个 C# 类、单个 Def |
| TERM-002 | Mod ID | Mod 的稳定机器标识，贯穿 About、命名空间、资源和翻译 | 玩家显示名称 |
| TERM-003 | Def | 由 XML/数据库加载的静态内容定义 | 动态运行时状态 |
| TERM-004 | DefName | Def 的稳定机器 ID，在项目范围内唯一 | label、翻译 Key |
| TERM-005 | DefOf | 对固定 Def 的类型安全引用集合 | 动态查询工具 |
| TERM-006 | DefModExtension | 附加在 Def 上的静态项目数据扩展 | 持久化运行时状态容器 |
| TERM-007 | Comp | 附加到具体对象/实例、负责运行时行为或状态的组合组件 | 全局服务、UI 控制器 |
| TERM-008 | Runtime State | 游戏运行期间可变的领域状态 | Def 配置、Save schema |
| TERM-009 | Save Data | 需要跨游戏会话恢复的稳定状态 | UI 缓存、Texture、Window |
| TERM-010 | Migration | 将旧 Save schema 安全转换为当前 schema 的显式过程 | 读取时随意修补数据 |
| TERM-011 | Domain | 与游戏规则和业务状态有关、独立于 UI 的逻辑边界 | UI 领域、第三方兼容目录 |
| TERM-012 | Core | 包含 Domain、Application Service、稳定 API 的核心模块集合 | 整个 Mod 的任意代码 |
| TERM-013 | Service | 提供一个明确用例或能力的无 UI 业务对象 | 任何叫 Manager 的类 |
| TERM-014 | Contract | 模块之间稳定、最小、可测试的接口或 DTO 约定 | 内部实现细节 |
| TERM-015 | Provider | 提供数据或能力的实现方 | 调用方的控制器 |
| TERM-016 | Adapter | 将外部 API/第三方模型转换为项目 Contract 的隔离层 | Core 中的兼容分支 |
| TERM-017 | Compatibility | 面向 Vanilla、DLC 或第三方 Mod 的适配模块 | Core 的条件分支 |
| TERM-018 | Patch | 对 XML 或运行时方法的最小、可追踪修改 | 完整复制目标 Def |
| TERM-019 | Harmony Patch | 通过 Harmony 改变运行时方法行为的适配动作 | XML 数据配置方式 |

## 2. 表现与本地化术语

| ID | 术语 | 唯一定义 |
|---|---|---|
| TERM-020 | Presentation | 将稳定数据与用户输入转为可见界面的模块，不拥有核心业务规则 |
| TERM-021 | Window | 负责生命周期、输入路由和顶层布局的 UI 容器 |
| TERM-022 | Panel | Window 内一个可独立渲染/验证的功能区域 |
| TERM-023 | UI Component | 可复用的 UI 行为或视觉单元；与 Data 层 Comp 通过上下文区分 |
| TERM-024 | UI State | 界面临时状态，如选中项、滚动位置、筛选条件 |
| TERM-025 | Theme | 语义化颜色、字体、间距、边框和控件样式集合 |
| TERM-026 | Skin | 对 Theme、Asset 或组件外观的可替换实现/配置 |
| TERM-027 | Asset | Texture、Sound、Material、Shader、图标等外部表现资源 |
| TERM-028 | Translation Key | Keyed 本地化使用的稳定字符串 ID |
| TERM-029 | DefInjected | 对已加载 Def 字段的语言覆盖数据 |
| TERM-030 | Fallback | 缺少目标翻译时按明确顺序返回可用文本的机制 |
| TERM-031 | Localization Isolation | 本 Mod 的 Key、DefInjected、默认值和扫描范围不会污染其他 Mod |

## 3. 工程与质量术语

| ID | 术语 | 唯一定义 |
|---|---|---|
| TERM-032 | Hardcoding | 将本应来自配置、Def、Contract 或资源的值直接散落在代码中 |
| TERM-033 | Magic Value | 无命名、无来源、无解释的数字、字符串、路径或时间常量 |
| TERM-034 | Gate | 对某一质量维度的可重复、可判定验收门槛 |
| TERM-035 | Evidence | 证明 Gate 结果的日志、测试报告、截图、指标或审查记录 |
| TERM-036 | Change Summary | 一次变更的范围、理由、风险、测试和迁移摘要 |
| TERM-037 | Release | 可被用户安装、识别、回滚和复核的版本交付物 |
| TERM-038 | Exception | 在限定范围和期限内批准的规范偏离 |
| TERM-039 | Deprecated | 保留兼容但不应继续使用的规则、API 或资源 |
| TERM-040 | Breaking Change | 破坏已有 Save、公共 Contract、依赖关系或用户行为的变更 |

## 4. 命名语义

同一后缀只表达一种职责：

```text
*Def          静态 Def/数据映射
*Extension    DefModExtension
*Comp         运行时组合组件
*Service      业务用例服务
*Provider     能力提供方
*Adapter      外部模型/第三方适配器
*Controller   输入或流程编排，不承载领域规则
*Window       顶层 UI 容器
*Panel        UI 功能区域
*ViewModel    UI 所需只读投影/交互状态
*Migration    Save schema 迁移器
*Patch        XML 或 Harmony 适配动作
```

`Manager`、`Helper`、`Utility` 不是默认架构职责；使用前必须能说明其单一职责，否则违反 [BASE-008](01-基础层规范.md#8-base-008-职责化命名) 与 [ARC-004](02-架构层-核心架构规范.md#4-arc-004-服务职责)。

## 5. 禁止混用

| 混用 | 正确区分 |
|---|---|
| “数据层”同时指 Def 和 Save | 使用 `Def`、`Runtime State`、`Save Data` |
| “组件”同时指 ThingComp 和 UI Component | 写全称或使用 `Data Comp` / `UI Component` |
| “翻译”同时指 DefInjected 和 Keyed | 明确写 `DefInjected` 或 `Translation Key` |
| “兼容”泛指所有功能 | 只有跨 Mod/DLC/版本适配才称 `Compatibility` |
| “配置”包含代码常量 | 区分 `Def Configuration`、`Mod Settings`、`Code Constant` |

## 6. 术语验收

```text
[ ] 文档和代码中的 Core/Presentation/Compatibility 含义一致
[ ] Def、Runtime State、Save Data 没有混写
[ ] Data Comp 与 UI Component 没有混写
[ ] Translation Key 与 DefName 没有复用为同一概念
[ ] 所有新名词都有归属模块和规则 ID
```
