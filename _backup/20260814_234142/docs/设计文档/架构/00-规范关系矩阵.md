# 00 规范关系矩阵

**规范地位：** [00-规范体系总纲.md](00-规范体系总纲.md) 的可执行依赖契约  
**核心目的：** 防止跨文件规则冲突、循环依赖和第三方 Mod 反向污染

## 1. 模块定义

术语必须来自 [00-统一术语与定义.md](00-统一术语与定义.md)，尤其是 `Core`、`Presentation`、`Compatibility`、`Contract`、`Provider`、`Adapter`、`Runtime State`、`Save Data`。

| 模块 | 负责 | 不负责 |
|---|---|---|
| Foundation | 公共类型、命名、日志、配置边界、基础工具 | 业务决策、UI、第三方细节 |
| Core | 领域模型、业务规则、稳定服务、公开契约 | UI、Theme、资源加载细节、第三方 Mod 判断 |
| Data & Extension | Def、DefOf、DefModExtension、Comp、配置装配 | UI 绘制、第三方内部状态 |
| Presentation | Window、Panel、ViewModel、输入、Theme、Skin、Asset 使用 | 改写业务规则、保存核心状态 |
| Localization | Translation Key、DefInjected、fallback、翻译审计 | 业务分支、动态状态管理 |
| Compatibility | 可选 Mod 检测、Adapter、条件 Patch、Harmony 边界 | 让 Core 依赖具体 Mod |
| Save & Migration | 持久化 schema、版本、迁移、降级保护 | UI 交互逻辑 |
| Testing & Diagnostics | 测试、验证、指标、诊断报告 | 为通过检查而修改运行时逻辑 |
| Release | 版本、变更摘要、发布包、回滚材料 | 直接改变未审查代码 |

## 3. 规则

### MATRIX-001 单向依赖

依赖方向必须从低层稳定契约流向高层实现；不得通过静态全局对象、反射或事件偷偷形成反向依赖。

### MATRIX-002 Core 纯净边界

Core 不得引用 UI、Theme、Texture、第三方 Mod 命名空间、兼容 Patch 类或 Harmony 目标类型。

### MATRIX-003 Presentation 只消费契约

UI 通过 Core API、Query、ViewModel 或只读数据 DTO 获取数据；不得直接改写 DefDatabase 或保存核心运行时状态。

### MATRIX-004 Compatibility 单向隔离

Compatibility 可以依赖 Core 公共契约，但 Core 不得出现 `if (TargetModLoaded)` 等目标 Mod 分支。

### MATRIX-005 Localization 无业务反向依赖

本地化只接收稳定 Key、参数和格式化数据；翻译结果不得被业务逻辑当作判断条件。

### MATRIX-006 Save 只序列化契约数据

Save 依赖稳定领域数据与 schema；不得序列化 Window、Texture、UI State、Def 的临时缓存或第三方对象引用。

### MATRIX-007 兼容 Patch 不改 Core 契约

为了适配单一 Mod，不得修改 Core 公共 API 的语义；需要扩展时新增可选能力或 Adapter。

### MATRIX-008 测试可观察而非可侵入

测试和诊断通过公开契约、模拟输入、日志与指标观察系统，不得仅为测试把内部字段公开为可变全局状态。

### MATRIX-009 资源路径隔离

Asset、Texture、Sound、Shader 路径必须使用 Mod 命名空间；Presentation 只能通过资源目录契约消费。

### MATRIX-010 循环依赖零容忍

项目图中不得出现 Core ↔ UI、Core ↔ Compatibility、Localization ↔ Domain 等循环。发现循环时先拆契约/端口，不得用 `static` 或事件逃避。

## 4. 跨文件责任归属

| 决策 | 唯一规范源 | 其他文件如何引用 |
|---|---|---|
| 优先级与冲突 | 总纲 | 引用 `GOV-004` |
| 名称与术语 | 术语/基础层 | 引用 `TERM-*`、`BASE-*` |
| 依赖边界 | 本文件/核心架构 | 引用 `MATRIX-*`、`ARC-*` |
| Def/Comp/Extension | 数据与扩展 | 引用 `DATA-*` |
| 第三方兼容/Harmony | 兼容与接入 | 引用 `COMP-*` |
| UI/Theme/Asset/Localization/Performance | 表现层 | 引用 `UI-*`、`LOC-*`、`ASSET-*`、`PERF-*` |
| Save/Migration | 数据与扩展 | 引用 `SAVE-*` |
| Test/Gate | 统一验收 | 引用 `TEST-*`、`GATE-*` |
| 版本/发布 | 变更日志与发布 | 引用 `REL-*` |
| AI 行为 | AI 开发 | 引用 `AI-*` |
| 例外与规则修改 | 例外与变更 | 引用 `EXC-*` |

## 5. Review 问题

```text
[ ] 新依赖是否出现在矩阵允许单元？
[ ] 是否存在隐式反向依赖或循环？
[ ] 是否把第三方判断放进 Core？
[ ] UI 是否直接改变领域状态或 Def？
[ ] Save 是否包含不可序列化对象？
[ ] Localization/Asset 是否拥有独立命名空间？
[ ] 是否需要新增 Contract、Provider 或 Adapter？
```
