# 01 基础层规范

**版本：** v3.0  
**定位：** 所有其他层必须遵守的最低工程约束  
**上位规范：** [00-规范体系总纲.md](00-规范体系总纲.md)  
**验收：** [GATE-ARCH](00-统一验收标准.md#2-gate-arch架构-gate)、[GATE-TEST](00-统一验收标准.md#8-gate-test测试-gate)

## 1. BASE-001 命名空间与唯一前缀

项目必须固定唯一的 Mod ID、C# Namespace、Def 前缀、Translation Key 前缀和 Asset 路径前缀：

```text
Mod ID:         com.example.mymod
C# Namespace:   MyMod
Def Prefix:     MyMod_
Key Prefix:     MyMod.
Asset Prefix:   MyMod/
```

禁止使用 `Archive`、`Settings`、`UI/Panel/` 等可能与其他 Mod 冲突的裸名称。

## 2. BASE-002 稳定 ID 与显示文本分离

程序逻辑只能依赖 DefName、内部 ID、枚举、Contract 或对象引用；不得读取 `label`、`LabelCap`、description、Translation Key 的结果进行逻辑判断。

```csharp
// 正确：
if (def == MyModDefOf.AdvancedRifle) { ... }

// 错误：
if (def.label == "Advanced Rifle") { ... }
```

## 3. BASE-003 用户可见文本必须本地化

代码 UI、消息、按钮、Tab、Tooltip、Letter、设置项和报告标题必须使用 Keyed Localization；Def 文本使用 DefInjected。中文或英文默认值不得成为另一种语言的隐式业务依赖。详细规则见 [LOC-001](05-表现层规范.md#loc-001-本地化命名空间)。

## 4. BASE-004 Def 唯一性与身份稳定

自定义 DefName 必须使用项目前缀。已经发布的 DefName 视为 Save 身份的一部分，不得直接重命名或删除；需要变更时遵循 [SAVE-005](03-架构层-数据与扩展规范.md#16-save-005-重命名删除与别名)。

## 5. BASE-005 文件、类、模块单一职责

禁止长期维护以下无界文件：

```text
AllDefs.xml / Everything.cs / HugeWindow.cs / GlobalManager.cs
```

一个文件可以包含同一职责的紧密类型，但不能同时承载业务规则、UI、Save、Localization、Harmony 和第三方兼容。拆分依据见 [ARC-003](02-架构层-核心架构规范.md#3-arc-003-核心模块职责)。

## 6. BASE-006 外部对象默认只读

Vanilla、DLC 和第三方 Def/对象默认只读。必须修改时，应进入 Compatibility 层，使用最小条件 Patch，并记录 [COMP-003](04-架构层-兼容与接入规范.md#3-comp-003-条件-patch-与最小范围)。

## 7. BASE-007 资源命名空间

```text
Textures/MyMod/UI/
Textures/MyMod/Icons/
Sounds/MyMod/
Materials/MyMod/
```

资源名称应表达用途和状态，如 `Panel_Normal`、`Panel_Hover`，不得用 `BluePanel2Final` 之类不可维护的临时名称。缺失资源必须有诊断和安全 fallback。

## 8. BASE-008 职责化命名

类名后缀必须对应 [00-统一术语与定义.md](00-统一术语与定义.md#4-命名语义) 的职责。`Manager`、`Helper`、`Utility` 不是默认设计；只有职责、输入输出和生命周期都明确时才可使用。

## 9. BASE-009 日志、诊断与错误分级

统一日志前缀和类别：

```text
[MyMod][Info]
[MyMod][Warning]
[MyMod][Error]
[MyMod][Compatibility]
[MyMod][Save]
[MyMod][Performance]
```

日志必须包含对象稳定 ID、操作上下文和可执行建议；禁止在 Tick 或每帧无界输出。外部 Provider 失败必须隔离并降级，不能使用空 `catch`。

## 10. BASE-010 硬编码治理

禁止散落：DefName、Translation Key、路径、颜色、布局尺寸、性能阈值、目标 Mod 标识、Save 版本号和业务常量。允许的常量必须：

```text
有命名
有来源
有单位/语义
有作用域
有变更策略
```

临时例外遵循 [EXC-004](00-规范例外与变更管理.md#exc-004-硬编码例外)。

## 11. BASE-011 编码与静态质量

```text
UTF-8
统一换行和缩进
XML 可解析
公开 API 有注释和版本语义
新增警告不得被忽略
```

提交前至少执行项目可用的编译、XML/Def 扫描、Translation 扫描和规则 ID 检查。

## 12. TEST-001 最小测试矩阵

每个可运行变更至少覆盖：

```text
Vanilla + MyMod
目标 DLC（如适用）
English / ChineseSimplified
新游戏 / 旧 Save（如涉及数据）
目标 Mod 缺失 / 存在（如涉及兼容）
```

高频逻辑、Provider、Migration 和 UI 关键路径需补针对性测试。证据格式由 [00-统一验收标准.md](00-统一验收标准.md#11-统一-gate-记录模板) 统一。

## 13. BASE-012 基础层验收

```text
[ ] 没有显示文本逻辑判断
[ ] 没有无界日志、无界缓存或空 catch
[ ] TEST-001 矩阵已执行
[ ] Changelog/Change Summary 已完成
```
