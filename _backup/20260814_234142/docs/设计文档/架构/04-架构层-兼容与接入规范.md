# 04 架构层：兼容与接入规范

**版本：** v3.0  
**定位：** Vanilla、DLC、第三方 Mod、可选依赖、条件 Patch、Harmony 与外部 Provider 的隔离接入层  
**上位规范：** [00-规范关系矩阵.md](00-规范关系矩阵.md)、[02-架构层-核心架构规范.md](02-架构层-核心架构规范.md)

## 1. COMP-001 兼容层隔离

推荐结构：

```text
Compatibility/
├── ModDetection/
├── Dlc/
├── ModA/
│   ├── Detection.cs
│   ├── Adapter.cs
│   └── Patches/
├── ModB/
└── Shared/
```

Core 只能看见本项目 Contract，不得出现目标 Mod 命名空间、程序集类型或 `TargetModLoaded` 条件分支。

## 2. COMP-002 依赖类型

| 类型 | 行为 | 适用场景 |
|---|---|---|
| 硬依赖 | 目标不存在则本 Mod 不应加载 | 功能本身无法独立存在 |
| 软依赖 | 目标不存在时基础功能仍可用 | 大多数第三方数据接入 |
| 能力探测 | 只检测能力/API/Def/Type | 版本差异或多种实现 |

About.xml 依赖声明不能被运行时 FindMod 替代；运行时条件也不能伪装成硬依赖。

## 3. COMP-003 条件 Patch 与最小范围

第三方 Patch 必须：

```text
检测目标存在/能力
→ 独立文件和目录
→ 精确目标 Def/方法
→ 最小字段/最小行为修改
→ 失败安全与日志
```

不得通过全量覆写 Def、全局替换 Translation Key 或修改目标 Mod 的通用 UI 资源实现“兼容”。

## 4. COMP-004 Harmony 升级条件

Harmony 只能用于无法通过以下方式完成的运行时行为：

```text
原生 XML / PatchOperations
DefModExtension
Comp / GameComponent
公开 API / 事件 / Provider Contract
```

必须登记 [EXC-002](00-规范例外与变更管理.md#exc-002-harmony-例外) 并提供 Patch 目标、原因、风险、替代方案、失败行为和回归证据。

## 5. COMP-005 Harmony Patch 类型与风险

默认风险顺序：

```text
Postfix → Prefix → Transpiler
```

Postfix 优先用于补充结果；Prefix 只有在必须提前校验/改变参数且不会无理由阻止原方法时使用；Transpiler 只有在前两者和原生机制都无法完成时使用。禁止无理由 `return false`。

## 6. COMP-006 第三方类型隔离

第三方类型只能出现在 Compatibility Adapter、检测器和局部 Patch 中。不得进入 Core Domain、公共 API、Save Data、Localization 逻辑或 UI 公共组件。Adapter 向项目 Contract 转换稳定数据后立即隔离外部类型。

## 7. COMP-007 第三方本地化隔离

本 Mod 不得修改其他 Mod 的 DefInjected、Keyed Key 或全局默认文本，除非它是明确登记、可回滚、最小范围的 Compatibility Patch。特别禁止为了本 Mod 的中文默认值而改写全局翻译环境。自己的 Key 必须使用自己的命名空间。

## 8. COMP-008 null、版本与初始化防御

外部对象默认可能：

```text
不存在 / null / 类型变化 / 字段缺失 / 初始化未完成 / API 不兼容
```

所有检测结果应缓存；热路径不得反射或重复扫描。异常应包含 Provider/Target/Operation 上下文。

## 9. COMP-009 兼容失败降级

```text
外部 Provider 失败
→ 记录一次结构化 Warning
→ 标记能力不可用
→ 使用内置 Provider/空结果/隐藏 Section
→ Core、Save 和其他 Provider 继续运行
```

禁止用空 `catch`、无界重试或让一个兼容模块阻止整个 Mod 启动。

## 10. COMP-010 兼容测试矩阵

至少覆盖：

```text
Vanilla + MyMod
MyMod + DLC
MyMod + TargetMod（目标存在）
MyMod - TargetMod（目标缺失）
English / ChineseSimplified
新游戏 / 旧 Save
Harmony 目标可解析 / 不可解析
目标 Mod 不同加载顺序（如适用）
```

兼容 UI 必须验证布局、翻译、滚动、空数据和异常降级；兼容数据必须验证 ID、去重、采样和 Save。

## 11. COMP-011 诊断与开关

兼容层应提供可关闭或可观测的能力开关（按项目实际实现），显示：目标是否发现、适配器版本、能力状态、最近一次失败及降级原因。诊断 UI 属于 Presentation，不得把诊断状态写入 Core Save。

## 12. COMP-012 兼容 Gate

```text
[ ] COMP-001–COMP-011 适用项通过
[ ] Core 无第三方直接依赖
[ ] 条件 Patch 可追踪、可回滚
[ ] Harmony 有 Exception 和回归证据
[ ] 缺失目标 Mod 不影响基础功能
[ ] 第三方本地化未被污染
[ ] 兼容测试矩阵完成
[ ] 通过 GATE-COMP
```
