# 05 表现层规范

**版本：** v3.0  
**定位：** UI 架构、交互、Theme、Skin、Asset、Localization 和表现性能  
**边界：** 表现层消费 Core/Data 的稳定数据，不拥有核心业务规则和持久状态

## 一、UI 架构与交互

### UI-001 UI State 与领域状态分离

```text
Core/Runtime State
        ↓ Query / Read Model
UI ViewModel / UI State
        ↓
Window / Panel / Component
```

UI State 只保存选中项、滚动位置、筛选条件、展开状态、输入草稿等临时状态；核心状态由 Domain/Application Service 管理，Save 数据由 Save 层管理。

禁止 Window 直接成为数据库、业务规则引擎或 Save 容器。

### UI-002 Window、Panel、Component 职责

```text
Window      生命周期、顶层布局、输入路由
Panel       一个可独立渲染/验证的区域
Component   可复用的绘制/交互单元
ViewModel   UI 所需的只读投影和交互状态
Renderer    将数据映射为视觉，不改变领域状态
```

推荐结构：

```text
ArchiveWindow
├── HeaderPanel
├── NavigationPanel
├── OverviewPanel
├── HistoryPanel
└── FooterPanel
```

### UI-003 UI 只读 Read Model

UI 优先消费 `ArchiveSectionSnapshot`、统计 DTO 或其他 Read Model。外部 Provider 不得返回 `Rect`、`GUIStyle` 或绘制回调；这样可以保持 UI 统一布局、Theme 和多语言适配。

### UI-004 输入、命令和反馈

点击、输入、删除、筛选和排序应转换为明确命令，交给 Application Service 校验并执行；UI 只负责收集输入和显示成功/失败/不可用反馈。危险操作必须有确认和本地化提示。

### UI-005 UI 状态机与生命周期

至少区分：

```text
Loading / Ready / Empty / Unavailable / Error
```

窗口打开、关闭、语言切换、屏幕尺寸改变、World/Map 切换时，必须清理或重建不可复用的 UI State 和缓存。

### UI-006 可复用组件与可替换主题

Button、Tab、Card、Table、List、ProgressBar、Tooltip、Dialog、Chart 等通用组件集中实现。组件接受语义化 Token 和数据，不在每个 Window 内复制颜色、尺寸和状态逻辑。

### UI-007 列表、表格、图表与 Timeline

大数据量必须有分页、窗口化/虚拟化、采样、排序上限或缓存。图表计算在绘制前完成；绘制循环不得做全量数据聚合、全库扫描、反射或高频分配。空数据必须提供 Empty State。

### UI-008 Empty、Loading、Error、Unavailable

每个可选 Section 都要定义：Provider 缺失、数据为空、读取失败、权限/能力不可用时的显示行为。隐藏 Section、显示“暂无数据”或显示降级状态必须是有意设计，不能留下空白区域或异常堆栈。

### UI-009 多语言布局

布局不得按中文、英文或任意单一语言长度硬编码。必须考虑：

```text
动态宽度 / 最大宽度 / 换行 / 截断
Tooltip / 滚动 / 最小可读尺寸
长 Key、复数、数字格式、日期格式
```

### UI-010 第三方 UI 隔离

本 Mod 表现层默认只作用于自己的 Window、Panel 和资源。不得覆盖第三方通用 UI 资源、全局 GUI 状态或不属于本 Mod 的窗口；跨 Mod UI 只能通过明确 Compatibility 方案。

### UI-011 UI 可测试性

关键组件必须能使用稳定的 ViewModel/DTO 进行渲染测试或至少进行布局检查。交互逻辑与绘制分离，确保语言切换、空状态和错误状态不必启动完整业务流程才能验证。

### UI-012 UI Gate

```text
[ ] UI-001–UI-011 适用项通过
[ ] Window 未承载 Core/Save 职责
[ ] Provider 只返回数据，不接管绘制
[ ] 状态和输入边界完整
[ ] 多语言与空/错/不可用状态可见
[ ] 第三方 UI 未被污染
```

## 二、本地化 Localization

### LOC-001 本地化命名空间

Keyed Key 必须使用项目固定前缀：

```text
MyMod.UI.Archive.Title
MyMod.Dialog.DeleteConfirm
MyMod.Message.LoadSuccess
MyMod.Settings.EnableFeature
MyMod.Error.ProviderFailed
```

DefInjected 只修改本 Mod 自己的 Def 字段：`MyMod_Archive.label`。`DefName`、Translation Key 和玩家文本不得复用为同一概念。

### LOC-002 DefInjected 与 Keyed 分工

```text
Def / XML 字段翻译 → Languages/<Language>/DefInjected/<DefType>/...
C# / UI / Message / Dialog → Languages/<Language>/Keyed/...
```

代码不得写裸用户文本；Def 不应通过代码动态拼接语言。任何公共 Key 的新增或重命名必须进入 Change Summary。

### LOC-003 默认值与翻译 fallback

默认语言必须可用，目标语言缺失时按项目明确顺序 fallback。默认 Def 值不能暗中承担某一种语言的业务依赖；缺失翻译不能改变业务分支或 Save 身份。

### LOC-004 占位符、格式化和长度

翻译 Key 的参数必须有稳定名称/顺序和示例：

```text
MyMod.Message.RecordCount = "Records: {0}"
```

各语言必须保持参数数量和类型语义一致。日期、数字和百分比使用适当格式化，不拼接语言词序固定的字符串。

### LOC-005 翻译覆盖审计

发布前扫描：缺失 Key、多余 Key、拼写/大小写差异、重复 Key、错误 DefInjected 路径、XML 解析错误、未翻译用户文本。检查结果作为 GATE-LOC Evidence。

### LOC-006 本地化与业务逻辑隔离

翻译结果只用于显示、日志和用户反馈；禁止 `if (text == ...)`、以 label 选择对象、以语言字符串决定存档迁移或兼容分支。

### LOC-007 第三方翻译不污染

本 Mod 不得修改其他 Mod 的 Key 或 DefInjected；需要协作翻译时通过对方公开 Key/兼容包/明确 Patch，且必须在 Compatibility 层登记。

### LOC-008 Localization Gate

```text
[ ] LOC-001–LOC-007 适用项通过
[ ] Key/DefInjected 命名空间唯一
[ ] 英文/默认语言完整
[ ] 目标语言 fallback 可用
[ ] 参数、长度和布局已验证
[ ] 未污染第三方翻译
```

## 三、Theme、Skin 与 Asset

### ASSET-001 资源命名空间

```text
Textures/MyMod/UI/
Textures/MyMod/Icons/
Textures/MyMod/Theme/
Sounds/MyMod/
Materials/MyMod/
```

路径和文件名都必须避免通用裸名，加载失败要有明确诊断和安全占位。

### ASSET-002 Theme Token

Theme 集中管理语义 Token：

```text
Primary / Secondary / Background / Surface / SurfaceElevated
Border / Text / TextSecondary / Accent / Success / Warning / Danger
Spacing / Padding / RowHeight / IconSize / Typography
```

Window 不得散落 `new Color(...)`、固定颜色或无来源的尺寸魔法值。

### ASSET-003 Skin 可替换性

Skin 是 Theme/Asset 的替换实现，不得复制 UI 业务逻辑。切换 Skin 不应改变 Domain 规则、Save schema、Translation Key 或公共 Contract。

### ASSET-004 9-Slice 与可变尺寸

窗口、面板、按钮、卡片等可变尺寸资源优先使用 9-Slice/等效九宫格设计，保证四角和边缘稳定，中心区域可扩展。禁止通过整图强行拉伸造成边角变形。

### ASSET-005 Material/Shader 使用边界

默认优先 Texture + Color；只有确实需要发光、动态渐变、特殊透明、扫描线等效果时使用 Material/Shader。相同材质应复用，避免为普通 UI 元素大量创建独立实例。

### ASSET-006 Asset 生命周期与缺失资源

资源必须可加载、可缓存、可释放或由平台管理；缺失资源不应导致核心功能崩溃。Asset ID、路径、用途和 fallback 记录在资产清单。

### ASSET-007 资产授权与发布包

每个非平台资源必须有来源/授权记录、目标分辨率、格式、是否需要压缩以及是否包含在发布包中的说明。不得把开发临时素材误打包。

### ASSET-008 Asset Gate

```text
[ ] ASSET-001–ASSET-007 适用项通过
[ ] 路径/文件名有 Mod 命名空间
[ ] Theme Token 集中管理
[ ] 可变尺寸资源正确处理
[ ] Material/Shader 有必要性
[ ] 缺失资源可诊断和降级
[ ] 发布包只含合规资产
```

## 四、表现性能

### PERF-001 热路径约束

Tick、高频回调和绘制循环不得进行全库扫描、反射、无界 LINQ/临时集合、重复 Def 查找、重复本地化解析、无界日志或 UI 写入。高频数据应采用受控采样、批量更新和稳定缓存。

### PERF-002 UI 刷新与缓存

UI 使用 `DataRevision`、显式刷新请求或固定节流刷新，避免每帧重建 Read Model。缓存必须有来源、失效条件和容量上限；UI 关闭后清理不再需要的缓存。

### PERF-003 性能证据

每次修改热路径、大列表、图表、Provider Registry 或 Harmony 时，至少记录：场景、样本规模、刷新/采样周期、分配趋势、异常行为和比较结论。无法测量时登记风险，不得声称“已优化”。

### PERF-004 GC、LINQ、反射和全库扫描

这些技术不是绝对禁止，但在热路径默认禁用；若使用必须说明频率、上限、替代方案和性能证据。反射应在初始化阶段完成并缓存结果。

### PERF-005 大数据集降级

当数据规模超过预算时必须有排序上限、抽样、分页、虚拟化、时间范围缩减、延迟加载或隐藏低优先级 Section 的策略。降级状态需要本地化反馈。

### PERF-006 Performance Gate

```text
[ ] PERF-001–PERF-005 适用项通过
[ ] 热路径无明显无界操作
[ ] UI 刷新受控
[ ] 缓存可失效/重建
[ ] 大数据集有降级
[ ] 有可复核 Evidence
```
