# RimWorld Mod Engineering Standard v3.0

本目录是面向 RimWorld 1.6 Mod 项目的统一工程规范体系。v3.0 不是在 v2.0 末尾追加说明，而是对原有规范进行全局重构：治理文件负责定义“规则如何生效”，分层文件负责定义“具体工作如何执行”，所有规则通过稳定的规则 ID 互相引用。

## 使用顺序

1. 先阅读 [00-规范体系总纲.md](00-规范体系总纲.md)，确认优先级、依赖方向和冲突裁决。
2. 按任务读取 [00-统一术语与定义.md](00-统一术语与定义.md) 与 [00-规范关系矩阵.md](00-规范关系矩阵.md)。
3. 按变更类型读取 01–07 分层规范；规则编号以 [00-规则编号索引.md](00-规则编号索引.md) 为唯一索引。
4. 开发过程遵循 [00-工程生命周期规范.md](00-工程生命周期规范.md)，交付前执行 [00-统一验收标准.md](00-统一验收标准.md)。
5. 任何偏离规范的实现必须先登记在 [00-规范例外与变更管理.md](00-规范例外与变更管理.md)。AI 必须遵守 [07-AI开发规范.md](07-AI开发规范.md)。
6. PersonalChronicle 的 Provider、Read Model、事件与接入层映射见 [附录-项目架构实施映射.md](附录-项目架构实施映射.md)。

## v2.0 到 v3.0 的统筹变化

| 原文件/主题 | v3.0 处理方式 |
|---|---|
| 规范体系索引与总则 | 重构为 `00-规范体系总纲`，并拆出矩阵、术语、生命周期、Gate、例外、编号索引 |
| 01-基础层规范 | 保留职责，统一为 `BASE-*` / `TEST-*`，补入硬编码、诊断和基础 Gate |
| 02-架构层-核心架构规范 | 统一 Core、Domain、Application、API、Presentation、Compatibility 边界和依赖图 |
| 03-架构层-数据与扩展规范 | 统一 Def、Runtime、Save、UI 数据边界，补齐 DefModExtension、Comp、Migration |
| 04-架构层-兼容与接入规范 | 将第三方 Mod、DLC、Harmony、可选依赖、降级和隔离测试纳入独立接入层 |
| 05-表现层规范 | 统一 UI、Theme、Skin、Asset、Localization、布局与 Performance 规则 |
| CHANGELOG_SPEC | 纳入生命周期、Gate、版本策略、迁移、回滚，重构为 `06-变更日志与发布规范` |
| AI 开发/标准化开发规范 | 改为可执行协议：任务识别 → 架构评估 → 实现 → Gate → 变更摘要 |
| 高拓展高接入架构方案 | 映射为 `附录-项目架构实施映射`，统一 Provider、Registry、Read Model、事件与 Compatibility 术语 |

## 原文件处理

原架构目录中的 v1/v2 文件保留作为历史材料；v3.0 目录是新的唯一规范入口。旧文件到新规则域的映射见 [00-版本迁移说明.md](00-版本迁移说明.md)。

## 规范性说明

- 本体系适用于 RimWorld 1.6 项目；具体 API 行为仍以项目锁定的游戏、DLC、Harmony 和编译引用版本为准。
- 规则 ID 是跨文件引用的稳定契约，不得因排版或文件移动而改号。
- 示例中的 `MyMod`、`MyMod_`、`MyMod.` 是占位命名空间，项目必须替换为唯一且固定的 Mod 标识。
- “必须/不得”是强制规范；“应/建议”是默认方案；偏离默认方案时仍需满足 [EXC-001](00-规范例外与变更管理.md#exc-001-例外先登记) 的例外流程。
