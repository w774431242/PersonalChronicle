# 附录：PersonalChronicle 项目架构实施映射

**用途：** 将现有“高拓展高接入架构方案”中的项目设计落到 v3.0 规范，而不是让项目方案与标准规范各自形成一套术语。  
**适用项目：** PersonalChronicle 及其外部 Mod 接入生态

## 1. 目标架构

```text
PersonalChronicle
├── Foundation
├── Domain
│   ├── Events
│   ├── Identity
│   ├── Career
│   └── Relations
├── Application
│   ├── ArchiveService
│   ├── Capture
│   ├── Queries
│   └── Providers
├── Api
│   ├── Contracts
│   ├── Version
│   └── Registry
├── Data
│   ├── ChronicleGameComponent
│   ├── DefCatalog
│   └── Migration
├── Presentation
│   ├── ReadModels
│   ├── Renderers
│   └── ArchiveMainTabWindow
└── Compatibility
    ├── ModDetection
    ├── Dlc
    └── Adapters
```

对应规范边界：

| 项目模块 | v3.0 术语/规则 | 允许依赖 |
|---|---|---|
| `Domain` | Core / Domain，[ARC-002](02-架构层-核心架构规范.md#2-arc-002-core-纯净边界) | Foundation、稳定领域类型 |
| `Application` | Service / Provider，[ARC-004](02-架构层-核心架构规范.md#4-arc-004-服务职责) | Domain、Contract |
| `Api` | Contract/API，[ARC-005](02-架构层-核心架构规范.md#5-arc-005-contractapi-边界) | 最小 DTO、版本、能力 |
| `Data` | Def/Runtime/Save，[DATA-001](03-架构层-数据与扩展规范.md#1-data-001-四类数据边界) | Core、RimWorld 数据接口 |
| `Presentation` | Read Model/UI，[UI-003](05-表现层规范.md#ui-003-ui-只读-read-model) | Core 查询、Theme、Localization、Asset |
| `Compatibility` | Adapter/Patch，[COMP-001](04-架构层-兼容与接入规范.md#1-comp-001-兼容层隔离) | Core Contract、目标 Mod（仅局部） |

## 2. Provider 注册与读取模型

外部 Mod 接入应采用：

```text
外部 Mod Provider
    ↓ 注册 IArchiveProviderRegistry
能力探测 / 优先级 / 失败隔离
    ↓
Domain/Application Contract
    ↓
ArchiveSectionSnapshot / Read Model
    ↓
PersonalChronicle Renderer
```

Provider 不得直接修改 `ChronicleGameComponent`、Pawn 内部字段、`ArchiveMainTabWindow` 或 UI 布局。它只提交经过验证的数据或事件，符合 [MATRIX-004](00-规范关系矩阵.md#matrix-004-compatibility-单向隔离)、[UI-003](05-表现层规范.md#ui-003-ui-只读-read-model) 和 [COMP-009](04-架构层-兼容与接入规范.md#9-comp-009-兼容失败降级)。

推荐契约：

```csharp
public interface IArchiveUiDataProvider
{
    string SectionId { get; }
    IReadOnlyCollection<string> SupportedTabs { get; }
    ArchiveSectionSnapshot BuildSection(ArchiveUiContext context);
}
```

`ArchiveSectionSnapshot` 只允许返回：标题/副标题 Translation Key、指标值、Tab ID、进度、稳定对象 ID、数据状态和有限的只读展示数据。不得返回 `Rect`、`GUIStyle`、Texture 实例或绘制回调。

## 3. 工作强度接入映射

工作强度、生产、战斗、关系、地点等外部领域都使用独立 Provider：

```text
IWorkIntensityProvider
IProductionProvider
IBattleProvider
IRelationProvider
IPlaceProvider
```

每个 Provider 必须声明：

```text
ProviderId
Contract/能力版本
支持的对象/时间范围
采样周期或数据新鲜度
空数据和失败行为
是否可写入事件
```

Provider Registry 是运行时对象，不写入 Save；加载/重开游戏后重新注册。连续失败可采用熔断或降级，但不得影响核心档案、Save 和其他 Provider。

## 4. 事件写入映射

事件输入使用稳定 Contract，而不是让接入方读取内部集合：

```text
外部事件
→ ArchiveEventInput
→ ID/类型/Tick/容量/去重校验
→ IArchiveEventSink
→ Domain 归档
→ DataRevision
→ Read Model 重建
```

事件应支持 `DeduplicationKey`、重要等级、来源 ID 和缺省值。事件文本只保存稳定 Key/参数，不保存已经翻译的句子。

## 5. UI 接入降级

| 情况 | 标准行为 |
|---|---|
| Provider 不存在 | 隐藏 Section 或显示不可用状态，不显示异常堆栈 |
| Provider 返回空数据 | 显示统一 Empty State |
| Provider 抛出异常 | 记录一次结构化 Warning，当前 Section 降级 |
| Window 尺寸变化 | Renderer 统一处理滚动和裁剪 |
| 语言变化 | 按 Translation Key 重新渲染，不持久化显示文本 |
| 目标 Mod 卸载/缺失 | Compatibility 能力关闭，Core 继续运行 |

## 6. Save 与缓存映射

```text
Save：稳定事件、对象 ID、schema 版本、必要的原始值
Runtime：Provider 注册、DataRevision、索引、聚合缓存
UI：筛选、滚动、当前 Tab、临时 Read Model
```

缓存必须能从 Save/Runtime 权威数据重建；`ArchiveMainTabWindow` 不应直接触发全量查询或写入。新增 `SourceId`、事件重要等级等字段时，按 [SAVE-003](03-架构层-数据与扩展规范.md#14-save-003-默认值与向后兼容) 和 [SAVE-004](03-架构层-数据与扩展规范.md#15-save-004-迁移流程) 提供默认值与迁移。

## 7. 版本演进建议

```text
API v1：保留既有 IArchiveService，停止继续堆叠无关方法
API v1.x：增加 IArchiveQueryService / IArchiveEventSink / Provider Registry
API v2：稳定 Read Model、能力探测和独立 Domain Provider Contract
未来：评估独立 Contracts 程序集，不以拆 DLL 作为解耦的前提
```

对于已有接入，优先采用“新增门面 → 适配旧服务 → 标记旧入口 Deprecated → 迁移窗口 → 再移除”的路线，符合 [REL-008](06-变更日志与发布规范.md#8-rel-008-公共-api-演进) 与 [SAVE-005](03-架构层-数据与扩展规范.md#16-save-005-重命名删除与别名)。

## 8. 项目验收映射

```text
[ ] Core/Domain 无 UI 和第三方类型
[ ] Provider 通过 Registry 和 Contract 接入
[ ] UI 只消费 Read Model
[ ] 外部 Provider 失败不阻断核心功能
[ ] Save 不保存翻译文本、UI 或缓存
[ ] Event 有去重、来源、重要等级和迁移策略
[ ] DataRevision/缓存失效可解释
[ ] 语言、DLC、目标 Mod 缺失矩阵已测试
[ ] 公共契约变更有 Changelog 和迁移说明
```
