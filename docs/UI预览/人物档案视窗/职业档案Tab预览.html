Concept UI：前端仅展示人物职业档案，不直接计算职称资格或授勋条件。 本页为自包含可视化原型（总览/履历/勋章 3 Tab 可切换，右下角「数据契约」标注各区块 C# 字段来源）； P5~P8 资格 / 考试 / 职称 / 勋章 已代码落地（Domain 纯逻辑 + Application 编排 + 数据驱动 Def，附录见 DataMap）； 荣誉墙/授勋/详情为可运行预览，勋章现含「阈值勋章」+「成就勋章（MedalKind.Achievement，依据 AchievementEvaluator 聚合）」两类。 「🎲 随机职业数据」按钮对应 C# DevTestButtons.CareerRandomize(Pawn)，仅 Prefs.DevMode 时显示（本预览默认显示以便演示）。 职业规划区现采用第一版职业"宇宙"骨架：12 个一级专业（工程/制造/农业/林业/畜牧/医学/武器/矿业/科研/烹饪/艺术/管理）； 算法为专业适配分析（非"推荐职业"）：五维 ProfessionalFit = 基础能力×0.45 + 实践×0.25 + 兴趣×0.10 + 成果×0.10 + 成长×0.10， 基础能力经 skillBase 边际递减（18→19 增益远小于 2→3），权重矩阵 MAJOR_WEIGHTS 每专业 12 技能权重和=100%； 专业名单行紧凑排列、悬停弹出五维明细卡片与优势✓/短板△，只提供决策依据，由玩家选择专业。

总览 / Overview
职业规划（专业适配分析，非"推荐职业"） → 第一版职业"宇宙"骨架：12 个一级专业（工程/制造/农业/林业/畜牧/医学/武器/矿业/科研/烹饪/艺术/管理）；原则=分类须被原版 SkillDef + WorkType + Job/Recipe/Research 持续提供成长来源；关键设计=一个原版 Skill 可进入多个专业形成不同 CareerSkill（Crafting→工程/制造/武器，Plants→农业/林业，Intellectual→科研/工程/医学）；候选由 MAJOR_WEIGHTS 12 权重矩阵驱动（每专业 12 技能权重和=100%）。五维推荐算法 analyzeMajor：基础能力(skillBase 边际递减)×0.45 + 实践适配(practiceNorm)×0.25 + 兴趣倾向(Passion)×0.10 + 成果表现(qualityScore)×0.10 + 成长潜力×0.10 = ProfessionalFit 0~100；可解释输出=五维条形+优势√/短板△+推荐方向；只提供决策依据，不替玩家决定职业。后续不增一级分类，只往每类下扩职业方向→职业技能→技能专精（工程/制造/科研/医学/武器优先做闭环）；目标职称路径待 P4 职称体系驱动；原版 12 技能 defName 已核验
职业身份·职称 → PawnObject.CareerData（P4 职称评定结果）
专业技能 → PawnObject.SkillSnapshot（技能等级）
相关工时 → WorkIntensityView.TotalHours
当前资格状态 → P4 职称资格判定（规划中，预览为静态样例）
资格预检条件 → P4 资格依赖链（规划中）
履历 / Career（工作经历）
一段经历 = 工坊就职时段 → 由 CareerData.Events 按 Tick 落入 WorkplaceSnapshot 的 [首次使用, 末次使用] 区间切分
工坊 / 房间 → WorkplaceSnapshot.BuildingDefName / RoomRoleDefName（经 DefDatabase.LabelCap 实时解析）
制造件数 / 品质 → CareerData.Events 过滤 ItemProduced + Quality 字段
建造 / 研究 / 著书 → CareerData.Events 过滤对应 CareerEventType（P1 仅 ItemProduced 真实写入，余为白名单占位）
累计使用 / 最近使用 → WorkplaceSnapshot.UseCount / LastUsedTick
勋章 / Honor（P7 已落地）
荣誉勋章墙 → ChronicleGameComponent.GrantedMedals（P7 勋章体系，代码已落地）；含两类：① 阈值勋章（MedalDef.threshold 传统指标）② 成就勋章（MedalKind.Achievement + achievementKey，由 AchievementEvaluator.Aggregate 聚合 CareerEvent 派生指标：LegendaryMade / MajorProjects / TitleCount / ExamPassCount / LongServiceTicks）
授勋流程 → MedalAwardEvaluator.EvaluatePawn 分发阈值/成就路径 → 达标写入 CareerEvent(MedalGranted)（MedalAwardService.WriteMedalGrantedEvent 回写事实库，闭环）
荣誉贡献结构 → P7 贡献维度（规划中，预览为静态样例）
资格 / 职称（P5~P8 已落地）
资格定义 → QualificationDef（Defs/QualificationDefs.xml：Q_Precision_Junior / Q_Precision_Assistant / Q_Precision_Senior / Q_Precision_Specialist / Q_Precision_Master）
职称定义 → ProfessionalTitleDef（Defs/QualificationDefs.xml：Title_Precision_Junior / Title_Precision_Assistant / Title_Precision_Senior / Title_Precision_Specialist / Title_Precision_Master）
资格状态机 → QualificationState：Locked → Eligible → Preparing → PracticalExam → TheoryExam → Thesis → Defense → Qualified → Granted（锁定 → 符合条件 → 准备中 → 实践考试 → 理论考试 → 论文 → 答辩 → 已通过 → 已授予，失败回准备中）
实践考试 → 真实制造行为证据（无假按钮，由 CareerEvent 派生）
理论考试 → ExamScoring 加权合成（无 AI 问答，阶段一）
著作证据 → BookEvidence（CareerEvent.BookProduced，真实 Hook 待接）；论文/答辩 → ThesisData
编排入口 → ArchiveService.RunQualification(this)（由 ChronicleGameComponent.Sampling 节流调用），append-only Scribe（未 bump schema）
开发者测试 → DevTestButtons.CareerRandomize(Pawn)，仅 Prefs.DevMode 显示，覆盖式随机生成 P1~P8 全维度数据
说明：本预览为纯前端原型。代码层已落地 P1（CareerData.Events + WorkplaceSnapshot 真实写入履历）、 P5~P8（资格/考试/职称/勋章 Domain 纯逻辑 + Application 编排，数据驱动 Def，零新 Harmony Patch）。 勋章墙/授勋/详情交互可运行；成就勋章图待补（暂用 no-img 占位）。BookProduced 真实 Hook 与 P9 资格 UI 仍待接入。
