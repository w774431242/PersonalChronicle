## [开发线] 2026-09-11

### Fixed（车间区被设备/建筑"抠格"—— P0 级可用性缺陷）
- **现象**：划分车间后在其中放置设备（或铺地板、砌墙），车间 zone 的对应格子会被移除；设备把车间切成两半时更大的一块会整块消失，极端情况下整个车间直接消失（管理 gizmo/面板一并没了）。
- **根因（原版机制，反编译实证）**：`Thing.SpawnSetup` 末尾 `if (!def.CanOverlapZones) map.zoneManager.Notify_NoZoneOverlapThingSpawned(this)` → 对 `OccupiedRect()` 每格 `Zone.RemoveCell(c)` + `Zone.CheckContiguous()`；`CheckContiguous` 从 `cells[0]` 洪泛，**不连通的残余格全部删除**；`Zone.RemoveCell` 内 `cells.Count == 0 → Deregister()` 使车间注销。而 `ThingDef.CanOverlapZones` 对「SupportsPlants 建筑 / `passability == Impassable` / `surfaceType >= 1`（地板）/ `ISlotGroupParent`（货架）/ 显式 `<canOverlapZones>false</canOverlapZones>`」均为 false —— **原版全部工作台继承的 `BenchBase` 正是最后一条**（蓝图/框架再委托 `entityDefToBuild`），故"放下蓝图那一刻格就没了"。
- **连带损坏**：`ZoneManager.ZoneAt(thing.Position)` 不再命中 ⇒ `WorkshopFloorViewProvider.BenchBelongsToBay`（设备归属）、`WorkshopStats.ScanDevices`（设备统计/清单）静默失效，车间俯视图设备数恒为 0。
- **修复**：`Automation/Zone_Workshop.cs` override `RemoveCell` —— **只在"本格存在 `!def.CanOverlapZones` 的物"时拒绝掉格**，其余情形完全走 `base`（原版行为不变）；`Delete(bool)` 与新增 `RemoveCellExplicitly` 置放行位，玩家用原生「删除区域/缩小区域」擦格经 `Find.DesignatorManager.SelectedDesignator is Designator_ZoneDelete` 放行。原版全部掉格路径都是 `callvirt Zone::RemoveCell`，虚派发即命中 ⇒ **零 Harmony**（符合 COMP-004）。
- **效果**：车间格不再被设备/墙/地板抠掉 ⇒ 设备归属、车间统计、俯视图**自动恢复**（未改动 `BenchBelongsToBay` / `ScanDevices` 一行代码）；车间不会再被吃空注销。
- Tests/Gates: 权威编译 **0 错 0 警**；单测 **212/212** 通过；发布区 dll 同步且 SHA256 两区一致 `025F012F8399A9DE43AE28D346A09114FC46FA8169DE00B90541C4B0DE1E58C6`；例外登记 `docs/设计文档/架构/EXC-2026-003.md`（E2）。
- Compatibility: 与「zone 只含空闲格」的原版不变式有意偏离（已登记 EXC）；水体/飞船着陆清场落在被占用的车间格上会被拒绝（边缘情形）；**正确操作顺序为先划车间、后放设备**（`Zone.AddCell` 仍拒绝把已被占用的格划入，见遗留待办）；dll 不热加载，**须重启游戏**。

### Changed（车间覆盖层置顶，兼容种植/存储等功能性 zone）
- **需求**：车间区需要与种植区、仓库区等功能性 zone 共存显示（玩家会在同一片场地上嵌套圈定），车间覆盖层应恒在其上。
- **机制（反编译实证）**：zone 覆盖层由 `Verse.SectionLayer_Zones.Regenerate()` 按**栅格扫描顺序**逐格 `GetSubMesh(zone.Material)` 烘焙（每 zone 一个 submesh），`Verse.MapDrawLayer.DrawLayer()` 对每个 submesh 各做一次 `Graphics.DrawMesh`；而原版所有 zone（`Zone.CreateMaterial`）与 `CellBoolDrawer`（区域高亮）的 `material.renderQueue` 全是 **3600** ⇒ 同队列内退化为提交顺序，重叠区"谁先被扫到谁在下面" ⇒ 车间范围被其它 zone 压住。
- **修复**：`Zone_Workshop` override `CreateMaterial()`，用 `SolidColorMaterials.NewSolidColorMaterial`（独立材质，不动按色共享缓存）+ 颜色量化保持一致，`renderQueue = 3601`（原版 `renderQueue` 赋值点实测仅 `13/2950/3201/3600`，无冲突；仍低于 Unity Overlay 4000 与 UI）。
- Tests/Gates: 编译 **0 错 0 警**；单测 **212/212**；两区 dll 哈希一致；例外登记 `docs/设计文档/架构/EXC-2026-004.md`（E1）。
