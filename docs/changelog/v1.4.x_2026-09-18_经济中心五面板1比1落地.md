## 二、三个 P1 缺陷的根因与修法

### 2.1 数值列不可见 —— `dims` 把指标列标成了「降调」

- **根因**：`EconomyMarketPanel` 把 `dimBuffer[1..3]` 全部置 `true`（"指标列降调前景"），
  而预览的 `.dt .num` 用的是**正文色**（`var(--text)`），全表**没有任何 dim 列**
  （CSS 149-150 只有 `.num.gain/.loss/.eq` 三种语义色）。降调后在深色底上这些数字几乎不可见。
- **修法**：`dimBuffer` 全置 `false`。

### 2.2 阈值带色列量纲不一致 —— `bandValues` 是归一化值，`bandRef` 是原始因子

- **根因**：`bandValueBuffer[i] = row.Price01`（归一化 `0..1`，`0.5` = 中性），
  而 `BandReference = 1f`（**原始因子**的中性值）。两者量纲不同 ⇒ 所有行都被判为"低于参照"，
  RUIF 的原生带色语义整体错位。
- **修法**：改传 `row.Factor`（**原始因子**），并在快照里显式区分 `Factor` / `HasFactor`；
  `bandRef` 保持 `1.0`（与 `MvsConstants.NeutralFactor` 同值，UI 层写字面量以免依赖 `MVS.Domain`）。

### 2.3 品种名回落英文 —— 面板文案不该依赖「DefInjected 是否命中」

- **根因**：`row.Name = ((Def)commodity).LabelCap`。`LabelCap` 在 DefInjected 未命中时
  **静默回落**到 Def XML 里写死的英文 label（`Defs/MVS_Commodities.xml` 的 `<label>` 是英文小写）。
  实机截图整列英文 = 该回落发生了。
- **修法**：`MVSCommodityDef` 新增 **`displayKey`** 字段（Def 自己声明键名，**不硬编码 DefName 映射**），
  Provider 走 `Keyed 优先 → LabelCap 兜底`；18 个品种全部指向既有的 `MVS.Status.*` 键集
  （该键集本就是这 18 个品种的显示名，冲击文案也用它 ⇒ 一处定义、零漂移）。
- **顺带补齐**：`MVS.Economy.Society.*` / `MVS.Economy.FactionDetail.*` / `MVS.Economy.FactionList.*`
  三组键 **在语言文件里完全缺失**（Provider 早就引用它们 ⇒ 实机上这些位置一直在显示**原始键名**）。
  本轮一次性补齐，并加了键审计脚本把这类缺失钉死。

- **净值符号**：预览图例是「差额 **−** 净进口 · **+** 净出口」⇒ 显示值 = `供应 − 需求`。
  旧实现是 `FormatRate(需求 − 供应)`，**符号与预览相反**。已改为 `FormatSigned(供应 − 需求)` +

## 九之二、第二轮（实机复测后 · 用户提供实测图）

用户给出实机截图，经 `_scripts/crop_shot.py` 按面板 6~8 倍放大逐块核对。
五面板栅格、KPI 7 卡、社会背景、派系状态、总库存链路+侧栏、派系列表（含科技列 /
商·基·軌·訪 / 色点 / 分组行 / 判据框）**均已与预览一致**。新发现并修复 3 处：

### 2.4 【P0】列宽契约搞错 —— 市场表只剩第一列（真正的根因）

- **现象**：8 倍放大确认，市场表**只有「品種」一列有墨迹，四个数值列一个都没有**。
- **根因**（读 RUIF 源码 `Components/TableAtoms.cs` 坐实）：
  ```csharp
  widths[i] = Mathf.Max(0f, shares[i] * row.width);   // ← shares[i] 当【占比】直接乘
  widths[n-1] = Mathf.Max(0f, row.width - used);      // 末列吃余宽
  ```
  `shares` **不做归一化**。落地侧按"任意比例"理解，传了 `2.385 : 1 : 1 : 1 : 1.001`（Σ = 6.386）
  ⇒ 首列宽 = 2.385 × 表宽 ≈ 2100px，**吃光整行**；列 1..4 被推到 `rect` 之外、整体落在画布外
  ⇒ **完全不可见**（表头同样只剩第一列）。
- **修法**：`RuifBridge.NormalizeShares` 在**桥层**归一化到 Σ = 1 再交给 RUIF（一处收口）。
  - 与 D2 自绘路径（调用方按 `share / Σshares` 切）**语义一致** ⇒ D0/D2 列宽不漂移；
  - 已核实第二个调用点「人口中心三张表」的 shares **Σ = 1.00**（`CorePerfTableShares` 等）
    ⇒ 归一化对它们是**恒等运算**，向后兼容（并有单测钉死）。
- **上一轮的误判已正名**：2.1（`dims` 降调）与 2.2（`bandRef` 量纲）都是**真缺陷**，
  但它们只让"唯一可见的那一列"变暗/错色 —— **不是"数值列不可见"的主因**。主因即本条。
- ⚠ 顺带修正 `MasterControlTabWindow.Roster.cs` 里一句**与 RUIF 实现不符**的注释
  （「`shares ÷ Σshares` = RUIF `TableFmt.ColumnSplit` 的同一比例式」）——
  两式只在 Σ=1 时等价，该错误注释正是同类缺陷的种子。

### 2.5 【P1】链路层级把「基础原料」判成「中游成品」

- **根因**：层级按**全部边**的角色推导，而「基础原料」有一条 `Import` 入边
  （貴重雜項 → 基礎原料）⇒ 被判成"既有上游又有下游 = 中间加工方"。
- **修法**：层级只按**加工边**（`Transform` / `Substitution`）推导 —— 进口 / 出口是**链的边界**，
  不是链内加工步骤。副产品：上游列标签随之由「上游原料」变为「產出源」，与预览一致。

### 2.6 【P1】市场表内层滚动（18 个品种只显示 12 行）

- **现象**：表底 `+6`。
- **根因**：面板高不足时按高度裁行，而预览的对应行为是 `.pbody{overflow:auto}` —— **滚动**。
- **修法**：表区改**内层滚动**（`Widgets.BeginScrollView`，滚动位置存窗口实例字段
  `economyMarketScroll`，UI 瞬时态不入档）；行数只受 `MaxDrawRows` 工作量闸门限制；
  `+N` 只在闸门真截断时出现，并画在**可见区右下角**（不再被滚动带走）。

### 2.7 回归护栏（并用注入法验证有效性）

新增 2 例：`RuifBridge_NormalizesShares_ToUnitSum_PreservingRatio`（Σ 必须为 1 且比例保持）、
`..._IsIdentityForUnitSum`（Σ=1 入参恒等 ⇒ 人口中心不受影响）。
**注入验证**：把归一化改成恒等 ⇒ 测试精确失败并报出 `Σ = 6.386` ⇒ 检测器有效（随即还原）。
单测 **368 → 370 全绿**。
