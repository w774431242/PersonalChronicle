## [开发线] 2026-09-19

### Added

#### Domain（纯函数，零库类型依赖）
- **`MarketShockModel`** —— 对数域冲击模型。取对数的三个红利：① 乘性冲击（供应 ×0.92 / 需求 ×1.05）变**加性** ⇒ 多事件可直接累加；② 衰减退化为**统一乘子**（与品种无关）；③ 存档只需「每品种一个 float」。
  - `Delta(demandShock, supplyShock, severity) = [ln(1+q) − ln(1−s)] × severity`。**只吞 NaN，不吞 ±∞**（+∞ 语义是"供应彻底消失 = 极稀缺"，必须走边界而非当 0）。
  - `Decay(deltaTicks, halfLifeTicks) = 0.5 ^ (Δt / 半衰期)`；**半衰而非线性归零**：线性有明确归零点会造成价格变化的一阶不连续（玩家可感知），且不可分段可加。
  - `Step` / `EffectiveDemand` / `TargetFactor` / `IsNeutral`。
  - ⭐ **核心不变式**：`offset == 0 ⟺ 因子 = 1.0`。**绝对供需比（`r = demandBaseline/supplyBaseline`）被有意舍弃** —— 18 个品种里 13 个基线是③设计假设值，让基线失衡直接定价等于用拍脑袋的数值把**所有**商品价格永久推离中性，与 v1「缺键即中性」「任何不确定都退化为不动」的哲学直接冲突。基线只服务面板显示与将来的库存模型。
  - `TargetFactor` **复用** `MarketFactor.Target`（以基线 = 1 为单位传参）⇒ 零重复实现、边界（∞/NaN/≤0）全部走既有收口。

#### Data（结算器）
- **`WorldComponent_Market.Settlement.cs`（partial）** —— 结算器。**为什么是 partial 而非新类型**：它要动 `private` 的 `globalFactors` / `SetFactor`，新类型只能靠把私有字段改 `internal` 或加一堆转发面（双份状态访问路径必然漂移）；partial 是**零契约改动**（类名 / Save 字段名 / 翻译键全不动）。
  - **`WorldComponentTick()` 覆写 + 组件内自节流**。Cecil 已证：`RimWorld.Planet.WorldComponent` 有 `public virtual WorldComponentTick()`，调用链 `TickManager.DoSingleTick → World.WorldTick → WorldComponentUtility.WorldComponentTick(world)` 遍历 `world.components` ⇒ **每游戏 tick 一次**。节流用**锚点差值**而非 `tick % N`（取模会丢 Δt，且半衰需要真实 Δt）。
  - **三条时序纪律**（均为止损）：① **首 tick 只重锚不结算** —— `lastSettleTick` 是 `[Unsaved]`，读档后为 0 而 `TicksGame` 可达百万级，不重锚就会用一个巨窗 Δt **把全表偏移一次衰干净**（"读档即毁市场"）；② **Δ 为负即重锚**（调试工具改 `TicksGame` 不得被读成"负时间流逝"）；③ **先锚定、后结算** —— 异常时重试频率被钉在 1 个结算间隔，否则原版工具层的 catch 会**每 tick 刷一行 `Log.Error`**。
  - **遍历域 = `shockOffsets ∪ globalFactors` 的键并集**，**不是** `DefDatabase.AllDefsListForReading`（踩「Tick 内全库扫描」红线），**也不是**「本步被事件触及的品种」（会漏掉仍在衰减中的存量）。并集同时解决收口：偏移归零删键后因子键仍在 ⇒ 仍被推进 ⇒ 直到 `SetFactor` 自删 ⇒ **无需额外"收口状态"**，且**中性品种绝不写键**（否则 `TryGetFactor` 恒真、`StatPart` 从恒等快路径变常走）。
  - **顺序不可交换**：① 对全部已有偏移**整体衰减** → ② 再加入本步新冲击。反序会让刚发生的事件在其发生的那一步就被扣掉 `1−decay`，且损失随结算间隔漂移（同一事件在不同 tick 到达会得到不同强度）。
  - **入队 `EnqueueShock`**：环形缓冲（预分配、O(1)、满载覆盖最旧 + 节流 Error 含被覆盖条目的 category）+ 累计丢弃计数。**O(1) 零展开**（`commodities` 展开推迟到结算步）⇒ 补丁热路径增量 = 一次组件查找 + 一次数组写入。自带「`Ready` + 非只读降级」双闸门（降级档清队列 + 单次日志，**不改任何数据**）。
  - **异常自守卫 + 节流日志**；`PerfProbe`（字面 key `mvs.settle`）只包真实结算体、**不包** per-tick 门控。
  - **稳态零分配**：出队走 ring 游标（不用 `List.RemoveAt(0)`，那是最坏 O(n²) 搬移）；两张 scratch 列表 `[Unsaved]` 复用；半衰乘子**每步只算一次**（严禁逐品种重算）。

#### Def / Patch
- **`MVSIncidentImpactDef.commodities`（受影响品种轴）** —— 本轮的**关键数据**：原有 `supplyShock`/`demandShock` 只说「影响多少」，缺了"影响什么"，结算器就只能在 C# 里写 `category → 品种` 映射 = **硬编码 defName 白名单**（违反 GOV-006 / AI-004，第三方无法接入）。形状是 **Def 引用**（与 `FactionEconomyExtension.preferred/avoided`、`MVSFlowEdgeDef.from/to` 同口径）⇒ 「Def 被卸载 / 拼写错」成为**可诊断的 null** 而非静默不匹配的字符串。
- **`Patches/MVS_IncidentImpacts.xml` 11 段全部补 `<commodities>`**。三条硬纪律写进文件头：① 空列表 / 缺节点 ⇒ 该事件**不产生任何冲击**（Fail-Closed）；② 元素解析失败 ⇒ null ⇒ 结算器跳过；③ **禁止引用 MayRequire 品种** —— 9 个 Core 项在无 DLC 环境下也加载，引用 `MVS_Commodity_InertRelics`（需 Ideology）会把"玩家没装 DLC"误报成配置错误 ⇒ 全部 11 项只引用无 `MayRequire` 的品种。

#### 启动期断言

## 残余风险 / 已知余留（诚实登记）

1. **有损窗口 ≤ 1 个结算间隔（约 4 秒）**：存档若恰好发生在结算窗口内，队列中的冲击会**永久丢失且无声**（读档后事件 ring 也清空）。成因：队列元素持 `Def` 引用，属"必不落盘"清单。升级路径已写进评审：若要收口，需把队列转成 `(defName, tick)` 纯值对并落盘 + 明确加载时序策略（**本轮有意后置**）。
2. **v1 因子无派系维度**：`globalFactors` 按品种索引，事件作用域（Faction / Global）虽已采集，但结算**统一按全局**累加（派系级定价属 B 通道，v1 未启用）。
3. **`inventory`（派系虚拟库存）仍无生产者**：本轮只接通了因子侧；`SupplyDemandModel` 全族（`BaselineStock` / `StepStock` / `IsConserved`）仍零运行时调用，属**下一单元**。
4. **基线不参与定价 ⇒ 面板「供应 / 需求」两列仍是 Def 基线**（③设计假设），只有**价格列**是运行时真值。
5. **未做游戏内实测**：`WorldComponentTick` 调度已 Cecil 核实，但「袭击后价格真的动了」需实机验证（沙箱无法起游戏进程）。`PerfProbe` key `mvs.settle` 已接入，开 `EnablePerfProbe` 即可采到一轮真实结算耗时。
6. **`MVS_IncidentImpacts.xml` 的 9 个 Core 项静默零命中风险**（第三方移除/改名 IncidentDef）在冲击开始驱动经济后，后果由"事件流少记"**升级为"经济冲击静默缺失"** ⇒ 建议下轮按 `MVS_StatParts.xml` 模板改 `PatchOperationSequence`（本轮未做，原登记文本已更新）。
7. **PERF P1**：`MVSCommodityRegistry.ForDefWithStuff` 的材料轴路径每次调用分配 1~2 个小 `List`。**当前休眠**（全 Def 零使用 `<stuffCategories>`），但材料腿启用后会进入 `MarketValue` 重算热路径 ⇒ 建议启用前先免分配化。
8. **未接线但已登记**：`WorldComponent_Market.IsOrphan`（D-2）· `MarketContracts.Events` 读面 · `MarketAccess.SnapshotInventory`。
9. **⚠ ARC-013 余量告急（本批新产生的压力）**：`WorldComponent_Market.cs` 已达 **757 行**，距「单文件 ≤ 800」仅剩 **43 行**。本批已把结算逻辑切进独立 partial（真·零契约改动）以避免撞线，但主文件自身因 schema v2 字段 + Scribe + 迁移 + 剪枝也长了约 110 行。⇒ **下一轮只要再往主文件加字段/方法，必须先切 partial**（可切出的最大块是其中的 `FactionInventoryEntry` 类，约 70 行；字段声明与 `ExposeData` 按铁律 6.3「契约锚点留主文件」保留）。
10. **`severity` 字段已启用**（本批把它作为冲击倍率乘进 `Delta`），此前该字段是"只校验不使用"的半接线状态。
