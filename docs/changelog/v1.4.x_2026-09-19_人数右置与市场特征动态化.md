## [开发线] 2026-09-19

### 要求 A：人数显示右置

原先数值压在条内**左端**——而左端恰是"条从这里开始"的**视觉锚点**：
数值占在那里既与填充起点混淆，又把长度读数挡掉。

⇒ 数值**右对齐**（组件只画条本身，数值由面板自绘右对齐标签）。
⚠ 仍是**覆盖式**绘制（条为底色 + 文本在其上），不额外占行高 —— 与工程既有的
`ProgressBar` caption 同一种做法，只是对齐方向变了。

### 要求 B：市场特征动态化

**原状**：三条**写死的 lore 问答**（`{pk}.Q1..A3`：方向 / 需求 / 门槛·敏感度）。
它们对同一派系**恒不变**，却被画在"市场特征"这个读起来像读数的位置 ——
**又一例"模板冒充数据"**（与 `out Xxx _`、阶级占比、市场面板分类行同族）。

**现状**：三条**每次重建都重算**的真实指标。

| 指标 | 口径 | 圈码 |
|---|---|---|
| **需求总缺口** | `Σ需求基线 × 需求偏置 − Σ供应基线 × 供应偏置`，只累加**该派系可见**品种 | **③**（含 Def 基线与偏置） |
| **供应库存** | 当前地图 `ResourceCounter` 里、属于可见品种命中集的物品总量 | **②**（真值，不依赖任何假设） |
| **市场准入** | 玩家与该派系的 `PlayerRelationKind`（敌对 / 中立 / 盟友） | **②**（真值） |

🔴 **同式是硬要求**：需求总缺口必须与市场面板**用同一个式子**。
两处口径不同会出现「市场面板说 −90、社会面板说 −40」这种**同屏自相矛盾** ——
两处都"有数"，最难查（本线在市场面板的净值上已经踩过一次同类坑）。

⚠ **市场准入按"实例"读、面板按"defName"看**：该 def 尚无实例时**不画这一行**，
而不是编一个"未知"出来 —— 「不知道」不得伪装成「未知状态」。

⚠ **旧 lore 键保留在语言包**以便恢复；派系 lore 现由**上方裁决段**承载（没有丢）。

### 一处刻意的代码放置（可复用的工程手法）
`AppendDynamicMarketTraits` 放在 **`BuiltinEconomyProvider.MarketPanel` 分部**，
而**不是**调用它的 `Society` 分部 —— 因为 `MVSCommodityDef` / `FactionCommodityVisibility` /
`CommodityMemberPicker` 的 `using` 在 MarketPanel 文件里，而 **using 是按文件生效的**。
📌 **同一个 partial 类的不同分部可以按"依赖就近"分工**：需要哪些命名空间，代码就放哪个分部，
而不是把 using 复制到每个分部。调用点只传参数，不引入任何新类型。

## 实机验证建议（重启后）

| 项 | 怎么看 |
|---|---|
| **人数右置** | 人口规模条内的「≈862 人 ③」应在**条右侧**，左端留空（不再压住填充起点） |
| **缺口一致** | 市场面板的「净值」与社会面板的「需求总缺口」应**互为相反数**（同式同数据） |
| **库存为真值** | 「供应库存」应随殖民地的实际库存变化（搬走/用掉物品后应减少） |
| **准入随关系变** | 与某派系开战后重开面板 ⇒「市场准入」应变为「敌对 · 不可进入」 |
| **无实例不画** | 从未接触、世界未生成完的派系 ⇒ **不应出现「市场准入」这一行** |
| **回归** | 市场面板各列数值与汇总应与本批之前**一致**（本批不动市场面板逻辑） |
