## 本批修了什么（12 项，按审计编号）

### 🔴 P0（2 项）

**1. `KpiGrid` 裁剪栈不入 finally（审计 §1.2）**
`BeginGroup` / `BeginScrollView` 直接写在 `try` 体里、`End` 在尾部 —— 任一次绘制抛异常
（RUIF 是外部依赖，`RuifBridge` 全方法带 try 正说明它会抛）⇒ **两者都不执行**
⇒ **Unity GUI 组栈与裁剪栈永久失衡**，此后所有窗口错位、整帧异常。
⇒ 改为**状态变量记住开了几层、在 finally 里逆序闭合**（与同工程 `ArchiveEmbeddedHost` 同范式）。
📌 这是"一处坏拖垮整个 UI"里**最难恢复**的一种：它不会自己好。

**2. 市场面板「均价」与行「价格」是两套算法（审计 §1.1）**
- 行价格 = **运行时市场因子**（② 真实读数，事件冲击累积）
- 汇总「均价」= **总需求 / 总供应**（③，由 Def 基线算出）
两者并列却都叫"价"，读者必然以为是聚合 ⇒ 极端情形列内全是 `1.00 ±0%` 而汇总 `1.60 ▲+60%`。
⇒ **改名为它实际是的东西：「供需比」**。
📌 **标签跟着值走** —— 不是改值去迁就标签。改标签是零行为风险的那一侧。

### 🟡 P1 便宜项（3 项）

**10. 段头补悬停（审计 §2.2 —— 系统性缺口）**
`SectionHeader` 是"口径注 / 数据级别"的唯一载体，此前**完全没有悬停**（全工程 43 处截断只有 7 处挂悬停）。
⇒ 给共享组件加 `tip` 参数，并**自动把被截断的 label / note 原文并入**。
📌 修在**组件层**而不是逐个调用点 —— 这才是"治系统性缺口"。

**11. `ClickableCard` 的 ▶ 是假热区（审计 §2.4）**
原顺序：先 `ButtonInvisible(rect)`（**整卡含箭头条**）⇒ 事件已被消费 ⇒ 后面箭头判定**恒 false**
⇒ 画出来的 ▶ **看得见、点不到**；真实入口是**没有视觉提示的右键**。
⇒ 改为**先判箭头区**，判卡身时自然排除它。工程自己的问题记录早已承认这条。

**12. RUIF 门控双标准（审计 §2.8）**
9 处图表桥只读字段 `available`、**不触发惰性探测** ⇒ RUIF 晚加载时图表**本会话永久不可用**且无日志。
⇒ 全部改为走 `Available` 属性（带 2s 节流重试）。已 grep 确认无残留。

## 实机验证建议（重启后）

| 项 | 怎么看 |
|---|---|
| **头号：环形图 5 段可辨** | 成员构成的环形图，**相邻扇区颜色必须都不同**（改前第 1/4/5 段同色） |
| **悬停 = 归属正确** | 悬停「市场规模」段头 ⇒ 只看规模明细（据点/人数/份额）；悬停「市场特征」段头 ⇒ **只看四个影响因子** |
| **降级标题** | 无权重派系 ⇒ 段标题应显示「**据点规模**」而 caption 显示「N 处」（两者必须同口径） |
| **供需符号一致** | 市场面板「净值」与社会面板「供需净值」应**同为 供应−需求**（不再互为相反数） |
| **均价不再冒充价格** | 市场汇总第 4 项应显示「**供需比**」，不再叫「均价」 |
| **卡片 ▶ 可点** | 点卡片右侧 ▶ 应触发跳转（改前恒无反应）；点卡身其余处仍为原行为 |
| **RUIF 图表** | 装 RUIF 且晚加载时，图表/统计表应在数秒内**自愈**（改前本会话永久不可用） |
| **P0 不崩** | 任一页抛异常时，**整页仍可交互**、日志有记录（改前会丢帧/栈失衡） |
