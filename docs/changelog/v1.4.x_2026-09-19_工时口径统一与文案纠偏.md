## [开发线] 2026-09-19

### 一、🔴 `2400` —— 注释里的算术本身就是错的

```csharp
// 旧（ArchiveUiDataProvider.Career.cs）
// 相关工时：按事件首末 tick 跨度（60000tick ≈ 25h → 1h ≈ 2400 tick）。
int hours = (int)(spanTicks / 2400L);
```

**「60000tick ≈ 25h」是笔误** —— 原版 1 天 = 60000 tick = **24** 小时 ⇒ 1h = 60000 / 24 = **2500**。

⇒ 该处工时**系统性偏高约 4.2%**（2500/2400 − 1），且与同工程 `PawnMedal.cs` 的
`GenDate.TicksPerHour` 口径不同 ⇒ **同一人物在两个界面算出不同的工时**。

**修法**：改用 `GenDate.TicksPerHour`（三处收口到同一常量）。

### 二、🟠 `2500f` 字面量 —— 值是对的，但违反了工程自己的铁律

```csharp
// 旧（Archive/ITab_Pawn_Chronicle.cs:438）
float hours = (float)b.Ticks / 2500f;
```

数值恰好正确，但本工程自己在 `PawnOverview.cs` 声明过「**禁止硬编码 2500**」。
⇒ 改走原版常量后，`Career.cs` / `PawnMedal.cs` / `ITab_Pawn_Chronicle.cs` **三处同源**，
原版若调整时间刻度也不会漏改。

### 三、🟠 资历悬停的「制造 5 次（5 h）」—— 两个数永远相等

`CareerSpanBreakdown` 对**每一条事件**都做 `Hours += 1`，于是悬停里
`• 制造 5 次（5 h）` 的"次"与"h"**永远相等**；`SpanBreakdown` 的字段名虽叫 `*Hours`，
实际是计数。

#### ⚠ 审计对此条的描述**不准确**，本次已澄清（写进代码注释）

审计原文是「每一条事件记 1 小时 ⇒ 事件数冒充时长」。实情更细 —— 上游
`ArchiveService.Career.cs:596-598` 明确写着：

> BE-005 基础劳作事实源：WorkCompleted 量子派生。每累计 `WorkCompletedQuantumTicks`
> （=游戏 1 小时）工作记 1 条事实，**与 UI「每事件=1h」口径一致**（CareerSpanBreakdown 每事件记 1h）

⇒ **`WorkCompleted`（走在 `default` 分支）的"每事件 = 1h"是正确的量子化**，而且是**有意设计**。

**真正的问题**：`ItemProduced` / `ConstructionCompleted` / `ResearchCompleted` / `BookProduced`
是**完成瞬间的事实**，与时长无关 —— 把五类混在一起再统一标成"小时"才是错的。

**修法**：`SpanBreakdown` 只保留 `*Count`（删掉 4 个 `*Hours` 字段）；
`CareerSpanBreakdown` 只计次数；悬停文案改为「资历来源（按事件类型的**完成次数**）」
（中英同步，占位符由 12 个减为 8 个）。**不再展示任何小时**。

> **分项真实时长**需要 `WorkTimeAccumulator` 的按工种 tick 累计（该面另有持久化数据）
> ⇒ 已登记为**后续接入口**，不在本次范围。

### 四、🟠 「净值」这个标签装的是「近 30 天产出」

```csharp
// Archive/ITab_Pawn_Chronicle.cs:465-471
string weekVal  = ...snap.WeeklyProductionSilver...;   // Kpi.WeekOutput → 「周产出」 ✓
string monthVal = ...snap.MonthlyProductionSilver...;  // Kpi.NetValue  → 「净值」   ✗
```

那个格子**没有扣任何东西**，就是近 30 天的产出折算银币 —— 中文「净值」/ 英文 "Net value"
都在暗示"净额"。而屏幕另一处（`PawnMedal` 的算式带）的「**净收益**」才是真扣了人力成本的净值。

⇒ **两处「净值」同名不同义**（审计登记项）。修法极简：`Kpi.NetValue` 中文改「**月产出**」、
英文改 "**Month output**"，与兄弟项「周产出」成对 ✓ 撞名问题随之消失。

### 五、❎ 复核后**不改**的一条：`NetLedgerHourlyCostRate = 2f`

审计把它列为「硬编码参与派生结论」。复核结论是**过度报告**：
- 它**已经是**命名常量 + GOV-006 注释（不是散落魔法数字）；
- UI 单位明确标着「银（**估**）」，且子行直接展示成本算式 ⇒ **玩家知道这是估算**；
- 真正的病是"同名两口径"，已由第四节解决。

⇒ 保留不动。**理想形态**是把它 Def 化以便免编译调整 —— 登记为后续项，非缺陷。

## 残余风险 / 已知降级

1. **⚠ Keyed 占位符变更**：`PersonalChronicle.UI.Career.Qual.Tooltip.Time` 的占位符由
   `{0}..{11}` 减为 `{0}..{7}`。**若任何第三方语言包覆写了这条键，会因占位符不足而显示异常**
   ⇒ 已在中英两份同步改；这属"展示层文案调整"，但**换语言包时需注意**。
2. **`Kpi.NetValue` 改文案后**：其他语言包若覆盖该键会显示旧词（英文/中文已同步）。
3. **工时数字会变小**（−4.2%）：这是**修正**不是回归；若此前有人拿旧数字做过对照，需知悉。
4. **未实机验证**（与 004~009 同批待验）。验证点见下。
5. **分项真实时长仍未接入**（见第三节）—— 现悬停只报次数，是**诚实但信息更少**的形态。
