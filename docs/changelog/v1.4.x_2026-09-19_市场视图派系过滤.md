## [开发线] 2026-09-19

### 一、核心设计：**零编造** —— 用真实 `ThingDef.techLevel`，不给品种手工声明档位

§10-1 的原文是"用画像 `techLevel` + `pawnGroupMakers` 推导该派系触碰的 `MVSCommodityDef` 子集"。
最直觉的实现是给每个品种**手工声明一个科技档**（如 `<minTechLevel>Industrial</minTechLevel>`），
但那意味着**18 个 ③ 假设值**。

⇒ 本批改用**真实数据推导**，一个编造值都不引入：

```text
品种对该派系可见  ⟺  其命中集（MVSCommodityRegistry.ThingsOf）里
                     存在至少一个物品满足  ThingDef.techLevel <= 派系 techLevel
```

- 这与原版 `StockGenerator_Category.HandlesThingDef` 判定链的 `t.techLevel <= maxTechLevelBuy`
  **同一形状** —— 我们不是发明规则，而是把原版已有的那一环**下沉到消费侧**
  （`MVSCommodityRegistry` 的架构部裁定明确要求如此："全局索引刻意不做 techLevel 过滤，
  因为 `maxTechLevelBuy` 是单派系买家语义，塞进全局索引会造成索引对立"）。
- **为什么用「存在」而不是「全部」**：品种是**品类聚合**，够得着其中任意一项它就在市场里；
  用「全部」会得出荒谬结果（基础原料含钢铁 ⇒ **部落连木材都看不到**）。
- **实测数据**：`MedicineHerbal.techLevel = Neolithic`
  （`Core/Defs/ThingDefs_Items/Items_Resource_Manufactured.xml`，**已读原文核实**）。

### 三、另一处**测试抓到的边界**：Ultra ≠ 全知

`IsVisible_UltraFaction_SeesEveryLevel` 最初写成"含 Archotech 全可见"，**测试自己红了**。

规则是**阶梯比较**，不是"最高档特权"：`Ultra(6) vs Archotech(7)` ⇒ `7 <= 6` 为假
⇒ **Ultra 派系够不到 Archotech 档物品**。

⇒ §10 说的「Ultra 全显示」应理解为"全显示**其能力范围内的**"。已把该边界改写为**显式断言**，
免得后来者按直觉把比较改成 `>=` 或加"最高档豁免"。

### 四、实现要点

1. **🔴 第三处「丢弃画像」被用起来**：`BuildMarketPanel` 原先写
   `out FactionArchetypeData _` —— **画像取了就丢**，只当布尔门禁用。现在真正消费它
   （`profile.TechLevel` 是过滤判据）。这是本工程第三处同一模式
   （前两处：社会背景面板 chips、价格块前的 `AppendMembers`）
   ⇒ **凡见 `out Xxx _` 都应该问一句"这个值本来就该用吧"**。

2. **`TechLevelBridge`（新）—— 双向枚举桥，消除重复**：`FactionProfileAdapter` 原有一个私有
   `ToArchetypeTechLevel`（正向）。过滤需要**反向**映射，若在别处再写一份正向就是
   **同功能两处实现**。现把两个方向收进 `MVS/Data/TechLevelBridge`（Application 向下引用 Data 合法），
   **并删除私有副本**。
   ⇒ 两个方向**必须成对维护**：分开放会让"加了一个 `case` 却只加在一侧"成为可能，
   症状是「画像里是 Medieval，过滤时按 Industrial 判」—— 无报错、极难定位。

3. **`CommodityVisibility`（Domain 纯函数）—— 未知档位两个方向都 fail-open**：
   - 派系档未知 ⇒ 判可见（否则**整个市场表**会因一个未映射枚举值而静默清空）
   - 物品档未知 ⇒ 判可见（否则**静默隐藏**未声明 `techLevel` 的第三方物品）
   ⇒ 与"缺口如实、禁止静默截断"同向：**不拿"未知"当"不可见"**。

4. **三个供需列画「不涉及」，价格列照常画**：
   - 留空会被读成"渲染坏了/数据没加载"—— 这正是 `CHG-20260919-ECON-UI-005` 里
     你判定「没有细分数据」的成因。**「不涉及」才读作"该品种不在这个派系的市场里"**。
   - **价格列不抹**：因子是**全球**品种读数，与该派系是否参与无关 ——
     "这个派系不买卖它" ≠ "全球市场没有它"。抹掉等于丢信息。

5. **`.msum` 汇总只累加参与品种**：把"该派系根本不碰的品种"算进总产量，
   会让同一个数字同时说两件事（全球存在量 vs 该派系市场量），而副标已声明口径是"该派系的市场"。

6. **说明放在副标，不往品种列塞字符**：品种列已到临界宽（2026-09-19 实测定标：Top-3 会被硬切
   且 `+N` 丢失），为解释再加字符只会让主信息更看不见。⇒ 副标追加一句
   `· N 个不涉及（该派系科技档位不含）`。

## 实机验证建议（重启后）

| 项 | 怎么看 |
|---|---|
| **部落（Neolithic）** | 市场表里「药品」**应仍然可见**（草药是 Neolithic）；而**成瘾品 / 义体 / 炮弹 / 武器** 等超档品种的三个供需列应显示「不涉及」 |
| **帝国（Ultra）** | 绝大多数品种可见；若某品种含 Archotech 档物品且无更低档物品，该品种应显示「不涉及」 |
| **副标** | 应形如 `品种 18 · N 个不涉及（该派系科技档位不含）` |
| **汇总行** | 总生产 / 总消费**不含**不涉及品种（数值应比改前更小） |
| **价格列** | 不涉及品种的**价格列仍应显示**因子（不是「不涉及」）—— 全球读数与派系无关 |
| **未建模派系** | 仍走"未建模"裁决，不受本批影响 |
