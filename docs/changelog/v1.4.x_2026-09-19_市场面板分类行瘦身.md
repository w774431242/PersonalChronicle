## [开发线] 2026-09-19

### 根因：分类行把**二级品种名**拼进了**一级标题**

```csharp
// EconomyMarketPanel.ComposeCommodityCell（改前）
string text = row.Name + row.LevelText;
if (!expanded && !string.IsNullOrEmpty(row.MemberText))
{
    text = text + "·" + row.MemberText;   // ← 「基础原料·钢铁/布/零部件 +15」
}
```

`MemberText` 是 Provider 侧拼好的**成员名摘要**（取前 N 个 + `+N`）。
它被拼进**收起态的分类行**，于是：

- 分类行实际显示的是「**分类名 + 一串二级品种名**」⇒ 正是用户说的"一级分类标题含有二级品种名字"
- 品种列本来就吃紧 ⇒ **分类名自己反倒被挤到截断**（本末倒置：一级标题为二级内容让位）

而代码里那段注释（`MemberSampleCount` 的实测定标说明）其实**记录了这个问题的历史**：
首版取 3 个名字被截图证伪（中途硬切、`+N` 看不见）⇒ 降到 2 —— 但**真正的问题不是"取几个"，
而是"根本不该在这里出现名字"**。

📌 **教训**：当一段文案反复调参（3 → 2 → …）仍被实测证伪时，
应当质疑**它该不该出现在这个位置**，而不是继续调参。参数调不动的问题往往是层级问题。

### 改法：只保留「数」，名字走展开与悬停

| | 改前 | 改后 |
|---|---|---|
| 分类行 | `基础原料·钢铁/布/零部件 +15` | `基础原料·12` |
| 成员名（逐项） | 展开后逐行 | **不变** ✓ |
| 成员名（全量） | 悬停 | **不变** ✓ |

⚠ **保留一个可见数字而不是全删**：分类行若只剩名字，玩家无从判断"这个品种是一条还是二十条"，
而**展开符只说明"可展开"、不说明"有多少"**。
⚠ 成员名仍有两处可达 ⇒ 这是"信息移位"而不是"信息减少"，**不构成静默丢弃**（LAND）。

### 顺带删除的采样逻辑

`MemberSampleCount = 2` 与 `JoinMemberNames(…, take)` 的**采样模式**一并删除 ——
采样**只服务于摘要**，摘要没了它就是死代码。
（该方法仍保留"全量"用法，供 `MemberTipText` 使用。）

### 契约字段语义变更

`EconomyMarketRow.MemberText`（`string`，名字摘要）→ **`MemberCount`**（`int`，成员数）。
**字段名与类型一起改**：语义变了名字必须跟着走（本线第四次同纪律：
`具体人数→据点规模`、`社会结构占比→成员构成`、`Settlement→Bar`、`MemberText→MemberCount`）。

## 实机验证建议（重启后）

| 项 | 怎么看 |
|---|---|
| **头号：分类行变短** | 收起态的分类行应形如「基础原料**·12**」——**不应再出现任何物品名** |
| **分类名可见** | 分类名本身**不应再被截断**（改前它被成员名挤掉） |
| **展开仍可用** | 点击展开 ⇒ 成员逐行显示（与改前一致） |
| **悬停仍给全量** | 悬停分类行 ⇒ 完整成员清单（与改前一致） |
| **无成员的行** | 命中集为空的品种 ⇒ 不显示 `·0`（只显示分类名） |
| **回归** | 供需/单价/汇总各列数值应与本批之前**一致**（本批不动任何数值） |
