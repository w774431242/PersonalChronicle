## [开发线] 2026-09-19

### 设计：为什么"点击展开"是对的问题的最优解

上一轮（`CHG-20260919-ECON-UI-003`）把品种列改成 `分类 · 物品样本` 后，实测暴露两个残余问题：
① 列宽临界 ⇒ 物品名被硬切、`+N` 多数看不见；② **RUIF 渲染路径不回传行矩形 ⇒ 悬停全量清单根本不可用**
（而实测截图走的正是 RUIF 路径）。

**点击展开同时解决两者**：展开后每个物品**独占一行**，宽度问题彻底消失；而展开只依赖
「行矩形 + 坐标」——那是我们自己算的，与 RUIF 无关。

### 实现要点

1. **可见行映射**（本次的架构核心）：展开把「品种行表」变成「品种行 + 成员子行」的混合表，
   于是**三处**都必须经过映射，不能再用 `snapshot.Rows[i]` 直接索引：
   - 单元格内容（父行走品种数据，子行只走物品名）
   - 语义色（子行走 `Dim`，不继承父行的涨跌色）
   - 命中检测（只有父行可点）
   ⇒ 新增 `visibleRowParent[] / visibleRowChild[]`（绘制期复用缓冲，与 `rowBuffer` 同族）。

2. **命中检测必须在内容坐标系里做**：滚动分支下 `content` 由 `BeginScrollView` 提供，
   行矩形随之落在内容坐标。在视口坐标里检测（拿外层 `rect`）会在滚动后整体偏移 ——
   这是「点不动 / 点错行」的头号根因，**且只有 scroll=0 时看起来是对的**，最难查。
   RUIF `StatTable` 的契约明确写着「不读 `Mouse`/`Event`，交互由调用方在 rect 上自判」
   ⇒ 本检测是唯一路径，不存在重复消费。

3. **状态归调用方**（绘制规范「第一原则」第 3 条：组件自身零状态）：
   `Draw` 新增 `HashSet<int> expandedRows` 形参，调用方 `MasterControlTabWindow` 用
   **窗口实例字段**持有 —— 与同处的 `economyMarketScroll` 完全同规（该字段的既有注释已写明
   「放窗口实例字段而不是面板静态字段（GATE-UI：UI State 不持持久状态；ARC-008：避免静态可变状态）」）。
   键用**品种行下标**而非显示名：显示名随语言切换而变（用它会让切语言后展开态集体失效）。

4. **可发现性**：有成员可展开时才画指示符 `▶` / `▼`，无成员则不画、**也不响应点击**
   （画了符却点不动 = 反劣质清单里的"点了没反应"）。字形取 `\u25BC` / `\u25B6` ——
   前者已被本工程实机截图证实可渲染（`EconomyMarketFormat.FormatChange` 的涨跌箭头同字符）。

5. **展开时隐去样本摘要**：成员此刻已在下方逐行列出，摘要（前 2 项 + 剩余计数）变成冗余，
   而品种列宽度本就吃紧。收起态保留摘要 —— 因为它是**唯一**能提示"这品种还包含别的东西"的信号。

6. **子行降调**：子行没有自己的供需/因子数据，用正文色会让人误以为它是独立品种 ⇒ 走 `Dim`。

7. **一次取名、三处共用**：Provider 侧只对命中集取一次 `LabelCap`，展开逐行 / 悬停全量 /
   折叠摘要共用同一份来源与顺序。分头各取一次会出现"摘要里有、展开里没有"这类无法解释的不一致。
   快照新增 `MemberNames: List<string>`（必须是**列表**：逐项成行需要结构化数据，
   靠再拆字符串会在"物品名恰好含分隔符"时出错）。

8. **抗卡死保险**（铁律 3）：子行索引越界时降级为空行而**不是抛异常** ——
   未捕获异常逃出 `DoWindowContents` 会让 `BeginScroll/EndScroll` 与 GUIClip 出入栈失衡 ⇒
   **整局 GUI 卡死（无法行动）**。一次 int 比较换这个保险，不能省。

## 残余风险 / 已知降级（诚实登记）

1. **⚠ RUIF 路径无法按行关闭阈值带色**：`bandCol` 是**整列**参数。子行本不该有价格单元格，
   但 RUIF 的 `TableFmt.BandTextOf` 在 `bandTexts[r]` 为空时会**回退成 bandValue 的 `"0.#"` 格式化**
   ⇒ 子行会凭空冒出一个 `1`。故子行传**单空格**（非空且视觉为空），代价是该格仍会画一枚
   **中性底色药丸**。要根治需给 RUIF 增加"按行跳过带色"的能力（跨仓库改动，未做）。
2. **RUIF 路径仍无悬停**：`StatTable` 不回传行矩形 ⇒ 全量清单的悬停只在 D2 自绘路径可用。
   展开功能**不依赖**它（这是本次的主要目的），故该降级的影响已被大幅削弱。
3. **子行不可点**：点子行不响应（避免"想看某物品却把整组收掉"的误触）。若将来要支持
   「点物品看它的详情」，需要新的交互面。
4. **1 帧滚动量滞后**：点击改变展开态后，本帧的滚动内容高仍按点击前的行数算（因为命中检测
   只能在 `BeginScrollView` 之内做，而 `needed` 在它之前就要定）。1 帧 ≈ 16ms，肉眼不可见。
5. **⚠ 无键盘路径（a11y 缺口）**：原版 IMGUI 的 `TabRecord` 轮转只覆盖 tab 条，
   经济中心五面板目前都只有鼠标路径。加键盘导航需要一个**跨面板的焦点环设计** ⇒
   **超本次范围，登记不假装解决**。
6. **工作量闸门 48 → 256**：展开后可见行可达 256（18 品种 + 6 个满员品种）。
   最坏情况 = 每帧 5 × 256 = 1280 次单元格绘制。典型用法（展开 1~3 个品种 ≈ 80 行 ≈ 400 格）
   远低于此，且超出 256 时走既有 `+N` 提示（工作量闸门语义，非静默截断）。
   ⚠ **实机需确认展开 6 个满员品种时的帧率**。
7. **展开态对 Def 顺序的依赖**：键是行下标 ⇒ 若用户中途增删 Mod 导致品种重新排序，
   展开态会指向别的品种（不崩、不错位，只是"展开的不是原来那个"）。
   Def 变更需重启游戏才生效，且此时用户多半也没保持展开态 ⇒ **接受**。
8. **未做游戏内实测**：编译 / 单测 / 两区一致已验证，但「点击是否落点准确」「展开符字形是否可渲染」
   需实机确认（尤其 `\u25B6`；若显示为方框，换成 ASCII 的 `+` / `−`，两者同样已实证）。
