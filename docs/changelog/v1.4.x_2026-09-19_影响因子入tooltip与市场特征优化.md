## [开发线] 2026-09-19

### 要求 A-1：影响因子进 tooltip（顺带消掉一处**无归属**元素）

那 4 枚 chip（产能 / 进口 / 奢侈 / 冲击）原先**悬在规模条与"市场特征"段之间、没有任何归属段落**
（用户截图可见）—— 问题不只是"占位"，而是**它不属于任何一段**，读者无从判断它是规模的一部分还是市场的一部分。

⇒ 移入**规模条的 tooltip**，与规模明细之间用**空行分隔**（两组性质不同，不分隔会让读者把
「产能系数 ×1.3」当成第三个规模指标）。

**同时删掉了整条 chip 渲染链**（`DrawChips` / `MeasureChipsHeight` / `ChipNeedsWrap` + 三个常量 +
计划行 + switch 分支）：`Chips` 现在**恒为空** ⇒ 这是**真正的死代码**，不是"暂时用不上"。
保留它只会让下一个人误以为还有一条可恢复的渲染路径。

### 要求 A-2：规模条主口径改**总人数**（③）

- **caption** 改为总人数（`{0} 人 ③` —— **③ 标记写进模板**，不靠调用点自觉）
- **段标题**「据点规模」→「**人口规模**」：**标题必须跟着值的语义走**，
  否则就是"据点"下面挂着"人数"的类别错配（与本线既有的「具体人数 → 据点规模」同一纪律）
- 🔑 **份额怎么算才不用先求"全世界总人口"**：估算人数 ＝ `据点数 × K × 归一化权重`，
  而 **K 是全局常量** ⇒ **求比值时约掉了**！于是"人口质量" ＝ `Σ(该派系每个据点的 owner 权重)`，
  与 K 无关，可在**同一次据点扫描**里累加得出（PERF-001：不为拿分母再扫一遍全库）
- ⚠ **两个口径并存、互不冒充**：tooltip 同时给**人口份额 ③** 与**据点份额 ②**；
  caption 与条的份额**必须同口径**（条画的是甲、字写的是乙就是欺骗）
- ⚠ **无权重 ⇒ 退回据点口径**（②配②），而不是画一条没有含义的条
- ⚠ 无主据点与**无权重派系的据点**在"人口质量"里**两边都不进** —— 计入分子会低估、计入分母会高估

### 要求 B：市场特征结构优化（直接针对截图里的截断）

| # | 原实现 | 现实现 |
|---|---|---|
| ① | 问题列宽**写死 74px** ⇒ 中文「门槛 · 敏感度」正好被压到截断，答案列因此更窄 | **按最长问题实测**（上界 34%、下界 56px），省下的宽度让给答案 |
| ② | 答案**单行硬截断**（截图：「科技越…出制成品」） | **两行换行** —— 截断的内容只能是"看不到"，换行至少让人读到完整一句 |

⚠ 仍保留**完整文本悬停**：`DrawWrapped` 超过两行时照样截断 ⇒ **截断必须配补偿**（LAND）。
⚠ 问题列宽在 `BuildPlan` 里**算一次**、绘制时复用（`qaQuestionWidth`）—— 绘制端若另算一次，
测量与绘制就会各测一套，症状是行高差几像素、底部被切（本文件开头那段纪律说的正是这个）。

### 顺带修的一个字段名与语义不符

规模条的份额字段原叫 `SettlementShare01`，现在**优先表示人口份额** ⇒ 更名 `BarShare01`/`HasBarShare`。
**名字必须跟着实际语义走**，否则下一个人会理所当然地以为它恒是据点口径。
（这是本线第三次应用同一条纪律：`具体人数→据点规模`、`社会结构占比→成员构成`、`Settlement→Bar`。）

## 实机验证建议（重启后）

| 项 | 怎么看 |
|---|---|
| **无悬空 chip** | 规模条与「市场特征」之间**不应再有任何 chip** |
| **规模条** | caption 应是「≈213 人 ③」形式（**总人数**，不再是「30 处」）；段标题应为「**人口规模**」 |
| **tooltip 三段** | 悬停应看到：规模明细 / 空行 / 「影响因子（③ 设计假设）」+ 四条系数 |
| **份额同口径** | 条填充比例应与 tooltip 的**人口份额**一致（不是据点份额） |
| **降级** | 无权重派系 ⇒ 条退回据点口径（caption 显示「N 处」）；两者都不可算 ⇒ **不画条** |
| **市场特征** | 三条答案应**换行显示完整句**，不再出现「科技越…出制成品」这种中段省略 |
| **回归** | 市场面板可见品种与供需数值应与本批之前**一致**（本批不动四系数） |
