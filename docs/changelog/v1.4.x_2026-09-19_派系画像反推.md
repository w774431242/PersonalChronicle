## [开发线] 2026-09-19

### 一、🔴 根因：**反推出来的数被丢掉了**

```csharp
// 旧（BuiltinEconomyProvider.Society.cs，画像只用来做布尔判断）
|| !MarketContracts.Factions.TryGetProfile(selectedFactionDefName, out FactionArchetypeData _))
                                                                             //  ↑ 丢弃
```

`FactionArchetype.ForTechLevel` **已经按科技档位算好了每个派系的 4 个系数**
（`ProductionFactor` / `TradeImportFactor` / `LuxuryPreference` / `ShockSensitivity`），
但取出来就丢了 —— 面板画的是**硬编码 Keyed 文案**：

| 派系 | 面板显示 | 实际画像 |
|---|---|---|
| 帝国（Ultra） | `Royal.Chip1 = 「产能过剩 ×1.5」` | `ProductionFactor = 1.5f` |
| 其他 | `Generic.Chip*.` **没有数字** | `0.7 ~ 1.6` **各不相同** |

⚠ **帝国那张看着对纯属巧合** —— 文案与系数同源（都照方案 §11.7.5 抄的），所以没人发现面板根本没在用它。
其他派系的模板里没有数字，于是表现为用户反馈的「数据没有反推」。

⇒ **诚实地说：这不是"没反推"，是"反推了但没用"。** 结论对用户的观感是同一回事。

### 二、修复：chips 与规模块改为真值驱动

**① 5 枚 chips 全部来自 `FactionArchetypeData`**（新增 5 个模板键）：

| chip | 值源 |
|---|---|
| 科技档位 {0} | `profile.TechLevel` → `MVS.Economy.Tech.*`（8 档显示名**早已存在**，此前从未被这个面板用过） |
| 产能系数 ×{0} | `profile.ProductionFactor` |
| 贸易净进口 ×{0} | `profile.TradeImportFactor` |
| 奢侈偏好 ×{0} | `profile.LuxuryPreference` |
| 冲击敏感 ×{0} | `profile.ShockSensitivity` |

⇒ 效果：部落（Neolithic）显 `×0.7 / ×1.25 / ×0.3 / ×0.85`，外来者（Industrial）显 `×1 / ×1.1 / ×1 / ×1`
—— **各派系明显不同**，且**改画像即改显示**（不再需要同步改两份文案）。

**② 规模块改为运行时真值**：原 Generic 模板的 `Population.Value = 「运行时计数」`
是**把方法名当答案画出来** —— 玩家读到的不是数字。现填该派系**真实的据点数量**
（`Find.WorldObjects.Settlements` 按 `FactionDef.defName` 计数）。

**③ 段标题跟着值的语义走**：`具体人数` → **`据点规模`**（新增 `Scale.Title`）。
标题不跟着改就是"人数"下面挂着"据点个数"的类别错配。

**④ 合并两条重复分支**：原先 `Royal` / `Generic` 是两份约 40 行**逐字重复**的 if/else
（"同功能两处实现"—— 改一处忘另一处），差别只有 tier 条数与 Q/A 键前缀。现合并为一条渲染路径，
差异用 `tierCount` 表达。

### 三、⚠ **没有**反推的三块（如实登记，不假装）

| 项 | 为什么不做 |
|---|---|
| **阶级分布（层数 / 占比 / 人数）** | 原版**没有社会分层字段**，也无法从任何 Def 推出层级占比。`pawnGroupMakers` 给的是"**出兵构成**"，与"人口分层"不是一回事 —— 硬折算等于编造（工程红线）。故这 N 条**保留模板文案**，代码注释已写明"这是设计假设，不是运行时读数" |
| **人口数** | 原版据点在玩家进入前**不生成地图**，没有"驻留人口"字段。`Royal` 模板写死的 `45 人/据点 × 社会因子 1.58` 是**设计常量**而非读数 ⇒ 不填 |
| **多层星球** | `WorldObjectsHolder.Settlements` 只覆盖**当前星球表面层**；Odyssey 多层的其余层不计。同族 API `AllSettlementsOnLayer(PlanetLayer)` 可逐层取，但"跨层求和是否该合并"属**产品口径问题** ⇒ 登记不擅自决定 |

> **判据**：**能从权威数据反推的 → 反推**（chips / 据点数量）；
> **需要假设才能得到的 → 不填或明确标注为假设**（阶级分布 / 人口）。
> 这条线画在这里，是因为跨过去就是编造。

### 四、API 核实（本工程铁律：先证后用）

新增了一个数据源（据点计数），按纪律用 Mono.Cecil 静态核实，**并纠正了一次命名空间猜测**：

| 事实 | 结果 |
|---|---|
| `Find.WorldObjects` | ✓ `WorldObjectsHolder WorldObjects { get; }` |
| `WorldObjectsHolder` 的命名空间 | ⚠ **不在 `RimWorld`**，在 **`RimWorld.Planet`**（首次按 `RimWorld.WorldObjectsHolder` 查是 `NOT FOUND`） |
| `WorldObjectsHolder.Settlements` | ✓ `List<Settlement> Settlements { get; }`（另有 `SettlementBases` / `DestroyedSettlements` / `AllSettlementsOnLayer`） |
| `Settlement` | ✓ `RimWorld.Planet.Settlement`，继承链上带 `Label` |
| `WorldObject.Faction` | ✓ `Faction { get; }`（**public virtual，可为 null** ⇒ 已逐项守卫） |

## 残余风险 / 已知降级

1. **⚠ 未实机验证**（与 004~012 同批待验）。本批的头号验证点：**切到不同派系看 chips 是否跟着变**
   （部落 vs 外来者的四个系数应明显不同）。
2. **据点数在无世界 / 无派系时为 `0 处`**：这是**真值**（确实没有据点），不是空态。
   若某派系尚未在星球上生成据点，显示 `0 处` 是对的。
3. **`0` 与"读不到"的区分**：`Find.WorldObjects == null`（极端早期）也返回 0 ⇒
   与"确实没有据点"同形。**已知取舍**：该分支只可能出现在世界尚未初始化的瞬间，
   而那时整个经济中心都不会被打开。**登记不修**。
4. **旧 Keyed 键成为死键**：`Royal/Generic.Chip1-5`（10 键）与 `Population.Title` / `Population.Label` /
   `Population.Value`（6 键）不再被引用。按工程惯例**保留以便恢复**，已在本 Changelog 登记。
5. **`MVS.Economy.Tech.*` 的 8 档显示名此前从未被社会背景面板使用** —— 本轮起才真正用上；
   其余面板（若也用科技档位）应复用同一组键，**不要新造**。

## 实机验证建议（重启后）

| 项 | 怎么看 |
|---|---|
| **chips 随派系变化** | 依次选中**部落 / 外来者 / 帝国**：「社会背景」段的 5 枚 chips 应显著不同（部落 `产能系数 ×0.7`、外来者 `×1`、帝国 `×1.5`） |
| 科技档位 | chip 第 1 枚应为「科技档位 新石器 / 工业 / 极致」（**不再是空白**） |
| 据点规模 | 段标题应为「**据点规模**」，值形如「3 处」；换派系时应跟着变 |
| 阶级分布 | 仍显示模板分层（**这是设计假设**，不是本轮反推项）—— 不应出现空白或键名 |
| 未建模派系 | 选海盗 / 机械族等（`permanentEnemy` / 非人类）应仍走「未建模」裁决，**不是**本轮改动目标 |
