### 二、交付内容（T2：人数模型）

**数据流**（单向、分层）：

```text
FactionDef.pawnGroupMakers ─┐
                           ├─► MVS/Data/FactionScaleReader（认识 Verse）
Find.WorldObjects.Settlements ┘        │
                                       ▼
               MVS/Domain/FactionScaleModel（纯函数：归一化 + 估算）  ← 可离线单测
                                       │
                        IFactionScaleProvider（新契约）
                                       │
                        FactionScaleAdapter（Application 侧薄适配器）
                                       │
                        MarketContracts.Wire（组合根装配）
                                       │
                        BuiltinEconomyProvider.Society → 快照 → EconomySocietyPanel
```

**实例化的设计决策**：

1. **新增独立契约 `IFactionScaleProvider`，不并进 `IFactionProfileProvider`**
   —— 后者是 **Def 静态反推**（同一 `FactionDef` 恒得同一结果，与世界/存档无关），
   前者是 **世界运行时**读数（据点被毁即变）。**生命周期不同**，合并会把 DATA-001 的
   Def/Runtime 边界在同一 DTO 内抹平。副作用（正向）：只关心画像的消费方不必被迫依赖世界读数（ISP）。

2. **`TryGetScale` 的 `false` 表示"Def 不存在"，不是"没数据"**
   —— 与"Def 存在但据点为 0"是**两种不同的空**：后者是**真值**，前者是**不知道**。
   两者混同会让 UI 把"未接线"画成"该派系没有据点"。

3. **权重不可用 ⇒ `HasWeightData=false` ⇒ UI 不画人数行**（不是画 0）
   —— 0 会被读成"该派系没有人口"。**数值冒充缺失**是本工程 LAND 明令禁止的。
   ⚠ 这条**修订了我自己 SDD 草稿里的写法**（草稿原写"权重为空时退化为 1.0"）——
   实现在语义上更严格：**不知道就不显示**，而不是猜一个满格值。

4. **③ 标记写在 Keyed 模板里**（`估算人数（③ 设计假设）`），不靠调用点自觉
   —— 只要这一行被画出来，标记就在。**"标注靠人记得加"是最不可靠的保障方式。**
   另加配色暗示（人数行走 `UITheme.Dim`，据点是真值走 `UITheme.Alive`）。

5. **刻意不做缓存**（并写进单测钉死）：据点被毁必须响应式反映；全库 `FactionDef` 求
   最大权重是数百次浮点加法的量级、调用点是**面板构建期**（有刷新门控）⇒ 缓存收益为负。
   新增 `FactionScaleAdapter_HasNoStaticMutableState` 断言防后来者"顺手补个 static 缓存"。

6. **据点计数收敛到单一来源**：原先 `BuiltinEconomyProvider.Society.cs` 里有一份
   `CountFactionSettlements`，本批**整体移除**并收敛到 `FactionScaleReader.CountSettlements`
   —— 同功能两处实现是本工程明令反模式（改一处忘另一处，且两处会悄悄漂移）。
   **不留注释掉的旧签名**（死代码会被 GATE-DELTA 残留扫描判为遗留项）。

### 四、K 的标定与**已知弱点**

```text
帝国 lore ③：基础 45 人/据点 × 据点 3 × 社会因子 1.58 ≈ 213.3 ≈ 214
模型：pop = 据点数 × K × 归一化权重
代入：3 × K × 1.0 = 214  ⇒  K = 45 × 1.58 ≈ 71.1
```

- K 落在 **Def 字段** `MVS_FactionScaleTuning.headPerSettlementBaseK`（非代码常量）⇒ 可在 XML 侧校准、可被第三方 Patch 覆盖（GOV-006）。
- ⚠ **已知弱点（必须实机抽查）**：归一化分母取「**全体派系**最大权重和」（照 §7 原文"全派系最大总权重"字面实现），
  因此 K 的有效性依赖「**帝国是权重最大的派系**」这一**未核实前提**。若某派系权重更高，帝国算出的人数会低于 214。
  ⇒ 实机抽查 ≥2 个不同 techLevel 派系的人数是否量级合理，必要时重新标定 K。

### 六、发布区事故与修复（如实登记，含根因）

[S-2] 我在同步到发布区时用 `Copy-Item <dir> <existing-dir> -Recurse -Force`，
**它把源目录复制为目标的子目录** ⇒ 产生了 `Mods/PersonalChronicleVer0.1/Defs/Defs/` 与 `Languages/Languages/`。

⚠ **这是发布级隐患**：RimWorld 对 `Defs/` 是**递归扫描**的，
`Defs/Defs/*.xml` 会让**每一个 Def 重复加载** ⇒ 启动即报重复 defName。
**已即时删除两处嵌套目录并复核**（`Defs\Defs exists = False`、`Languages\Languages exists = False`），
随后改用**逐文件显式复制**（本工程既有同步脚本的形态），复核 `same=76 diff_or_missing=0`。

📌 教训：目录同步必须用 `Copy-Item "$src\*" "$dst\" -Recurse`（复制**内容**）或逐文件复制；
`Copy-Item <dir> <existing-dir>` 的语义是"**放进去**"，与直觉相反。

## 实机验证建议（重启后）

| 项 | 怎么看 |
|---|---|
| **人数行出现** | 选中部落 / 外来者 / 帝国：「据点规模」段应有两行 —— `据点（运行时真值）` **和** `估算人数（③ 设计假设） ≈ N` |
| **③ 标记存在** | 人数行的标签必须**自带** ③ 设计假设；若只有数字没有标记 ⇒ 说明 Keyed 未生效，报我 |
| **人数随派系变化** | 不同派系人数应不同（权重与据点数都不同） |
| **响应式** | 开发者模式销毁该派系一个据点 → 重开面板，**据点数与人数都应立即变化**（无缓存） |
| **降级** | 若某派系没有 `pawnGroupMakers` 数据 ⇒ **只显示据点行**，人数行不出现（**不是**显示 0） |
| ⚠ **K 的量级** | 帝国人数应 ≈ 214 量级。若差得离谱（如个位数或上万）⇒ 说明"帝国是权重最大派系"这一前提不成立，告诉我重新标定 |
