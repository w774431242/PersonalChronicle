## [开发线] 2026-09-19

### 一、🔴 P2 · 产出宫格里的 `0` 冒充空态（且与同格的 `--` 自相矛盾）

`Archive/ITab_Pawn_Chronicle.cs` 的「产出」宫格同一屏内出现两种口径：

| 位置 | 无产出时显示 | 问题 |
|---|---|---|
| 大值 `prodVal` | `--` | ✅ 诚实 |
| inline 种类数 | **`0 类`** | ❌ 写死 —— 与左边的大值**自相矛盾**（一个说"没数据"、一个说"就是 0"） |
| 「周产出 / 月产出」两行 | **`0 银`** | ❌ 同上（原注释还写着"无数据时显示 0 银"，是**有意**的错） |

**修法**：三处统一到同一个 `prodOk` 判据 ——
**从未有产出 ⇒ `--`**；**有产出但窗口内为 0 ⇒ `0 银`**（那才是真值，例如"这周确实没产出"）。

⚠ 这里的关键是**判据要能区分两种 0**：`prodOk` 来自累计器总量，与窗口量是两回事 ⇒
窗口 0 保留 `0 银` 是正确的，只有"整体从无产出"才降级为 `--`。

### 二、🟠 P3 · 三个孤儿字段的注释**承诺了不存在的 UI 行为**

`EconomyFactionStatusSnapshot` 的三个布尔字段，注释明写 UI 行为，实际**零 UI 读者**：

| 字段 | 原注释的承诺 | 实际 |
|---|---|---|
| `Truncated` | 「true 时 **UI 显示**『仅显示前 N 个』提示」 | 截断提示实际由组合层写进 `SubText` 文案 |
| `ReadOnlyDegraded` | （布尔）| 降级提示经 `DegradedText` 到达界面 |
| `MarketReady` | 「false 时 **UI 在标题旁挂『待启动』角标**」 | 该角标**从未实现**；UI 读的是 `MarketPendingText` |

**修法**：**改注释而不是删字段**。理由：它们是**可消费的稳定契约**（`EconomySnapshotContractTests`
钉着默认值），删除会缩窄契约；而注释里的虚假承诺才是真正的危害（下一个人会以为功能在）。

⚠ 特别说明 `MarketReady` 背后的**设计意图仍然成立且已落地**：「因子未就绪时**不隐藏面板**，
因为派系画像来自 Def（静态可读）」—— 这一点由 `IsEmpty` 的门控实现了，与 `Modeled` 同规。
注释已改为如实描述"意图成立、角标未实现"。

### 三、🟠 P3 · `policy_center` 声明 `reserved=false`，但它**零代码**

本工程对 `reserved` 的判据**写在 `SystemCenterDefs.xml` 自己身上**（`population_center` 段）：

> 模块已存在（殖民地档案馆 = 个体档案），缺的只是「经 Provider 接入中心框架」
> ⇒ `reserved=false`（非预留）+ 无 Provider，总控中心如实显示「**数据未接入**」，
> 而不是「**预留（待做）**」。

⇒ `reserved=false` 的语义是「**模块已存在**，只是没接框架」。

而 `policy_center`：全仓检索 `policy` 的 24 处命中**全部是 `*PolicyDef` 命名模式**
（`ThingArchivePolicyDef` / `SocialRelationPolicyDef` / `ProfessionalXpPolicyDef` …），
**与该中心无关** ⇒ 它**一个模块都没有**。

⇒ 声明 `reserved=false` 等于**谎称"模块已存在"**；卡片上的「数据未接入」会让玩家以为"马上就好了"。

**修法**：`reserved` 改 **`true`** ⇒ 卡片显示「预留（待做）」—— 与 `<centerVersion>0.1.0-draft</centerVersion>`
的实际状态一致，也与 `diplomacy/research/defense/environment` 四个真预留中心同列。
**已就地写下反悔路径**：「将来若真要落地该中心：补 Provider + 把本行改回 false，一行即回。」

## 残余风险 / 已知降级

1. **⚠ `policy_center.reserved` 的显示变化**：卡片从「数据未接入」变「预留（待做）」。
   若产品上希望它显示为"待接入"，把 `SystemCenterDefs.xml` 该行改回 `false` 即可（已就地注明）。
2. **⚠ `reserved=true` 会触发启动校验的另一条路径**：`ChronicleMod.cs` 的启动校验会拦
   「**预留却注册了 Provider**」的反常 —— `policy_center` 无 Provider，故不冲突（编译 + 校验逻辑均已核）。
3. **产出宫格的判据口径**：`prodOk` 用的是**累计器总量**，而周/月是**窗口量**。
   当前实现下"曾经产出过、但窗口内为 0"仍显示 `0 银`（**这是有意保留的真值**）。
   若希望窗口 0 也显示 `--`，是另一个口径决策，需另行裁定。
4. **未实机验证**（与 004~011 同批待验）。
