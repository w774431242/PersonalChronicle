## [开发线] 2026-09-19

### ① 市场面板品种列：分类 → 「分类 · 物品样本」

**问题**：品种列原本只显示 `MVSCommodityDef` 的显示名（「基础原料」「织物与皮革」…），
而那其实是**原版品类聚合名**（`ResourcesRaw` / `Textiles` / `MeatRaw`…）——
玩家看不出这个品种到底覆盖哪些东西。

**做法**：
- **`MVSCommodityRegistry` 新增反查索引** `byCommodity`（品种 → 命中集 ThingDef）+ 公开查询 `ThingsOf()`。
  ⚠ **关键实现裁决**：反查表**由已剪枝的正向索引一次性反向展开**，而不是自己再扫一遍轴。
  理由是两条索引若各自扫轴，一旦「可交易性过滤 / 两重排除」在某处微调，两张表就会**静默不同集**
  （症状：面板列出的物品，点它却查不到所属品种）。派生自同一份真相 ⇒ 结构上不可能漂移。
- **新增 `CommodityMemberPicker`**（`MVS/Data/`）：按 **`statBases` 里的 `MarketValue` 基值降序**
  取 Top-N，同值用 `defName` 序数序兜底（确定性、可回归）。
  - ⚠ **平台事实**：`ThingDef.BaseMarketValue`（旧版的静态价格字段）在 1.6 **已不存在**
    （Mono.Cecil `fieldsearch BaseMarketValue` 零命中）⇒ 唯一可用的静态价格源就是 `statBases`；
    它不触发 `StatWorker`、不需要 `Thing` 实例，是纯 Def 静态值。
  - **不用静态 scratch 缓冲**（会引入 Def 访问层的可变静态状态），改用每品种一个临时 List ——
    分配只发生在 Provider 构建期（约 5 秒一次、上限 18 次小分配），用有界低频分配换零静态可变状态。
- **快照加两个字段**：`EconomyMarketRow.MemberText`（摘要，形如 `零部件/玻璃钢/黄金 +17`）与
  `MemberTipText`（**全量、不截断**，供悬停）。两者**同源同序**（只排一次序），
  故悬停看到的顺序必然与摘要一致。
- **摘要语义 = 「前 N + 剩余计数」，不是截断**：截断会让玩家以为该品种只有这三样东西；
  显式 `+N` 既省宽度又如实说明"还有更多"（LAND：不静默截断）。
- **列宽 `Shares` 有意偏离预览**：`{2.385,1,1,1,1.001}` → `{3.4,0.9,0.9,0.9,0.9}`。
  两条不变式被刻意保住并由单测钉死：① **四个指标列必须等宽**（故不单独加宽价格列）；
  ② **品种 : 指标 ∈ [3.5, 4.5]**（低于 3.5 物品样本被截断，高于 4.5 指标列自身开始截断数字）。
  ⚠ 该数组自此**不再是"预览实测值"而是"用户裁定的设计值"** —— 已在代码注释里登记「别再拿 124:52 来纠正它」。
- **悬停补全**：D2 自绘路径下，品种列命中区挂 `Verse.TooltipHandler.TipRegion` 显示全量清单。
  ⚠ RUIF `StatTable` 不回传行矩形 ⇒ **D0/D1 路径无悬停**，已登记为已知降级（与"RUIF 只有一个带色列"同类）。

### ④ 实测复查修复（同日第二轮，用户交实机截图）

**先更正一条我自己的读图错误**：上一轮我据截图判断「总生产/总消费/净值与核算值差约 3 / 20 / 800」，
**那是读错**。第二轮截图（更清晰）逐项吻合：

| 截图 | 客观核算（18 品种 Def 基线求和） |
|---|---|
| 总生产 2,849 | 2848.90 ✓ |
| 总消费 3,656 | 3656.10 ✓ |
| 净值 −807.2 | −807.20 ✓ |
| 均价 1.28 ▲+28% | 1.2833 / +28.3% ✓ |

⇒ **汇总口径完全正确**，`EconomyMarketFormat` 的精度阶梯与千分位按预期工作。上一轮的"差异"结论作废。

**实测暴露并已修（2 项）**：

1. **表头放不下**：`MVS.Economy.Market.Col.Price` 原文 `价格 · 涨幅`（6 字符）而该列仅约 50px
   ⇒ 实测表头被挤断（`净` / `价` / `值·涨幅` 错位）。改为 **`价格`**（英文 `Price · change` → `Price`）——
   涨幅已由单元格内的 ▲▼ 自证，标题无需重复。
2. **物品样本被硬切、`+N` 丢失**：首版样本数取 3，实测多行在物品名**中途被切**
   （`阿尔法敲击兽皮/`、`主脑节点/轨道轰炸`），且**多数行的 `+N` 看不见** —— 而 `+N` 是"还有更多"的
   唯一提示，丢了就是 **LAND 禁止的静默截断**（悬停虽兜底，但玩家不会去悬停一个看不出有内容的格子）。
   ⇒ 样本数 **3 → 2**，并把分隔符由 ` · ` 缩为 `·`（换回约 1 个汉字宽）。首版"取 3"的算术依据被实测证伪，
   已在常量注释里写明「改这个值必须重新对着实机截图核对，不要凭算术推」。

**实测观察到但本轮未修（登记，待裁定）**：

3. **价格列未读因子时的 `—` 带绿**：截图走的是 **RUIF 路径**（标题 `StatTable` 徽章），
   带色列由 RUIF `DataAtoms.StatTable` 的 `bandCol/bandRef/bandValues` 决定 ——
   已核 RUIF 源码：该列每格走 `TableAtoms.ValueCell(rect, text, value, bandRef)`，
   `value = bandRef = 1.0` ⇒ 落 `TableFmt.BandColor(ratio01)` 的**中档色**。
   ⚠ 语义问题：`—`（= **没读到**）被染成与"跌价"同族的色，玩家会误以为"价格跌了"。
   修法有两条（**未择一**）：① 未读因子时不让该格走带色分支（RUIF 侧无此开关，需改调用形态）；
   ② 给 RUIF 增加"中性/无效"档。**属跨仓库改动，先登记请裁定**。
4. **数据级别码疑似渲染为非圈码**：代码侧已核实 `EconomyMarketFormat.LevelMark` 返回的是
   Unicode 圈码 `\u2460/\u2461/\u2462`（①②③），但实测截图里看着像 `(3)`/`(1)`/`(2)`。
   ⚠ **未定论**：可能是 12px 字号下我读图失真，也可能是 RUIF 路径的字体缺字形走了替换。
   若确为非圈码，它占约 3 倍宽度，会直接加剧第 2 条的截断问题 —— **请实机确认一眼**。

## 残余风险 / 已知余留（诚实登记）

1. **RUIF 路径无悬停**：D0/D1（`RuifBridge.TryStatTableEx`）不回传行矩形 ⇒ 品种列的完整物品清单
   只能在 D2 自绘路径悬停查看。D0/D1 下 `+N` 仍会显示（如实告知"还有更多"），只是看不到具体是哪些。
2. **物品样本的排序语义是"贵者优先"而非"最常用"**：`MarketValue` 基值降序能让「基础原料」显示
   零部件/玻璃钢/黄金这类有代表性的实物，但对某些品种（如 `PlantFoodRaw`）会偏向 `Hay` 这类
   边际物品。**有意接受**：换任何其它键（字母序/品类序）都更差或不可解释。
3. **六块说明的 Keyed 键成为"当前无消费者"的键**（`Flow.Side.*` / `Flow.ChainNote` /
   `Market.Footnote` / `FactionDetail.*.EventNote` / `FactionList.Rule.*` / `Society.RestoreNote` 等）。
   **有意保留**（可一行恢复）；⚠ 下轮若要做"死键清理"，请先读本 Changelog 确认它们不是漏接线。
4. **`EconomyFlowGraphSnapshot.SideSections` 字段与 `ChainSideSection` 类型保留但当前无生产者** ——
   保留是为了「恢复时无需动 UI」；已登记，勿当死代码删除。
5. **未做游戏内实测**：本轮全部为表现层改动，编译/单测/两区一致已验证，但「列宽是否真的放得下
   3 个物品名」需实机确认（`Shares` 的比值护栏是按 390px 面板宽估算的）。
6. **`ChronicleStartup` 未新增断言**：本轮无新的"静默失败面"（物品样本取不到 ⇒ 如实留空，
   不报错也不臆造），故不加启动期断言。
