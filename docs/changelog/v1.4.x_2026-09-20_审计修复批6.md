## 本批修了什么（1 项，**审计最后一条**）

### 🟠 §0.7 第 2 条：`qaQuestionWidth` 是**静态字段写的隐式跨方法通道**

审计原文：

> `qaQuestionWidth` 是**静态字段**写的隐式跨方法通道（`BuildPlan` 写、`DrawQa` 读）——
> 当前调用序安全，但**签名里看不出"谁在写"**，任何重排都会读到上一帧残值。

**它为什么是真缺陷（而不是洁癖）**：
- 该值是 **`.qa` 问题列的宽度**，必须在**同一次布局内**由"测量"传给"绘制"（否则两处各测一套，
  症状是行高差几像素、底部被切 —— 本文件开头的注释就写着这个教训）；
- 但它经**静态字段**传递 ⇒ 签名上完全看不出这条依赖 ⇒
  **任何"把 BuildPlan 挪个位置 / 拆一步 / 加一条早退"的改动，都会静默读到上一帧的值**；
- 而 `BuildPlan` 有**两条出口**（未建模 / 正常）—— 走未建模出口时，字段保留**上一帧**的值。
  当前因为未建模时不会 Plan 出 `BlockQa` 块，所以读不到它 ⇒ **安全纯属巧合**。

⇒ 修法（**显式数据流**，消灭字段）：

```
BuildPlan(...)  →  返回 float（两条出口各自返回）  →  Draw 存局部  →  DrawPlan(…, qaQuestionWidth)  →  DrawQa
```

- `BuildPlan`：`void` → **`float`**；两条出口**各自显式返回**（未建模出口返回**下界**，
  并在注释里写明"不是忘返回"）
- `Draw`：两次调用都接收返回值（第二次是"宽度让出滚动条后重建计划"，**必须接收新值**）
- `DrawPlan`：**加参数**接收；`DrawQa` 处原样使用 ⇒ 签名上"谁写谁读"一目了然
- **删除** `private static float qaQuestionWidth;`

📌 **工程纪律（已写入代码注释）**：
**测量与绘制之间的派生量必须走参数，不走字段** —— **字段能穿过重排，参数不能**。

> ⚠ **零行为变化**：数值、时机、布局一字未改；改的只是"它怎么从测量走到绘制"。
> 这也是本批**无需实机验证行为**（只需确认社会面板外观不变）的原因。
