## 一、P0：保存报错「The Writer is closed or in error state」

### 现象

保存游戏（含自动存档）弹出报错：

```
Exception while saving PersonalChronicle.Domain.ItemFlowLedger:
System.InvalidOperationException: The Writer is closed or in error state.
  at System.Xml.XmlWellFormedWriter.AdvanceState(Token)
  at System.Xml.XmlWellFormedWriter.WriteEndElement()
  at Verse.ScribeSaver.ExitNode()
  at Verse.Scribe_Collections.Look[K,V](Dictionary`2&, String, LookMode, LookMode, ...)
  at PersonalChronicle.Domain.ItemFlowLedger.ExposeData()
```

### 根因（已离线复现）

`ItemFlowLedger` 的物品流向键用 `material + '\u0001' + product` 拼接（扁平化键），而 **`\u0001` 是 XML 1.0 非法字符**。

用与 RimWorld 完全相同的方式构造 `XmlWriter` 复现，结果：

```
checkCharacters = True
writerType      = System.Xml.XmlWellFormedWriter
w1 = THREW  :: '', hexadecimal value 0x01, is an invalid character.
w2 = THREW  :: The Writer is closed or in error state.
end= THREW  :: The Writer is closed or in error state.
saved_bytes = 82   ← 文件被截断在 <li> 处
```

机制链条：

1. 写含 `\u0001` 的键 → `XmlWellFormedWriter` 抛「非法字符」并**把自身置为 error 态**；
2. 之后**任何**写入（包括 `finally` 里收尾的 `ExitNode`）都抛 `The Writer is closed or in error state`；
3. `Scribe_Collections.Look` 的 `finally { Scribe.ExitNode(); }` 使**后一个异常覆盖了原始异常** —— 所以日志只看到「closed」，看不到真正的「非法字符」；
4. ⇒ **保存必然失败**，且只要有任何一条流向记录，就永远失败。

### 影响面（已核查）

| 项 | 结论 |
|---|---|
| 存档是否损坏 | **未损坏**。`Autosave-2.rws` 不存在（保存失败后被丢弃），现有 `新移民2.rws`（8.6 MB）完好 |
| 同类隐患 | `\u0001` 全工程**仅此一处**，无扩散 |
| 何时开始 | 自流向槽功能（2026-09-20）上线后，一旦流向槽有数据即触发 |

### 修复

1. **分隔符换为 `'|'`**：`'|'` 在 XML **元素名**中非法 ⇒ 任何 `defName`（均源自 XML 元素名）都不可能包含它 ⇒ 拼接仍无歧义，同时它是合法 XML **文本**字符。
2. **加一道「存档不可失败」兜底**：保存前对所有槽键做 XML 合法性清洗（旧分隔符 `\u0001` → `'|'` 保留语义；其它非法字符 → `'_'`；清洗后重名则合并计数）。同时保证「内存键 == 存档键」，读取路径无需再做映射。
3. **读档兜底**：`PostLoadInit` 再清洗一次（幂等）。
4. 记录：`EXC` 无需新增（本次是缺陷修复，非例外）。

## 二、P2：设备「产出」列恒为 `0 / 0`

### 现象

设备页「产出」列一直是 `0 / 0`，但同行「累计运行」有正常值（7.5 小时 / 21.2 小时）。

### 根因

产量统计的唯一写入路径 `MapComponent_WorkshopManager.NotifyProductMade` 有一道门槛：

```csharp
if (activeWorkers.TryGetValue(worker, out zone) && zone != null)   // ← 只统计"本系统在岗"的人
```

而运行时长走的是完全独立的采样路径（不看在岗）。玩家把殖民者**直接派去做原版工单**（最常见玩法）时，该殖民者不在本系统值勤表中 ⇒ **产出一件都不计数**。

### 修复

**两条口径分开**：

| 台账 | 口径 | 理由 |
|---|---|---|
| **设备台账**（每日/每周产出） | 成品出炉即按其工作台归账，**不要求在岗** | 设备产出是物理事实，与「谁在做、是不是本系统派的」无关 |
| **车间绩效**（生产率分子） | 仍按「在岗」 | 衡量「本系统排班时段内的劳动产出」，混入零散产出会污染读数 |

归账范围限定为已被车间设备扫描追踪的工作台（`IsTracked`），并在扫描路径每轮 `Touch` 一次建条目 —— 避免"设备尚未被采样为运行中"时漏记首批产出，同时不把车间之外的工作台纳入台账。

## 三、需求：产出分为「每日」和「每周」

- 统计窗口由 5 天改为 **7 天（一周）**；
- 设备行「产出」列显示 **`今日 / 本周`**（原为 `5天窗口 / 累计`）；
- 表头 `产出（每日/每周）`；顶部 KPI 横幅 `本周产量`；
- 「今日」直接查逐日环形缓冲，**跨日自然归零，不依赖 `RollDay` 的调用时机**。

**旧档兼容**：窗口由 5 槽扩到 7 槽是安全的 —— 写入用 `day % N` 定位，读取按每槽自带的**绝对天**过滤，不依赖槽位映射；`EnsureWindow()` 会把旧档补足到 7 槽（新槽为空槽）。
