# v1.4.x · 2026-10-02 · 车间工作「优先度最高」

- Change ID：`CHG-SHOP-WORKPRIO-001`
- 影响范围：车间排班 → 原版「工作」面板的联动行为（档位提升）
- 例外登记：`EXC-2026-013`（E2）；`EXC-2026-012`（E2）授权不变
- 依赖：`CHG-SHOP-4FIX-001`（自动勾选原版工作）

## 变化

**做了什么**：被排班的成员，其**车间类型对应**的原版工作类型现在会被提升到**最高档（1）**，让殖民者优先去做车间里的活（烹饪坊→烹饪、锻造坊→锻造、缝纫坊→缝纫、机械加工坊→锻造、制作/制药/石工坊→制作、伐木坊→砍伐、雕塑坊→艺术、研究坊→研究；维护岗位→建造）。

**为什么之前不生效**：原版工作类型的排序里，车间类工作普遍排得很靠后 ——

```
建造 900 · 种植 700 · 采矿 600 · 砍伐 500 · 锻造 470 · 缝纫 450 ·
艺术 430 · 制作 400 · [车间值勤 350] · 搬运 300 · 清洁 200 · 研究 100
```

同时原版对新殖民者**只默认启用前 6 项工作类型**（按技能排序），车间需要的工作常常压根没被勾选。两者叠加，就是「排了班却看不见人去干活」。

## 行为边界（请读完）

- **只作用于车间类型映射里的那些原版工作类型**，以及参与排班的人；其它工作、其它殖民者一律不动。
- **只往上提、不往下压**：`0 → 1`、`2 → 1`、`3 → 1`、`4 → 1`；**不会**关闭任何工作，也**不会**重排其它类型的相对次序。你随时可以在原版「工作」面板里手动改回去（下次修改排班时会再次收敛到最高档）。
- **值勤类型不提升**：车间的「站岗值勤」工作仍只是被勾选（默认档）。这是刻意的 —— 把它顶到最高会让殖民者一直站着值勤、不去干活。
- **原版只在「手动优先级」模式下读取优先级**。若你用的是**简单模式**（默认），优先级设置对引擎无意义，此时：
  - 本模组**不会**写入无效的档位，只做勾选；
  - 车间管理窗口「设置」页会显示一行状态提示，并提供 **「开启手动优先级」** 按钮 —— 点了之后车间工作才会真正排到最前。
  - 本模组**不会**自动替你开启这个全局设置（它影响所有殖民者的工作面板形态）。
- 该模式可随时在原版「工作」面板**左上角**取消勾选关闭。

## 内部变更

- `MapComponent_WorkshopManager.WorkEnable.cs`：新增 `TopWorkPriority` 命名常量（原版 `Pawn_WorkSettings` 没有 `HighestPriority` 常量，最高档就是 1）；`EnableWorkTypes` 拆为「值勤类型仅 Enable」+「映射类型提升到最高档」两条通道；新增简单模式守卫（不写无效档位）与 `EnableManualWorkPriorities()`（由面板按钮触发，镜像原版写设置 + 全量通知的写法）。
- `WorkshopManageView` 设置页新增常驻状态行 + 一键开启按钮（EXC-2026-013 要求的玩家可见披露与出口）。
- 新增本地化键 4 条（中英同步）：`WorkPrioManualOn` / `WorkPrioManualOff` / `WorkPrioEnable` / `WorkPrioHint`。
- 例外登记：新建 `EXC-2026-013`（E2，受控档位提升）；`EXC-2026-012` 追加跨引用备注；两份 SDD 与 `Defs/WorkshopTypes.xml` 注释同步更新。

## 回滚

撤销代码即止写；本模组无存档格式变更。若你点过「开启手动优先级」，该值由**原版**存档保存、卸载模组后仍为开启状态 —— 在原版工作面板左上角取消勾选即可恢复。
