## 变更（分类：Changed / Removed / Fixed）

### Changed — 信息架构

- **页签 5 → 4**：「作息与三餐」页仅剩 1 行只读指路（空页）⇒ 整页取消，指路行并入「车间」页尾的

- **「诊断」页改为开发者模式专属**：未开开发者模式时不再出现；若当时正停在诊断页而开发者模式被关，
  自动钳制回「档案」页（不会出现"页签没了但内容还在"的错位）。

### Removed — 设置项

- **「在班自动回写」整项移除（默认化）**：该项修的是"写 0 / 回写不对称"的**缺陷**，不是行为偏好，
  不应给玩家关闭的入口。设置页不再有这一行，配置键 `autoRestoreOnShift` **停止读取**
  （旧配置残留键被忽略，无需迁移）。
  ⚠ **行为变更**：曾把它关掉的玩家，升级后自动回写**恒开**（这是本次唯一的玩家可感知行为变化）。

### ⚠ 例外登记（本轮最重要的合规动作）

实施「离班停工」默认化时发现一个**既有治理缺陷**：该链写 `SetPriority(wt, 0)`，但

- 它的代码头误引 `EXC-2026-025`（那是"忽略『无法从事』"的 Harmony 例外，与本行为无关）；
- 全仓没有任何 EXC 登记过它；
- 而 `EXC-2026-016` / `EXC-2026-023` 的修订段**都声明**「本 Mod **唯一**允许写 0 的地方是接管通道」。

⇒ 该写 0 点当时**既无有效登记、又与两份 EXC 直接冲突**。本次默认化又把玩家退出权取消，
**进一步扩大**授权面。故：

1. 新建 **`EXC-2026-026`（E2）** 补登记该写 0 点 + 登记本次授权面扩大，并如实登记
   「本链无 `MandatoryKeep` 显式守卫，靠 Def 映射表间接保护」这一缺口；
2. `OffShift.cs` 引用更正为 `EXC-2026-026`；
3. `EXC-2026-016` / `EXC-2026-023` 追加修订段更正「唯一」→「共 2 个写 0 调用点」（原文不改写）。

**Architecture Review**：四项硬触发（Harmony / Hardcoding / Cross-Mod Direct Reference /
Static Mutable State）**均为 No** ⇒ 不触发 AR；但因改写上述两份 EXC 的前提，以 E2 登记并请 PM 追认。

## 存档与兼容

- **不触存档 schema**：实测 `ModSettings` 不随存档保存（只存在于全局 `Config/`），`SchemaVersion` 不 bump。
- 仅一个配置键停止读取（`autoRestoreOnShift`），旧配置残留键被 Scribe 忽略，**无 Migration**。
- 主题 id、归档阈值/保留天数、事件上限的**键名与默认值全部未变**。
- ⚠ **一个例外（准入夹紧）**：事件上限的下限提高到 72 后，旧配置里 **10–71** 的旧值在新滑块域中
  不可表达 ⇒ 读档时一次性夹紧到 72。**这是本次第二处玩家可感知变化**（旧值 <72 的老玩家会被提升到 72），
  已在代码注释与变更标注登记；这样处理是为避免"打开设置页才被隐式改掉"的诡异行为。
