- Change ID：`CHG-20261006-CENTER-RESERVE`

- 依据：玩家裁决「将医疗和内务禁用」，并在三档选项中选择「只降级为预留中心（不动框架代码）」

两个中心本身的 Def（稳定 ID、档位、职责、事件与能力契约）**都保留**，只是不再作为「在跑的中心」出现。

## 为什么用「预留」而不是删掉

`reserved` 是一个**可逆**状态：它表示「ID 与档位已登记、玩法暂不对齐」，不参与数据采集，但仍保留：

- 稳定主键 `medical_center` / `logistics_center`（外部引用与 DefInjected 按它索引）；
- 档位（Tier 12 / Tier 15）与职责、事件、能力契约（`evt.medical.treated` 等）；
- 其它中心指向内务的依赖锚点（`manufacturing_center` / `economy_center` 的 `dependsOn: logistics_center`）。

删 Def 会把这些一并丢掉，且不可逆；将来要重建该中心时，`补数据源 + reserved 改回 false` 一行即回。

## 内部一致性（为什么同时动了代码）

框架有一条硬不变量：**`reserved=true` 的中心不得注册数据 Provider**。

- 数据 Provider 是「这个中心有没有 KPI 数据源」的运行期事实；
- 一个「预留却有 Provider」的中心会**每次启动**在 Player.log 写一条
  `[PersonalChronicle][Provider] SystemCenter provider registered for a reserved center: …`，
  且该 Provider 永远不会被调用（= 死代码）。

因此本次把**医疗 / 内务两中心的 KPI 数据源一并下线**：

- `SystemCenterDataRegistry.CreateWithBuiltins` 中解除两条注册；
- `BuiltinMedicalProvider.cs` / `BuiltinLogisticsProvider.cs` 两个只读观测 Provider 整个删除
  （两者无 Harmony、无存档字段、无策略状态）；
- `Domain/SystemCenterIds.cs` 中对应的两个稳定 ID 常量删除（该类的自述是「只登记被内置数据源绑定的中心 ID」）；
- 随之零引用的 5 条 KPI 翻译键（中英各 1 组）删除。

**原件快照**：`_backups/centers_retire_20261006/`（两个 `.cs` + `README.md` 回滚步骤）。
之所以要快照：这两个文件在本仓库中未被 git 跟踪，删除后没有历史副本可恢复。

## 对存档与第三方的影响

- **存档**：无影响。本次删除项不涉及任何持久化字段（两个 Provider 无 Scribe、无状态），
  旧档可直接加载，不需要迁移。
- **第三方 Mod**：`SystemCenterIds.Medical` / `Logistics` 属于 `public const`，**不是对外契约面**
  （契约面是 `IPersonalChronicleApi`）。常量在编译期内联，已编译的第三方程序集没有运行期破坏；
  只有「从源码重新编译并直接引用这两个常量」的集成方需要改用自己的字符串字面量。
- **运行期扩展点**（`SystemCenterData` 注册表）完全不变：第三方仍可自行给任意中心注册 Provider；
  若给这两个预留中心注册，会命中上述启动期告警（设计如此）。
