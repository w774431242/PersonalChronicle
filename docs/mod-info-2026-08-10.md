## 二、核心问题：版本口径四处分裂 ⚠️

| 位置 | 当前值 | 含义 |
|---|---|---|
| `About/About.xml` `<modVersion>` | **1.0.0** | 给玩家看的**发布版本号** |
| `README.md` 徽章/结尾 | **1.0.0** | 文档口径，与 About 一致 |
| `Api/ApiVersion.cs` `Current` | **4.1.0** | 公共 API 契约版本（`Major.Minor.Patch`） |
| 代码注释 / 翻译键注释 | **v4.5 → v4.7** | 实际功能演进里程碑 |

**功能演进真实进度（按代码注释）：**
- v4.0 首页 KPI 仪表盘、累计工时/产出、scope 修正
- v4.1 统一 API 门面 `IPersonalChronicleApi`（契约版本定格于此）
- v4.3 阵营图鉴（Faction Codex）、Provider 注册表、`ChronicleEventParams` victim faction 快照
- v4.5 UI Design System（UITheme 令牌层 + UIComponents 组件层，`ArchiveUiStyle` 转发壳）
- v4.6 pawn 检视面板「档案」页签（`ITab_Pawn_Chronicle` + `ChronicleInspectTabInjector`）
- v4.6.1 健康残值三维评分（肢体/精神/未衰老）

## 五、公共接入 API（第三方 mod 入口）

- 单一入口：`PersonalChronicleApi.TryGet(out var api)`
- 门面：`IPersonalChronicleApi`（Queries / Events / WorkTime / WorkIntensity / Providers / WorkIntensityProviders / Supports(major,minMinor)）
- 能力探测：`api.Supports(4, 2)` —— **当前 `ApiVersion.Minor = 1`，故任何 `Supports(4, 2+)` 均返回 false**，即使 v4.2+ 功能（如强度 Provider、Read Model）实际已落地。这是一处**功能性隐患**。
- 统一 Provider 注册：`api.Providers.Register(provider)`（替代旧 `WorkIntensityProviders`）
- 旧静态属性（`ChronicleMod.ArchiveService` 等）保留二进制兼容。
