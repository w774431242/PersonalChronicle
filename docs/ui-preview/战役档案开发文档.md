# 战役档案（Battle Archive）开发文档

**版本口径**：v4.10（预览原型，对应 `docs/ui-preview/完整档案馆UI预览.html` 当前状态）
**日期**：2026-08-10
**关联**：`docs/combat/设计文档_战斗履历.md`、`docs/combat/方案_击杀图鉴卡片.md`、`Defs/ArchiveCategoryDefs.xml`
**定位**：PersonalChronicle 是**只读编年史**——战役档案是「历史转折点」的档案，**不是战斗战报**。只记录引擎真实能采到的事件，经 `IArchiveUiDataProvider` 聚合成 Read Model 快照，窗口纯消费呈现。

---

## 0. 设计红线（不可逾越）

1. **只读记录，不制造机制**——不得通过 Harmony 给战役加任何游戏影响。
2. **数据驱动，零硬编码叙事**——展示内容必须来自真实事件流（`ChronicleEvent` / `BattleObject`），不凭空生成。
3. **窗口只消费快照**——排序 / null-guard / 显著性判定归属 `ArchiveUiDataProvider`，不在窗口内。
4. **UI 经 Design System 两层**——新增视觉走 `UITheme` 令牌 + `UIComponents` 组件，绘制态配对恢复。
5. **不建独立战役详情页**——会与 CombatLog 阵营图鉴重复；Overview 卡本身就是档案条目。

## 1. 引擎可实现性约束（先看这块，决定能做什么）

RimWorld 1.6 引擎现实是战役档案的天花板。关键事实（2026-08-10 code-explorer 探查确认）：

| 引擎事实 | 影响 | 结论 |
|---|---|---|
| **无单一「整场袭击结束」事件** | 引擎无 `ThreatComponent` / `RaidEnded` 之类状态；袭击结束被拆成**逐袭击者**的生命周期回调 | 需用 `Lord.Notify_PawnLost` 的 `ownedPawns` 归零聚合出「整场结束」 |
| **有逐袭击者精确回调** | **`Verse.AI.Group.Lord.Notify_PawnLost(Pawn, PawnLostCondition, DamageInfo?)`**：一次袭击 = 一个/多个 `Lord`（`LordJob_AssaultColony` 等），其 `ownedPawns` 即来袭敌人；任一袭击者死亡/倒地/俘虏/撤离触发并移出 `ownedPawns`（**落地前反编译 1.6 实测，`RaidStrategyWorker` 无 Notify_* 方法**） | ✅ **这是「流程过后归档」的精确落点** |
| **敌人开战瞬间后才生成** | `AttachBattleRoster` 只能快照我方（`ParticipantIds`）；但 `TryExecuteWorker`（同步生成入口）postfix 时敌人已全部生成 | ✅ **规模人数可精确快照** |
| **击杀/阵亡挂在 battle subject 上** | `OnKillRecorded` 在 `activeBattle != null` 时挂 kill/death 到 battle 的 Subjects | ✅ **我方战损可反推** |

**定位修正（关键）**：本 mod 是**档案馆**，**不需要同步实时记录**——只需要「完整流程走完后能记录在案」。因此方案**弃用轮询/实时**，改用引擎精确的 `Notify_*` 回调在**最后一个袭击者消失那一刻一次性归档**三要素。

### 1.1 三要素归档点

| 要素 | 语义 | 归档点 | 精度 |
|---|---|---|---|
| **触发时间** `StartTick` | 袭击 incident 执行成功 | `Patch_IncidentWorker` postfix（`__result=true`，已有） | 精确 ✅ |
| **规模人数** `RaidCount` | 本场 raid 来袭敌人数 | `OnBattleStarted` 内 `LinkRaidLords`：扫描地图上**敌对阵营 raid Lord** 的 `ownedPawns` 求和（`TryExecuteWorker` 已同步生成完毕） | 精确 ✅ |
| **击退时间** `EndTick` | 最后一个袭击者死亡/撤离 | `Lord.Notify_PawnLost` postfix：该 Lord 的 `ownedPawns.Count` 归零那一刻 | 精确 ✅ |

### 1.2 核心机制：`Lord.Notify_PawnLost` 权威归零（一次性归档，已落地 v4.11）

> **引擎事实修正（落地前反编译 1.6 确认）**：早期文档假设 `RaidStrategyWorker.Notify_PawnKilled/Notify_PawnDied/Notify_PawnLeftMap` 存在，**实测 1.6 的 `RaidStrategyWorker` 根本没有这些方法**。真实的「逐袭击者消失」回调是 **`Verse.AI.Group.Lord.Notify_PawnLost(Pawn pawn, PawnLostCondition cond, DamageInfo? dinfo)`**：一次袭击 = 一个（或多个）`Lord`（`LordJob_AssaultColony` 等），其 `ownedPawns` 即来袭敌人；任一袭击者死亡/倒地/俘虏/撤离时引擎会调 `Notify_PawnLost` 并把它移出 `ownedPawns`。

```
开战（Patch_IncidentWorker postfix，TryExecuteWorker 已同步生成敌人）
  └─> OnBattleStarted：建 BattleObject（StartTick=TicksGame）
        └─> LinkRaidLords(battle)：扫 Find.Maps → 各 map.lordManager.lords
             过滤条件：faction != null && faction.HostileTo(player) && ownedPawns 非空 && 未登记
             → raidLordToBattle[lord.loadID] = battle.StableId
             → RaidCount += lord.ownedPawns.Count；RemainingRaidCount = RaidCount
战斗过程（逐袭击者消失）
  └─> [Patch] Lord.Notify_PawnLost postfix（读 __instance.loadID + ownedPawns.Count）
        → service.OnRaidPawnGone(lordLoadId, remainingPawns)
        → 若 remainingPawns <= 0：
            从 raidLordToBattle 移除该 Lord；扫剩余链接是否都归零
            全部归零 → battle.EndTick = TicksGame（击退时间）+ MarkChanged
```

**关键点**：
- **权威计数**：`Notify_PawnLost` postfix 时该 pawn 已被移出 `ownedPawns`，所以 `ownedPawns.Count` 就是**剩余袭击者数**。直接用这个权威值而非 `--` 计数，天然免疫「同一 pawn 因多种 `PawnLostCondition` 重复上报导致提前归零」的偏差。
- **多 Lord 战役**：`RemainingRaidCount` 记录各 Lord 剩余数的最小值；只有当**所有**关联 Lord 的 `ownedPawns` 都归零才写 `EndTick`。
- **不轮询、不实时、零性能开销**——只在有袭击者消失时触发一次，完全贴合「流程过后归档」的档案馆定位。
- **敌方归属精确**：只统计 `faction.HostileTo(player)` 的 Lord，天然排除商队/访客/野生动物/我方 Lord，避免 `RaidCount` 虚高。
- **归档前二次确认**：`RaidCount <= 0`（非 Lord 威胁如虫灾/机械集群/坠船，无 raid Lord）时**不由此路径终结**，交给 `ClosePreviousBattle` 兜底，防假归档。

### 1.3 边界情况（档案馆诚实性）

| 情况 | 处理 |
|---|---|
| 中途存档（战斗进行中保存/退出） | `RemainingRaidCount` 是 `[Unsaved]` 不落盘；载入后 `ResetBattleRaidCounters` 从 `RaidCount` 重建 + `RelinkOngoingBattles` 重新关联 raid Lord，击退倒计时可续。若 raid 引擎状态已清 → `EndTick` 保持 -1，UI 显示「进行中（未归档）」，不造假 |
| 敌人撤离而非被灭 | 撤离触发 `Notify_PawnLost`，`ownedPawns` 递减 → 全部撤离归零即结束 → 击退时间 = 最后撤离者离开 |
| 跨存档污染 | `raidLordToBattle` 是 static，已在 `FinalizeInit` 调 `ArchiveService.ResetRaidLordLinks()` 清空，`Lord.loadID` 跨存档不会串戏 |
| 我方/非 raid pawn 离开 | `Notify_PawnLost` 对**所有** Lord 触发，但我们只对已登记到 `raidLordToBattle` 的 Lord 行动，未登记的（仪式/商队/我方）一律 no-op |
| 保留 `ClosePreviousBattle` 作兜底 | 处理「raid Lord 因存档/异常未归零」极端情况，防 `EndTick` 永远 -1；主路径精确闭合后 `EndTick != -1` 会被它跳过 |

## 3. 战役档案条目信息架构（v4.10 预览落地）

### 3.1 时空身份（让同名袭击可区分）
- **标题**：`IncidentDefLabel(IncidentDefName)`（如「人类部落袭击」）。
- **日期**：`FormatDate(StartTick)` → 「5503 秋 12」。
- **副标题**：`N 人参战`（`ParticipantIds.Count`，**我方人数，准**）+ 来袭规模（`RaidCount`，敌方）。

> 一役一卡，不聚合降噪。多场同名袭击靠日期后缀区分——「档案粒度」是编年史的价值，合并成「×5」会丢叙事。

### 3.2 显著性着色（Provider 扩展点闭环）
- `IsSignificant=true`（决定性战役）→ 卡片左 accent 边框 + 顶部 2px 强调条 + `Decisive` 徽章。
- `IsSignificant=false`（小规模冲突）→ 卡片灰淡（`opacity .86`）+ `Skirmish` 徽章 + 右上角小圆点。
- 色值走 `UITheme` 令牌：Decisive=`Accent`，Skirmish=`Muted`。**零硬编码阈值**。

### 3.3 我方战损展开（点卡就地展开，仿 FactionCodex）
- 点击战役卡 → 就地展开 `battle-expand` 区，列出「我方击杀 N · 阵亡 X」明细。
- 数据来源：`GetEventsFor(battle.StableId)` 反推 Kill/Death 事件，**纯 Read Model 聚合**。
- 内嵌滚动模式复用 FactionCodex 的 `Widgets.BeginScrollView`（固定视口行数），不随条数撑高。

### 3.4 信息层组件（v4.10 第二轮拓展）
| 组件 | 预览类 | 数据源 | 说明 |
|---|---|---|---|
| KPI 汇总条 | `.battle-kpis`（5 格） | `GetBattleSummary()` Read Model 聚合 | 战役总数/决定性/我方击杀/阵亡/参战人次；不逐卡计数，窗口零排序 |
| 三格指标 | `.battle-metrics .metric` | `ParticipantIds.Count` + 战损反推 | 参战/击杀/阵亡三格；阵亡格 `Dead` 令牌强调，中文行高 ≥28f |
| 参战名单 chips | `.battle-roster .chip` | `ParticipantIds` → pawn 映射 | 点击跳转 pawn 详情（`NavTarget.Pawn`）；人多折叠「N 人参战」不撑高卡 |
| 威胁类型标签 | `.battle-tag big/small` | `IncidentDef.category` 弱语义 | ThreatBig=Accent / ThreatSmall=Tag；`BattleObject` 需补存 category 快照（P2） |

### 3.5 三要素展示（v4.11 袭击档案）
| 展示 | 数据源 | 说明 |
|---|---|---|
| **触发时间** | `StartTick` | `FormatDate` 显示「5503 秋 12」；标题含日期区分同名袭击 |
| **规模人数** | `RaidCount` | 卡头 `ThreatTag` 旁显示「来袭 N」；`LinkRaidLords` 对敌对 Lord `ownedPawns` 求和 |
| **击退时长** | `EndTick - StartTick` | 仅 `EndTick != -1`（已闭合）时显示「历时 X 天/时/分」；`EndTick == -1` 显示「未击退（进行中）」 |

> 时长口径：`EndTick` 由 `Lord.Notify_PawnLost` 归零精确闭合 =「最后袭击者消失时刻」，非下一场战役（区别于旧 `ClosePreviousBattle` 兜底）。

### 3.6 随机化示例数据（预览 HTML）
战役卡在预览中**非静态 HTML**，而是 JS 数据驱动随机生成（`BATTLE_POOL` 池 + `genBattle`/`genBattles`）：
- **每次进入 Overview/Home 重新随机** 3~6 场（`renderAll` 里 `state.battles = null` 触发），toolbar「随机战役」按钮可手动重掷。
- 随机字段：来袭规模（big 8~30 / small 3~9）、击退时长（1~8 时 + 10~59 分）、我方击杀（≤ raid 80%）、阵亡（≤ 2）、参战名单（从 pawn 池抽 2~5 人，chips 可跳转）、显著性（按模板概率）。
- KPI 汇总条 + sidebar 战役计数 + Home 页战役 KPI **同步随机结果**（`battle-total`/`side-battle-count`/`home-battle-count`）。
- 随机数值全部走**引擎可采口径**（规模/时长/战损随机分布，无伪精确字段），仅作视觉/布局演示；C# 落地后由真实 `BattleObject` 数据驱动。
- 测试：`node` + document mock 执行级验证（genBattle 字段完整、200 轮分布合理、kills≤raid、KPI 同步），21/21 PASS；综合测试 22/22 PASS。

### 3.7 明确不做
- ❌ **实时/轮询监测**——本 mod 是档案馆，只在 `Notify_*` 流程过后归档，不逐帧扫描。
- ❌ **未闭合战役的时长**——`EndTick == -1` 时不造假时长，显示「进行中」。
- ❌ **敌军构成明细**（敌方各 pawn 类型/装备构成）——开战快照只有数量，无逐兵构成；CombatLog 阵营图鉴已在击杀维度覆盖。
- ❌ 独立战役详情页（与 CombatLog 重复）。
- ❌ 把 Battle 从 `StatOnly` 改成 `Record` 深度导航——它仍是统计性档案条目，不是可钻取的实体。

## 7. 与现有 CombatLog 阵营图鉴的边界

| 维度 | 阵营图鉴（CombatLog，v4.3） | 战役档案（Overview › Battle，v4.10） |
|---|---|---|
| 视图 | 详情页 tab | Overview 分类卡片 |
| 粒度 | 按受害者阵营聚合击杀 | 一场一卡 |
| 视角 | 我方击杀明细 | 我方参战 + 战损 |
| 数据 | `cachedKillLines` / `BuildFactionCodex` | `BattleObject` + `IBattleProvider` + `Notify_*` 事件 |
