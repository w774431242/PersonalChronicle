## 3. 本轮必须交付的功能单元

### A. 有版本的公有机构政策与只读供给

新增明确的新引擎政策/报价/岗位公告契约，前端设置使用 RUIF 和版本化命令。允许玩家配置新政策草稿/公告，不写旧冻结账本；政策保存、报价生效时间、版本、关闭/销毁/地图失效都可解释。机构仍公有，不实现私营或自动外贸。

生活费用至少落实一个实际适配的产品域，优先既有衣物链；食品只有真实可食用性、营养/消耗、量纲与合法覆盖有支持时才给已知估计。不按 MarketValue 伪造成交价、不写死每天三餐、不把野果/树木/野兽等自然公共资源变收费。报价由玩家明确政策形成，物品/存量与当前报价绑定；未来消费费用只是预算，不等于已消费、收费权限或硬预留。

先使用已有/已付物品及明确公共保障，按唯一需要、资源份额和窗口去重。原版仍 PublicVanilla 的服务保持免费访问；不得为了凑正储蓄目标虚构收费。缺价、无货、未知覆盖、未知消耗、未适配分别显示原因，不能统一显示买不起。

### B. 真实可执行的岗位候选 Provider

至少适配一种现有公有工坊生产岗位。来源须包含真实工单、允许生产、必要材料/设备、区域、开放时段、当前容量、真实可用公款及工资上限。资金只读 M11 实资账本，不用旧 OpeningBudget、不预支外贸、不把未到账工资算现金。只读候选不占岗、不锁钱、不创建真实 Job。

按原版实际能力、年龄、技能和许可判断可应聘；`WorkIsActive` / Priority=0 不作为能力禁用，真正 `WorkTypeIsDisabled` 仍不得绕过。无材料、无可执行工单、无法及时发薪、关闭或未知原版访问时给具体原因，不能只返回一个空列表或用配置岗位冒充有效劳动机会。

原版工单检查先验证当前游戏 DLL 公开 API 的签名及查询副作用。不得在 OnGUI 中采集或在影子规划中用 `StartJob`、真实预预约/派工来测试可执行性。若某挂点必须 Harmony，先形成范围、时序、幂等和回滚的架构记录，仅在证据充分的最小范围实现。

### C. 规划仲裁、持久滞回与有界性能

接通 Provider 到 `IShadowPlanningSource.ReadInput`，不再用永久 null/false 代替已适配域。生活成本、供给和资金摘要带版本、采样年龄及窗口；旧计划不得因新 Tick 包装成新鲜 Ready。持久保存必要激活/补储滞回及有限目标身份，不保存派生报价、UI、路径缓存、Pawn 强引用或虚构资金。

完成最小目标前置 DAG 及循环检测、有界候选搜索；同一受益需要一个稳定身份，重评不重复筹资；资格费→工作→工资→资格费循环必须受阻，不能无限递归或赠币。S 未知保留历史滞回但当前收入未知；低水位启动、高水位退出；已有现金、硬预留和预计收入分别列明；原版控制、急救、进食、睡眠、征召和强制任务优先。

避免每个 Pawn 反复扫描整张地图或所有人口。按事件/目录版本失效并对地图级摘要共享缓存；保留每 Tick 配额、候选/寻路上限、陈旧年龄及积压诊断。无执行资源的等待项不每 Tick 重试。

### D. 玩家可解释的 RUIF 展示

个人页展示缺口→费用/覆盖→有限储备→收入目标→候选岗位→拒绝原因，各值标示已知/未知、来源与年龄；机构页展示价格、有效库存、岗位资金/容量与生产受阻原因。至少中英双语和长文本动态换行；前端使用 RUIF，不另造通用组件。
