## 3. 功能范围与视觉要求

### 3.1 卡片位置与层级（必做）

保留生活保障标题、需求概览进度条和心情行。其下追加「个人账户」区域，用轻量分隔和 RUIF 现有原子组件形成同一卡片内部的次级分组。账户主数值是「可用余额」，其次是「账户总额」「预留金额」。金额与需求满足度属于不同量纲，账户金额不参与生活保障进度条均值或心情数值。

建议排布（窄屏自动转为逐项行，不机械复制字符框）：

```text
生活保障                         已规划 3 项 · 仅观察 3 项
[原有生活保障进度条]
心情                                           未知
──────────────────────────────────────────────────
个人账户                         可用余额 30.00 银
账户总额 40.00 银                   预留金额 10.00 银
生活储备目标 40.00 银                  补储缺口 10.00 银
收入状态：正在补储
```

最后两行是简洁解释，不展开整份决策页。账户无数据时保留标题与状态说明；不能导致整张需求页空白，也不能误用 Pawn 没需求的空态屏蔽账户。选择无需求但有合法账户的对象时，按宿主现有可见性规则显示账户卡片。

### 3.2 必须显示的账户字段

| 字段 | 口径 | 展示规则 |
|---|---|---|
| 可用余额 | 当前个人账户 AvailableMinor | 最突出，固定两位小数及银币单位；已知零显示 0.00 |
| 账户总额 | BalanceMinor | 含已被预留的余额，不称为可花余额 |
| 预留金额 | ReservedMinor | 已有真实账本预留，不是预测开销或未来工资 |
| 生活储备目标 | 当前有效计划的 ReserveTargetMinor | 属于未来预算，未知时显示具体状态 |
| 补储缺口 | 同一预算的 IncomeGapMinor | 不用账户新快照配合旧目标擅自重算 |
| 收入状态 | 当前预算 RefillActive 与当前计划决策 | 区分正在补储、暂不需要补储、等待报价/账户、计划过期，以及无法工作等实际原因 |

账户摘要可显示最新账本金额，预算仍来自带时间戳的计划。两者采样时点不一致时必须在说明中区分「账户余额」和「计划采样余额」，不声称缺口是按最新余额计算；过期计划不得包装成实时数据。

### 3.3 提示与交互

悬停账户标题/金额区显示：账户归属 Pawn、总额/预留/可用解释、资金来源为现行实资账本、采样时间或年龄及状态原因。正常正文不展示技术账户 ID、Minor 字段名、内部 reason 枚举或日志。

悬停储备/收入区解释预算窗口、储备目标、启动线、正在补储时的退出线和当前阻断原因；未到账工资只是预计收入，不计入余额。提供「查看决策详情」的页内跳转，复用现有决策页签及滚动复位，不创建新窗口；不能在点击时写钱、签约、派工或修改政策。

本轮只读展示，不加入存款、取款、转账、赠款、充值、取消预留、修改求职门槛或账户管理按钮。用户没有授权把「玩家派发合同」改成无视个人收入需要的强制承接，保留既有就业保护与仲裁机制。

## 4. 金额、未知状态与缺钱逻辑

### 4.1 账本数据边界

1. 唯一账户归属键为当前选中 Pawn 的稳定身份（现行 GetUniqueLoadID 链路），不是姓名、列表索引或当前地图人口排序。国库、机构账户及其他 Pawn 余额不能混入。
2. 金额底层为整数 minor，100 minor = 1 银币。格式化复用现有金额约定，不使用 float 累加；余额 12345 minor 显示 123.45 银。
3. 已知有效账户满足总额 = 可用余额 + 预留金额。异常/无效账本不夹成零、不显示负数正常态，返回明确错误状态。
4. 缺账户、账本未就绪、未知 schema、读取错误、不适用、陈旧必须分开。显示「尚未建立个人账户」「账本暂不可用」「数据版本不支持」「读取失败」「不适用」「计划待刷新」等可理解说明。不得为显示而开户、迁移、补齐资金或解除预留。
5. 个人账户已知、食品报价未知时，账户数字仍正常；仅储备目标/补储状态显示等待报价。公共免费保障或真实目标 0 与「缺价」不是同一状态。

### 4.2 求职阈值只解释，不重写

实现时以 Domain 当前政策为真值，提示层读取其结构化结果；如缺少触发线输出，允许补齐只读 presenter 字段，不在绘制层复制公式。当前逻辑为：

- T = 必要生活成本扣除有效覆盖后的储备目标；当前政策通常为 2 天窗口，不能宣传所有生活项目均已计费适配。
- C = 个人账户可用余额。低水位 L = ceil(T × 70%)，应急额 E = floor(T × 8%)，启动线 H = min(T, L + E)，均按 minor 运算。
- 尚未补储时：T > 0 且 C < H 才启动；已补储时：继续至 C ≥ T。低于目标但未到启动线，可以有缺口而暂不求职。
- RefillActive 只表示收入需要，实际 SeekWork/工作还受征召、吃饭、睡眠、能力、工时、岗位及机构资金等条件约束。「正在补储」不能写成「正在工作」或「必定承接合同」。

量化验收：T=40.00，L=28.00，E=3.20，H=31.20；C=35.00、未激活补储时暂不补储；C=30.00 时启动；已激活后 C=35.00 继续；C=40.00 退出。C=31.20 未激活时不启动（严格小于）。只有真实结算改变账户余额，报价/合同金额/计划工资不能提前入账。

以上状态是排布示意，绝不能把示例字样写成固定逻辑。显示的每个状态要有独立结构化证据；用户截图只能确认余额与预算，不能推导其余循环稳定/未评估。通常账户子区控制在约 180～220 UI 单位高；实际高度按本地化文本测量，禁止为了达成高度指标裁剪内容。窄宽转为两列或逐项行，保留完整可用余额、当前决策和主要原因，次级详细数据进入详情。

金额主数值使用现有可用字号的最高一级，其余金额降一级；金额右对齐、字段标签弱化。身份由当前 Pawn 页面给出，不重复长姓名。颜色用于状态：蓝色为当前选择、绿色为有事实的成功/充足、琥珀色为等待或让路、红色为错误/不一致、灰色为未评估/不适用；同时保留文字，不能仅靠颜色。零余额本身不把整卡变红。

### 11.2 资金指标与储备条

主区恒显可用余额；总额、预留用同一紧凑行。预算已知时显示计划覆盖率 `计划采样可用余额 / 储备目标`，并标启动线与目标线；覆盖率显示可超过 100% 的真实数值，绘制条填充可截到 100%，不把超额余额藏掉。

储备条复用 RUIF 已有能力。无法用现有组件安全标阈值时显示「启动 ≤对应线的严格条件 / 目标值」文本，不修改框架。启动线是严格小于：正文可写「低于 31.20 启动」，不可写成「≤31.20」。不能把真实硬预留加到可用余额，也不能把储备目标叫“冻结资金”。目标未知显示短横和明确等待原因；真实目标 0 显示“当前无必要储备目标”，不做除零或假 100%。账户新余额与旧计划不同源时标「计划值」，详情列出双方金额及采样年龄。

### 11.3 四循环是并行状态面板，不是线性完成进度

复用现有四循环业务身份：即时满足、储备保障、劳动收入、消费与服务。用一行四个紧凑单元（窄屏 2×2），每个包含名称、状态文字和当前重点指示；单元点击打开已有决策页相应详情，若现有宿主无法定位分区则切决策页，不能假装已精确定位。

状态契约必须包含稳定业务 ID、状态枚举、原因码、证据来源、采样 Tick/陈旧性；禁止根据中文状态字符串决定配色/可点击性/分支。不同循环可以同时活跃，互斥的实际行动由仲裁决策单独表达。允许的呈现状态为未评估、待处理、等待事实、受阻、可行、执行中、完成/满足、不适用、过期；各循环只使用适用子集。没有执行证据就不出现执行中/完成。

特别校正现有 `BuildCycles` 的语义风险：无活跃需要不能直接证明“已满足”；`ShadowDecision.SeekWork` 只说明规划选择了收入机会，不证明已签约/正在工作；空候选、空 Options 不能统一表示功能未实装。早退分支应显示未评估或等待前置，并保留原因。

### 11.4 AI 决策状态机与执行证据

提供独立紧凑「当前决策」行和一条主要原因；实际控制权优先，不能因已有合同就遮掉吃饭/睡眠/征召的让路状态。核心映射按当前 Domain 字段定义：

| 当前依据 | 玩家文案 | 后续方向 |
|---|---|---|
| 无计划/WaitingFacts | 等待感知数据 | 获取有效事实后重评 |
| NativeYield | 让路原版控制 | 解除征召/强制任务/安全保护后重评；具体原因取实际值 |
| NativeNeed | 优先满足基本需要 | 完成当前基本需要后重评 |
| WaitingBudget | 等待生活预算 | 具体报价/账户/不一致分支，不能只写“AI 等待” |
| WaitingOpportunity | 等待可行收入机会 | 区分资格、工时、供给、容量、资金、可达性等实际原因 |
| SeekWork | 已选择收入机会 | 等待实际签约提交结果，不能直接叫正在工作 |
| MaintainReserve / NoIncomeNeeded | 维持储备 / 暂无收入需要 | 目标/启动线/滞回变化后重评 |
| OutOfScope / Error / stale | 不适用 / 模型读取异常 / 计划待刷新 | 对应范围或有效数据恢复，陈旧值不表现为当前行动 |

收入执行子状态额外读取真实合同/劳动/工资事实，映射为“已选择候选 → 待承接结果 → 合同履约中 → 待结算 → 已到账”，并允许拒绝、退出、到期、撤销、支付失败及等待协调分支。它是执行链说明，不是每次必然经过所有节点的动画。

“合同履约中”须有有效合同；“正在执行工作”须有当前 Job 与合同任务对应证据，不以工作类型授权代替；“待结算”须有实际未结清应付义务；“已到账”须有对应已完成结算记录，不以账户大于零或合同完成件数推断。无本次结算证据时不展示“已到账”。如果当前接口没有选中任务/承接结果/Job 关联证据，显示“执行状态未确认”，可最小扩展有界只读契约，不能伪造时间线或持久化 UI 推断。

### 11.5 高效显示 AI 模型：事实 → 缺口 → 选择 → 执行

使用玩家向名称「需求规划」，不冒称神经网络、大语言模型推理或训练进度。摘要只展示当前最高优先级目标、当前决策、主要阻断点和下一步；“下一步”是建议/等待条件，不能用命令口吻声称已经执行。

详情复用决策页，补齐四段可解释链：

1. 输入：活跃需求、个人可用余额、费用与供给事实、各自采样年龄。
2. 缺口：储备目标、启动线、补储滞回、收入缺口；未到账工资单列。
3. 仲裁：最终决策、最高优先级目标、实际候选数和选中项；候选资格/资金/可执行性以已知/未知/不满足分别表示。
4. 执行反馈：承接/合同/实际工作证据/应付与到账；没有证据的节点明确未确认。

优先展示 1 条主要原因及最多 2 条次要原因，其余折叠；候选详情最多 3 项，余数可进入既有列表。源本来只采样部分候选时显示“本次评估 N 项”，不得宣传为地图所有岗位总数。不增加全图扫描、无界历史日志、每帧字符串拼装或模拟执行。结构化输出按现有采样/刷新配额更新；暂停、切人和语言切换失效保持正确。
