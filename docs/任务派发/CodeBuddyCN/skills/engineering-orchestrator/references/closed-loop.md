# 真实调用链与不变量

## 最小链路表

|阶段|核查事实|常见假完成|
|---|---|---|
|入口|设置/Def/ThinkTree/HTTP或按钮真能触发|只有类定义|
|感知|事实范围、时效、完整性、未知|缺账户直接当零，扫描截断称完整|
|判决|优先级、权限、能力、预算和玩家保护|UI写让路，执行仍直接买衣|
|承诺|岗位租约、资源与付款授权|合同等于占位，余额比较等于预留|
|执行|实际进入合法岗位/柜台/服务|启用工作类型等于进入合同工坊|
|交付|真实物品/劳动/服务唯一事件|发收据等于完成生产|
|使用|原版需要或穿戴真实改善|付钱等于吃饭|
|反馈|修改事实触发重采/重规划|旧资金缓存继续当实时余额|
|恢复|重放、中断、读档、退出可收敛|保存字段存在等于完整恢复|

每个节点回答：生产者、消费者、事实来源、可写者、授权条件、持久状态、失败后下一步。追间接构造和适配器后再判“零消费者”；搜索无命中不等于功能不存在。

## 必须保持的性质

- 资金与物品数量守恒；钱包扣款、商品交付、授权消耗分开描述，共同恢复。
- 一个权利和事实只有一个权威写源；历史/UI/缓存/学习不成为第二钱包。
- 业务幂等 ID 稳定，并发版本检查不能让正常重放变成新收费；重复事件的学习样本也要去重。
- 合同结束不吞掉已完成劳动应付；消费退款必须有实际撤回证据。
- 校验器、只读预判和实际维护使用一致条件；显示端不得更正不了执行状态。
- 玩家强制、原版紧急生存与已批准保护边界优先，消费与穿戴也受仲裁。
- 合法零值、没有发布、不适用、读取错误分开；健康账本可证明新 Pawn 零余额，故障账本不能猜零。
- 终态归档保留未履行权利和重放水位；4096行固定上限不是长期可运行证明。

## 复用此次经济项目的反例

1. 新账户仅在收薪时创建，但缺账户让预算不Ready，预算又挡求职：冷启动循环，修入口生命周期。
2. 原始食品堆栈拆一件后身份不同；背包TryAdd允许合堆，返回成功但原对象已销毁：凭证需实际持有与数量增量。
3. 商品交付异常保留Prepared，恢复却按“无银币物理移动”取消：两种交割事实混用。
4. 所有权启用部分成功，后续失败仅终止合同：补偿必须包含已写工作类型。
5. 索引常量或规划偏好只有展示消费者：属于解释能力，不是运行行为。

这些是调查模板，不是对未来版本仍有缺陷的预设；必须读当前代码重新证实。
