# 验证、集成与关闭

## 证据等级

|状态|可声称的事实|
|---|---|
|Implemented|当前源码已改并接线，尚未证实运行|
|CodeVerified|绑定构建版本的必要自动检查通过，关键适配路径有证据|
|RuntimeVerified / GameVerified|目标真实运行场景通过；覆盖范围明确|
|Released|已授权部署，哈希/版本正确且目标进程加载得到确认|

不可用编译成功替代游戏验证，不能用磁盘DLL一致证明旧进程已重载。测试失败后改代码必须重跑受影响场景；新增绿色记录不能掩盖未解释的失败或被跳过的关键用例。

## 按风险挑验证

- 纯规则：边界、单位、未知、溢出、去重、滞回、并发版本。
- 接线：从真实入口到状态源的最小集成；同时验证UI预判与执行维护。
- 事务：交割前后失败、合堆/拆堆、付款与授权之间失败、Prepared/Cancelled/Finalized重放、读档。
- 生命周期：关闭重开、离图、死亡、能力变化、玩家改写、历史满额。
- 运行：多Pawn争岗、资金不足与注资、远处到店、玩家强制/急救让路。
- 性能：必要时量测真实地图与规模；“每tick数量上限”不能替代耗时与分配曲线。

不写只重复常量或照抄实现的测试。Adapter缺陷优先验证Adapter，不以Domain测试充当覆盖；测试名或静态字符串搜索也不是测试运行结果。

## 集成裁决

总控核对所有diff与任务文件所有权；检查实际消费者、完整状态机、schema兼容及证据与当前版本对应。并发修改正在发生时重新读取最后变动的关键分支，已修的旧项标为“已修/部分修复/未核验”，避免重复假警报。

实际失败示例：更新QueryContractExit，却不更新MaintainContract。要让同一场景验证两者输出/状态，不能单测新的纯退出函数。

未通过的必要门阻止对应能力发布；其他已完成能力保留进展。禁止凭截止时间、测试数量或“所有文件齐全”关闭任务。
