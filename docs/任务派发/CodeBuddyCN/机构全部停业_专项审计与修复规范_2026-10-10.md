## 确定缺陷：机构首页读取旧制度

`Source/PersonalChronicle/Economy/PawnEconomy/EconomyCommands.cs:27–28,48–57`：首页通过 `Institution(anchor)` 读取旧 `EconomyInstitution.Open`，为空或为 false 就显示“停业”。它没有读取新 `QueryInstitutionPolicy(anchorKey).Open`。

`EconomyInstitutionMode.cs:19`：`LegacyFeesAllowed => false`。`EconomyRuntime.cs` 的 Register 不再创建旧机构记录；`EconomyCommands.cs:44–45` 又移除旧操作按钮，仅保留 Focus 与 Treasury 命令；`Execute:141` 直接拒绝旧写入。因此首页“管理”只是选中旧对象，并不能打开新机构。新机构缺少旧记录时，会稳定显示停业。

真正的新营业开关在 `Dialog_PawnEconomy.Policy.cs:101,126–127` 的“机构政策”页，提交 `ApplyInstitutionPolicy`。即使这里设置 Open=true，首页仍可能显示停业。这个缺陷可以独立于全局制度状态发生。

**修复要求（P1）：** 首页机构列表改用 QueryInstitutions + QueryInstitutionPolicy；管理按钮直接导航对应新政策；旧制度记录独立放在“历史对账”，不得作为当前营业状态来源。不要恢复 LegacyFeesAllowed，也不要同时写两个 Open 来制造一致性。

## 条件阻断一：首次开启停留 Preparing

`EconomyInstitutionMode.cs:57–64`：恢复证明必须满足 LoadedFromSave、Frozen、两项账本无 fault；新档/尚未重载的会话没有 LoadedFromSave，RecoveryProvenRevision 默认 -1，SaveRecoveryVerified=false。

`InstitutionModeService.Observe`：readiness.AllReady=false 时进入 Preparing；`InstitutionModeSnapshot.NewCommitmentsAllowed` 只在 Active + Desired + AllReady 时为 true。因此仅勾选 Mod 设置，并不能保证当场开放工资与消费。当前源码在开启并冻结后保存、重载，有机会建立该恢复标志；旧权益或其他故障仍可能继续阻断。此处是源码条件，未确认用户当前会话究竟缺哪项。

**修复要求（P1，启动流程）：** 明确初始化、恢复健康检查与人工完整游戏验收的区别。若仍要求首次保存重载，必须在设置和机构首页明确提示下一步；不要只显示停业或把完整验收自动等同于加载标志。新政策编辑应在准备期可用；每个支付能力以自己的已验证运行时条件放行，不得直接写 AllReady=true。

## 条件阻断二：有资金时关开制度卡在 Draining

`EconomyInstitutionMode.cs:43`：任何 TotalLiabilitiesMinor!=0 或 ActualReserveMinor!=0 都使 modeOutstanding=true。正常托管资产和账户余额也被包含。

`InstitutionModeService.cs`：关闭时若有 outstanding 则进入 Draining；再次开启，若仍有 outstanding，明确保持 Draining。这意味着没有在途交割、只有正常托管余额，也可能需要先清空全部资金才能重新营业。

**修复要求（P1，可重启性）：** 区分正常保留资产和需要完成的在途承诺/旧权益。重新开启时，只要账本健康、资产归属一致且没有不可恢复的旧事务，不应要求正常余额归零；在途承诺保留并继续履约。若确有迁移冲突，显示具体阻断对象与处理入口，不能靠反复开关解决。

## 条件阻断三：Faulted 无恢复出口

`InstitutionModeService.Observe`：`next == Faulted` 时跳过所有状态推进，即使当前故障来源已经消除也不会离开 Faulted。`ApplyInstitutionModeSetting` 又以 institutionMode.State.Fault 为第一故障来源，使历史 fault 常驻。

**修复要求（P2）：** 保留 fail-closed 行为，但提供显式、审计可追踪的重新核验命令；只有完整恢复检查通过才能解除。不要在切换设置时直接清 fault。

## 展示模型必须分层

统一输出：制度（关闭/准备/运行/清理/故障）、机构配置（未配置/营业/停业）、当前时段（营业时段/非营业时段）、能力（岗位/食品/衣物/医疗分别可用与否）及原因。机构 Open=true 不等于制度已开放支付；首页也不能把未配置与全局准备期统称为停业。

## CodeBuddy 修复顺序及验收

1. 修首页新旧读写路由，管理按钮到新政策。新建机构→设置营业→首页、政策、总览一致；旧档迁移后不读取旧 Open 作当前状态。
2. 修启动诊断，解释 SaveAcceptance、旧权益、资金异常的实际来源。首次开启与保存重载分别验证，不以加载事件冒充完整验收。
3. 修正常资产下的关开流程。注资→运行→关闭→保留余额→再开启，在无真实阻断时能恢复；在途工资/消费不得丢失或重复。
4. 加显式 Faulted 重审。故障未解决拒绝；解决且核验通过才恢复。
5. UI 与真实工资/购买请求交叉验证；仅改颜色/标签不算启用成功。
