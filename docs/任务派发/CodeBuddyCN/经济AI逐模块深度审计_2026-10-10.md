## 3. 横切制度闸门

### 已通过的结构检查

- LegacyFeesAllowed => false，旧收费/旧订单写入路径没有作为新引擎回退支付所有者。
- 正常余额不再被当作必须归零的未完成事项；关闭后保留合法余额可重新开启。
- 新 Pawn 每 250 tick 由 EconomyEnrollment.EnrollObservedPawns 建立零余额账户，避免查询副作用。
- 设置、冻结、账本恢复、故障重核验构成 fail-closed 闸门。

### 仍需实机证成的闸门

- 首次新档开启制度时，LoadedFromSave/RecoveryProvenRevision 是否按预期完成；需保存→重载→重核验的真实流程。
- Preparing、Draining、Faulted、非营业时段时，所有新承诺是否一致拒绝，既有工资/治疗权利是否仍可恢复。
- 关闭→保留余额→重开、存档→重载、旧档切换均无 GameVerified 证据。

## 4. M1：状态与需求感知

### 已证成

- Application/PawnEconomy/Perception/PerceptionCoordinator.cs：owner-thread、分组采样、每 tick 上限、过期快照、离图/死亡终态。
- PerceptionQuery 以 OutOfScope/Loading/Error/Stale/Partial/Ready 区分未知，不把未知转成零。
- 照护结算后会对受益 Pawn 标记 Needs|Body 脏域。

### 缺口

1. EconomyShadowPlanning.cs 的 planningAccounts 以会话 epoch 和 250 tick 轮询刷新，没有按 settlement.Version 或成功结算事件立即失效。工资/购买/医疗完成后，其他 Pawn 的规划可能暂时使用旧余额。
2. 食品、衣物、工资没有对应 MarkPerceptionDirty；需求改善、现金变化、机构库存变化依赖下一轮轮询。
3. 感知层没有统一的“交易完成→相关事实失效”协议。

### 修复与验收

- 规划缓存键改为 PerceptionSessionEpoch + SettlementVersion。
- 结算成功后发出 Finance/Needs/Stock 相关脏域事件。
- 验收两个 Pawn 连续消费/领薪、食品交割后的需求刷新、离图重新入图不复用旧快照。

## 5. M2：长期风格、劳动偏好与储蓄

### 已证成

- LifePolicy 有中性基线、四条批准的特质映射和 M9 学习偏移。
- LifeBudget 有储备目标、下水位、应急缓冲、收入缺口和补储滞回。
- 新 Pawn 零余额账户注册已实现。

### 缺口

- PreferredWorkHours、RetainedLeisureHours、ReserveDays、SavingBasisPoints 仍主要是固定策略值；未形成真实班次、娱乐时间、储蓄分配行为。
- ReservePreference、TimeValue、FamilyParticipation、CareerOrientation、ReliabilityPreference、SocialLeisure 多数只有读数，没有行为消费者。
- 成本源主要是食品；衣物、治疗、服务、育儿、教育、贸易订单未完整进入预算。
- EconomyFoodCostSource.CarriedNutrition 没有显式按 stackCount 累加，必须用目标游戏程序集实测，不能把堆栈覆盖量视为已验收。

### 修复

先为每个偏好定义单位、输入、消费者、可视化字段和验收场景；预算成本切片至少分为生存必需、工作必需、家庭义务、可选消费、储蓄目标；预算和实际扣款统一使用精确营养计价。

## 6. M3：短期需求与多需求迸发

### 已证成

- ShadowPlanBuilder 构造 Food/Rest/Joy 目标，支持进入/完成阈值、优先级、等待权重、风险期限、制度性受阻。
- ShadowPlanningCoordinator 对每个 Pawn 有界刷新并发布计划。
- NativeYield/WaitingFacts 已在执行层拦截。

### 缺口

- ShadowPlan 是只读影子计划；OnPlanPublished 直接按食品、衣物、求职顺序尝试，没有持久 ActionIntent、动作锁、取消、完成证据。
- 方案集包含 Purchase/Service，但 Service 没有真实供给执行器。
- NativeNeed 仍可能继续衣物购买；多个缺口没有统一“生存→医疗→收入→储蓄→可选消费”的互斥优先级。
- 执行前仅局部复核，资金、报价、岗位改变后计划可能已过期。

### 修复

引入 EconomicActionIntent：Observe → RankNeeds → SelectOneIntent → Reserve/Route → Execute → Verify → Replan。Intent 必须带 Pawn、需求、供应者/岗位、资金上限、预期事实版本、取消原因和完成证据。

## 7. M4：方案比较和候选选择

### 已证成

- 工作机会包含能力、可执行、资金、可达、工资和到账时间。
- 低可信度机构可触发候选替换。
- PlanOption 原因码已进入展示层。

### 关键缺陷

QueryFoodPricePolicy、QueryApparelPricePolicy、QueryServicePricePolicy 和库存目标投影按最低 AnchorKey 选发布者，但不检查 Open、营业时段、库存、真实可达和服务能力。停业 A 可能屏蔽营业且有库存的 B；预算和购买都会错误选择 A。

### 修复

报价使用 ProviderCandidate 集合，依次过滤真实报价、Open、时段、库存/服务能力、可达、资金证据，再稳定排序。无报价、停业、无库存和买不起必须是不同原因码。

## 8. M5：原版生活执行与自主到店

### 已证成

- Patches/PawnEconomy_ThinkTree.xml 注入 JobGiver_EconomicDemand。
- SafeDecision、Drafted、Downed、MentalState、PlayerForced 等保护输入存在。
- 已有资产使用和衣物归属恢复存在代码路径。

### 最高优先级断链

EconomyRuntime.Plan 在新制度模式下先返回 PlanTreasuryDelivery 或 PlanPreservedAssetUse。旧 PC_PEA_Visit 订单路径不再为新食品、衣物、服务购买生成到店 Job。

新路径 OnPlanPublished 直接调用 TryPurchaseFoodAtCounter、TryPurchaseApparelAtCounter、TrySignForOpportunity；两个购买函数都要求 Pawn 已在柜台约 8 格内。远处 Pawn 只能得到 NotAtCounter，不能自行前往。

### 修复

计划层产生 GoToEconomicCounter intent；JobDriver 负责预订、走位、可中断保护和到店后二次验证；到店后才 Prepare，交割成功后 Complete；食品交给原版进食，衣物交给原版穿戴并记录 PendingUse。

## 9. M6：就业、岗位与劳务合同

### 已证成

- TrySignForOpportunity 验证政策、工坊区、班次、工作类型和国库承诺额。
- 合同激活后通过工作类型所有权开启原版工作；失败会终止合同并释放所有权。
- EvaluateContractExit 由查询和维护共用，支持制度关闭、岗位删除、班次消失、能力失效。
- TrimExpiredContracts 可清理离图/销毁 Pawn 的过期合同。
- 欠薪有界重试，不把旧欠薪变成新工作证据。

### 关键缺口

1. 新签约没有车间岗位租约。TrySignForOpportunity 没有调用 MapComponent_WorkshopManager.AddSlot；旧 EconomyRuntime.FinishVisit 中的 AddSlot 位于 LegacyFeesAllowed 旧路径。打开工作类型不等于绑定目标工坊、班次和容量。
2. FulfilsContractedPosition 只检查 bill 所在工作区和存活状态，未核对真实 shift/task type；同一工作区错误配方可能领到本合同工资。
3. 工资预留只在签约时比较 OutstandingCommitments，没有进入 FundedSettlementLedger 的 Reserved 口径；其他提款仍可能耗尽未来工资或欠薪资金。
4. 岗位容量和 MaxJobs/计件上限概念混用。

### 修复

创建持久 WorkshopSlotLease，绑定 contractId、anchor、zone、shift、task type、pawn、expires、remaining jobs；工作开始/完成均核验 lease；将未付工资和活跃合同保证额纳入唯一可用余额。

## 10. M7：消费、衣物与服务

### 已证成

- 食品和衣物使用机构自持库存、真实可食/可穿条件、个人账户余额、Prepare/Complete。
- 交割失败有实际移动物品回滚和待对账分支。
- 衣物结算后穿戴失败保留衣物并显示 PendingUse。
- 治疗证据使用稳定 evidenceId；活动授权选择检查到期、额度和指定执行者。

### 关键缺口

1. 无远端到店 Job。
2. 商品交付没有独立持久凭证。PawnSettlementSaveHost.Recover 主要根据银币 movement journal 恢复，无法证明商品当前持有者和交付阶段。
3. 背包已有同类堆时，TryHandOver 的 taken 可能被吸收销毁；ReturnToStock 看到 destroyed 后不能追回。
4. TrySettleCareAct 没有统一读取 NewCommitmentsAllowed、Open、InHours；停业、Preparing 或非营业时段仍可能在已有授权/报价下收费。
5. CompletePurchase 成功后 Care.Charge 失败时，Replay Finalized 直接返回 Applied，授权额度可能没有补记。

### 修复

建立 GoodsDeliveryEvidence；商品和银币使用分开的恢复协议但共用同一资金账本；医疗收费统一制度/机构能力门；以 evidenceId 关联“结算已完成”和“授权已扣额”，支持幂等补记。

## 11. M8：家庭、照护和医疗机构

### 已证成

- CareAuthorization 表达 beneficiary、guardian、executor、payer。
- SelectChargeable 使用未过期、未用尽、执行者匹配的统一选择器。
- 治疗接入原版 tend 证据，授权额度有上限和到期时间。
- 非 CaptureWired 类型周期复核能力，未知时保持原版公共路径。

### 未完成

Childcare、Education、Bed 目前主要是授权/能力状态，未形成婴儿喂养、陪护、教学、床位占用的自主任务。家庭参与度、监护人、执行者和付款人没有进入短期动作调度。

### 修复

按 Treatment 完成一类完整服务证据链，再扩展 Childcare、Education、Bed；所有服务复用统一授权、路由、交付、结算和恢复协议。

## 12. M9：学习、可信度与风格适应

### 已证成

- StyleLedger、重试失败和下次尝试 tick 已落盘。
- 风格摘要有 summary id 去重、每日限幅和有界容量。
- 工资结算结果会影响 ReliabilityPreference 学习偏移。

### 缺口

- wageExperience 是 GameComponent 内存字段，不在 EconomyLearningPersistence 中导出；读档后机构可信度回到中性。
- RecordSettlementOutcome 以 obligation 结果调用 RecordWageOutcome，ExperienceLedger 没有 obligationId 去重；同一欠薪多次重试会产生多个样本。
- 多个风格维度没有行为消费方，学习结果可能只在 UI 改变。

### 修复

可信度改为 obligationId→最终结算结果；重试只更新同一行；明确保存协议或在 UI 标记为会话统计；每个学习维度必须说明影响哪个候选、阈值或时长。

## 13. M10：再生产与公共机构补货

### 已证成

- 真实资源计数、机构库存目标和工坊 bill 读数可读。
- 授权提案先创建真实 vanilla bill，再写入有限授权账；重复提案返回原回执。
- 生产完成 patch 能按 bill key 核销交付。

### 缺口

- DemandDomainNotWired 和 TradeDomainNotWired 仍为 Unknown；消费需求、订单需求、外贸出口没有进入补货输入。
- ReadWorkInProgress 只要 bill.ShouldDoNow 就累加配方产量，没有确认材料、设备、执行 Pawn、实际开工。
- 扫描达到上限时仍可能 complete=true。
- 补货主要由授权页触发，没有自动从需求缺口产生订单、执行、入库、消费/贸易闭环。

### 修复

分离已确认需求、已授权未开工、已开工在制、已交付入库四桶；每桶有稳定 key 和恢复证据；扫描截断发布 Partial/Unknown。

## 14. M11：资金、储蓄与持久化

### 已证成

- FundedSettlementLedger 是新体系唯一资金账本；Prepare/Replay/Conflict/Cancel/Finalize 阶段明确。
- 零余额账户不占交易 entries。
- 银币物理 reserve journal 有版本、证据和读档恢复。
- 制度关闭区分正常余额和未决结算行。

### 关键缺口

- MaximumEntries=4096，满额后 Prepare 永久返回 CapacityReached；没有安全终态归档/压缩，长档会停止购买、发薪和医疗结算。
- EmploymentSaveData 合同/应付/证据分别固定上限；证据 key 不能简单裁剪，但没有归档水位和防重摘要。
- 工资承诺没有进入账本 Reserved。
- 商品交付和银币 movement 使用不同事实源，读档没有统一恢复状态。
- 跨存档重试必须区分业务幂等 key 和账本版本，否则旧 Intent 可能误判 CommandConflict。

### 修复

设计终态归档，保留账户快照、命令 id 水位、未付权利和防重摘要；将未付工资、活跃合同保证额、未决行接入唯一可用余额；商品、医疗、工资分别记录业务凭证，但所有货币变更仍进入同一账本。

## 15. M12：RUIF 展示与玩家可见性

### 已证成

- 需求/决策页展示目标、满足度、阈值、预算、水位、岗位、四循环和阻断原因。
- 机构首页已读取新 InstitutionPolicy，管理动作指向新政策页；旧记录标为历史只读。
- 机构行能显示制度阶段、营业状态、时段和能力原因。

### 缺口

- BuildAccounts、BuildLedger、BuildJobs 仍主要读取旧 State 的 EconomyAccount/EconomyReceipt/EconomyContract；新结算账本、EmploymentService、Care、ProductionAuthorisation 未完全汇总。
- UI 显示 ShadowPlan/候选/循环只能证明观察和规划，不证明 Job、到店、交割、工资和需求改善。
- LegacyFeesAllowed=false 会剥掉旧动作 verb；需实机确认新政策页和新账本页仍有有效玩家控制入口。
- 没有实机截图/录制证明中文字体、四向机构资产、状态颜色和长文本。

### 修复

建立只读 EconomyOverview 投影，统一新账本账户、合同、欠薪、授权、服务能力、商品凭证和生产授权；每个行动显示计划、Job、执行阶段、最终事实四段。

## 16. 修复优先级

## 17. 最小实机验收清单

每条记录：存档、地图、tick、Pawn key、机构 key、账本 version、结果、截图/日志、程序集 SHA-256。

### 冷启动与制度

- 新档：开启制度→保存→重载→Active。
- 新 Pawn：账户自动为 0，不手动发钱；国库有资金和岗位时自动签约。
- 关闭→保留余额→重开；真实未决事务仍阻断并可重核验。
- Faulted→修复→Reverify；不能靠切换设置伪清除。

### 多需求与自主行动

- 远离商店、食物低、账户有钱：自动走到正确柜台、交割、原版进食。
- 账户无钱、开放岗位、工作类型全 0：自动签约、进入目标工坊、完成任务、到账。
- 同时 Food/Rest/Joy/Medical 缺口：顺序符合规则，不让可选衣物抢占生存。
- PlayerForced、Drafted、危险、倒地、精神状态出现：动作中断且未使用资金/物品不丢失。

### 交易和恢复

- 背包已有同款堆、机构库存堆：成功/失败回滚数量守恒。
- Prepare 后商品离库或结算异常→保存→重载：商品、钱、账本阶段可解释，不免费、不重复。
- 医疗重复事件：同 evidenceId 不重复扣钱/扣额度。
- 钱已结算、授权扣额失败：重试后两边收敛。

### 就业和资金

- 两人争一个岗位：仅一人获得 lease，另一人显示原因。
- 签约后提款：不能耗尽保证工资。
- 错误工坊/配方：不发本合同工资。
- 离图/销毁/删班次/关闭机构：合同按规则终止，玩家值不被覆盖，欠薪仍可支付。

### 再生产和展示

- 无原料时：待做 bill 不抵扣真实缺口。
- 扫描截断：Partial/Unknown，不显示完整确定数。
- 重复授权提案不重复建 bill；产出后按 bill key 核销。
- UI 同时显示新账本、新合同、新授权、新需求；计划/Job/结算/需求改善不可混淆。
- 五类机构四向资产：北向基准、四向朝向、健康状态、遮挡、中文标签均截图验收。
