## 1. 模块定位与设计红线

### 1.1 定位
PersonalChronicle 是**殖民地档案馆**：游戏内真实发生的事件 → 数据层写入 → Read Model 聚合 → UI 呈现。装备传承模块记录**一把武器的完整生命周期叙事**：来自哪里、被谁铸造、历经几代持有者、与谁同袍共用、最终如何退役。

### 1.2 设计红线（落地全程严格遵守）

| # | 红线 | 落地方式 |
|---|------|----------|
| 1 | **只读记录，不制造机制** | 退役捕获 `Patch_ThingDestroy` 是 **Postfix**，绝不跳过原方法 |
| 2 | **数据驱动，零硬编码叙事** | 所有展示内容来自真实事件流 / 持有记录 / 退役捕获，无凭空生成文本 |
| 3 | **窗口只消费快照** | 排序 / null-guard / 重叠计算归属 `ArchiveUiDataProvider` |
| 4 | **UI 经 Design System 两层** | `UITheme` 令牌 + `UIComponents` 组件，无窗口内散落 `GUI.color = new Color(...)` |
| 5 | **配置与代码分离** | 捕捉规则 / 阈值 / 黑名单全在 `Defs/ThingArchivePolicy.xml`，可 PatchOperation 覆盖 |

## 3. 装备捕捉范围（Thing Archive Policy）

### 3.1 背景
v4.9 前 `Overview › Thing` 硬编码 `def.IsWeapon || def.IsApparel`，把**所有可穿戴物**都收进档案（防尘衣 / 工作服 / 时尚衣等无战斗价值服装），污染装备类别统计与侧栏。

### 3.2 判定规则（v4.9.1）

```
Captures(ThingDef def):
  1. def == null            → false
  2. def.IsWeapon           → !黑名单命中（黑名单 = excludeApparelDefNames）
  3. def.IsApparel:
       - 黑名单命中           → false
       - excludeNonCombatApparel == false → true（放行全部服装）
       - 否则: MaxCombatArmor(def) >= minCombatArmorForApparel(默认 0.20)
  4. 其他类别               → false

MaxCombatArmor = max(Sharp, Blunt)  ← 取最高单项，不算 Heat
```

**关键教训**：护甲判定用「最高单项」而非「总和」——总和会让防尘衣（Sharp 0.12 + Blunt 0.10 = 0.32）误判为战斗服装。

### 3.3 默认配置（`Defs/ThingArchivePolicy.xml`）

```xml
<PersonalChronicle.Domain.ThingArchivePolicyDef>
  <defName>PersonalChronicleThingArchivePolicy</defName>
  <excludeNonCombatApparel>true</excludeNonCombatApparel>
  <minCombatArmorForApparel>0.20</minCombatArmorForApparel>
  <excludeApparelDefNames></excludeApparelDefNames>
</PersonalChronicle.Domain.ThingArchivePolicyDef>
```

### 3.4 单点收窄
所有 Thing 类别来源（捕捉 → 侧栏 / 统计 / 详情）都走 `RegisterThingObject`。收窄 `ArchiveService.IsEquipableDef`（改用 `ThingArchivePolicy.Captures`）即**全链路一致**，UI 侧无需任何改动。

### 3.5 解析机制（`Domain/ThingArchivePolicy.cs`）
- **懒加载**：`DefDatabase<ThingArchivePolicyDef>.GetNamedSilentFail`（Defs 加载后安全）
- **缓存**：`policyResolved` 门控，Def 缺失时不锁死，下次重试
- **回退**：Def 缺失时返回 `DefaultFallback()`（同默认阈值），调用方永不看到 null
- 镜像 `SocialRelationFilter` 既有模式

## 6. 退役仪式捕捉链路

```
Thing.Destroy(DestroyMode)  →  Patch_ThingDestroy Postfix
    │  (Harmony PatchAll 自动生效，签名探测防漂移)
    ▼
过滤器：ThingArchivePolicy.Captures(__instance.def)   ← 与捕捉范围同源，防漂移
    + 仅已入档物品（HasRecord）
    ▼
IArchiveService.OnThingDestroyed(Thing, Pawn)
    ▼
ArchiveService：写 DecommissionRecord（Tick/最后持有者/地点/服役天数/最后战役）→ ThingObject.Decommission
```

**关键点**：
- Postfix 不跳过原方法（只读红线）
- 捕捉与退役用**同一 policy**——退役 patch 与注册集永不失配
- `PlaceLabelForDestroyedThing` 处理退役地点标签

## 7. UI 规范落地

### 7.1 传承「当前持有者」行高亮（v4.9.1 UI 修复）

**问题**：原实现 `GUI.color = UITheme.WithAlpha(UITheme.Alive, 0.12f); Widgets.DrawBoxSolid(row, Color.white);` —— Alive 是亮薄荷绿（0.57, 0.90, 0.69）× 白底 → **米黄**，与深色工业终端风冲突。

**修复**（两步收敛）：

```csharp
// 最终实现 —— 完全合规
if (h.IsCurrent)
{
    UIComponents.TintedBox(row, UITheme.AccentSoft);
}
```

| 规范项 | 合规点 |
|---|---|
| §1 两层架构 | `UITheme.AccentSoft`（令牌）+ `UIComponents.TintedBox`（组件） |
| §2 配对恢复 | `TintedBox` 组件内建 `prev` 快照 + 恢复，窗口零手写 |
| §2 禁散落 `new Color` | 窗口无颜色字面量，全走令牌 |
| §3 色表对齐 | `AccentSoft` = Accent @ 0.15（`ColoredText.NameColor` 派生） |
| §5 窗口边界 | 只消费 `LegacyView` 快照 |

### 7.2 新绘制全走组件
`DrawLegacyTab` / `DrawOriginTab` / `DrawCoUseTab` / `DrawDecommissionTab` 的绘制统一用 `UIComponents.Label/Pill/Badge/StatCell/Rule/TintedBox`，无裸 `GUI.color`。
