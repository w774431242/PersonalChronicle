## 1. 一句话定位

Pawn 检视窗的第三个页签「个人需求」（`ITab_Pawn_PersonalNeeds`）：**一页式 + 页内三页签**（需求 / 目标 / 决策），**整页由 RUIF 绘制**，把「经济需求驱动 AI」模型的**需求循环**（观察 → 缺口 → 目标 → 仲裁 → 预算）呈现给玩家。

**两条不可动的定位约束：**

1. **不接管原版「需求」Tab**（`RimWorld.ITab_Pawn_Needs` 保持纯净，玩家有两页）
2. **不调用任何原版需求 UI**（`NeedsCardUtility` / `PawnNeedUIUtility` / `Need.DrawOnGUI` 一律禁用）——原版仅作为**数据真值来源**（读 `Need.CurLevelPercentage`）

## 4. 三页签内容规格

| 页签 | 分区 | 内容 | 数据来源（View 字段） |
| --- | --- | --- | --- |
| **① 需求** | 概览卡 | 生活保障满足度条 + 「已规划 N · 仅观察 M」+ 心情 | `Needs` 均值 · `HiddenCount` · `Mood` |
| | **个人账户**（概览卡内次级分组） | 可用余额（最突出、固定两位小数 + 银币单位）/ 账户总额 / 预留金额 / 生活储备目标 / 补储缺口 / 收入状态；账户不可读时**只留标题与状态说明**（绝不显示 0.00）；两处悬停解释 + 「查看决策详情」页内跳转决策页签 | `Account`（`NeedAccountView` / `PawnEconomyFactsPresenter.BuildAccount`） |
| | 需求满足度 | **优先级芯片 + 活跃呼吸点** / 需求 / 条 / 满足度 / 长期目标 | `Needs[].Priority/Active/Ratio01/RatioState/Target` |
| | 其它需要 | 原版不显示的需求（`showOnNeedList=false`），单独成区（同结构） | `Needs[].Hidden/Target` |
| | 状态条件 | D03 衣着与温度 / D09 健康与生育准备 | `Status` |
| | **长期生活规划** | 生活政策参数（工时 / 闲暇 / 储备 / 储蓄倾向）+ 政策来源 | `LongTerm`（`BuildLongTerm`） |
| **② 目标** | **目标卡 ×N** | 每条需求一张卡：芯片 + 呼吸点 + 满足度条 + **进入阈值 → 目标值** + **等待加权行**（`已等待 N / 上限 M`，0 时不出行）+ **缺口三口径**（相对/绝对/原始）；未纳入规划者也可成行 | `Goals`（`NeedGoalLine` / `BuildGoals`） |
| **③ 决策** | **四个业务循环** | 即时满足 / 储蓄保障 / 劳动收入 / **消费与服务（M7/M8 真实三态：可行 / 受阻 / 未接通）** | `Cycles`（`NeedCycleLine` / `BuildCycles`） |
| | **劳动与合同** | 合同状态（履约中/未签合同）+ 岗位 / 工资与计件 / 剩余期限与**退出预判**（M6）/ **应付工资** / **购买退避**（M9）/ **机构工资可信度**（分档 + 样本） | `Employment`（`NeedEmploymentView` / `PawnEconomyFactsPresenter`） |
| | **照护与服务** | 以本 Pawn 为**受益人**的照护授权（种类 / 已计费 / 上限 / 剩余期限）+ 治疗服务能力状态（无授权且能力不可读时整区隐藏） | `Care`（`NeedCareView` / `PawnEconomyFactsPresenter`） |
| | 影子仲裁 | 规划阶段 / 计划龄 / 拟选行动 / 原因 / 拟选岗位 | `Planning`（`Build`） |
| | 预算与储蓄 | 预算状态（自解释）+ 现金（**带进度条**）/ 储备目标 / 水位 / 收入缺口 / 补储 + **三分配**（即时/储蓄/可选） | `Budget`（`NeedBudgetView` / `BuildBudget`） |
| | 候选岗位 | 每个 offer 一行（工资 / 能力 / 执行 / 资金 / 可达） | `Opportunities`（`BuildOpportunities`） |
| | 观测明细 | 原始观测事实（含数据龄、事实状态） | `Facts` |
