  • 让 CodeBuddy 打开 docs/UI预览/*.html 并读取 console / 网络请求——精准捕获此前手动才发现的"勋章路径 404""资源 404"类问题。

4.1 dnSpyEx（C# 运行时断点调试 · 对标 DevTools Sources）

核心用途：在游戏运行中直接对 Mod 代码下断点、单步、查看局部变量与调用栈，用 Immediate 窗口执行任意表达式，并可临时改写方法体（IL）后立即生效、免重启验证假设。这是本项目唯一可用的「运行时源码级调试」能力，补齐 Verse.Log 只能事后翻日志的缺口。

位置：D:\toolbox\dnSpyEx（v6.6.0 x64 自包含版，已写入系统 PATH）· GUI dnSpy.exe + 命令行 dnSpy.Console.exe

关键组件：dnSpy.Debugger.DotNet.Mono.x.dll——RimWorld 跑在 Unity/Mono 后端，附加调试必须依赖此 Mono 调试引擎（已随包提供，无需另装）。

使用方式

  1. 启动 RimWorld 并进入存档（别在空载主菜单就附加，易在加载期断到无关代码、拖慢排查）。
  2. dnSpy.exe → Debug ▸ Attach to Process → 选 RimWorldWin64.exe → 调试引擎选 Unity / Mono。
  3. File ▸ Open 打开 Assemblies\PersonalChronicle.dll（或发布区那份，与游戏实际加载的一致），在方法上按 F9 下断点。
  4. 命中后可查看 this、局部变量、调用栈；Immediate 窗口直接调静态方法验证逻辑（如 ProfessionalEffectResolver.ResolveContributions(...)）。
# 反编译留证（本项目既有做法，产物落 %TEMP%\rw_spy）
ilspycmd -p -o out_dir Source\PersonalChronicle\bin\Release\PersonalChronicle.dll
# dnSpy 命令行用法
dnSpy.Console.exe --help
注意：dnSpy 里的 IL 改动只在内存中，不落盘。用于快速证伪/证实，确认结论后仍须改源码重编译，并走「dll 同步发布区 + 哈希校验」正常流程。

4.2 Roslynator CLI（静态审计 · 对标 DevTools Lighthouse / Issues）

核心用途：不启动游戏、不跑 Unity，直接对 Source\PersonalChronicle.csproj 做一次静态诊断扫描——死代码、可空性、多余分配、可简化表达式、拼写等，产出「问题清单」。把代码门槛从「编译 0 错 0 警」提升到「性能陷阱与坏味道可见」。

位置：D:\toolbox\bin\roslynator.exe（v1.0.0.0，Roslyn 5.0，dotnet tool 安装，随 D:\toolbox\bin 已在系统 PATH）

常用命令（已实测）

# ① 全量诊断 —— 必须显式给 --analyzer-assemblies，否则报 "No analyzers found" / 0 diagnostics
roslynator analyze Source\PersonalChronicle.csproj --analyzer-assemblies "D:\toolbox\roslynator-analyzers\4.16.1\analyzers\dotnet\roslyn4.7\cs" > _verify_tmp\roslynator_analyze.txt
# ② 代码规模统计（实测 783ms；27,837 逻辑行 / 61,612 总行）
roslynator lloc Source\PersonalChronicle.csproj
# ③ 拼写检查（注释 / 本地化键 / 标识符）
roslynator spellcheck Source\PersonalChronicle.csproj
关键坑（首次踩到）：roslynator analyze 只跑「项目自身引用的分析器」，本项目 csproj 未引任何分析器包 → 直接跑会输出 No analyzers found / 0 条诊断。解决方式二选一：
① 用 --analyzer-assemblies（简写 -a）指向已落盘的 Roslynator 分析器包（推荐，不动构建门禁）；
② 在 csproj 加 Roslynator.Analyzers 的 PackageReference（会让诊断随 dotnet build 一起输出，需按警告量分阶段收紧，否则淹没「0 错 0 警」门禁）。
分析器包选 4.16.1 的 roslyn4.7 变体：Roslynator CLI 1.0.0 自带 Roslyn 5.0，可向后兼容加载 Roslyn 4.x 分析器（roslyn3.8 变体亦可，但 roslyn4.7 更贴近）。
首次审计基线（2026-09-10）：1702 条诊断（1691 info / 11 warning），产物 _verify_tmp\roslynator_analyze.txt。规则集中在风格类：RCS1146、RCS1123(412) 加括号、RCS1206(207) 条件访问、RCS1226(178) 文档段落、RCS1118(168) 局部变量可 const、RCS1163(120) 未用参数。热点文件：ITab_Pawn_Career.Qualification.cs(105)、OverviewFieldRegistry.cs(80)、ITab_Pawn_Career.Overview.cs(69)。
值得优先处理的 11 条 warning：3 × RCS1075 空 catch 吞 System.Exception（Capture\Patch_BuildingLabel.cs:43、Capture\Patch_PawnTitleBadge.cs:132、Capture\Patch_RoomRoleLabel.cs:107）；2 × RCS1263 文档注释参数名不存在（Data\ChronicleGameComponent.cs:743 注释里的 force、Application\MedalAwardService.cs:102 注释里的 component）；6 × RCS1139 缺 summary。lloc 亦可为「ITab_Pawn_Career.Overview.cs 破 800 行」这类拆分提供量化依据，替代人肉估算。

4.3 Dubs Performance Analyzer（游戏内性能剖析 · 对标 DevTools Performance）

核心用途：游戏内逐项归因 CPU 开销——Harmony 补丁耗时排行、Tick/Update/AI/渲染分项、GC 分配量与分配热点。直接回答「Capture 补丁每 tick 花多少 ms、GC 是不是被我拉高」，是验证本项目两条性能红线（每帧入口禁 new/GetComponent/Find.*、CacheRefreshInterval 唯一刷新门控）的唯一实测手段。

来源：Steam Workshop 本体 ID 2038874626（作者 Dubwise，支持 1.6）· 汉化可选 3525634104 或 3547165458（任选一个，勿叠加）

接入约定（重要）

  • 仅调试档启用：这是开发者工具，不得写入本项目 About.xml 的 modDependencies——玩家不需要它。
  • 需在游戏 选项 ▸ 开发者模式 打开后使用其面板；数据可导出供离线分析。
  • 与自研 PerfProbe（Start/End("key",t0)，Settings 内 EnablePerfProbe 默认关）配合：DPA 给全局归因，PerfProbe 给自定义代码段计时。
  • 前置依赖：Harmony（本机已订阅 2009463077）。
对照：Unity Profiler 对本项目不可用——RimWorld 是 release 构建，不含开发符号与 Profiler 端口。
