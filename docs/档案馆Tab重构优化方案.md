# 档案馆 Tab 重构优化方案（v3.1）

> 触发：Tab 镜像原版、过碎过陋；v3.0 评审后继续收紧——**概览加厚、生涯加深、战史→战斗履历、纽带→社会关系、移除统计**。  
> 基线：`ArchiveMainTabWindow` + `IArchiveService` v2.4  
> 规范：rimworld-modder  
> **可交互真源**：[`docs/ui-preview/archive-ui-preview.html`](./ui-preview/archive-ui-preview.html)（UI Spec **v3.1**）

---

## 一、结论摘要（先答三个问题）

### 1.1 设计内容覆盖是否广泛？

| 维度 | v3.1 覆盖 | 广度评价 |
|---|---|---|
| 身份与生命周期 | 概览：身份 / 加入·死亡 / 在殖天数 / 背景快照 | ✅ 档案封面级完整 |
| 时间叙事 | 编年：全事件 + kind 过滤 | ✅ 档案馆核心 |
| 劳动与贡献 | 生涯：工时深表 · 产出 · 技能成长 · 主业/副业 · 贡献摘要 | ✅ 职业履历主轴 |
| 暴力与伤亡 | 战斗履历：参战 · 击杀 · 阵亡档案 · 关联武器 | ✅ 战斗史完整 |
| 人际 | 社会关系：重要关系 · 事件共现人物 · 关系事件 | ✅ 人际史（非 opinion 面板） |
| 空间足迹 | **收进概览**（主驻地 / 地点履历摘要），不占社交 Tab | ✅ 避免和「社会关系」概念打架 |
| 物品网络 | 产出→生涯；装备/凶器→战斗履历与武器档案流转 | ✅ 按语义分流 |
| 纯数字墙 | **删除统计 Tab**；KPI 进概览头条 + 各 Tab 页脚小计 | ✅ 去重、减按钮 |

**广度结论**：对「殖民者个人档案」主轴（是谁 → 经历了什么 → 干了什么 → 打过什么 → 和谁有关）**覆盖已足够广泛**。  
未做进 v3.1 主路径、但可二期扩展的：研究贡献细账、医疗手术编年、心理崩溃史、宗教/意识形态转变、基因改造史、商队远征细账——见 §五「已知缺口」。

### 1.2 是否符合档案馆主题？

| 档案馆应有 | v3.1 做法 | 判定 |
|---|---|---|
| 记录「已发生事实」 | 事件编年 + 累计工时/产出/参战 | ✅ |
| 死后仍可回看 | 全 Tab 主数据可存档；活读仅角标 | ✅ |
| 不是第二角色卡 | 无优先级/实时 hediff/实时 opinion | ✅ |
| 可检索的人生故事 | 概览里程碑 + 编年过滤 + 关系/战斗交叉跳转 | ✅ |
| 少而厚的目录 | **人物 5 Tab / 武器 4 Tab** | ✅ |

**主题结论**：**符合「殖民地档案馆 · 个人履历」**，而不是「原版信息面板聚合器」。

### 1.3 个人履历是否全面？

把「个人履历」拆成六块人生问题：

| 人生问题 | 落点 | 深度 |
|---|---|---|
| 你是谁？ | 概览 · 身份区 | 厚（含背景快照、在殖时长） |
| 你的一生按时间怎么走？ | 编年 | 厚（事件流） |
| 你靠什么立足、贡献了什么？ | 生涯 | **加深**（工时/产出/技能/主副业/贡献摘要） |
| 你经历过哪些生死战斗？ | 战斗履历 | 厚（参战+击杀+阵亡） |
| 你和谁绑定过命运？ | 社会关系 | 中厚（关系类型+共现+关系事件；婚姻等采集二期加深） |
| 数字总账？ | 概览 KPI（取消独立统计） | 够用 |

**履历结论**：v3.1 下个人履历 **主轴全面**；短板集中在「需要新采集」的社会事件（结婚/离婚/仇敌结成）与医疗史，不靠再加 Tab 解决，而靠加深 **社会关系 / 编年 kind**。

## 二、相对 v3.0 的变更清单

| 变更 | v3.0 | **v3.1** | 理由 |
|---|---|---|---|
| 人物 Tab 数 | 6 | **5** | 去掉统计，目录更干净 |
| 战史 | 战史 / Combat | **战斗履历** / CombatLog | 强调履历而非战报面板 |
| 纽带 | 纽带（人+物+地混装） | **社会关系**（以人为主） | 语义收紧；地点→概览足迹；物品→生涯/战斗 |
| 统计 | 独立 Tab | **移除**；KPI 并入概览 | 与概览头条重复 |
| 概览 | 4 KPI + 短字段 | **全面封面**（见 §3.2） | 用户反馈不够全面 |
| 生涯 | 工时+产出+技能 | **加深**（主副业、贡献摘要、产出分类、技能成长幅度） | 用户反馈不够深 |
| 武器 Tab | 5（含统计） | **4**（概览/编年/战斗履历/流转） | 统计并入概览 |

```
人物 v3.1：
┌──────────────────────────────────────────────────────────┐
│  [概览]   [编年]   [生涯]   [战斗履历]   [社会关系]      │
└──────────────────────────────────────────────────────────┘

武器 v3.1：
┌────────────────────────────────────────────────┐
│  [概览]   [编年]   [战斗履历]   [流转]         │
└────────────────────────────────────────────────┘
```

## 三、目标信息架构（v3.1 定稿）

### 3.1 Tab 总表

| Key | 中文 | 英文 | 一句话 |
|---|---|---|---|
| `Overview` | 概览 | Overview | 档案封面：身份 · 生命周期 · KPI · 足迹 · 里程碑 |
| `Timeline` | 编年 | Chronicle | 全部历史事件时间轴 |
| `Career` | 生涯 | Career | 劳动工时深表 · 产出 · 技能成长 · 贡献 |
| `CombatLog` | 战斗履历 | Combat record | 参战 · 击杀 · 阵亡档案 · 关联武器 |
| `Social` | 社会关系 | Social | 重要关系 · 共现人物 · 关系向事件 |

武器：`Overview` · `Timeline` · `CombatLog` · `Custody`（流转）

### 3.2 概览 — 必须「全面」的封面结构

```
┌─ 姓名 ──────────────────────── [在世|已故] ── 活读角标(可选)
│ 身份行：职业 · 派系 · 背景(童年/成年快照) · 在殖 X 日
│
│ ┌ KPI 条：事件 | 工时 | 产出 | 参战 | 击杀 | 关系 ─┐
│ └────────────────────────────────────────────────┘
│
│ 【生命周期】加入 / 死亡 / 死因 / 凶手（已故）
│ 【生涯摘要】主业 · 副业 · 代表技能成长 · 代表产出 1 条
│ 【足迹】主驻地 · 地点数 · （在世）当前地图角标
│ 【里程碑】3～5 条（首次加入/首件制造/首战/婚约/阵亡…）
│ 【关键事件】最近 3 条（可点进编年/事件）
└────────────────────────────────────────────────────
```

原则：
- **先故事与数字，后字段**；DetailRow 只服务生命周期与身份。  
- 原「统计 Tab」的 EventCount / FirstLast / TotalWork 全部在此可见。  
- 死后：活读角标消失，KPI/生涯摘要/足迹/里程碑仍满。

### 3.3 生涯 — 必须「更深」的职业结构

| 区块 | 内容 | 深度要求 |
|---|---|---|
| **A. 生涯结论** | 主业（工时 Top1）· 副业（Top2）· 劳动总工时 · 「贡献一句话」 | 顶部先给结论，非直接扔表 |
| **B. 工时深表** | 工作类型 \| 累计工时 \| 占比条 \| 最近从事 \| **排名** | **禁止优先级**；可按工时排序 |
| **C. 产出履历** | 按类型聚合：数量 · 最近一次 · 可跳转物品档案；可选分组（武器/服装/建筑） | 保留并加分组 |
| **D. 生涯脚注** | 采样说明（自本版本起 / 死后冻结） | 诚实空态 |

> **v4.x 变更**：生涯不再含独立的「技能档案」区块（原 D 行：技能\|入档\|当前/死亡\|Δ 成长）。技能能力仅作为同工种卡片矩阵的附属信息展示（见 `工时强度评价设计.md`），不单独成区；死后快照语义不变。

二期加深（不挡 v3.1 UI）：季节工时分布、职称/理念相关工作、研究项目列表。

### 3.4 战斗履历（原「战史」）

| 区块 | 内容 |
|---|---|
| **阵亡档案**（若已故） | 死亡日期 · 死因 · 凶手 · 关联战役 · 关联武器（可跳转） |
| **参战列表** | 日期 · 战役名 · 角色（参战/阵亡）· 可进事件 |
| **击杀记录** | 日期 · 目标摘要 · 所用武器（人物侧从死亡事件反查） |
| **页脚 KPI** | 参战次数 · 击杀数 · （可选）受伤次数二期 |

不做：实时健康条、当前 hediff 列表。

### 3.5 社会关系（原「纽带」）

| 区块 | 内容 | 不做 |
|---|---|---|
| **重要关系** | 类型（恋人/配偶/仇敌/导师/亲属…）· 对方 · 状态（存续/已故/已结束）· 可跳转 | 实时 opinion 数值墙 |
| **命运交织** | 因共同事件关联的人物（同战役、制造链、凶手等） | 把「物品」当社交主体 |
| **关系事件** | 过滤后的社交向编年子集（结婚/分手/见义勇为…有采集后填充） | 无事件时诚实空态 |
| **地点** | **不在此 Tab** | 见概览「足迹」 |

物品关联：制造物在 **生涯·产出**；凶器在 **战斗履历**。

### 3.6 编年（保持灵魂地位）

- 全量事件；kind 过滤（加入/死亡/制造/建造/战役/…）  
- 行：日期 · 标题 · 参数；展开描述 + 跳转 chip  
- 与概览「关键事件 / 里程碑」同源，仅展示窗口不同

### 3.7 统计 Tab — 移除与迁移

| 原统计字段 | 迁移到 |
|---|---|
| 事件数 / 关联数 | 概览 KPI |
| 最早/最近事件 | 概览生命周期旁或关键事件区 |
| 总工时 / 主业 | 概览生涯摘要 + 生涯结论区 |
| 参战/击杀 | 概览 KPI + 战斗履历页脚 |

## 四、覆盖面矩阵（档案馆主题验收用）

### 4.1 人物档案 × 主题适合度

| 内容块 | 主题适合 | 死后可回看 | v3.1 位置 | 采集现状 |
|---|---|---|---|---|
| 加入/死亡事件 | ✅ | ✅ | 编年/概览 | ✅ 已有 |
| 制造/建造 | ✅ | ✅ | 生涯/编年 | ✅ 已有 |
| 战役参与 | ✅ | ✅ | 战斗履历 | ⚠️ 部分 |
| 工时累计 | ✅ | ✅ | 生涯 | ❌ 需采样 P1 |
| 技能快照 | ✅ | ✅ | 生涯 | ⚠️ 字段有、写入需补 |
| 重要关系事件 | ✅ | ✅ | 社会关系 | ❌ 二期为主；先共现边 |
| 地点履历 | ✅ | ✅ | 概览足迹 | ❌ 需采集 |
| 工作优先级 | ❌ 非档案 | — | **禁止** | 废弃展示 |
| 实时伤口列表 | ❌ 角色卡 | ❌ | **禁止** | — |
| 实时社交数值 | ❌ 角色卡 | ❌ | **禁止** | — |

### 4.2 「是否还要加 Tab？」决策规则

只在同时满足时加第 6 个 Tab：  
1) 独立叙事轴（无法放进现有 5 个而不毁掉语义）；  
2) 已有稳定采集；  
3) 死后仍有整页价值。  

当前 **医疗史 / 意识形态史 / 远征史** 均未同时满足 → **不进 v3.1 目录**，进二期编年 kind 或生涯子区块。

## 八、成功标准（v3.1 DoD）

1. 人物 **恰好 5** Tab，武器 **恰好 4** Tab；无「统计」按钮。  
2. 概览一页能回答：是谁、何时来去、贡献摘要、足迹、里程碑、关键数字。  
3. 生涯一页能回答：主业是什么、各工作干了多久、造过什么、技能如何成长。  
4. 战斗履历 / 社会关系命名与内容语义一致；无物品/地点硬塞进社会关系。  
5. 死后打开任一 Tab 不出现「整页无实时数据」作为唯一内容。  
6. HTML 预览与本文 §三 结构一致，作为改 C# 前的验收板。
