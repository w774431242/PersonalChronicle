# 统计活读化修复方案（问题一）

> 对应问题：档案馆统计是静态数据层——无法统计新角色、无法精准统计当前殖民者数
> 生成方式：团队 SOP（系统/兼容并行 → 质量审计 → 汇总裁决）
> 日期：2026-08-08 21:30 ｜ 基线：RimWorld 1.6.4871，用户环境 221 mod

---

## 〇、根因（三专家共识）

| 问题 | 根因 | 代码点 |
|---|---|---|
| 无法统计新角色 | `BackfillExistingColonists` 仅读档时跑一次；后续加入仅依赖 `Patch_SetFaction`，Biotech 怀孕出生 / xenogerm 转化 / mod 招募路径不走 SetFaction → 漏采 | ChronicleGameComponent 479-520 / Patch_SetFaction |
| 无法精准统计当前殖民者数 | `RebuildPawnCounts` 数的是**档案快照**（`!IsArchived`），非游戏运行时 `FreeColonists`；放逐/卖奴无"离开"事件导致虚高 | ArchiveMainTabWindow 189-208 |

**核心缺陷**：统计读的是"档案里有多少"，不是"游戏里现在有多少"——活读与快照两个概念混为一谈。

## 一、修复方案（三支柱，零新增 Harmony）

### 支柱 1：活读统计（当前殖民者数 = 游戏事实）
- **数据源**：三源合并 + `thingIDNumber` 去重
  1. 每地图 `map.mapPawns.FreeColonists`（过滤 `IsChronicleColonist`）
  2. 世界侧所有 `Find.WorldObjects.Caravans` 的 `PawnsListForReading`（含 VehicleCaravan 乘员）
  3. 兜底 `Find.WorldPawns.AllPawnsAlive`（过滤 `IsChronicleColonist`，覆盖非商队世界殖民者）
- **谓词单一实现**：`IsChronicleColonist`（含 DlcStatus.IsSubhuman 门控）提取为 **Domain 层 `ChronicleColonistScanner`**——Data 回填与 Application 活读共用同一语义，防口径分裂（P1 红线）
- **独立缓存**：不复用 livePawnCache（口径不同 + 惰性刷新问题）——独立 `[Unsaved]` 活读缓存，600 tick 窗口，跟随 UI 120-tick 刷新节奏

### 支柱 2：定期 reconcile（新角色采集兜底）
- **入口**：`ChronicleGameComponent.GameComponentTick`（新增，600 tick 节流 = 10 秒）
- **逻辑**：`ChronicleColonistScanner` 枚举当前殖民者 ↔ PawnObject 差集，缺失以 `JoinTick=-1` 回溯建档
- **确认窗**：`[Unsaved] HashSet` 连续 2 次在场才建档（防 VE 临时增援/Medieval 佣兵**永久误建档**——P2 兼容风险）＋每 pass 剪枝
- **门控**：首行 `if (!IsRecordingEnabled() || Current.Game == null) return;`（与既有写路径一致）
- **只增不删**：不做"缺席即归档"（冷藏舱殖民者在 AllPawnsAlive 内，误判死会污染时间线）；死亡归档仍由 Patch_PawnKill 负责

### 支柱 3：双轨展示（首页统计格）
- 6 格布局**不变**：
  - 1-4：Pawn/Thing/Battle/Location 档案计数（快照，不变）
  - 5：「当前殖民者（活读）」← `GetLiveColonistCount()`
  - 6：「档案记录（快照）」总数 + 副标签"活跃 X · 已归档 Y"
- 翻译 key 新增（中英双写）：`CurrentColonists` / `ArchivePawnRecords`

## 二、契约扩展（append-only，v2.4）

```text
/// 当前（活读）自由殖民者数。三源合并 + IsChronicleColonist + 600-tick 独立缓存。
int GetLiveColonistCount();

/// 档案快照口径：活跃 = PawnObject.DeathTick == -1
int GetActiveSnapshotCount();

/// 档案快照口径：已归档 = DeathTick > 0
int GetArchivedSnapshotCount();
```

**裁决**（程检规 P2-1/P2-5）：ReconcileColonists **不进 UI 读契约**（写路径由 Data 的 GameComponentTick 内部驱动，不进接口）；快照计数用契约方法 + 删除窗口本地循环（单一来源）。

## 五、关键裁决记录

1. **缓存**：独立活读缓存（兼容方对），但"一次扫描单一谓词"经 Domain 扫描器实现（系统方对）——两方案正确合并
2. **reconcile 频率**：600 tick（10 秒），与活读缓存同窗同节奏
3. **确认窗**：必要（防临时增援永久误建档）
4. **LeftTick**：本阶段 defer（确认窗已从源头防误建档）
5. **不新增 Harmony**：PawnGenerator 超热点，defer，reconcile 收口统计正确性
