# 地点地图志（Location Atlas）开发文档

**版本口径**：v4.13（预览原型，对应 `docs/ui-preview/完整档案馆UI预览.html` 当前状态）
**日期**：2026-08-10
**关联**：`docs/overview/设计文档_总览.md`、`Defs/ArchiveCategoryDefs.xml`、`Source/.../Domain/LocationObject.cs`、`Source/.../Domain/PlaceVisit.cs`
**定位**：PersonalChronicle 是**只读编年史**——地点地图志是「领地 / 地志」的档案，**不是实时地图快照**。地图身份（类型 / 归属 / 地理 / 商贸）在地图首次落成时快照，编年史由发生于此的事件流反推，销毁 / 荒废由地图销毁与定居点摧毁钩子归档，**不轮询、不实时**。

---

## 0. 设计红线（不可逾越）

1. **只读记录，不制造机制**——不得通过 Harmony 给地点加任何游戏影响（区域影响力 / 领地增益等一律不做）。
2. **数据驱动，零硬编码叙事**——展示内容必须来自真实引擎快照 + 事件流，不凭空生成「这座城曾有王」。
3. **窗口只消费快照**——排序 / null-guard / 类型判别 / 事件聚合归属 `ArchiveUiDataProvider`，不在窗口内。
4. **UI 经 Design System 两层**——新增视觉走 `UITheme` 令牌 + `UIComponents` 组件，绘制态配对恢复。
5. **档案绑定稳定 MapId，不绑定易消失实体**——`Settlement` 等世界对象会随摧毁/改名消失，地图志只存 `MapId` + defName 快照。
6. **定位为「地图志」而非「足迹」**——per-pawn `PlaceHistory`（足迹）已存在并挂在 Pawn 详情，地图志是**全局地志**视角，二者不重复。

## 1. 引擎可实现性约束（先看这块，决定能做什么）

RimWorld 1.6 引擎现实是地图志的天花板。关键事实（2026-08-10 code-explorer 探查确认）：

| 引擎事实 | 可读性 | 影响 / 结论 |
|---|---|---|
| **地图是持久化对象** | ✅ `Map.Biome`（1.6 无 `Map.def`，走 `map.Biome`，已编译通过）/ `Map.uniqueID` / `Map.Tile`（int）| 地图级档案**可靠可行** |
| **地图类型可判别** | ⚠️ `Map.Parent.def`（WorldObjectDef）+ `mapGenerator`（MapGeneratorDef）+ `ParentFaction` 三件套 | 判别「玩家定居点 / 派系城市 / 任务地点 / 临时地图」 |
| **世界 tile 禀赋可读** | ✅ `Find.WorldGrid.GetTile(tile)` → `Tile.biome/hilliness/altitude/pollution/WaterCovered/snowCovered` | 地理层字段全可快照 |
| **年均温度** | ⚠️ `GenTemperature.GetAvgAnnualTemperature(tile)`（需反射核验） | 年均非瞬时，防季节失真 |
| **地图销毁钩子** | ✅ `Map.Deinited`（事件，优于 patch）/ `MapParent.Deinited` | **零签名漂移的精确落点** |
| **定居点被摧毁** | ✅ `Settlement.Destroyed` / `WorldObject.Destroyed` / `DestroyedSettlement` | 标记「已荒废」 |
| **任务地点反推 Quest** | ⚠️ `MapParent` 侧反推 `Quest` 需反射核验 | 渐进方案：先按 WorldObjectDef/mapGenerator 快照 + 诚实标注 |
| **该地图上的事件流** | ✅ 本 mod 自有 `ChronicleEvent.Subjects` | 编年史反推来源 |

**定位修正（关键）**：本 mod 是**档案馆**，**不需要同步实时记录**——只需要「流程走完后能记录在案」。地图志完全不需要实时扫描，只在**地图落成 / 事件落点 / 地图销毁 / 定居点摧毁**这 4 个流程点归档，零轮询。

### 1.1 捕捉点四件套（零轮询）

| 捕捉点 | 语义 | 归档方式 | 精度 |
|---|---|---|---|
| **建档（地图首次落成）** | 地图身份快照 | 地图生成 / 首次进入后建档（`EstablishedTick=now`） | 精确 ✅ |
| **事件落点（持续，被动）** | 发生于此的事件反挂地图 | 所有 `Record*`/`AddEvent` 在 pawn 在地图上时，把当前 map 挂进 `ev.Subjects`（幂等） | 精确 ✅ |
| **闭合（地图销毁）** | 地图生命周期终结 | **订阅 `Map.Deinited` 事件** → `DeinitTick=now` | 精确 ✅ |
| **定居点被摧毁** | 城市荒废 | `Settlement.Destroyed` / 变 `DestroyedSettlement` → `DeinitReason=Destroyed` | 精确 ✅ |

> **钩子选型**：地图销毁**优先订阅 `Map.Deinited` 事件**而非 Harmony patch `Map.Deinit`（事件零签名漂移风险）。项目已有 `Patch_ThingDestroy.cs` 的 `ProbeTargetMethod()` + `[StaticConstructorOnStartup]` 签名探测模式可复用为兜底。

## 2. 信息架构（五层，全部可采）

现有 `LocationObject` 只有 `MapId / CellLabel / WorldTile / MapDefName` 四个字段。地图志扩展为 **5 层**：

### L1 身份层（静态档案身份）
| 字段 | 类型 | 来源 | 备注 |
|---|---|---|---|
| `MapId` | string | `Map.uniqueID` | 已有 |
| `CellLabel` | string | 显示名快照 | 已有 |
| `WorldTile` | int | `Map.Tile` | 已有 |
| `MapDefName` | string | `Map.Biome.defName` | 已有 |
| `WorldObjectDefName` | string | `Map.Parent.def.defName` | **新增** |
| `MapGeneratorDefName` | string | `MapParent.def.mapGenerator.defName` | **新增**，判别利器 |
| `MapSize` | string | `Map.Size` | **新增** |

### L2 归属层（这是谁的领土）
| 字段 | 类型 | 来源 | 备注 |
|---|---|---|---|
| `FactionDefName` | string | `Map.ParentFaction.def.defName` | **新增**；null=无主 |
| `IsPlayerHome` | bool | `Map.ParentFaction.IsPlayer` | **新增** |

### L3 地理层（世界 tile 禀赋）
| 字段 | 类型 | 来源 | 备注 |
|---|---|---|---|
| `Hilliness` | string | `Tile.hilliness` enum 快照 | **新增** |
| `Altitude` | float | `Tile.altitude` | **新增** |
| `IsCoastal` | bool | `WorldGrid.IsCoastal(tile)` | **新增** |
| `Pollution` | float | `Tile.pollution` | **新增** |
| `AvgTempC` | float | `GenTemperature.GetAvgAnnualTemperature` | **新增**，年均非瞬时 |
| `SnowCovered` | bool | `Tile.snowCovered` | **新增** |

### L4 生命周期层（何时建、何时亡）
| 字段 | 类型 | 来源 | 备注 |
|---|---|---|---|
| `EstablishedTick` | long | 首次建档 tick | **新增** |
| `DeinitTick` | long | `Map.Deinited` 事件闭合 tick（-1=仍活跃） | **新增** |
| `DeinitReason` | string | 销毁类型（Destroyed/Abandoned/None） | **新增** |

### L5 统计层（事件反推，让地点有「史」）
**不新增字段**，复用事件系统：所有发生于此的事件（战役/生产/死亡/入队）落点时把 `ObjectRef.ForLocation(mapId, biomeLabel)` 挂进 `ev.Subjects`（幂等）→ Read Model 聚合出该地图的事件时间轴 + 驻留人口 + 战役计数。

## 3. 任务地点 / 城市地点专项

### 任务地点（Quest Site）
- **判别**：`WorldObjectDef.defName` 含 Quest 语义（如 `QuestSite`）+ `mapGenerator.defName` 是任务专用 generator。
- **记录**：L1/L3 照常快照 + L5 事件反推该任务期间的战役/死亡。若 `MapParent` 能反推 `Quest` 则补 `QuestDefName`，否则标 `QuestSite` 类型即可（诚实标注）。

### 城市地点（Settlement / 派系定居点）
- **判别**：`MapParent.def` 的 `worldObjectClass=Settlement` + `ParentFaction != player`。
- **记录**：L2 归属层完整记录派系；**关键洞察**——档案绑定 `MapId`（稳定），**不绑定 settlement 实体**（会随摧毁/改名消失）。
- **被摧毁**：`DestroyedSettlement` 状态 → L4 `DeinitReason="Destroyed"` + `DeinitTick`，编年史呈现「这座城市毁于战火」。

### 玩家定居点（本家）
- `IsPlayerHome=true`，`mapGenerator=Base_Player`。这是「家」的主地图，UI 获得**特殊强调**（Home 标记 + Accent 顶条，仿 Footprint 的「家」语义）。

### 商贸（可交易城市 + 主要售卖类型，v4.13 新增）
**定位**：用户只需要「这座城能不能交易 + 主要卖什么」。这是**纯只读 Def 判别**，不需要捕捉交易事件（无 `TradeDeal` patch），地图志卡上标注即可。

**引擎数据源（100% 可读）**：
| 需求 | 数据源 | 判定 |
|---|---|---|
| 可交易 | 派系 `FactionDef.baseTraderKinds` 非空 | ✅ 有 `baseTraderKinds` = 可交易 |
| 售卖类型 | `TraderKindDef.stockGenerators` → `StockGenerator_Category.categoryDef` / `StockGenerator_Tag.tradeTag` / `StockGenerator_SingleDef.thingDef` | ✅ 归一 8 大类 |
| 许可门槛 | `TraderKindDef.permitRequiredForTrading`（如帝国 `TradeSettlement`） | ✅ null=无需 |
| 绑定派系 | `TraderKindDef.faction`（如 `Base_Empire_Standard` 绑 `faction=Empire`） | ✅ |

**售卖类型 8 大类归一**：资源 / 布料 / 食物 / 药品 / 武器 / 护甲 / 植入物 / 科技（由 `stockGenerators` 的 categoryDef/tradeTag 映射，`CategoryKey` 走 UITheme 着色）。

**Read Model 快照**（`LocationDetailSnapshot` 新增）：
```csharp
public bool CanTrade;                  // baseTraderKinds 非空
public string PermitRequiredDefName;    // permitRequiredForTrading（null=无需）
public List<TradeCategoryView> TradeKinds; // 归一售卖类别（2~4 个）
```
- `TradeCategoryView { string CategoryKey; string CategoryText; }`（CategoryKey 走 UITheme 着色 / CategoryText 已本地化）。

**落地要点**：`LocationObject` 建档时快照 `TraderKindDefName` + `PermitRequiredDefName`（随地图快照保存，防 Def 变更漂移）；Read Model 从 `TraderKindDef.stockGenerators` 归一售卖类别。**不需要** `TradeSession`/`TradeDeal`/`Tradeable` 反射核验（这些是交易历史路径，本次不做）。

## 6. 落地优先级

### P0（数据面 + 捕捉点，让 Location 从「空壳」变「有肉」）
- `LocationObject` 补 L1-L4 字段 + Scribe（老存档 Scribe 默认值零迁移，Save Schema 不变）。
- `ObjectRef.ForLocation(mapId, label)` 工厂。
- 事件落点：`ArchiveService.AddEvent`/`Record*` 在 pawn 在地图上时挂 map 边（幂等）。
- 建档：地图生成 / 首次进入后建档。
- 商贸快照：`LocationObject` 建档时快照 `TraderKindDefName` + `PermitRequiredDefName`（`FactionDef.baseTraderKinds` → `TraderKindDef`）。

### P1（生命周期闭合 + UI）
- 订阅 `Map.Deinited` → `DeinitTick`。
- `Settlement.Destroyed` / `DestroyedSettlement` → `DeinitReason`。
- `ArchiveCategoryDefs.xml`：Location `behavior` 改 `Event`。
- `ArchiveUiDataProvider.BuildOverview(Location)` / `BuildLocationDetail`：类型判别 + 地理快照 + 事件聚合 + **商贸归一**（`CanTrade` / `TradeKinds` / `PermitRequired`）。
- `UIComponents`：`LocationKpiStrip` / `TerrainTag` / `LocationLifeCell` / `LocationTimeline` / **`TradeChip`**。
- i18n 键（zh/en，`Languages/*/Keyed/Archive.xml`）：对齐预览 HTML 的 `loc*` + `trade*` 键族。

### P2（扩展点 + 深度）
- 任务地点 Quest 反推（待反射核验后补 `QuestDefName`）。
- `IPlaceProvider` 扩展为地图志 Provider，第三方可注入判别/显著性。
- colony 级迁徙史（per-pawn `PlaceHistory` 聚合「共识驻留」，单独一轮）。
- （可选）交易往来记录：patch `TradeDeal.TryExecute` 记成交历史（**需反射核验** `TradeSession`/`Tradeable`/`Trader` 签名；本次不做，用户只需城市能力）。

## 7. 明确「不做」清单（防跑偏）

| 不做 | 原因 |
|---|---|
| ❌ 轮询/实时扫描 pawn 位置做足迹 | 违背档案馆定位，引擎无「到达事件」 |
| ❌ 精确到格子的坐标记录 | 无编年史价值，引擎无钩子 |
| ❌ 绑定具体 settlement 实体引用 | 会随摧毁消失；只存 MapId + defName 快照 |
| ❌ 为地点造机制（区域影响力/领地增益） | 本 mod 只读不造机制 |
| ❌ 记录「地图上所有东西的当前状态」 | 那是快照不是编年史；只记事件反推的史 |
| ❌ 记录交易成交历史（买卖明细/金额） | 用户只要城市能力 + 售卖类型，无需 `TradeDeal` patch；交易记录列为 P2 可选 |

### 引擎 API 核验结论（2026-08-10 编译驱动，推翻早期推断）
**重要教训**：此前 code-explorer 基于引擎知识的推断（`WorldGrid.GetTile(int)` / `Tile.biome/altitude/snowCovered` / `GenTemperature.GetAvgAnnualTemperature` / `MapParent.ParentFaction` / `StockGenerator_Category.categoryDef`）**全部错误**——首次编译 17 个 CS1061 错误。改用 PowerShell 反射（`Assembly.LoadFrom` + Resolve 事件）核验真实签名：
| API | 真实签名（1.6） |
|---|---|
| 地理 | `Map.TileInfo`（Tile struct）：`PrimaryBiome`/`elevation`/`hilliness`/`pollution`/`WaterCovered`/`IsCoastal`/`MaxTemperature`/`MinTemperature` |
| 世界 tile | `Find.WorldGrid[PlanetTile]`（索引器；int 隐式转 PlanetTile）|
| 归属 | `Map.ParentFaction`（属性直接可用，无 MapParent.ParentFaction）|
| 地图身份 | `Map.Parent.MapGeneratorDef` / `Map.Parent.def` / `Map.Tile.tileId` / `map.uniqueID`（int 字段）|
| 商贸 | `Settlement.TraderKind`（TraderKindDef）/ `FactionDef.baseTraderKinds`（List）/ `TraderKindDef.stockGenerators`+`permitRequiredForTrading`(RoyalTitlePermitDef) |
| internal 字段 | `StockGenerator_Category.categoryDef` / `StockGenerator_SingleDef.thingDef` 是 **internal** → 用 Harmony `Traverse` 读取；`StockGenerator_Tag.tradeTag` 是 public 直读 |

**结论**：写 RimWorld 1.6 代码必须**编译/反射驱动核验**，不能依赖 AI 推断；DLL 首次使用的新 API 一律先 probe。
