# 生涯页 · 工作时长强度五档评价 — 设计开发文档

> 状态：v4.0 已落地（Def 驱动、可扩展 Provider、运行时采样与缓存已接入）
> 关联模块：`Archive`（生涯标签页 / 人物详情 Career 区）
> 关联预览：`career-c-intensity.html`（整合版，含强度头部 + 同工种站位 + 技能能力）

---

## 1. 背景与目标

用户需要在 PersonalChronicle 的「生涯」标签页，对**单个人物**的累计工作投入做一个**统筹评价**：
- 一眼看出这人是「核动力驴」还是「社会懒汉」，给出强度档位（趣味化、直观）。
- 评价基于**客观工时数据**，不拍脑袋；要能跨殖民地、跨天数可比。
- 与已有的「同工种站位」「技能能力」卡片矩阵并存，分工明确：
  - **强度头部** = 对单人的整体统筹评等（总工时归一化成日均）。
  - **卡片矩阵** = 对单人**全部做过的工作类型**逐类拆解（同工种排名 + 技能能力），不合并为「其它」兜底，保证统计完整。

---

## 2. 核心评价思路

用**日均工作时长 D（h/天）** 作为强度主指标，消除「在殖民地天数不同」的偏差。

```
H = 总工作时长（小时）
    = Σ WorkTimeAccumulator.TicksByWorkType[wt] / GenDate.TicksPerHour
N = 在殖民地天数
    = (结束Tick − 首次观测Tick) / GenDate.TicksPerDay      // 优先 JoinTick，旧档回退 FirstObservedTick
D = H / N                                                   // 日均工作强度
档位 = f(D)                                                 // 见 §3 阶梯阈值
```

> 之所以用「日均」而非「总时长」：刚来 3 天的人 vs 老臣不能直接比总时长；日均是强度（intensity），总时长是总量（volume），评价强度必须用前者。

---

## 3. 强度区间机制（五档，高→低）

| 档 | 名称 | 日均 D | 月工时(30d) | 语义 |
|----|------|--------|-------------|------|
| T0 | 核动力驴 | **≥ 12 h/天** | ≥ 360h | 觉醒即干、终日不休，接近生理极限 |
| T1 | 超级牛马 | 9 – 12 h/天 | 270 – 360h | 远超常人，殖民地顶梁柱 |
| T2 | 常规牛马 | 6 – 9 h/天 | 180 – 270h | 标准勤勉，可靠主力 |
| T3 | 劣质牛马 | 3 – 6 h/天 | 90 – 180h | 干得不情愿，低于均值 |
| T4 | 社会懒汉 | < 3 h/天 | < 90h | 基本在摸鱼/养病/闲晃 |

**映射规则（纯静态函数，无数据依赖）：**

```csharp
// 建议落点：Domain 层新增 WorkIntensityTier 枚举 + 静态评估器
public enum WorkIntensityTier { Undefined = 0, ReactorMule = 1, SuperBeast = 2,
                                 RegularBeast = 3, PoorBeast = 4, LazySlack = 5 }

public static WorkIntensityTier Evaluate(double dailyHours, int daysInColony)
{
    if (daysInColony < SAMPLE_MIN_DAYS) return WorkIntensityTier.Undefined; // 样本不足
    if (dailyHours >= 12) return WorkIntensityTier.ReactorMule;
    if (dailyHours >= 9)  return WorkIntensityTier.SuperBeast;
    if (dailyHours >= 6)  return WorkIntensityTier.RegularBeast;
    if (dailyHours >= 3)  return WorkIntensityTier.PoorBeast;
    return WorkIntensityTier.LazySlack;
}
```

## 4. 防坑设计（必做）

1. **样本护栏（预估 vs 实际）**：`N < 5 天` 仍按当前工时折算给出档位，但标记为**预估（Estimated）**，UI 徽章显示「预估 · <档位>」，并在阶梯色带附「样本<5天·按当前情况预估」提示；`N >= 5 天` 才标记为**实际（Actual）**，徽章显示「实际 · <档位>」。这样既能避免某人来 1 天干 20h 被误当确定结论，又不会在样本不足时完全「不评等」而丢失信息。无有效工时（TotalTicks<=0）时仍显示「采样中」。
2. **相对维度（可选叠加，非核心）**：在绝对评等之外，可叠加殖民地均值 `D_avg`，`R = D / D_avg`；`R ≥ 1.5` 标「超负荷」、`< 0.5` 标「显著摸鱼」。**核心评等仍按绝对 D**，保证跨殖民地可比、不随人数漂移（你举例的「10 人殖民地有人月 360h+」正是 D=12 → T0，与绝对线一致）。

## 5. 数据来源与落地可行性

| 所需输入 | 来源 | 状态 |
|----------|------|------|
| 总工作时长 H | `PawnObject.WorkTime.TicksByWorkType[defName]` 求和 / `GenDate.TicksPerHour` | 已接入 |
| 在殖民地天数 N | `JoinTick`，旧档回退 `FirstObservedTick` | 已接入 |
| 日均 D 与档位映射 | `WorkIntensityEvaluator` + Def 阈值 | 已接入 |
| 同工种排名 | 遍历当前人物的 `PawnObject.WorkTime` 同工种求和排序 | 已接入 600 tick 缓存 |
| 全部工作类型枚举 | `WorkTimeAccumulator.TicksByWorkType` 的所有 key（即各 `WorkTypeDef` defName） | 真实已有，直接遍历，无兜底合并；游戏内中文标签由 `WorkTypeDef.LabelCap` 自动取，无需硬编码 |
| 占殖民地总工时比 | 同上聚合的 colony 总和 | 已接入缓存派生 |
| 技能能力（等级+激情） | `pawn.skills.GetSkill(workType.relevantSkills[0]).Level` + `.passion`（活读 `SkillRecord`） | 真实已有（技能页已用） |
| 最近活跃 | `(TicksGame − WorkTimeStatView.LastTick) / 60000` | 真实已有 |

**工作类型清单来源（已核对真实游戏数据）**：`E:\SteamLibrary\steamapps\common\RimWorld\Data\Core\Defs\WorkTypeDefs\WorkTypes.xml` 中 Core 共定义 17 个 `WorkTypeDef`，其中玩家可指派的主工种含 种植(Growing)/建造(Construction)/研究(Research)/治疗(Doctor)/采矿(Mining)/搬运(Hauling)/清洁(Cleaning)/烹饪(Cooking)/割草(PlantCutting)/狩猎(Hunting)/驯兽(Handling)/裁缝(Tailoring)/锻造(Smithing)/制造(Crafting)/艺术(Art)/看守(Warden)/消防(Firefighter)；另有被动类 养病(Patient)/卧床(PatientBedRest)/杂务(BasicWorker) 不计作主动工作。`WorkTimeAccumulator` 直接按这些 defName 累计，预览里的工种名与游戏内 `LabelCap` 一致。

**结论：评价使用已有工时账本，动态数据由 GameComponent 采样维护；外部 mod 可通过 `IWorkTimeCaptureService` 补充自定义工作来源。** Colony 级聚合查询与缓存已经落地。

## 6. 落地架构（建议）

### 6.1 新增（Domain 层，单一口径，守 P1 红线）
- `WorkIntensityDef.cs`：`WorkIntensityPolicyDef` / `WorkIntensityTierDef`，阈值、颜色和翻译键均由 XML 注入。
- `WorkIntensity.cs`：纯 C# 输入、结果与 `WorkIntensityEvaluator`，不依赖 RimWorld/UI。
- 颜色/名称只通过 Tier Def 的元数据解析，UI 不复制评价阈值。

### 6.2 新增（Application 层）
- `IWorkIntensityService` / `ArchiveService.GetColonyWorkAggregate()`：聚合当前人物各工种工时 → 返回
  - 每工种 colony 总和、最大值、参与人数
  - colony 总工时、平均日均（用于相对维度，可选）
  - 加 600-tick 缓存，避免每帧重算；同时使用 `DataRevision` 在采样写入后失效。
- `IWorkTimeCaptureService.RecordSample(WorkTimeSample)`：外部工作系统使用稳定 Pawn ID + WorkTypeDefName 写入统一账本。
- `IWorkIntensityProviderRegistry`：外部评价器按 `Priority` 注册；异常只记录一次并自动回退内置评价。

### 6.3 修改（UI 层）
- `ArchiveMainTabWindow.DrawCareerTab`：
  - 顶部新增**强度统筹头部**：大号档位徽章（核动力驴…）+ 总时长/日均/周均三联。
  - 阶梯条：5 段色带，当前档 `cur` 高亮（原版用 `Widgets.DrawBoxSolid` 画分段矩形）。
  - 卡片矩阵**枚举该人物做过的全部真实工作类型**：直接遍历 `WorkTimeAccumulator.TicksByWorkType` 的 key（各 `WorkTypeDef` defName，游戏内中文标签由 `WorkTypeDef.LabelCap` 自动取，无需硬编码），不再用「其它」兜底；采用两列高密度布局。
- 概览统计格（首页第 5 格）可复用方案 A 位置显示档位徽章。

### 6.4 UI 映射（原版 Widgets，无外部依赖）
| HTML 预览元素 | 原版实现 |
|---------------|----------|
| 档位徽章 | `ArchiveUiStyle.DrawBadge` / `DrawCard`（直角 + 左侧 4px 强调条） |
| 阶梯色带 | 循环 `Widgets.DrawBoxSolid(rect, color)` |
| 卡片 | `ArchiveUiStyle.DrawCard` + `Widgets.FillableBar`（已在用） |
| 网格排布 | 循环算 Rect（参考概览 4 列网格算法） |
| 文字 | `Widgets.Label` + `Text.Font` |

> 注意：预览里的圆角是浏览器 CSS 效果，游戏内为直角——更贴合环世界美术，非 bug。

## 8. v4.0 已落地配置

- 默认策略 Def：`PersonalChronicleWorkIntensityPolicy`。
- 默认样本护栏：5 天；相对负荷标签阈值：`R >= 1.5` / `R <= 0.5`。
- 默认档位 Def：`T0` 至 `T4`，按 `minimumDailyHours` 从高到低匹配。
- 默认只展示有正工时的工作类型；调用 `GetWorkTypeBreakdown(stableId, true)` 可要求包含零工时类型。
- 生涯页生产区先显示累计产出数量、累计市场价值和物品类型数，再显示分类型明细。
- UI 不依赖外部图片、材质或圆角资源，使用原版 `Widgets` 与现有 `ArchiveUiStyle` 渲染。

档位、阈值、颜色和翻译键都可通过 XML Patch 调整；不应在 UI 代码中复制阈值。
