# 击杀记录「阵营图鉴卡片」——给想改这块的人看

模块：PersonalChronicle · 战斗履历子系统
相关文档：`docs/combat/设计文档_战斗履历.md`、`docs/combat/preview_combat.html`
状态：已经写完（v4.3），C# 代码都落地了，能编译过。

---

## 0. 先说这功能干啥的

以前战斗履历里，击杀是一行一行列出来的。现在改了：按**阵营**把击杀攒成一张张**卡片**。

- 一张卡片 = 一个阵营，比如「索恩虫巢」「野生动物 / 无派系」「我方」。
- 卡片上写着：杀了多少、袭击几次、打了几场、我方死几个，还有一条「构成条」显示都杀了些啥种类。
- 点一下卡片，就在原地展开这条阵营的明细（日期、目标、用的啥武器），不跳页面。
- 屏幕宽就排 2 列，窄就 1 列。

旧的「战斗记录」逐条列表已经删了，信息都并进卡片里了。

## 1. 要改的话，动哪几个文件

| 文件 | 管啥 | 你一般因为啥碰它 |
| --- | --- | --- |
| `Application/ArchiveService.cs` | 击杀发生时，把受害者阵营/种类存进事件 | 想多记点信息（比如受害者等级、武器材质） |
| `Domain/ChronicleEventParams.cs` | 定义那些存数据的键名（字符串常量） | 加了新字段，就在这补个常量 |
| `Archive/ArchiveUiStyle.cs` | 阵营颜色、卡片底色 | 想换配色 |
| `Archive/ArchiveMainTabWindow.cs` | 把击杀聚成卡片、画出来 | 改布局、加减指标、改展开逻辑 |

数据怎么流动的，顺着这条线看就行：

击杀事件（里面带着阵营信息）→ `cachedKillLines`（击杀行列表）→ `BuildFactionCodex`（聚合成卡片数据）→ `DrawFactionCodex`（画到屏幕上）

## 2. 数据哪来的：杀人那一下顺手记下来

有个事得先明白：**外面那些敌人、动物、任务怪，被杀的时候不会建档案**（游戏里没有对应的 `PawnObject`）。所以阵营信息只能在「它死的那一刻」从还活着的 `Pawn` 身上扒下来，存进事件里。之后界面永远读存好的数据，不依赖当时那个 Pawn 还在不在。

代码在 `ArchiveService.OnKillRecorded`（大概 1696–1713 行），紧跟在 `VictimStableId` 后面：

```csharp
// 记下受害者阵营/种类（外面的怪不会建档，这是唯一能采到的时机）
ev.Params[VictimFactionDefName] = victim.Faction?.def?.defName;   // 没有派系就是 null
ev.Params[VictimFactionLabel]   = victim.Faction?.Name;            // 显示用的人话名字
ev.Params[VictimKindDefName]    = victim.kindDef?.defName;         // 构成条靠这个分
// 分个类：机械 > 动物 > 人形
string category = VictimCategoryHumanlike;
if (victim.RaceProps?.IsMechanoid == true) category = VictimCategoryMechanoid;
else if (victim.RaceProps?.Animal == true) category = VictimCategoryAnimal;
ev.Params[VictimCategory] = category;
```

存的都是普通字符串，不改 `Params` 的结构，所以**老存档不用处理**，直接能读。老存档里没有这些键也没事，界面读不到就把它丢进「未知 / 环境」那张卡，不会崩。

想加个新字段，照这三步走：
1. 在 `ChronicleEventParams.cs` 加个字符串常量（比如 `VictimWeaponMat = "victimWeaponMat"`）。
2. 在 `OnKillRecorded` 里 `ev.Params[...] = ...` 写进去。
3. 在 `BuildFactionCodex` 里取出来用。

## 3. 阵营怎么分桶

`BuildFactionCodex` 对每一行击杀，按下面顺序判断它归哪个阵营。先命中谁就用谁：

| 顺序 | 啥情况 | 阵营标记 | 卡片颜色 |
| --- | --- | --- | --- |
| 1 | 凶手查不出来 | `__unknown__` | 灰 |
| 2 | 死的是我方/俘虏（有档案） | `__player__` | 红 |
| 3 | 死者有派系 | 派系名 | 机械族→蓝，其他敌对→金，中立/友方按关系算 |
| 4 | 没派系但它是动物 | `__wild__` | 绿 |
| 5 | 其他没派系的（任务怪之类） | `__factionless__` | 灰 |

分组全靠判断类型（`faction.HostileTo(Faction.OfPlayer)`、`RaceProps.IsMechanoid`/`Animal`），**没有写死「派系名 == 某某」这种比法**。这样以后出新阵营也能自动归对类，不用专门配。

卡片右上角那个关系小标（敌对/中立/友方/没搞清楚）由 `relationKey` 决定：`hostile` / `neutral` / `ally` / 其他。

## 4. 聚合逻辑：BuildFactionCodex

方法签名：`BuildFactionCodex(IArchiveService service)`。它读 `cachedKillLines`，算出 `cachedFactionCodex`（就是卡片数据的列表）。

对每一行击杀干这些事：

1. 从 `line.TargetEvent.Params` 里拿阵营标记（按第 3 节的顺序）。
2. 找到或新建这个阵营的 `FactionCodexView`，然后 `KillCount++`、把这一行加进 `MemberLines`。
3. 如果死的是我方（`victimIsArchive`），`OurLossCount++`（只有「我方」那张卡这个数才有意义）。
4. 扫一遍 `ev.Subjects` 里标记成 `Battle` 的，把它们的 `StableId` 丢进这个阵营的 `HashSet`（**自动去重**，所以同一场打了好几个人也只算一场）。

方法最后还会做几件事：
- 把每个阵营 `HashSet` 里不重复的数量，写回 `BattleCount` 和 `RaidCount`。
  - `BattleCount` 就是涉及这个阵营的不重复战役数。
  - `RaidCount` 现在跟 `BattleCount` 算的是同一回事，以后可以改成「袭击类事件的去重数」。
- 按 `VictimKindDefName` 统计 `Composition`（就是构成条，排个序）。
- 排序：按 `KillCount` 从多到少排；「我方」那张卡永远放最后。

> 提醒一句：`FactionCodexView` 以前是 `struct`（值类型），从字典里取出来改了 `KillCount++`，其实改的是副本，字典里还是 0，所以早先卡片数字全显示 0。现在改成 `class` 了，**以后别手滑改回 struct**，不然数字又变 0。

## 5. 卡片长啥样

入口：`DrawFactionCodex(rect, y, service)`，在 `DrawPawnCombat` / `DrawWeaponCombat` 里调用。

里面大概这么走：
- 没数据 → 显示 `NoKillRecords` 占位文字。
- 列数：`rect.width >= 720f` 就 2 列，否则 1 列。
- 一张张调 `DrawFactionCodexCard` 画出来；整张卡片盖了一层隐形按钮，点一下就切换展开（`expandedFactions` 这个 `HashSet` 记着哪些阵营展开了）。
- 一行排满 `cols` 张卡就换行，行高取这一行最高的卡。

`DrawFactionCodexCard` 从上到下画这些：
1. **卡片头**：一个色点（`FactionAccent(kind)`）+ 阵营名 + 小字类型（人形/机械/动物）+ 右上角关系小标。
2. **四个数字格**：`DrawFactionStat(rect, 数字, 标签, 颜色)`
   - 击杀数（`KillCount`，红）
   - 袭击次数（`RaidCount`，金）
   - 交战战役（`BattleCount`，蓝）
   - 我方阵亡：只有「我方」卡显示真的 `OurLossCount`；**敌方卡显示「—」**。为啥？因为击杀事件里死的是敌方，根本反推不出我方死了多少，硬写 0 反而误导人。
3. **构成条**：`Composition` 按比例画成一段段的色条；没数据就整条用 accent 色铺满。
4. **展开后的明细**：一个**固定 5 行高的内嵌滚动区**（`FactionCodexPreviewRows`=5），所有击杀明细都在里面滚动着看，条数再多也不会把卡片撑高。

---

## 6. 高度要一起改，容易忘

卡片高度是变的，滚动条长度靠 `ComputeDetailPanelHeight` 算，算不准滚动就错位。

两处得一块改：
- `FactionCodexCardHeight(card, expanded)`：算单张卡片多高。
  - 收起时基础高度 = `26 + 8 + 52 + 8 + 6 + 8`（卡头+缝+数字格+缝+构成条+缝）。
  - 展开时再加 `8 + FactionCodexPreviewRows*(TimelineRowHeight+2)`（固定 5 行视口，不随条数涨）。
- `ComputeDetailPanelHeight` 里 `CombatLog` 那段：每张卡按 `FactionCodexCardHeight(...) + 12`（卡间距）往上加。

**只要动了卡片里的布局或者行数，这俩地方必须跟着调。**

## 7. 颜色和字体

- 阵营颜色都在 `ArchiveUiStyle.cs`：`FactionEnemy`/`FactionMechanoid`/`FactionAnimal`/`FactionUnknown`/`FactionPlayer`，用 `FactionAccent(FactionCodexKind)` 取。**想换色只改这里**，别在窗口代码里写 `new Color`。
- 卡片底用 `ArchiveUiStyle.DrawCard(rect, accent)`。
- 凡是动了 `Text.Font` / `Text.Anchor` / `GUI.color`，用完都要还原（看 `DrawFactionCodexCard` 结尾 `GUI.color = previous` 那种写法）。

## 8. 文字要走翻译

加的这些翻译键，中文英文各一份，在 `Languages/*/Keyed/Archive.xml`：

- `FactionCodexTitle`（区块标题）
- `StatKills` / `StatRaids` / `StatBattles` / `StatOurLosses`（四个数字格的标签）
- `FactionKindEnemy` / `FactionKindMechanoid` / `FactionKindAnimal` / `FactionKindUnknown`（类型小字）
- `FactionRelHostile` / `FactionRelNeutral` / `FactionRelAlly` / `FactionRelUnresolved`（关系小标）
- `FactionWild` / `FactionFactionless`（那两个桶的显示名）
- `NoKillRecords`（没数据时占位，本来就有）

**新加的文字一律走翻译键，别直接把中文/英文写死在代码里。**

## 9. 想改点啥，去哪改

| 你想干啥 | 动哪里 |
| --- | --- |
| 加个新数字格（比如「主要击杀者」） | `DrawFactionCodexCard` 的四格区 + `FactionCodexView` 加字段 + `BuildFactionCodex` 里填值 + 翻译键 |
| 换阵营配色 | `ArchiveUiStyle.FactionXxx` 常量 |
| 卡片太挤/太高 | `FactionCodexCardHeight` 基础公式 + `ComputeDetailPanelHeight` 同步 |
| 改构成条怎么分 | `BuildFactionCodex` 里 `Composition` 统计 + `VictimKindDefName` 取值 |
| 让敌方卡也显示「我方阵亡」 | 得在 `OnPawnDied` 系列里额外记下「谁杀的/属于哪个阵营」，再在 `BuildFactionCodex` 反查（现在做不到，所以显示「—」） |
| 改宽屏几列 | `DrawFactionCodex` 里的 `720f` |
| 展开明细区想露几行 | `FactionCodexPreviewRows` 常量（滚动视口行数，默认 5） |
| 老存档也想有阵营数据 | 办不到（受害者 Pawn 早没了，没法补），文案上写句「历史记录」糊弄一下就行 |
