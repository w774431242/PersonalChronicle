相关文档：`docs/combat/方案_击杀图鉴卡片.md`（击杀图鉴卡片那块专门讲）、`docs/combat/preview_combat.html`（UI 预览）
状态：核心功能都落地了，C# 代码能编译过。这份文档把整块战斗履历讲一遍，不只是图鉴卡片。

## 0. 先说这功能干啥的

战斗履历回答三件事：**打了多少场、杀了多少人、怎么死的**。

- 主页 CombatLog 主视图：顶部一排 KPI（战役数 / 击杀数），下面按阵营把击杀攒成卡片（就是击杀图鉴那套）。
- 某个殖民者 / 武器的详情页 Combat 子页：抬头是死亡档案（死了的话），下面是这人/这把武器的击杀卡片。

以前击杀是一行行列出来的，现在改成按**阵营**聚成卡片了（具体见 `方案_击杀图鉴卡片.md`）。这份文档把整条链路从「捕获」说到「画出来」。

## 1. 整条链路长啥样

代码分四层，单向依赖，UI 在最上面，Capture 在旁边往里写：

```
UI (ArchiveMainTabWindow)           ← 只画，不算
  └─> Application (ArchiveService)   ← 统计核心 ScanCombatData
        └─> Domain (ChronicleEvent / PawnObject)
              └─ Data (存档序列化)
Capture (Harmony 补丁)  ──写入──> Application
```

顺着这条线看数据怎么流：

击杀/战役事件（Harmony 补丁写进 `ArchiveService`）→ `events` 列表 → `ScanCombatData` 过滤计数、聚类 → 缓存在 `cachedKillLines` / `cachedBattleLines` / `cachedFactionCodex` → 窗口 `DrawXxx` 拿出来画。

各层干啥：

- **UI 层** `ArchiveMainTabWindow`：主页 `MainView.CombatLog` 画 KPI 头部 + 阵营卡片；`DrawPawnCombat` / `DrawWeaponCombat` 画详情页。它只消费缓存，**不算数**。
- **Application 层** `ArchiveService`：
  - `ScanCombatData`（约 1633 行）：从 `events` 按 category 过滤，做计数 + 战役聚类 + 跨战役去重。
  - `OnCombatLogKpis`（约 1744 行）：供主页头部拿 `battles` / `kills`。
  - `OnBattleStarted`（约 1731 行）：把相邻的作战事件合并成一场战役。
- **Domain 层**：`ChronicleEvent`（category/kind/tick/params）、`PawnObject`（死亡档案字段）。
- **Capture 层**：
  - `Patch_IncidentWorker`（约 103 行）`OnBattleStarted` 写作战事件。
  - `Patch_Pawn_` 系列写击杀与死亡。
  - `Patch_PawnTakeDamage`（v4.0 加的）`[HarmonyPrefix] Pawn.TakeDamage` 维护 `DamageLedger`，用来算「谁真杀了这个人」和协助（见第 2 节）。

## 2. 击杀归属与「协助」：谁算杀了人

RimWorld 1.6 里 `Pawn.Kill` 的 `DamageInfo.Instigator` 经常是 null（近战转发、环境致死），或者指向 `Projectile` 而不是 Pawn；补刀的人未必是造成伤害最高的。为了还原「谁真正杀的」，搞了个伤害账本：

| 环节 | 实现 | 说明 |
| --- | --- | --- |
| 伤害采集 | `Patch_PawnTakeDamage`（`[HarmonyPrefix] Pawn.TakeDamage`） | 按受害者把各 Pawn 的伤害累加到 `DamageLedger`；环境这种非 Pawn 伤害源忽略 |
| 取主伤害者 | `Patch_PawnTakeDamage.ConsumeTopDamagers(victim, max=3)` | 击杀时按伤害从高到低取前 3，并清掉这个受害者的账本（防泄漏；活人的条目在 `PruneStale` 里惰性清） |
| 归属 | `ArchiveService.OnKillRecorded(instigator, victim, weapon, assistLookup)` | 伤害最高者 **A 拿击杀**；补刀者 **B（instigator）若不 = A → 记成 `assist` 协助** |
| 凶手查不出 | `killer==null` | 归 `UnknownKillerId` 桶，`killer` 文案用翻译键 `UI.UnknownKiller`，**不会再因为 `TryClassifyCurrent(null)` 报 NRE 把整类丢掉** |

归属只在「受害者是敌方 / 外部 humanlike」时算（`killerIsChronicle || IsExternalHumanlike(victim)`）。下面都是殖民地视角：

| 场景 | killerId | assist | 说明 |
| --- | --- | --- | --- |
| A 削 80% 血、B 补刀（都是殖民者） | A | B | A 记击杀、B 记协助 |
| 只有 B 补刀，没账本 | B | — | 无协助 |
| 凶手完全查不出（环境/敌方互杀） | `UnknownKillerId` | — | 若主伤害者是殖民者则升格成击杀者 |
| 敌方杀我方殖民者 | `UnknownKillerId`（或解析到的敌方 id） | — | 走 `OnPawnDied`，不算击杀归属 |

**事件详情**里有个「协助」分支（翻译键 `UI.Assist` / `UI.AssistWithName`），读 `params[ChronicleEventParams.Assist]`。

**提醒一句**：v4.3 起，击杀明细那一行（`CombatLineView.SubText`）**不再显示击杀者姓名，也不再内联显示协助者姓名，只显示用的什么武器**。协助信息只在事件详情分支里还能读到。这个改动是为了「个人档案里战斗履历只关心用什么武器杀的」，别手滑又加回击杀者名。

**静态状态治理**：`DamageLedger` 是个静态可变字典（按规范算反模式）。已经用「击杀即消费 + `PruneStale` 容量门槛 64 惰性清脏」把它压成瞬态，避免长局泄漏；捕获前缀全程 `try/catch`，不挡原伤害管线。

## 3. 数据存在哪

### 3.1 战斗相关的 ChronicleEvent

```csharp
// Domain/ChronicleEvent.cs（最小骨架）
class ChronicleEvent {
    string category;   // "Battle" | "Kill" | ...
    string kind;       // Battle: "Raid"  | Kill: "Combat"
    long   tick;       // 游戏内 tick（60000 tick = 1 天）
    Dictionary<string,string> params;
}
```

- `Battle/Raid` → `params`：通常空或作战上下文。
- `Kill/Combat`（即 `ChronicleEventType.Death` + `combatRole=CombatRoleKill`）→ 实际写入的字段：
  - `killer`（击杀者 LabelShort；查不出就用翻译键 `UI.UnknownKiller`）
  - `victim`（受害者 LabelShort）
  - `victimStableId`（受害者 `GetUniqueLoadID()`，去重键）
  - `combatRole`（`CombatRoleKill`）
  - `assist`（可选；协助者 LabelShort，仅当补刀者 ≠ 主伤害者时才有）
  - `weapon` / `weaponLabel`（来自 `NoteWeaponHolder` 的边索引）
  - 阵营相关四个（见 `方案_击杀图鉴卡片.md` 第 2 节）：`victimFactionDef` / `victimFactionLabel` / `victimKindDef` / `victimCategory`

### 3.2 死亡档案（PawnObject）

```csharp
// Domain/PawnObject.cs
bool   IsArchived;
long   DeathTick;
string DeathCauseKey;   // → CauseLabel 翻译
string DeathKillerLabel;
```

只有 `IsArchived && 已死亡` 时，才在 `DrawPawnCombat` 抬头画出来（死亡日期 / 原因 / 击杀者）。注意这是「死亡档案」，跟战斗履历击杀明细不是一回事——击杀明细只显示武器（见第 2 节），死亡档案这里仍显示「被谁杀」。

### 3.3 文案走 Defs，不写死

- `Defs/Chronicle_Events.xml` 里 `Battle`/`Kill` 的 `ChronicleEventDef` 提供 `title`/`params`/`desc` 模板（K#/B# 编号），UI 用 `Translate` 渲染。
- `Defs/ArchiveCategoryDefs.xml`：`Battle` 的 `ArchiveCategoryDef` 定义泳道标签。

## 4. 统计核心算法（ScanCombatData）

### 4.1 计数

```csharp
var battles = events.Where(e => e.category == "Battle" && e.kind == "Raid");
var kills   = events.Where(e => e.category == "Kill");
battleCount = battles.Count();
killCount   = kills.Count();
```

### 4.2 战役聚类

按 `kind` 分组 → 按 `tick` 升序 → 相邻事件间隔 **> `BATTLE_GAP_THRESHOLD = 30000` tick** 就开新战役。

> 30000 tick = 0.5 天；同一拨作战要是停了半天以上，就算新的一场。

每场战役输出一行：`{ kind, startTick, count }`，界面拿「战役起点」来显示。

### 4.3 击杀跨战役去重

按 **天（`<tick/60000>`）** + **目标标识（`targetId`/`targetLabel`）** 去重。同一天、同一目标、跨多场战役的多次击杀，只算 1 次。

```csharp
// 伪码
var dayKey = e => $"{e.tick/60000}:{e.params.targetId ?? e.params.targetLabel}";
seen.Add(dayKey(e));  // 已经有了就不计
```

### 4.4 边界情况

- 空存档 → 全 0，显示「无记录」占位（`NoKillRecords` / `NoBattleRecords`）。
- 只有击杀没战役 → 战役 KPI=0，战役区空。
- 只有战役没击杀 → 击杀 KPI=0。

## 8. 已知坑和约束

- 战役只记「起点」，不展开每场细节（想做时间轴回放得新加 `BattlePhase` 事件类）。
- 击杀去重靠 `victimStableId`（`GetUniqueLoadID()`）；要是捕不到稳定 id（比如匿名野生动物），去重退化成按 label，可能漏去重。
- 死亡档案靠 `PawnObject.IsArchived`，只有归档殖民者看得见；袭击者没档案。
- **协助内联展示已移除**：v4.0 用 `CombatLineAssistSuffix(ev)` 在击杀行 `SubText` 后面加「 · 协助：X」；v4.3 改成击杀明细只显示武器，`CombatLineAssistSuffix` 方法已删除，协助只在事件详情分支读得到。
- **跨 bucket 同死亡去重**：`OnKillRecorded` 写之前先调 `HasRecordedDeathForVictim(component, victimId)`，扫一遍全局 `component.Events` 看这个 `victimStableId` 是不是已经在哪个桶里有 `Death` 事件了；有就直接 return，避免 `instigator==null` 同时命中 `OnPawnDied` 和 `OnKillRecorded` 写出双份 Death。
- **伤害账本是热路径副作用**：`Patch_PawnTakeDamage` 在**每次伤害结算**都跑（所有 Pawn）。逻辑已经极简（cast + 字典累加 + 死亡早退 + `PruneStale` 容量 64 惰性清脏），全程 `try/catch` 不挡原管线；但毕竟是静态可变状态，按规范算「能接受但要记一笔」的反模式。
- **v4.0 修过的历史 bug**：`OnKillRecorded` 早先对 `killer==null` 调 `TryClassifyCurrent(null)` 会 NRE 被捕获，导致所有「凶手查不出」的击杀整类静默丢掉；现在改归 UnknownKiller 桶，战斗履历始终有数据。

## 9. 以后还能做啥（规划中，仅渲染层）

**③ 战役分组卡片**（没做）：把裸时间线行升级成「战役分组卡片」，每组 header 显示战役名/跨度/场数/击杀数，可折叠；组内逐条带胜负 tag。

- `Text.Font` / `GUI.color` / `Text.Anchor` 用完必须配对还原（前车之鉴：`DrawBadge` 溢出的教训）。

**落地顺序建议**：① 阵营卡片（已完成）→ ② KPI 玻璃条 → ③ 战役分组卡片。
