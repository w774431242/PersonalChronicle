## 1. Change Intent

### 1.1 目标用户行为

开发者（人/AI）在**不启动 RimWorld** 的情况下，快速模拟职业系统的真实数据管线运行：

```text
配置 pawn 行为（配方/次数/品质分布/间隔 tick）
  → 模拟"游戏运行"按管线推进
  → 观察：XP/等级成长曲线、评级里程碑、效果加成曲线、
         资格达成 tick 与缺口原因、职称授予序列、方向对比
  → 输出 CSV（Excel 分析）+ HTML 报告（图表）+ 控制台摘要
```

典型用途：数值调参前的批量对比（如品质策略对成长速度的影响）、验证差异化特化点数据（4 方向加成对比）、资格门槛可达性分析（P1-5 场景可视化）。

### 1.2 非目标

- ❌ 不模拟完整 RimWorld 引擎（工作流/派系/战斗/存档）——只模拟职业系统数据管线
- ❌ 不做 GUI 编辑器——CLI + 预置场景 + HTML 报告
- ❌ 不替代 NUnit 单测——两者互补：单测验证函数正确性，模拟器验证**管线时序行为**与**数据调参**
- ❌ 不写入游戏存档 / 不加载游戏程序集（离线，零引擎依赖）

### 1.3 涉及层级与数据面

| 项 | 说明 |
|---|---|
| 涉及层级 | 纯工具（Tools/），不进入 Source/ 发布体；逻辑为 C# Domain 公式的 JS 转写 |
| Def | 读取 `Defs/ProfessionalSkills.xml` / `QualificationDefs.xml` / `MedalDefs.xml`（只读，不修改） |
| Runtime / Save / UI | 无（离线） |
| Translation | 无（工具文案硬编码中文/英文均可，非游戏文本） |
| 兼容面 | 无第三方 Mod / DLC 依赖；Node.js ≥ 18 即可运行 |

### 1.4 验收标准

| # | 验收项 | 通过标准 |
|---|---|---|
| 1 | 管线完整性 | 一次模拟输出覆盖：事实 → XP → 能力 → 等级 → 评级 → 效果加成 → 资格 → 授予 全链 |
| 2 | 公式一致性 | 核心公式与 C# 实现一致（XP/Level/Rating/ResolveSpeedFactor/CompositeScore），转写表见 §3.3，用已知输入校验输出 |
| 3 | 场景可跑 | 预置 ≥4 场景一键运行（`node run.js`），含 4 方向对比与资格缺口分析 |
| 4 | 输出可用 | **交互式 HTML 报告**（场景切换 / pawn 多选对比 / 指标切换 / 悬停 tooltip / 能力雷达 / 职称时间线，零依赖 file:// 可开）+ CSV 逐 tick 快照 + 控制台摘要 |
| 5 | 零依赖 | 无 npm 依赖，`node run.js` 直接运行 |

## 2. 架构：按架构管线组织

模拟器**按游戏数据管线的真实顺序**分层实现，每层对应游戏代码与规则：

```text
┌─────────────────────────────────────────────────────────────┐
│ ① 行为模拟层   simulator: 按配置生成制造行为序列（配方/品质/数量/tick） │ ← Patch_GenRecipe.PostProcessProduct（Capture）
│ ② 事实层       生成 CareerEvent(ItemProduced)（含 RecipeDefName/Quantity/Quality）│ ← ArchiveService.RecordCareerProduced（Application）
│ ③ 状态层       XP 计算 → 能力拆分 → 等级/熟练度                       │ ← ApplyProfessionalProgress / ProfessionalXpEvaluator
│ ④ 评级层       Level → 评级档位（软上限封顶）                        │ ← ProfessionalRatingEvaluator
│ ⑤ 效果层       速度系数 / 品质偏置（含技能级覆盖 effectOverrides）     │ ← ProfessionalEffectResolver
│ ⑥ 评价层       资格判定（门槛链 + 综合评分）、成就聚合、考试评分        │ ← QualificationEvaluator / ExamScoring / AchievementEvaluator
│ ⑦ 授予层       Qualified → 职称授予（autoGrant）→ 回写 TitleGranted   │ ← ChronicleGameComponent.RunQualification（Data）
│ ⑧ 输出层       CSV 快照 + HTML 报告 + 控制台摘要                     │ ← 工具自有
└─────────────────────────────────────────────────────────────┘
```

**设计铁律**（与游戏一致）：
- 事实/评价分离：事实层（②）append-only，评价（③~⑦）只派生不污染事实
- 数据驱动：全部 Def 数据从 XML 读取（不硬编码门槛/数值）
- 能力 XP 只增不减；Level 由 XP 曲线派生（可随时重算）

### 2.1 文件结构（Tools/DataSimulator/）

```text
Tools/DataSimulator/
├── run.js              # CLI 入口：node run.js [--scenario <名>] [--out <目录>] [--open] [--list] [--selftest]
├── README.md           # 用法说明
├── .gitignore          # out/ 输出忽略
├── src/
│   ├── xml.js          # 迷你 XML 解析器（项目 Defs 规整格式专用）
│   ├── defs-loader.js  # 加载 3 个 Defs XML → 结构化对象（含内建 fallback）
│   ├── sim-core.js     # 数据管线核心（公式与 C# 对齐，见 §3.3）
│   ├── scenarios.js    # 预置场景定义
│   ├── report.js       # CSV / 交互式 HTML（数据嵌入）/ 控制台摘要
│   └── renderer.js     # 浏览器端渲染器（零依赖：场景 tab / pawn 多选 / 指标切换 / tooltip / 雷达 / 时间线）
└── out/                # 运行输出（gitignore）
```

### 2.2 数据流

```text
run.js --scenario X
  → defs-loader（解析 XML）
  → scenarios[X]（行为配置：pawn、配方、品质分布、次数、间隔）
  → sim-core.simulateRun()：
      for each 制造行为:
        ② 追加 CareerEvent
        ③ XP += ComputePracticeXp(...)；能力拆分；Level/Mastery 派生
        ④⑤ 评级 + 效果加成（当前等级下的速度系数/品质偏置）
      （每 N 次行为打一个快照）
      （模拟结束时）⑥⑦ 资格判定链 + 综合评分 + 职称授予序列
  → report（CSV 快照表 + HTML 图表 + 里程碑 JSON + 控制台摘要）
```

### 2.3 公式转写表（JS ↔ C# 对齐）

| 公式 | JS 实现（src/sim-core.js） | C# 来源 |
|---|---|---|
| 单次 XP | `base × rel × qm × d × clamp(q,1,4)` | `ProfessionalXpEvaluator.ComputePracticeXp` |
| 品质系数 | `Legendary 5 / Masterwork 3 / Excellent 1.5 / Good 1.2 / 其他 1`（优先 XpPolicyDef 表） | `ProfessionalXpEvaluator.QualityMultiplier` |
| Level | `floor(maxLevel × (1 − (1 − xp/xpCap)^0.4))`，clamp [0, maxLevel] | `ProfessionalXpEvaluator.LevelFromXp` |
| Mastery | `level/maxLevel × 100` | `ProfessionalXpEvaluator.MasteryFromLevel` |
| 评级 | 阈值 ≤ level 的最高档（order 最小）；无 → null | `ProfessionalRatingEvaluator.ResolveRating` |
| 速度系数 | `1 + Σ value×(1+rw)`；技能级覆盖（hasValue/value、ratingWeightScale） | `ProfessionalEffectResolver.ResolveSpeedFactor` |
| 品质偏置 | `Σ int(value×(1+rw))`；覆盖同左 | `ProfessionalEffectResolver.ResolveQualityLevels` |
| 品质 clamp | `clamp(cur+levels, 0, 6)` | `ProfessionalEffectResolver.ClampQuality` |
| 资格门槛链 | level → careerTime → events → achievements → prevTitle → exam → thesis → defense → score | `QualificationEvaluator.EvaluateOne` |
| 综合评分 | `0.25×实践 + 0.20×理论 + 0.20×论文 + 0.15×答辩 + 0.20×等级(level/50)` | `QualificationEvaluator`（W 权重） |
| 成就 | LegendaryMade / MajorProjects / ExamPassCount / TitleCount / LongServiceTicks | `AchievementEvaluator.Aggregate` |
| 实践考试 | `100×q×(0.5+0.5×qd)×(t?1:0.6)`；硬门槛 `CountAtLeast ≥ RequiredCount` | `ExamScoring.ScorePractical` / `CountAtLeast` |

### 2.5 开发者调试 UI（dev 桥接，2026-08-19 新增，REQ-Tools-002）

**需求**：数据初始化 + 交互式行为模拟调试，挂载于 `docs/UI预览/人物档案视窗/职业档案Tab预览.html`。

- **📊 数据初始化**：空白原版殖民者（CareerData 全空：无事件/技能/资格/职称，显示空态——复用预览 HTML 空态渲染）。
- **🧪 数据模拟**：面板模拟原版游戏行为——
  - **制作物品**：221 种原版可制作物品（ThingDef costList 提取）+ 16 条 RecipeDef 配方（Recipes_Production.xml 提取），支持批量次数（1~1000）；
  - **建造**：建筑可选（ThingDef category=Building 过滤）+ 批量；**研究 / 著书**：批量；
  - **评价模式开关**：考试（通过/未通过/按传奇产出自动）、论文/答辩（通过/未通过）——调试资格缺口展示；
  - **勋章判定**：Threshold（productionQuantity=制造件数）+ Achievement（LegendaryMade 等成就键）双路径，勋章墙实时刷新（#medalStrip）；
  - **履历分段**：每 100 次制造生成一段工作经历（时段 #N）。
- **真实管线**：行为 → CareerEvent 事实（append-only）→ XP/能力/等级（白名单配方才涨 XP）→ 评级/效果 → 资格判定/职称授予 → 档案实时刷新（复用 renderOverview/renderCareer）。
- **挂载顺序**（预览 HTML 尾部，相对路径）：
  `../../../Tools/DataSimulator/dev/sim-core.js`（UMD）→ `defs-data.js` → `recipes-data.js` → `sim-bridge.js`。
- **自检钩子**：URL 带 `?simtest=1` → 自动执行 初始化→批量制作→评价缺口→勋章→输出结果（headless 回归）。
- **重新生成数据**：`node src/gen-data.js [--rimworld <RimWorld 安装目录>]`（默认自动探测本机路径）。

**验证**（headless Chrome，?simtest=1 全通）：加载链就绪（SimCore / 4 技能 / 221 物品 / 31 勋章）；空白初始化"未建档"；30 次优秀组件 → Lv1；考试开关 fail → Senior BLOCKED(exam)；300 件 → Medal_Labor_Worker_Bronze 授予；1130 次 → Lv50/大师评级/2 勋章/12 段履历。

## 3. 测试计划与验收

### 3.1 自测（模拟器内部一致性）

| 用例 | 验证点 |
|---|---|
| 公式金样 | 已知输入 → 期望输出（如 10 XP×500 次 Normal = 5000 XP → Level 50；全 Excellent → 更快达成） |
| 金样对照 | 与 C# 实现公式逐一核对（转写表 §2.3），输出数值断言 |
| 场景可跑 | 4 个预置场景全部一键运行无异常 |

### 3.2 与 NUnit 的关系

- NUnit（Tests/）验证 C# Domain 函数正确性（函数级）
- 模拟器验证**管线时序行为与数据调参**（系统级），两者互补；公式以 C# 为权威源，转写表登记版本（2026-08-19 对齐 P2-A §5 / P3-A / P4-A / P5-A 基线）

### 3.3 风险与缓解

| 风险 | 缓解 |
|---|---|
| JS 与 C# 公式漂移 | 转写表 + 金样断言；C# 改动后跑模拟器对照 |
| Defs XML 结构变化 | mini parser 容错 + fallback 数据；解析失败报错指明文件 |
| 模拟器不代表真实引擎行为（无 job/工时/派系） | 明确非目标；行为序列由配置驱动，模拟"数据层"而非"引擎层" |
