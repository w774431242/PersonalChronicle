**玩家经营公有机构并进行对外贸易；Pawn 根据生活需求和有限储蓄目标，自主就业、消费与使用服务。生产资料及售出前的产物归公有机构，工资归劳动者，个人购买获得物品或服务使用权。**

## 1. 制度开关和玩家权限

在现有 **Mod 设置 → 经济制度 → 启用公有机构工资与消费制度** 设置一个总开关，前端沿用现有 RUIF 设置页。新安装默认关闭，避免旧档在更新时突然收费。总开关管理制度启停；机构页只配置本机构政策，不另设第二个全局开关。

| 主体 | 权限与职责 |
|---|---|
| 玩家 | 建设公有机构、指定生产工单和贸易方向、注入实际货币、分配预算、设置岗位薪资/价格/时段/保障额度 |
| 公有机构运行器 | 在玩家授权范围内维护招聘、排班、补货、生产需求、订单与预算占用；没有资金或真实工作时停止扩招 |
| Pawn | 比较生活方案、主动找工作、接受或退出合同、购买产品/服务、照护家庭、保留有限储蓄与休闲 |
| 原版调度 | 征召、玩家强制任务、危险与紧急生存等控制权继续有效；经济动作通过原版 Job 执行 |

机构建设、首次配置及外贸需要玩家治理；正常求职、补货、履约与消费不要求逐 Pawn 强制操作。尊重原版禁工、能力、区域、可达性和 DLC 条件，不自动改变玩家的这些授权。

开关改变后在主线程安全时点应用，不在 RUIF 绘制中转账、修改 Job 或生成物品。关闭时停止新合同与新收费，取消未交付预约并释放预留；完成中的原子交易先结算或回滚。已得工资、已购物品、已履约应付款和历史账本保留。公有库存恢复原版合法供给时记录实际移出/消耗，再开启不重生库存或补发启动金。

## 2. 资源规则：归属与使用权分别记录

| 资源状态 | 所有权与默认使用方式 | 经济处理 |
|---|---|---|
| 野果、自然树木、野兽等未开发资源 | 公共自然资源；原版允许且安全时可采集、砍伐、狩猎 | 不收资源占有费；危险、禁用、生态损耗和实际采集时间照常存在 |
| 有偿采收、农作或狩猎交付的原料 | 进入公有生产库存 | 工人领取对应劳动报酬；不能同时将这批原料算作个人收入 |
| 机构原料、半成品、待售成品 | 公有库存，按生产/物流/销售用途授权 | 不能因建筑公有就任意拿走已登记的商品或生产投入 |
| 加工食品、衣物、药品等再加工产品 | 默认收费；成交前公有，交付后按订单归个人或使用方 | 实际物品交付触发结算，不靠账本生成物品 |
| 建筑、设备、医院、居住设施 | 始终公有；可有免费公共功能和付费使用时段 | 付款购买床位/服务权，不购买机构所有权 |
| 公共保障或雇主提供的产品/服务 | 仍有真实资源成本，由公共专项或雇主预算承担 | 对受助者可以免费；付款方明确，不虚构销售收入 |
| 个人自救获得、个人已购的合法物品 | 个人持有；沿用明确的个人使用登记 | 原版个人使用可继续；当前不开放私营商店或商业转售 |

不能只按 ThingDef 判断收费：同一种浆果可能是野生自采、公共原料或机构待售商品。收费与用途权限绑定真实批次/物品及其流转记录；拆分、堆叠、烹饪、损毁后同步数量与归属。不同权属批次不能通过混堆丢失记录。

个人自救采集与机构雇佣采集是不同任务来源。个人采集到的木材等不是系统自动收购的商品；进入有偿生产链必须先按明确的捐入/公共接收规则登记，不能自动按 MarketValue 换钱。野兽属于公共自然资源不代表能够直接当作无风险食物，仍需原版捕猎、处理与食用过程。

## 3. 再生产侧同样提供工资岗位

工资购买实际劳动；公有生产资料经过劳动形成公有产品，产品再供给内需或外贸。不能只有柜台服务人员领薪，而种植、加工和物流没有劳动入口。

| 链条与岗位 | 输入 → 输出 | 可验证结算单位 |
|---|---|---|
| 农作/采收 | 授权田地或自然资源 → 实际原料入公共链 | 完成的播种/收割批次分别结算，收割数量与实际产物关联；不能种植后等成熟才付全部工资 |
| 狩猎/屠宰 | 合法猎物、尸体 → 真实肉料/皮革 | 授权任务完成与实际交付；猎杀和屠宰分别登记，避免同一事实重复计件 |
| 烹饪/加工/制药/制衣 | 公有原料 + 原版 Bill → 实际成品 | 配方迭代实际完成、产物登记；有上限的计件/批次工资 |
| 搬运/补货 | 指定公共来源 → 合法目标库存 | 实际移入数量、来源和目标；去重，不按每次拿起物品发工资 |
| 清洁/维修/设施维护 | 合法服务工单 → 清洁度/维修进度等实际改变 | 授权区域的有效完成量或经核验的工作片段；限制无效往返和反复造脏刷薪 |
| 医疗/照护/教学 | 真实人员、时段、材料 → 合格服务交付 | 按第 7 节服务证据；服务者报酬与患者/儿童的最终恢复成长分别处理 |

默认先采用有限计件和服务结算；需要保障待命人员时，单独配置有容量上限、实际当班条件与预算的待命合同，不能把“站着不动”统一当作劳动收入。

合同必须写明角色、任务范围、班次、报酬单位、结算点、最高承诺量、资格、暂停及退出条件。必要资格体检由雇主有限预算支付，避免无钱 → 无资格 → 无工作 → 无钱。现有体检报告仍只表示岗位资格，不等同于治疗服务。

玩家配置岗位模板后，由机构自动接受合法申请、补岗与安排适合的工作。没有可执行工单、材料、服务需求或支付额度时不发布虚假岗位。机构搬运使用自主物流岗位，不能把当前手动 StockItem 命令当作日常自动补货已经完成。

## 4. 货币来源与外贸循环

闭环分成两条相互对应的链：

**实物流：自然资源/种植 → 原料 → 公有加工 → 内部产品和服务 / 外贸货物。**

**货币流：玩家外贸净银币收入 → 实际缴存 → 公共资金 → 机构预算 → 员工工资 → 产品和服务消费 → 公有机构收入 → 再生产与下一轮工资。**

外贸提供新增可注入货币；内部消费提高已有资金周转。订单上涨必须由真实购买、可负担预订、库存缺口或玩家明确的生产授权驱动，不能把每个未满足愿望直接变成已付款订单。

### 4.1 统一账户拓扑

设公共总账户 `Treasury`、各公有机构账户 `Institution:<id>`、个人账户 `Pawn:<id>`。公共保障作为有上限的专项预算，可与总账户共享账本但需单独记录承诺。

- 外贸收入先进入公共资金，再按玩家预算规则拨款，不能一次同时记入总账户和机构收入。
- 机构支付工资、接受消费款；跨机构原料/物流结算是预算转移，合并公有报表时抵销内部往来，不伪装成对外收入。
- 工资、消费、拨款、退款都借贷相抵；预留占用现有余额，不增加货币总量。
- 接单前预留最高合法支付额。已履约未付记应付，不再次发相同工资，也不当作已收现金。

### 4.2 真实银币与内部账本只入账一次

建议沿用内部整数最小单位，显示 1 单位对应 1 银币、内部 100 分。启用本身不赠送货币；玩家可以将已有真实银币作为期初投入，持续资金来源由之后外贸提供。

缴存时把实际银币移入专用结算储备，转移成功才生成等额公共余额和唯一入账凭据。储备银币不同时用于原版交易或工资物品发放。若允许提取，只可从公共未占用余额等额扣减后释放银币，不能动用员工余额或已承诺工资对应的储备。

对于从零建立的新账本：`全部账户余额之和 = 累计缴存 − 累计提取`；足额银币储备对应这些余额。自然损失、被掠夺或损毁单独记储备缺口并冻结新增提取/承诺，不能靠扫描发现缺币后再次发行补平。

外贸事件用于说明来源并辅助注入：只认真实结算与实际到账，不按卖出货物估值或总成交额发币。以物易物、赠礼、荣誉货币、未成交或净买入不产生“外贸净银币收入”。商队/空投尚未入库的银币不能提前作为可用机构预算。一般已有银币缴存仍可作为明确的期初/追加投入，不能伪称全部来自外贸。

当前参考代码首次启用赠送的 1000 内部单位必须移除新发放路径。旧余额和欠薪记录迁移到历史权益记录，不归零、不重复赠送；迁入新可用账本需落实对应实际银币。未落实部分显示为待清算历史权益，不投入新的工资承诺；已购物品不收回。迁移前展示差额与处理结果，不能静默把旧余额当作全额新现金。

### 4.3 外贸不是永动保证

贸易受原版商人到访、价格、收购种类、银币和运输约束；当前不自动操控玩家交易，也不凭空生成外部买家。外贸下降时，依次停止扩招和非必要新生产、调拨未占用公共资金、保留已承诺工资与公共急救预算，并报告可支付周期。

个人储蓄是有限目标，达到水位后不为继续赚钱无限延长劳动；也不为机构回款强迫无需求消费。所有人储蓄上升、销售下降时，允许经济收缩，玩家通过外贸、预算和实际供给治理。允许失败并可解释，比假定现金必然回流更完整。

## 5. 从消费到生产订单

每个机构维护三类不同信号：未满足生活缺口、有效购买/预约、玩家授权的库存与外贸计划。前者解释需求，后两者才形成有边界的生产任务。

对某种产品使用拟议补货规则：

`新增计划量 = max(0, 已确认未交付量 + 目标自由库存 + 玩家授权出口量 − 可用库存 − 已有可完成在制量)`。

这里可用库存包含已为上述确认订单预留的实物；目标自由库存不含这些订单预留，避免重复计算。缺料、过期、损坏和不可达库存不算可用。计划量还要受原料、设备、人员、仓容、保质期、机构预算和玩家工单上限裁剪；已存在的出口任务计入在制/计划，不能每轮再次追加。

销量平滑统计可更新有限的目标库存，不能销量一高就无限扩产。订单取消释放对应未开工承诺；已开工则按真实生产状态处理。原版工单决定合法配方，经济模块只产生授权范围内的工作需求；与既有车间生产控制保持单一计划写入者。

## 6. Pawn 的长期风格与短期动作

总调度仍只有一个，下面四个业务循环分别处理短期需求、储蓄、劳动与消费/服务；机构供给和玩家治理是外围反馈。

1. 读取原版需求、健康、家庭事实、余额、已承诺开销和合法机会。
2. 长期目标给出食品品质、休息/娱乐时间、可用工时、家庭责任和有限保障期；用可负担方案的实际费用估计未来缺口。
3. 短期先处理原版控制权和紧急风险，再按时限、首次有效帮助时间和可执行性选择方案；一次只提交一个前台意图。
4. 当可用资金低于有限储蓄下水位且存在未来合理支出时，提前寻找适合岗位，不等到余额为零才求职；达到上水位后停止补储目标。
5. 有需要且可负担时消费；免费自救与付费产品按真实营养、品质、时间、风险和可靠性比较。免费方案确实同等时允许选免费。
6. 使用真实产品/服务，反馈 Need、健康或家庭事实；付款成功不代表生活目标自动完成，效果未到也不代表服务应退全部费用。

原型起始参数建议：生活预测 1–3 游戏日，储蓄下水位为目标的 60%–80%，上水位为 100%，可选储蓄分配 0%–40%。这些是待试玩的 Mod 参数，不是原版数值或固定阶层。资金不足时先保障眼前必要生活，不硬扣比例导致饿死。

食物/休息紧急动作不能直接套当前“Food≥0.5 且 Rest≥0.4 才允许经济动作”的购物安全门。求职和购物可延迟，吃饭、急救、必要照护应进入各自合法紧急路径。婚恋沿用原版关系与事件；可以规划共同生活费用，不新增“花钱必定结婚”的保证。

## 7. 服务与医疗的具体契约

参考现实中的“服务过程、材料、占用时段”区分收费，实际交付仍以原版游戏事实为准。所有服务机构公有；哪些服务由个人、公费或雇主承担是政策，而不是机构所有权变化。

| 服务 | 付款与交付 | 中断、失败与效果 |
|---|---|---|
| 食品零售 | 预留款项，真实物品交付后结算；营养改善由实际食用产生 | 未交付全额释放；已交付不能因暂未吃下退款，腐坏/错货按交付时事实处理 |
| 公有居住/休息床位 | 按已报价的有效使用片段结算，预留本周期上限；设备与房间始终公有 | 未使用片段释放，不能因睡眠不足再次收同一片段；危险离床不算违约 |
| 普通诊疗/治疗 | 服务费与实际耗用药物分列；按真实合格治疗行为结算，疗程有费用上限 | 未实施不收费；部分已实施按事实结算；不承诺疾病一定消失，不人为写健康值 |
| 急救 | 由玩家配置的有限公费额度先承担，不让先缴费成为紧急救治前置 | 仍需医生、药物和床位；额度不足明确报警并回退原版合法救助，不默默向患者造债 |
| 岗位体检 | 雇主承担必要资格检查，按有效检查交付报告收费 | 资格不通过不等于未服务；取消释放未交付费用；报告有有效期，不代替治疗 |
| 托育/教学 | 监护人或公共专项支付；按真实有效照护/教学片段、对象与容量计量 | 中断后结算已交付片段；同一儿童同一片段不重复付款；原版发展/学习结果另追踪 |
| 娱乐与公共活动 | 未建立专用服务适配前保留原版公共活动 | 不先将原版全部娱乐设成收费；以后只对明确登记的新服务计费 |

每份服务订单绑定受益者、执行者、付款方、场所、时段、材料、最高价、交付凭据、取消与退款状态。服务承诺前检查双方时间、资格和容量；患者或儿童无自主执行能力时由照护责任方发起和协调。

原版医疗、寻食、寻床与物品搜索需要按资源登记局部适配，不能只在商店 UI 做收费。预约只获取临时优先权，不能阻止征召、逃生或急救；未登记的原版资源保持原版合法规则。服务方离图或死亡，释放后续预约并重派责任；已履约部分留账。

## 8. 启动、人口变化与收缩

启动顺序固定为：**打开设置 → 玩家登记机构和授权岗位 → 缴存与划拨真实资金 → 检查工作/物资/基本生活 → 开放对应收费能力 → Pawn 自主求职和消费**。每项能力独立检查准备状态，无需等所有机构一起建好。

个人零现金不阻止申请；首笔工资前的必要资格由雇主承担，必要启动餐由有限雇主/公共预算采购或原版合法免费资源支持。没有实际资金、岗位和生存供给时显示“未准备”，不能靠生成食品或启动金假装开启成功。已有床位/已开始服务不追溯收费，新周期采用新条款。

新来居民沿用零现金启动规则；婴儿和失能者由明确监护/公共责任承担；死亡、离图、机构损毁解除未来承诺与占位，保存已付事实和欠款。无人账户/资产进入保管状态，当前不实现完整遗产法；回归时按稳定身份恢复。

玩家可用治理动作限定为真实有效动作：调预算、调整新合同薪资、调整新报价、授权岗位/时段、调整库存/出口计划、设置有限公共保障和建设扩容。增加时段仍需人员，增加预算仍需资金，调价不追改已承诺订单。UI 显示问题、受阻原因、可执行动作及下一周期效果。
