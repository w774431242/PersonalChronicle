# 多需求并发仲裁：设计补充 v0.4

2026-10-08。状态：讨论方案，不修改运行代码。本册补充[原版需求缺口方案 v0.3](原版需求缺口驱动经济AI_设计方案_v0.3.md)，优先用于解释多需求仲裁、长期/短期循环及储蓄保护；未涉及的账本、原版事实来源和 RUIF 约束继续沿用原册。

## 1. 当前方案有顺序，但尚不完整

已有：P0–P3 分级、先合法性后评分、即时需求优先于赚钱、目标滞回、家庭缺口唯一、购买与满足分离。

需要补齐：同级竞争、原版控制权与自主行为的区别、任务依赖、紧急但无可行方案、可中断阶段、多人共享资源、被长期挤占的需求、现金与时间预算竞争、恢复与过期处理。

当前实装仅有衣物业务、机构 Job、账户及合同等参考基础；单一 Goal 字段和经济 JobGiver 的固定优先值不代表存在本册仲裁器。尤其不能将本方案的 P0–P3 直接换成任意几个 GetPriority 浮点数，就声称与整棵原版 ThinkTree 正确衔接。

## 2. 一个执行入口，多个持续目标

长期循环维护生活风格、预算、储备水位和可持续时间分配；短期循环处理当前缺口、迫近风险与正在履行的承诺。两者共用同一目标池和执行出口。

一个 Pawn 可同时有多个生活目标，但同一时刻只选择一个前台行为意图，实际 Job 由原版规则执行。等待工资、排队资格、订单状态可以后台推进，不各自占用一个永不结束的等待 Job。原版 Job 内部允许的复合效果不等于 Pawn 可以同时履行两份互斥任务。

储蓄/劳动/消费/服务循环向调度器提交意图，不直接轮流强制 StartJob。当前目标与被暂停目标都保留，切换不等于删除人生计划。

## 3. 需求输入与预测

每个需求记录：GapKey、主体、事实可用性、gap、当前类别、风险等级、最迟开始产生有效帮助的时刻、预计持续影响、来源版本。每个行动记录：执行者、受益者、付款方、前置条件、实际预约对象、预计路程/排队/服务时间、资金占用、可中断阶段及预计效果。

必须区分：

- 当前已不足；继续执行当前任务后才会不足；只是长期改善愿望。
- 生理需求主体和承担照护任务的成人；不能复制孩子的缺口给每个监护人。
- 缺口很大与即将出现严重后果；缺口比例本身不代表死亡或事故时限。
- 未知时限与立即到期；缺少预测依据不能填 0，也不能假设无限安全。

时限估计来自可验证的原版需求变化、伤病/环境事实与服务安排。没有可靠精确预测时用原版类别、保守时间区间及“不确定”标记，不承诺能预测精神崩溃、疾病恶化或死亡的准确时刻。Mood 风险用于调整已有目标的紧迫性，不额外创造第二份心情收益。

## 4. 先处理原版控制权

原版征召、玩家强制任务、精神状态、昏迷/倒地、Lord/活动约束等首先决定经济 AI 是否有权行动。经济系统不以“我的优先级更高”为由改写玩家命令或接管精神状态。

控制权不允许经济自主行为时：经济 Job 按原版机制退出或不进入，记录暂缓原因；必要风险通过只读提示报告。哪些原版需求允许中断玩家命令，由原版实际机制决定，不由经济分数决定。

控制权允许后才进行 P0–P3 仲裁。P0 意味着经济行为让路并使用经过验证的原版保护路径，不意味着经济模块凭空获得急救、瞬移、额外移动或任何身体能力。

## 5. 等级由风险决定，不把需求类别钉死

| 等级 | 定义 | 典型情况 | 对其他任务的影响 |
|---|---|---|---|
| P0 即时保护 | 已出现或迫近严重生命/安全问题，原版保护条件成立 | 急救、婴儿危险、严重饥饿、失能风险 | 可行的保护优先；按原版许可中断自主经济活动 |
| P1 近期保障 | 若不及时处理，将错过基本生活保障或必要责任 | 下一餐、近期睡眠、必要喂养、即将出现的温度防护问题 | 允许调整普通班次与可选消费；禁止安排必然错过时限的工作 |
| P2 可持续日常 | 维持正常生活、履约和已分配时间的活动 | 正常班次、计划娱乐、普通学习、日常服务、非紧急补储蓄 | 同级仲裁与时间保障，不能让一种活动永久排除其余活动 |
| P3 长期改善 | 无近期风险、可推迟的事件准备与升级 | 奢华婚礼、非必要家具、额外财富目标 | 用剩余时间/资金；允许分段推进 |

普通娱乐通常 P2；严重、持续的娱乐不足结合原版风险可能上调其保障意图，但不能仅等待够久就伪装成医疗急救。睡眠、衣物、学习也不固定永远属于某一等级。普通婚礼到时不自动成为 P0；安全相关的孕产/育儿子目标单独评估。

储蓄不是永远 P3：一般补储是 P2；若预测基础餐费将在近期耗尽，相关生活保障目标进入 P1。但赚钱行动仍必须在时限前有效，不能借父目标的 P1 标签无限工作。立即饥饿时先寻找即时食物/保障，不将远期工资当救命行动。

## 6. 同级竞争：比较后果与可行时限

对等级相同、实际可行的保护/保障方案，依次比较：

1. 延误可能造成的严重且不可逆后果；以原版事实为依据，不按所有需求的百分比直接混排。
2. 距离必须开始产生有效帮助的剩余时间。
3. 行动能否及时带来足够缓解，而不只是最终完成整个目标。
4. 对其他临近高优先级需求的影响，以及能否交给其他合法执行者。
5. 在基本可行方案间比较效果、时间、成本、长期偏好与等待情况。

可计算的辅助量：

```text
预计首次有效帮助时刻 = now + 路程 + 前置步骤 + 排队 + 开始产生效果前的服务时间
slack = 需求风险时限 - 预计首次有效帮助时刻
```

同类可比情况下 slack 较小者通常更急，但不能机械将所有负 slack 排在一切之前。负 slack 只说明无法完全按原计划赶上，应改选最快稳定/减轻损失方案；仍可能比什么都不做好。无法可靠预测时限的目标用类别和区间处理，不制造伪精度。

对多个 P0 目标，不作“所有情况下都能救下所有人”的承诺。先找并行的合法执行者和资源；容量不足时，根据严重后果、实际可救性和最早缓解机会做有界选择，并明确记录未覆盖风险。只有正在独占同一 Pawn 的行为需要串行；其他成人可以协作。

对 P2/P3 日常目标，在满足上面的风险/时限约束后，才比较规范化净收益和长期风格。完全同分采用稳定 goalId/actionId 排序，避免随机来回切换。

## 7. 多需求冲突时选择“短方案组合”

不能只选某个最高需求后一次做到满。对最紧迫的少量目标比较有限方案：

- 快速吃一份现成合法食品 → 睡眠，可能比远距离购买高级餐后再睡更合适。
- 成人短暂进食、另一成人喂孩子，可能优于一个人先后包办。
- 临时稳定伤势后等待医生，可能优于不顾可达性锁定远处服务。

MVP 只比较关键目标的短方案组合和前置链，不声称全局最优。安全缓解阶段结束后再评估，目标未达到完整完成条件时仍保持 Active/Paused，不能把“暂时稳定”冒充永久满足。

任务依赖建立有向无环图：如生活保障 → 需要资金 → 合同 → 工资到账 → 服务。发现循环依赖则拆开或标为制度性受阻，不能递归创建无穷子目标。

付费体检是入职前提但本人无钱、工作又是唯一收入来源，是典型启动闭锁。可选制度解法包括公共资格检查、明确的雇主代付或不要求体检的合法岗位；每种代付必须有真实付款方，不默认开无限赊账。

## 8. 中断、清理和恢复

| 当前阶段 | 普通新目标 | 更高风险需求 | 恢复原则 |
|---|---|---|---|
| 尚未执行 | 可重新比较 | 重新选取合法保护行动 | 不保留无用短期预约 |
| 行走/可逆准备 | 需明显收益差才切换 | 原版许可下中断 | 清理订单、释放经济/游戏预约，保留生活目标 |
| 已产生部分效果 | 通常先完成最短有效段 | 比较继续和中断的实际风险 | 记录真实效果，剩余需求重新计算 |
| 交易原子提交 | 不在同步提交步骤中切换 | 同一无 yield 的短提交结束后处理；不得扩展为长期不可中断服务 | 只能完整提交或按事务补偿，不重复扣款 |
| 已交付未使用 | 按使用目标继续 | 可暂停使用 | 保留资产/服务事实，不因暂停再次购买 |
| 已完工待发工资 | 后台结算 | 不占前台等钱 | 真实到账再更新资金，欠薪不可花 |

中断规则复用原版 Job 清理、可中断性和行为限制；不能因已付款就阻止逃生，也不能把整个医疗过程一概当作可以无损中断。具体服务必须定义真实交付、部分服务和费用结算规则。

恢复时重新读取事实、价格、库存、关系、服务和期限，不盲目重放旧 Job。原目标已满足/失效则关闭；未满足时继续下一合法阶段。切换成本不能压过紧急风险，但可防止普通方案小幅波动导致反复折返。

## 9. 避免需求长期被饿死

长期策略给睡眠、娱乐、家庭、劳动和准备分别保留可行时间；短期 P0/P1 可临时借用，但记录被挤占原因和待恢复时间。恢复不是强行立即加倍补偿，更不能把休闲欠账做成永久累积的失控压力。

同级且可执行的等待目标可获得有上限的等待加权。受阻、主体不存在、睡眠冻结、不适用的目标不能不断累计优先级。等待时间不会突破身体能力、玩家命令、P0 保护或合法性限制。

连续多个规划周期因基本保障占满时间时，应反馈“原生活计划不可持续”：降低可选消费/储蓄承诺、调整工时、改变服务安排、增加照护分担。不能一边坚持过高储蓄比例，一边永久剥夺娱乐与家庭时间。

## 10. 钱、物、时间与服务容量共同仲裁

- 同一笔可用资金只能分配一次。先识别已经完成的承诺与真实冻结，再安排新目标；可按政策释放可撤销的低优先级软预算，但已成交不自动退款。
- 为应急准备的钱可以用于对应应急目标，不能因“这是储蓄”而阻止治疗。未到账工资不作付款许可。
- 一张床、一件衣服、同一个服务名额不能同时保证给两个冲突目标。准备与提交之间必须再次检查版本、原版预约与实际对象。
- 食物必须考虑真实数量及分配；婴儿/成人合法食品不同，不用统一营养数值掩盖实际不可食用问题。
- 成人同一时间不能承诺生产、睡眠、照护三件互斥的事；路线和排队也占时间。
- 服务方也有需求和日程。医生和照护者不能被经济合同永久锁住，服务排队需要替班、重新预约和有限容量。
- 多个目标共享筹资来源时，合并为有明细的有限收入计划，目标金额去重；不能让每个需求各派一份同时间劳动合同。

## 11. 家庭与多 Pawn 协作

需求排序按实际主体风险进行，但是否由某成人执行还要检查责任、能力、日程和可达性。被监护孩子的高风险需求不能因其没有个人钱包而丢失；成人自身严重失能也不能靠“家庭责任高分”突破能力限制。

以 GapKey 去重，指定一个当前责任执行者；其他成人可承担替代或后续任务。指派采用先校验后提交的原子规则，指派后执行前再次检查；发生死亡、离图、倒地、工作约束变化时重新指派。

医生自己饥饿且病人急需救治时：先找替代医生/快速合法补给，再比较实际时限；不套用“成人永远先吃”或“服务方永远牺牲自己”。家庭只建立明确分担的预算和责任，不自动合并产权、余额或强行改原版关系。

## 12. 无可行方案、异常与退出

需求与行动分别保存。高需求没有合法行动时保留风险和阻塞原因，但不能每个 tick 重发同一个必败 Job，也不能凭空标为满足。

对缺货、缺岗、无医生、无床、路径不通、预算不足、营业关闭、队列已满分别处理：寻找替代、安排最快可行缓解、请求协作/保障、等待事件或有限退避。紧急受阻期间仍持续监测风险和可行缓解，不直接安排一个很长的低优先级工作。

缺钱与无供给是两类问题：赚钱不能解决没有医生；有医生而不合法可达也不能通过付款解决。未知 DLC/第三方机制标不适用或不支持，不用最高缺口惩罚该 Pawn。

目标失败有冷却；风险升级或供给变化可提前触发重评。设置有限目标数量、扫描候选、失败次数和重试频率，保留被截断原因，不能静默丢弃紧急需求。离图、读档、时间回退、关系变化和资产销毁都使旧计划重验。

## 13. 重点冲突矩阵

| 同时发生 | 建议处理 | 必须避免 |
|---|---|---|
| 饥饿 + 疲劳 | 看实际危险与首次缓解时限；可先快速补给再睡，必要时原版保护接管 | 固定永远先吃或先睡 |
| 饥饿 + 高薪班次 | 基本进食保障先处理，再履约/调整班次 | 用高工资抵消饥饿风险 |
| 受伤 + 没钱 + 储蓄目标 | 原版急救优先，使用允许的医疗储备/明确保障 | 等赚够治疗费才求救 |
| 成人饥饿 + 孩子急需喂养 | 查替代照护者，比较可执行的最短缓解方案 | 孩子没钱就不进入队列 |
| 婴儿危险 + 已付娱乐服务 | 安全先行，按服务规则取消/改期 | 已付款便不能中断 |
| 医生疲劳 + 病人急救 | 替班/能力/时限共同评估 | 无视服务方真实能力 |
| 玩耍不足 + 儿童学习不足 | 按发展阶段确认哪些 Need 实际存在，再分配活动 | 把婴儿 Play 和儿童 Learning 强加给所有年龄 |
| 娱乐持续不足 + 补储蓄工作 | 保护计划娱乐，降低非必要储蓄/工时；实际风险另评 | 补储任务永远胜出 |
| 婚礼临近 + 基本餐费不足 | 保留合法原版婚礼，缩减可选筹备，保障食品 | 婚礼预算抢走全部餐费 |
| 婚礼进行 + 紧急需求 | 原版活动约束与安全退出规则决定可执行动作 | 经济模块直接改成已婚或忽略紧急需求 |
| 两个孩子 + 一个照护者 | 按风险时限分配并找合法协作 | 给两个目标同时承诺同一时间 |
| 两个客户 + 一个医生 | 原版急救路径优先；可选服务按资格/时限/有限公平队列 | 谁付钱多就覆盖所有急救 |
| 食品与衣物争同一资金 | 保障迫近基本需求，保留可推迟衣物目标 | 两单分别看到同一余额都扣款 |
| 储蓄不足 + 无商店 | 根据真实未来支出保留储蓄预测；找有效岗位 | 无商品就认为没有生活需求 |
| 有钱 + 无床/无治疗能力 | 查公共安排、供给建设、替代与保障 | 把资金充足当作服务已获得 |
| 有岗位 + 没原料或没工单 | 重估收入可行性，换岗/等待供给 | 按名义工资承诺能养活家庭 |
| 入职要自费体检 + 零余额 | 明确代付/保障或找其他合法岗位 | 工作与体检互相等待成死锁 |
| 工资延迟 + 服务即将到期 | 重排现金、服务与保障；工资保持应收 | 把欠薪余额当真钱支付 |
| 已购衣物 + 新商品更好 | 先处理已购资产的实际适用性，再评估替代 | 同一待穿目标反复采购 |
| 原版强制任务 + 自主需求 | 经济系统退让原版控制权并保留目标 | 自主分数强行覆盖玩家命令 |
| 各种日常需求持续占满时间 | 上报不可持续，修改长期工时/预算/服务策略 | 永远声称排一遍就能全满足 |
| 需求来源失效 + 已有订单 | 重验主体/关系/资产，按事务取消或保留已提交事实 | 为失效目标继续工作付款 |

## 14. 拟议仲裁过程

```text
Reevaluate(pawn, reason):
    facts = ReadCurrentFacts()
    ReconcileCommittedResultsAndExpiredClaims()
    authority = ReadVanillaControlAuthority()
    if authority forbids economic autonomy:
        DeferEconomicIntentsAndReportRelevantRisk()
        return control to vanilla

    demands = EvaluateCurrentAndNearFutureGaps(facts)
    goals = DeduplicateAndUpdateLifeGoals(demands)
    options = BuildBoundedOptionsAndDependencyPlans(goals)
    FilterIllegalAndPhysicallyImpossibleOptions(options)

    if any P0/P1 risk is uncovered:
        options += FindLegalMitigationDelegationOrFallback()

    ranked = RankByRiskBandConsequenceTimeAndFeasibleEffect(options)
    ranked = ApplySameBandFairnessAndLongTermPreferences(ranked)
    winner = KeepCurrentUnlessNecessaryOrMateriallyBetter(ranked)

    if no executable winner:
        RecordBlockedReasonsAndScheduleBoundedReevaluation()
        return control to vanilla

    RecheckAuthorityFactsMoneyTimeAndReservations(winner)
    if recheck fails:
        InvalidateStaleOptionAndRetryWithinBound()
    else:
        SafelyPauseOrCompleteCurrentPhase()
        IssueOneIntentThroughVerifiedVanillaJobBridge(winner)
        ObserveActualEffectAndFeedBackToGoals()
```

“找回退路径”和“交还原版”都要有明确适配，不保证任意返回 null 就必然获得正确紧急 Job；原版树中的实际优先、资格和活动限制需要单独接入验证。现有固定优先值 6 只能作为当前衣物机构入口的参考，不能承担多需求总仲裁。

触发采用自然决策点、重要风险/关系/供给变化事件和有限低频刷新。交易原子区不重入；同一 Pawn 的事件合并，避免工资、库存、需求同时变化时重复派单。原版 Need 的自然变化仍由原版推进。

## 15. 玩家解释、验证与范围

RUIF 详情应展示：当前为何选择该行动、哪些需求正在等待、风险等级/时限是否可靠、暂停了什么、资金由谁承担、什么事件会重评。并显示“当前计划不可持续”“供给不足”“没有合法照护者”等实际可行动原因，不只给出总分。

后续验证包括：冲突矩阵中的情景回放、目标与预算去重、可中断阶段恢复、多人容量竞争、等待公平性、无合法行动退避、长周期时间/预算可持续性。优先级算法的纯领域检查与真实原版 Job/活动交互验收分开。
