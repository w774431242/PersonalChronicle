# 玩法完整度评估与设计准入 v0.6

> 后续状态：用户进一步明确公有机构、公共自然资源、加工品收费与外贸资金来源后，已形成[优化基线 v0.7](公有机构与外贸循环_优化方案_v0.7.md)。本报告保留当时的 7 项阻断分析；其最新规则处理见 v0.7 §9，第一批已进入代码设计，以下“未满足/Open”不再代表当前设计准入状态。运行实现与游戏验收仍未因此通过。

2026-10-08。审计对象：[需求缺口 v0.3](原版需求缺口驱动经济AI_设计方案_v0.3.md)、[并发仲裁 v0.4](多需求并发仲裁_设计补充_v0.4.md)、[自主经济社会 v0.5](自主经济社会与玩家角色_总体设计_v0.5.md)。现有运行代码仅用于检查可复用基础和原版接入约束，不将“尚未写代码”直接计为玩法缺口。

## 1. 结论与范围

结论：**仍有明显玩法缺口，暂不满足进入正式游戏代码设计文档的条件。**

个体需求、长短期循环、储蓄、仲裁、家庭责任与玩家角色已经形成较清晰框架；从开局启动到机构再生产、持续支付、制度切换和服务交付的社会闭环尚未冻结成可执行规则。

本次发现 **7 项阻断项 G01–G07**、**4 项深度与体验问题 D01–D04**。分级含义：阻断项会使核心承诺无法连续运行或要求玩家反复逐人救场；深度问题会影响差异化、长期变化和解释体验。没有用机构/需求数量估算完成百分比，没有进行游戏内测试，也没有仿真出总体稳定性结论。

以下建议是为补齐规则而提出的具体候选，不自动将相关问题改为已关闭。进入代码设计不要求先完成尚未编写的游戏功能，但必须先明确结构性规则和可验证场景，避免把同一玩法问题留给多个程序模块各自猜测。

## 2. 已具备的玩法基础

| 方面 | 已有设计 | 当前判断 |
|---|---|---|
| 生活动机 | 原版事实、当前/未来缺口、有限生活目标 | 框架成立；不是凭空生成赚钱欲望 |
| 行为组织 | 一个总调度、四个业务循环、一个前台意图 | 能避免多个循环争抢同一 Pawn |
| 多需求冲突 | 控制权、P0–P3、时限、短方案、中断恢复 | 覆盖主要冲突，不保证资源不足时人人都成功 |

## 3. 七项必须补齐的规则

### G01 开局启动与制度切换

证据：v0.5 §2/§7 列出阶段和多种启动选择，但未选择首批默认启动方案，也未定义开启收费时现有使用者、人员、资金和已开始服务如何处理。

反例：所有个人余额为零，餐饮要求付款，岗位未招到人，机构又要求先交资格费；原版能自救不代表经济社会已启动。直接切换全部原版资源为收费还可能使旧档生活突然中断。

建议首批规则：

1. 由玩家一次性启用制度模板并授权设施、预算与合法工作范围；不逐个选择日常执行者。
2. 公共食物/基本床位/急救保留其实际可供给范围；受雇者的启动餐费或必要资格检查由明确、有限的公共/雇主预算覆盖。
3. 只有人员、真实物资、有限付款能力和首笔工资时限满足时，相关付费能力才开放；不要求整个社会一次全部开启。
4. 已分配床位、已经开始的服务不追溯收费；制度变化从新合同/订单周期生效。
5. 关停制度清理未提交订单与制度自有排班，保留已成交资产和应付权益，恢复原版合法供给；不能清空账户解决问题。

关闭标准：零个人现金场景可以在正常需求恶化前启动第一份合法收入；启用、降级、关停无需逐 Pawn 强制操作且无追溯扣款。无实际物资时允许启动失败，但原因和退出路径明确。

### G02 供给再生产与基础劳动

证据：v0.5 §5/§7 说明机构反馈与实际生产原则，没有确定农作、烹饪、搬运、清洁、维修、药品、库存补货等工作由谁持续承担、何时发薪、产物如何进入服务端。

反例：人人自主求职，但只有衣物工坊合同；食物被吃完、商店不再补货。医生也可能因为服务资格与日程不匹配无法持续提供供给。

建议：先定义首批“供给链责任表”，逐链写明生产者、物资来源、公共/个人/机构归属、搬运与补货职责、完成证据、费用承担。基础劳动可以保留原版公共调度，但要明确其时间如何与个人合同共存；有偿化时逐类适配完成证据，不能统一按站岗或 Job 开始发工资。

用目标库存/服务容量触发有限补货与生产；达到需求覆盖和授权库存目标后暂停新增生产。保留必要应急库存与原版工单设置权，不为发工资而无限制造无用途产品。

关闭标准：连续消费若干周期后仍可在供给与预算允许的情况下补货；没有玩家逐次选搬运者、指定生产者；停产、缺料、损耗、腐败及物流受阻有明确响应。

### G03 机构自主运营与有效劳动合同

证据：v0.5 §1/§6 把招聘/排班列为目标，未冻结机构自运行条件和合同生命周期。当前参考代码的发布岗位、指派医生、搬运入库均仍有手动命令入口，不代表后续自主设计已经闭合。

反例：消费者会预约，但没有合法服务人员；岗位公告仍开放，实际无工单或材料；固定计件合同没有任务范围与承诺量，公共账户持续支付无实际需求的生产。

建议：机构按授权岗位模板自动维护申请、签约、当班、临时暂停、替班、结束与再招聘；发布岗位前检查真实工作机会、岗位时间和有限支付额度。条款包含角色、任务范围、报酬依据、结算时点、有限承诺量、合理退出和不可执行条件。

工坊可先采用有限数量的标准配方加工合同。服务岗位按可验证交付/合法当班义务另设规则，不套用所有 Job ID 都按工件付费。短暂休息或照护不等于恶意违约；机构关闭、长期无工可做及已完成未付分别处理。

关闭标准：在设施和政策一次配置后，自主发布有效机会、招工、履约、补岗、停止无效招聘；资格、资金、班次和基础劳动不会形成互等死锁。

### G04 公共资源、收费权与消费价值

证据：v0.3 §5、v0.5 §7 明确免费替代可见与服务权边界，但未为具体食品/床位/医疗服务给出公共、售卖、预付和私人使用的完整规则。

反例 A：免费与付费食品的品质、时间和可靠性完全相同，付费方案仅增加成本；理性的 Pawn 不会消费，工资循环可能停在储蓄。

反例 B：原版搜索能免费拿走柜台待售食品或使用收费床位，订单系统被绕过。反向把全部公共物品隐藏，又破坏基本自救与原版玩法。

建议：明确每类资产/服务的使用权、付款资格、实际交付与应急例外；只对已登记商业资源实施访问适配。公共保障覆盖有限而真实的基本需求；付费服务的价值来自可观察品质、时间、便利或确定性，不人为降低原版免费物品的数值。免费方案确实同等时就允许选择免费。

关闭标准：付费路径在明确情景下有可解释吸引力；原版行为不能绕过商业交付；公共资源保持可用；不要求人人每周期都必须消费。

### G05 持续支付能力与群体储蓄

证据：v0.5 §10 已声明资金守恒和资金来源原则，但财政回流、机构流动资金、个人储备与有限总货币之间的关系未定。

反例：假设封闭系统共 1000 单位，10 人各积累 100，且其余账户余额为零。资金总额完全守恒，但雇主已无资金支付下一份劳动。该反例不代表真实游戏必然如此，只证明守恒本身不足以保证就业持续。

建议：

- 明确首批资金拓扑：哪些机构与公共账户共用资金，哪些有独立账户，消费款、工资、供货款与补贴如何流动。
- 机构必须有有限支付承诺与流动资金预测，不依赖“事后会有人来消费”发行无限合同。
- 生活成本预测扣除实际公共覆盖；储蓄达到有限水位后停止新增补储目标，但不要求为恢复货币流动强迫消费。
- 对不足的公共/机构支付能力采用明确的预算重分配、有限公共采购或其他已选择的合法财政规则。是否引入税收/发行/对外结算必须选定再适配，不能假设货币自动回流。
- 除货币外检查收入、必要支出与可用工时是否可持续。缺真实产出不能靠账本转账解决。

关闭标准：选择一种明确的首批支付和回流规则；在有限总资金、储备增长、销售停滞、欠薪和需求变化情景下，模型能继续运行或进入清晰、可治理的收缩状态。无须证明所有经济都永不衰退。

### G06 服务合同、效果与收费

证据：v0.3 §7/§9、v0.4 §8 要求交付证据和部分服务规则，但未逐项选择餐饮、床位、医疗、托育/教学的计费与取消方式。现有体检报告不能代替这些合同定义。

反例：治疗后疾病未消失，不代表医生没有交付合格治疗；孩子中途离开课堂，不等于整段教学无价值。若只按 Need 最终满足计费，会拒付真实服务；若按预约或站岗计费，又可刷收入。

建议逐类区分两个终点：**合格服务交付**决定付款；**生活需求改善**决定生活目标是否结束。原版疾病恢复与长期成长具有其他影响，不能要求医生/教师保证最终结果。

每项首批服务定义：付款方、服务对象、服务时段/计量单位、材料、交付事实、合理费用、迟到/缺席、部分交付、取消、退款和服务方无法履约。避免提交/取消之间出现无限免费使用、重复收费或以已付钱为由阻止逃生。

关闭标准：每个进入首批的服务都有一份具体契约，并能解释正常、中断、无效果、部分交付和双方失约时的结果。

### G07 治理行动、人口变化与失败恢复

证据：v0.5 §11 描述结果面板，v0.4 描述退出/重派，但未冻结政策命令与实际效果、预算承担、新人启动、死亡/离图和制度回退的完整玩法。

反例：玩家看到缺医生，却只有逐人指派才能解决；主要照护者离图，孩子目标被暂停但无人接手；居民死亡后付款/床位/服务承诺长期占用，公共预算无法继续周转。

建议为每类主要问题定义“玩家可用的治理动作 → 生效时点 → 真实资源成本 → AI 响应 → 成效指标”：例如开放额外服务时段必须有可用人员，预算转移必须有来源，扩容必须有实际设施。

首批给新人提供明确的合法启动规则；死亡/离图释放未提交短期承诺、重派照护、保留已付事实及应付权益。复杂继承可延期，但无人账户和资产至少有明确的保管/冻结状态及后续处置入口，不能静默删除。制度降级保留原版有效保护路径。

关闭标准：典型问题可以用政策或建设解决，无需逐 Pawn 强制任务；没有资源时明确受阻；人口变化不会形成永久占位或失去责任人的孩子。

## 4. 四项深度与体验问题

| ID | 问题 | 建议补齐 | 是否要求所有复杂扩展先完成 |
|---|---|---|---|
| D01 | 八个风格维度还缺具体输入映射、参数范围和选择差异标准 | 固定首批连续参数、合法范围和少量对照情景；明确原版特质映射为 Mod 规则 | 否，不需要先做完整人格系统 |
| D02 | 已知报价和经历会影响选择，但首次发现机构与更新过期信息未定 | 首批使用合法公共机构公告和有限有效期报价；后期再加询价与关系信息 | 否，不需要全知市场或复杂信息博弈 |
| D03 | 制度阶段具备概念，但开启条件、引导和降级反馈未具体化 | 用供给/人员/预算准备状态与一次性模板引导，失败可撤回；解释玩家下一步可做什么 | 否，不需要无限阶段树 |
| D04 | 中后期职业/经营深度与基础稳定性之间没有明确截断 | 明确第一个可玩的制度集合、事件变化与可选后续；把借贷、投资、复杂继承留后期 | 否，不需要把未来能力都纳入首版 |

这些问题中，参数分布和数值乐趣需原型迭代；进入代码设计前只要求规则范围和对照验证方式明确，不要求提前证明某一套参数已经好玩。

## 5. 四个反例演算的边界

本次附带[反例演算](../04-实装指导手册/evidence/玩法完整度_反例演算.json)，全部采用假设参数：

1. 1000 总货币、10 人各存 100 → 其他账户为 0，证明守恒不能单独保证支付流动性。
2. 每天最多有偿劳动 4 小时、每小时收入 10、必要支出 50 → 每天差额 -10，证明只调整个人执行顺序无法满足此预算。
3. 一名服务者每天能交付 5 单、每天新增 8 单 → 未满足量每天增加 3，证明资金充足也不能消除服务容量不足。
4. 同效果/同时间/同风险的免费与收费方案，所有价格成本权重为正 → 收费方案净评分更低，证明不能仅靠定价制造消费价值。

这些是逻辑反例，不是当前运行轨迹、真实服务速度、游戏参数建议或总体经济仿真。它们要求设计给出处理规则，而非要求任何场景都无条件成功。

## 6. 建议先冻结的可玩范围

首个可玩集合建议为：公共基本保障 + 有偿生产/物流 + 食品与衣物采购 + 有明确边界的居住/医疗服务 + 家庭照护 + 有限储蓄。玩家一次授权机构规则，之后正常日常行为无需逐人强制。

自主企业家、复杂税制、信贷、投资、保险、完整继承和自动城市建设不作为这次玩法完整性的前置条件。它们可以增强深度，但不能替代 G01–G07。

为避免范围继续膨胀，逐项选定“首批完整服务契约”与“保留公共原版机制的服务”。尚未定义契约的服务不能同时宣称全面商业化、自主交付和可计费。生活需求仍可完整观测，不因商业适配延期而消失。

## 7. 进入游戏代码设计文档的准入条件

| 条件 | 当前状态 | 需要的设计成果 |
|---|---|---|
| C01 启动/切换规则固定 | 未满足 | G01 的默认制度、预算、供给和退出规则 |
| C02 供给与组织责任闭合 | 未满足 | G02/G03 的供给链责任、机构状态和有限合同 |
| C03 资源权利与消费价值明确 | 未满足 | G04 的访问/交付规则与公共替代对照场景 |
| C04 资金与时间模型闭合 | 未满足 | G05 的资金拓扑、合法回流和可持续性边界 |
| C05 首批服务与生命周期明确 | 未满足 | G06/G07 的契约、政策命令和人口变化处置 |
| C06 首批范围与参数边界固定 | 未满足 | D01–D04 的范围清单、参数约束和可观察差异 |

准入通过后再编写代码设计：模块边界、事件与调用顺序、游戏/原版适配点、账户和目标 schema、Def/Job/WorkGiver、RUIF 快照与命令、迁移、性能预算和验证矩阵。

代码设计阶段的 API 复核与原型可能暴露新问题，需要反馈玩法规则；这不意味着要求现在先把未来代码实现或实机测试全部完成才允许设计。
