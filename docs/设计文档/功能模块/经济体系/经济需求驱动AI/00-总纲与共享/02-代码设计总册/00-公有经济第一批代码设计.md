## 1. 第一批交付边界

贯通开关 → 实资缴存 → 公有机构有效岗位 → 实际生产/补货 → 需求驱动消费 → 资金回流 → 有限储蓄与补储就业。先实现加工食品/衣物及生产、物流岗位；医疗、居住、托育收费适配分批启用，未完成的服务保留原版公共机制。

不增加私有机构、银行贷款、税制、保险或自动外贸代理。玩家配置机构政策与原版工单，日常招聘、劳动、补货、消费由规则运行；不把手动命令入口当成自主 Job。

## 2. 模块落点与职责

| 模块 | 拟议落点 | 输入与输出 / 约束 |
|---|---|---|
| 设置 | 现有 `ChronicleSettings.cs`、`Settings/SettingsCatalog.cs`、`SettingsDrawer.cs`、`SettingsText.cs` | `EnablePublicEconomy` 布尔值，默认 false，稳定 Scribe 键；追加 SettingId 不重排旧值；RUIF 绘制只修改设置意图 |
| 制度协调 | `Application/PawnEconomy/InstitutionModeService.cs` + 游戏主线程适配器 | 读取开关和存档阶段，输出启动/关停命令；不在 UI Paint 中执行游戏副作用 |
| 公共资金 | `Domain/PawnEconomy/FundingModel.cs`、`Application/PawnEconomy/FundingService.cs` | 实际缴存凭据 → 唯一入账；拨款/工资/消费是账户间转移 |
| 银币保管 | `Economy/PawnEconomy/SettlementReserveAdapter.cs` | 持有真实 Silver 的唯一容器；以现有 ThingOwner 保存模式实现；禁止同时计入普通交易库存 |
| 外贸取证 | `Economy/PawnEconomy/TradeReceiptAdapter.cs` | 候选 TradeDeal 观察补丁 → 待到账贸易凭据；不能直接发币；失败/赠礼/非银币不记净现金 |
| 库存与权限 | 扩展现有库存/产权模块 | 真实批次、用途、机构、数量和流转版本；售出转移给个人；原版使用入口按登记局部过滤 |
| 供给计划 | `Application/PawnEconomy/PublicSupplyPlanner.cs` | 有效订单、库存、原料、授权工单与预算 → 有界工作需求；与车间模块确定唯一计划写入者 |
| 岗位与结算 | 扩展 `EconomyService` 和劳动适配器 | 合同预留 → 实际完成凭据 → 工资；加工和物流分别证据，不统一按 JobID 发所有工资 |
| Pawn 决策 | 扩展 `EconomyRuntime`，分离需求仲裁与行动适配 | 真 Need/家庭事实 → 有限目标/候选 → 一个意图 → 原版 Job；紧急生存不套购物安全门 |
| UI/解释 | 现有 RUIF 设置、机构和个人页 | 只读版本化快照 + 命令；显示余额、占用、应付、需求、预算、库存、缺工和受阻原因 |

现有 `EconomyModel/EconomyService/EconomyRuntime/EconomyCommands/EconomyWorld` 是复用基础，不能整体照搬：首次赠币、共享公账/独立体检账混合、衣物不可负担才找工作、手动补货及通用购物安全门都需要定向调整。

## 3. 持久化对象与不变量

拟议 schema 从当前 v1 向 v2 迁移，保留旧存档读取路径。全局设置只保存能力开关；钱包、机构预算、库存、合同、凭据、迁移状态均存在游戏存档，不放 ModSettings。

| 对象 | 最小字段 |
|---|---|
| `InstitutionModeState` | schemaVersion、阶段 Off/Preparing/Active/Draining、最后应用的设置版本、迁移阶段 |
| `FundingReceipt` | receiptId、来源 Opening/Trade/Additional、实际缴存数量、最小单位金额、保管容器、状态、入账 txId |
| `TradeReceipt` | receiptId、交易上下文、银币实际转移数量、成功标记、到账状态、累计已缴存数量；不能将静态 TradeSession 当存档引用 |
| `InstitutionBudget` | institutionId、cash、reserved、payable、岗位上限、专项上限、policyVersion |
| `WorkCommitment` | contractId、角色、真实任务范围、工资单位、最大量、预留金额、有效时段、状态 |
| `DeliveryEvidence` | evidenceId、工种、执行者、合同、输入/输出批次、实际完成量、完成时点、已结算 txId |
| `ResourceRegistration` | 真实 Thing 引用/稳定身份、批次、机构/个人归属、用途、数量、版本、保管位置 |
| `SupplyDemand` | 订单关联、目标自由库存、出口授权、计划量、在制关联、阻塞原因、版本 |
| `LifeBudget` | 原版事实版本、有限预测期、必要开销、可靠公共覆盖、储蓄上下水位、已承诺费用 |
| `LegacyEntitlement` | 原账户、历史余额/应付、已兑现额、未清算额、迁移凭据；不冒充新缴存 |

金额使用整数最小单位与 checked 运算；交易去重键持久保存，不只驻留内存。实物只由一个 ThingOwner/地图对象序列化，其余用引用或稳定身份，避免 Scribe_Deep 重复保存同一 Thing。

核心不变量：余额非负、预留不超过可用资金、转账借贷相抵、凭据只结算一次、无实物不交付、无缴存不新增货币、同一批产品不重复归属、同一 Pawn 同时一个前台意图、已承诺报价不可追改。新账本总量等于净缴存；历史待清算权益单独报告。

## 4. 事件与调用顺序

1. 主线程接收设置变化/政策命令，更新版本和制度准备状态；校验人员、资金、库存与许可。
2. 观察原版交易完成与实际银币转移，生成来源凭据；银币实际到账后才允许缴存。非交易银币采用明确的期初/追加投入来源。
3. 缴存事务先转移真实银币到保管容器，验证结果，再唯一记账；失败回退实物与预留。游戏存档发生在主线程安全边界，恢复时按持久事务阶段核对。
4. 供给计划处理受影响的库存/订单/预算事件，维护有上限工作需求；不遍历全图反复重建全部计划。
5. 机构在可执行任务和预留工资额度内发布岗位；Pawn 根据生命周期、需求仲裁和储蓄目标申请。
6. 执行原版合法 Job；真实完成适配器生成类型化证据，登记产物/物流，完成工资结算。分阶段劳动分别有完成证据，不等待整季农业结束。
7. 需求调度比较免费替代与合法商品，预留资金/库存/容量，提交单一行动；交付和费用原子结算，使用效果另反馈目标。
8. 缺料、离图、中断或价格变更使相关候选失效；取消未提交承诺，保留已履约部分，退避后重规划；不能在同一 Tick 无限重试。

外贸挂点必须专项原型：`TradeDeal.TryExecute` 执行内会更新/限制交易数量并 Reset。Prefix 只保存上下文不保证最终数量，Postfix 的成功标记不证明款项已入库。需要观测最终实际 Silver 转移并关联成功上下文；当前不指定未经核验的事件或承诺只加一个 Postfix 就完成。

## 5. 设置、UI 与命令

总开关走现有 RUIF 设置系统和 `ChronicleSettings.ExposeData`，稳定键建议 `enablePublicEconomy`。全局设置影响以后载入的存档，当前存档通过协调器应用；存档保存阶段与历史，不再另存一个互相争夺的启用布尔值。重新加载时协调期望开关与存档阶段，不能重复启用赠币。

机构页提供缴存/公共拨款、岗位模板、薪资、产品价格、库存与出口上限、公共保障额度。命令携带 expectedVersion，过期则返回重读提示。显示 cash/reserved/payable/待清算权益，不用单一“资金”数字掩盖不可用余额。

个人页显示“当前缺什么 → 为什么选择工作/消费/免费自救 → 下一次重评条件”，以及生活预测、储蓄目标、实际支出、合同与服务权益。候选解释来自已生成快照，不在绘制时扫图、翻译整个市场或运行决策。

服务能力显示“原版公共 / 准备中 / 可收费运行”；未实现适配的医疗、托育不能因总开关打开就收费。政策涨价与薪资变更仅影响新报价/新合同；正常玩家治理不要求手动分配每个搬运者和医生。

## 6. 实现顺序与验证门槛

| 顺序 | 交付 | 必须验证 |
|---|---|---|
| A0 需求观察 | 原版事实、唯一受益需求、有单位的聚合、RUIF 总览/详情与受阻原因 | 无钱仍有需求、免费生活可见、儿童去重、未知/DLC 状态、窗口版本一致；不依赖收费开启 |
| A 设置与迁移 | RUIF 总开关、存档阶段、历史权益、停止首次赠币 | 新档/旧档/反复开关不重复发币；关闭保留工资与已购物品 |
| B 实资账本 | 银币缴存/保管、独立机构预算、外贸来源凭据 | 失败交易、以物易物、净买入、迟到空投不提前发币；保存重载不重复入账；提取不侵占私人权益 |
| C 再生产 | 食品/衣物加工、物流岗位、实际产物和有限补货 | 零现金入职、无料不招、完成去重、自产归公、搬运不刷薪、缺料/腐败可收缩 |
| D 需求驱动 | 原版 Food/Rest 等读取、有限储蓄、免费比较和单一意图 | 先于破产求职；紧急饥饿不被购物安全门阻塞；储蓄达标不无限劳动 |
| E 服务分批 | 床位、治疗、托育适配分别验证后开放 | 真实服务证据、部分交付、材料费用、逃生、无效果不等于未服务、死亡/离图释放容量 |

性能设计：事件标记脏数据、机构增量更新、Pawn 分散重评、每次限定候选数量和计划量；不承诺全系统零分配。具体 Tick 间隔和批量上限通过当前目标人数的剖析确定，暂不把未经测量的时延写成保证。

自动验证先覆盖账本/凭据/取消与迁移等高风险不变量；游戏内验证覆盖跨入口寻食、床位、医疗、Job 抢占、堆叠、物资损毁、商队/轨道贸易到账。构建和离线测试通过不等于这些游戏验收通过。
