## 1. 目标、范围与交付纪律

目标是使 Pawn 根据真实生活缺口，自主形成生活目标、寻找工作、获得收入、消费产品/服务并维护有限储备；玩家通过公有机构、生产授权、薪资、价格、公共预算及对外贸易治理经济。前端硬依赖 RUIF，行动扩展原版 ThinkTree/Job，不建立第二个抢控制权的调度器。

不纳入本轮既定范围：私营机构、自动外贸、贷款、无限福利、税制、保险、强制劳动和婚姻结果保证。婚姻/育儿只能响应原版实际关系、条件与玩家授权，不能用钱直接修改关系或生育结果。

批次完成必须分别说明代码、离线验证、游戏验收和发布状态。完整功能不得用 DTO、接口占位、模拟成交或静态文档检查充数。新保存字段、付费能力及劳动证据必须有各自验证，不能凭全局总开关推定可用。

## 3. 架构决策与数据边界

本计划作为本次任务 Intake/ADR。适用规则：GOV-001–013、MATRIX-001–010、ARC-001–010、DATA-001、SAVE-001/007、COMP-001、LOC-001、TEST-001、AI-001–010，以及对应 GATE。

依赖为 `Domain 契约/规则 ← Application 协调与查询 ← 游戏适配器/数据宿主/RUIF 表现`。Domain 不引用 Verse、RimWorld、UnityEngine、Harmony 或 RUIF；DLC 专属读法在 Compatibility 层实现端口；UI 仅消费不可变读模型并提交版本化命令。

扩展点选择：纯计算先用领域服务；运行生命周期复用 GameComponent；原版行动使用 ThinkNode_JobGiver/JobDriver；机构数据优先 DefModExtension/Comp。Harmony 只用于原生扩展点无法取得的真实结果证据，逐挂点登记目标、签名、触发时机、可重复性和回滚策略，未验证能力保持关闭。

B1.1 新增纯 Domain 内核及测试；不增 Def、Save、UI、Key、Asset、Harmony、第三方引用或静态可变状态。全部新类型先 internal，不承诺公共 API。无例外申请。后续新增性能热路径、持久化、补丁或公开契约时按本表逐批更新 ADR 和审查结果，既有授权不需要重复询问。

共同不变量沿用总册：稳定需要身份与时间切片分离；未知不等于零；金额为 checked long 最小单位；同一主体一个经济前台租约；M11 唯一资金/权利写入；M6/M7 业务完成不自行重复入账；学习与 UI 不写钱包；事实缓存和派生预算不写存档。

### B1.2 人口、采集与查询

1. Application 定义主线程采集端口、PerceptionCoordinator、PerceptionQuery 及分组年龄契约。
2. 游戏适配器按地图共享目录维护 spawned 与 held 人口；只读采集 Needs、控制、健康、衣着、环境和关系。死亡终止、离图显式 OutOfScope，非成人不被观察过滤。

## 7. B3：生活规划、储蓄与影子决策

M2 先形成生活风格和期限目标；M5 根据同一时间窗量价、实际覆盖及硬预留计算储备；M3 做保护等级/时效/前置 DAG 仲裁；M4 有界比较合法候选。当前余额、未来工资、预算意向与硬预留不得混为现金。

落点分别为 `Planning/`、`Budget/`、`Goals/`、`Actions/` 的 Domain/Application；只读供给通过 Provider。影子报告能说明“想做什么、为什么、需要什么前提”，不准备订单、不占用资源、不 StartJob。

验收：多需求同时出现仍保留原版紧急权；家庭同一受益需要只计一次；储备达到高水位停止补储、跌破低水位才重启；S 未知保持等待；资格费→工作→工资循环依赖被识别并转有限公共资格支持；持有未使用物品先用而非再买；不存在一轮递归规划直到收敛。

## 8. B4：第一条自主经济闭环

范围先食品和衣物，配一个有效公有生产/物流岗位。玩家配置机构政策和实际资金，Pawn 不需要逐人强制求职/下单。

1. M10 仅发布有真实工单、材料、原版许可、开放时段和支付上限的岗位；资格不能一律要求自费体检。
2. M6 固定合同条款和工资上限；原版工单劳动按真实完成阶段取证。同一 Job 多轮配方必须有不同完成序号，Job 结束不等于产出成功。
3. M4 选中后提交 ClaimBundle，票据有 TTL；原版 ThinkTree 自然选择 Job，JobDriver 成功预约后取唯一行动租约。失败释放，不能派等待 Job 占人。
4. M7 真实商品转移、谱系/权属、付款按短事务提交；取得食品/衣物后由原版使用，重新读取 Need/穿戴事实验证结果。
5. 食品首类收费前必须验证原版寻食访问、私人物品、公共保障、保留自然资源与紧急处理；不能只扣钱却允许所有 Pawn 无规则拿走同一商品。未就绪时食品保持 PublicVanilla。
6. 工资只来自公有机构现有资金。未发工资形成唯一应付，岗位按规则收缩；缓冲充足可合法退出，既有应付不消失。
7. 堆叠、拆分、合并、腐败、销毁、搬运、抢夺及读档须维持实物身份，不以 ThingID 永久代表整个变化中的堆叠。

首次整体验收：零现金 Pawn 取得岗位并履约→工资到账→消费→真实使用→缺口回落→达到储备目标后恢复休息/娱乐；停贸、无材料、无岗位、有钱无货、有货无钱及两人抢末件均给出真实受阻原因，既不假成交也不无穷求职。

## 9. B5：家庭与服务分项落地

M8 先建立受益人、监护授权、执行者和付款来源四种身份；默认政策支持合法自主协作，但关系本身不授权扣配偶款。孩子需求只来源于孩子，成人接到的是责任/行动。

服务按以下顺序独立验证：体检→床位→基础诊疗→托育→教育/娱乐登记服务。顺序可按挂点原型结果调整，但每类必须同时具备原版访问、供应方过程、容量/时段、价格上限、实际结算、打断恢复和 RUIF 解释，才从 PublicVanilla 进入收费 Ready。

诊疗按实际过程/材料结算，不按治愈承诺收费；体检只报告实际可见事实；床位不直接写 Rest；照护/教学遵循原版年龄、许可和真实过程。紧急公共保障消耗有限预算或已授权库存，记公共成本，不记患者债或虚假销售收入。

验收覆盖抱持/交接、家长征召、照护中断、服务人员离岗/死亡、儿童成长、公共资金不足、父母分别付款授权、多人共享教学与一对一喂养容量区别。

## 10. B6：机构再生产与有限学习

M10 接入十二类机构工具模板，可复用建筑/组件而非强制十二座新建筑。真实订单、授权出口、可用库存、可完工在制及未开工授权量共同决定新增生产量；同一产出和同一订单不得重复计入。

关键补货式：`max(0, 已确认未交付需求 + 自由库存目标 + 已授权未交付出口总量 - 可用库存 - 可完成在制 - 已授权未开工量)`。开始生产时 U→W，完工 W→库存，交付同时消耗库存并减少相应未交付需求。车间现有执行器仍为工单/排班唯一执行者。

M9 记录实际到账、交付、耗时和失败原因，有限更新工资可信度与服务预期；去重、退避和生命周期恢复独立于学习。裁剪经验不得裁剪财务防重凭据；普通重试不阻止紧急处理。停贸/缺材料可以形成可解释收缩，不能靠强制消费或增加虚拟货币维持表面循环。

验收覆盖授权后尚未开工反复评估不追加同量、生产中断与恢复、机构关闭、供给瘫痪、同一通知重复到达、有界历史裁剪后仍不重复付款。
