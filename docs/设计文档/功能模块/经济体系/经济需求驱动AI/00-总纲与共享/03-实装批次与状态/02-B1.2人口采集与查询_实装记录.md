# B1.2 人口采集与查询：实施记录

Change ID：`CHG-20261008-ECON-PERCEPTION`。授权：用户“继续实装”，沿[实装计划](00-实装落地计划_v1.0.md)继续 B1.2。本记录在编码前建立 Intake/ADR，以下结果为完成后补充的实际证据。

## 1. Intake / ADR

目标：真实地图殖民者人口（含儿童、抱持、倒地、征召），原版 Needs、控制、可见身体/生活条件/关系采集；主线程分组调度、会话隔离及只读新鲜度查询；收费关闭仍观察。非目标：新求职/消费/账本迁移、收费服务和 B1.3 RUIF 新页面。

边界：新增 Domain 不可变事实/查询契约；Application 协调器通过采集端口访问游戏适配器；复用现有经济 GameComponent；Biotech 需要和可见怀孕读法隔离在 Compatibility/Dlc。UI 后续仅消费 Query，不获取 Pawn/Need/Hediff 或可变账户。

新增 Runtime/缓存，修改既有宿主生命周期；无 Def、Save schema、UI、Key、Asset、Harmony 或新第三方依赖。缓存不保存，PostLoadInit 丢弃，FinalizeInit 后按新会话重建；未知/缺失数据显式分组状态，旧档持久数据不改。无新的静态可变状态。架构审查适用：新增契约与 Tick 路径；采用 GameComponent + Service/Provider 原生扩展，不需要补丁。

规则：GOV-001/003/005/008/011/013、MATRIX-001–010、ARC-002/003/005/008/010、SAVE-001/007、COMP-001、TEST-001、AI-001–010。八种基础 Need 与 Mood 依据本机 NeedDefs/当前 DLL；Play/Learning 仅由 Biotech 适配注册。未核验第三方子类不按原版兼容；所有列表有容量和截断说明。

调度：快组 Context/Needs 150 Tick、Body 250、Relationships 600、人口目录 600 为命名的原型配置。每 Tick 至多采集 8 人且以软耗时预算在工作单元之间检查；人口扫描每次只处理一张地图，使用地图现有共享索引，不逐 Pawn 扫地图。不可中断单个第三方 getter，诊断保留耗时/超限/积压。紧急原版行动不等待这些采样。

验证计划：纯协调器 fake source 测试、实际 Need 对象的离线读数测试、只读账本不创建记录/不泄露可变对象、主工程构建、经济相关测试与全工程回归；保存测试确认新增缓存不进入旧保存格式。游戏内人口、持有、时序、性能和界面仍须实机验收，未执行不标通过。

## 2. 实现与验收证据

已接入运行宿主，完成代码与离线验收；尚未部署或进行游戏进程验收。当前状态 `CodeVerified`，不是完整 M1/M12 完成。[机器证据](B1.2_实装验证.json)由 `_scripts/verify-pawn-perception.ps1` 针对实际 DLL、源码和最终 TRX 生成。

| 项目 | 实际行为 |
|---|---|
| 人口目录 | 每次人口周期逐地图处理，一次最多一张；读取 FreeColonists 后即时复制需要的 ID/引用，并用 IsFreeNonSlaveColonist、Humanlike、非任务访客筛选；不按年龄/征召/倒地排除。人口列表跨图非原子，末尾复核已知主体的实际 MapHeld |
| 快组 | 原版八种基础 Need，加 Biotech Play/Learning 的精确类型适配；Mood 单独作为结果。单次取得 AllNeeds，原始量、MaxLevel、原版类别、未知冻结分别保留；第三方类型/被修改的 NeedDef 明确未支持 |
| 慢身体/生活组 | 只读取可见 Hediff、严重度/可治疗事实，实际穿戴/耐久，温度/舒适温区，已分配/当前床位，以及 Beauty/Comfort/RoomSize 瞬时条件。集合分别带采集状态，截断不算确认不存在 |
| 关系组 | 原版直接关系 Def、对方稳定 ID、起始 Tick；不创建监护、扣款或婚姻目标。可见怀孕仅为可见事实，由 Biotech 适配读取，不揭示隐藏病症 |
| 调度 | 每 Pawn 一个到期条目，按最早到期/稳定 ID 处理，重复标脏合并；默认最多 8 人/Tick、2ms 软预算，在不可分工作单元之间检查；周期分散相位，普通采样不会被持续标脏流量无限饿死 |
| 生命周期 | 新 GameComponent/读档/时间回退生成新的正会话 nonce；PostLoadInit 清缓存并取消旧初始化 token；FinalizeInit 排队到加载完成后，核对主线程、token 和所属 Game 才构造，首 Tick 有兜底；死亡/离图释放引用，仅留有界标量历史；重入不复用旧慢组 |
| 查询 | 返回组状态、独立年龄、原因和必需组是否可用；陈旧、部分、加载和范围不同。查询不采集、不创建账户、不发钱；缺口查询同时保留事实新鲜度/范围，不将百分比当行动权限 |
| 账本只读面 | 无记录返回 Unknown(NotEnrolled)；已有账户/人物返回不可变副本，明确旧账余额不是实物储备验证；M11 实资与迁移仍在 B2 |
| 宿主 | GameComponentTick 首先执行 TickPerception，再判断旧经济 Enabled/Ready；不依赖窗口和收费开关；旧 AI/Job/交易路径本批未接管 |

数值校验沿用 B1.1。Body 不同集合缺失保留 Unknown/Partial，温度/耐久/严重度的非有限值不成为有效事实。抱持者的地图/位置来自 MapHeld/PositionHeld；其容器温度和当前床位无法确认时 Unknown，不假定与所在地图地面条件一致。

线程检查约束协调、查询、主体目录及诊断读取只能在拥有线程调用。原版 Root_Play 通过异步 LongEvent 初始化/加载，不能在 FinalizeInit 当场绑定拥有线程；本批改用 ExecuteWhenFinished，并显式检查 UnityData.IsInMainThread，过期 token/旧 Game 回调不构造新缓存。构造失败只记录错误，本会话不每 Tick 重试。初始化本身不采集，暂停时仍可能 Loading，直到游戏 Tick 推进；读取页面不会触发补采。延迟初始化的当前编译 IL 已核验，真实读档线程时序仍列为待实机验证。
