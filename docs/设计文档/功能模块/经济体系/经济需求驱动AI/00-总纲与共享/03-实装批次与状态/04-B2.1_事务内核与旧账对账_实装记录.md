Change ID：`CHG-20261008-ECON-FINANCE-CORE`。授权：用户“批准继续”，推进 B2。

## 1. Intake / ADR（编码前）

目标：实装可离线验证的整数货币、多账户原子资金预占、资源 ClaimBundle、版本/期限/幂等与双分录转账算法；生成 schema=1 旧账的不可变只读对账报告。此批为 B2.1，不把整个 B2 标成完成。

选型：Domain 仅放不可变契约、整数换算；Application 放单线程影子事务内核及旧账读取器。事务内核只消费显式输入的影子余额快照，不接受 OpeningBudget、存款或提款命令，不连接游戏消费；其 BackingVerified/CanExecuteInGame 恒 false。它是交易算法的可执行原型，不能作为实资账本使用。重复 ID 保留终态，不按历史长度删除；达到容量拒绝新准备，不影响已有事务收尾。提交要求非空证据标识，但标识不代替实际履约验证。

Prepare 对所有借方可用资金、贷方上限及独占资源一次校验，全成或全败。预占按总借方计算，不能用同一束未来收入垫付；冻结的账户金额与资源随提交/取消/到期一起释放。失效命令不得静默延长期限；版本不符拒绝；同 ID 不同内容拒绝；证据 ID 不可被不同提交复用。实例绑定创建线程，不引入静态可变状态或外部回调。

旧账报告逐条复制全部九类已知记录的字段及身份、集合和元信息，保留原数值；问题单独列出，不把损坏值修正为零。余额、预占、待付工资、OpeningAllocation 分列，后者绝不视为实物储备。只读报告是调用时当前 legacy revision 的观察，不声称保留读档恢复前的原始权益（旧 RecoverAfterLoad 会取消待办）。完整存档原文备份与显式迁移映射归 B2.3。

边界：无 UI/本地化/Def/Asset/Harmony/Save/设置变更，不改旧经济服务，不接入新支付路由。RUIF 界面沿用 B1.3，B2.1 不新建其他前端。遵守 GOV/MATRIX/ARC、AI-001–010、DL-1/2、SAVE-001/007；只做新增纯内核与主线程只读查询。全局 GATE-DELTA 脚本缺失时仅报告 scoped gate。

验证计划：整数边界、原子失败、并发需求的共享余额与资源冲突、重复/冲突命令、陈旧版本、TTL 与时钟回退、取消和重复提交、证据冲突、不可变快照、满容量收尾、跨线程拒绝、累计金额守恒；旧账全部字段保留、损坏/未来 schema、预占差额及未付工资、OpeningAllocation 分离。Release 构建、定向及全工程测试；程序集纯层与无运行路由检查。离线测试不替代真实银币/存档/实机验收。

## 3. 已实装行为与调用约定

| 模块 | 已有行为 | 边界 |
|---|---|---|
| MinorCurrency | checked long、1:100、整数可取部分和余数、每账户/单笔上限 10^12 最小单位 | 只是换算，不生成 Thing 或发币 |
| FinancialIntent / AccountSnapshot | 不可变账户、双边分录、有界腿数/资源数、稳定命令 ID、预期版本、ExpiresTick | 不推定主体权限或设施存在；独占键由后续资源适配器提供 |
| ShadowTransactionKernel.Prepare | 总借方预占、独占键、贷方余额空间同步校验；全束成功才改变状态 | 不允许用同束预期收入垫付借方；贷方不以尚未提交的流出抵减空间，属于保守防溢出策略 |
| Commit / Cancel / Expire | 双边金额守恒；释放本束资金/贷方空间/资源；保留外来预占；TTL 左闭右开 | Commit 仅模拟账面；没有实际履约核验、实物交付或 Applied/Finalized 持久阶段 |
| 命令/证据防重 | 相同命令内容返回已有阶段；不同内容拒绝；同证据不复用；终态不可反向取消 | Replay 是返回原命令结果，必须检查 Transaction.Phase；不是重新授予行动权限。ID 仅在当前实例生命周期保留，跨存档防重归 B2.3 |
| 版本/时钟/容量 | 全局单调版本；拒绝陈旧新写入和时钟回退；默认 4096 命令，上限 100000；满容量可收尾 | 版本不是各账户独立版本；重载时钟/持久恢复尚未接入；无历史裁剪换取重复执行机会 |
| LegacyReconciler.Capture | 九类记录身份/全部公共持久字段、列表及元信息复制；InvariantCulture/float R 文本；不开户、不恢复、不修账 | 财务/身份检查不是完整业务引用或产权验证；未知版本字段原文尚不在此报告内 |
| 旧账诊断 | 余额与预占、持款订单、未付 Wage、OpeningAllocation、Committed 订单金额分列；无效/重复 ID、账户/订单金额、订单参与者、缺少付款人、预占不符等问题 | 已完成订单金额不是“尚未使用资产金额”；应付服务、合同和已付未用资产仍保留在原字段行中，不合并成现金 |
| 运行查询 | GameComponent 的 QueryLegacyReconciliation，主线程生成不可变报告 | 未加入 UI，也未改设置/旧服务/加载；当前旧账可能已被旧 RecoverAfterLoad 改写 |

实例上限 4096 账户，每束 64 条分录、64 独占键；旧账报告最多复制 100000 条记录，超过显式 Truncated/RecordLimit，合计只覆盖已复制行。读取不推进 TTL；游戏适配器未来必须在安全阶段调用 Expire。资源不存在、权限、库存数量、排期重叠、服务完成、Silver 谱系均未在字符串资源键/证据 ID 中自动证明。

入口（以源码 API 为准）：构造影子内核 → Prepare(intent, now) → 按当前 Version 提交/取消 → 定期 Expire(now) → ReadAccounts/ReadTransaction；快照均不可变，实例严格绑定创建线程。没有 Account 查询自动注册、Enable、Deposit、Withdraw 或调用旧 OpeningBudget 的入口。此内核运行能力恒 false，禁止用于真实支付。
