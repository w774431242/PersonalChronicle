# B2.2 实物银币储备原型：实施记录

Change ID：`CHG-20261008-ECON-SILVER-RESERVE`。授权：用户“批准继续”。

## 1. Intake / ADR（编码前）

目标：用真实 Verse.ThingOwner 和 Silver Thing 验证独立实物储备、单堆缴存/提取、两端数量证据、异常隔离及独立 Scribe 保存往返。禁止仅按转移返回值入账，禁止从旧余额或开局分配反造银币。

选型：Domain/Finance 增加纯数量规则、移动意图/证据与储备审计快照；Data/PawnEconomy 保存独立原型 journal 的版本化原文；Economy/PawnEconomy 增加无地图父级的 IThingHolder + IExposable 原型。无新 Def、建筑、UI、Key、Asset、运行补丁或静态可变业务状态。RUIF 硬依赖沿用。本批不挂到 GameComponent，不提供游戏命令入口、不改设置或旧账；B2.3 再装配整个存档与活动账本，B2.4 再接管路由。

原型内每条命令只处理一个实际银币堆、禁止合堆，保留源/结果 ID 和两端增减。货币换算和公有可用资金提款上限为纯规则，不是付款授权；原型 CanExecuteInGame 恒 false。地上银币应先由后续搬运 Job 实际交到容器，本批不远程取走地图资源。容量受限，主线程/重入保护；保存中、加载未完成或有不明证据拒绝新移动。

隔离依据：当前原版轨道贸易扫描信标格内 Thing 及特定书架/基因库/运输容器，地面贸易扫描 map.listerThings 和建筑 IHaulSource，搬运扫描 map.listerHaulables。本储备不是 Thing/Building/IHaulSource，不注册地图、货仓或远行队，也不添加父 Holder。该结论仅限当前原版路径；第三方全递归扫描仍需 B2.4 兼容准入和实机核验，不能据此标 Active。

适用规则：GOV/MATRIX/ARC、AI-001–010、DATA-001/004/006/008、SAVE、TEST/REL。真实游戏 API 封装在适配层；Domain 不含 Verse/RimWorld/UI。测试可使用既有 Harmony 离线日志/Profiler 及 Find.UniqueIDsManager 宿主垫片，不改动 SplitOff、TryTransferToContainer、TryAdd、Destroy 或 Scribe 核心方法。

## 2. 保存契约（编码前）

这是独立原型 schema=1，不更改既有 `pawnEconomicInstitutions`，不声称已实现 v2 游戏账本。固定 wire 为 `silver`（ThingOwner Deep）与 `metadata`（XML 原文字符串）。metadata 含 schema、version、fault 和完整命令 journal；所有金额来自已完成移动的实物数量，无开局资金字段。

旧/缺失 metadata 与空容器：初始化为零；缺失 metadata 而实际有银币：报未登记盈余并隔离，绝不认作存款。未知未来 schema / 损坏 XML：保留 metadata 原文再保存，拒绝写入；实物容器照常保存，不重新解释为账户余额。已知 schema journal 校验 ID 唯一、版本、数量、方向、阶段及两端证据；Prepared 或 ReconciliationRequired 不自动重做/冲销，拒绝新移动，等待 B2.3 明确恢复。

Scribe 加载结束重新建立 ThingOwner 的 owner/holdingOwner；不把运行缓存、线程 ID、反重入锁或 UI 存档。命令 ID 和终态证据跨独立保存保留，不裁剪。重复命令需原内容一致，只返回历史证据；不能再次移动。储备数量与 journal 净缴存有差额时报告缺口/盈余并拒绝新移动，不改写历史、不造币补平。

验证计划：真实 ThingOwner 分堆/整堆/单堆提款、重复/冲突/版本/容量、非银币/自转移/错误持有者、零头规则、拒收/部分移动/回调抛错/重入、毁损与未登记增减、Scribe 往返及身份/所属恢复、未来/损坏/缺失 metadata 原文保留、未完成阶段加载不重放；当前 DLL 与源码隔离依据、定向/全工程回归。无实机或完整旧游戏档验收时明确标未执行。

## 3. 本批已实装

| 模块 | 行为 | 限制 |
|---|---|---|
| ReserveMovementIntent / Evidence | 不可变命令 ID、方向、原版本、对方 ID、源堆 ID、数量；保存 Prepared/Completed/ReconciliationRequired 和两端前后数量、返回值、结果 ID、错误 | CompletedMinor 是数量凭据金额，不是已入账余额或真实履约凭据 |
| SettlementReservePrototype | 内部 IThingHolder；ParentHolder=null、无地图注册、非 Building/Thing/IHaulSource；只接受 DefOf.Silver | 尚未装配 GameComponent 或建筑；没有玩家入口，不能在游戏中使用；CanExecuteInGame=false |
| Execute | 从实际持有容器选定一个银币堆，禁止合堆，使用原版 TryTransferToContainer；两端精确增减、结果实际持有关系及数量吻合才 Completed | 不处理地上直接缴存、多堆原子提取、原版预约或账户权利；这些不能由字符串 ID 代替 |
| 数量审计 | 实物数量与已完成 journal 的净缴存分列；未知/无效所属不显示为零；缺口、盈余不补平 | 净缴存不是账户负债总额；需要 B2.3 对接真实账本才能证明足额支持 |
| 提款数量规则 | requested ≤ 公有可用金额；1 银币=100 最小单位，向下取整、账户余数不丢；全程 long | 只证明整数运算，不是公有资金授权；返回数量可能超过 int，后续必须按实际堆显式分批，不能窄化强转 |
| 主线程/重入/容量 | 绑定创建线程；回调中重入返回 Busy，Scribe 非 Inactive 拒绝命令；命令上限 4096，不裁剪终态；存取中拒绝保存 | 不承诺所有第三方回调安全；异常以不明阶段和实际数量保留，后续命令停止 |
| 独立 Scribe | Deep 保存银币，XML metadata 保存全部证据；读回 ID、owner/holdingOwner 和防重状态；缺失/损坏/未来 schema 保守隔离 | 是独立原型保存往返，不是游戏 v2 完整保存或旧整局迁移；不修改旧存档段 |

存取失败的处理区别：普通预检查拒收不写 journal、不移动；已开始调用后出现异常、数量/结果所属不符则记 ReconciliationRequired，不假定成功、失败或自动退款。整堆 SplitOff 可能在源移除回调抛错时留下无主持有的已知源对象：本批将它保全到隔离的储备容器并保存 ID，错误记 DetachedSourceSafeguarded，不给 CompletedMinor 或存款额度；这是实物保全，不是财务回滚或恢复授权。历史重复命令返回 Replay 与原 Phase，包括不明阶段；调用方必须检查 Phase，不能凭 Replay 再发币。原版 IThingHolder 接口会暴露底层容器，直接外部增删仍可能发生，本批通过数量审计隔离，不宣称阻止任意第三方作弊或直接引用修改。第三方重写 SplitOff/TryAdd 并在内部创建其他孤立对象的行为未验证。

持有者验证要求对方是其 owner.GetDirectlyHeldThings 返回的规范容器，沿 ParentHolder 有界追溯至首个 ILoadReferenceable ID，并拒绝储备嵌套、自转移、循环/过深链或 Map 直接容器。正常 Pawn 随身/搬运容器仍须 B2.3/B2.4 的权限、到达和预约门禁；本批不能从 ID 推导拥有支付权。
