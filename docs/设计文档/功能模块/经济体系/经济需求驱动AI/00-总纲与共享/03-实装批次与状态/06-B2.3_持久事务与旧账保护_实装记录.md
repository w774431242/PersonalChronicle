# B2.3 持久事务与旧账保护

Change ID：CHG-20261008-ECON-PERSISTENCE。状态：CodeVerified（离线），未部署、未实机验收。

## 1. Intake 与 Architecture Review

目标：把实物储备与新资金账本保存到 GameComponent 的同一旁路宿主；持久保存完整命令身份、阶段和消费防重；在旧 RecoverAfterLoad 之前保存旧 payload 原文；提供有实际资金约束的显式旧权益承接。

边界：本批无设置、UI、搬运 Job、自动薪资/消费接管，无新 Def/Asset/Key、运行时 Harmony、第三方引用或静态可变状态。RUIF 硬依赖保持。新宿主不授予制度 Active，旧系统仍运行；归档权益与旧系统当前账本必须区分，B2.4 停止旧通道并再次对账之前，不得把归档权益当成最终切换结算单。

依赖：Domain 契约 → Application 资金规则；Data 编解码/旧账归档；Economy 适配实际 ThingOwner 与 Scribe。选用既有 GameComponent + IExposable/Service，不需要 Def/Comp/Patch。适用 MATRIX-001/002/006、DATA-001/006/008/010、SAVE-001～007、AI-001～009。新增持久契约，进入 Architecture/Save Review；采用旁路 wire 保持旧格式，未需新增例外。

## 2. Save Review / ADR

- 原 `pawnEconomicInstitutions/payload` schema 1 不重命名；新增 `pawnEconomicSettlement` 宿主，metadata schema 1 保存完整命令/阶段/归档指纹；独立字段保存首次旧账原文与其来源标识，另 Deep 保存 reserve（沿用 B2.2 schema 1）。metadata 与旧原文使用 `base64-utf8-v1` 文本 wire，并各自保存 encoding；缺失 encoding 兼容直接文本，未知/坏 encoding 原 wire 保留且冻结。
- 缺失旁路宿主：空储备、空账本、零资金、无自动启用。首次读取旧档在旧恢复前归档原始 payload；没有旧 payload 则归档空值，不能用恢复后的重新编码冒充原文。新游戏首次保存时可标记为 FirstSaveSnapshot，不能声称是旧档加载前原文。
- 不支持/损坏/未知字段或枚举：保存原 metadata，冻结新写入；旧归档原文独立存于宿主字段，未来/损坏旧 payload 不自动承接。储备容器仍按原版 Deep 保存，不能清空来消除错误。
- 命令 ID/完整请求与终态永久保留，上限 4096，满额拒绝新命令而允许已准备命令完成。账本版本为命令序号；每次只允许一个未完成命令，准备提取先锁定国库金额，禁止花费将来收入。
- 存款：账本 Prepared → 实物转移与两端证明 → 消费同 ID/同完整请求的 Completed 证明 → 国库唯一发行 → Finalized。提取：先锁国库 → 实物交付证明 → 扣减 → Finalized。拒收/前置失败取消自身锁；数量/所有者不明时保持权益及锁并冻结，不自动重试或猜测补偿。
- 恢复：已完成实物、账本 Prepared 可凭匹配证明幂等入账；无实物 journal 的 Prepared 取消并保留 ID；不明实物阶段冻结。账本终态与实物 journal 一一核验，孤立证明、正文冲突、余额/储备净额不符均冻结；不凭完成标记造币。
- 旧权益：原始九类记录完整保留。仅可识别、诊断通过的余额和未付工资形成有上限的货币承接项；OpeningAllocation 不构成存款。显式承接从已入账国库转给指定新账户，记录原记录 ID、金额、目标；同一权益不能重复超额承接或改换目标。订单/合同/已付未用资产/所有权仍留在归档，不以新货币伪装完成；B2.4 才允许最终互斥切换。
- 不改旧身份/字段，不提供降级到旧版的自动写回。回滚前应备份含新宿主的存档；旧版无法恢复旁路储备，禁止把含实际银币的新档直接降级覆盖保存。

验证矩阵：零资金/空旧档；真实 ThingOwner 存取与完整宿主 Scribe 往返；重复命令/正文冲突/版本/余额/容量；Prepared 切点/不明阶段/毁损与孤立证明；原始旧订单预留、欠薪和已付未用资产保留；承接不超资金/不超权益；未来/损坏/未知字段原文往返；GameComponent 旧恢复顺序；全量回归与当前程序集指纹。离线宿主沿用 B2.2 测试垫片，实机保存、贸易和搬运尚待验收。

## 3. 实装与验证

| 层 | 实装 | 边界 |
|---|---|---|
| Domain | SettlementIntent/Entry/Result/Audit、LegacyCashClaim | 完整请求、不可变快照、未知负债为 null，不冒充零 |
| Application | FundedSettlementLedger | 零余额起步；实物证明消费；国库提取锁；完整 ID 永久保留；上限 4096；显式金额承接转账 |
| Data | SettlementLedgerCodec、LegacySettlementArchive | 严格 schema/字段/阶段/顺序/资金重放校验；旧九类记录原文、指纹和只读报告；未知旧字段不自动承接 |
| Economy | PawnSettlementSaveHost + GameComponent 挂接 | 新旧 wire 并存；原文先归档再旧恢复；Scribe inactive 后才恢复；挂接保存不代表支付就绪 |
| 既有储备 | 只读完整 journal、宿主生命周期线程交接 | 仍不生产银币、不调用旧账户/影子账；不公开付款入口 |

新账总额只随实际存款/提取变化。显式承接仅从 Treasury 转移已存在余额，不会增加总额；余额含旧订单预留的事实保留在原文，未以订单再造一份货币权益。余额项和欠薪项各引用原记录 ID/归档 hash，部分承接保留剩余金额，同项不得换目标、超额或重复。非货币权益保留在归档，不能因资金承接成功而声称已完成订单/合同/资产迁移。

加载/保存可能由 long-event worker 执行：只有宿主的串行 Scribe 生命周期边界与显式主线程绑定允许转交线程所有权，普通查询/命令仍拒绝跨线程。FinalizeInit 仅在主线程且 Scribe inactive 时绑定；首个主线程 Tick 可补做。储备转移或结算 busy 时禁止重入保存与线程交接，不允许跨线程并发付款。主线程稳定后的每 Tick 只有无分配门禁检查，不重扫账本/旧档；无实测性能承诺。

## 4. 保存恢复与原版依据

原版依据为本机 `Assembly-CSharp.dll`（指纹和版本在机器证据）。本批直接反编译核对 `ScribeSaver.InitSaving/WriteElement`、`ScribeExtractor.ValueFromNode`、`Scribe_Values.Look` 和 `GenTypes.GetTypeInAnyAssembly/ClearCache`。原版 XmlWriter 默认换行替换会影响内嵌原始字符串；采用带版本的 UTF-8/Base64 wire，保留首次由 Scribe 读取到的旧 payload 字符串，包括混合 LF/CR/CRLF、中文和未知内容。它不是整个原游戏存档文件的字节备份；旧 payload 进入 Scribe 之前的外层 XML 编码转换不在本契约内。

恢复切点：

1. 账本 Prepared、实物 journal 缺失：取消自身准备，释放自身资金锁，保留 ID，不再移动物品。
2. 账本 Prepared、同正文实物 Completed：校验全局绑定后一次入账/扣款，后续恢复返回终态。
3. 实物 Prepared/ReconciliationRequired：不猜测成功或自动补发；保留余额、提取锁和实物，冻结。
4. 孤立实物证明、正文冲突、Finalized 缺少证明、旧权益超额/映射冲突：冻结，不把旁路问题修成新货币。
5. 实物毁损：保留负债，报告 deficit；未知/坏元数据则负债未知，保留原文与实际物品。

该 journal 是随游戏保存的恢复协议，不是每个阶段独立写入磁盘的数据库 WAL；保存失败/游戏崩溃回到最后成功存档，不承诺恢复未保存的内存交易。转移进行中保存被拒绝。实际完整 Game 根保存、跨地图/远行队和第三方自定义容器仍须实机验证。
