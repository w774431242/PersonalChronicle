# B2.4.1 制度设置与互斥门禁

Change ID：CHG-20261008-ECON-MODE-GATES。状态：CodeVerified（代码与离线验证）；B2.4 整批 InProgress，未部署、未实机验收。

## 1. Intake / Architecture Review

目标：唯一、默认关闭的 RUIF Mod 设置；Off/Preparing/Active/Draining/Faulted 纯状态机；阶段保存；在旧系统首次被接管时冻结最新账本，连同 B2.3 原始归档保全；封闭旧开关、发薪、结算、预约/订单及加载取消等写入，避免两套账同时运行。

本子批不新增实际缴存/提取 Job，不宣称 Active 可用；B2.4.2 补实物预约/交付、授权与最终权益逐项承接。实际游戏 readiness 明确缺失，开关开启只进入 Preparing，关闭有未承接权益时进入 Draining。B2.4 不得因本子批通过而整体 CodeVerified。

依赖：Domain 状态/只读 DTO → Application 状态推进 → Data 保存/快照 → GameComponent 装配 → RUIF 设置/查询。选择原有 ModSettings、GameComponent、Service，无新 Def/资产/Harmony/第三方依赖/静态可变业务状态。新增 Save/UI/双语 Key，触发 Architecture、Save、Localization Review；适用 MATRIX-001/002/003/006、DATA-001/008/010、SAVE-001～007、UI-001～009、LOC、AI-001～009。

## 2. Save Review / ADR

- 原旧账与 B2.3 保存 wire 保留；新增 `pawnEconomicMode` schema 1，版本化 Base64 UTF-8 payload 保存请求值、阶段、修订、首次冻结的最新旧账、原始归档 hash 与新账版本。缺失该宿主默认 Off、false、未冻结、零新资金。
- 唯一设置为 `enablePawnEconomicInstitution`，默认 false；旧 State.Enabled 只作为历史记录，旧页面 Enable 命令退役，不能再触发 OpeningBudget。设置是意图，阶段/能力是每局状态，开关 true 不等于 Active。
- 旧 GameComponent RecoverAfterLoad 的自动取消在运行接入处退役，仍保留旧 Service 作为参考/离线兼容测试；当前旧订单、预留、欠薪、合同、所有权不再因加载/旧 Job finish/机构消失被自动改写。旧制度付费行为全部关闭，原版免费行为与需求观察继续。
- 旧经济排班槽保留数据但暂停参与排班和运行名册，防止停止发薪后继续按旧合同安排工作；普通玩家排班不变。已付衣物可通过无收费的权属检查继续使用，不把使用动作当购买或迁移完成；冻结后的历史账字段不随穿戴重写。
- 首次请求启用时，在任何新承诺前固定最新旧账；与 B2.3 首次加载原文分别保存，不覆盖其中之一。记录已存在的新账金额承接，不将旧已付工资/余额变化自动并入新余额；仍需 B2.4.2 明确核对差异与非货币权益。
- 已加载 Active 必须退回 Preparing 后重新验证实际能力；未知/坏 schema/字段/枚举/编码原文保留、Faulted、所有付费路由关闭。设置切换不能清除 Faulted。Loaded Draining 保留待处理权益，不因关开设置跳过清理。
- Draining 只停止新承诺；没有明确完成证据不能减少负债/权益或关闭账本。原版行为不因等待对账而停摆。已有储备/新负债/不明事务/未承接旧权益均保留；当前无真实清理执行器时显示等待，不伪造完成。
- 恢复与保存不依赖打开 UI；Tick/设置变更推动，暂停中点击设置也立即更新阶段。查询只返回状态，不开户、不付款；Settings 页唯一开关，经济页只显示状态/阻塞及 Mod 设置指引。
- 旧→新无身份重命名；重复启用/读档不追加冻结快照或发币。回滚不得让旧版本覆盖含旁路实物的存档；旧经济暂停属明确行为变化，写 Changelog Breaking。

验证：状态转换、所有能力齐备的纯夹具/实际适配未齐、撤销与 Draining、Faulted 不绕过；设置默认/保存；原始与最终快照独立/幂等/未知原文；Loaded Active 重验；旧加载不取消、旧开关不发币、旧 finish/发薪/配置不写账；已付衣物访问与旧经济槽暂停、普通槽不变；双语键/ RUIF 结构与全量回归。实机布局、暂停/读档、预约/交付及最终 Active 尚待后续验收。

### 3.2 Breaking 与保护策略

旧经济收费系统即使历史 `State.Enabled=true` 也暂停，包括旧发薪、收费、合同派工和自动取消。加载后不会继续旧页面开关的行为；玩家原版需求行为和只读观察继续。旧账中的余额、预留、欠薪、合同、订单、所有权和已付未用资产不会被清零或静默转换。原始归档和切换快照独立保留，前者不能替代后者。

当前 Draining 没有清理执行器，不凭切换按钮宣告清理完成。Faulted 原文/实物保留且不可用开关解除。模式 schema 1 新增旁路键、旧键保留；涉及新储备的存档不能交给不认识旁路的旧版本覆盖保存。
