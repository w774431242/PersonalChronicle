# B2.4.2 真实交付与权益承接

Change ID：CHG-20261008-ECON-DELIVERY。状态：CodeVerified（代码及离线验证）；B2.4 整批仍 InProgress。完整准备资金操作与最终旧权益接管单元已接入，未部署、未实机验收。

## 1. Intake / Architecture Review

依赖：Domain 交付订单/权益 DTO → Application 纯对账规则 → Data 版本化控制记录 → GameComponent 授权及原版 Job/ThingOwner 适配 → RUIF 查询和指令。采用原生 JobDef、JobDriver、ThinkNode 已有入口、ReservationManager、CarryTracker、ThingOwner、Scribe；不新增 Harmony、第三方依赖或静态可变业务状态。原版 API 以本地 1.6 DLL 签名/反编译为准。

范围：公有结算处的玩家资金准备指令，Pawn 在原有安全决策窗口自动执行搬运；一次仅一个未终结请求，提取先锁实资国库资金，实际两端数量/所属证明才入账。保存请求身份、原始来源、搬运中来源、预期版本与终态；重复完成不再次搬运/入账；取消释放未经实物交付的资金锁，未知实物结果进入对账。原版征召、玩家强制、饥饿/疲劳/医疗/火灾优先。

旧权益：同时对比原始归档与最终冻结旧账，记录差异；已承接金额按原记录身份关联，剩余额度由最终旧账限定。最新债权使用真实 Treasury 资金显式承接，不发币。所有非货币记录逐项确认处理方式：待办订单取消并释放旧预约、旧合同结束、所有权保留使用、身份/机构/岗位/报告/已付凭证保留。原旧账不改写；处理凭证存于新旁路，重复确认幂等。无法匹配的预留/先前承接、身份/资产冲突会阻塞接管，不能静默丢弃。

Settings 开关仍唯一默认 false。准备缴存属于玩家公有机构管理授权，不表示一般经济收费已开放；Draining 允许无新增债务的清理/国库提取。真实游戏存档验收仍缺时保持 Preparing，不用纯夹具 Active 替代。B3/B4 工资、消费和储蓄循环不在此批。

适用 GOV-001～013、MATRIX-001/002/003/006、DATA-001/002/006/008/010、SAVE-001～007、UI/LOC、AI-001～014。新增 Def/Save/双语 Key，触发 Architecture/Save/Localization Review。原有资金和制度保存键保留，新控制宿主默认空；未知控制格式保留原文并冻结资金操作。

### 3.1 保存与回滚

- 新增 `pawnEconomicTreasuryOperations`，schema 1：有限交付订单、阶段、稳定命令身份、Pawn/柜台/地图/来源/搬运中身份、数量、期限、预期版本、旧权益处理及快照 hash。缺失时空集合、零请求；不会自动新建个人余额或发币。
- 未知 schema/字段/枚举/编码/损坏序列/重复身份/DTD 保留原文并冻结；未知 wire 另加 Base64 外层传输标记，避免 XML 保存改变换行。已识别但正文绑定冲突也持久 Faulted，不能靠读档或切换开关消除。
- 原 `pawnEconomicSettlement`/`pawnEconomicMode`/旧制度键保留；实资宿主增加最终旧账 payload、encoding、hash。旧 B2.3 金额承接入口在最终快照存在后退役，只有最终债权验证入口可新增承接；历史承接仍按原记录绑定参与扣减。
- 关闭设置取消未交付缴存，保留/完成已经授权的清理提取；已有实物交付不冲销、不回填。Pawn 中断时只放下本请求绑定的 carried Thing，不处理其他背包/携带物；死亡/离图由原版物品持有/掉落继续保存，禁止 Destroy 或重新生成币。
- 旧历史账户的 Reserved 仍保留在冻结原文；确认取消旧订单后，新承接账户可用余额不再承继该预约。新账户负债本身保留，不等于全部 Draining 已清理。

## 4. 操作与实机验收

1. 在测试存档加载此批构建，设置 → 经济 → 请求启用，确认 Preparing；关闭/重开不能出现 OpeningBudget 或旧工资。生产、吃饭、睡觉、医疗、救火、征召、玩家强制 Job 保持原版优先。
2. 建造公有工资结算处，机构页选中它，再到账户页选成年殖民者。地面准备一堆至少 25/100 银币，申请缴存，等待安全 Anything 时段自主拾取/到柜台；核对地面、carried、专用储备与 Treasury 等量变化。
3. 申请提取时余额先锁定、储备不变；交付才扣 Treasury，银币位于搬运者 carried 容器并放回身边。分别测试到达前取消、征召、饥饿/疲劳、失火、柜台销毁、来源变小/他人搬走、离图/死亡和存档重载；不重复出币、不拿其他 carried 物。
4. 在拾取前、carrying 中、提取预锁后、物理交付后保存重载；确认 Job 步骤编号稳定、无证明锁被取消、完成证明只补终态。重复 UI 指令/旧状态戳拒绝，丢失或冲突证据等待对账。
5. 旧档逐项检查原始/最终差异，确认所列取消/结束/留档/保留权属处理；使用真实国库出资承接旧余额/欠薪。资金不足拒绝，不缩减债权；已付衣物继续可用。对非零承接账户关闭设置必须仍 Draining。
6. 核对中文/英文窄窗口/滚动/参数，完成真实整局保存和恢复验收后才考虑将对应能力验收为真。目前实际适配器的 SaveAcceptance 固定 false，工资、消费、服务和储蓄循环仍属于后续模块。

## 5. 剩余边界

本批只提取公有 Treasury 可用余额；承接到个人/机构账户的余额仍是保留负债，不能借关闭制度自动没收或退回国库。个人偿付/消费、再生产工资以及完整 ClaimBundle 履约需后续业务接线，故有这些余额时 Draining 可能持续。冲突仅隔离报告，不提供自动改账修复。B2.4 后续为完整游戏验收及能力解锁，不把这次离线通过算作 Active 或完整 AI 闭环。
