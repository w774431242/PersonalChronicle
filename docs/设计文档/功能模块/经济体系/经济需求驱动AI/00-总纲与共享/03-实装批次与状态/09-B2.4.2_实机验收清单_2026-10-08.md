## 1. 先明确这次能测什么

本次测试三个主体：需求事实可视化、真实银币准备操作、旧制度权益承接，以及它们对原版任务和存档的保护。**当前制度正常状态是“准备中”，不是“运行中”。** 完整存档验收能力在代码中仍固定为未通过，全部清单通过后也不会自行解锁；需要后续按证据修改能力门禁。

| 可以验收 | 现在不能要求它做到 |
| --- | --- |
| 观察原版需求、身体条件、直接关系和采样状态 | 自动生成生活目标、预算、需求驱动劳动和储蓄策略 |
| 公有工资结算处：25/100 银币缴存、提取、取消和恢复 | 个人账户提现、公私机构自由转账、多堆拼单 |
| 真实资金承担旧余额及欠薪；逐条确认旧记录处理 | 无资金兑换旧余额、首次凭空拨款、自动抹掉欠薪 |
| 保留已付资产权属及已有衣物使用 | 新购衣物、新签劳务、新发工资、收费体检和服务消费 |
| Pawn 在原版安全决策点自行执行已申请的搬运 | Pawn 自主决定财政缴存金额，或打断玩家命令强行搬运 |

“自主执行”指玩家管理公有机构并提交一次资金指令后，不需要再右键强制搬运；金额和搬运者由玩家选择。本批不宣称完整经济 AI 已完成。旧文档中的“启用即拨款1000”“工资→购物→体检”属于已退役原型，不能作为本构建的操作步骤。

## 3. 界面入口与最短操作路径

1. 设置 → Mod 设置 → 殖民地综合管理系统 → **经济** → **需求驱动经济**，勾选“请求启用经济制度的准备流程”。关闭设置页并运行几秒。
2. 建筑菜单 **经济机构** 建造 **工资结算处**。点击柜台的“经济机构”，或总控中心 → 经济中心 → 经济机构。
3. 在 **机构** 页选择该工资结算处；进入 **账户/需求** 页，顶部“所选殖民者”按钮循环选择 A。确认名称和地图正确。
4. 找到 **公有国库准备与旧权益承接**。记录“国库、已锁定、实物储备”；点击“向国库缴存 25 枚公有银币”对应的 **申请缴存**。
5. 解除暂停，等待 A 自然进入安全决策点。观察“等待安全空闲→搬运中→交付完成”，不追加右键强制指令。
6. 点击“将国库可用的 25 枚银币放回殖民地”对应的 **申请提取**。先观察预锁，再等待交付，最后记录地面银币与国库。
7. **需求观察** 是单独的标签页；账户页下方“以下是保留的旧制度记录”是历史区，历史金额不能当成当前可用资金。

当前界面每 60 个游戏 Tick 左右刷新，制度巡检约每 250 Tick 进行一次；暂停时 Tick 不增长。搬运请求有效期为 5000 Tick，标准速度约 83 秒游戏运行时间（受速度/性能影响），不是可无限等待的订单。取消后需要重新申请。没有响应时先恢复安全条件、关闭重开面板，再查看请求是否已终结，勿连续狂点。

准备缴存与机构原型的收费营业时段是不同门禁；本清单不把柜台营业时间当作准备资金的必备条件。可达、玩家所有权、未着火及角色安全条件才是本批重点。

## 4. 资金读数与守恒判据

内部 100 分对应 1 枚银币；界面 `25.00` 对应 25 银币。国库余额包含已锁定款；**可用国库 = 国库 − 已锁定**。旧历史金额不能与新账相加。专用储备由保存宿主持有，不一定显示在地图资源栏或柜台普通库存中；不能仅凭顶部资源计数判断丢币。

记 `G` 为国库余额，`L` 为已锁定额，`C` 为所有已承接个人/机构账户余额合计，`R` 为专用实物储备（均按银币单位）；`M` 为地图地面银币，`H` 为 Pawn 实际携带/库存及其他已确认容器中的银币。无贸易、生成、销毁或其他资金来源的封闭样本应满足：

```text
R = G + C                   正常终态：实物覆盖全部新账余额
0 ≤ L ≤ G                   预锁只是限制可用额
M + H + R = 测试前总银币     搬运时要把手上银币计入
```

干净测试档（无旧权益承接）示例：

| 检查点 | 地面 M | 携带 H | 实物储备 R | 国库 G | 已锁定 L |
| --- | ---: | ---: | ---: | ---: | ---: |
| 初始 | 500 | 0 | 0 | 0 | 0 |
| 缴存 25，已拾取尚未交付 | 475 | 25 | 0 | 0 | 0 |
| 缴存 25，完成 | 475 | 0 | 25 | 25 | 0 |
| 申请提取 25，尚未交付 | 475 | 0 | 25 | 25 | 25 |
| 提取已交付，尚未放下（瞬时） | 475 | 25 | 0 | 0 | 0 |
| 提取完成并放下 | 500 | 0 | 0 | 0 | 0 |

在搬运者处放下时，原版可能合并附近银币堆；看数量总和，不要求堆 ID 永远相同。缴存拆堆后的搬运物是新的实际身份，不能误认为账目应该继续引用原地图堆 ID。已支付/已交付记录重复加载不得再次转移。

旧权益承接 X 的正常结果是：`G 减 X，C 加 X，R 不变`。原始旧账保持只读。确认记录的处理方式本身不转钱，不能替代债权足额承接。

## 6. 第一轮建议执行顺序

如果先做一轮约 20～30 分钟的冒烟验收，按以下顺序；实际耗时受界面、地图和旧档规模影响：

1. A01～A05：确认加载、门禁、入口。
2. B01、B02、B06、B07：25 银币完整往返及守恒。
3. C02、C03、C05：持币取消、预锁取消、征召中断，分别从保存分支开始。
4. D04、D05、D06：搬运途中、提取预锁、完成后的恢复。
5. F01～F03、F06：需求事实、未配置缺口和中文可读性。
6. 有旧档再做 E01、E03～E05、E07、E14：历史只读、资金不足、实资承接及等待清理。

先回报这一轮，后续补齐其余必测、英文、兼容和工程切点。冒烟通过不等于全部清单通过，尤其不能证明缺少的旧档迁移样本。

## 7. 何时停止、如何判断验收结论

| 分类 | 情况 | 处理 |
| --- | --- | --- |
| P0 | 存档无法读入、钱物增减不守恒、重复出币/付款、旧余额/欠薪/已付资产被无提示抹掉、已交付反复重放 | 立即暂停该分支；保留前后存档/日志/数字；不继续反复开关“修复” |
| P1 | 始终不接单、搬运循环/卡死、正常条件下永久预锁、强制任务被抢、完成状态与实际资金不一致、中文关键操作不可读 | 保留能复现的最小步骤，停止该功能的正式使用，其他独立分支可测 |
| P2 | 非关键排版、历史名称显示不佳、反馈不清楚、可恢复的缓存延迟 | 记录语言/分辨率/缩放及截图，继续独立检查 |
| 正常边界 | 准备中、SaveAcceptance 待验收、尚未工资消费、无单堆够数被拒、已有个人负债时等待清理、未知冲突冻结 | 按对应清单核对，不为得到“运行中”而改账/强开门禁 |

本轮可给出“本批已测场景通过/有问题/仍有未测”，不能给出“完整经济 AI 已完成”。普通必测均通过、旧档样本情况明确、无未处理 P0/P1 且关键恢复证据齐备后，才讨论 B2.4.3 能力确认。工程扩展未测、其他 Mod 兼容范围和缺少的旧样本必须继续显式保留。SaveAcceptance 仍须后续代码变更，不能由 CSV 勾选自动解锁。
