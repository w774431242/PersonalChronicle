# 全部关闭原版工作后，自主求职未发生

用户实机反馈：取消所有 pawn 的原版工作类型后，pawn 未因需求自主寻找岗位，也未自动启用岗位所需工作类型。截图可见闲逛和工作安排提醒；无法仅凭截图确定个人余额、需求缺口、岗位资金或当前进程载入的 DLL 版本。

**结论：当前部署不满足自主经济就业目标。这是实现缺口，不能要求玩家重新勾选工作或手动分配岗位后判为通过。此次完成核查和问题登记，未修复运行代码。**

## 已核对的阻断

| 环节 | 当前源码事实 | 影响 |
| --- | --- | --- |
| 新经济执行入口 | `EconomyInstitutionMode.LegacyFeesAllowed` 固定为 false；`EconomyRuntime.Plan` 此时仅返回国库交付或既有资产使用任务 | 旧求职原型不会执行；B3/B4 仍为 Planned，新的自主就业链尚未接通 |
| 旧岗位筛选 | `EconomyRuntime.CanJoin` 同时要求未被能力禁用和 `WorkIsActive(type)` | 玩家设为 0 的工作类型被当作无法入职；出现“先勾选才能求职”的循环条件 |
| 旧求职动机 | `PlanTradeOrEmployment` 先寻找有合适服装的商店，无商品就返回 WaitingSupply | 并非食品、休息、服务预算及储蓄缺口共同驱动的收入规划 |
| 旧签约落地 | `FinishVisit` 签约后添加带 EconomicContractId 的 WorkshopSlot；普通工坊运行名单排除此类 slot | 不能依赖普通工坊名单接管来保证经济合同所需的工作优先级与实际劳动 |

已有工坊功能在进入有效排班时调用 EnableWorkTypes 和 WorkshopPostLandingService，适用于已经安排的人员；它不会按个人需求发现岗位和签约。不能据此宣称自主经济求职已经完成。

源码 DLL 与 Mods 部署 DLL 核对一致：SHA-256 `F72561366C7959388678D27CE4C61DB23EE2E84B87AB365F96885E4E84FF5FEE`。这证明文件一致，不证明正在运行的游戏进程已经载入该版本。

## 必须补齐的运行链

需求缺口和储备缺口 → 收入目标 → 有资金、可达且能实际执行的岗位 → 能力与技能筛选 → 有效合同 → 岗位所需工作优先级接管 → 原版 WorkGiver 实际劳动 → 经核验的工资支付 → 消费与储蓄 → 重新评估。

工作优先级为 0 不作为能力禁用。实际能力禁用仍不可绕过。签约前不得提前改工作类型；签约后只接管必要类型，记录原值和本系统写入值。离岗、合同取消或制度退出时，仅恢复仍归本系统管理且未被玩家改写的值。不能每 tick 强行覆盖玩家修改，也不能打开全部工作类型来掩盖问题。

依次落实 B3 的收入目标、岗位可行性和阻断原因只读规划，再落实 B4 的合同、工作权限、真实劳动与支付联动。财务、存档恢复和制度能力按原门禁验证，不能恢复已停用的旧收费路线来模拟闭环完成。

## 后续回归与实机验收项

以下均为待实装后执行的用例，当前不记为通过。

| ID | 条件 | 必须观察到的结果 |
| --- | --- | --- |
| EMP-01 | 全部工作优先级 0，有收入缺口、有可执行且有资金岗位 | 自主选择并签约，仅启用岗位必要类型，产生实际劳动 |
| EMP-02 | 对岗位工作类型有原版能力禁用 | 不启用、不签约，显示能力阻断 |
| EMP-03 | 无岗位、无支付能力、无材料或无可执行任务 | 显示具体原因，无虚构合同、工资或反复勾选 |
| EMP-04 | 饥饿、疲劳、急救、征召或玩家强制任务 | 按需求及保护规则暂停或让路，不靠强制劳动覆盖 |
| EMP-05 | 多人争抢最后一个岗位 | 不重复占岗、不超额承诺资金 |
| EMP-06 | 在合同期间玩家手动修改工作优先级 | 不逐 tick 抢回；退出时不覆盖玩家新值 |
| EMP-07 | 离岗、取消合同、关闭制度 | 释放岗位并按所有权恢复工作设置 |
| EMP-08 | 签约、劳动、结算各阶段保存并载入 | 工作设置所有权可恢复，工资不重复、不遗漏 |
| EMP-09 | 没有可买服装，但存在食品预算或储蓄缺口 | 收入规划仍可成立；不依赖服装商店触发 |
| EMP-10 | 同时存在玩家工坊排班和经济岗位 | 不重复管理同一劳动，不重复计薪，冲突原因可见 |

当前 B2.4.2 的国库交付验收与此问题分别记录；其通过不能抵扣 EMP-01。截图反馈也不能据此将完整经济模型或 B2.4.3 存档能力标为通过。
