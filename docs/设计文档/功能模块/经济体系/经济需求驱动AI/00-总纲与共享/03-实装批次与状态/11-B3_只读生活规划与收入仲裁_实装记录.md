# B3：只读生活规划与收入仲裁

本轮承接“继续实装”，落实 M2/M5/M3/M4 的可运行只读规划单元。Domain 纯计算生活目标、有限预算与储备滞回，Application 有界更新每人报告，游戏适配器仅读取已有感知、有效特质及经核验的新账本，RUIF 展示已发布报告。具体岗位执行、工资、购买和工作类型接管仍属于 B4，不通过恢复旧收费引擎绕过。

适用 GOV-001–013、MATRIX-001–010、AI-001–014、LOC-001、PERF、TEST 和 SAVE 相关规则。复用 GameComponent Tick 和现有感知目录；无 Harmony、无新 Def/资产、无第三方引用、无静态可变状态。原版类型仅出现在游戏适配层；特质只按稳定 DefName 和 degree 读取，跳过 Suppressed。引用当前游戏 DLL 的现有公开 API，不新增未经核实的反射调用。

架构审查：原型目标、工作时长、储备天数及水位集中于有版本的纯策略，来源为 M2/M5 设计样例，不作为原版生理参数。语义 DefName 在适配和策略注册处集中；不根据中文标签判断。风格暂不学习，因此按当前有效特质从中性基线重建，无累计叠加；八维中尚无实据的维度保持明确中性默认。

资金只从已恢复且实物审计无异常的 M11 读取；历史原型 Account/Person 不参与。未开户保持未知；未来工资不算可用现金。成本契约验证同窗、覆盖唯一性和硬预留对称扣除；缺报价/消耗覆盖估计时储备与收入额保持未知，不以 MarketValue 或固定三餐填充。

只读规划的激活/补储滞回是会话缓存，读档/时间回退/换地图重建，尚不授权行动。后续执行接入前须将必要滞回和目标生命周期按 M3/M5 保存、往返验证；本轮不新增存档字段，旧档字段及权益不变。UI 只查询已发布缓存，不在 OnGUI 采集、计算计划或写账。

验证计划：独立预期的预算金额/去重/滞回/未知/溢出测试；多需求和原版控制保护；工作优先级 0 与能力禁用区分；影子协调的 Tick 配额、会话/地图/时钟失效和查询无副作用；中英文 Key 对齐；构建与全回归。实际游戏、存档完整能力、性能剖析独立记录。

## 本轮实际落点与结果

- `LifePolicy`：中性基线及有效特质的可解释映射；食品/休息/娱乐目标、工作/闲暇软倾向、有限储备天数和结余比例。其他需要没有适配目标时仍明确未配置，不能因此判为已满足。
- `LifeBudgetPlanner`：已付/实物、公费和硬预留覆盖；同窗费用去重；L=B−R；必要净储备 S；70% 下水位与 100% 上水位；收入缺口；必要、软保留和可选分配共享现金。未知、重复、超限和覆盖冲突明确返回，未来工资不算现金。
- `ShadowPlanBuilder`：三类需求激活滞回及 P0/P1/P2 分层；原版控制让路；基本生活优先；只在费用、资金、能力、可执行性、可达性、有效期和及时足额支付均有证据时拟选岗位。优先级 0 不当能力禁用。本轮候选模型为一笔保证支付，不模拟连续工资预测。
- `ShadowPlanningCoordinator`：按到期队列每 Tick 最多更新 2 人，每人常规 250 Tick；共享感知目录，最多 4096 人；目录发布变更立即接入，600 Tick 兜底协调；会话/时钟/地图失效；单项异常隔离并能恢复。UI 查询不运行采集/规划。
- 复用需求页的 RUIF 动态换行 StatRow/StatTable，显示目标、原始缺口、规划年龄、生活风格来源、预算状态、拟选行动与原因。儿童/婴儿普通就业软工时显示不适用。未接入真实费用和岗位市场的游戏环境，预算与收入仍显示未知；这是明确缺口，不是模拟成功。

Release 构建成功，0 警告、0 错误。最终全量测试 962 通过、0 失败、1 既有跳过（`Measure_Content_vs_Viewport`），其中本轮新增规划/预算用例 54 个。首次全回归为 958 通过；检测到同工作区构建刷新后，已对最终 DLL 和本轮源文件执行测试前后哈希绑定并复验，后者计入工作区同期新增的 4 项既有需求页测试。运行验证见 [B3.1_实装验证.json](B3.1_实装验证.json)，验收步骤见 [只读规划清单](12-B3.1_只读规划验收清单.md)。结构/参数与离线测试通过不代表实机布局、游戏性能或完整存档能力通过。
