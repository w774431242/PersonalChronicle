## 追加与**更正**：交付证据的类别归因（tend = 治疗，不是体检）

**更正**：上一段把原版 `TendUtility.DoTend` 的交付证据记在「体检」名下，属**归因错误** —— 该回调是**治疗**过程。已修正：

| 服务 | 交付证据来源 | 七门现状 |
| --- | --- | --- |
| **诊疗** | 原版 `DoTend`（EXC-2026-029 只读挂点） | 访问/交付/容量/价格（真实发布）/结算/恢复/界面 —— **代码级齐全**；玩家发布服务单价后才 `ReadyPaid` |
| 体检 | 原版**无**体检过程 | `DeliveryEvidence = false` ⇒ 保持「取证中」，**不报价** |
| 床位 / 托育 / 教育 | 尚未接入交付证据（床位休息片段、托育喂养、教学活动各需专属挂点） | 保持「取证中」 |

代码随之通用化：`CareService.AcceptCareAct(ServiceKind, …)` 按类别记账（类别互不串用：治疗授权不会授权体检证据），`TrySettleCareAct(ServiceKind, …)` 按类别结算；能力求值 `RefreshServiceCapability(kind, context)` 中 `deliveryEvidence` 只在**确有该类别原版过程**时为真。

验证：Release 0 错 0 警；全量 **1015 通过 / 0 失败 / 1 既有跳过**（新增「证据按类别隔离」用例）；部署 DLL 与源 DLL 哈希一致。

**下一步（仍未做）**：诊疗首次实机验证（NOT EXECUTED）；床位/托育/教育各自的交付挂点与 EXC 登记；U2 收口（部署终检 + 变更标注 + 各 Gate + DELTA）。
