# 05 证据索引与验证记录

整理日期：2026-10-08。资料用于本手册的实装依据，不等同于完整运行实现、已审批设计或第三方兼容保证。

## 1. 证据等级与裁决顺序

| 等级 | 本册含义 | 可以支持 | 不可以支持 |
|---|---|---|---|
| B | 当前磁盘程序集的元数据/所选 IL | 类型、签名、可见性、虚方法标志、选定调用关系 | 游戏实际加载哪一份、完整运行结果 |
| L | 本地源文件/已有反编译文本、当前游戏 XML | 实现语义、项目落点、树的局部顺序 | 未核对文本与当前 DLL 完全同版本 |
| D | 公开 modding 作者/社区教程，Harmony 官方文档 | 扩展模式与接入注意事项 | 目标游戏全部细节仍与教程一致 |
| S | Mod 作者公开仓库的固定提交 | 指定代码路径的实现示例 | 等同于工坊当前发行 DLL、可以无条件复制 |
| P | Mod 作者工坊页面 | 作者宣称的已发行功能 | 本项目已兼容、实测性能、全部闭环真实通过 |
| V | 本次独立编译与结构检查 | 示例实际调用可编译、链接和证据指纹一致 | 完整 UI/AI/存档在游戏里已验收 |

遇到冲突，原版接口以目标 DLL 的 B 证据为准，具体语义再核对 L 的调用点；RUIF 以实际安装 DLL 与当前源文件为准。已有项目注释、README 和旧教程只作线索。经济模型的正确性仍需不变量/游戏场景验证，不能从引擎接口存在直接推导。

## 7. 复跑方式

在项目根 PowerShell 执行：

```powershell
& 'docs/设计文档/功能模块/经济体系/经济需求驱动AI/00-总纲与共享/04-实装指导手册/tools/Collect-Evidence.ps1'
& 'docs/设计文档/功能模块/经济体系/经济需求驱动AI/00-总纲与共享/04-实装指导手册/tools/Verify-Handbook.ps1'
```

证据脚本默认使用项目已存在的 `InspectTypes/bin/Release/net8.0/Mono.Cecil.dll`；其他机器通过 `-WorkspaceRoot/-GameRoot/-RuifSourceRoot/-CecilPath` 指定实际路径。编译工程的游戏根可通过 MSBuild `RimWorldPath` 传入；复跑前同步验证脚本/工程的路径配置。

游戏/RUIF 升级后先重新取证，再更新手册和示例，不应仅重新生成 JSON 就把旧设计视为兼容。取证脚本验证各目标方法存在，但不能自动判断行为语义和模型平衡。验证脚本可用 `-SkipBuild` 做结构检查，此时 JSON 明确标记跳过编译。
