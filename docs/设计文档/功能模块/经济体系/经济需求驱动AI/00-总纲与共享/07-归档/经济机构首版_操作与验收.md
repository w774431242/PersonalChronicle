## 一、已经接通的机构

| 地图建筑 | 可操作内容 | 真实结果 |
|---|---|---|
| 劳务站 | 供殖民者到场签约 | 占用招聘名额，生成带合同 ID 的工坊排班 |
| 工坊管理处 | 设置新岗位时段、计件工资、人数、体检条件；绑定已有车间并发布或撤岗 | 招聘进入实际 `Zone_Workshop`；撤岗结束对应经济合同 |
| 工资结算处 | 账户、收支凭据、补发欠薪 | 真实账户转账；余额不足产生一次待付工资，并停岗解约 |
| 生活用品商店 | 选择搬运者，将地图上的公共衣物搬进柜台；设置每件固定售价 | `ThingOwner` 保存真实 Apparel，购买后转入个人库存并执行穿戴 |
| 体检中心 | 指定医生、设置价格、预约个人或入职体检 | 双方到场完成600 tick检查，保存真实能力及可见健康状态，支付费用和医生报酬 |

柜台暂用原版桌子贴图；五类功能通过名称和管理内容区分。体检采用柜台旁站立检查，没有病床、治疗、手术或药品功能。原先预留的医疗/物流系统中心仍保持预留状态。

## 二、从零启用

1. 确认 Harmony、RUIF 和本 Mod 正常加载，重启游戏后打开存档。旧档默认不启动经济系统。
2. 在建筑菜单“经济机构”中建造劳务站、工坊管理处、工资结算处、商店；需要入职体检时再建体检中心。柜台留可通行的邻接格。
3. 打开任意柜台的“经济机构”，或“总控中心 → 经济中心 → 经济机构”。界面内容使用 RUIF 控件。
4. 点击“启用 · 首次拨款1000.00”。公共账户只在首次启用获得1000内部单位；不是白银，也不会再次启停补钱。
5. 建立已有车间系统的 `Zone_Workshop`，设置车间类型；在区内放置工作台并添加有效生产工单、原料。不要给拟招聘者预先分配固定班、轮岗池或班组。
6. 在“机构”页选择工坊管理处，配置工资、名额和时段，再点击对应车间的“发布岗位”。条款在发布时复制到岗位；改柜台设置只影响新发布岗位。
7. 确认候选殖民者的原版工作面板启用了该车间对应生产工作；系统不擅自开启或改写工作优先级。
8. 选择商店，进入“商店”页；点击顶部切换搬运者，再对适合殖民者的公共衣物点击“搬运入库”。必须等实际搬运完成，地图衣物才成为商店库存。
9. 衣物默认每件60，计件工资默认20。缺钱且有改善衣着机会的成年殖民者，会在合法自由时段前往劳务站签约、按现有工坊系统生产、取得收入，再购买与穿戴。

商品不足、无有效岗位、原版工作未开启、路径不通、已有手动排班、余额不足，都会让闭环等待；“账户/需求”和“结算/订单”页显示目标与交易情况。柜台营业时间默认为06–18，可切换为18–06或全天。

## 三、体检配置

选中体检中心，在顶部选医生，再点击“指派所选殖民者”。医生需成年、可移动和操作、医术至少4级，原版医生工作已启用。

工坊发布岗位前开启“招聘需要有效体检”。招聘者会预约入职检查，由公共账户支付；医生通过医生 WorkGiver 自然接单，普通救治工作排序在体检前。手动“预约个人体检”由所选殖民者自己支付，需要本人账户足够。

客户与医生都到柜台旁，检查才累计进度。费用在600 tick检查完成时结算：60%进入医生账户、40%留在机构账户。报告记录移动、操作、意识及**当时可见**的 Hediff 类型；有效期60000 tick。首版入职门槛为移动/操作各≥60%、意识≥70%；原版即时身体限制仍决定能否真正工作。

报告不改变健康，不曝光隐藏疾病，也不保证未来一直适岗。医生暂忙时客户等待；5000 tick订单期限包含路程和等待，超过期限取消并释放冻结款。

## 四、交易与劳动边界

- 资金采用整数分，启用后的工资、购物、体检均为账户间转账。个人不能透支；准备订单只冻结，不提前扣款。
- 工资只接收真实 `DoBill` 完成回调，并校验合同、经济排班、车间、时段、Bill 和 Recipe 类型。当前支持标准 `Bill_Production` / `Bill_ProductionWithUft`、基础 `RecipeWorker`、正数静态 products 表；不支持特殊产物、机体孕育及自定义 Bill/RecipeWorker 的工资适配。
- 一个 Job ID 只付一次。站岗、走路、扫描工单、取消制作不支付。余额不足保留已完成的一笔欠薪，暂停岗位并移除该合同的经济排班；补发后需重新发布岗位与签约。
- 衣物需求评分首版使用实际耐久、防护、保温与可穿条件；阈值0.05。尚无完整季节、性格、地位、储蓄或跨机构竞价模型。
- 商店保存单件物品，不用 Def+数量重造。出售后保留品质、材质、耐久、颜色及身份，登记个人产权。购买后衣物自动设为禁止公共使用，掉落仍保留产权；玩家手动解除禁止或强制转交属于人工干预。
- 穿戴前再次验证服装策略、身体部位、生物编码及锁定/强制衣物；无法使用时保留“已购待穿”，不会因同一待穿目标反复扣费。采购完成后在同一 Job 内执行60 tick穿戴阶段；中断后可重新拾取自己的掉落衣物。
- 不改原版 `MarketValue`、动态价格、财富或原版白银。首版公共生产资料和产品仍使用已有共享车间规则；尚未实现企业资产确权、商品回收、个人出售或二手产权流转。

## 五、中断、存档和容量

经济决策只在自然 ThinkTree 决策点参与，限定自由时间，食物≥50%、休息≥40%；征召、倒地、精神状态、强制任务、地图火灾、高危险与救治需求会阻止自主机构活动。执行中的服务在食物<35%、休息<25%或失能时退出。原版需求和医生工作继续负责其自身调度。

关停系统、取消订单、柜台停业/移除、失去客户或超时，会取消未结订单并释放冻结款。购入物品和已完成工资不因取消而撤销。柜台被拆除或离图时将真实库存掉在原地图附近。

存档键为 `pawnEconomicInstitutions`，内部 schema 1。Data 层用 Scribe 保存版本化 XML primitive payload；真实库存另外由建筑 `ThingOwner` 深存档。读档取消未完成服务并退还冻结款；已完成凭据、账户、产权、合同与排班标识保留。无键旧档默认关闭；未知版本或坏数据进入只读保护，原始 payload 在再次保存时原样保留。

当前边界：每店64件；一次决策最多检查128件候选；最多128个未结订单；保留128条已结订单、512条已付凭据和每人最新2份报告；欠薪凭据不裁剪。机构和岗位各256条历史上限；自主人员4096，产权8192，停用合同保留512。达到上限需后续迁移/清理工具，首版不静默删除余额与产权。
