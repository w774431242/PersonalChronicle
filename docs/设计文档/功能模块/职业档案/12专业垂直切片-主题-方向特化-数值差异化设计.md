# 12 专业垂直切片：一级主题 · 二级方向特化 · 数值差异化设计

> **状态**：设计（AI-002 先架构后编码，P0 落地前定稿基线）。本文件为 P0 垂直切片（BookProduced 采集 + 11 专业展开）的**设计基线**。
> **2026-08-22 v2.0**：全 12 专业定位/基调/主题深度优化 + 数值加成组合扩展（招牌能力机制 + 战斗 Stat + 语义修正）。
> **基线**：《职业生涯系统开发者指南V2.0》§3/§4/§7/§8/§9/§10/§11/§13、《全部专业职称称呼体系》§2.5、`Defs/ProfessionalSkills.xml`（48 方向 + 精密制造闭环）。
> **术语**：一级专业=12 类；二级方向=每专业 4 个；技能=`ProfessionalSkillDef`；效果=`ProfessionalEffectDef`；特化点=方向 `specializationKey` + 技能级 `effectOverrides`；**招牌能力**=该方向最独特、玩家一眼记住的加成。

---

## 1. 设计原则

1. **一级专业主题**：一句话定义"这个专业练什么、玩家因何长期投入"（职业定位），对齐原版 Skill/WorkType 真实来源。
2. **招牌能力机制**（2026-08-22 v2.0 新增）：每个方向必有 **1 个招牌能力**——该方向独有的记忆点（如外科=手术成功率、驯养=驯服成功率、外交=交易价格改善）。招牌能力不依赖通用速度，让方向"一听就懂"。
3. **二级方向特化**：每个方向一个**特化维度**（`specializationKey`），在共享效果之上用 `effectOverrides` 拉开数值差异（V2.0 §9"推荐≠强制"+ P2-A §9 差异化特化点机制）。
4. **数值差异化多维通道**：
   - **WorkSpeed**（工作速度，statDefName 指向专业基调官方 Stat）：特化"产量/效率"的方向给高值；
   - **QualityBias**（品质）：特化"质量/精度"的方向给档位偏置；
   - **YieldBonus**（产量）：特化"收获/产出"的方向；
   - **XpBonus**（学习系数）：特化"成长"的方向；
   - **SuccessBonus**（成功率，2026-08-22 v2.0 新增概念）：特化"成功率"的方向（手术/驯服/建造/训练）；
   - **CombatStat**（战斗类 Stat，2026-08-22 v2.0 新增）：武器类方向走 `RangedWeapon_DamageMultiplier`/`MeleeDamageFactor`/`RangedWeapon_RangeMultiplier` 等，与制造类形成差异化。
   - 叠加 `ratingWeightScale` 控制评级加成强度。
5. **能力维度（abilityKeys）按专业自定义**（4 个/专业，小写驼峰），贴合专业语义。
6. **禁硬编码**：一切数值/白名单进 Def；C# 零 if(skill=="...")。
7. **避免专业重叠**（v2.0）：林业不再用 PlantWorkSpeed（采伐≠种植）；武器类不再只走 GeneralLaborSpeed（加入战斗 Stat）；音乐不走工作速度（走娱乐效力/冥想）。

## 2. 效果库（共享 ProfessionalEffectDef 池）

> **核心洞察**：`WorkSpeed` 效果通过 `statDefName` 指向**不同官方 Stat**，即可让每个专业贴合其基调；
> 武器类额外用战斗 Stat 区分制造类；招牌能力用成功率/产量/价格等非速度维度体现记忆点。

### 2.1 效果 Def 池（kind + 默认 value）

| 效果 Def | kind | 默认 value | 语义 | 引擎状态 |
|---|---|---|---|---|
| `ProfessionalEffect_WorkSpeed` | WorkSpeed | 0.03（+3%） | 工作速度（statDefName 指向专业基调 Stat） | ✅ 已实现 |
| `ProfessionalEffect_QualityBias` | QualityBias | 1（+1 档） | 品质整档偏置 | ✅ 已实现 |
| `ProfessionalEffect_MaterialEfficiency` | MaterialEfficiency | 0.05（-5% 损耗） | 材料效率 | ⏳ 枚举已预留 |
| `ProfessionalEffect_YieldBonus` | YieldBonus | 0.05（+5% 产量） | 收获/产量 | 🆕 需新增枚举 + Resolver |
| `ProfessionalEffect_XpBonus` | XpBonus | 0.1（+10% 成长） | 专业经验成长 | 🆕 需新增枚举 + XP 接入 |

## 4. 数值差异化规则（编码约定）

1. **共享效果池 + 技能级覆盖**：每专业引用 `ProfessionalEffect_*` 池中的效果，`effectOverrides` 写该技能专属数值（hasValue=true）。不建重复 Def。
2. **专业基调 Stat 绑定**：`WorkSpeed` 效果必须设 `statDefName` = 该专业基调官方 Stat（§2.2 矩阵），同名效果可被多技能共享，经 `effectOverrides` 差异化数值。
3. **招牌能力约束**（v2.0）：
   - 每个方向 **恰好 1 个招牌能力**（成功率/产量/价格/战斗 Stat 等非速度维度），`specializationKey` 与招牌能力一致；
   - 招牌能力 value 为该方向最高（如成功率 +10%、产量 +10%），其余副加成收敛 ≤5%；
   - 无招牌能力的方向（平衡型）保留 QualityBias 为记忆点。
4. **性格轴约束**：
   - 特化 **Q**（品质）：主 Stat 加成 ≤ 0.03 且 `QualityBias ≥ 1`；
   - 特化 **T**（产量/速度）：主 Stat 加成 ≥ 0.04 且 `QualityBias = 0`；
   - 特化 **X**（成长）：`XpBonus ≥ 0.1` 且其他加成收敛；
   - 特化 **S**（成功率）：招牌能力 +10%，主 Stat 收敛；
   - 特化 **C**（战斗）：战斗 Stat +10%，工作速度收敛。
5. **ratingWeightScale**：T/X/S 方向设 1.5~2.0（评级加成更强），Q/C 方向 1.0。
6. **能力映射**：每个方向 1 个 `AbilityMappingDef`，权重表对应该方向 abilityKeys（主能力 50/次能力 30/辅助 15/边缘 5）。
