# 制造类职业效果设计（P3-A）

> **状态**：领域设计（AI-002 先架构后编码）。**2026-08-16 起进入 P3-B 实现**（Resolver/Service/StatPart/Postfix 链路已落地，见 `Domain/Profession/ProfessionalEffectResolver.cs`、`Application/Effects/`、`Capture/Effects/`）；验收结论见 `Gate-Record-2026-08-19-职业生涯体系验收.md`。
> **基线**：《职业生涯系统开发者指南V2.0》（V2.0，§= 章节号）、《制造类职业领域设计》（P2-A，§= 章节号）、《09-模块文件架构范式》、《07-AI开发规范》。
> **范围**：V2.0 §22 P3 垂直切片 = 精密制造 → 专业效果 → **真实制造速度/品质**。即 §23 验收闭环「专业等级 → 制造速度/品质效果 → 真实制造」环节。
> **引擎基线**：RimWorld 1.6 / PersonalChronicle v1.1.4 / **Save Schema Version 6**。引擎 API 已反射探针核验（2026-08-16，§3）。
> **分层铁律**：UI → Application → Domain ← Data / Capture；Domain 无 Verse 依赖（可离线单测）；效果经 Effect → Resolver → Adapter 三层，**禁止直接 Harmony Patch 全世界**（V2.0 §11）。

## 1. 任务定位

P2-B 已落地：制造行为 → CareerEvent（含 Recipe/Quantity）→ ProfessionalXP → 能力 → 等级 → 持久化。

P3 补齐闭环缺口：**专业等级/能力 → 真实游戏数值（速度/品质）**。

```text
【精密制造】→【加工/质控能力】→【制造 XP】→【专业等级】→【制造速度/品质效果】→【真实制造】→【CareerEvent】→【履历】
                                                                   └── P3 本阶段补齐 ──┘
```

**判断标准**（V2.0 §23）：玩家看到的不是"制造类 72/100"，而是"这个 Pawn 因为真实做过这些工作，所以形成了某种专业能力；专业能力又真实改变了他下一次工作的结果"。

**范围裁剪**（V2.0 §12 + 领域设计 §3.3）：
- 本阶段只做 P1 批的 **WorkSpeed（制造速度）** 与 **QualityBias（品质倾向）**。
- 经验/履历效果已由 P2-B 完成；RecipeUnlock/MaterialEfficiency（P2 批）、SpecialWork/工具/工作台（P3 批）**明确不做**。
- 效果强度不直接读 Level 硬算，经 Rating 档位聚合（P4）后生效；P3 仅实现**基础效果链路**。

## 3. 引擎 API 核验事实（AI-007 铁律，反射探针 2026-08-16）

> 以下全部为 `Assembly-CSharp.dll`（1.6.9676.17735）反射核验结果，非推断。

### 3.1 品质链路（已证实）

```text
GenRecipe.PostProcessProduct(Thing, RecipeDef, Pawn, Precept_ThingStyle, ThingStyleDef, int?)
  └─ 内部调用 QualityUtility.GenerateQualityCreatedByPawn(Pawn, SkillDef, bool)   [public static]
  └─ 内部调用 CompQuality.SetQuality(QualityCategory, ArtGenerationContext?)       [public]
```

- `RimWorld.CompQuality.SetQuality(QualityCategory, ArtGenerationContext?)` **public** ✅
- `RimWorld.CompQuality.get_Quality()` **public** ✅
- `RimWorld.QualityUtility.AddLevels(QualityCategory, int)` **nonpub static**（不依赖，见 §6.4）

**结论**：品质偏置可在**已有 PostProcessProduct Postfix 中事后覆盖**（原版设品质 → 按专业效果重算 → `SetQuality`），零新增 Patch，范围精确到"制造产物"。

### 3.2 速度链路（已证实）

- `Verse.RecipeDef.workSpeedStat : RimWorld.StatDef` **public** ✅ —— 制造速度 = `pawn.GetStatValue(recipe.workSpeedStat)`（制造 tick 反复评估）。
- `RimWorld.StatDef.parts : List<StatPart>` **public** ✅ —— 可程序化注入 StatPart。
- `RimWorld.StatPart`（抽象类）✅：`TransformValue(StatRequest, ref float)` public virtual；`ExplanationPart(StatRequest)` public virtual；字段 `priority`/`parentStat` public。
- 制造上下文判定链（全 public）✅：
  - `Pawn_JobTracker.curDriver : JobDriver` public
  - `Pawn_JobTracker.curJob : Job` public
  - `Job.bill : RimWorld.Bill` public
  - `Bill.recipe : Verse.RecipeDef` public（recipe 定义在基类 `Bill`，`Bill_Production` 继承）
- `JobDriver_DoBill` 的 `workLeft`/`billStartTick`/`ticksSpentDoingRecipeWork` public；**tick 扣减逻辑不在该类简单可见处**（IL 确认 `workLeft` 仅 `ExposeData` 直引）→ **不推荐 Patch tick 扣减点**（§7 Q1-B 风险依据）。

## 5. 效果 Def 补充（复用领域设计 §3.3，仅细化语义）

现有 `ProfessionalEffectDef` 已满足 P3，不改结构。语义约定：

| 字段 | 语义（P3 冻结） |
| --- | --- |
| `kind = WorkSpeed` | 制造速度修正；`value` 为**乘算修正量**（0.03 = +3%），作用于配方 `workSpeedStat` |
| `kind = QualityBias` | 品质档位偏移；`value` 为**整档偏移量**（1 = +1 品质档） |
| `statDefName` | WorkSpeed 时空留：注入按**配方上下文**解析（配方 workSpeedStat），不依赖该字段；保留供未来"指定全局 stat"场景 |

XML 示例（并入 `Defs/ProfessionalSkills.xml`）：

```xml
<PersonalChronicle.Domain.ProfessionalEffectDef>
  <defName>ProfessionalEffect_ManufacturingWorkSpeed</defName>
  <labelKey>Professional.Effect.ManufacturingWorkSpeed</labelKey>
  <kind>WorkSpeed</kind>
  <value>0.03</value>
</PersonalChronicle.Domain.ProfessionalEffectDef>

<PersonalChronicle.Domain.ProfessionalEffectDef>
  <defName>ProfessionalEffect_QualityBias</defName>
  <labelKey>Professional.Effect.QualityBias</labelKey>
  <kind>QualityBias</kind>
  <value>1</value>
</PersonalChronicle.Domain.ProfessionalEffectDef>
```

> `ProfessionalSkill_PrecisionManufacturing`（领域设计 §3.2 XML）已声明 `effectDefNames` 含上述两效果，无需改动。

## 6. 速度效果链路（WorkSpeed）

### 6.1 注入器（RimWorldAdapter）

`[StaticConstructorOnStartup]` 静态构造时：

1. 构建**效果注册表**：遍历 `DefDatabase<ProfessionalSkillDef>`，收集 `effectDefNames` 中 `kind == WorkSpeed` 的效果 → `skill → (effectDef, value)` 映射。
2. 收集**白名单配方**：每个技能的 `practiceRecipeDefNames`（空=全部相关，与 `RecipeRelevance` 语义一致）→ 命中 RecipeDef 集合。
3. **注入目标 StatDef 去重**：遍历白名单 RecipeDef，取 `recipe.workSpeedStat`（非空）→ 去重。
4. 对每个目标 StatDef：`stat.parts.Add(new StatPart_ProfessionalWorkSpeed { ... })`，static `HashSet<StatDef>` 防重复注入。

> **为何按配方注入而非全局 StatDef**：只有会触发精密制造实践的配方才需要效果，避免污染 `WorkSpeedGlobal` 等被全工作共享的统计。

### 6.2 StatPart 运行时判定（TransformValue）

```text
val（原 workSpeedStat 值）→ 判定 → val *= (1 + Σ 速度效果值)
```

判定链（任一不满足即 return，零影响）：

1. `req.pawn` 非空 且 `req.pawn.Faction?.IsPlayer == true`（非玩家派系零影响，对齐 P1 采集边界）。
2. pawn 拥有**声明了该速度效果**的 ProfessionalSkill，且 `level ≥ 1`（经 Service 查 `CareerData.Professional.skills`）。
3. pawn **正在制造**：`req.pawn.jobs?.curDriver is JobDriver_DoBill jdb` 且 `jdb.job?.bill?.recipe?.defName` 命中该技能的 `practiceRecipeDefNames`。
4. 全部通过 → `val *= (1 + effectDef.value)`。

**性能**：每制造 tick 评估一次。判定 1 为 O(1) 快速失败；判定 2 遍历 skills（量小）；判定 3 用预构建 `recipe → skillEffects` 字典 O(1)。首版不做缓存，观察日志确认无性能问题后 P4 可加 pawn → 效果值缓存。

**UI 一致性**：pawn 空闲（无 DoBill job）时属性面板显示基础值；正在制造命中配方时显示加成值。`ExplanationPart` 返回说明文字"仅制造对应配方时生效"（翻译键）。

### 6.3 效果叠加

同一 pawn 多个技能声明同一效果 → 值相加（Σ）后一次性乘入。P3 首版技能数量少，先实现加法叠加。

### 6.4 品质效果链路（QualityBias）

挂载：**复用 `Patch_GenRecipe.PostProcessProduct` Postfix**，在现有 `RecordCareerProduced(...)` 后追加：

```text
Postfix(product, recipeDef, worker)
  └─ service.RecordCareerProduced(product, recipeDef, worker)   // P1/P2 已有
  └─ service.TryApplyQualityBias(product, recipeDef, worker)    // P3 新增
```

`TryApplyQualityBias` 内部：

1. `product.TryGetComp<CompQuality>()` 为空 → return（无品质物品零影响）。
2. `GetQualityBiasLevels(worker, recipeDef)` → int levels（判定链同 §6.2 步骤 1~2 + recipe 命中该技能 practiceRecipeDefNames）。
3. `levels == 0` → return。
4. `QualityCategory target = ProfessionalEffectResolver.ClampQuality(current, levels)`（Domain 纯函数）。
5. `compQ.SetQuality(target, null)`（public，探针确认）。

**ClampQuality 纯函数**（Domain，可单测）：

```csharp
// QualityCategory 枚举索引：Awful=0, Poor=1, Normal=2, Good=3, Excellent=4, Masterwork=5, Legendary=6
// ClampQuality(Normal, +1) => Good；ClampQuality(Legendary, +2) => Legendary；ClampQuality(Awful, -1) => Awful
```

**为何不调 nonpub `AddLevels`**：`AddLevels` 为 nonpub（探针确认），语义与"索引+clamp"等价，自实现可离线单测且规避反射调用。

**执行顺序风险**：Postfix 在原方法返回后执行，覆盖安全。未来他 mod 也 Postfix 覆盖品质则顺序无契约；本阶段 `[HarmonyAfter]` 可选暂不强加（P1 挂载点无冲突记录）。

## 7. 备选方案与取舍记录

| 决策 | 方案 A（推荐） | 方案 B（备选） | 取舍理由 |
| --- | --- | --- | --- |
| Q1 速度挂载 | **StatPart 注入** `recipe.workSpeedStat` | Harmony Patch `JobDriver_DoBill` 内 workLeft 扣减点 | 引擎原生扩展点（AI-003 优先）；tick 扣减点 IL 不可见（§3.2），Patch 定位风险高；StatPart 自动获得 UI 说明 |
| Q2 品质挂载 | **复用 PostProcessProduct Postfix 事后覆盖** | Patch `QualityUtility.GenerateQualityCreatedByPawn` 偏移 | 前者范围精确（仅制造产物）、零新增 Patch、`SetQuality` public；后者是全局品质入口（下厨/裁缝等也走），需额外上下文判定 |
| Q3 强度初值 | P3 固定 `effectDef.value`（Def 可调），P4 接 Rating | P3 即用 Level 硬算 | 领域设计 §3.3 明确效果强度经 Rating 聚合（P4）；P3 用固定值保链路先行 |
| Q4 品质语义 | **整档偏移**（value=1 → +1 档） | 百分比倾向（如 +2%） | 整档偏移确定性强、可单测、与 clamp 语义一致；百分比倾向需概率模型，P4 再评估 |

## 8. 效果强度与 Rating 的边界（P3 vs P4）

- **P3**：生效值 = `ProfessionalEffectDef.value`（固定）。条件 = 拥有技能 && level ≥ 1 && recipe 命中。
- **P4**：`ProfessionalRatingDef`（熟练/专业/高级/大师）接入后，在 `value` 基础上按档位加权（V2.0 §13 示例：熟练+3% → 大师+10% 速度；品质 +1 档 → +6% 倾向）。
- **预留扩展位**：`ProfessionalEffectResolver.ResolveSpeedFactor` 签名带 `rating` 参数（P4 传入档位），P3 传占位，不影响 P4 接入。
- **数值不冻结**（D5）：P3 用 `value=0.03 / 1` 作为可调初始值，P4 评级数值冻结时统一校准。

## 9. 数据流

```text
【速度】StatWorker 评估 recipe.workSpeedStat（制造 tick）
  └─ StatPart_ProfessionalWorkSpeed.TransformValue(req, ref val)
       └─ ProfessionalEffectService.GetSpeedFactor(pawn, recipe)
            └─ ProfessionalEffectResolver.ResolveSpeedFactor(skills, effects, recipeDefName)
                 └─ val *= (1 + factor)

【品质】GenRecipe.PostProcessProduct（原版设品质）
  └─ Patch_GenRecipe.PostProcessProduct Postfix
       └─ service.TryApplyQualityBias(product, recipeDef, worker)
            ├─ ProfessionalEffectService.GetQualityBiasLevels(worker, recipe)
            │    └─ ProfessionalEffectResolver.ResolveQualityLevels(skills, effects, recipeDefName)
            └─ ProfessionalEffectResolver.ClampQuality(current, levels)
                 └─ compQ.SetQuality(target, null)

【启动】StaticConstructorOnStartup
  └─ ProfessionalEffectRegistry.Build()   // skill→effects 注册表 + 白名单配方 → workSpeedStat 去重注入
```

## 12. 验收标准（对齐 V2.0 §23 闭环）

| # | 验收项 | 通过标准 |
| --- | --- | --- |
| 1 | 速度效果 | 精密制造技能 pawn（level≥1）制造命中配方，`workSpeedStat` 实际提升（DevMode Player.log 或游戏内确认耗时缩短） |
| 2 | 品质效果 | 同一 pawn 产出品质 +1 档；普通 pawn 不变 |
| 3 | 精确性 | 非命中配方 / 非玩家派系 / 无技能 pawn 均零影响 |
| 4 | 持久化 | 存档 → 读档后效果持续 |
| 5 | 原版兼容 | JobDriver/RecipeWorker/RecipeDef 零改动，原版制造流程零侵入 |

**游戏内验收路径**：DevMode → 给 pawn 加精密制造技能（Debug 或真实制造积累）→ 制造 Component → 观察速度/品质 → 存档读档复验。
