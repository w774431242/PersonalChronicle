# 制造类职业资格与荣誉体系设计（P5~P8）

> **状态**：架构设计基线（AI-002 先架构后编码）
> **对齐**：《职业生涯系统开发者指南 V2.0》§14~§20、§22（P5~P8 顺序）、§23（闭环）
> **范围**：制造类垂直切片（精密/武器/装备/工业四个二级方向的资格/Eligibility）
> **落地原则**：Domain 零 Verse 依赖、纯逻辑可 NUnit 离线测试；真实游戏行为形成证据；所有评价回写 CareerEvent 事实 ledger。

---

## 0. 本阶段在全局管线中的位置

```text
P1 制造行为 → CareerEvent（事实）
P2 专业判定 → ProfessionalXP → 专业能力
P3 专业效果（速度/品质）→ 真实制造 → CareerEvent
P4 专业评级（Proficient/Specialist/Senior/Master）
────────── 以下为本设计 ──────────
P5 职业资格 Qualification → 实践考试 → 理论考试
P6 书籍 BookEvidence → 论文 ThesisEvidence → 答辩 DefenseResult
P7 职称授予 TitleGrant → 回写 CareerEvent
P8 成就评价 AchievementEvaluator → 勋章资格 MedalQualification → 授勋 → 回写 CareerEvent
```

核心约束（V2.0 §19/§20）：
- **职业等级不直接等于职称**，必须过 QualificationEvaluator。
- **勋章不直接读专业等级**，必须经 CareerEvent → AchievementEvaluator → HonorEligibility → MedalQualification → 授予 → 回写 CareerEvent。
- 所有"考试/论文/答辩/授勋"成功动作，最终都追加一条 `CareerEvent`（事实数据库）。

## 2. P5-A 职业资格与考试

### 2.1 QualificationDef（Def 数据驱动，禁硬编码）

对齐 V2.0 §14 字段：

```text
QualificationDef
├── defName                // 稳定键，如 Q_Precision_Senior
├── titleDefName           // 对应 ProfessionalTitleDef（P7 授予目标）
├── professionalSkillDefName  // 关联 ProfessionalSkillDef（如精密制造）
├── requiredMinLevel       // 专业等级下限（int）
├── requiredCareerTimeTicks // 职业时长下限（long）
├── requiredEvents         // List<(EventType, count)> 事实门槛
├── requiredAchievements   // List<string> 成就键门槛（P8 产出）
├── requiredPreviousTitle  // 前置职称 defName（可空）
├── requiredExam           // 是否要求实践+理论考试通过
├── requiredThesis         // 是否要求论文通过
├── requiredDefense        // 是否要求答辩通过
├── minimumScore           // 综合评分门槛（float，0~100）
└── order                  // 排序（职称阶梯）
```

### 2.2 资格状态机（V2.0 资格状态机：Locked→Eligible→Preparing→PracticalExam→TheoryExam→Thesis→Defense→Qualified→Granted）

> 注：V2.0 主文 §14 只列 QualificationDef 字段，状态机来自 Summary 中已确认的阶段模型。本设计按该状态机落地。

`QualificationState` 持有每个 `QualificationDef` 的进度：

```csharp
public sealed class QualificationProgress : IExposable

    public bool PracticalPassed;
```

`QualificationEvaluator`（Domain 纯逻辑）输入 `ProfessionalState` + `CareerData` + `ExamData` + `ThesisData` + 已授勋章，输出每个 Def 的 `Eligible / NotEligible(Reason)`。

### 2.3 实践考试（V2.0 §15，真实行为证据）

**反模式**：假"考试按钮"+1。
**正模式**：

```text
报名高级精密制造师
  → 生成实践考试任务（限定 RecipeDef 白名单 + 数量 3 + 最低品质 Excellent + 时限 ticks）
  → Pawn 真实制造（复用 P1 ItemProduced 采集链路）
  → 系统捕获 CareerEvent(EventType=ExamProduced, Metadata={examId, quality})
  → ExamEvidence 聚合（数量/品质/时限内）
  → 评分 → PracticalPassed
```

`ExamData` 结构（实践）：

```csharp
public sealed class PracticalExamRecord : IExposable
{
    public string ExamId;
    public string QualificationDefName;
    public List<string> TargetRecipeDefNames; // 限定配方
    public int RequiredCount;
    public string MinQuality;                  // QualityCategory name
    public long TimeLimitTicks;
    public long StartedTick;
    public int ProducedCount;
    public List<string> ProducedQualities;    // 实际产出品质
    public bool Passed;
    public float Score;                        // 0~100
}
```

评分算法（Domain 纯函数，NUnit 可测）：
- 数量达标率 `q = min(ProducedCount, RequiredCount) / RequiredCount`
- 品质达标率 `qd = 达到 MinQuality 及以上件数 / ProducedCount`
- 时限内 `t = 是否在 StartedTick+TimeLimitTicks 内完成`
- `Score = 100 * q * (0.5 + 0.5*qd) * (t ? 1 : 0.6)`

> **2026-08-19 验收修复（P1-2/P1-3）**：落地时补充两条评分语义——
> 1. **最低品质为硬门槛**：`达到 MinQuality 及以上件数 ≥ RequiredCount` 才可能通过（`ExamScoring.CountAtLeast`），仅靠评分加权（qd 软性扣分）不足以体现"最低品质 Excellent"任务要求；数量够但品质不足时考试**继续**等待更高品质产出。
> 2. **超时即结束**：超时后以当前证据评分（×0.6 罚分）并置 `Finished`，不再继续累计（修复原实现超时后永不评分的卡死问题）；超时后品质硬门槛仍须满足才通过。

> **决策 D-E1（推荐 A）**：实践考试的证据捕获**复用 P1 的 `ItemProduced` 采集点**（Patch_GenRecipe Postfix），通过 `Metadata["examId"]` 关联，不新增独立 Harmony patch。理由：避免重复 patch 同一调用点导致顺序/幂等问题，符合 AI-003 扩展点优先级（复用已有采集点 > 新增 Patch）。

### 2.4 理论考试（V2.0 §16，第一阶段无 AI 问答）

```text
阅读相关书籍(BookEvidence)
+ 研究相关项目(CareerEvent ResearchCompleted)
+ 专业能力(ProfessionalState.Level)
+ 理论考试活动(Reading/Research 行为累计)
  → 理论成绩 TheoryScore
```

`ExamData` 结构（理论）：

```csharp
public sealed class TheoryExamRecord : IExposable
{
    public string QualificationDefName;
    public List<string> RequiredBookTopics;   // 需阅读的书籍主题
    public int RequiredResearchCount;         // 相关研究项数
    public float BookScore;                   // 来自 BookEvidence 覆盖
    public float ResearchScore;
    public float SkillScore;                  // 专业能力折算
    public float ActivityScore;               // 理论考试活动累计
    public bool Passed;
    public float Score;
}
```

`TheoryScore = wBook*BookScore + wResearch*ResearchScore + wSkill*SkillScore + wActivity*ActivityScore`（权重表由 Def 或常量定义，第一阶段建议 `0.4/0.3/0.2/0.1`）。

> **决策 D-E2（推荐 A）**：理论考试第一阶段**不设选择题 UI**，成绩由"书籍证据 + 研究 + 技能 + 理论考试活动"加权合成（V2.0 §16 明确）。后续阶段再补问答 UI。

## 3. P6-A 书籍 / 论文 / 答辩

### 3.1 书籍 BookEvidence（V2.0 §17，理论证据而非道具）

```csharp
    public string Quality;        // 书籍品质
    public string Field;          // 领域（如 精密制造）
```

> **决策 D-B1（推荐 A）**：`BookEvidence` 列表挂在 `CareerData`（事实 ledger 的衍生证据容器），不单独建 PawnObject 顶层字段。

### 3.2 论文 ThesisEvidence（V2.0 §18）

论文不是"+1 Thesis"，而是由以下共同形成质量：

```text
书籍(BookEvidence) + 研究(ResearchCompleted) + 专业成果(ProfessionalState) + 职业履历(CareerData) + 专家参与
  → ThesisEvidence.QualityScore
```

```csharp
public sealed class ThesisEvidence : IExposable
{
    public string ThesisId;
    public string QualificationDefName;
    public List<string> SourceBookIds;     // 引用书籍
    public List<string> SourceResearchEventIds;
    public float BaseQuality;              // 由书籍/研究聚合
    public float ComputedScore;            // 综合论文质量 0~100
    public bool Completed;
    public long CompletedTick;
}
```

`ThesisQuality = 0.4*BookAvg + 0.3*ResearchScore + 0.3*ProfessionalScore`（权重阶段一常量，后续可 Def 化）。

### 3.3 答辩 DefenseResult（V2.0 §18 + 注意项）

```text
论文完成 → 召开答辩活动 → 召集专家（同 faction 高技能 Pawn / 委员） → 委员会评分 → DefenseResult
```

```csharp
public sealed class DefenseRecord : IExposable
{
    public string ThesisId;
    public string QualificationDefName;   // 答辩归属的资格 defName（2026-08-19 验收 P1-4 修复新增；
                                          // 旧存档为空 → 判定回退 ThesisId 匹配，兼容早期 DevTest 数据）
    public List<string> CommitteePawnIds;  // 专家 PawnId
    public float CommitteeScore;           // 委员平均评分
    public float FinalScore;               // ThesisQuality*0.5 + CommitteeScore*0.5
    public bool Passed;
    public long HeldTick;
}
```

> **决策 D-D1（推荐 A，V2.0 §18 注意项）**：答辩"召集专家"第一阶段**不依赖 Ideology/DLC 特定 Activity/Precept API**，改用"同阵营高专业等级 Pawn 自动列为委员 + 玩家在 UI 中确认/指定"的轻量机制。理由：V2.0 §18 明确要求不得假设具体 Activity API 一定存在，需单独验证；第一阶段以最小可运行实现保证闭环。

> **决策 D-D2（推荐 A）**：论文与答辩的"活动"触发点第一阶段以 **ITab footer 按钮组 + Dialog**（沿用 P3-B/P4-B 的 Debug/操作按钮范式，因 `[DebugAction]` 不可用）实现报名/召开，不新增 Harmony patch 游戏原版行为。

## 5. P8-A 成就评价与授勋

### 5.1 接入链路（V2.0 §20）

```text
CareerEvent（事实）
  → AchievementEvaluator（新增：读取 CareerEvent 聚合成就键）
  → HonorEligibility（产出 requiredAchievements 门槛键）
  → MedalQualification（替换现有阈值 MedalAwardEvaluator 单一路径）
  → 授予 MedalGranted
  → 回写 CareerEvent(EventType=MedalGranted)
```

### 5.2 AchievementEvaluator（Domain 新增，纯逻辑）

不读专业等级，只读 CareerEvent 事实聚合：

```csharp
public static class AchievementEvaluator
{
    // 输入 CareerData.Events，输出 成就键 → 值 字典
    public static Dictionary<string, double> Aggregate(PawnObject pawn);
}
```

成就键示例（阶段一，制造类）：
- `MajorProjects`：大型制造项目数（Metadata 标记）
- `LegendaryMade`：传奇品质制造次数
- `LongServiceTicks`：职业时长
- `TitleCount`：已获职称数
- `ExamPassCount`：考试通过数

### 5.3 MedalQualification 与现有 MedalAwardEvaluator 的关系

现有 `MedalAwardEvaluator` 仅支持 `kind=Threshold`（读 PawnObject 累计指标）。本阶段扩展为**双路径**：

1. **Threshold 路径**（保留）：读 PawnObject 指标，阶段一已落地。
2. **Achievement 路径**（新增）：`kind=Achievement`，读 `AchievementEvaluator.Aggregate` 的成就键，匹配 `MedalDef.achievementKey + threshold`。

> **决策 D-M1（推荐 A）**：不重写现有 `MedalAwardEvaluator`，而是**扩展 `MedalDef`** 增加 `kind=Achievement` 分支 + `achievementKey` 字段，在 `EvaluatePawn` 内按 `kind` 分发。理由：零破坏现有阈值勋章（P1~P4 已授勋数据不变），append-only 扩展，符合 AI-005 实现顺序与稳定优先。

> **决策 DISCLOSE（推荐 A）**：勋章授予后回写 `CareerEvent`（EventType 新增 `MedalGranted`，需 PM 批准扩展 CareerEventType 白名单——当前 Allowed 仅 5 种）。**此为 P8 唯一需要突破 P1 白名单的决策点**，默认推荐：扩展白名单追加 `MedalGranted` / `TitleGranted` / `ExamPassed` / `ThesisDefended` 四类评价回写事件（均为事实记录，不承载评价数值，符合 P1 铁律）。
