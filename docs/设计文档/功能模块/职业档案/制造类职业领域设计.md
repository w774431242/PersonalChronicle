## 1. 术语收敛（D4 决策落地）

此前讨论与前端原型使用 `CareerSkill` 概念；V2.0 指南使用 `ProfessionalSkill` 系列。**本设计统一收敛为 ProfessionalSkill 系列**，`CareerSkill` 一词从本 mod 术语表中退役（前端原型文案后续阶段再迁移，不阻塞本设计）。

| 术语 | 英文 | 说明 | 对应 V2.0 |
| --- | --- | --- | --- |
| 一级专业 | `Profession` | 12 类之一（工程/制造/农业/林业/畜牧/医学/武器/矿业/科研/烹饪/艺术/管理） | §3 |
| 二级方向 | `Direction` | 专业下的方向（制造类=精密/武器/装备/工业） | §3/§9 |
| 专业技能 | `ProfessionalSkill` | 方向内的可成长技能（数据驱动 Def） | §4 |
| 专业能力 | `Ability` | 技能拆出的能力维度（制造=加工/精度/工艺/材料/质控） | §3/§8 |
| 专业效果 | `ProfessionalEffect` | 能力对游戏的最终影响（Effect Library） | §10/§11 |
| 专业评级 | `Rating` | 能力水平的职业资格档位（熟练/专业/高级/大师） | §13 |

**层级关系**：`Profession(12) → Direction(每类若干) → ProfessionalSkill(每方向若干) → Ability(每技能若干维度) → Effect(声明拥有)`。

## 2. 领域模型总览

```text
制造类 Profession
└── Direction ×4（精密/武器/装备/工业）
    └── ProfessionalSkill ×N（每方向 1~3 个，如 精密制造）
        ├── SourceSkills     → 原版技能证据（Crafting/Intellectual…）
        ├── PracticeRules    → 实践来源（Recipe/WorkType/Job）
        ├── XP → Level → Ability 成长
        │      └── Ability ×5（加工/精度/工艺/材料/质控）
        │              └── Effect 声明（WorkSpeed/Quality/…）
        └── Statistics       → 履历证据（首次获得/末次实践/实践次数）
```

**事实与评价分离**：`CareerEvent`（事实 ledger，P1 已落地）→ 追加 `RecipeDef`/`Quantity` 字段（D2）；`ProfessionalSkillData`（Pawn 状态模型）在事实之上派生，**绝不反向写回 CareerEvent**。

### 3.2 `ProfessionalSkillDef`（专业技能 — V2.0 §4 核心）

```csharp
public sealed class ProfessionalSkillDef : Def
{
    // —— 定位 ——
    public string profession;                    // 一级专业
    public string direction;                     // 二级方向

    // —— 证据来源 ——
    public List<string> sourceSkills;            // 原版技能 defName 列表（Crafting/Intellectual…）
```

### 3.3 `ProfessionalEffectDef`（专业效果 — V2.0 §10/§11）

**本设计只定义 Def 结构与效果类型枚举；Resolver/Adapter 实现留 P3**（V2.0 §12 明确 P1 效果批只做速度/品质/经验/履历）。

```csharp
public enum ProfessionalEffectKind
{
    WorkSpeed,          // 工作速度修正
    QualityBias,        // 品质倾向修正
    RecipeUnlock,       // 配方资格（P2 批）
    MaterialEfficiency, // 材料效率（P2 批）
    SpecialWork,        // 特殊制造工作（P3 批）
}

public sealed class ProfessionalEffectDef : Def
{
    public ProfessionalEffectKind kind;
    public float value;               // 效果强度（如 0.05 = +5% 速度）
    public string statDefName;        // 目标 StatDef（kind=WorkSpeed 时必填；空=由 Resolver 按上下文解析）
    public string description;        // 效果说明（翻译键）
}
```

> **关键约束**：效果强度不直接读 `ProfessionalSkillData.Level` 硬算，而是**经 Rating 档位聚合后**再决定生效值（V2.0 §13 评级提供少量额外效果 + 软上限），P3 落地。

## 5. XP 计算算法（V2.0 §7 — Domain 纯函数，可单测）

**公式**：

```text
ProfessionalXP(单次实践) =
    基础实践值 × Recipe相关度 × 品质系数 × 难度系数 × 数量系数
```

**各项定义**：

| 系数 | 来源 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 基础实践值 | `ProfessionalSkillDef.xpPerPracticeBase` | 10 | 单次默认 |
| Recipe相关度 | `PracticeRule` 匹配 | 0.0~1.0 | 匹配白名单=1.0；仅 WorkType 匹配=0.5；无匹配=0（不获得该技能 XP） |
| 品质系数 | `QualityCategory` | 见下 | 普通 1.0 / 良好 1.2 / 优秀 1.5 / 大师 3.0 / 传奇 5.0（P3 治理后以 `ProfessionalXpPolicyDef` 数据表为准，含 Good=1.2 档；Evaluator 无表时回退内建表） |
| 难度系数 | Recipe 难度数据 | 1.0 | 第一版固定 1.0，留 Def 扩展位（`xpDifficulty`） |
| 数量系数 | 产出数量 | 1.0 | `Quantity`（批量产出，如 >1 按数量累加，上限 4） |

**品质系数表**（Def 化，可在 `ProfessionalXpPolicyDef` 覆写）：

```csharp
public static float QualityMultiplier(QualityCategory qc)
{
    switch (qc)
    {
        case QualityCategory.Legendary: return 5f;
        case QualityCategory.Masterwork: return 3f;
        case QualityCategory.Excellent: return 1.5f;
        case QualityCategory.Good: return 1.2f;
        default: return 1f; // Normal/Awful/Poor/Shoddy 等
    }
}
```

**边际递减（Level 曲线）**：对齐前端 `skillBase(L)=100×(1−(1−L/20)^1.6)` 的哲学——**等级越高，升一级所需 XP 越多**。XP→Level 采用分段曲线：

## 6. 能力映射矩阵（V2.0 §8 — Domain 纯函数，可单测）

**设计**：每次制造实践，按「RecipeDef → 能力权重表」给各能力分配 XP。矩阵 Def 化，不硬编码。

### 6.1 `AbilityMappingDef`（行为→能力映射，Def 驱动）

```csharp
public sealed class AbilityMappingDef : Def
{
    public List<string> recipeDefNames;      // 匹配的原版 RecipeDef（空=全部制造类）
    public string workTypeDefName;           // 匹配的 WorkTypeDef（制造=crafting）
    public List<AbilityXpWeight> weights;    // 各能力维度权重（和为 100）
    public string mappingKey;                // 映射语义键（如 "PrecisionMachinery"）
}

public sealed class AbilityXpWeight
{
    public string abilityKey;  // 能力维度（machining/precisionControl/processKnowledge/...）
    public float weight;       // 该维度获得本次实践 XP 的比例（0~100，可 >100 表示加权，归一化后按 100 分配）
}
```

**权重归一化规则**：一次实践的技能 XP 总额按 weights 比例拆分到各能力（如总 100 XP → 精度 60 / 工艺 30 / 加工 10）。**每个能力独立累加 `abilityXp`**（V2.0 §8 "各专业能力独立成长"）。

### 6.2 能力维度定义（制造类）

| abilityKey | 中文 | 含义 | 典型获取行为 |
| --- | --- | --- | --- |
| `machining` | 加工能力 | 基本加工操作 | 大多数制造 |
| `precisionControl` | 精度控制 | 精密操作 | 精密机械、电子件 |
| `processKnowledge` | 工艺理解 | 工艺/流程理解 | 复杂配方、研究关联 |
| `materialApplication` | 材料应用 | 材料选择与利用 | 高级材料制作 |
| `qualityControl` | 质量控制 | 品质把控 | 高品质产出/检视 |

**示例映射**（Def XML）：

```xml
<PersonalChronicle.Domain.AbilityMappingDef>
  <defName>Mapping_PrecisionMachinery</defName>
  <recipeDefNames>
    <li>Make_Component</li>
    <li>Make_AdvancedComponent</li>
  </recipeDefNames>
  <weights>
    <li><abilityKey>precisionControl</abilityKey><weight>60</weight></li>
    <li><abilityKey>processKnowledge</abilityKey><weight>30</weight></li>
    <li><abilityKey>machining</abilityKey><weight>10</weight></li>
  </weights>
</PersonalChronicle.Domain.AbilityMappingDef>
```

## 7. 二级方向判定（V2.0 §9 — Domain 纯函数，可单测）

**原则**：推荐 ≠ 强制。玩家最终选择存 `ProfessionalState.primaryDirection`。

**方向分**：

```text
DirectionScore(D) =
    技能相关度 × 0.35
  + 实践适配   × 0.25
  + 实践质量   × 0.15
  + 成果贡献   × 0.15
  + 专业能力   × 0.10
```

| 分量 | 来源 | 说明 |
| --- | --- | --- |
| 技能相关度 | `Pawn.skills.GetSkill` × `ProfessionalSkillDef.sourceSkills` | 原版技能等级经边际递减归一化后按技能权重聚合 |
| 实践适配 | `practiceCount / 320`（对齐前端 practiceNorm） | 方向内实践次数 |
| 实践质量 | 品质加权平均（对齐前端 qualityScore） | 高品质实践提升方向分 |
| 成果贡献 | 能力 XP 相对占比 | 能力强的方向更推荐 |
| 专业能力 | 各能力 `mastery` 均值 | 当前能力水平 |

**输出**：按分数降序的 `DirectionFit[]`，供 UI 渲染（前端 12 专业适配卡片同款交互，后续 P9 ITab 接入）。

### 7.1 二级方向差异化特化点（2026-08-19 新增）

**问题**：方向数据加成雷同——`ProfessionalEffectDef.value` 全局共享（所有引用技能同一数值）、`ProfessionalRatingDef` 权重全局统一（所有技能同一套档位加成）、`ProfessionalDirectionDef` 无数据字段（纯分组标签）。若不治理，"四个方向 = 同一套速度/品质加成"。

**机制**（3 项，全部 append-only Def 字段，不影响存档）：

1. **技能级效果覆盖** `ProfessionalSkillDef.effectOverrides`：`effectDefName + hasValue/value + ratingWeightScale`——同 kind 效果在不同技能拥有差异化数值与评级权重缩放；缺省 = 回退共享值（既有技能零影响）。
2. **方向特化语义** `ProfessionalDirectionDef.specializationKey / specializationDescKey / labelKey`：机器可读特化标识 + 说明翻译键（UI 展示方向差异，未来专属机制挂载点）。
3. **能力权重差异化** `AbilityMappingDef.weights`（§6 已有机制）：方向间能力成长轨迹不同（如精密制造精度权重 50 vs 工业制造工艺权重 40）。

**4 方向特化定位与数据蓝图**（数值为 D5 未冻结示意，随各方向垂直切片经引擎核验后冻结）：

| 方向 | 特化点 | 效果组合（蓝图） | 评级缩放（蓝图） | 能力权重侧重（蓝图） | 成长曲线（蓝图） |
| --- | --- | --- | --- | --- | --- |
| 精密制造 | Quality 品质 | QualityBias 1 档 + WorkSpeed 3%（现状基准） | 品质/速度 ×1.0（现状） | precisionControl 50 / processKnowledge 30 / machining 15 / qualityControl 5 | xpCap 5000 / base 10（慢而稳） |
| 武器制造 | Throughput 产量 | WorkSpeed 覆盖 +5% 级，QualityBias 弱或 0 | 速度 ×1.5 / 品质 ×0 | machining 40 / precisionControl 30 / processKnowledge 20 / qualityControl 10 | xpCap 4500 / base 12（快） |
| 装备制造 | Material 材料 | MaterialEfficiency（V2.0 §12 P2 批预留）+ WorkSpeed 弱 | 材料相关权重（效果落地时定） | materialApplication 40 / qualityControl 30 / machining 20 / processKnowledge 10 | xpCap 5000 / base 10（中） |
| 工业制造 | Volume 批量 | RecipeUnlock（V2.0 §12 P2 批预留）+ WorkSpeed 覆盖 4% | 工艺相关权重（效果落地时定） | processKnowledge 40 / machining 30 / precisionControl 20 / qualityControl 10 | xpCap 5500 / base 11（中快） |

**落地现状**：
- 机制 C# 已实现：`effectOverrides`（`ProfessionalSkillDef`）+ 方向特化字段（`ProfessionalDirectionDef`）+ Resolver 覆盖解析（`ProfessionalEffectResolver`），含离线单测 5 例（覆盖生效/评级缩放/禁用评级/跨效果隔离/品质覆盖）。
- 4 方向 Def 与翻译键已落地（`Defs/ProfessionalSkills.xml` + 中英 Archive.xml：`Profession.Direction.*` 8 键）。
- 武器/装备/工业三方向的**技能 Def 与配方白名单随各自垂直切片落地**（V2.0 §22 不横向铺开），届时按上表配置 `effectOverrides` 与 `AbilityMappingDef`；效果数值按 D5 流程经引擎核验后冻结。

**约束**：
- 所有方向技能 `maxLevel` 保持 50——评级档位阈值（10/25/38/45）全局一致，不随方向变化；方向差异体现在**成长速度**（xpCap / xpPerPracticeBase）与**加成**（effectOverrides）上。
- override 全字段缺省 = 不覆盖（回退共享值），既有技能零影响。

## 8. 数据流（P2 完整链路）

```text
原版 GenRecipe.PostProcessProduct
        ↓  (P1 已落地 Patch_GenRecipe)
ArchiveService.RecordCareerProduced(product, recipe, worker)
        ↓
① CareerEvent 追加 RecipeDefName/Quantity（D2）
② ProfessionalXpEvaluator.Compute(skillDef, recipe, quality, quantity)
        ↓
③ 能力映射矩阵拆分 → abilityXp 独立累加
        ↓
④ ProfessionalState.Skills 更新（XP/Level/Mastery/PracticeCount/LastPracticeTick）
        ↓
Scribe 持久化（PawnObject.CareerData，append-only 不 bump schema）
```

**关键**：① 是事实层追加（只记 recipe 信息，不记评价）；②③④ 是状态层派生（可随时用新曲线重算，不污染事实）。评价规则变更只影响状态层，历史事实永远不变。

## 11. 验收标准（对齐 V2.0 §23 第一条闭环）

**P2 验收闭环**：

```text
【制造类】→【精密制造】→【加工/质控能力】→【制造 XP】→【专业等级】
        ↓
【CareerEvent 含 Recipe/Quantity】→【履历】
```

| # | 验收项 | 通过标准 |
| --- | --- | --- |
| 1 | 制造→事件 | 制造一件物品产生 CareerEvent，含 RecipeDefName + Quantity |
| 2 | 事件→XP | 对应 ProfessionalSkill 获得 XP，品质不同 XP 不同 |
| 3 | XP→能力 | abilityXp 按映射矩阵拆分，独立增长 |
| 4 | 能力→等级 | level 按曲线上升，边际递减成立 |
| 5 | 持久化 | 存档→读档后 Skills 状态完整一致 |
| 6 | 兼容原版 | 原版制造流程零侵入，非玩家派系不记录 |

> 效果（速度/品质修正）属 P3，P2 验收**不含**游戏数值改动。
