- **Change:** 主界面「职业档案」导航移除（嵌入个人档案「生涯」tab）+ 下一职称链倒挂逻辑修复
- **Version:** v1.1.4+（Save Schema 未变，不 bump）
- **Date:** 2026-08-21
- **Reviewer:** AI（静态审计 + 编译/单测复跑）
- **Scope:** `ArchiveMainTabWindow`（Shell/Nav/Cache/PawnWork/主文件）、`ArchiveMainTabWindow.Career.cs`（删除）、`ArchiveUiDataProvider.Detail.cs`、`SectionSnapshots.Career.cs`、`ArchiveSectionSnapshot.cs`、`QualificationEvaluator.cs`、`CareerQualificationTests.cs`、中英 Keyed/Archive.xml + 重建 DLL

## 0. 需求（用户反馈）

主界面「职业档案」导航存在两个问题：

1. **职称倒挂**：人物「当前职称」高于「下一职称」（如当前高级技工、下一职称却显示初级技工），疑似硬编码或逻辑混乱。
2. **导航冗余**：点击「职业档案」导航按钮会跳转到「人物」导航下的个人档案界面（列表行点击 → PawnDetail）。要求：将职业档案界面嵌入个人档案「总览、生涯、战斗履历、社会关系」四个 tab 之中，并移除主界面的「职业档案」导航按钮。

## 1. 根因分析

### 问题一：下一职称倒挂（Read Model 键空间不匹配）

`ArchiveUiDataProvider.FindNextQualification` 判定前置职称时调用 `HasGrantedTitle`，**只比较 `GrantedTitles[].TitleDefName`**（如 `Title_Precision_Junior`）；而 `QualificationDefs.xml` 的 `requiredPreviousTitle` 存的是**资格 defName**（如 `Q_Precision_Junior`）。后果：

- 从第二档起的前置职称链永远判定「未满足」→ 高档次资格全部被跳过；
- 「下一职称」回落到最低档（初级技工），出现 **当前职称（order 2）> 下一职称（order 0）** 的倒挂显示。
- 注：`QualificationEvaluator` 已于 2026-08-19 修复为职称/资格双键匹配（`Qualification_PreviousTitle_MatchByQualificationDefName` 用例），但 Read Model 侧未同步，形成两套判定逻辑。

另外 `FindNextQualification` 缺少「严格高于当前已授最高档」的守卫：即使前置链匹配正确，数据缺失（如 DevTest 只授予单档）时仍可能把低于当前档的资格当作「下一职称」。

### 问题二：导航冗余（v4.16 职业档案总览）

v4.16 在档案馆侧边栏新增「职业档案」入口（殖民地级总览列表），行点击 → `OpenPawnDetail(tabIndex=1)` 直达个人档案生涯 tab。该入口与「人物」分类导航功能重叠，且职业档案内容本就归属个人档案（个人档案四 tab 中的「生涯」tab），独立导航造成「点击职业档案 → 跳入个人档案」的割裂体验。

## 2. 修复方案（按 AI-005 管线顺序）

### 2.1 Domain：职称链判定唯一收口（`QualificationEvaluator.cs`）

- 新增 `HasGrantedTitleKey(cd, key)`：**职称/资格双键匹配**（全模组唯一前置职称判定入口），`EvaluateOne` 内联判定改调此方法（消除双实现）。
- 新增 `NextQualification(cd, defs)`（纯逻辑、可注入 defs 供离线单测）：
  - 候选 = 未授予 + 前置职称已授予（双键；无前置 = 第一档）+ **档位严格高于当前已授最高档**（`QualificationDef.order`）；
  - 取 order 最小者；全部授予 → null（封顶）。
  - 严格高于守卫杜绝任何数据形态下的「当前职称 > 下一职称」倒挂。

### 2.2 Read Model：委托 Domain + 移除殖民地级投影

- `FindNextQualification` 委托 `QualificationEvaluator.NextQualification(cd, DefDatabase...)`；删除本地 `HasGrantedTitle`，`BuildTitleTiers` 改调 `HasGrantedTitleKey`。
- 删除殖民地级 `BuildCareerOverview(service, revision)` 与 `CareerOverviewRowView`（接口 `IArchiveUiDataProvider` 同步移除成员）。

### 2.3 主窗口：移除「职业档案」导航

- 侧边栏移除「职业档案」入口；`MainView.Career` / `GoCareer` / `DrawCareerContent` / `cachedCareerRows` / `careerScroll` / `RefreshCareerCache` 全部删除；`ArchiveMainTabWindow.Career.cs` 整文件删除。

### 2.4 职业档案界面嵌入个人档案「生涯」tab

- `RebuildDetailCache` 缓存 `detail.CareerOverview` → `cachedCareerOverview`（Read Model 快照，窗口只消费，架构 §3.1 G 层边界）；
- `DrawCareerTab` 顶部新增职业档案区块：**职业身份**（当前职称大字 + 方向/技能/工时副行 + 制造/建造/研究/著作/成果 5 指标格）→ **下一职称**（职称名 + 准备度进度条 + 缺口列表/封顶提示）→ **资格状态**（6 条件 2 列网格）；
- `ComputeDetailPanelHeight` Career 分支计入区块高度；复用既有 `Career.Ov.*` 翻译键，无新增键。

### 2.5 本地化

- 删除孤儿键（仅殖民地级总览使用）：`CareerOverview`、`CareerOverviewDesc`、`CareerEmpty`、`ColPawn`、`ColRole`、`ColSkill`、`ColNextTitle`、`NoTitle`、`TitleMaxed`、`NoCareerData`、`PromotionReadiness`（中英同步，11×2）。

## 4. 新增测试用例（CareerQualificationTests）

| 用例 | 断言 |

## 5. 结论

- 职称倒挂根因为 Read Model 前置职称键空间不匹配 + 缺严格高于守卫，已收口 Domain 统一修复，7 条回归用例覆盖。
- 主界面「职业档案」导航整体移除，职业档案界面（职业身份/下一职称/资格状态）嵌入个人档案「生涯」tab，个人档案四 tab（总览/生涯/战斗履历/社会关系）成为职业档案唯一入口。
- 无 P0/P1 风险，无 Save schema 变更，无需 bump 版本。
