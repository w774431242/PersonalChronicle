# 职业生涯系统全链路细化：制造 → CareerEvent → XP → 能力 → 等级 → 评级 → 加成

> 本文基于 `Source/PersonalChronicle` 真实代码梳理，作为《职业生涯系统开发者指南 V2.0》的「纵向链路」补充。
> 横向体系（资格、职称、荣誉等）见同目录其他文档。

## 0. 链路总览

```
[制造行为]
   │  Patch_GenRecipe.Postfix(GenRecipe.PostProcessProduct)       ← 每成品一次
   │  Patch_BillProduction.Postfix(Notify_IterationCompleted)     ← 制造完成
   ▼
[事实层 Domain/Career/CareerEvent]   ItemProduced / BookProduced / 实践考试证据
   │  ArchiveService.RecordCareerProduced / RecordCraftCompleted / RecordExamProduced
   │  → CareerData.Events  (append-only 事实 ledger)
   ▼
[原版技能经验链路 Capture/CraftXpSettlement + Patch_SkillRecord_Learn]
   │  pawn.skills.Learn(workSkill, total)  原生 Passion/学习速率公式生效
   ▼
[状态层 Domain/Profession/ProfessionalState.skills]  ProfessionalSkillData
   │  RecordSkillLearn: xp += / level = LevelFromXp / mastery / abilityXp / practiceCount
   ▼
[评级层 Domain/Profession/ProfessionalRatingEvaluator]  level → ProfessionalRatingDef(minLevel, 软上限)
   │  ratingWeight = rating.workSpeedWeight / qualityBiasWeight / ratingWeightKind
   ▼
[加成层 Domain/Profession/ProfessionalEffectResolver]  value × (1 + ratingWeight)，全方向参与
   │  ProfessionalEffectService.GetSpeedFactor / GetQualityBiasLevels / GetGenericStatFactor
   ▼
[适配注入层 Capture/Effects]
      StatPart_ProfessionalWorkSpeed  → recipe.workSpeedStat
      StatPart_ProfessionalStatBonus → 通用官方 Stat
      Patch_GenRecipe.TryApplyQualityBias → 成品品质档位覆盖
```

## 1. 阶段 0：制造行为捕获（Capture 层）

- **Patch_GenRecipe**（`Capture/Patch_GenRecipe.cs`）：Harmony Postfix on `GenRecipe.PostProcessProduct`（原版 private static，每成品一次，带成品 `Thing` 参数——最稳定的 per-product 采集点）。
  - 双职责：① `service.RecordCareerProduced(...)` 写 `ItemProduced` 事实；② `TryApplyQualityBias(...)` 事后覆盖成品品质。
  - 启动 `ProbeTargetMethod` 校验原版签名未漂移（失败仅 `Log.Error`，Patch 静默失效防护）。
- **Patch_BillProduction**（`Notify_IterationCompleted`）：制造完成统一回调，覆盖 `GenRecipe` 之外的长尾制造路径。
- 过滤：仅玩家派系 humanlike（`ChronicleColonistScanner.TryClassifyCurrent`），防污染/重复。

## 2. 阶段 1：事实层 CareerEvent（Domain/Career）

- 只记**事实**（人物/时间/物品Def/品质/技能/recipe/数量），绝不写评价字段。
- 落 `CareerData.Events`（append-only）+ `RecordCountByType` 聚合计数；与通用 `ChronicleEvent` 解耦（职业事实 ledger 独立）。
- 同采集点并行捕获书籍证据（`BookProduced` + `BookEvidence`）与实践考试证据（零新增 Patch）。
- 书籍/考试证据用于资格（V2.0 §17）与实践考试评分，是后续「资格状态机」的输入。

## 3. 阶段 2：原版技能经验链路（XP 注入机制 v2.3/v2.4）

**问题**：原版制造经验为 tick 制——`DoRecipeWork` 每 tick `SkillRecord.Learn(0.1/...)`，若直接分流会数值爆炸/触碰每日衰减。

**方案：CraftXpSettlement 整件结算制**
1. `Patch_SkillRecord_Learn` Prefix：制造 job（`JobDefOf.DoBill`）期间的 Learn 调用被**拦截缓存**（不写原版、不分流职业 XP）。
2. 制造完成（`Notify_IterationCompleted`）时 `CraftXpSettlement.Flush` 一次性 `pawn.skills.Learn(workSkill, total)` → 原版 Passion/学习速率公式对**总量**自动生效。
3. 之后 `SkillRecord.Learn` Postfix 一次性分流职业 XP（`ArchiveService.RecordSkillLearn`）。
4. 产出导向、无双重计数；制造中途取消则缓存随 job 变化重置丢弃。

**白名单防误拦截**（`CraftXpSettlement`）：`ManufacturingSkillNames = {Cooking, Crafting}`（v2.4.1 由黑名单改为**白名单**，根绝「手术配方 workSkill=Medicine 被误纳入制造集 → 医疗经验丢失」bug）。

## 4. 阶段 3：状态层 ProfessionalState / ProfessionalSkillData（Domain）

- **ProfessionalState**（落 `CareerData.Professional`，`IExposable`）：
  - `primaryDirection`：主方向（玩家选择，V2.0 §9 推荐≠强制）。
  - `skills`：已获专业技能列表（按 defName 唯一）。
  - `practiceCountBySkill`：分技能实践计数。
- **ProfessionalSkillData**（append-only，能力 XP 只增不减，绝不反向写回 CareerEvent）：
  - `skillDefName` / `xp` / `level`(由曲线派生，持久化便于显示) / `mastery`(0~100) / `firstAcquiredTick` / `lastPracticeTick` / `practiceCount`
  - `abilityXp`：能力维度 XP（按 `AbilityMappingDef` 权重拆分，**独立成长** V2.0 §8）
  - `xpBySource`：原版来源技能精确拆分（供浮层来源占比）
  - `statistics`：扩展统计（各品质制造次数等）

## 5. 阶段 4：XP → 等级（Domain/Profession/ProfessionalXpEvaluator）

- **单次实践 XP**：`baseValue × recipeRelevance × qualityMultiplier × difficulty × q^0.8`
  - 数量系数 `q^0.8` 衰减（×4 批量仅 ~2.3 倍收益），抑制专做批量配方刷级。
  - 品质系数表**数据驱动**（`ProfessionalXpPolicyDef.qualityMultipliers`，回退内建表）。
- **等级曲线（通用参数化）**：`xpAtLevel(n) = xpCap × (n/maxLevel)^curvePower`
  - `curvePower` **全局统一调用 `ProfessionalXpPolicyDef.DefaultCurvePower`**（无则回退 1.6），禁止写死 `"ProfessionalXpPolicy_Manufacturing"`。
  - `curvePower > 1` 升级成本递增（温和 1.6）。
- `LevelFromXp(xp, maxLevel, xpCap, curvePower)` → 整数等级；`MasteryFromLevel = level/maxLevel × 100`。

## 6. 阶段 5：等级 → 评级（Domain/Profession/ProfessionalRatingEvaluator）

- `ResolveRating(level)`：取「阈值 `minLevel ≤ level` 的最高档位」(`order` 最小)；未达最低 `minLevel` → `null`（无评级、无额外效果，退回 P3 行为）。
- `ProfessionalRatingDef`：含 `minLevel`（阈值）+ 各 kind 权重（`workSpeedWeight` / `qualityBiasWeight` / 通用 `ratingWeightKind`）。
- **软上限封顶**：高等级不再线性增权重。

## 7. 阶段 6：评级 → 数值加成（Resolver + Application/Effects）

- `ProfessionalEffectService.GetSkills(pawn)` 返回 **全部方向**技能列表（**不筛 `primaryDirection`**）。
- 三类解析逻辑一致（`ProfessionalEffectResolver`）：
  - `ResolveSpeedFactor` → `GetSpeedFactor`
  - `ResolveQualityLevels` → `GetQualityBiasLevels`
  - `ResolveStatBonus`（StatBonus/CombatStat/YieldBonus 各 kind 独立聚合后**相乘**）→ `GetGenericStatFactor`
- 核心公式：`bonus += baseValue × (1 + ratingWeight)`，其中 `ratingWeight` 由 `level` 经 `ProfessionalRatingDef` 派生（软上限封顶）。
- **生效硬条件**：
  - `level < 1` → 跳过（无等级无加成）
  - `recipe` 必须命中技能白名单（`practiceRecipeDefNames` / `practiceWorkTypeDefNames`），否则等级再高也不加成。
- **关键结论**：
  - 任何**二级方向**练到 `level≥1` 且配方命中其白名单即按等级贡献加成 → 二级方向专业等级**会影响**数值加成。
  - `primaryDirection`（主方向）**不影响**数值加成（仅影响称号徽章/资格状态/UI 高亮）。
  - 多方向同命中同一配方 → 加成**加法叠加**。

## 8. 阶段 7：加成注入适配（Capture/Effects）

`ProfessionalEffectRegistry`（`[StaticConstructorOnStartup]`）：
1. 索引全部 `ProfessionalEffectDef`（`EffectDefs`）+ `ProfessionalRatingDef`（`RatingDefs`）。
2. `CollectTargetStats`：
   - WorkSpeed → 技能白名单配方的 `recipe.workSpeedStat`
   - 通用（StatBonus/CombatStat/YieldBonus）→ `effectDef.statDefName` 指向的官方 `StatDef`
3. `InjectInto`：WorkSpeed 目标注入 `StatPart_ProfessionalWorkSpeed`；通用目标注入 `StatPart_ProfessionalStatBonus`（`priority=100`，在原生 StatPart 之后评估）。
4. `EnsureInjected`：DevMode Def reload 后幂等补注入（引擎重建 `StatDef.parts` 会丢失本 Mod 的 StatPart）。

- `StatPart` 在 `pawn.GetStatValue(stat)` 时调 `ProfessionalEffectService.GetSpeedFactor` / `GetGenericStatFactor`。
- 品质覆盖：`Patch_GenRecipe.TryApplyQualityBias` → `GetQualityBiasLevels` + `ClampQuality`（原版设好品质后事后覆盖档位）。

## 9. 关键设计铁律

| 铁律 | 说明 |
|---|---|
| 事实/状态分离 | `CareerEvent` append-only；`ProfessionalSkillData` 由事实派生，绝不反向写回 |
| 数据驱动禁硬编码 | 曲线幂指数统一 `DefaultCurvePower`；评级/效果/品质系数全 Def 化 |
| 全方向参与加成 | `GetSkills` 不筛主方向；主方向仅 UI/称号用途 |
| 产出导向无双重计数 | 整件结算制（CraftXpSettlement） |
| 白名单防误拦截 | 制造技能白名单 `{Cooking, Crafting}` |
| 静默失效防护 | Patch 启动校验原版签名 |
| Domain 可单测 | Resolver/Evaluator 零 `Verse/RimWorld` 依赖 |

## 10. 已知约束 / 易混淆点

- **职业 XP 由「原版技能经验链路」驱动**（v2.1 起不再由制造事实直接派生）+ 实践考试/书籍证据；制造 `RecordCareerProduced` 仅保留事实 ledger / 书籍 / 实践考试三线。
- **能力维度**（`abilityXp`）独立于技能 XP 成长（方向映射矩阵 `AbilityMappingDef`）。
- 评级软上限、加成叠加上限见具体 Def 配置（`ProfessionalRatingDef` / `ProfessionalEffectDef`）。
- 主窗口生涯 Tab 不应渲染职业档案区块（职业体系内容归 `ITab_Pawn_Career`）；若某人物偶发显示，系历史嵌入区块未清理所致，已移除（见 v1.1.x 修复记录）。
