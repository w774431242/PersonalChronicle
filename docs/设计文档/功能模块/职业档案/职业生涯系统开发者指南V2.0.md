# 《职业生涯系统开发者指南》V2.0

> **状态**：正式规范基线（2026-08-16 定稿）
> **定位**：开发规范，不是产品介绍。
> 本指南在现有职业档案 ITab 数据契约（`职业档案ITab数据契约v0.1.md`）与 P1 CAREER-001 事实层（`Domain/Career`）的基础上，将原有"职业履历—资格—考试—论文—答辩—职称—勋章"管线进一步落到**专业技能与 RimWorld 实际游戏行为**层。职业系统应把原版真实行为转化为事实档案，再进入评价、资格认证、考试/论文/答辩、职称和勋章。

# 2. 第一原则：职业系统不替代 RimWorld 原版技能

必须严格区分：

```text
原版 Skill
        ↓
专业能力来源
        ↓
职业专业技能
```

例如：

```text
Crafting 16
Construction 14
Intellectual 12
```

不能直接等于：

```text
制造专业 = 14
```

而应该：

```text
Crafting
+
Construction
+
Intellectual
+
真实制造行为
+
制造成果
+
职业履历
        ↓
制造类专业能力
```

因此：

> **原版 Skill 是基础能力证据，Professional Skill 是职业系统自己的长期能力模型。**

# 3. 专业体系四层结构

制造类作为第一个完整垂直切片。

```text
制造类
│
├── 一级专业
│
│   制造类
│
├── 二级方向
│   ├── 精密制造
│   ├── 武器制造
│   ├── 装备制造
│   └── 工业制造
│
├── 专业能力
│   ├── 加工能力
│   ├── 精度控制
│   ├── 工艺理解
│   ├── 材料应用
│   └── 质量控制
│
└── 专业效果
    ├── 工作速度
    ├── 品质倾向
    ├── 材料效率
    ├── 配方资格
    └── 特殊工作
```

# 4. ProfessionalSkillDef

专业技能必须数据驱动。

```csharp
ProfessionalSkillDef
```

建议字段：

```text
defName
label
description

profession
direction

sourceSkills
practiceRules

xpCurve
levelCurve

effectDefs
qualificationTags
```

例如：

```text
PrecisionManufacturing

Profession:
Manufacturing

Direction:
Precision

SourceSkills:
Crafting
Intellectual

Practice:
PrecisionRecipe

Effects:
WorkSpeed
Quality
RecipeUnlock
```

**禁止：**

```csharp
if (skill == "PrecisionManufacturing")
{
    ...
}
```

把所有职业规则硬编码进 C#。

现有设计同样要求资格规则数据驱动，而不是把职称条件全部写死。

---

# 5. ProfessionalSkillData

`Def` 定义"技能是什么"。

`Data` 保存"Pawn 现在是什么状态"。

```text
ProfessionalSkillData
│
├── SkillDef
├── XP
├── Level
├── Mastery
├── FirstAcquiredTick
├── LastPracticeTick
├── PracticeCount
└── Statistics
```

例如：

```text
张三
制造类
精密制造

XP        12,480
Level       27
Mastery     64
实践次数     318
```

# 6. 制造实践采集管线

制造类必须优先利用你当前 P1 已经建立的 `CareerEvent` 思路。

```text
Pawn开始制造
      ↓
原版Recipe / Job执行
      ↓
产品生成
      ↓
捕获制造结果
      ↓
CareerEvent
```

事件至少保存：

```text
PawnId
Tick
EventType
RecipeDef
ThingDef
Quality
Quantity
```

当前职业档案设计已经强调"事实记录"与"评价"分离，因此 CareerEvent 不应直接保存"这个人很优秀"之类评价。

---

# 7. 制造专业 XP 计算

不要：

```text
制造一次 = +10 XP
```

应该根据实践内容产生权重。

```text
ProfessionalXP =
基础实践值
× Recipe相关度
× 制作品质系数
× 难度系数
× 数量系数
```

例如：

```text
普通机械部件
基础 XP = 10

优秀机械部件
基础 XP × 1.5

大师级机械部件
基础 XP × 3

传奇机械部件
基础 XP × 5
```

但 **XP 与最终游戏加成必须分离**。

---

# 8. 专业能力计算

制造类：

```text
制造类
│
├── 加工能力
├── 精度控制
├── 工艺理解
├── 材料应用
└── 质量控制
```

制造一次物品不应该让五项能力全部等量增长。

例如：

```text
普通武器制造
→ 加工能力 +XP
→ 工艺理解 +XP
→ 质量控制 +少量XP
```

精密机械：

```text
精密机械
→ 精度控制 +大量XP
→ 工艺理解 +大量XP
→ 加工能力 +XP
```

因此：

> **实践行为 → 能力映射矩阵 → 各专业能力独立成长。**

---

# 9. 二级方向判定

制造类不是一个单一职业。

```text
制造类
│
├── 精密制造
├── 武器制造
├── 装备制造
└── 工业制造
```

方向分数建议由：

```text
原版技能相关度
+
实践次数
+
实践质量
+
成果
+
专业能力
```

计算。

例如：

```text
张三

精密制造   82
武器制造   64
装备制造   57
工业制造   71
```

因此系统可以推荐：

```text
推荐方向：
精密制造
```

但 **推荐方向 ≠ 强制选择方向**。

# 10. Effect Library

专业能力不要直接修改游戏。

中间增加：

```text
ProfessionalEffect
```

例如：

```text
Effect Library
│
├── WorkSpeedEffect
├── QualityEffect
├── RecipeUnlockEffect
├── MaterialEfficiencyEffect
├── FailureReductionEffect
└── SpecialWorkEffect
```

专业技能只声明：

```text
我拥有哪些 Effect
```

Effect 再决定：

```text
如何影响 RimWorld
```

这样以后增加：

```text
农业
医学
矿业
林业
畜牧
```

无需重写专业技能核心。

---

# 11. RimWorld 效果适配层

这是最容易失控的部分。

必须独立：

```text
ProfessionalEffect
        ↓
EffectResolver
        ↓
RimWorldAdapter
        ↓
原版系统
```

而不是：

```text
ProfessionalSkill
        ↓
直接 Harmony Patch 全世界
```

根据现有开发规范，AI 实现时应优先遵循：

```text
原版 XML
↓
DefModExtension / Comp / Component
↓
目标程序集公开能力
↓
必要时 Harmony
↓
最后才是 Reflection / 私有内部实现
```

这一优先级也与已有 1.6 Modding 资料一致。

# 12. 制造类第一批效果

建议只做：

### P1

```text
制造工作速度
制造品质影响
专业经验获取
职业履历记录
```

### P2

```text
专业配方资格
材料效率
特定制造工作
```

### P3

```text
特殊制造行为
专业工具
专业工作台
```

不要第一阶段就同时修改几十种原版生产机制。

# 13. 专业评级

评级不是专业技能等级。

```text
专业能力 Level
        ↓
能力水平

专业评级
        ↓
职业资格等级
```

例如：

```text
专业能力  Lv.35

评级：
熟练制造师
```

评级可以提供少量额外效果：

```text
熟练
→ 制造速度 +3%

专业
→ 制造速度 +5%
→ 品质倾向 +2%

高级
→ 制造速度 +8%
→ 品质倾向 +4%

大师
→ 制造速度 +10%
→ 品质倾向 +6%
```

评级必须有**软上限/递减设计**，避免专业等级无限增长最终造成游戏数值失控。

---

# 14. 专业 → 职称

职业系统不要把：

```text
专业等级 50
```

直接转换成：

```text
高级工程师
```

应该进入资格系统：

```text
ProfessionalState
       ↓
QualificationEvaluator
       ↓
是否满足资格
```

资格定义：

```text
QualificationDef
├── RequiredProfessionalLevel
├── RequiredCareerTime
├── RequiredEvents
├── RequiredAchievements
├── RequiredPreviousTitle
├── RequiredExam
├── RequiredThesis
├── RequiredDefense
└── MinimumScore
```

这与现有设计的 `QualificationDef` 保持一致。

# 15. 实践考试

这是制造类最重要的考试。

**不要制作一个假的"考试按钮"。**

原有设计已经明确要求实践考试必须由真实游戏行为形成证据。

例如：

```text
申请高级精密制造师
        ↓
报名
        ↓
生成实践考试任务
        ↓
要求：
制造指定物品 × 3
最低品质 Excellent
限定时间
        ↓
Pawn真实生产
        ↓
系统捕获 CareerEvent
        ↓
ExamEvidence
        ↓
评分
```

这样玩家真正是在：

> **玩游戏的过程中参加考试。**

---

# 16. 理论考试

第一阶段不要做复杂 AI 问答。

RimWorld 原版不存在通用答题考试机制，这部分本身就是 Mod 自定义系统。现有设计也建议第一阶段采用"知识准备 + 技能 + 研究/书籍证据 + 考试活动"。

因此：

```text
阅读相关书籍
+
研究相关项目
+
专业能力
+
理论考试活动
        ↓
理论成绩
```

后续再增加真正的选择题/问答 UI。

---

# 17. 书籍

书籍应该成为**理论证据**，而不是简单的"考试道具"。

建议：

```text
BookEvidence
├── BookThingId
├── AuthorPawnId
├── Topic
├── Quality
├── Field
├── CreatedTick
└── Relevance
```

已有设计已经采用这一方向。

---

# 18. 论文与答辩

最终：

```text
专业实践
    ↓
论文选题
    ↓
写作/制作书籍
    ↓
形成 ThesisEvidence
    ↓
召开论文答辩活动
    ↓
召集相关专家
    ↓
委员会评分
    ↓
DefenseResult
```

论文不是：

```text
点击"写论文"
→ +1 Thesis
```

而应尽量利用：

```text
书籍
研究
专业成果
职业履历
专家参与
```

共同形成论文质量。

> 注意：利用 Ideology/DLC 的活动机制组织专家答辩，从游戏体验上合理，但**代码实现上必须单独验证目标版本中可复用的活动入口和生命周期**，不应在架构阶段假设某个具体 Activity/Precept API 一定存在。

# 19. 职业履历是整个系统的"事实数据库"

最终所有系统都回写：

```text
CareerEvent
```

例如：

```text
5510
制造优秀机械部件

5511
完成大型机械项目

5511
发表专业著作

5512
通过高级工程师实践考试

5512
通过理论考试

5513
论文答辩通过

5513
获得高级工程师职称

5515
获得技术先进个人勋章
```

因此履历不是 UI 日志。

它实际上是：

> **整个职业系统的长期事实来源。**

# 20. 勋章系统接入

勋章不要读取专业等级直接授予。

正确：

```text
CareerEvent
      ↓
AchievementEvaluator
      ↓
HonorEligibility
      ↓
MedalQualification
      ↓
授予
      ↓
CareerEvent
```

例如：

```text
连续完成重大制造项目
+
传奇品质制造
+
长期职业贡献
        ↓
技术贡献类勋章资格
```

授予后：

```text
MedalGranted
```

再次写入 CareerEvent。

于是形成闭环：

```text
职业行为
 ↓
职业能力
 ↓
职业成果
 ↓
职业资格
 ↓
职称
 ↓
长期贡献
 ↓
勋章
 ↓
履历
```


# 23. 第一条真正应该验收的完整闭环

不要先做 20 个职业。

只验收：

```text
【制造类】
    ↓
【精密制造】
    ↓
【加工能力 / 质量控制】
    ↓
【制造 XP】
    ↓
【专业等级】
    ↓
【制造速度 / 品质效果】
    ↓
【真实制造】
    ↓
【CareerEvent】
    ↓
【履历】
```

如果这条链能够在 RimWorld **真实运行、存档、读档、重复制造、兼容原版工作流程**，才说明专业技能架构成立。

之后再把：

```text
精密制造
武器制造
装备制造
工业制造
```

逐步扩展。

**核心判断标准只有一个：**

> 玩家看到的不是"制造类 72/100"这个数字，而是"这个 Pawn 因为真实做过这些工作，所以形成了某种专业能力；专业能力又真实改变了他下一次工作的结果"。

这才是职业系统从"数据面板"进入"游戏机制"的分界线。

# 决策记录（2026-08-16）

本次评审会（PM 确认）追加的架构决策，作为后续实现阶段的约束：

- **D1 - 指南处置**：本指南作为职业系统后续阶段（P2+）的**规范基线**，以本文档为准，与 `职业档案ITab数据契约v0.1.md` 并行。
- **D2 - CareerEvent 字段缺口**：指南 §6 要求事件含 `RecipeDef`/`Quantity`，P1 契约已有 `DefName`(=ThingDef)/`Quality` 但缺二者。决策=**P2 阶段追加可选字段**（`RecipeDef`/`Quantity`），append-only，旧存档事件为 null 兼容，不 bump Schema Version（沿用 v1.1.4 工坊/住所先例）。
- **D3 - 基础文档**：原引用的《职业生涯开发设计详细文档》在 docs 下不存在；确认**不再补建**，以本指南 + `职业档案ITab数据契约v0.1.md` 为职业系统双基线。
- **D4 - 命名对齐（待 P2-A 细化）**：指南使用 `ProfessionalSkillDef`/`ProfessionalSkillData`/`ProfessionalEffectDef`/`QualificationDef` 命名体系，与此前讨论的 `CareerSkill` 概念的关系需在 P2-A《领域设计》中收敛（建议统一为 ProfessionalSkill 系列，避免术语漂移）。
