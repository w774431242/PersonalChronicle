# 基础设施体系之电力体系方案

日期：2026-10-06。版本：拟定稿 v0.1。适用项目：殖民地综合管理系统。游戏基线：**RimWorld 1.6.4871 rev590**（`RimWorld/Version.txt` 实测）。

本稿是 [T1 基础设施补全设计方案](AUTO-2026-10-06-T1基础设施补全设计方案.md) 的**电力分册**：主稿给出 14 种设施的总表与首轮数值，本稿把其中的**能源（发电、储能、配电）**展开成子系统级方案——口径、拓扑、平衡模型、燃料循环、失效语义、读数接入与验收。

本稿交付玩法与工程边界、建议数值与待确认点；**尚未增加运行 Def、代码或游戏贴图**。凡本稿未亲自取证的数字都标「待确认」，不写成已实装或已实机验证。

## 1. 定位与范围

### 1.1 与主稿的关系

| 维度 | 主稿（T1 基础设施补全） | 本稿（电力体系） |
|---|---|---|
| 范围 | 14 种设施的总表、批次、美术入口 | 只做「源—储—配—荷—测」链，共 4 台设备 |

## 2. 语汇与单位口径

### 2.1 七个语汇

| 语汇 | 含义 | 不指 |
|---|---|---|
| 源 | 向电网输出功率的设备（燃油机、光伏） | 不指「抵扣型」净耗电设备 |
| 储 | 以 Wd 累计能量的设备（蓄电池组） | 不指燃料箱（燃料箱是物品库存） |
| 配 | 只传导、不产出不消费的节点（导线、配电柜、开关） | 不指「电力管理器」 |
| 荷 | 消费功率的设备（10 台生产台 + 灯 + 冷却器 + 炼制台 + 研究台 + 冷藏柜） | 不指待机自放电之外的损耗 |
| 网 | 一张 `PowerNet`（一个连通分量） | 不指全地图电网 |
| 测 | 对某张网的读数（净收支、已储、容量） | 不指对单台设备的读数 |
| 控 | 由人执行的隔离动作（拨配电柜） | 不指自动控制 |

### 2.2 三个单位

| 单位 | 含义 | 换取方式 |
|---|---|---|
| **W**（瓦） | 瞬时功率 | 电网净收支、单台功耗/输出 |
| **Wd**（瓦·日） | 能量：1 W 持续 1 游戏日 | 电池容量、已储电量 |
| **Wd/tick** | 引擎内部量 | **只在换算点内部出现，禁止外泄到 UI** |

1 游戏日 = 60000 tick，故 `CompPower.WattsToWattDaysPerTick = 1/60000`（项目内已核实，见 `PowerGridReading` 类注释）。

### 2.3 唯一换算点（代码事实）

`Source/PersonalChronicle/Domain/PowerGridReading.cs` 是本工程电网读数的**唯一换算点**，三条口径已固化：

```27:39:Source/PersonalChronicle/Domain/PowerGridReading.cs
        internal static float NetWatts(PowerNet net)
        {
            return net == null ? 0f : net.CurrentEnergyGainRate() / CompPower.WattsToWattDaysPerTick;
        }

        internal static float StoredWattDays(PowerNet net)
        {
            return net == null ? 0f : net.CurrentStoredEnergy();
        }
```

本稿的电力设备**不新增第二套换算**：任何新读数（水位、状态判定）都必须扩在这一个类里，不得各处手写。

### 2.4 三条硬口径

1. **净收支 W = `CurrentEnergyGainRate() / WattsToWattDaysPerTick`**。直接把 `CurrentEnergyGainRate()` 当 W 取整会恒为 0（2026-09-13 实机缺陷，顶栏显示 `电网 0W · 0Wd`）。
2. **已储 Wd 用 `CurrentStoredEnergy()`，不自遍历电池列表**——该方法会**排除被 EMP 眩晕的电池**，自遍历会多算。
3. **容量必须反推**：原版没有「总容量」字段，容量 = Σ(`StoredEnergy` + `AmountCanAccept`)。无电池时容量为 0，调用方**走「无储能」降级，不得画成 0% 水位**（`PowerGridReading.CapacityWattDays`）。

### 3.1 原版事实基线（本机 `Data/Core/Defs/ThingDefs_Buildings/Buildings_Power.xml` 实测）

| 类型 | defName | 关键事实 |
|---|---|---|
| 导线 | `PowerConduit` | `isPowerConduit=true`；`CompPowerTransmitter`；1 钢；工作量 35；HP 80；`rotatable=false`；`neverMultiSelect=true` |
| 暗线 | `HiddenConduit` | 继承导线；2 钢；工作量 280；HP 100；不吃攻击伤害 |
| 防水线 | `WaterproofConduit` | 继承导线；10 钢；地形要求 `WaterproofConduitable` |
| 开关 | `PowerSwitch` | `thingClass=Building_PowerSwitch`；`CompPowerTransmitter` + `CompProperties_Flickable`；`allowWireConnection=false`；`passability=Standable`；HP 120；工作量 200；15 钢 + 1 零件；`rotatable=false` |
| 燃油机（原型） | `ChemfuelPoweredGenerator` | 2×2；−1000 W；`CompPowerPlant`；`fuelConsumptionRate 4.5`；`fuelCapacity 30`；`Flickable` + `Glower(80,112,180)` + `HeatPusher(6/s)` + `Breakdownable` + `Stunnable` + `Explosive`；`graphicClass=Graphic_Single`；`rotatable=false` |
| 光伏（原型） | `SolarGenerator` | 4×4；−1700 W；`CompPowerPlantSolar`；`graphicClass=Graphic_Single`；`rotatable=false`；建造技能 6 |
| 电池（原型） | `Battery` | 1×2；`storedEnergyMax 600`；`efficiency 0.5`；`shortCircuitInRain=true`；`Breakdownable` + `Stunnable`；`graphicClass=Graphic_Multi`；**未声明 `rotatable` ⇒ 取默认 `true`** |
| 风电 / 地热 / 水电 | `WindTurbine` / `GeothermalGenerator` / `WatermillGenerator` | −2300 / −3600 / −1100；本轮沿用，不做 T1 版本 |

`CompProperties_Battery` 在 1.6.4871 rev590 **只有两个字段**：`storedEnergyMax`、`efficiency`（Cecil `type RimWorld.CompProperties_Battery full`）。自放电**不在 Def 里**：`CompPowerBattery.CompTick()` 的 IL 是 `DrawPower(Mathf.Min(5f × WattsToWattDaysPerTick, storedEnergy))` ⇒ **恒定 5 W 口径**（Cecil `il RimWorld.CompPowerBattery Tick full`）。主稿的「约 5 W 自放电」据此确认为事实。

### 3.2 连通即并网

原版不区分「发电母线 / 用电支路」：**相邻的输电体自动并成一张网**。发电与储能建筑自身 `transmitsPower=true`，本身就是输电体——两台燃油机放在一起会**自动联网**，不需要导线。导线只解决「跨越距离」。

⇒ 设计含义：**不要为「并机」设计建筑**；主稿的「两台机组」就是两台 `PC_T1_FuelGenerator` 相邻摆放。

### 3.3 隔离的实际条件（旁路陷阱）

配电柜是 `CompPowerTransmitter` + `Flickable`，与导线同类。断开只影响「**必须经过本节点**才能到达的那部分建筑」：

- 若被断开的支路存在并联旁路（第二条导线、或另一台发电建筑直接相邻），**断开无效**；
- 不能凭「位于车间」切断区域内所有建筑——区域是房间概念，电网是连通概念，两者不重合。

⇒ 设计含义：车间布线应做成**辐射形（星形）**，一个配电柜下只挂一条支路；环形布线会让配电柜的开关失去隔离能力。这是玩家侧布线约定，本稿只写明，不做自动检查。

### 3.4 共享读数的去重义务

功率、已储、容量都是**网的属性**，不是配电柜的属性：

- 多个配电柜读到同一张网时**不得重复累计**；
- 生产台清单里已展示「本台所在网」的储能（`WorkshopFloorViewProvider.Detail.cs`），数据层再列全网时**不得与之相加**；
- 主稿 §9 的「禁止货架库存 + 同格物品 + 管道在途重复累计」在电力侧的同构条款是：**禁止「配电柜读数 + 该柜所在网读数」重复累计**。

### 3.5 屋顶、墙体与导线

- 导线可**穿墙、穿建筑**（`clearBuildingArea=false`、`PlaceWorker_Conduit`），不需要为布线开门；
- 屋顶**不阻断**导电，只影响光伏（见 §4.4）；
- 雷暴会触发短路事件（`shortCircuitInRain`）——注意 T1 十台生产台自身已声明 `shortCircuitInRain=true`（`Defs/T1_Production.xml` 实测），即**用电侧也会短路**，不只是电池。

### 4.3 智能燃油发电机

- 复用 `CompPowerPlant` + `CompProperties_Refuelable` + `CompProperties_Flickable` + `Breakdownable` + `HeatPusher` + `Stunnable`。无燃料 / 损坏 / 关闭时输出为 0。
- **组件显式声明纪律**：`Flickable`（§7.1 的「关闭」态与 §9.3 的关闭词依赖它）、`Glower`、`HeatPusher`、`Explosive` 四者都必须在新 Def 里**逐项写明有无**，不允许「继承得来、设计文档里没写」。各自取舍见 §7.2。
- 补燃料**不自动从全地图吸取**；`showAllowAutoRefuelToggle` 的既有语义沿用原版，玩家可关。
- ⚠ **爆炸继承（裁决项）**：原型带 `CompProperties_Explosive`（`explosiveExpandPerFuel 0.95`、`Flame`、`destroyThingOnExplosionSize 2`、`preExplosionSpawnThingDef Filth_Fuel`、`wickTicks 70~150`）。直接抄原型 comps ⇒ 燃油机会**在低血被摧毁时爆炸起火并洒燃料**。主稿未提该组件，见 §7.2。
- ⚠ **可旋转**：原型 `rotatable=false`。本批有四向美术 ⇒ 新 Def 必须显式 `rotatable=true`，不得整块复制原型 Def。
- 产热：原型 `CompHeatPusherPowered.heatPerSecond = 6`（1000 W 机器）。2400 W 机组的产热值**待确认**，不先承诺精确热功率。

### 4.4 工业光伏阵列

- 用原版 `CompPowerPlantSolar`：输出 = 峰值 × 天光 × 露天比例。**不自写日夜曲线**（项目已有同公式实现可对照：`Source/PersonalChronicle/Automation/CompPowerTraderWithSolar.cs`，其屋面扣减照抄原版）。
- **本台是纯发电设备**（输出 ≥ 0），不使用农机那套「光伏抵扣 + 净耗电」语义。农机的 `CompPowerTraderWithSolar` 是为「发电恒小于功耗的净耗电器」定制的；把它套到纯发电机上会重新引入 `PowerOn` 门控振荡问题（该类注释记录了 2026-09-08 的换血原因）。
- 峰值 2600 W **不是全天平均**。遮顶按占地内屋顶格比例扣减；夜间 0；不得按 2600 × 全天时长估算日发电量。
- 屋顶比例按 **占地格** 计算（4×3 = 12 格），不是按贴图。

### 4.5 工业蓄电池组

- 复用 `Building_Battery` + `CompPowerBattery` + `CompProperties_Battery`，保留电量存档；**不造第二套电池库存**。
- 单位是 **Wd**，不是 W，也不是现实 kWh。2400 Wd = 2400 W 放电 1 日，或 100 W 放电 24 日。
- `efficiency 0.75` 只在**入库充电**时生效；放电不重复乘。自放电恒定 5 W（§3.1 已核实），24 小时不停。
- 保留原版风险：`shortCircuitInRain=true`、`Breakdownable`、`Stunnable`（EMP）。**不提供「绝对安全」保底**。
- 建议摆在有顶、可隔离的电池间；柜顶实体电芯盖板，电量读数由运行时绘制，**不烘焙固定「满电」数值**。
- ⚠ 单电力 comp 原则：`PowerNetMaker.ContiguousPowerBuildings` 每建筑只取**主电力 comp** 建网，第二个电力 comp 的 `transNet` 会为 null（项目已在 `CompPowerTraderWithSolar.AlignSiblingTransNet` 记录）。电池组**不要挂第二个电力 comp**；若将来必须挂，须照该对齐方案处理，否则检视会恒显示「未接入电网」。

### 4.6 车间配电柜

- 实现基座 = 原版 `PowerSwitch`（`Building_PowerSwitch` + `CompPowerTransmitter` + `CompProperties_Flickable`），**不是**会主动调度电力的管理器。
- 保留 `allowWireConnection=false` 与 `passability=Standable`：低矮、可穿行、不吃拉线——与主稿「避免把可站立开关画成封路高柜」一致。
- 开关由殖民者按原版切换执行；界面可显示待切换状态。**首版不承诺**自动负载优先级、限流、短路豁免、远程瞬时切换、UPS。
- 功率 / 储能 / 净负荷是**共享电网读数**（§3.4），不是配电柜自身的发电功率。
- 若将来改成高柜形态，必须**先重做线路拓扑与通行规则**，再改美术与 Def（主稿已声明）。

### 4.7 复用而不新增

风电、地热、水电、导线、暗线、防水线一律沿用原版。本轮**不新增只是更大更强的同功能版本**——待地图约束与成本差异确定后再单独设计。

## 5. 功率平衡模型

### 5.1 平衡式

```
净收支(W) = Σ发电输出(W) − Σ负载需求(W) − Σ电池自放电(5 W × 电池数)
```

三条限定：

1. **发电输出是「当下」值**：光伏随天光，燃油机随燃料与开关；不得用标称峰值代入全天。
2. **负载需求是「声明值」**：`CompPowerTrader` 恒定声明需求（农机换血教训），不能假设「无人操作就自动少耗电」。断电与否由电网决定。
3. **净收支为负不代表立刻停电**：电池会放电顶住，直到已储耗尽。停电是 `PowerOn` 判定的结果，不是账面结果。

### 5.3 场景验算

| 场景 | 算式 | 结论 |
|---|---|---|
| 1 台燃油机带十台生产台 | 2400 − 3630 | **−1230 W**，无法独立支撑 |
| 上例中满电池能顶多久 | 2400 ÷ (1230 + 5) | ≈ **1.94 游戏日**（理论极限） |
| 单一支路起步：冶炼 + 机加 + 缝纫 + 石工 | 2400 − (900+500+180+400) | **+420 W**，留有余量 ⇒ 推荐起步组合 |
| 2 燃油机 + 十台 + 冷藏柜 + 灯 + 冷却器 | 4800 − 4220 | **+580 W**（少量充电余量） |
| 上述再开炼制台 + 研究台 | 580 − 500 − 250 | **−170 W**，需光伏 / 第三台 / 关其他负荷 |
| 全族满载（4970 W）纯电池供电 | 2400 ÷ 4975 | ≈ **0.48 日 ≈ 11.6 小时** |
| 2 燃油机满足全族满载所需台数 | 4970 ÷ 2400 | **需 3 台**（或 2 台 + 白天光伏 + 电池缓冲） |

⇒ 结论：**2400 W 的单机功率设计上要求「分批开机」而不是「全族常开」**。这不是缺陷，是本批的规模梯度；但必须让玩家在界面上看得见缺口（§9.5）。

### 5.4 充能时间与储能水位

以「稳定净盈余 580 W、一组空电池、含 5 W 自放电」为例：

```
充满时间 = 2400 ÷ (580 × 0.75 − 5) = 2400 ÷ 430 ≈ 5.58 游戏日
```

充电时间必须按**实际净盈余**与**入库效率**累计；光伏不得按峰值折日。储能水位定义为 `StoredWattDays / CapacityWattDays`，容量为 0 时走「无储能」降级（§2.4）。

## 6. 燃料循环

### 6.1 耗油侧

| 机组 | 功率 | 耗油 | 油箱 | 满箱续航 |
|---|---:|---:|---:|---:|
| 原版 `ChemfuelPoweredGenerator` | 1000 W | 4.5 /日 | 30 | 6.67 日 |
| `PC_T1_FuelGenerator` | 2400 W | 10.8 /日 | 60 | **5.56 日** |
| 两台 T1 机组 | 4800 W | **21.6 /日** | 120 | 5.56 日 |

比例一致：**每 222.2 W 耗 1 化合燃料/日**（1000 ÷ 4.5 = 2400 ÷ 10.8 = 222.22）。

### 6.2 产油侧（原版配方实测）

| 配方 | 工作量 | 投入 | 产出 | 折算 |
|---|---:|---|---|---|
| `Make_ChemfuelFromWood` | 2000 | 木材 70 | 化合燃料 35 | **2 木材 → 1 化合燃料** |
| `Make_ChemfuelFromOrganics` | 2500 | 有机物（用量待确认） | 待确认 | — |

原型 `BiofuelRefinery`：3×2、**170 W**、工作量 2000、HP 200、150 钢 + 3 零件；T1 智能燃料炼制台：3×1、**500 W**、基础加工速度 4.0。**功率是原型的 2.94 倍**，这是为了换取 4 倍加工速度与更小占地，属于设计取舍而非错误。

### 6.3 日循环闭合验算

以两台 T1 机组持续满负荷、走木材配方为例：

| 步 | 计算 | 结果 |
|---|---|---|
| 日耗燃料 | 2 × 10.8 | 21.6 化合燃料/日 |
| 折算木材 | 21.6 × 2 | **43.2 木材/日** |
| 折算批数 | 21.6 ÷ 35 | 0.617 批/日（≈ 1 批/1.62 日） |
| 原版炼制台等效工时 | 0.617 × 2000 ÷ 1.0 | ≈ 1234 工作量/日 |
| T1 炼制台等效工时 | 0.617 × 2000 ÷ 4.0 | ≈ **309 工作量/日** |
| 炼制的用电代价 | 炼制台 500 W | 已计入 §5.2 负载 |

⇒ 结论：**燃料自给的瓶颈不是电，是木材量产与搬运**。43.2 木材/日 的产出与运输需要与伐木、仓储（主稿 A 批重载原料架）联合估算。

### 6.4 搬运与工人在线时间

补燃料与炼制都是**人工工单**，不是自动链：

- 补燃料：原版 `CompRefuelable` + 搬运工作，按 5.56 日/箱 的频率发生；
- 炼制：需殖民者站在炼制台前完成工单；
- 因此「两台机组天天满负荷」在实测前**不能承诺**——工人在线时间、原料搬运距离、仓库位置都会改变实际出勤率。

## 7. 失效、风险与故障语义

### 7.1 状态矩阵

| 状态 | 触发条件 | 电网影响 | 设计口径 |
|---|---|---|---|
| 缺燃料 | `fuelFilter` 中无化合燃料 | 燃油机输出 0 | 沿用原版组件提示，不自动关机提示 |
| 关闭 | `CompFlickable` 置关 | 输出 0 | 玩家操作，不自动重开 |
| 故障 | `CompProperties_Breakdownable` | 输出/耗电中断 | 保留原版维修工作，不做自动修理 |
| 雷暴短路 | `shortCircuitInRain` | 短路爆炸事件 | **用电侧同样会短路**（生产台已带该标记） |
| EMP 眩晕 | `CompProperties_Stunnable` | 电池被排除出 `CurrentStoredEnergy()` | 读数走引擎方法，不自遍历 |
| 夜间 | `skyGlow = 0` | 光伏 0 | 不自写曲线 |
| 遮顶 | 占地内屋顶格 | 光伏按比例扣减 | 照抄原版屋面扣减 |
| 离网 | `PowerNet == null` | 设备不工作 | 提示「铺电缆」而非「故障」 |
| 供给不足 | 需求 > 供给 | 原版让部分设备 `PowerOn=false` | **不承诺确定性优先级**，不做限流 |
| 摧毁爆炸 | 燃油机原型 `CompProperties_Explosive` | 火灾 + 洒燃料 | **待裁决**（§7.2） |

### 7.2 燃油机的爆炸继承（裁决项）

原版 `ChemfuelPoweredGenerator` 带 `CompProperties_Explosive`（`explosiveExpandPerFuel 0.95`、`explosiveDamageType Flame`、`destroyThingOnExplosionSize 2`、`preExplosionSpawnThingDef Filth_Fuel`、`wickTicks 70~150`）。若 T1 直接复制原型 comps，`PC_T1_FuelGenerator` 会继承：低血被摧毁 → 起火 → 洒 `Filth_Fuel`。主稿未记录该项。

同批需要**显式裁决有无**的原型附加组件（照 §4.3 纪律，不得静默继承）：

| 组件 | 原型 | 影响 | 建议 |
|---|---|---|---|
| `Explosive` | 有 | 摧毁时起火 + 洒燃料 | 裁决项，见下 |
| `Glower`（80,112,180，半径 6） | 有 | 机组自带常亮蓝光 | 建议**保留**以对齐原型观感；与「美术不画常亮屏」不冲突（光是引擎绘制的，不是烘焙进贴图的） |
| `Flickable` | 有 | 关闭态与「关闭」状态词 | **必须保留**，否则 §7.1 关闭态与 §9.3 词表落空 |
| `HeatPusher`（6/s @ 1000 W） | 有 | 车间升温 | 保留；2400 W 对应值待确认（§15 #5） |
| `Stunnable`（EMP） | 有 | EMP 眩晕 | 保留，与原型一致 |

`Explosive` 三个选项，请 PM 裁决：

1. **保留**（照抄原型）：与原型一致，代价是车间内爆炸风险；
2. **移除**：更安全的工业机组，但偏离「沿用原型机制」原则；
3. **保留爆炸、去掉洒燃料**：折中，改动量最小但需说明理由。

无论选哪个，都必须在 Def 里**显式声明**该 comp 的有无，不允许「继承得来、设计文档里没写」。

### 7.3 雷暴短路

- 电池：`CompProperties_Battery` 继承 `CompProperties_Power.shortCircuitInRain`，原版 `Battery` 显式 true；
- 生产台：`Defs/T1_Production.xml` 十台均显式 `shortCircuitInRain=true`；
- ⇒ **短路不是电池专属风险**。文档与界面措辞不得写成「只有电池会短路」。

### 7.4 EMP 与储能读数

EMP 眩晕的电池**仍在 `net.batteryComps` 里**，但会被 `CurrentStoredEnergy()` 排除。所以：**已储读数下降 ≠ 电量丢失**。UI 在 EMP 期间不得把差额画成「损耗」。

## 8. 运行与隔离编排（首版手动）

### 8.1 玩家可执行的三条手法

1. **辐射布线**：一个配电柜只挂一条支路，保证断开有效（§3.3）；
2. **分批开机**：按 §5.3，按 3630 W 基线分批上电，用配电柜在「冶炼+机加」与「烹饪+制药」之间切换；
3. **备机与油库**：两台机组错峰补料，油库放在机组旁以缩短搬运（与主稿重载原料架/备料架联动）。

### 8.2 不承诺项

界面**不**提供自动负载优先级、不自动切备用机、不自动补料、不做 UPS 秒级切换、不报「哪台设备先掉电」。这些属于后续扩展候选，须待玩法需求成立后单独设计。

### 11.2 drawSize、graphicClass 与方向陷阱

- `drawSize = (占地宽 + 0.5, 占地深 + 0.5)`：燃油机 (3.5, 2.5)、光伏 (4.5, 3.5)、电池 (2.5, 2.5)、配电柜 (1.5, 1.5)；东西向交换宽深。
- ⚠ **可旋转**：原型里 `ChemfuelPoweredGenerator` / `SolarGenerator` / `PowerSwitch` **显式** `rotatable=false`；`Battery` **未声明**，取默认 `true`（`Verse.ThingDef.rotatable` 默认为 true，父级 `BuildingBase` 无覆写；电池用 `Graphic_Multi` 四向图可佐证）。本批四台都有四向资源 ⇒ 新 Def 必须**显式** `rotatable=true`，不得整块复制原型的 `rotatable` 行。
- ⚠ **`graphicClass` 必须是 `Graphic_Multi`**：三台原型的 `graphicData` 是 `Graphic_Single`（燃油机 / 光伏 / 配电柜原型）。只改 `rotatable` 而照抄 `graphicData`，**四向 PNG 同样不会被使用**——这是与上一条配对的另一半陷阱。工程惯例见 `Defs/T1_Production.xml`，十台均为 `Graphic_Multi`。
- ⚠ **配电柜的关断态贴图**：复用 `Building_PowerSwitch` 后，关断态渲染走 `texPath + "_Off"` 变体（`Building_PowerSwitch` 的渲染分支经 `CompFlickable`）。主稿资产体系（资产清单、四向提示词、美术说明）**只有四向主图、没有 `_Off` 变体** ⇒ 见 §15 裁决项。

### 11.3 配色与「不烘焙状态」

- 能源识别用**暗钢蓝**；功能读数屏用**暗青**；黄色只用于少量警示；
- 电池不画固定电量读数（运行时绘制）；配电柜不画常亮屏；燃油机不烘焙油量数字；
- 光伏可大面积使用暗蓝光伏材料，不把整机涂蓝；
- 画面不出现人、场景、地板、可读文字、logo、棋盘格或烘焙投影。

### 12.2 扩展点风险升序与零 Harmony 声明

按规范风险升序：原生 Def/XML → DefModExtension → Comp/GameComponent → Service/Contract/Provider → PatchOperations → Harmony Postfix/Prefix/Transpiler。

本批**不新增任何扩展点类型**：不新增 Comp、不新增 Provider、无 PatchOperations、**不写 Harmony**；唯一的 XML 产物是 4 个 `ThingDef` + 2 个 `ResearchProjectDef`，全部靠装配原版组件实现功能。既有数据层 / 顶栏的电力读数**只读复用、零代码改动**；若实装时确需给数据层增加只读字段，那仍是既有 Provider 内的改动，**不构成扩展点升级**。若实装时发现必须新增辅助组件（例如燃油机的爆炸取舍需要自定义），**必须回到 Architecture Review** 登记理由与回滚方案，不得在实现阶段静默升级扩展点。

### 12.3 禁止项（本批明确不做）

- 在 `Tick`/`CompTickInterval` 中遍历全网或全图建筑；
- 自遍历 `net.batteryComps` 求已储量（会漏算 EMP 排除）；
- 各处手写 `WattsToWattDaysPerTick` 换算；
- 把 Wd/tick 当 W 输出到界面；
- 用显示文本（label）做逻辑判断；
- 为电力单独引入静态可变状态。
