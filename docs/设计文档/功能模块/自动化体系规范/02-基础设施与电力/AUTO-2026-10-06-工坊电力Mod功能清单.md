# 工坊电力 Mod 功能清单（34 个实测）

日期：2026-10-06。版本：v0.1。适用项目：殖民地综合管理系统。游戏基线：RimWorld **1.6.4871 rev590**。

本稿是对创意工坊电力相关 Mod 的**功能普查与机制溯源**，用于给《基础设施体系之电力体系方案》定边界。凡标「已确证」均有文件/行号或方法名证据；标「推测」的不作为实现依据。

## 0. 调研方法与可信度

| 项 | 内容 |
|---|---|
| 取样 | 4 组关键词（`power grid` / `electricity circuit breaker` / `power logic switch` / `fuse short circuit surge`）+ 4 组补充（`power generation` / `battery energy storage` / `reactor nuclear power` / `wireless power transmission`），命中总量 2.2k–9.1k 条，只取前若干页 |

## 1.5 1.6 可实装性判定（先过滤不能用的）

### 1.5.1 三维判定法

| 维度 | 判据 | 说明 |
|---|---|---|
| ① 版本声明 | `About.xml` 的 `<supportedVersions>` 是否含 `1.6` | **不含 ⇒ RimWorld 按版本过滤，默认不可启用**（游戏不会加载） |
| ② 版本目录 | 是否有 `1.6/`、`v1.6/` 目录（配 `LoadFolders.xml`） | 多版本 Mod 靠它给 1.6 单独发 DLL/Def |
| ③ API 存活 | 它 patch / 反射的原版成员在 1.6 是否还在（Cecil 核实） | **推论**：声明 1.6 且用 `PatchAll` 的 Mod，其 patch 目标**必然存在**——否则 Harmony 启动即抛 |

### 1.5.2 结论：34 个的 1.6 可用性

**A. 1.6 可用（28 个）**

| 单版本即 1.6（8） | SS Battery Fuse · Electric Overview · Quality Power · Battery Indicator · Power Priority · More Batteries · Efficient batteries |

## 1.6 低版本 Mod 的 1.6 移植判定（对应 §1.5.2 B 组）

**结论：6 个都能移植，成本差 5 个档。** 逐项已 Cecil 核实。

| Mod | 上限 | 移植成本 | 真正的阻塞点 |
|---|---|---|---|
| **Fuse Plus** | 1.3 | **≈ 0** | 无。纯 XML，只依赖 `RT_Fuse.CompProperties_RTFuse` 的 `surgeMitigation` / `breakdownOnTrip`——**RT Fuse 1.6 两字段都在**（`decomp16\728314182_v1.6_RT_Fuse` L33/L35）。加 `<li>1.6</li>` 即可；但 1.6 已有同功能替代（SS Battery Fuse，12k–768k Wd） |
| **Backup Power** | 1.4 | **低** | 无。**全批唯一"零 Harmony"的备机自启**。`Flickable.Force(mode)` 不是原版 API——是**它自带的扩展方法** `public static void Force(this CompFlickable flickable, bool mode)`（L924）。核心依赖 `CompRefuelable.HasFuel` ✅ / `CompBreakdownable.BrokenDown` ✅ / `CompPowerPlant.DesiredPowerOutput`（protected virtual）✅ 全在 |
| **Short Circuit Blues** | 1.4 | **低–中** | 须重编译：标称"软依赖"却**硬 `using RT_Fuse`**。RT Fuse 1.6 仍有 `MitigateSurge()` ✅（L85）；它 patch 的 `PowerLogic.ZzztFuse.FuseIgnited` 在 Power Logic 1.6 里仍是 `private static bool FuseIgnited(Building)` ✅（L16442）。移植须带 RT Fuse 1.6 + Power Logic 1.6 |
| **Battery Charger** | 1.4 | **中** | 核心（`Building_Storage` + `CompPowerBattery.AddEnergy` + 按格瓦数）好移；**世界层那套风险高**——1.6 的 `list CaravanArrival` 未命中对应类型，`selectedStorageSettings` 也未命中 ⇒ 商队交易宜砍掉 |
| **Active Circuits** | 1.2 | **中** | **硬阻塞**：`MapDrawer.sections` 在 1.6 是 **`Section[]`（一维）**（`fieldsearch sections`：`Verse.MapDrawer :: [priv] Section[] sections`），它按 `Section[,]` 取 ⇒ `as Section[,]` 得 null ⇒ **按网着色静默失效**。次要：`MainTabWindow_Architect` 在 1.6 **无 `PostOpen`**（继承自 `MainTabWindow`）⇒ Harmony 落到基类，补丁面扩大但不崩 |
| **Battery Overhaul** | 1.3 | **高** | 靠 **`(BaHPowerNet)__instance` 强转**接管整条 `PowerNet` 生命周期。1.6 里那些方法**全在**（`NewPowerNetStartingFrom`/`PowerNetsTick`/`Register/DeletePowerNet`/`RegisterConnector`/`PowerNet.Map` getter…），但这条路**与 Parallel PG、Logic Switch 互斥**；且 1.6 `CompProperties_Power` 新增 `idlePowerDraw`/`alwaysDisplayAsUsingPower`/`powerUpgrades`，1.3 时代代码不认识 |

### 1.6.1 三个前置结论

1. **Harmony 不是门槛**：6 个里 5 个用 Harmony 2.x `new Harmony(...)`；Backup Power 与 Fuse Plus **完全不用 Harmony**。
   > ⚠ 陷阱：root 目录反编译里 Power Logic / Parallel PG / Power++ / RT Fuse 显示 `HarmonyInstance.Create`（1.x 旧 API）是**旧版本**；它们的 1.6 构建**全部已迁到 `new Harmony`**（`decomp16` 实测）。看 Harmony API 必须看 1.6 版本目录。
2. **依赖的原版 API 在 1.6 基本全在**（20+ 个成员逐个核实）。
3. **没有任何一个卡在"1.6 删掉了它需要的类型"上**——唯一真正消失的是 `MapDrawer.sections` 的**维度**。

### 1.6.2 移植检查清单（任何 1.3/1.4 时代电力 Mod 通用）

| 检查点 | 说明 |
|---|---|
| `MapDrawer.sections` | `Section[,]` → **`Section[]` 一维** |
| `MainTabWindow_Architect.PostOpen` | 已不存在，继承自 `MainTabWindow` |
| `CompProperties_Power` 新字段 | `idlePowerDraw` / `alwaysDisplayAsUsingPower` / `powerUpgrades` |
| 命名空间 | `Verse.Profile.MemoryUtility`、`RimWorld.SectionLayer_ThingsPowerGrid`、`RimWorld.Planet.WorldObjectComp`、`RimWorld.PowerNetGrid`（查错命名空间会误判"不存在"） |
| `CompFlickable` | **没有 `Force`** —— 谁调谁得自带扩展方法 |
| `HarmonyInstance` | 1.x 旧 API；1.6 须换 `new Harmony(id)` + `PatchAll` |
| `About.xml` | 加 `<li>1.6</li>`，否则游戏按版本过滤不加载 |

### 1.6.3 移植价值排序（对我们的取舍）

1. **Backup Power** —— 成本最低（零 Harmony）+ 能力空缺最大（1.6 无备机自启）
2. **Fuse Plus** —— ≈0 成本，但只是数值，且已有 1.6 替代

其余 4 个**移植不如重写**：Active Circuits 自带 3 处算法错；Battery Overhaul 路径互斥；Short Circuit Blues 依赖三方耦合。**照它的错误实现搬，不如照它的正确部分重写。**

## 2. 功能清单（按功能域）

### 2.1 短路与保护（8 个）

| 功能 | Mod | 实现机制（已确证） | 对我们 |
|---|---|---|---|
| **能量预算抵扣** | RT Fuse `728314182` | Harmony **Prefix `return false` 完整替换** `ShortCircuitUtility.DoShortCircuit`。**照抄原版抽干全网电池**，再遍历 `powerNet.transmitters` 找 `CompRTFuse`，逐个减 `surgeMitigation`（保险丝 1800 Wd），减到 ≤0 则**取消爆炸**、只给 culprit `Rand.Range(0, 0.1×MaxHP)` 伤害 | ⚠ 它**不解决断电范围**（电池照样抽干）。Comp 参数化思路可借；整体替换不可借 |
| **跳闸两种形态** | RT Fuse | `CompRTFuse.MitigateSurge()`：`breakdownOnTrip=true` → `CompBreakdownable.DoBreakdown()`（烧断要修）；`false` → `flickable.ResetToOn(); flickable.DoFlick(); FlickUtility.UpdateFlickDesignation()`（**真·分闸**） | ✅ 跳闸的标准写法，直接借 |
| **事件层拦截 + 割点切网** | **Circuit Breaker** `3367738537` | 4 个挂点（`IncidentWorker_ShortCircuit.CanFireNowSub` P=700 / `.TryExecuteWorker` P=800 / `ShortCircuitUtility.DoShortCircuit` P=700 / `CompPower.CompGetGizmosExtra`）；核心 `Netter.Shuttle`：**以事故点为源 BFS，把断路器当割边逐个跳闸**，成功后 `map.powerNetManager.UpdatePowerNetsAndConnections_First()` 强制重算 ⇒ `culprit.PowerComp.PowerNet` 变成**小网**，爆炸按小网电池算 | ✅✅ **唯一真正解决断电范围的实现**，Shuttle 算法可借 |
| **全套参数化** | Short Circuit Blues `2322956181` | Prefix `DoShortCircuit`（**P=500**，比 RT Fuse 400 高 ⇒ 抢占）；可调抽电比例 / 爆炸阈值 / 起火 / 伤害 / 文案 / 音效；**硬 `using RT_Fuse` 调 `MitigateSurge()`** 做兼容 | ✅ priority 分层实践（400/500/700/800）；"总量−扣减−差值"计量骨架 |

## 4. 可直接采用 / 必须避开

**直接采用（已确证可用）**

1. **开关写法**：覆写 `Building.TransmitsPowerNow` + `map.powerNetManager.Notfiy_TransmitterTransmitsPowerNowChanged(PowerComp)`（Power Logic 全文件反复使用）；对耗电设备用 `CompFlickable.Force()`（Backup Power）而非裸写 `PowerOn`。
2. **分区**：Postfix `PowerNetMaker.ContiguousPowerBuildings` 做阻断边（Power Diode）+ 可达性闭包修正。
3. **邻格取网**：`Map.powerNetGrid.TransmittedPowerNetAt(cell)`（RT Power Switch / Power Diode）。
4. **备机自启**：`MapComponent` 分网轮询 + `FloatRange` 双阈值 + `MinimumOnTime` 去抖 + 可用性预检 + 加权随机（Backup Power）。
5. **负载优先级**：`Level{Critical=1..Low=4}` + `Classify()` 默认表 + `PowerSuspensionReason` + `PlanShedding/PlanByPriority/HoursUntilReserve` + 多档滞回（Power Priority）。
6. **分区持久化**：电网指纹（`transmitters ∪ connectors` 的 `thingIDNumber` 集合 + `AnchorThingId` + 交集复用）（Power Priority）。
7. **告警公式**：`续航游戏秒 = StoredWattDays / (max(0,-NetWatts)/60)`；`燃料游戏秒 = Fuel / fuelConsumptionRate × 1000`；Brownout 三态；`shortCircuitInRain + !roofGrid.Roofed`（Power Alerts）。
8. **叠层可视化**：4 份预铸 `Graphic_LinkedTransmitterOverlay` + `renderQueue=3600` + `NotifyDrawersForWireUpdate(cameraPos)` + 1 s 节流（Electrical Grid Toggler）。

10. **数值进 `CompProperties` 字段**：让第三方纯 XML 扩展（RT Fuse 的 `surgeMitigation`、Battery Charger 的 `distributionAmountPerCell`）。
11. **Prefix 安全阀**：`if (!AnyXxxOn(map)) return true;`（Logic Switch）——无配置时完全走原版。

**必须避开**

1. **整体替换 `DoShortCircuit`**（已有 5 家在抢；破坏性，且会让别人的 Postfix 永不执行）。
2. **Prefix-return-false 掉 `PowerNetManager.PowerNetsTick` / `NewPowerNetStartingFrom`**。

8. **Transpiler 靠"第 N 个 call"定位**（Electrical Grid Toggler）。
