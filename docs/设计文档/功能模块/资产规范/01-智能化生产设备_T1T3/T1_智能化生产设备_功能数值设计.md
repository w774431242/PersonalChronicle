## 0. 一句话结论

**T1 = 廉价、低产、需人操作（pawn 站台前）的入门级加工台；靠研究链逐级解锁 T2/T3，支持原地升级替换。**

## 1. 三级关系：研究递进 · 可升级

### 1.1 递进轴（已定）

```
T1 智能化工作台（入门）  →  T2 半自动化机（中档）  →  T3 全自动生产舱（高端）
     需要人操作               人只上下料             无人，传送带直连
     2×2 占地                 2×2~2×3               3×3 统一底盘
     密度 60%                 密度 80%              密度 100%
```

**硬规则**：同工序三级**自上而下解锁**，高级别覆盖低级别能力（不是各有各的用途并列）。

| 项 | T1 | T2 | T3 |
|---|---|---|---|
| 研究档位 | 第 1 档（本档新增） | 第 2 档 | 第 3 档 |
| 前置研究 | `Machining` + `Electricity`（已存在） | T1 档 + `MicroelectronicsBasics` | T2 档 + `Fabrication`（或自定） |
| 造价量级 | 最低 | 中 | 最高 |
| 工时系数（对原版基准） | ~0.95 | ~0.80 | ~0.60 |
| 是否需 pawn | 必须 | 必须（仅上下料） | 不需要 |

### 1.2 可升级机制（原地替换）

**设计决策：采用「原地升级」而非「拆了重造」。**

- 玩家在已建成的 T1 设备上点击「升级到 T2」→ 消耗差价材料 + 建造工时 → 原地替换 Thing（保留位置、朝向、区内归属、ItemStorage 内物品）。
- **实现口径**（留给实现任务，此处定型语义）：
  - 走独立 `CompUpgradableDevice`（新增 comp），持 `upgradeToDefName` / `upgradeCostList` / `upgradeWorkAmount`；
  - 升级 = 生成目标 Def 的新 Thing 到同格同向 → 迁移存量（存储物品/电力状态）→ `Destroy` 旧 Thing；
  - **不做**「同 Thing 换贴图」——ThingDef 的 stat/comps 是静态的，换 Def 才能让数值真正生效，避免伪升级。
- 降级不做（不符合工业逻辑，且徒增分支）。

### 1.3 与现有研究链的挂接

现有研究链（`Defs/Automation_Research.xml`，独立标签页 `PC_AutomationTab`）目前只有农业自动化两档：

| 现有 defName | 用途 | 建议 |
|---|---|---|
| `PC_Research_AutomationBasics` | 传送带 / 农机组件 / 小农机 | **复用为 T1 档前置**（农机与工作台同属「基础工业自动化」语义） |
| `PC_Research_AutomationAdvanced` | 中大型农机 | 保留（农业线），另开武器产线档位 |

**建议新增 3 档研究（武器产线独立成链，不与农业混档）**：

| defName（建议） | label | baseCost | prerequisites | 解锁 |
|---|---|---|---|---|
| `PC_Research_WeaponWorkshopT1` | basic weapon workshop equipment | 1800 | `Machining`, `Electricity` | 12 台 `PC_*_T1` |
| `PC_Research_WeaponWorkshopT2` | semi-automatic weapon workshop equipment | 3600 | `PC_Research_WeaponWorkshopT1`, `MicroelectronicsBasics` | 12 台 `PC_*_T2` |
| `PC_Research_WeaponWorkshopT3` | automated weapon production line | 6000 | `PC_Research_WeaponWorkshopT2`, `Fabrication` | 12 台 `PC_*_T3` |

> 坐标系：沿用 `PC_AutomationTab`，`researchViewY` 另起一行（农业线在 Y=1.00，武器线建议 Y=2.50 起），X 按档位 1.00/4.00/7.00，避免与农业格位相撞。

**统一占地 2×2 的理由**：T1 是「工作台」不是「机床」，占一格太小（约 1.5 格高的 pawn 站台前无操作空间），3×3 又侵占了 T3 的尺感。2×2 让 pawn 站在前沿缺口、视觉成立且与 T2 最小档一致，升级时**位置不需重排**，这是可升级机制成立的前提。

### 2.1 四向贴图（已定：需要四向）

T1 全部 12 台走 `Graphic_Multi`，四向文件：

```
Textures/Things/Building/WeaponWorkshop_T1/PC_<工序>_T1.png        （north，默认）
Textures/Things/Building/WeaponWorkshop_T1/PC_<工序>_T1_east.png
Textures/Things/Building/WeaponWorkshop_T1/PC_<工序>_T1_south.png
Textures/Things/Building/WeaponWorkshop_T1/PC_<工序>_T1_west.png
```

- **基准向 = east**（进左出右/操作位朝右），与 T2/T3 一致，玩家读图零学习成本。
- `rotatable=true`，`drawSize (2,2)`，`size (2,2)`，恒为 64px/格。
- 目录 `WeaponWorkshop_T1` 独立成目录，不混入 `Automation`（后者是传送带/管线）。
- **代价说明**：12 台 × 4 向 = 48 张贴图，是单向方案的 4 倍出图量。若工期紧，可先出 east 向跑通链路，其余三向后补（Def 侧 `Graphic_Multi` 在缺文件时会回退到主图，不崩，只是旋转后朝向错误）。

## 3. 数值设计

### 3.1 基准锚点（从存量资产实测）

设计 T1 数值时以下列已落地资产为标尺，保证同体系内手感一致：

| 参照件 | 占地 | WorkToBuild | MaxHitPoints | MarketValue |
|---|---|---|---|---|
| `PC_ConveyorSegment` | 1×1 | 600 | 100 | — |
| `PC_AutoFarm_S` | 1×1 | 1200 | 150 | 900 |
| `PC_AutoFarm_M` | 2×2 | 2000 | 200 | 1850 |
| `PC_AutoFarm_L` | 4×4 | 3200 | 260 | 3350 |

> **取向**：T1 是「必须有人看着」的低端设备，**单位产能性价比要低于农机**（农机是全自动、无人）。因此 T1 的 WorkToBuild 取 2×2 量级的偏下段，但造价不能低于传送带族——否则玩家会拿工作台当墙体用。

### 3.2 统一数值表（12 台）

**所有 T1 设备共用一套基础数值**（工序差异走车间加成与配方体现，不在设备本体做差异，避免 12 套数值的维护地狱）：

| 字段 | 值 | 说明 |
|---|---|---|
| `size` / `drawSize` | (2,2) | 统一 |
| `WorkToBuild` | 1400 | 介于传送带 600 与农机 M 的 2000 之间 |
| `MaxHitPoints` | 180 | 低于农机 M 的 200，体现「轻型工业框架」 |
| `Mass` | 26 | 略轻于农机 M（32） |
| `MarketValue` | 1200 | 低于农机 S 的 900 与 M 的 1850 之间取中 |
| `Flammability` | 0.5 | 同农机 |
| `terrainAffordanceNeeded` | Medium | 同农机 |
| `passability` | Impassable | 设备本体不可穿过（pawn 站前沿缺口） |
| `rotatable` | true | 四向 |
| `castEdgeShadows` | true | 同农机 |
| `fillPercent` | 1 | 同农机 |

**建造材料（costList）** —— 统一 3 件套，体现分级：

```
Steel 40 + ComponentIndustrial 4 + ComponentSpacer 0
```

- 对比：传送带（Steel 6 + ComponentIndustrial 1）→ T1 设备约为其 6.7 倍，符合「设备 >> 单节传送带」。
- T2 建议 `Steel 80 + ComponentIndustrial 10`；T3 建议 `Steel 140 + ComponentIndustrial 20 + ComponentSpacer 2`，形成明确造价梯度。

### 3.3 电力与 comps

| comp | 参数 | 理由 |
|---|---|---|
| `CompProperties_PowerTrader` | `basePowerConsumption = 250` W | T1 是「辅助智能化」而非驱动式，功耗低于农机 S（300W）；无自发电（不挂光伏） |
| `CompProperties_Flickable` | — | 可开关，与农机一致 |
| `CompProperties_Breakdownable` | — | 会故障，维修车间有用武之地 |
| **不挂** `CompProperties_Refuelable` | — | T1 走纯电力，不烧化燃料（与农机区分：农机是野外自驱，工作台在厂内接电网） |

> **电力取向说明**：T1 定位为「厂内接电网的工作台」，纯电即可；农机是「野外据点自驱」，才需要光伏+化燃料的复合方案。两者不可混用同一电力 comp。

### 3.4 与 WorkshopTypeDef 的绑定（能力接口）

车间蓝图的 `IWorkshopDevice` 族是**能力探测接口**，T1 该实现哪些，按下表定：

| 接口 | T1 是否实现 | 理由 |
|---|---|---|
| `IWorkshopDevice` | **是**（必实现） | 所有设备的入网凭证，含 `DeviceLabel` / `Status` |
| `IProducingDevice` | **是** | T1 是真在产出的加工台，需暴露 `SupportedRecipes` / `Progress` |
| `IPowerAwareDevice` | **是** | 有功耗，供车间电费/负载面板读取 |
| `IQualityAwareDevice` | **否** | 品质偏差由 P4 评级系统在车间层接管，T1 本体不做品质干预（那是 T2/T3 的能力） |

**绑定方式**：车间蓝图 §5.2 明确「不强绑定」——设备放进任何车间都被统计，`WorkshopTypeDef.expectedDeviceClasses` 只用于概览页的「匹配/多余/缺失」提示。因此：

- `PC_Smelter_T1` 放进 `WT_Smelting` 车间 → 匹配，吃车间加成；
- 放进 `WT_Forging` 车间 → 仍可运行，只是不匹配、概览页提示「本车间期望设备未找到」；
- **加成方向由车间类型决定，不由设备决定**（蓝图 §7.4 方向锁定纪律），T1 设备不携带任何方向字段。

**Def 写法（示意，本轮不落地）**：

```xml
<expectedDeviceClasses>
  <li>PersonalChronicle.Automation.Building_WorkshopDevice</li>
</expectedDeviceClasses>
```

> 建议 12 台 T1 共用一个 `Building_WorkshopDevice` 类（抽象基类），`defName` 区分工序；不要 12 个类——零注册纳管的意义就在于不给每台设备开类。

### 3.5 配方与工时（接口预留）

- 设备本体的加工配方沿用原版 `RecipeDef` 白名单机制（项目 P3 已有 `ProfessionalEffectStatPartInjector` 注入 `workSpeedStat`）。
- **车间加成（`WorkshopEnvBonus`）与职业加成（`ProfessionalContribution`）在同一 `workSpeedStat` 上自然相乘**，T1 设备无需自建加成逻辑。
- T1 的「低产」由三处共同体现，不需要在设备上写死惩罚系数：
  1. 车间类型加成系数（`workTimeFactor` 等）在 T1 车间档位配置较低；
  2. 研究档位递进导致 T2/T3 拿到更高加成类型的车间（如 `qualityOffset` / `maxHpFactor`）；
  3. 升级到 T2/T3 后设备类型切换，吃对应车间的加成。

> **设计纪律**：T1 不在设备 Def 里做数值惩罚，一律通过「车间类型档位 + 研究递进」表达。这是单一真源要求（蓝图 §7.4 禁止风格飘逸）。

## 4. 与美术规范的交叉约束

| 项 | 要求 | 出处 |
|---|---|---|
| 画布 | 128×128，PNG-32 RGBA，透明底 | 美术规范 §3 / §7 |
| 细节密度 | 基准件 `PC_AutoFarm_M` 的 **60%** | `01_T1` 文档 |
| 功能色 | 每台只取 1 主功能色 + 黄色警示；蓝=能源/绿=生化/橙=运动 | 美术规范 §2.2 |
| 视角 | 2D 俯视正交，无透视/无地面/无阴影 | 美术规范 §4 |
| 等级识别标志 | **台面前沿 pawn 站位缺口**（T1 独有） | `01_T1` 文档 |
| 四向 | 需四向，east 为基准向 | 本文 §2.1 |

**密度 60% 的量化口径**（补 `01_T1` 文档的歧义）：

以 `PC_AutoFarm_M` 为 100%，T1 的密度按「**独立机械细节元素数**」计——

| 元素类型 | T1 上限 |
|---|---|
| 独立功能模块（屏/表/罐/架） | ≤ 3 个 |
| 管线/电缆接口 | 1 处 |
| 指示灯珠 | 2~3 个 |
| 面板分缝/铆钉行 | 台面 2 条，机身 1 行 |
| 做旧痕迹（锈斑/划痕） | 边角 2 处 |

> 说「60%」是指**上述元素总数约为基准件的六成**，不是把线宽画细 40%（线宽受 2px 最小单位限制，不可再减）。
