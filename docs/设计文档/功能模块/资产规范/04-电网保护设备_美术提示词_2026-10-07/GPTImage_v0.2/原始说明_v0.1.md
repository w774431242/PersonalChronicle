### ⚠ 三条会直接导致「洋红错误贴图」的硬约束

1. **`_Off` 必须拼在方位之前**。反编译链实证：
   ```text
   CompFlickable.CurrentGraphic
     → GraphicDatabase.Get(graphicClass, texPath + "_Off", ...)   ← _Off 先拼
     → Graphic_Multi.Init 再拼 _north/_east/_south/_west           ← 方位后拼
   ```
   ⇒ 实际文件名 = **`{texPath}_Off_{dir}.png`**。
   ❌ 按直觉命名成 `PC_PowerIsolator_{dir}_Off.png` ⇒ **4 张全缺** ⇒ `Graphic_Multi` 打 `Log.Error("Failed to find any textures at ...")` 并返回 **BadMat**。
   ⚠ **关断图整体缺失时没有回落主图的机制** —— 比"空框"更响、更明显。

2. **断路器不做 `_Off`**。它的跳闸态走 overlay / Fleck，**不替换 `Graphic`**。若误做 `_Off` 命名反而会与"不依赖 `_Off`"的设计相矛盾。

3. **两张图必须 `Graphic_Multi` + 显式 `rotatable = true`**。原型三台设备是 `Graphic_Single` / `rotatable=false`，**照抄会让四向贴图白做**（电力分册 §11.2 已登记的陷阱）。这属 Def 侧纪律，此处登记以免美术做完才发现白做。

### 待确认（拟定值，**不得当作已定**）

| 项 | 拟定 | 依据 | 风险 |
|---|---|---|---|
| 占地 | **1×1** | 原版 `Building_PowerSwitch` 是 1×1；隔离开关直接 `: Building_PowerSwitch` | 若断路器实际占地大于 1×1，母图尺寸需重算 |
| `drawSize` | **(1.5, 1.5)** | T1 规范：`占地 + 0.5` | 需以放置预览检查轮廓与操作格 |
| 母图尺寸 | **384×384**（每格 256 px） | T1 规范 | 模型未必支持精确尺寸 |
| 游戏导出尺寸 | **192×192**（每格 128 px） | T1 规范 | 实际生成后等比缩小，禁拉伸/超分 |

> ⚠ **放置预览是唯一判据**：上述尺寸都是拟定值，**必须**以放置预览逐项核对占地、选择边界、操作格与相邻通行。提示词里的尺寸**不能作为已落地的证据**。

## 2. 视觉锚点（沿用 T1 规范，逐字复述以便本批可独立提交）

- 正交俯视、短侧边、深色轮廓、低饱和**钢灰 / 暖灰 / 暗灰**；采用清楚的色块。
- **不走**写实照片、等距模型、像素画或密集机械线条。
- **能源识别色 = 暗钢蓝**用于主结构；功能读数屏用**少量暗青**；**黄色只用于少量警示**。
- ⛔ **没有**可读文字、数字、logo、库存数量、固定电量、固定温度或灯光投影。真实状态由游戏渲染绘制。
- 母图**每格 256 像素**；PNG 为真 RGBA，四角透明，**背景没有白/灰边和棋盘格**。

### 四向坐标（北向是结构母版）

```text
北向：前沿在画面【下】
东向：前沿在画面【左】
南向：前沿在画面【上】
西向：前沿在画面【右】
```

北→东→南→西 按机体俯视结构**顺时针**转向，**相机保持固定**。
⇒ 固定部件（接线口、拨杆、标签槽）在四向之间**数量与结构一致**，只是随转向改变画面位置。**不可靠镜像生成另一方向。**

**制作顺序（不可省）**：先出**北向结构样张** → 用户选定母版 → 以**实际北向图作为图像参考**生成其余方向。仅靠四段文字独立抽样**无法保证部件一致**。

## 3. 两台设备的辨识重点（先看这张再写提示词）

| 设备 | 一眼看出的主结构 | 与另一台的区分点 | 最容易画错 |
|---|---|---|---|
| **断路器** | 单格低矮机箱 + **两端进出线端子** + 正面一根**机械合闸拨杆** + 顶部短散热格栅 | **有保护机构**：两端接线口 + 格栅 + 一个警示色指示位 | 画成高柜（与通行矛盾）；画成 T1 已有的「车间配电柜」（那是终端设备，无进出线两端） |
| **隔离开关** | 单格**更矮**底座 + 一个**裸露旋转刀闸/手柄** | **只有开断机构**：无格栅、无保护元件、更简单更矮 | 与断路器画成同一台；把刀闸画成按钮 |

**★ 这个区分是功能性的，不是审美的**：
- 断路器 = 装在导线路径上的**节点**，两端都要接线 ⇒ **必须有进出线两端**
- 隔离开关 = 纯手动开断，**零新逻辑**复用 `Building_PowerSwitch` ⇒ 视觉上就该更简单

### 4.9–4.12 隔离开关关断图（`_Off`）

> 关断图的唯一任务是把「**断开**」这个状态画出来。**不许用整体变暗 / 褪色表达** —— 那读起来像"设备坏了"，而"已断开"是一个**正常且由玩家主动**造成的状态。

**共同要求（4 张相同，仅前沿方向按下表变化）**：

```text
正交俯视工业设备单体图，与参考图（同一方向的隔离开关主图）**完全同一台设备、同一构图、同一配色**，
唯一的差别是【刀闸已被扳到断开位置】：

- 旋转刀闸的金属刀片**抬离两组固定触座**，呈斜向上翘起的断开姿态；触座保持原位不动。
- 画面【<前沿>】的横向短手柄转到另一侧（与主图的闭合位相反）。
- 机身、接线端子、底座、明暗与主图**逐项一致**，不得整体变暗、褪色或加高光变化。
- 不画电弧、不画火花、不画发光断裂符号、不加警示图标。

禁止：用整体变暗/灰度表达断开；等距透视；文字、数字、logo；发光；灯光投影；地面阴影；
白底或棋盘格背景；改变机身结构或部件数量。
```

## 5. PNG 阶段验收（生成后逐项核对）

1. **12 张齐全**，文件名与 §1 表**逐字符一致**（尤其 `_Off` 在方位之前）。
2. 真 PNG RGBA，**四角透明**；背景无白/灰边、无棋盘格。
3. **四向固定部件逐项核对**（接线端子 / 拨杆或刀闸 / 格栅 / 手柄的**数量与结构**），
   检查东西向纵长与前沿方向 —— **不是只确认文件后缀齐全**。
4. 缩小到 192×192 后与现有 T1 设备**并排比对**：轮廓可辨、无噪点、无过密细线。
5. `_Off` 四张与对应主图**并排比对**：除刀闸位置与手柄方向外，其余应逐项一致；
   **不得出现整体亮度/饱和度差异**。
6. **实机放置预览**：占地、`drawSize`、选择边界、操作格、相邻通行逐项核对
   （提示词尺寸**不作为已落地证据**）。
7. 断路器**左键点合闸 gizmo** 时，overlay / Fleck 指示出现且**底图不变**（验证「无 `_Off`」路线成立）；
   隔离开关手动开断时**图正确切换到 `_Off`**（无 `Log.Error`、无洋红）。
