## 二、P1 清单（必修）

### P1-A【性能·声明失真】值勤计划实际仍每游戏秒重建

- **证据 1**：`MapComponent_WorkshopManager.cs:756` —— `PurgeDeadReferences()` 末尾**无条件** `MarkDutyPlanDirty()`，而该方法由 `MapComponentTick`（`:201`）每 60 tick 调用。
- **证据 2**：`MapComponent_WorkshopManager.Schedule.cs:16-17` —— `EnsureDutyPlan` 的放行条件含 `TicksGame - dutyPlanBuiltTick < CheckIntervalTicks`，即**距离上次重建满 1 游戏秒就强制重建**（跨小时已有 `dutyPlanHour == hour` 覆盖，该条属冗余）。
- **后果**：`dutyPlanDirty` 每秒被置真 + 兜底条款每秒触发 ⇒ `RebuildDutyPlan` 每游戏秒至少跑一次（每次新建 ≥5 个临时集合 + O(班次数²) 插入排序），**`ReconcileDutyPlan` 的"可观测失配才标脏"被完全抵消**。此前注释与 Changelog 中"稳态重建次数下降 95% 以上"的说法**在当前代码下不成立**（PERF-003：不得声称已优化而无证据）。
- **建议**：① `PurgeDeadReferences` 改为"确有移除才标脏"；② 删除 `EnsureDutyPlan` 的 60 tick 条款，只留 `dirty || 跨小时`；③ 修正相关注释与 Changelog 表述。

### P1-B【架构·显示失真】名额估算与派工口径不一致，玩家看到"假满员"

- **证据**：派工侧已收窄为"多班次车间不回落到全员"（`MapComponent_WorkshopManager.Schedule.cs:389-401` `FallbackPool`），但**展示/估算侧仍读旧实现** `WorkshopShift.EffectivePool`（`WorkshopShift.cs:95-106`，池空 ⇒ 无条件回落整份车间名单）：
  - `WorkshopScheduleChart.cs:106`、`:174`（甘特/覆盖条按有效池人数估算名额）
  - `WorkshopOpsAccessBinder.cs:138`（覆盖率/在册名额）
- **后果**：多班次车间未指派时**实际空岗 0 人，图表/覆盖率却显示满员** —— 玩家据此判断"我明明排了班"，与现象直接冲突（这是 2026-10-02 连环问题的同类残留通路）。
- **建议**：两处消费者改走与派工同源的解析（把"是否允许全员回落"抽为共享纯函数，或暴露 `MapComponent_WorkshopManager.ShiftStaffingOf(shift)`）；`WorkshopShift.EffectivePool` 若仅剩轮岗门槛在用则保留并改注释说明用途差异。

### P1-C【架构】`Capture/Patch_GenRecipe.cs` 直读 Automation 内部，跨层红线未闭环

- **证据**：`Capture/Patch_GenRecipe.cs:126-128` 直接 `PersonalChronicle.Automation.MapComponent_WorkshopManager.Get(...).NotifyProductMade(worker)`；EXC 目录（`docs/设计文档/架构/EXC-*.md` 共 12 个）中**未见该直读的例外登记**，而 `审计-制造系统中心-2026-09-21.md` 声称"Capture 仅依赖 Domain" —— **声明与实现不符**。
- **对照**：同类需求在 Effects 侧已完成契约化（`StatPart_Workshop*` 走 `WorkshopBonusAccess`）。
- **建议**：在既有 `WorkshopBonusAccess` 或新增 `IWorkshopProductionSink` 契约中补 `NotifyProductMade(Pawn)`，Patch 只转调契约；`WorkshopProductRegistry.Mark` 同链路一并收口。

### P1-D【数据】设备台账条目无淘汰，且与"读档 ID 重分配"假设相矛盾

- **证据**：`WorkshopDeviceLedger.cs:25`（键 = `thingIDNumber`）、`:63-80`（只有写入，**全类无删除/淘汰**）、`:142-155`（`RollDay` 只重置计数）；而 `MapComponent_WorkshopManager.cs:181-184` 明确假设"读档后 `thingIDNumber` 会重新分配"，并据此清空 `WorkshopProductRegistry`。
- **后果**：① 两个假设互斥 —— 若 ID 会重分配，则设备台账读档后可能**挂到错误设备**；若不会，则 `:181-184` 的清空理由不成立。② 无论哪种，条目**随游戏时长单调增长**（无界，违反有界性）。
- **建议**：在设备扫描路径按"本轮实际存在的设备集合"淘汰陈旧条目；并把 ID 稳定性结论统一到一处注释。

### P1-E【数据】静态注册表只在"读档"清理 ⇒ 回主菜单开新局存在串扰

- **证据**：`MapComponent_WorkshopManager.cs:184` `WorkshopProductRegistry.Clear()` 仅位于 `PostLoadInit` 分支；而组件由 `ConditionalWeakTable` 惰性创建（`:115-134`），**新开局不经过任何 `ExposeData`**。
- **后果**：同进程"回主菜单 → 开新局"后，上一局按 `thingIDNumber` 记录的精度/耐久项仍在，新局 ID 从低位复用 ⇒ 新造物品可能被错误加上加成（正是该 `Clear()` 注释要防的现象）。
- **建议**：清理点提升为"会话起点"（`Create` 回调或 `GameComponent.FinalizeInit`）。

### P1-F【存档】`AssignShift` 在 ID 未分配时静默丢弃持久化

- **证据**：`WorkshopCrew.cs:75-85`（`if (shift.LoadId >= 0)` 才写 `AssignedShiftIds`）；ID 只在 `AddShift`（`MapComponent_WorkshopManager.cs:479-490`）与读档补号分配。
- **后果**：任何绕过 `AddShift` 直接进 `shifts` 列表的班次，其 `LoadId == -1`；玩家勾选后**引用列表有值、ID 列表为空** ⇒ 读档后指派消失且无日志（"勾了没用"类疑难）。
- **建议**：ID 分配收口为管理器唯一出口（`EnsureLoadId`），并在写入 ID<0 时补一条一次性告警。

### P1-G【UI】排班相关看板每帧全量开销

- **证据**：`WorkshopRosterBoard.cs:123-142 → 165-179` **每帧** `WorkshopStats.ScanDevices(zone)`（重扫车间区）；`WorkshopHandoverBoard.cs:198 → 221-247` **每行**重建班次列表 + 例外表 + 轮转槽计数（当班负责人全表相同却每行重算）；`RosterBoard.cs:236-240`、`HandoverBoard.cs:97` 每帧数组分配。
- **后果**：大车间下打开这些页签持续掉帧；与 `WorkshopManageView` 的"打开只扫一次"纪律自相矛盾。
- **建议**：设备清单/班次列表/例外表提到 `Draw` 入口算一次或用 `Refresh` 期快照 + TTL 缓存。

### P1-H【UI】窗口可被缩到任意小 ⇒ 负宽重叠

- **证据**：`Dialog_WorkshopManage.cs:46-52` **未设** `resizeable = false`（同模块其它三个对话框都设了）；`Schedule.cs:277-281` 的 `listW = innerW - AvatarSize - 6f - MemberRightW`（`MemberRightW = 112f` 固定）在窄卡下为负；`Schedule.cs:431-436` chip 两块文本间隙 = `chip.width * 0.05f - 4f`（chip 宽 < 80f 即为负）。
- **后果**：缩窄窗口/在 ITab 宿主下出现三列重叠、chip 文字互压（"文字被挤兑""chip 重叠"的残留形态）。
- **建议**：`resizeable = false`（或 `minSize`）+ 窄宽降级（卡片单列、隐藏工时/产量列）。

### P1-I【UI】破坏性操作无二次确认

- **证据**：`Schedule.cs:386-390` 卡头 "X" 直接 `zone.RemoveCrew(crew)`；`WorkshopRosterBoard.cs:355-359` 同样直删；而删除**班次**有确认框（`Shifts.cs:281-288`）。
- **后果**：一次误点丢掉整个班组编制（含成员与指派），不可撤销。
- **建议**：统一走 `Dialog_MessageBox.CreateConfirmation`。

### P1-J【UI】定宽列动态文本未截断（遗漏点）

- **证据**：`WorkshopRosterBoard.cs:250-252`（班组名画入固定 144f）、`WorkshopHandoverBoard.cs:186-199`（点检表四列全无截断）、`WorkshopScheduleChart.cs:219-220`（甘特行标签画入 142f）、`Dialog_WorkshopCrewEditor.cs:155/168`（按钮固定 68–72f，英文文案溢出）、`Dialog_WorkshopShiftEditor.cs:112-113`（长提示单行不换行）。
- **后果**：英文/自定义长名下列间相互侵占（与已修纪律相矛盾的遗漏）。
- **建议**：批量补 `UIComponents.TruncateToWidth(..., tipRect)` 重载。

### P1-K【UI/主题】字体绕过 Token；一处缓存不随语言失效

- **证据**：`Dialog_WorkshopCrewEditor.cs:61`、`Dialog_WorkshopShiftEditor.cs:74/92/113/188/194`、`Dialog_RotationEditor.cs:76/93/132/138/184/218` 直写 `GameFont.*`；`WorkshopManageView.cs:1063-1093` `typeBuffCache` 是静态字典、**无语言失效守卫**（同文件 `buttonWidthCache` 与 `Shifts.cs` `shiftHeaderCache` 都有）。
- **后果**：改主题令牌不生效；运行期切换语言后设置页类型副行仍显示旧语言。
- **建议**：换 `UITheme.Font*`；给 `typeBuffCache` 加语言守卫（照抄同文件既有写法）。

### P1-L【兼容】RUIF 硬依赖未登记例外

- **证据**：`About/About.xml:10-27` 声明 RUIF 为硬依赖；`Archive/UI/RuifBridge.cs:12-15` 自陈"缺 RUIF 不提供降级"；EXC 目录 12 个文件中**无 RUIF 硬依赖条目**（仅 ADR-AMD-1/2）。
- **后果**：按 GATE-COMP 铁律，"目标 Mod 缺失时可运行"不可证明 ⇒ 无法 PASS。
- **建议**：补 EXC 编号（引用 ADR-AMD-1/2 作为例外凭据）⇒ 该项转"带理由的 N/A"。车间侧实际降级是完整的（`RuifBridge.StatRowHeight` 有 `FallbackRowHeight` 回落）。
