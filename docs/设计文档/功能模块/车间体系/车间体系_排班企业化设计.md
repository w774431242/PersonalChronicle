## 2. 倒班数学模型（`WorkshopCrewCycle`）

设班组数 `C`、班次数 `S`。第 `d` 天，第 `c` 个班组的岗位序位 = `(c + d) mod C`：

- 序位 < `S` ⇒ 上该序位对应的班次（0 = 早，1 = 中，2 = 夜）；
- 序位 ≥ `S` ⇒ **当天休息**；
- 周期长度 = `max(C, S)`；每天休息班组数 = `max(0, C − S)`。

推论（已由单测钉死）：

| 制度 | 参数 | 行为 |
|---|---|---|
| 三班倒 | C=3, S=3 | 每天三班各一组人，无休，3 天轮一圈 |
| 两班倒 | C=2, S=2 | 白/夜两班逐日互换 |
| **四班三运转** | C=4, S=3 | 每天恰好 1 组休息，每组"上 3 天休 1 天"（连续生产最常见） |
| 编制不足 | C<S | 每天有 `S−C` 个班次**无人**（排班表会亮出停班格） |

相位：调用方传 `当前日 − CycleAnchorDay`，用于车间之间错峰交接。

## 3. 落地细节

- **一键组建**：排班页「套用班制 → 生成班组」→ 若车间尚无班组，按 `S+1` 组建（= 四班三运转），
  并把车间人员名单**轮流编入**各班组；随后生成的班次自动带 `UseCrewCycle = true` 与序位 0/1/2。
- **运行期**：`RebuildDutyPlan` 解析每个班次"当天该谁上"——该班次序位的班组编制成员即为候选池；
  该组当天休息 ⇒ 该班次当天停班（不会误派）。
- **手工路径不受影响**：不启用班组轮转的班次仍走"自定义池 → 车间人员名单"；老档 `crews` 为空 ⇒ 行为与升级前完全一致（向后兼容）。
- **清理**：`PurgeDeadReferences` 会剔除班组编制里的死亡/被删引用。

## 4. Phase 2（已落地 2026-09-11）

| 项 | 承载 | 口径 |
|---|---|---|
| **调休 / 请假 / 顶班** | `WorkshopCrewException`（zone 存档，按绝对日 + 班组）；倒班表**点格子**循环"正常 → 请假 → 顶班 → 正常" | 请假让出班次；顶班补到"当天没人顶的班次"（通常即请假让出者）；本应上班者标顶班无效（不许一天两班）；无空缺则仍休 |
| **考勤与加班** | `WorkshopAttendance`（zone 存档，按日累计，保留 15 天） | 实际人时 = 值勤时长之和；**加班** = 单次值勤超出当班班次时长的部分；计划人时与出勤率当场由排班表算（不落库，避免口径漂移） |
| **KPI 看板** | 倒班表底部 4 卡 | **出勤率** = 实际/计划人时；**加班** = 当日加班人时；**工时利用率** = 计划人时 ÷（编制人数 × 24h）；**稼动率** = 本车间设备中"运行"占比（OEE 可用率简化口径，瞬时值） |
| **交接班** | 新视图「交接·点检」上半 | 当前班次（班组/时段/在岗人数）· 距下次交接小时数 · 待加工工单数 · 故障+断电设备数 |
| **设备点检** | 同视图下半（表） | 设备 / 状态 / 工单数 / **当班责任班组**；状态走唯一实现 `WorkshopDeviceStateResolver`（自报优先 → 原版 comp 反推），与设备页、稼动率同源 |
| **错峰相位** | 倒班表顶部 ± 按钮 | 写 `CycleAnchorDay`，用于车间之间错开交接班 |

仍未做（如需要再排期）：**交接记录的历史留档**（当前只显示"当班此刻"的快照，不存历史）、**良品率的实测统计**（现只有 `goodRateFactor` 设计值）、**请假审批/调休额度**等流程性概念。

## 5. 验收锚点（实机）

1. 排班页第 3 个视图「倒班表」：行 = 班组、列 = 周期天数、格 = 早/中/夜/休，今天列高亮。
2. 「套用班制 → 生成班组 → 三班倒」⇒ 自动建 4 个班组（四班三运转）+ 3 条班次；表上每天恰好 1 组「休」。
3. 到点后：当日对应班组的成员上岗（其他人不上），轮休组当天不派工。
4. 班组行首点击可"加入成员 / 清空 / 删除"，改动即时反映到表与上岗名单。
