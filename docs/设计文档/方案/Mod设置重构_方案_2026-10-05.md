## 0. 问题定性

设置页当前**塞了大量内部实现细节**（本该内定的行为被做成玩家开关），而真正属于玩家决策的项反而没有被认真设计（无联动、无护栏、披露文案与实现不符）。本次按三种口径收口：

| 口径 | 含义 |
|---|---|
| **开关化** | 值得给玩家决策的布尔项，保留/修复，并补齐联动与披露 |
| **阈值化准入** | 数值项补单位 / 合理区间 / 默认值 / 越界护栏，并说明区间依据 |
| **默认化移除** | 从设置页撤下、改为内定默认行为（并优化默认值） |

## 3. 阈值化准入边界设计

| 项 | 单位 | 区间（代码常量） | 默认 | 护栏语义 |
|---|---|---|---|---|
| `MaxEventsPerPawn` | 条/人 | `[10, 1000]`（`SettingsDrawer.cs:496-497`） | 200 | 下限保底留存。**发现边界缺陷 D6**：区间 `[10,23]` 存在「分类预算反转」——routine 预算 `max(24, max/3)` 在 `max≤23` 时（=24）**反超**其它事件预算（=max），语义倒挂。建议下限上移（推荐 **72 = 3×24**） |
| `AutoArchiveSilver` | 银币 | `[0, 5000]`（`:498-499`） | 200 | `0` = 事实上不归档；`5000` ≈ 几乎所有死者可归档（仍有 purgeDays 后悔期兜底）。建议高段加提示「将归档几乎所有死者档案」 |
| `AutoArchivePurgeDays` | 天 | `[7, 365]`（`:500-501`） | 30 | `7` = 一周后悔期；`365` = 一年封顶 |

### 3.4 「保留天数 = 7 / 30 / 365」疑点：**已查清，不成立**

任务前置假设「若声明下限 > 7 则是既有缺陷」**不成立**，逐条证据：

1. **下限就是 7**，不是 30：`SettingsDrawer.cs:500-501` `PurgeDaysMin = 7f / PurgeDaysMax = 365f`；旧绘制路径同为 `7f, 365f`（`ChronicleSettings.cs:278`）。全仓无任何把 30 当下限的代码。
2. **`30` 的真实身份 = 字段默认值**：`ChronicleSettings.cs:118`（`= 30`）与 Scribe 默认 `:161`。
3. ⇒ **「值低于声明下限」缺陷判定：不成立**。截图中的 7 只可能是「值 = 下限」这一合法状态。
4. 旁证：现行配置 `Config/Mod_PersonalChronicleVer0.1_PersonalChronicleMod.xml` **无** `autoArchivePurgeDays` 键（Scribe 跳过「值 = 默认值」字段）⇒ 上次写盘时值 = 默认 30；同文件含 `debugLiveCount=True`、`enablePerfProbe=True`（确被手动打开过，印证 §2 发布动作）。
5. **实机 3 秒复核法**：打开设置 → 档案页 → 看该行四数字位置关系 `[值列] [min] —— [max]`。值列 = 30 ⇒ 一切正常；值列 = 7 ⇒ 玩家拖到底而已。

## 4. 存档 / 配置兼容结论

**核心取证（本方案新增，档文件级）**：`Autosave-1.rws`、`新移民1.rws` 内**无** `ModSettings` / `ChronicleSettings` / `enableOffShiftCancel` / `themeId` / `maxEventsPerPawn`；含 `ChronicleGameComponent=True`、`workshopWorkTakeover=True`。
⇒ **ModSettings 全部 16 项不随存档保存**，只存在于全局 `Config/Mod_*.xml`。故「旧档可加载」不受键增删影响；验证重点是「**旧 Config + 旧档**」双口径。

| 处置路径 | 适用性 | 理由 |
|---|---|---|
| **停止读取 + 残留键忽略 + 弃用登记**（✔ 推荐） | 全部 4 个「默认化移除」字段 | 本仓两次先例：`CHG-20261005-MEALBYSHIFT` 删 8 字段（注释自证「旧档键被 Scribe 忽略，无需 Migration」）、`CHG-20261004-WORKTAB-ORIGINAL` 停止读取残键忽略。Scribe 按 label 查找，多余键零副作用 |
| 保留读取 + 忽略写 | ✘ | 留死字段 = 技术债 + 误导后人，且无任何消费者 |
| 显式 Migration | ✘ | 无值需翻译（均属「回落新默认可接受」型） |

**必做披露**：曾把 `autoRestoreOnShift` 设为 `false` 的玩家，升级后自动回写**恒开** ⇒ 变更标注 + Changelog 必须显式列为**行为变更**（REL-001，Breaking 分类）。
**SchemaVersion 不 bump**（存档形状未变，键增删不属 schema 变更，沿先例）。
