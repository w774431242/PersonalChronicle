# Mod 重命名与 About 方案

日期：2026-10-05。状态：历史方案已被用户最终决定取代。最终名称为 **殖民地综合管理系统**，版本 **0.1**，独立标识 `colony.integratedmanagement`，按新账号新条目准备。现已落实中文 About、独立发行目录与新封面，旧工坊关联已留档移出开发区；尚未上传。当前操作依据见 [0.1 新账号首发准备记录](../../开发参考/发布/0.1新账号首发准备记录.md)。下文候选名与 XML 为此前讨论过程，不能继续用作发行源；生效元数据以根目录 `About/About.xml` 为准。

## 1. 中文品牌与命名方向

本轮确定：名称以中文为主，采用独立品牌名配合管理系统副标题；新发行版本统一为 **0.1**；介绍、更新日志与展示素材以中文为主。下列名称仍是候选，不视为已经定名。

**推荐品牌名：星枢**  
**工坊标题 / Mod 列表显示名：星枢 · 殖民地综合管理系统**  
**展示副标题：人员组织 · 生产调度 · 资源运营 · 档案追溯**  
**一句话定位：以总控中心串联人员、车间、制造、物流、库存与档案的殖民地管理系统。**

“星”对应太空殖民地题材，“枢”对应总控与多系统协同。主品牌用于图标和封面，完整名称用于 Mod 列表与工坊标题；品牌不以当前某个单一功能命名。

档案馆作为系统内的记录与追溯模块保留，品牌主视角改为管理系统。游戏中继续以“总控中心”作为管理入口，“档案馆”作为档案入口，不必把每个功能按钮都改成品牌名。

| 完整名称候选 | 命名气质 | 侧重点 |
|---|---|---|
| 星枢 · 殖民地综合管理系统（推荐） | 科幻、现代、平台化 | 以总控串联多个管理模块 |
| 星环统筹 · 殖民地运营系统 | 组织与运营 | 突出人员、班组与资源协同 |
| 殖星矩阵 · 殖民地管理平台 | 科技与系统化 | 突出多模块、数据和设备网络 |
| 环界中控 · 殖民地管理系统 | 工业与控制中心 | 突出制造、排班和监控界面 |

上述中文候选未做完整同名检索；最终定名前核查工坊同名情况。当前文案不再使用英文副品牌。

### 文字与版本约定

- 显示名称、简介、功能说明、更新日志、安装与升级说明、封面及截图注释均以中文为主。
- 英文翻译作为可选补充，不在主标题中并列英文名；现有英文游戏语言支持可保留。
- 游戏与第三方依赖专有名称可保留，例如 RimWorld、Harmony、RUIF；功能和依赖说明使用中文。
- 新发行 About 的 `modVersion`、封面版本、工坊介绍与新发行日志均统一为 **0.1**，不再沿用上一方案的 1.5.0。
- 发行版本重置不代表 API 契约、存档 schema 或第三方依赖版本重置。它们按各自兼容规则维护。
- `packageId`、DLL、命名空间、DefName 等供程序识别的标识保持合法且稳定，不做无必要的中文化迁移。

## 2. About 字段方案

| 字段 | 当前 | 推荐方案 |
|---|---|---|
| `name` | Personal Chronicle - Archive | 星枢 · 殖民地综合管理系统（候选） |
| `author` | Personal Chronicle Team | CK3专用号（按当前工坊昵称建议；署名可另定） |
| `packageId` | PersonalChronicle.Archive | `personalchronicle.xingshu`，配合推荐候选名，用于新的独立条目 |
| `modVersion` | v1.4.1（旧版现状） | **0.1（已按用户要求确定）** |
| `supportedVersions` | 1.6 | 保持 1.6 |
| `modDependencies` | Harmony + RUI Framework | 保持实际依赖 ID；RUIF 描述要求至少 1.2.0 |
| `loadAfter` | Harmony + RUI Framework | 保持对应 ID |
| `incompatibleWith` | 无 | 声明旧版 `PersonalChronicle.Archive`，提示勿同时启用 |
| `modIconPath` | UI/ArchiveIcon | 草案先引用现有资源；新图标就绪后再替换路径 |

`packageId` 是游戏 Mod 标识，`PublishedFileId` 是工坊条目标识，两者独立。新条目可使用新的 packageId；这会改变存档 Mod 列表及第三方依赖的识别，需要迁移说明和旧档验证。若最后决定沿用旧 packageId，新旧包将共用同一身份，不能用本草案的旧版 `incompatibleWith` 声明；那属于另一种封装策略。

新版 packageId 不要求同步重命名 DLL、命名空间、DefName、Harmony ID 或存档类型。首轮封装保留 `PersonalChronicle.dll`、`PersonalChronicle.*`、既有 DefName、Scribe 键和 `PersonalChronicleApi`，减少迁移范围。旧、新包具有重叠类型、Def 与补丁，不支持同时启用。`incompatibleWith` 用于冲突提示，不等于绝对禁止加载。

RUIF 仍用 `PersonalChronicle.RUIFramework`；它是独立依赖，不随本 Mod 改名。发行版本与 API 版本分别管理；当前 API 源码为 1.2.0，删除旧 About 中“API 1.0 与发布版本一致”的错误声明。

## 3. 中文 About 文案

星枢是一套面向《边缘世界》的殖民地综合管理系统。以总控中心为入口，将人员组织、车间生产、物流运输、库存经济与历史档案纳入统一的管理界面。

从班组排班到设备产出，从资源流转到人物生涯，持续掌握殖民地的运行状态，让组织安排、生产记录与资源变化有据可查。

当前版本：0.1

主要功能
- 总控中心：集中查看系统入口、殖民地概况及已接入的运行指标。
- 车间管理：划定车间、组织班组、安排班次与倒班，配置岗位、作息及班中三餐。
- 制造管理：俯视图与自由编排画布、设备详情、工单信息及设备产出统计。
- 农业与物流：三档自动农机、设备储物、传送带及管道运输。
- 库存与经济：财富与库存市值、库存数量 K 线和分类热力图。
- 人员与档案：职业成长、工时、人物经历、物品流转、战役与地点记录。

运行要求
- RimWorld 1.6。
- 必需依赖：Harmony 补丁框架与 RUI 界面框架（RUIF 1.2.0 及以上），两者先于本模组加载。
- 简体中文为主要展示语言，保留英文游戏语言支持。

使用说明
- 从底部“总控中心”进入管理界面，从“档案馆”查看记录。
- 车间编组会联动参与人员的相关工作档位和作息；实际生产仍使用原版工作与工单。
- 经济模块只做观测与记账，不通过市场模拟改变原版物价。
- 本项目持续开发中，部分系统入口为预留，部分自动化设备仍使用测试期配置。

旧版升级
本项目由“殖民地档案馆”扩展而来。切换前备份存档，只启用新版，避免与旧版同时加载。新版独立模组标识的旧档切换需要验证，首发前不作无损迁移承诺。

## 5. 新上传封装方案

1. 保留旧条目及其 `3780570854` 关联作为旧版维护记录，创建独立的新版发布目录，例如 `RimWorld/Mods/星枢`；开发区路径可继续保留。
2. 新包采用上述候选 About，并只装入现行运行资源、许可及新版展示素材；首发前修正测试期配置或明确测试状态。
3. **新上传包不得携带旧 `About/PublishedFileId.txt`**。旧关联先留档，新包中不放该文件；重新加载 Mod 元数据后，新建上传才会进入新条目创建路径。不要在旧发布目录直接清掉关联。
4. 当前部署脚本会复制开发区 `About/PublishedFileId.txt`，实现新封装时必须专门区分首次创建与后续更新，避免把旧 ID 又复制回来。源/目标 packageId 校验也需要为新的发布目录初始化匹配元数据。
5. 新条目创建成功后，游戏会写入新的 PublishedFileId；记录新 ID，后续更新必须保留它。新建条目与修改旧条目是 Steam 的两条操作路径，[官方实现说明](https://partner.steamgames.com/doc/features/workshop/implementation)。
6. About 负责游戏内元数据；工坊页标题、描述、前置条目和展示图也需核对。创建新条目不会迁移旧条目的订阅、评论及更新历史。
7. 新预览图以“星枢”为主品牌，“殖民地综合管理系统”为副标题，版本统一标注“0.1”；展示说明以中文为主。截图排序改为总控概览 → 车间 → 班组排班 → 设备 → 库存 → 档案。图标资源未产出前不填不存在的路径。
8. 改名首发核验：单启新版、新档启动、旧档副本切换、保存再读、设置保留、Def 引用、Harmony 日志、依赖加载及发布目录体积。首发迁移说明按实际结果完善。

此处“新包首次创建不带 PublishedFileId”限定于新建独立条目；已有条目更新仍遵循发布规范，保护现有工坊 ID。
