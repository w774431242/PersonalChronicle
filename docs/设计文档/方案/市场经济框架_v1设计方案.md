# 市场经济框架（MVS）· v1 设计方案

- 目标 Build：**RimWorld 1.6.4871 rev590**
- 本方案性质：**设计规格**（不出代码）。全程未改动任何工程代码。
- 定稿依据：架构设计部 Phase 1 输出 + 机制研发部 M1–M6 + 数据与存档部 D1–D7 + 主理人 Mono.Cecil IL 取证（`Assembly-CSharp.dll`）
- 前置文档：`市场经济框架_同类Mod架构横向解析.md`（同类 Mod 全谱与反编译解析，含 §10 可行性裁决）

---

## 1. 目标与非目标

**目标**：一套**按派系背景驱动的、稳定的供需市场**，并**奠定库存与贸易的数据基础**。

**非目标（v1）**：不做 UI；不做商队/交易流程接管；**默认通道不引入 Harmony**；不做实时重定价；不做派系差异化成交价（属 v2）。

---

## 2. 口径：两步走（用户已拍板）

**v1 ＝ 弱口径**：价格由**全球统一供需**驱动；派系背景只决定该派系的**库存 / 货物构成 / 经济画像**，**不影响价格**。

**v2 ＝ 强口径**：派系差异化成交价 → 启用 **B 通道**（Harmony 写 `Tradeable` 私有价字段）。B 通道接口在 v1 **预留但不启用**（默认关，EXC-002/E2 保持登记）。

> **为什么必须两步走（IL 依据）**：`RimWorld.StatRequest` 确有 `Faction` 槽位，但 `StatRequest.For(Thing)` 用 `initobj` 清零后只写 `thingInt`/`defInt`/`stuffDefInt`/`qualityCategoryInt`，**从不填 `faction`**（唯一填 faction 的重载是 `For(RoyalTitleDef, Faction, Pawn)`）。而 `Thing.get_MarketValue` 走的正是 `For(thing)` ⇒ **MarketValue 路径上 `req.Faction` 恒为 `null`**。且 `StatRequest` 是按值传递的 struct，Harmony 后缀也改不到调用方副本。⇒ 零 Harmony 的默认通道**物理上看不到交易对手派系**。

---

## 3. 分层与依赖方向

```
Foundation → Domain → Application → Data → (Presentation / Compatibility)
```

| 层 | 内容 |
|---|---|
| **Domain**（纯，零库类型依赖） | `FactionArchetype`、`SupplyDemandModel`（供需→因子**纯函数**）、`MarketFactor`、`ICommodityIndex` |
| **Application** | `MarketService`（离线预计算 / 衰减 / 守恒 / 复位）、`MarketScopeGuard`（`[ThreadStatic]` 深度计数 + `try/finally`） |
| **Contracts** | `IMarketFactorProvider`、`IMarketReadModel`、DTO 快照、**`IMarketPriceChannel`（B 通道抽象）** |
| **Data** | `WorldComponent_Market`（权威因子表 + 虚拟库存 + schema）、`CommodityRegistry`（三轴惰性 HashSet） |
| **Compatibility** | `MarketBridge`（分派·**零库类型**）、`StatPart_MarketValue`（库类型方法体）、`MarketHarmony`（B 通道 2 Postfix，默认关） |

**依赖纪律**：B 通道接口**只在 Contracts 抽象、Compatibility 实现，不进 Core**；`StatPart` 属消费侧库类型，**不进 Domain/Data**。

> **⚠ 2026-09-19 修订（CHG-MVS-SETTLE-001，结算器落地）**：上表 Application 行写的
> `MarketService`（离线预计算 / 衰减 / 守恒 / 复位）**从未落地**，且按此分配是**不可行**的 ——
> 结算的驱动面只有 `WorldComponentTick`（宿主 `WorldComponent_Market` 在 **Data**），
> 若结算体住 Application，Data 就必须反向调用它 ⇒ 违反「**Data 不得依赖 Application**」。
> **现行裁决（与代码一致，以本条为准）**：
>
> | 职责 | 落点 |
> |---|---|
> | 冲击数学（对数域偏移、半衰、目标因子） | **Domain** · `MarketShockModel`（纯函数）＋ 既有 `MarketFactor` |
> | 冲击累加 / 状态推进 / 结算编排 | **Data** · `WorldComponent_Market.Settlement.cs`（partial，零新类型） |
> | 采集入队（Application → Data） | **Application** · `MarketEventSink.RecordCore` → `MarketAccess` → `EnqueueShock` |
> | 读取（Data → Contracts → 消费方） | **Application** · 适配器 + Read Model（方向不变） |
>
> 即：Application 只承担「**入队**」与「**读**」两个方向，**结算本身不下沉到 Application**。

## 4. Def 规格

### 4.1 `CommodityDef : Def`（商品注册表）

| 字段 | 类型 | 说明 |
|---|---|---|
| `thingDefs` | `List<ThingDef>` | 精确命中轴 |
| `thingCategories` | `List<ThingCategoryDef>` | 品类轴（含后代，用 `ContainedInThisOrDescendant`） |
| `stuffCategories` | `List<StuffCategoryDef>` | 材料轴（变化经材料传导到成品） |
| `weight` | `float` | 权重；**数值待验证** |
| `severityLetters` | `List<...>` | 事件文案（**Keyed**，禁硬编码） |

命中语义：**三轴任一命中即归属**。

**惰性索引**：内部 `Dictionary<ThingDef, List<CommodityDef>>` + `Dictionary<ThingCategoryDef, ...>`（品类轴按子孙递归展开）。O(1) 签名：`bool AffectsDef(ThingDef)`、`IReadOnlyList<CommodityDef> ForDef(ThingDef)`。
**命中集＝可重建缓存，禁止 Scribe**；Def 加载 / mod 表变化时重建；无可用事件时"一次构建"，DevMode 重载后接受陈旧并可强制重建。

**不可越界**：不持运行时状态、不进存档、不做裸字符串匹配（`tradeTag` 弱匹配若需要须单列并可登记）。

### 4.2 `FactionEconomyExtension : DefModExtension`（派系背景画像）

**挂载点**：`FactionDef.modExtensions`。依据：`Verse.Def :: [pub] List<DefModExtension> modExtensions` 存在（IL 已证）；**原版不存在 `FactionDefExtension` 类型**，故必须自定义——好处是第三方 Mod **只写 XML 即可接入**。

| 字段 | 类型 | 说明 |
|---|---|---|
| `techTierOverride` | `TechLevel?` | 缺省 → 由 `FactionDef.techLevel` 做**确定性有限映射**（穷尽 switch，**禁随机**） |
| `preferred` / `avoided` | `List<CommodityDef>` | 画像偏好，**Def 引用**非字符串 |
| `stockBaseline` | `List<{CommodityDef, float}>` | 库存基线，**符号参数** |
| `usePriceChannel` | `bool` | B 通道预留位，默认 `false` |

**缺省路径**：未挂载 extension 的第三方派系 → 全画像走 `techLevel` 映射、偏好为空、基线由外部参数供、B 通道关。要求**确定 / 有限 / 无随机**。

**未核实**：`DefModExtension` 自身**没有生命周期钩子**（普通类）；`preferred` 的 `CommodityDef` 在**哪个阶段**解析完属 XML 加载层行为，Cecil 证不了 ⇒ **设计不得依赖"该引用在迁移/对账阶段已就绪"**，实现期须用最小样例验证。`MayRequire` 作用于 `modExtensions/<li>` 是否生效**同属未核实** ⇒ 在验明前 XML 示例不依赖它。

## 5. 运行时与桥守卫

### 5.1 定价通道 A（默认，零 Harmony）

`MarketBridge.TryGetFactor(string commodityId, out float factor)` —— **参数与返回零库类型**；返回 `false` 表示"无因子/未就绪"，调用方**原样返回**。

`StatPart_MarketValue : StatPart` 位于 Compatibility，`TransformValue(StatRequest req, ref float val)` 闸门顺序（**最廉价优先**）：

| 闸门 | 判定 |
|---|---|
| **G0** | `MVS_Enabled`（未注册即返回） |
| **G1** | `Current.Game != null && Find.World != null` |
| **G2** | `WorldComponent_Market.Ready == true`（**不判 GetComponent 是否为 null**） |
| **G3** | 由 `req` 解析 commodityId → 命中且 `TryGetFactor` 为真 ⇒ `val *= f` |

**四闸任一不过、或 G3 未命中 ⇒ `val` 不修改**（一个字节都不改）。

**为什么 G1/G2 必需（IL 依据）**：`WealthWatcher.ForceRecount(**Boolean allowDuringInit**)` 是专为"初始化期也算财富"而留的参数，而它读 `MarketValueIgnoreHp` 与 `Thing.get_MarketValue`；Vanilla Trading Expanded 也专门打 `ResetMarketValue_Patch` 包住 `GenStep_PreciousLump.Generate` 与 `GenStep_ScatterLumpsMineable.ChooseThingDef`（若地图生成期不读市价，该补丁没有存在理由）。⇒ StatPart **会在组件未就绪 / 世界未生成的时机被调用**。

**`ExplanationPart(StatRequest)`**：文案**走 Keyed**（如 `"MVS_MarketValueExplain".Translate(...)`），禁硬编码。

**禁止回读原值**：`Verse.ThingDef.get_BaseMarketValue()` → `GetStatValueAbstract(MarketValue)`、`RimWorld.Tradeable.get_BaseMarketValue()` → `Thing.get_MarketValue` —— 两条都会**重入**。安全读法只有：`Verse.BuildableDef.statBases`（`[pub] List<StatModifier>` 原始字段），或**干脆不回读**（`val` 进参已是含前序 parts 的累计值）。若要回读，须加 `[ThreadStatic]` 深度计数自重入守卫（`++` / `finally --`，`>1` 即判定自重入 → 原样返回）。

### 5.2 `<priority>`：把"链尾"从碰巧变成确定

```xml
<PatchOperationAdd>
  <xpath>/Defs/StatDef[defName="MarketValue"]/parts</xpath>
  <value>
    <li Class="MarketEconomy.Compat.StatPart_MarketValue">
      <priority>-1000</priority>
    </li>
  </value>
</PatchOperationAdd>
```

**依据（IL）**：`StatDef.PostLoad` 内 `GenCollection.SortBy(StatDef::parts, x => -x.priority)` —— 键取负后升序 ⇒ **实际按 priority 降序，priority 越大越先执行**。XML 不写 priority 时为 `0f`，而原版 `StatPart_Quality`/`Health`/`Age` 也是 0 ⇒ **同优先级并列，相对位置不受保证**。
⇒ 要让"我方因子最后执行"（乘在原版品质/耐久/年龄与其后所有 part 之上）**必须显式写大幅负值** `-1000`。

**位置语义的取舍依据**：`StatPart_Quality.TransformValue` 含 `mul + sub + add`（原版有 `factorAwful..factorLegendary` 乘数**且** `maxGainGood/Excellent/Masterwork` **加法上限**，上限相对 vanilla 基值衡量）⇒ **原版 parts 链非纯乘性、位置不可交换**。因此让 Quality/Health/Age 先在 vanilla 基值上完成、再由我方做外层统一乘算，语义最干净；生态里 `Pawnmorpher` 的 `val +=` 加算型 part 亦被统一缩放，符合"全局市场系数"语义。
**正确性不得依赖排序**：`SortBy` 稳定性未逐字确认，若他人也用极负值则并列致序不定 —— 我方仅做乘算、闸门失败无条件不动 `val`，已满足该纪律。

### 5.3 `WorldComponent_Market` 的组件契约

**基类**：`RimWorld.Planet.WorldComponent`（`[abstract]`，`implements Verse.IExposable`）。
**⚠️ 签名差异**：`WorldComponent.FinalizeInit(**Boolean fromLoad**)` **带参数**；`Verse.GameComponent.FinalizeInit()` 无参。**不要照抄 `GameComponent` 的签名。**
驱动链：`World.FinalizeInit(bool)` → `WorldComponentUtility.FinalizeInit(World, bool)` → 逐组件 `FinalizeInit`。

**对外暴露分级**：

| 调用方 | 入口 |
|---|---|
| Bridge（唯一窄入口） | `TryGetFactor(string id, out float)` |
| **Application · 事件采集（v2 新增）** | `EnqueueShock(MVSIncidentImpactDef impact, int tick)` —— **O(1) 入队、零品种展开、绝不抛**；自带「`Ready` + 非只读降级」双闸门；由 `MarketEventSink.RecordCore` 在**去重门之后**调用 |
| Application / 读模型 | `GetBaseline(Faction, string commodityId)`、`IMarketReadModel` 实现 |
| B 通道 | `ApplyExternalFactor(...)`（默认关） |
| 数据部 | `ExposeData()`、`SchemaVersion`、迁移钩子 |
| **诊断 / 测试（v2 新增）** | `PendingShockCount` / `PendingShockDropped` / `SettleSteps`（只读，不落盘） |
| **private** | 内部字典、重建 / 衰减、对账、结算步 `SettleMarket` |

**禁止**：缓存 MarketValue、写 UI / 翻译、每帧全库扫描。

> **Hook 面登记（v2 新增，2026-09-19）**：本组件覆写 **`WorldComponentTick()`** 作为结算驱动面。
> 依据（Mono.Cecil 实测，1.6.4871 / Assembly-CSharp 15,777,280 B）：
> `RimWorld.Planet.WorldComponent` 有 `[public virtual] Void WorldComponentTick()`；调用链
> `TickManager.DoSingleTick → World.WorldTick → WorldComponentUtility.WorldComponentTick(world)`
> 遍历 `world.components` 逐个调用 ⇒ **每游戏 tick 一次**。
> ⚠ 原版该工具方法自带 try/catch + `Log.Error`（异常不炸链，但会**每 tick 刷日志**）⇒
> 覆写方必须自守卫：**组件内自节流**（`SettlementIntervalTicks`，非 `tick % N`）+ 整体 try/catch +
> 节流日志 + **先锚定时间戳再结算**（把异常重试频率钉在 1 个结算间隔）。
> **不是 Harmony**（原生虚方法），故无需新 EXC；但 `EXC-2026-006` 的「零 mutation」登记已随之更新。

**构造期纪律（由 `FillComponents` 语义推出）**：反射补建发生在 `components.RemoveAll(...)` 之后、且 `components` 尚未构造完 ⇒ **ctor 内只允许存 `world` 引用 + 置空态**；禁读 `world.components` / `world.factionManager`、禁建索引、禁任何 Scribe / 落盘。一切初始化推后到状态机 `Boot`。

### 5.4 `Ready` 状态机（顺序无关）

```
Boot → Migrated → Reconciled → Ready
```
每一步**只做一次**且前置条件自检；`ExposeData` 的 `PostLoadInit` 与 `FinalizeInit` **两个钩子都尝试推进**该状态机（谁后到谁把链跑完）；`Ready` 置位后才允许 `TryGetFactor` 返回非中性值。**`Ready` 未置位期间的读请求一律走中性 / `Unavailable`，不缓存、不落盘。**

**为什么必须顺序无关**：`ScribeLoader.FinalizeLoading()` 内已证 `CrossRefHandler.ResolveAllCrossReferences()` **先于** `PostLoadIniter.DoAllPostLoadInits()`；但 **`PostLoadInit` 与 `FinalizeInit` 的相对先后无法从现有 IL 断言** ⇒ 迁移（原拟落 `FinalizeInit`）与对账（原拟落 `PostLoadInit`）**不得依赖彼此先后**。

**三条收敛路径都必须到 `Ready`**：新档 `Game::InitNewGame → FinalizeInit`；读档 `Game::LoadGame → FinalizeInit`；新世界 `WorldGenerator::GenerateWorld → FinalizeInit`。

## 6. 存档 schema（v1 → v2）

**宿主**：`WorldComponent_Market`。**契约级硬要求**：`public`、**非 abstract**、**必须提供 `public WorldComponent_Market(World world)` 单参构造** —— 因为原版按 `Activator.CreateInstance(t, new object[]{ world })` 补建（见 §7.1），只有无参构造会在旧档补建时**直接抛异常**。

| 字段 | 类型 | 默认值 | 稀疏 | 序列化 |
|---|---|---|---|---|
| `schemaVersion` | `int` | **0（哨兵，不是 1）** | 否 | `Scribe_Values.Look(..., 0)` |
| `globalFactors` | `Dictionary<string,float>` | 缺键 ⇒ 中性因子（符号，外部参数） | 是 | 4 参 `Value/Value` |
| `inventory` | `List<FactionInventoryEntry>` | 无 entry ⇒ 未涉足；缺商品键 ⇒ `Unavailable` | 是（两级） | 外层 `LookMode.Deep`，内层 4 参 `Value/Value` |

```csharp
FactionInventoryEntry : IExposable {
    int loadID;
    string factionDefName;
    Dictionary<string,int> amounts;
}
```

**关键裁定**：
- **`schemaVersion` 必须用 0 哨兵**。IL 证实 `Scribe_Values.Look` 方法体内为 `if (!forceSave && value.Equals(defaultValue)) return;` ⇒ 若 default 写 1，v1 **永不落盘**。
- **双键不用 `LookMode.Reference`**：`Reference` 走 `CrossRefHandler`，对象不存在即置 null + 警告、键静默消失；纯值 `int loadID` + `string factionDefName` **不参与交叉引用解析**，死活由我们自己的对账判定 ⇒ 悬空变为**可诊断孤儿键**。
- **不采扁平复合键**（如 `Dictionary<string,int>` 拼 `loadID|defName`）：`defName` 原版**无字符集约束**，分隔符有碰撞与非法字符（可能产出非法 `.rws`）风险。两字段显式序列化则**零解析、零分隔符依赖**，且 `loadID` 复用时仍能按 `defName` 二次判别。
- **`inventory` 存量值＝`int`，语义严格锁定为「物理件数」**；**所有归一化 / 派生量**（供需比 `r`、均衡存量、弹性中间量）**一律不落盘**（可由「存量 + Def 静态 + 外部参数」重建）⇒ 存档契约内**不存在"小数存量"概念**，`int→float` 破格式风险从源头消失。`globalFactors` 保持 `float`。
- **稀疏策略**：未涉足派系不建 entry；派系内未涉足商品不建键；**因子回归中性时删键**（保持"缺键＝中性"单一语义）。不做全笛卡尔积物化。

### 6.1 `MigrateIfNeeded`（幂等）

1. 落点：`FinalizeInit(bool fromLoad)` 推状态机（**禁写 `ExposeData` 的业务逻辑**）。
2. 读 `schemaVersion`（缺失已由 default=0 归一）。
3. **破格式前置拒绝**：`schemaVersion > Current` → Keyed **Error** + 置只读降级标志，**不迁移、不回写、不抛异常**。
4. 顺序推进一级一步：`if (schemaVersion < N) { MigrateTo(N); schemaVersion = N; }`；只 `if` 链尾追加，**禁 `else-if` 串联**。
5. v0→v1：集合 `??=`；缺键视作中性且**不物化**；孤儿键交对账。**不产生任何数值**。
6. 未来加字段模板：默认值由 `Scribe_Values.Look(default)` 承担 ⇒ `MigrateToV2()` 可 no-op，但**版本号必须 +1 并写进链尾**；改语义 / 删字段须显式转换或留别名读路径。
7. 校验：`schemaVersion == Current`；集合非 null；每 entry `loadID > 0` 且 `factionDefName` 非空；数值 `float.IsFinite`。失败**降级不报错**：单条不合法只丢该条 + 日志，**绝不阻断整档**。
8. 写回 `schemaVersion = Current`；结构变动则 `RebuildIndexes()`。

**幂等论证**：判据只有单调的 `schemaVersion`，且每级成功才推进 ⇒ 二次执行全部 `if` 为假 ＝ no-op；迁移体只做 `??=` / 补默认 / 规范化 / 剪枝（减集），**不追加记录、不生成新 ID、不读 Tick / 语言 / 第三方 Mod**。

### 6.2 对账清理

`K_live = World.factionManager.AllFactionsListForReading`（IL 已证 `World.factionManager` 存在）；存活判据 `f.loadID == entry.loadID && f.def == entry.factionDefName && !f.defeated`（`Faction.defeated` 是 `[pub]` **字段**）。

- 差集孤儿**不删除**，读侧投影 `Unavailable`；**`Unavailable` 不入档**（可重建）。
  - `0` ＝ 已知无货；`Unavailable` ＝ 未知 / 不可交易 / 对象已亡。**语义不同，不可混用。**
- 孤儿 entry **保留**（防第三方 Mod 临时未加载造成永久丢数据）；v1 **只标记不删除**。
- **原版没有"派系消亡事件"**（`FactionManager` 只有 `allFactions` / `toRemove` 列表）⇒ **只能轮询对账**，**禁每 Tick 全表扫描**，频率由外部参数给。
- 对账快照的失效信号：S1 世界重载 → `FinalizeInit` 无条件重建；S2 派系计数变化；S3 显式 recheck。重建路径 `ReconcileFactions()`。
- **不变式**：快照只存身份键，**不缓存 `alive`**，`defeated` **每次 live-read** ⇒ 陈旧快照不会把活派系误判为 `Unavailable`。

## 11. 首条产能链样板：Empire × 原木（wood）

> 本节是"派系经济背景 → 产能 / 消费 / 库存"的**第一条样板链**。数值锚**全部取自原版真实数据**（取证命令见 §11.5），非设计臆造；无法从静态数据确定的一律标「未核实」。

### 11.1 先定派系：为什么是 Empire

原版**没有"体量最大"这个量**——31 个 `FactionDef` 的 `settlementGenerationWeight` **一律为 1**、`requiredCountAtGameStart` 一律 1（少数 0），原版刻意让各派系地盘规模均等。故"最大"只能按**经济复杂度**取口径，Empire 四项居首：

| 判据 | 值 | 唯一性 |
|---|---|---|
| `techLevel` | **Ultra** | 唯一**可贸易**的 Ultra（Mechanoid 虽也是 Ultra，但 `permanentEnemy` 且无贸易） |
| `baseTraderKinds` | **1** | **全场唯一**有"基地商人"的派系 ⇒ 存在常驻据点级贸易层 |
| 货币 | 涉及 `Favor` | `TradeCurrency { Silver=0, Favor=1 }`，唯一涉及第二货币的派系 |
| 描述 | *"refuse to trade with anyone who lacks the appropriate royal title"* | **原版唯一一条"政治条件 → 交易资格"的现成规则**（机制未取证，仅见于 Def 描述） |

### 11.2 帝国的人口与经济结构假设（贴合游戏背景）

原版**没有派系人口计数**（IL 已证 `FactionManager` 无人口量、无消亡事件）。可用锚：`requiredCountAtGameStart = 1` / `settlementGenerationWeight = 1`（至少 1 个定居点，规模与其他派系均等）＋ `caravanTraderKinds = 1` / `baseTraderKinds = 1`（一支商队 + 一个基地商人）＋ `techLevel = Ultra`。

Def 描述原文给出三条社会特征：**"ultratech refugee society"（超技术残存文明）/ "strict class system"（严酷阶级）/ "enforced social stasis"（强制社会停滞）**。

据此假设人口经济结构（**三层生产力差异是核心**）：

| 层 | 占比（假设） | 生产 | 消费 |
|---|---|---|---|
| 上层（贵族 / 官僚） | 少 | **零生产** | 极高，**集中在象征性建造** |
| 中层（工匠 / 技术） | 中 | 高附加值制成品（仿生体、精密件、武器） | 中 |
| 底层（劳工） | 多 | 维持运转，**不扩张** | 低 |

**关键推论（决定原木市场的形状）**：帝国**不是**"生产→消费"闭环体，而是 **「高价值产出 + 高奢侈消耗 + 靠贸易补低级原料」**。⇒ 对原木这类**低级原料，帝国应当是净进口方**，而非自产自销。

### 11.3 供应端（产能）—— 全部锚在原版真实数值

原版树基类 `TreeBase`（`Core/Defs/ThingDefs_Plants/Plants_Bases.xml:88-129`）实测字段：

| 字段 | 原版值 | 含义 |
|---|---|---|
| `plant.harvestedThingDef` | **`WoodLog`** | 砍树产木材 |
| `plant.harvestYield` | **25** | **每棵树 25 木**（原版经典值） |
| `plant.harvestMinGrowth` | **0.40** | 成熟度 40% 即可采伐，**产量按成熟度缩放** |
| `plant.harvestWork` | **800** | 单株伐木工作量 |
| `plant.harvestFailable` | `false` | 不失败 |
| `plant.sowWork` / `sowMinSkill` / 前置研究 | 4000 / 6 / `TreeSowing` | **人工种植门槛高** |
| `plant.mustBeWildToSow` | `true` | 只能野外播种 |
| `chopped` / `burned` / `smashedThingDef` | `ChoppedStump` / `BurnedTree` / `SmashedStump` | 伐后残桩（各 30 天、4 木） |
| `plant.treeCategory` | `Full` | 完整树 |

树种 `growDays` 实测分布（`Plants_Wild_*.xml`，24 个值）：**2.5 / 5 / 6 / 12 / 13 / 14 / 15 / 15.05 / 20 / 27 / 30 / 32.5 / 35 天**。

**单位产能公式**（可复算）：
```
单株日产能 = harvestYield / growDays          ← 例：30 天的树 = 25/30 ≈ 0.833 木/株/日
区域日产能 = 单株日产能 × 单位面积株数 × 可采伐面积占比
```
**密度锚**（`BiomeDef.plantDensity`，25 个 biome 实测）：IceSheet 0 → Tundra **0.19** → BorealForest **0.40** → TemperateForest **0.65** → TemperateSwamp **0.80** → TropicalRainforest **0.90**。
**未核实**：`plantDensity` 到"每格株数"的换算（需游戏内实测）⇒ 上式第三项只作**相对锚**，不作绝对计数。

**帝国产能系数应当很低**：残存舰队文明 + 强制社会停滞 + 不扩张 ⇒ 可采伐面积占比低；且人工种植（`sowWork 4000` + 需 `TreeSowing` 研究）对它是非优先项。

**第一条腿：木质材料消耗**。原版实测：`stuffCategories` 含 `Woody` 的 ThingDef 共 **76 个**，`costStuffCount` 合计 **5310**。
DLC 分布：Core 46 / Ideology 20 / Royalty 5 / Biotech 2 / Anomaly 2 / Odyssey 1。

顶层消耗者：

| ThingDef | 材料用量 | 性质 |
|---|---|---|
| `SculptureGrand` | **400** | 奢侈品 |
| `Altar_Grand` / `NatureShrine_Large` | **300** | 宗教 / 权力象征 |
| `Altar_Large` | 200 | 象征 |
| `Apparel_PlateArmor` | 170 | 军事 |
| `TotemicSlab_Broad` / `AnimalistSlab_Broad` | 150 | 象征 |
| `MeleeWeapon_Warhammer` | 150 | 军事 |

| `SculptureLarge` / `MeleeWeapon_LongSword` | 100 | 奢侈 / 军事 |

**这张表的形状本身就是证据**：前 10 名里 **6 个是奢侈品与权力象征**（雕像×2、祭坛×2、王座、板甲）——**与"严酷阶级社会 + 残存舰队"高度吻合**。⇒ 帝国木材消耗集中在**象征性建造**，而非生产性建造。

**第二条腿：燃料**。`WoodLog` 带 `burnableByRecipe`，Core 内有 **3 处 `fuelFilter`**（`Buildings_Furniture.xml` ×2、`Buildings_Misc.xml` ×1）⇒ 木材同时是营火 / 火盆类建筑的燃料。这条腿是**持续消耗**（vs 建造是一次性），模型里必须与建造消耗**分开记账**。

**总库存**：原版**没有**派系级库存（IL 已证），只能自建；但**基线锚真实可读**：
- `Settlement_TraderTracker.StockListForReading`（`[public] List<Thing>`）⇒ 帝国定居点商人手里的实际木量，**开局直接采样**，不必凭空设定
- `StockGenerator` **13 个子类** + `TraderKindDef.priceFactors` 已移除 ⇒ 可**只读推导**某 TraderKind 是否带木头

库存演化式（**符号，数值待验证**）：
```
总库存 += 自产产能 + 进口 − 建造消耗 − 燃料消耗 − 出口
```
三个强制项（呼应 §9.1）：
1. **守恒**：产 + 进口 = 消耗 + 燃料 + 出口（逐 tick 校验，容差待验证）
2. **出口 sink**：帝国"社会停滞"⇒ 不扩张，多余木材**无自然去处**（原版木材不腐烂）⇒ 必须有 sink，否则单调累积
3. **软校正锚**：定期用 `StockListForReading` 的实际木量做**有限幅**校正，把模型拉回现实

`WoodLog` 本体实测：`statBases.MarketValue` = **1.2** 银 / `Mass` = **0.4** / `stuffProps.categories` = `Woody`。

### 11.6 设计闭环（本链最值得注意的一点）

因为帝国是「净进口方 + 高奢侈消耗」，**原木在帝国市场的均衡价格应当高于原版 MV 1.2 银/木**。这会自然产生"玩家向帝国卖木材很赚"的玩法；而帝国那条 **"无爵位不交易"** 的政策规则又构成门槛——**要赚这笔钱，先得有爵位**。政策与市场在这里第一次真正咬合，正是"派系经济背景 + 供需市场"想达到的效果。

### 11.7 帝国经济画像的数值模型（v1 起点，供数值部接手）

> 本节是 §11 的定量补充。**页面（玩家预览）只显示结论，推导过程留档在此**（用户 2026-09-17 要求从面板删除"映射"行）。

#### 11.7.1 数据语义前提（先定这一条，否则算法全错）

`FactionDef.pawnGroupMakers` 下的 `traders` / `carriers` / `guards` 与 `options` **同为 `List<PawnGenOption>`**（IL 实测）⇒ 其中的数值是**相对权重**，**不是人数**。`Empire_Fighter_Cataphract` 的 `1.5` 即为铁证（不可能有半个 pawn）。

**推论**：**构成比可从官方权重直接算；人数算不出来**（需 `maxTotalPoints` 预算 × `PawnKindDef.cost`，且随玩家财富浮动）。

#### 11.7.2 可从官方权重直接得到的构成比

| 组 | 官方权重 | 归一化结果 |
|---|---|---|
| Settlement（驻留武装） | 重装 2 / 精锐 4 / 近卫 3.5 / 步兵 5（合计 14.5） | 重装 **13.8%** / 精锐 **27.6%** / 近卫 **24.1%** / 步兵 **34.5%** |
| Trader（商队人员） | 护卫 31.5 / 商人 1 / 平民 3（人类合计 35.5；另驮畜 14） | 护卫 **88.7%** / 平民 **11.3%** |

#### 11.7.3 社会结构占比（三层）

**推导前提**：武装人口占社会 **40%**（依据：官方"无弱兵"注释 ＋ 三组权重一致 ⇒ 高度军事化）。

| 层 | 计算式 | 占比 |
|---|---|---|
| 上层（贵族 / 重装） | 40% × 13.8% | **6%** |
| 中层（精锐 ＋ 近卫） | 40% × (27.6% ＋ 24.1%) = 40% × 51.7% | **21%** |
| 底层（步兵 ＋ 非武装平民） | 40% × 34.5% ＋ 其余 60% | **73%** |

合计 100%。**唯一的设计假设是"武装占 40%"这个前提**，其余由官方权重推出。

#### 11.7.4 具体人数 —— 基础人数 × 影响因子（v1 模型）

**官方锚**：`requiredCountAtGameStart = 1`。
⭐ 注意 `maxConfigurableAtWorldCreation = 1` 是**世界上该派系实例数的上限**，**不是据点上限**（前期曾误读）。据点数无官方字段，由 `settlementGenerationWeight`（= 1，与外来者/部落同级）在世界生成时加权分配。

```
总人数 = 基础据点人口 × 据点数 × Π(社会因子)
       = 45 × 3 × 1.58
       ≈ 214
```

| 因子 | 取值 | 来源与依据 |
|---|---|---|
| 基础据点人口 | **45 人/据点** | ③ 设计假设（参照原版 NPC 据点地图生成规模；Ultra 技术据点取中等偏上） |
| 据点数 | **× 3** | ③ 设计假设（世界生成中非隐藏人形派系通常 2–5 个据点，取中值） |
| 产能过剩 | **× 1.5** | ① 官方 `techLevel = Ultra` ⇒ 单位产能远高于消耗，可供养的非生产人口比例高 |
| 贸易净进口 | **× 1.2** | ③ 设计推导（净进口低级原料 ⇒ 人口上限不被本地原料限制） |
| 军事化 | **× 1.15** | ② 官方推导（无弱兵、三组权重一致 ⇒ 军事人口本身计入人口且不挤占平民） |
| 社会停滞 | **× 0.85** | ① 官方描述 `enforced social stasis` ⇒ 抑制扩张与迁移 |
| 灾后残存 | **× 0.9** | ① 官方描述 `survivors of a great calamity` / `remnants of their fleet` ⇒ 基数受损 |

社会因子积 = 1.5 × 1.2 × 1.15 × 0.85 × 0.9 ≈ **1.58**；总人数 ≈ **214**。

**分层人数**：上层 **13 人** / 中层 **45 人** / 底层 **156 人**（合计 214）。

> ⚠ **全部为待验证量**。原版**无派系人口字段**，`基础据点人口 45` 与 `据点数 3` 是纯假设，**须游戏内实测校准**；三个负向因子（停滞 / 灾后）与两个正向因子（产能 / 贸易）的**具体倍率未经数值仿真验证**（门禁 ③ 未执行）。

### 11.8 原版据点数量机制取证（2026-09-17 补，Mono.Cecil 全覆盖）

**结论先行**：**原版不给出"任何派系的据点数"**。它给出的是**全星球据点总量**的计算参数，派系归属靠**逐据点独立加权抽签**——所以"帝国据点数"在原版语义里根本不是一个可配置量，而是一个**随机变量**。

#### 11.8.1 原版给出的具体数据（全部为硬证据）

| 数据 | 声明位置 | 原版取值 | 语义 |
|---|---|---|---|
| `settlementsPer100kTiles` | `PlanetLayerDef`（`[public] FloatRange`） | **C# 默认 `FloatRange(75, 85)`** | 每 10 万格据点密度；`RandomInRange()` 每次随机取区间内一个值 |
| `viewAngleSettlementsFactorCurve` | `PlanetLayerDef`（`[public] SimpleCurve`） | **C# 默认 `{(0,1),(1,1)}` = 恒 1** | 视角比例衰减因子 |
| `overallPopulation` | 世界创建滑条 → `World.info` | **7 档 0.1 / 0.4 / 0.7 / 1 / 1.5 / 2 / 2.75** | 全局人口缩放，**直乘据点总量** |
| `settlementGenerationWeight` | 每个 `FactionDef`（`[public] Single`） | **原版 31 家一律 `1`**（Empire 亦为 1） | 逐据点抽签的**权重**，不是数量 |
| `requiredCountAtGameStart` | `FactionDef`（`[public] Int32`） | Empire = **1** | 开局强制创建的**派系实例数** |
| `maxConfigurableAtWorldCreation` | `FactionDef`（`[public] Int32`） | Empire = **1** | 世界创建 UI 可调上限 —— 管的是**派系实例数，不是据点** |
| `startingCountAtWorldCreation` | `FactionDef`（`[public] Int32`） | 帝国 XML **未写**（用 C# 默认） | 只被世界创建 UI 消费 ⇒ **派系实例数默认值** |
| `layerWhitelist` / `layerBlacklist` | `FactionDef` | Empire 未写 | 派系可出现在哪些行星层；`whitelist` 空 ⇒ 仅根表面层 |
| `maxCountAtGameStart` | `FactionDef` | **1.6 零引用（死字段）** | `refs maxCountAtGameStart` 无输出 ⇒ **改了不生效** |

> ⭐ 两处关键取值都在 **C# 构造函数**里，不在 XML 中 —— 只读 XML 会得出"该字段不存在"的错误结论。
> 证据：`il RimWorld.PlanetLayerDef .ctor` →
> `IL_00A0: ldc.r4 75 / IL_00A5: ldc.r4 85 / newobj FloatRange..ctor` ⇒ `settlementsPer100kTiles = (75,85)`；
> `IL_00B5: newobj SimpleCurve..ctor` + `Add((0,1))` + `Add((1,1))` ⇒ `viewAngleSettlementsFactorCurve` 恒 1。
> Core 的 `Data/Core/Defs/PlanetLayerDefs/PlanetLayers.xml` 的 `Surface` 块**确实没有**这两个字段 ⇒ 用默认值。
> Odyssey 只在 `OrbitLayer` 抽象基类上覆写（`1000~1000` ＋ 衰减曲线 `(0,1)(0.3,1)(0.5,0.75)(1,0.5)`）。

#### 11.8.2 算法（`il RimWorld.FactionGenerator GenerateFactionsIntoWorldLayer` 逐条还原）

```csharp
InitializeFactions(layer, factions);            // 先按 requiredCountAtGameStart 建立派系实例
var candidates = Find.World.factionManager.AllFactionsListForReading.Where(Validator);
// Validator（IL: g__Validator|0）:
//   !def.isPlayer && !Hidden && !temporary && CanExistOnLayer(layer, def)

if (candidates.Any()) {
    float fAngle = layer.Def.viewAngleSettlementsFactorCurve.Evaluate(Mathf.Clamp01(layer.ViewAngle / 180f));
    float fDensity = layer.Def.settlementsPer100kTiles.RandomInRange();
    float fPop = OverallPopulationUtility.GetScaleFactor(Find.World.info.overallPopulation);

    int total = GenMath.RoundRandom(layer.TilesCount / 100000f * fDensity * fPop * fAngle);
    total -= Find.WorldObjects.AllSettlementsOnLayer(layer).Count;   // 减去已有据点

    for (int i = 0; i < total; i++) {
        Faction f = candidates.RandomElementByWeight(x => x.def.settlementGenerationWeight);  // ← 逐个抽签
        var wo = WorldObjectMaker.MakeWorldObject(layer.Def.SettlementWorldObjectDef);
        wo.SetFaction(f);
        wo.Tile = TileFinder.RandomSettlementTileFor(layer, f, mustBeAutoChoosable: false, extraValidator: null);
        if (wo is INameableWorldObject n) n.Name = SettlementNameGenerator.GenerateSettlementName(...);
        Find.WorldObjects.Add(wo);
    }
}
```

```

```
⇒ **确认 `RandomElementByWeight` 的权重就是 `settlementGenerationWeight`**。

**候选过滤器铁证**：`il "RimWorld.FactionGenerator/<>c__DisplayClass3_0" Validator full` → 依次判 `isPlayer` / `Hidden` / `temporary` / `CanExistOnLayer`。

#### 11.8.3 由此得到的推论

1. **帝国据点数 = 随机变量**，不是配置值。因原版权重全为 1，归属等价于**均匀分布**：
   `E[帝国据点] ≈ 总量 / 参选派系数`（原版参选约 9–10 家 ⇒ 约 10%）。区间无上界，只有总量上限约束。
2. **总量量级**（默认世界 150×150、`Normal` 人口、Surface 默认密度）：
   `TilesCount/100000 × 75~85`。≒ **5（仅陆地格）～18（含海洋格）**，随人口档位在 **0.5× ~ 2.75×** 间放缩。
   ⇒ `TilesCount` 是否含海洋格**未实测**，故此处标 **LAND-009 未验证**，须游戏内读 `Find.WorldGrid.Surface.TilesCount` 校准。
3. **11.7.4 里的「据点数 × 3」确属自设假设**，但**不必再假设**——原版提供运行时真值读取入口：

   | 需求 | 官方 API（IL 确认存在） |
   |---|---|
   | 全局据点列表 | `Find.WorldObjects.Settlements` → `List<Settlement>` |
   | 某层全部据点 | `Find.WorldObjects.AllSettlementsOnLayer(layer)` → `List<WorldObject>` |
   | 某派系是否有据点 | `Find.WorldObjects.AnyFactionSettlementOnLayer(f, layer)` / `AnyFactionSettlementOnRootSurface(f)` |
   | 逐派系计数 | `Find.WorldObjects.Settlements.Count(s => s.Faction == f)` |

   ⇒ **MVS 的派系体量应改为"运行时读取 + 兜底默认值"**，不再依赖世界生成的随机结果去猜。

4. **必须响应式更新**：据点会被玩家摧毁（`DestroyedSettlement`）或被事件移除 ⇒ 派系体量缓存须在 `WorldObjectsHolder` 增删后重算（低频轮询或钩 `Add`/`Remove`），**不得一次性算完缓存到存档**。

判据：**取「排除表长度」与「白名单长度」的短者**（不做全局一刀切）。

⚠ **采排除法的前置条件**：必须用 `ThingDefCount` 做启动断言（见 §12.4），把第三方 Drift 从**静默扩大**变为**可见**。

`tradeTags` 是 `List<string>` 上的 `Contains`，无 Def 引用、无本地化能力 ⇒ 与设计文档"禁止裸字符串匹配"冲突，**不用**。

### 12.5 Def 命名与本地化定稿（`MVSCommodityDef`）

| 项 | 定稿值 | 依据 |
|---|---|---|
| Def 类短名 | **`MVSCommodityDef`** | 见下 |
| Def XML 根元素 | `<MVSCommodityDef>` | 与短名同一字符串 |
| `DefInjected` 目录 | `DefInjected/MVSCommodityDef/` | 同上 |

| 品种 DefName | `MVS_Commodity_<Name>` | — |

| 面板 UI 文案 | 走 **Keyed** `MVS.MarketPanel.*` | 同上 |

#### 为何 Def 类要叫 `MVSCommodityDef` 而不是 `CommodityDef`
`il Verse.GenTypes GetTypeInAnyAssembly` 的**签名**：
```
GetTypeInAnyAssembly(String typeName, String namespaceIfAmbiguous)
```
第二个参数直译即「**命名空间歧义时用**」⇒ **短名撞名是原版已知问题**。而
```
refs GetTypeInAnyAssembly：
  Verse.LoadedLanguage::LoadData  ->  GetTypeInAnyAssembly   (两处)
```
⇒ `Languages/**/DefInjected/<目录名>/` 的类型解析走 `LoadedLanguage.LoadData`，**我们无法干预它传的 `namespaceIfAmbiguous`**。一旦 `CommodityDef` 与某第三方 Mod 撞名，解析结果只能由全局按名解析的遍历顺序决定 —— **这是最难查的一类故障（无报错、翻译静默错位）**。
⇒ 用全局唯一短名彻底消除歧义。**改名成本论证**：落地前改 = O(1)；落地后改 = C# 类名 + Def XML 根元素 + `DefInjected/` 目录 + 全部 XML patch 引用，四处同改且漏一处即静默失败。

#### Keyed 资产清单（实现阶段落盘用）
`MVS.MarketPanel.Title` = 市场面板 ｜ `.ColCommodity` = 品种 ｜ `.ColSupply` = 供应 ｜ `.ColDemand` = 需求 ｜ `.ColDelta` = 差额 ｜ `.Unit.Suffix` = 件/日 ｜ `.Legend.Supply` / `.Legend.Demand` ｜ `.Legend.LevelSource` = 品种名后圈码＝数据级别 ①原版锚 ②官方推导 ③设计假设 ｜ `.Legend.DeltaSign` = 差额 −净进口 · +净出口 ｜ `.Legend.ScaleNote` = 条形共用全局线性基准 ⇒ 跨行可比；小量品种受像素极限压缩，请读数值列 ｜ `.Legend.DeltaMinus` = − ｜ `.Legend.DeltaPlus` = + ｜ `.Empty.Title` = 尚未建立经济画像 ｜ `.Empty.Body` ｜ `.Empty.Method1` / `.Method2`

### 13.2 目标选择：为什么是 `IncidentWorker.TryExecute`
```
[public] Boolean TryExecute(IncidentParms parms)          ← 非虚，单一实现，全部子类共用
[protected virtual] Boolean TryExecuteWorker(IncidentParms) ← 子类各自覆写
```
⇒ **必须补 `TryExecute`**。补 `TryExecuteWorker` 只能命中基类实现，会漏掉绝大多数事件（各类 worker 均自行覆写）。

`refs TryExecute` 命中调用点覆盖：`CompAbilityEffect_RaidEnemy` / `CompAbilityEffect_Infestation`（能力触发）、`QuestPart_Incident` / `QuestPart_RandomRaid`（任务触发）、`Dialog_Trade`（交易界面触发）、`FactionDialogMaker.CallForAid`（求援）、`GameCondition_DroughtInitial`、`Planet.TimedDetectionRaids`、`Instruction_DownRaider` ⇒ **一个 Postfix 收全部派发入口**。

`IncidentParms` 有 `[public] Faction faction` / `[public] IIncidentTarget target`；`IncidentWorker` 有 `[public] IncidentDef def`。

### 13.3 补丁形状（Compatibility/Patch 层）
```csharp
[HarmonyPatch(typeof(IncidentWorker), nameof(IncidentWorker.TryExecute))]
static class Patch_IncidentWorker_TryExecute
{
    // 桥守卫：方法体内只出现 IncidentDef / Faction / int，DTO 构造禁在补丁体内
    [MethodImpl(MethodImplOptions.NoInlining)]
    static void Postfix(IncidentWorker __instance, IncidentParms parms, bool __result)
    {
        if (!__result) return;                 // 门控①：未返回成功不记
        var def = __instance?.def;
        if (def == null) return;
        if (!MVSImpactRegistry.HasImpact(def)) return;   // 门控②：白名单（只记挂了 MVSIncidentImpactDef 的）
        MarketEventSink.Record(def, parms?.faction, Find.TickManager.TicksGame);
    }
}
```
- **降级**：`AccessTools.Method(typeof(IncidentWorker), "TryExecute")` 取空 ⇒ 告警一次后跳过，**不新增静态可变布尔**（并入环形日志的同键去重 + 退避）。
- **去重**：同 `def` + 同 tick 只记一次（防 `GameConditionTick` 类重复派发）。

### 13.4 ⚠ 返回值语义修正（IL 证据，推翻「宁漏勿误」假设）
`il RimWorld.IncidentWorker TryExecute` 开头：
```
IL_0006: isinst Verse.Map         // parms.target as Map
IL_0015: ldfld IncidentDef::requireColonistsPresent
IL_0022: callvirt MapPawns.get_FreeColonistsSpawnedCount
IL_0029: ldc.i4.1 ; ret           ← 未执行任何 worker，直接返回 true
IL_002D: callvirt IncidentWorker.TryExecuteWorker
```
⇒ **存在一条「未执行却返回 true」的路径**（`requireColonistsPresent` 为真且无自由殖民者时直接 `ret 1`）。
⇒ `__result == true` **不保证事件真正发生过**；仅靠返回值门控是「可能误记」，不是「宁漏勿误」。
⇒ 因此门控②（**白名单**）是必需的，且面板侧须容忍极低概率的幽灵记录；不得反过来放宽为「无白名单全记」。

### 13.5 无派系事件（灾害维度）→ `EventScope.Global`
天象/灾害类（`IncidentWorker_MakeGameCondition` 系：寒潮/热浪/极光/死雾等）`parms.faction` 可能为 null。
- DTO 的 faction **可空**，配 `EventScope { Faction, Global }`。
- **不丢弃**（会丢掉整个灾害维度）；**不按 `parms.target` 归因**——target 是 `Map`/`World` 而非派系，按它归因会把殖民地寒潮计成某派系冲击，属错误归因。
- 代价：灾害维度跨派系共享，暂不支持按派系拆分冲击。

### 13.6 存储：不落盘
有界 ring（建议 200）**仅会话内**，不进 Scribe。理由：它是可重建的 UI 消费数据，落盘会把 schema 版本 / 默认值 / 旧档迁移无收益卷入 GATE-SAVE。
代价：读档后为空 ⇒ UI 必须有**显式空态文案**（GATE-UI 状态完备）。日后要跨会话 ⇒ 另开 SDD + schema v2 + 独立迁移。
