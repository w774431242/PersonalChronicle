# 原版事件流类型分类（MVS · 派系状态面板取据）

> 配套：`系统中心蓝图/市场经济框架_玩家预览_RUIF单页统一版.html` 的「派系状态」面板事件流。
> 取证基线：RimWorld **1.6.4871 rev590**，`Assembly-CSharp.dll`；Mono.Cecil 静态取证（`rimworld-assembly-api-verify` skill）。
> 级别圈码：① 原版实测/官方推导　② 设计假设（数值待游戏内验证）　③ 设计假设（无原版入口，占位）。

## 1. 结论先行

原版玩家能看到的「事件流」由 **三条相互独立的生产线** 构成，不能混为一谈：

| 生产线 | 系统 | 预览页对应 |
|---|---|---|
| **事件（信件/信条）** | `IncidentWorker` 继承树 | 派系状态·事件流 |
| **天象/天气持续态** | `GameCondition`（多数由 `MakeGameCondition` 系 worker 派发，但本身是独立系统） | 灾害频率（读 `Goodweather`/`ToxicFallout` 等状态） |
| **任务** | `Quest`（独立系统） | `GiveQuest` worker 仅是派发入口 |

本文件聚焦 **事件线（IncidentWorker）** —— 它是派系状态面板「战争 / 灾害 / 人口影响」三因子的真实来源。

## 2. IncidentWorker 的两层模型（不可按 worker 数直接数）

| 层级 | 含义 | 1.6 rev590 实测数量 |
|---|---|---|
| **直接子类** | 每个是独立 worker 代码实现 | **61 个**（`subs IncidentWorker`） |
| **全树真实类型** | 含 DLC / 间接子类，剔除 `<>c` / `<>c__DisplayClass` 编译器闭包 | **约 140 个**（含皇室、机械族、异常等） |
| **具名事件（IncidentDef）** | XML 中每个事件绑定一个 `workerClass`，多个事件可复用同一 worker | **远大于 140**（经典事件如寒潮、敌袭是 Def 而非独立 worker） |

> 关键认知：**worker 数量 ≠ 事件数量**。一个 `IncidentDef` 通过 `workerClass` 字段指向某个 worker；许多玩家熟知的事件（寒潮、热浪、敌袭、友袭）是 Def，复用共享 worker，并非独立子类。

## 3. 两条已验证架构事实（IL 取证）

用 Mono.Cecil 直接枚举继承关系，已坐实两条「共享 worker」规律：

**事实 A — 天象类全走 `IncidentWorker_MakeGameCondition`**
```
subs IncidentWorker_MakeGameCondition
  → Aurora / ColdSnap / DeathPall / HeatWave / MakeInitialDrought
```
即极光、寒潮、死亡薄雾、热浪、初始干旱均为 `MakeGameCondition` 的直接子类；该 worker 的语义＝「创建一个 `GameCondition` 持续态」。`Flashstorm`（电暴）是独立 worker，不走此类。

**事实 B — 敌袭 / 友袭共享 `IncidentWorker_Raid`**
```
subs IncidentWorker_Raid
  → RaidEnemy / RaidFriendly
```
敌袭、友袭是 `Raid` 的子类；`Raid` 本身才是 `IncidentWorker` 直接子类（含 61 之列）。

**可复现取证命令**

## 5. 三大宏维度归并（派系状态面板直接采用）

把 61 个直接 worker 按面板三因子归并，计数均为 ① 原版实测：

| 宏维度 | 涵盖 9 类 | 直接 worker 计数 | 代表具名事件（③ 示例） |
|---|---|---|---|
| **战争** | 4.1 袭击/战争 | **12** | 机械族集群 · 敌袭 · 深渊之门 · 蹒跚者袭击 |
| **灾害** | 4.2 天象 + 4.3 异常 + 4.4 动物狂乱 + 4.5 疾病 | **25** | 寒潮 · 热浪 · 电暴 · 虫巢 · 瘟疫 |
| **人口·民生** | 4.6 贸易 + 4.7 加入 + 4.8 资源 + 4.9 勒索/精神 | **24** | 流浪者加入 · 商队来访 · 野人 · 资源坠落 |

计数校验：12 + 25 + 24 = 61（全覆盖直接子类，无遗漏）。

> 口径说明：「人口·民生」把贸易/资源/勒索/精神归到一起，是因为它们在面板里共同驱动「人口增减 / 贸易状态 / 经济压力」三个因子；「疾病」归入灾害（属威胁，且直接减员）。若后续面板要把「疾病减员」单独成因子，可从灾害类拆出 `Disease*`（1 个直接 worker）。

## 6. 对派系状态面板的设计映射

| 面板因子 | 事件流来源（原版） | 数据可得性 |
|---|---|---|
| 战争态势 | 4.1 袭击/战争类（Raid/Ambush/MechCluster/PitGate/Shambler*/各 Assault/EntitySwarm/Revenant） | ② 需游戏内记录该派系实际触发的 IncidentWorker 类别 |
| 灾害频率 | 4.2–4.5（天象/异常/动物狂乱/疾病） | ② 同上；天象持续态另读 `GameCondition` |
| 人口增减 | 4.7 加入（正）/ 4.5 疾病（负） | ② 同上 |
| 贸易状态 | 4.6 贸易/访客 | ① `TraderCaravanArrival` / `OrbitalTraderArrival` 真实存在 |
| 经济压力 | 4.8 资源 + 4.9 勒索/精神 | ② 需游戏内记录 |

**当前预览页状态**：事件流结构已接原版真实 9 类分类（① 原版），但「近期具体触发了哪几条」为 ③ 设计假设占位（预览无实时游戏状态）。原型化后，事件流改为**读取 `Find.Storyteller` / `IncidentDef` 实际派发记录**，按 4 节 9 类动态聚合，映射到三大宏维度三色徽标。

## 7. 落地注意事项（GATE 相关）

- 事件记录是**运行时观测**，不得写进 Def / 存档 schema 之外；建议存 `WorldComponent` 轻量环形缓冲（仅记 `defName` + tick + 派系），旧档可缺失（LAND-009 空态）。
- 统计「某派系触发频率」须按派系过滤：`IncidentWorker` 多数不带派系归属，需从 `Parms.target`（派系据点/地图）反查；原版无「派系事件计数器」官方字段 ⇒ 自建设计假设，标 ②。
- `MakeGameCondition` 系天象是 `GameCondition` 而非 `Incident`；读「灾害频率」应同时查 `Find.World.GameConditionManager` / 地图 `gameConditionManager`，否则漏算寒潮/热浪。
