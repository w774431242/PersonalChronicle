## 1. 绑定约束（用户 5 要求 + 1 追加）
- **要求一 · 禁止硬编码**：不写任何 per-faction 样板数值（当前 Empire 样板整体违规）。
- **要求二 · 按官方背景反推**：数据模型只由 `FactionDef` 官方字段 + 官方 lore 反推；所有反推常数统一标 **③ 设计假设**。
- **要求三 · 预留第三方 mod 接入 API**：mod 可通过声明/注册覆盖或增强自身派系经济画像。
- **要求四 · 解耦高兼容**：画像模型与 deriver 落在 `MVS.Domain`/`MVS.Data`；UI 只消费契约；第三方软依赖、每边界 null-guard。
- **要求五 · 建立记忆文档**：本件 + `MEMORY.md` 指针。
- **追加 · 第三方覆盖必选**：默认 deriver 必须覆盖**每一个**派系（含第三方 mod 派系），不得 NotModeled，除非该派系确实非经济（非 humanlike / hidden / permanentEnemy / 无 trader）。

## 3. 目标架构（依赖方向 UI→App→Domain→Data 单向）
```
FactionDef (官方字段, 只读)
   │
IFactionEconomyDeriver  ← 默认 FactionDefFieldDeriver（纯字段反推）
   │                       ← 第三方可 Register 自定义 IDeriver（覆盖/增强）
   ▼
FactionEconomyProfile (领域模型: 自给率/消费偏好/社会分层/人数估算/事件流)
   │
IFactionEconomyProfileProvider (契约, MVS.Application.Contracts)
   │
BuiltinEconomyProvider.* (组装快照, 自吞异常返回安全快照)
   │
Economy*Panel (UI, 只渲染契约数据, 无 defName 分支)
```
- `FactionProfileAdapter`（已存在、无状态）即 deriver 解析宿主（**未新增** `IFactionEconomyDeriver`/`Register`；它读 `FactionDef` 字段 + `FactionEconomyExtension` 双路）。落地即复用此既有宿主，未另起类型。
- 画像缓存随 World 重建（构造函数不缓存 world 引用，每次调用重解析 —— 沿用 `MarketFactorAdapter` 纪律，避免读档/新世界后 world 引用失效）。

## 4. 反推建模规则（要求二）
输入全部为 `FactionDef` 官方字段（Mono.Cecil 已证存在：`techLevel` / `apparelStuffFilter` / `backstoryFilters` / `pawnGroupMakers` / `royalTitleTags` / `leaderTitle` / `fixedLeaderKinds` / `settlementGenerationWeight` / `maxConfigurableAtWorldCreation` / `humanlikeFaction` / `permanentEnemy` / `hidden` / 四条 `*TraderKinds`）。

### 4.1 可贸易门禁（tradeable gate，6 字段）
`!isPlayer && humanlikeFaction && settlementGenerationWeight>0 && !permanentEnemy && !hidden && (≥1 of 4 traderKinds 非空)`。不满足 → 诚实 NotModeled（LAND-009：不填占位数值）。

### 4.2 生产 / 自给率
- `techLevel`（Neolithic…Ultra）→ 产能档位曲线，决定该派系可生产哪些 `MVSCommodityDef` 品类（如 Neolithic 不能造 Medicine/Spacer 武器，Ultra 全可）。**③ 曲线形状为设计假设**。
- `apparelStuffFilter`（ThingFilter）→ 服装材料偏好向量（Metallic/Fabric/Woody 权重），读 filter 允许类别推导。
- `pawnGroupMakers`（List<PawnGroupMaker>，权重点）→ 集团类型构成（raider/trader/caravan/settler）；战斗重 → 武器/药品需求高；贸易重 → 贵重品需求高。

### 4.3 消费偏好
- `backstoryFilters` → 人口构成（worker/noble/slave 比）→ 消费混合（Meals/ProcessedFood vs Artifacts/Valuables）。
- `techLevel` → 科技品需求档。
- `royalTitleTags`（Empire）→ 贵族消费溢价（Artifacts/luxury）。

### 4.4 社会分层
- `royalTitleTags` 非空 → 有爵位；层数 = 不同 title tag 数；分布 **③ 引官方 lore**（Empire 6/21/73 出自开发者日记，明标 ③）。非爵位派系 → 1–2 层（酋长/平权），**③ 假设**。
- `leaderTitle` / `fixedLeaderKinds` → 领导模型（单体 vs 议会），影响 tier-0 权重。

### 4.5 人数估算（最难，见 §7 开放问题）
- **运行时真值优先**：`Find.World.worldObjects.Settlements` 按 faction 过滤 → 实际据点数（派系被灭/据点被毁须响应式更新，不可一次缓存进存档）。
- 每据点人数代理 = `pawnGroupMakers` 总权重 × 全局标定常数 K（**③**）。
- `settlementGenerationWeight` 仅作相对密度归一（非绝对值）；`maxConfigurableAtWorldCreation` 是派系**实例数上限**（非据点数，原版 IL 已证）。

## 5. 第三方 mod 接入 API（要求三 + 必选覆盖）
两层，互补：
1. **自动覆盖（必选）**：默认 `FactionDefFieldDeriver` 只读 `FactionDef` 字段 → 任何 mod 派系都定义这些字段 → **自动被覆盖**，零 per-faction 代码。这是"第三方覆盖必选"的硬保障。
2. **覆盖 / 增强钩子（可选）**：
   - `FactionEconomyExtension : DefModExtension`（**仓库已存在类型**，非 `MVSFactionEconomyExtension`）→ 挂 `FactionDef` 的 `<modExtensions>`；`FactionProfileAdapter.TryGetProfile` 经 `def.GetModExtension<FactionEconomyExtension>()` 读 `EffectiveTechLevel` 覆盖/增强派系画像；缺省 null → 走默认 `FactionDef.techLevel` 路径。**（已落地，满足 要求三 覆盖钩子）**
   - 自定义 `IFactionEconomyDeriver` + `Register(IDeriver)` 注入 API（按 defName 谓词或全量注册）→ **本范围未落地（DEFERRED）**。当前 `TryGetProfile` 走"默认字段反推 + `FactionEconomyExtension` 覆盖"双路，已覆盖所有标准字段派系；自定义 deriver 注册是未来增强项（不阻塞 要求三 必选覆盖，因自动覆盖路径已满足）。
   - 解析顺序（已落地）：`TryGetProfile` 先查 `FactionEconomyExtension`（命中→覆盖 techLevel）→ 回退默认 `FactionDef.techLevel` 字段反推（`FactionArchetype.ForTechLevel`）。未知 mod 派系由默认路径自动覆盖（满足 第三方覆盖必选）。

## 6. 解耦与兼容（要求四）
- 画像模型 + deriver 在 `MVS.Domain`/`MVS.Data`；UI 仅消费 `IFactionEconomyProfileProvider` 契约，**无 `defName` 字符串比较**。
- 移除 `MarketPanel.cs:46` 的 `!= "Empire"` → `profileProvider.TryGetProfile(factionDef, out profile)`；`profile == null` → NotModeled（仅非经济派系）。
- `FactionStatus` / `MarketPanel` / `Society` / `FactionDetail` 面板用通用模板 + 占位符渲染（无 `Empire` 字面量）。
- 第三方交互全部软依赖：mod 缺失 → extension null → 默认路径；mod 存在 → 读 extension。无 Harmony 改派系类（用 DefModExtension + DefDatabase）。
- 每边界 null-guard。

## 7. 人数绝对标定锚（已拍板：方案 A）
纯字段反推只能产出相对权重，无法产出绝对人数（字段只给相对量）。**用户裁定采用 A**：运行时真实据点计数驱动，不绑定任何派系的绝对数。

- **机制**：`pop ≈ settlementCount_actual × avgHeadPerSettlement`，其中 `avgHeadPerSettlement = K × normalizedPawnGroupWeight`。
  - `settlementCount_actual` = `Find.World.worldObjects.Settlements` 按 faction 过滤（响应式，派系被灭/据点被毁实时反映，**不进存档缓存**）。
  - `normalizedPawnGroupWeight` = 该派系 `pawnGroupMakers` 总权重 / 全派系最大总权重（∈(0,1]）。
  - `K` = 全局缩放常数（**③ 设计假设**），语义＝"权重满格派系的每据点人数基准"。
- **K 的标定方式（非硬锚）**：用帝国文档 ~214 作**校验靶**反推 K 的量级（让 Empire 派生值≈214 证模型量级合理），但 K 不写死进 Empire 分支、对所有派系统一应用 —— 等价于"方案 B 的锚降级为校验用例"。
- **方案 C 的残留价值**：相对经济质量评分（以 Empire=1.0 的倍数）仍作 UI 排序/对比的次级指标保留，与绝对人数并存。

## 10. 派系画像 → 市场仿真接法（已拍板：视图过滤+偏置）
用户裁定采用 (a)：**不改全局唯一仿真，派系画像只做"可见品种过滤 + 偏好偏置"**。理由：原可行性门禁 §10 已否"零 Harmony A 通道做 per-faction 真实成交价"，故不能逐派系独立价格。

- **机制**：市场面板数据仍来自 `IMarketFactorProvider`（全局 `WorldComponent_Market` 因子表，零 Harmony 保持）。选中派系时：
  1. **可见品种过滤**：用画像 `techLevel` + `pawnGroupMakers` 推导该派系触碰的 `MVSCommodityDef` 子集（Neolithic 不显示 Medicine/Spacer 武器；Ultra 全显示）→ 市场表只列该子集。
  2. **生产/消费偏好偏置**：对可见品种施加偏置乘子（来自 `techLevel` 产能档 / `apparelStuffFilter` 材料偏好 / `pawnGroupMakers` 集团构成）→ 该派系视角下的相对供需强度，叠加在全局因子状态上（非独立状态）。
- **PERF**：仍是单份全局因子表（≤32 行），仅多一层投影；不新增 per-faction 状态，≤40 派系无状态膨胀。
- **诚实性**：偏置乘子标 ③；被过滤品种对该派系显示"不涉及"（非 0、非占位）。

⇒ "按派系背景拟定稳定供需市场"以**零 Harmony + 单仿真**方式满足：派系背景改变的是"市场视图的构成与相对强弱"，而非另起价格体系。
