## 0. 结论速览

1. **思维树有 6 条互不排斥的挂载通道**（P-01~P-06），按侵入性从低到高排列：原版 `insertTag` → DutyDef 内联树 → race.thinkTreeMain 整体替换 → XPath 强挂 → 运行期代码改写 → Harmony 改结果。**绝大多数需求在前三条内就能闭环，不需要 Harmony。**
2. **全生态的范式重心是「兼容」而非「功能」**。46 条范式里，有 14 条（P-27~P-40）纯粹是「怎么不被别的 mod 打断 / 怎么不打断别人」。生态最稀缺的资源是 `insertTag` 槽位与思维树出口。
3. **最值得抄的三条**：
   - **P-19 意图引擎与树分层**（巴尔）：把「什么时候想做什么」放进 `GameComponent`，`JobGiver` 只做「意图→Job」翻译。**这是自驱力类需求的正解**——树的职责被压到最薄一层。
   - **P-08 Duty 树内回挂原版 insertTag**（Hospitality）：任何自定义 `DutyDef` 若不回挂 `Humanlike_*`，会**静默屏蔽**全生态的 humanlike 子树。本地全部 Duty 树先例（VEE / VIE-Memes / Rocket's Ranks）都漏了这一步。
   - **P-20 运行期动态优先级**（Misc. Robots）：把优先级从 XML 常量搬到 `GetPriority(pawn)` 按「需求水位 × 距离 × 时间表时段」实时计算。本地全部先例（含巴尔自驱树、CAI 5000）都停在 XML 常量层。
4. **评估时机是可行性分水岭**（P-46）：原版主树是**事件驱动**（无 job / job 到期 / 显式 `CheckForJobOverride`）而非常驻每 tick。因此「空闲期自主」用纯 XML 可行，「**正在干活时抢过来**」必须走 Harmony 或 Duty 通道。
5. **切片 C 批次误报率 40%**：该批二进制字符串扫描命中的 10 个候选 MOD 里有 4 个完全没碰思维树。已建立三层判据（字符串 → 反编译 grep → .NET 元数据表），见附录 B。

## 2. 原版思维树机制基线（封装自各切片）

> 本节是全部 46 条范式的公共前提。主报告 §2 已详细展开，此处只保留「设计时必须知道」的硬事实。

### 2.1 节点类型语义

| 类 | 语义 | 关键行为 |
|---|---|---|
| `ThinkNode_Priority` | **顺序表** | 子节点按顺序求值，**命中即短路**（`ThinkNode_Priority.cs:13-22`）——首个返回有效 Job 的节点赢 |
| `ThinkNode_PrioritySorter` | **打分表** | `OrderByDescending(GetPriority(pawn))` 后依次尝试；原版的「需求优先级」由此实现 |
| `ThinkNode_JobGiver`（抽象） | **叶子** | 产出 `Job`；返回 null = 让位 |
| `ThinkNode_Subtree` | **引用** | 跳进另一棵树（`treeDef`），常用于复用 `SatisfyVeryUrgentNeeds` 等原版子树 |
| `ThinkNode_SubtreesByTag` | **插入点** | 遍历 `DefDatabase<ThinkTreeDef>.AllDefs`，取 `insertTag` 相同者按 `insertPriority` **降序**尝试（`Verse/AI/ThinkNode_SubtreesByTag.cs:24-47`）——**官方 modder 钩子** |
| `ThinkNode_Conditional*`（约 90 个子类） | **门** | 只答布尔，不做动作 |
| `ThinkNode_ChancePerHour*/PerDay*` | **概率门** | 按 MTB 折算概率放行 |
| `ThinkNode_Tagger` | **记账** | 给子树挂 `tagToGive`（如 `SatisfyingNeeds` / `Idle` / `DraftedOrder`），影响原版后续的标签计数与覆盖判定 |

**设计含义**：`ThinkNode_Priority` 的「命中即短路」意味着**树的子节点顺序 = 绝对优先级**，XML 里缩进位置就是语法。这是本报告中「用 `<li>` 顺序表达状态机」的全部理论依据。

### 2.2 官方 modder 插入点（硬证据）

| insertTag | 原版位置 | 语义（EBSG Wiki 交叉验证） |
|---|---|---|
| `Humanlike_PostMentalState` | `Humanlike.xml:84-85` | **最早**。早于满足需求、自我治疗、征召命令 |
| `Humanlike_PostDuty` | `Humanlike.xml:122-123` | 晚于征召命令与 Lord Duty，早于囚犯越狱/应急工作/进食 |
| `Humanlike_PreMain` | `Humanlike.xml:357-358` | 晚于囚犯越狱/应急工作/进食 |
| `Humanlike_PostMain` | `Humanlike.xml:382-383` | **最晚**，之后基本只剩闲置行为 |

动物侧：`Animal_PreMain` / `Animal_PreWander`（`Animal.xml:98-99,325-326`）。
原版 `SubTrees_Misc.xml` 还留了一个 `InsertHookTest` 范例（Ludeon 官方论坛教程引用）。

**表内顺序即语义强弱**。选择 `insertTag` 等于选择「我的行为在原版决策链里的位置」——这是本报告所有挂载决策的第一性问题。

### 2.3 三条原生通道

1. **`insertTag` 通道**：新增 `ThinkTreeDef` + 设 `insertTag`/`insertPriority`。**纯 XML，零 Harmony，天然多 mod 兼容。**
2. **`TraitDegreeData.thinkTree` + `ThinkNode_TraitBehaviors` 通道**：特质可挂整棵树。限制：取**第一个非 null** 的特质树即 return，即「一特质一树」，多特质会互相覆盖。
3. **`DutyDef.thinkNode` 通道**：在 DutyDef 里内联一棵完整 `thinkNode`，由 `pawn.mindState.duty = new PawnDuty(...)` 派发。**Duty 生效期间，原版主树被整棵替换。**

### 2.4 求值节拍（决定架构的关键）

| 对象 | 节拍 | 证据 |
|---|---|---|
| **主思维树** | **事件驱动**，非每 tick | 仅在：① `CurJob == null`；② job 到期且 `checkOverrideOnExpire`；③ 显式 `CheckForJobOverride()` |
| 常驻树 `ConstantThinkTree` | 每 **30 tick** | `Pawn_Thinker.ThinkerTickInterval` 相关 |
| Need 求值 | 每 **150 tick** | `Need.NeedInterval` |
| `Pawn_JobTracker` | `JobTrackerTickInterval` | 可 Harmony 覆写 |

**这条决定了 P-46**：纯 XML 只能在「主树被求值的那一刻」插入行为 → 空闲期自主可行；想在 pawn 正干活时抢过来，必须让主树被求值（Harmony `CheckForJobOverride` / `JobTrackerTickInterval`，主报告 §4.1 E9 判定为生态低频争用点）或走 Duty。

### 2.5 接口契约（跨范式通用）

| 接口 | 用途 | 范式引用 |
|---|---|---|
| `pawn.jobs.StartJob(job, condition, source, ..., thinkTreeDef: X)` | 启动 job 并**指定思考树** | P-07（空树冻结） |
| `pawn.jobs.CheckForJobOverride(minPriority, ignoreQueue)` | 手动触发重评估 | P-34 |
| `thinker.ConstantThinkNodeRoot.TryIssueJobPackage(pawn, default(JobIssueParams))` | **只读**跑树拿结果 | P-40 |
| `thinker.ConstantThinkTree` | 参照判定 | P-40 |
| `Pawn_JobTracker.ShouldStartJobFromThinkTree` | 「本次树结果是否被采纳」闸门 | P-34 |
| `Pawn_JobTracker.DetermineNextJob` | 树出口 | P-33 |
| `PawnComponentsUtility.AddComponentsForSpawn` | 换 `Pawn_Thinker` 子类的时机 | P-32 |
| `JobMaker.ReturnToPool(job)` | 归还对象池（**只读跑树后必须调用**） | P-40 |

## 3. 范式总库（46 条）

> 编号规则：`P-xx`。每条给出 **做法 / 代表 MOD / 证据 / 适用与代价**。
> 「代表」列中 `[A]`=切片 A、`[B]`=切片 B、`[C]`=切片 C、`[D]`=切片 D。

### 族 1：挂载层 —— 让树生效（P-01 ~ P-10）

---

**P-01 原版 `insertTag` 挂树，而非 patch 原版树**
- **做法**：新增 `ThinkTreeDef`，只设 `insertTag` + `insertPriority`，`thinkRoot` 自己写。不碰任何原版 XML。
- **代表**：VEF（`Reloading_AmmoReload_Colony` / `VEF_DraftableHook`）[A]、巴尔 4 棵树 [B]、Dubs Bad Hygiene [D]
- **证据**：`2023507013/1.6/Defs/ThinkTreeDefs/Reloading.xml:5-18`；`3768871513/Defs/ThinkTreeDefs/BPC_*.xml`
- **适用/代价**：✅ 首选方案。零 xpath、天然与其他 mod 兼容、卸载干净。⚠️ 只能落在原版**预置的 6 个钩子**上，位置固定。

**P-02 `insertTag` 作对外 API（库 mod 提供树，下游挂载）**
- **做法**：库/框架 mod 新增树但**不在自己包里挂载**，由下游 mod 用 `<race><thinkTreeMain>` 引用。
- **代表**：VEF（`VEF_AnimalHarvester` / `VEF_AnimalWeirdEater`）[A]、Ancot Library（`Ancot_Drone`）[A]
- **证据**：VEF 三棵 Animal_* 树在自身 XML 无任何 `thinkTreeMain` 引用、全 294100 范围 grep 仅命中自身版本 → 判定为 API 树；`AncotDefOf.cs` 中不存在任何 `ThinkTreeDef` 字段
- **适用/代价**：✅ 做扩展框架时的标准姿势。⚠️ **必须写文档**，否则下游不知道树存在（VEF 的 API 树就是这样"哑"着的）。

**P-03 XPath 强挂官方树的分支**
- **做法**：`PatchOperationInsert(order=Prepend)` 把节点插到官方 `thinkRoot/subNodes` 的**指定锚点之前**，从而在官方分支之前接管。
- **代表**：巴尔（`ThinkNode_ConditionalTerritoryTactical` 插到 `ConditionalColonist` 前）[B]、CAI 5000（`JobGiver_DuckOrRetreat` 插到 `ConditionalNPCCanSelfTendNow` 前）[B]、VEF [A]
- **证据**：`3768871513/Patches/TerritoryForceTacticalThinkTree.xml:4-13`；`3673768803/1.6/Patches/ThinkTree_Humanlike.xml:5-11`
- **适用/代价**：✅ 需要精确控制位置时唯一选择（`insertTag` 做不到）。⚠️ 锚点被上游改动即失效；CAI 5000 的注释说明了它的价值：「插到自愈节点**之前**，使所有受威胁的远程 NPC 都能躲避，而不只是当时能自愈的那些」。

**P-04 DutyDef 内联树（+ `hook` 选择插入段位）**
- **做法**：一个 Duty 的完整行为链直接写进 `DutyDef.thinkNode`，**不新建 ThinkTreeDef**。用 `<hook>HighPriority/MediumPriority</hook>` 决定插进 `LordDuty` 树的哪一段；不写 hook 则由 `PawnDuty` 主动赋值（可控性更强）。
- **代表**：VEE（14 行 XML 搞定一个 Duty 行为）[C]、VIE-Memes（2 棵）[C]、Rocket's Ranks [C]、RimSimManagementFramework [A]、Hospitality [D]
- **证据**：`1938420742/1.6/Defs/DutyDefs/DutyDefs.xml:3-13`（全文仅 14 行）
- **适用/代价**：✅ **最小侵入**。⚠️ **Duty 生效期间原版主树被整棵替换** → 必须配 P-08 回挂，否则静默屏蔽生态。

**P-05 `race.thinkTreeMain` 整体替换 / 镜像树**
- **做法**：复制原版树 → 改名 → 挂到自己的 `ThingDef.race.thinkTreeMain` → 裁掉不适用分支 → **保留原版 insertTag 钩子点**。
- **代表**：VIE-Dryads（`VDE_DryadCleaner`，333 行镜像 `Animal` 树）[C]、Vehicle Framework [A]
- **证据**：`2720631512/1.6/Defs/ThinkTreeDefs/Animal_Cleaner.xml`（74 节点 vs 原版 104 节点）；`Dryads .../Races_Animal_AwakenedDryads.xml:1470`；保留 `:94 <insertTag>Animal_PreMain</insertTag>`、`:248 <insertTag>Animal_PreWander</insertTag>`
- **适用/代价**：✅ 完整控制且不与其他 mod 争槽位。⚠️ **必须保留钩子点**，否则新种族屏蔽全生态动物子树；⚠️ 上游树改版时要手工同步。

**P-06 运行期树改写（代码遍历 + 锚点多级回退）**
- **做法**：`[StaticConstructorOnStartup]` 静态构造里遍历 `DefDatabase<ThinkTreeDef>.AllDefsListForReading`，按**锚点重要性依次回退**查找插入位（命中即插，未命中继续下一级），再 `subNodes.Insert(index, node)`。
- **代表**：Perspective Shift [C]
- **证据**：`PerspectiveShift/Startup.cs:10-18,45-94,97-124`；四级回退锚点：`ThinkNode_ConditionalColonist` → `ThinkNode_QueuedJob` → `ThinkNode_Subtree(treeDef == DefsOf.LordDuty)` → `ThinkNode_ConditionalRevenantState`；用 `[DefOf]` 拿 `LordDuty`/`Downed` 做参照树判定与排除
- **适用/代价**：✅ **零 XML**，天然兼容其他 mod 的树改动（只要锚点还在）；可一次覆盖「每一棵含殖民者入口的树」。⚠️ 启动期副作用，锚点全失效时静默无效果——**必须加日志**。

**P-07 Dummy 空树临时顶替 pawn 的 AI**
- **做法**：造一棵 root 为「永远 `return ThinkResult.NoJob` 的 ThinkNode」的 `ThinkTreeDef`，在自定义 `JobDriver` 的 toil 里 `pawn.jobs.StartJob(job, ..., thinkTreeDef: 该空树)`。演出/传送期间 pawn 无法被自身 AI 打断。
- **代表**：Vehicle Map Framework [A]
- **证据**：`3426502333/1.6/Defs/ThinkTreeDefs/DummyThinkTree.xml:4-7` + `JobDriver_GotoDestMap.cs:62-103`
- **适用/代价**：✅ 做「演出/强制流程」的标准解。⚠️ 结束必须重新 `StartJob` 恢复正常树，否则 pawn 永久失去 AI。

**P-08 ★ Duty 树内回挂原版 `insertTag`**
- **做法**：自定义 Duty 树里主动放回 `ThinkNode_SubtreesByTag(Humanlike_PostDuty/PreMain/PostMain)`，使第三方 humanlike 子树在客人/自定义角色身上依然生效。
- **代表**：Hospitality [D]
- **证据**：`Hospitality/1.0/Defs/DutyDefs/Duties_Visit.xml`（树内自带 `<!-- Insertion hook for modders -->`）
- **适用/代价**：✅ **生态兼容的关键手法**。⚠️ 本地全部 Duty 树先例（VEE / VIE-Memes / Rocket's Ranks）**都未做**这一步 → 这是本报告最有价值的「补课项」。

**P-09 同一需求树的多插入点 + 原版 `tagToGive` 复用**
- **做法**：同一组 JobGiver 按语境挂不同 `insertTag`（囚犯/口渴 → `PostDuty`；出门带水 → `PreMain`），并用 `ThinkNode_Tagger(tagToGive=SatisfyingNeeds)` 融入原版记账。
- **代表**：Dubs Bad Hygiene [D]
- **证据**：`Dubs-Bad-Hygiene/1.0/Defs/ThinkTreeDefs/SubTrees_Misc.xml`（3 启用 + 1 注释）
- **适用/代价**：✅ 避免「一个位置硬塞所有语义」。⚠️ 多插入点 = 多份维护。

**P-10 把非生物实体建模成「无肢体 Pawn」以复用整套 AI**
- **做法**：`VehiclePawn : Pawn`，ThingDef `<race>` 里 `body=emptyBody`、`doesntMove=true`（防被判定可击倒）、`alwaysAwake=true`、`intelligence=ToolUser`，然后正常写 `thinkTreeMain`/`thinkTreeConstant`。**零 Harmony、零自建 AI 循环。**
- **代表**：Vehicle Framework [A]
- **证据**：`3014915404/1.6/Defs/VehiclesDefs/VehiclePawnBase.xml:96-107`
- **适用/代价**：✅ **本报告最具结构性启发的一条**——「非 pawn 实体」这个类别可能根本不存在。⚠️ 需要接受 Pawn 的全部机制负担（需求/心情/Hediff 等需自行关掉）。

### 族 2：结构层 —— 树怎么搭（P-11 ~ P-18）

---

**P-11 头尾固定槽：树首挂 `SatisfyVeryUrgentNeeds`，树尾挂 `WanderNearDutyLocation`**
- **代表**：Vehicle Framework、VMF、SimplePortal、SimMgmt [A]、巴尔-共和国 [B]

**P-44 战略 / 世界级 AI 不要塞进思维树**
- **做法**：势力的移动/开战等战略决策走 `WorldComponent`；思维树只管 pawn 级行为。
- **代表**：Rim War [D]（确认不涉及 `ThinkTreeDef`/`ThinkNode`/`JobGiver`/`JobDriver`；其 Harmony 只作用于世界与事件层：`SettlementUtility.AttackNow`、`Caravan_PathFollower.StartPath`、`IncidentWorker.TryExecute`、`Faction.RelationWith` 等）
- **适用/代价**：➖ 对思维树研究的价值是**边界定义**：若要为 PersonalChronicle 做「跨图/世界级自主决策」，思维树不是正确工具。

**P-45 只想替换某个原版 JobGiver 的产出时，不必改树**
- **做法**：新增平行 `WorkGiverDef` 拿活，再用 Postfix/Transpiler 把原版 JobGiver 的产物换掉。Transpiler 用 `MethodReplacer` 只换**一个静态方法**，粒度极小。
- **代表**：Pick Up And Haul [D]（`JobGiver_Haul.TryGiveJob` Transpiler → `MethodReplacer(HaulAIUtility.HaulToStorageJob, HaulToStorageJobByRace)`；`JobGiver_DropUnusedInventory.TryGiveJob` Postfix 等）
- **适用/代价**：➖ 设计启示：若目标只是「换掉某个原版 JobGiver 的产出」，思维树不是唯一入口；但若要「**新增自主决策时机**」，本 MOD 无参考价值。

**P-46 ★ 尊重评估时机：主树事件驱动，抢占必须另辟通道**
- **做法（设计准则）**：先判定「新行为需要在什么时机生效」，再选通道。主树只在 ① 无 job ② job 到期且 `checkOverrideOnExpire` ③ 显式 `CheckForJobOverride()` 三类时机被求值 —— 因此：
  - 只需**空闲期**生效 → 用 P-01 `insertTag`，**纯 XML 完全够用**；
  - 需要**工作中途抢占** → 必须让主树被求值：Harmony 覆写 `CheckForJobOverride` / `JobTrackerTickInterval`（生态低频争用），或走 Duty 通道（P-04）。
- **证据**：`_research/vanilla/Assembly-CSharp/Verse/AI/Pawn_JobTracker.cs`（`CheckForJobOverride` 的全部调用点均为事件驱动，无周期性调用）；主报告 §2.7 求值节拍总表与 §0 结论 6「本案唯一『必须要不要 Harmony』的分水岭」
- **适用/代价**：✅ **本报告最容易被忽略、代价最高的一条**。⚠️ 先按这条筛一遍能砍掉大量过度设计；反之若忽略它，会做出「纯 XML 写完发现根本不触发」的方案。

## 6. 三个「结构级」新范式详解

> 以下三条是切片 D 从线上 MOD 挖到的、本地工坊先例中**完全没有**的手法，单独展开。

### 6.1 Hospitality：Duty 树内回挂原版 `insertTag`（P-08）

**问题**：`DutyDef.thinkNode` 生效期间，pawn 的原版主树被**整棵替换**。此时第三方 mod 插在 `Humanlike_PostDuty/PreMain/PostMain` 上的子树（需求、医疗、应急）**全部失效**。

**Hospitality 的解法**：在自己的 Duty 树里主动放回这三个钩子。

```xml
<DutyDef>
  <defName>Relax</defName>
  <thinkNode Class="ThinkNode_Priority">
    <subNodes>
      <!-- Insertion hook for modders -->
      <li Class="ThinkNode_SubtreesByTag"><insertTag>Humanlike_PostDuty</insertTag></li>
      ...
      <li Class="Hospitality.ThinkNode_FilterGuestRooms">
        <subNodes>
          <li Class="ThinkNode_SubtreesByTag"><insertTag>Humanlike_PreMain</insertTag></li>
          ...
          <li Class="ThinkNode_SubtreesByTag"><insertTag>Humanlike_PostMain</insertTag></li>
```
（证据：`OrionFive/Hospitality/1.0/Defs/DutyDefs/Duties_Visit.xml`，raw 全文已读）

**代价**：极小。**收益**：从「静默屏蔽生态」变成「生态照常生效」。
**本地先例缺口**：VEE / VIE-Memes / Rocket's Ranks 的 Duty 树**均未做**这一步。

> ⚠️ 数据时效说明：上述 XML 读自仓库 `1.0/` 分支（该仓库为发布产物，最新版本目录未能确认）。属**设计证据**，不代表 1.6 版 XML 逐字一致。

### 6.2 EBSGFramework：框架级 insertTag「再导出」（P-02 进阶）

**问题**：N 个 mod 想在「已征召且附近有敌人」时插入行为 → 每个 mod 各自写一遍条件判断，重复且易冲突。

**EBSG 的解法**：只插入一次原版树顶，然后在自己树内**大量嵌套 `ThinkNode_SubtreesByTag`**，把细粒度语义 tag 暴露出去。第三方只需挂一个 tag。

- 顶部只挂**一个**原版 tag：`Humanlike_PostMentalState` + `insertPriority=100`
- 树内逐个数出 **22 个**自定义 insertTag（Wiki 称 19 个，以文件实际内容为准，记为版本差异）：

| 分支 | insertTag |
|---|---|
| 殖民者入口 | `EBSGAI_Colonist`、`EBSGAI_UndraftedAndFreeColonist`、`EBSGAI_UndraftedColonist_NoEnemyOnMap` |
| 未征召·有敌 | `EBSGAI_UndraftedColonist_{EnemyOnMap, HarmedRecently, ShotRecently, MeleeThreat, NearbyEnemy, ManyNearbyThreats}` |
| 已征召 | `EBSGAI_DraftedAndFreePawn`、`EBSGAI_DraftedColonist_{HarmedRecently, ShotRecently, EnemyOnMap, MeleeThreat, NearbyEnemy, ManyNearbyThreats}` |
| 非殖民者 | `EBSGAI_NonColonist`、`EBSGAI_NonColonist_{HarmedRecently, ShotRecently, MeleeThreat, ManyNearbyThreats, NearbyEnemy}` |

（证据：`KonradHeinser/EBSGFramework/1.6/Defs/EBSGThinkTree.xml` raw 全文已读；Wiki: Think-Tree-Stuff）

**兼容性成本从「各自写条件」降到「各挂一个 tag」。** 配套源码：`Source/EBSGFramework/EBSGAI/ConditionalNodes/` 21 个条件节点 + `JobGivers/` 7 个 JobGiver。

### 6.3 Misc. Robots：运行期动态优先级（P-20）

**问题**：XML `<priority>` 是常量。「电量 40% 但刚从远处回基地」和「电量 40% 且在充电站旁」该不该抢先，常量表达不了。

**解法**：覆写 `GetPriority(pawn)`，按三因子实时算：

```csharp
public override float GetPriority(Pawn pawn)   // 需求水位 × 距离 × 时间表时段
if (timeAssignmentDef == TimeAssignmentDefOf.Anything || timeAssignmentDef == TimeAssignmentDefOf.Work) {
    bool isOutsideMaxDistance = distance > 25f;
    if (curLevel < 0.40f && isOutsideMaxDistance) return 8f;
    if (curLevel < 0.25f) return 8f;
    return 0f;
}
if (timeAssignmentDef == TimeAssignmentDefOf.Joy)   { if (curLevel < 0.3f)  return 8f; return 0f; }
if (timeAssignmentDef == TimeAssignmentDefOf.Sleep) { if (curLevel < 0.75f) return 8f; return 0f; }
```
（证据：`HaploX1/RimWorld-Miscellaneous_Source/Source/AIRobot/X2_JobGiver_RechargeEnergy.cs` raw 全文已读）

**⚠️ 约束**：`GetPriority` 在 `PrioritySorter` 路径上会被频繁调用 → **必须是纯函数、无分配、无全图扫描**。

**附赠**：该仓库内 `X2_JobGiver_Work_v1/v2/v3` 三代**并存**，可直接对比同一 JobGiver 的演进。

### 7.2 推荐落地组合（按侵入性从低到高）

**阶段 1 · 最小可用（零 Harmony）**
- P-01 新增 `ThinkTreeDef` + `insertTag=Humanlike_PostMain` + P-21 负 `insertPriority`（例如 `-10`，晚于官方且不抢 0 槽）
- 树内只挂**一个** JobGiver，它向 `GameComponent` 取意图（P-19）
- 树顶 `ThinkNode_Tagger(tagToGive=SatisfyingNeeds)`（P-09 记账复用）
- 树尾不需要兜底（因为 `insertTag` 是插入而非替换，天然回落原版）

**阶段 2 · 决策质量（仍零 Harmony）**
- P-20 在 JobGiver 上覆写 `GetPriority(pawn)`，让「此刻该不该自驱」由需求水位 × 情境实时决定
- P-30 条件开关：无 colony / 关闭设置时整棵子树短路（性能保险丝）
- P-42 建议做**一个探针节点**用于开发期观测（可参照 EBSG 的字段设计）

**阶段 3 · 需要「抢在干活时」时才上（引入 Harmony）**
- 只补 `Pawn_JobTracker.CheckForJobOverride` 或 `JobTrackerTickInterval`（**争用情况见主报告 §4.1 E9 与 §6.5「Harmony 争用面」：当前生态零占用**；而 `StartJob` 已被 Common Sense + CAI 5000 双占，应避开）
- 补 `ShouldStartJobFromThinkTree`（P-34）做闸门而非改 `DetermineNextJob`

**明确不做**（反例）：
- ❌ 不用 P-33 改 `ThinkResult` —— 本需求是「新增决策时机」，不是「换原版产出」
- ❌ 不动世界层（P-44）

## 附录 B：误报甄别方法论（切片 C 核心产出）

**三层判据，强度递增：**

| 层级 | 手段 | 强度 | 说明 |
|---|---|---|---|
| 1 | DLL 二进制字符串命中 | **最弱，必产生误报** | 本切片 10 个候选中有 4 个是误报（40%） |
| 2 | 反编译产物 `grep "ThinkNode\|ThinkTreeDef"` | 中等 | 结果为 0 基本可判误报（4 个误报全部满足） |
| 3 | **.NET 元数据表解析**（TypeRef/MemberRef/Field/MethodDef/Param 名称列 + 签名编码令牌检索） | **最强** | 可区分「真实使用的类型引用」与「未被引用的悬挂 TypeRef」 |

**已观察到的 3 类误报成因：**
