# 经济系统中心：原版经济能力调研与空缺分析

> 目的：在拟定「经济系统中心 SDD」之前，先核实 RimWorld 1.6 原版代码与公开资料中
> **已经存在哪些"经济"相关内容**，划清「可复用 / 需谨慎 / 需自建」三档，避免重复造轮子或与原版口径冲突。
>
> 证据来源（均为一手）：
> - 原版反编译源码：`_research/vanilla/Assembly-CSharp/`（RimWorld 1.6，9226 个 .cs）
> - 原版 Def：`E:\SteamLibrary\steamapps\common\RimWorld\Data\Core\Defs\`
> - 公开资料：RimWorld Wiki（Silver / Market Value 条目）
> - 本项目现状：`Source/PersonalChronicle/Application/SystemCenters/`
>
> 核查日期：2026-09-15

## 一、结论速览

| 判断 | 结论 |
|---|---|
| 原版有"经济系统"吗？ | **没有完整经济系统**，只有三块彼此孤立的碎片：财富估值、一次性易货贸易、通用物品索引 |
| 原版代码里有 "Economy" 这个词吗？ | **有，但只在开发者调试层**（`[DebugOutput("Economy")]`，21 张平衡分析表），**运行时无 Economy 类/Manager/Def** |
| 原版有动态市场、供需、价格波动吗？ | **完全没有**（全库检索 `supplyAndDemand` / `inflation` / `priceIndex` / `priceFluctuation` 零命中） |
| 原版有账本、收支流水、产出统计吗？ | **没有**。只有 4 条财富历史曲线 + pawn 级 `RecordsDef` 计数 |
| PC 现有实现 | `BuiltinEconomyProvider` 仅 2 个 KPI（白银、总财富），属**占位级**，与经济中心目标差距大 |

**一句话**：原版把"经济"当作**难度平衡的副产品**（财富 → 袭击点数）与**一次性交易 UI**，
而不是一个可观测、可记账、可分析的殖民地经济系统。这正是 MOD 的价值空间。

## 二、原版代码中"经济"的实证清单

### 2.1 「Economy」字面只存在于调试层（关键定性证据）

文件：`Verse/DebugOutputsEconomy.cs`

该类用 `[DebugOutput("Economy", false)]` 标注了 **21 个静态方法**，全部是**开发者用的平衡分析表**：

| 方法 | 分析对象 |
|---|---|
| `AnimalEconomy` | 动物经济（产肉/产毛/饲料/价值） |
| `Crops` | 作物产出与价值 |
| `Recipes` / `RecipeSkills` | 配方与技能门槛 |
| `Buildings` / `Floors` | 建筑与地板造价 |
| `ItemAndBuildingAcquisition` | **物品与建筑的获取途径** |
| `ItemAccessibility` | 物品可得性 |
| `Drugs` / `Wool` / `ApparelByStuff` / `ApparelArmor` / `ApparelInsulation` | 商品品类平衡 |
| `ThingSetMakerTags` / `ThingSmeltProducts` | 掉落池与熔炼产物 |
| `RoamingVsEconomy` | 游荡动物与经济 |
| `HediffsPriceImpact` | 伤病对 pawn 售价的影响 |
| `AnimalBreeding` / `ArchonexusAllowedItems` / `RewardTags` / `ApparelCountsForNudity` | 其余平衡表 |

**解读（对 SDD 有直接价值）**：
Tynan 官方对"经济"的定义域是 **「生产链 + 获取途径 + 品类平衡」**，
而**不是**「收支账本 / 现金流 / 市场价格」。
这意味着：「经济系统中心」若要贴合原版设计哲学，应以**产能与获取途径**为主线，
而非硬套现实世界的财务模型。做现金流账本则是**原版没有的增量**，属于 MOD 原创区。

### 2.2 运行时三块碎片

| 碎片 | 代表类 | 服务目标 | 是否互相连通 |
|---|---|---|---|
| ① 财富估值 | `WealthWatcher`、`WealthUtility`、`StorytellerUtility` | **袭击难度平衡** | 否 |
| ② 易货贸易 | `TradeSession`、`TradeDeal`、`Tradeable`、`TradeUtility` | 一次性交易 UI | 否（不写账本） |
| ③ 物品索引 | `Map.listerThings`、`ResourceCounter` | 搬运/储存/资源栏 | 否（只计数量不计价值） |

**三者之间没有桥梁**：财富不知道库存构成，贸易不写账本，库存不参与定价。

### 2.3 常见误解更正（核查中已证伪）

| 坊间/直觉说法 | 实测结论 |
|---|---|
| 原版有 `StatCategoryDef` 叫 Economy | **没有**。`Stats/StatCategories.xml` 共 44 个分类，无 Economy。`MarketValue` 的 category 是 `BasicsImportant` |
| 有 `WealthTameAnimals` 独立属性 | **没有**。驯服动物并入 `WealthPawns` |
| 有 `ColonyWealthForStoryteller` | **没有**。正确名 `PlayerWealthForStoryteller` |
| 有 `GlobalPointsRandomFactor` | **没有**。实际是 `IIncidentTarget.IncidentPointsRandomFactorRange` |
| 有 `TradeMode` / `TradeDealUtility` / `TradeGood` | **都没有**。`TradeTags` 也不是类，是 `ThingDef.tradeTags` 字符串列表 |
| 有 `IncidentWorker_QuestTradeRequest` | **没有**。走 Quest 系统（`QuestPart_InitiateTradeRequest`） |
| `ResourcePodCrash` 叫 `TransportPodCrash` | 错误，正确名 `IncidentWorker_ResourcePodCrash` |

## 三、可直接复用的原版能力（资产清单）

### 3.1 估值与财富

| 能力 | 入口 | 备注 |
|---|---|---|
| 殖民地财富四分项 | `Map.wealthWatcher.Wealth{Items,Buildings,Pawns,FloorsOnly,Total}` | 5000 tick 缓存 |
| 全殖民地财富 | `WealthUtility.PlayerWealth` | 跨地图累加 `IsPlayerHome` |
| 单 pawn 随身财富 | `WealthWatcher.GetEquipmentApparelAndInventoryWealth(pawn)` | 静态 |
| 单物估值 | `Thing.MarketValue` → `StatDefOf.MarketValue` | worker 为 `StatWorker_MarketValue` |
| 建筑估值（忽略耐久） | `StatDefOf.MarketValueIgnoreHp` | 财富统计用这个 |
| Pawn 估值 | `PriceUtility.PawnQualityPriceFactor/Offset` | 含健康/技能/年龄/特质 |
| 房间财富 | `RoomStatWorker_Wealth` | |
| 财富历史曲线 | `HistoryAutoRecorderWorker_Wealth{Total,Items,Buildings,Pawns}` | **Def 驱动，可扩展** |

### 3.2 库存与产出采集

| 能力 | 入口 |
|---|---|
| 全图物品索引 | `Map.listerThings`（按 `ThingRequestGroup`） |
| 待搬运 / 可合并 | `Map.listerHaulables`、`listerMergeables` |
| 分类资源计数 | `ResourceCounter.GetCount(def)` / `GetCountIn(group)` / `GetCountIn(category)` / `.Silver` |
| 全部计数快照 | `ResourceCounter.AllCountedAmounts`（`Dictionary<ThingDef,int>`） |
| 储存区 | `SlotGroup`、`StorageSettings`、`HaulDestinationManager`、`StorageGroupManager` |
| 生产订单 | `Bill_Production` |
| 完成计数 | `RecordsUtility.Notify_BillDone` → `RecordDefOf.ThingsCrafted`（**pawn 级**） |

### 3.3 贸易定价（作为基准价）

| 能力 | 入口 |
|---|---|
| 买入价 / 卖出价 | `TradeUtility.GetPricePlayerBuy/Sell(thing, ...)` |
| 交易条目 | `Tradeable.GetPriceFor(action)` |
| 货币判定 | `Tradeable.IsCurrency`（硬编码 `ThingDefOf.Silver`） |
| 商人类型 | `TraderKindDef`（7 个 Def 文件）+ `StockGenerator` 15 子类 |
| 贸易 → 好感 | `Faction.Notify_PlayerTraded`（每 600 市值 +1 好感） |

**定价公式（`TradeUtility.cs:270-298`，实测）**：

```
卖出价 = MarketValue × 0.6 × 商人PriceType倍率 × SellPriceFactor × 0.6(人口)
         × (1 - difficulty.tradePriceFactorLoss)
         × (1 + 谈判者 + 毒品加成 + 定居点加成 + 畜产品加成)

买入价 = MarketValue × 1.4 × 商人PriceType倍率
         × (1 + difficulty.tradePriceFactorLoss)
         × (1 - 谈判者 - 定居点加成)

常数：PriceFactorBuy_Global = 1.4 / PriceFactorSell_Global = 0.6
     最低买价 0.5 / 最低卖价 0.01
     PriceType 倍率：VeryCheap 0.4 / Cheap 0.7 / Normal 1 / Expensive 2 / Exorbitant 5
```

> **无数量项、无时间项、无历史成交项** —— 这就是"原版无市场"的铁证。
> 另有 `ITrader.RandomPriceFactorSeed` 接口成员，但**全库无任何消费点**（历史遗留）。

### 3.4 可扩展的历史曲线框架（最值得复用）

`HistoryAutoRecorderWorker` 是 **public 非 abstract 类**，含 `public virtual float PullRecord()`；
`HistoryAutoRecorderDef : Def`，通过 `<workerClass>` 指定 worker。

**含义**：MOD 可以纯靠 Def + 一个派生类，就往原版「历史」面板里注入自定义曲线
（如：日收入、日支出、净现金流、库存价值、产能利用率）。
原版已有 13 条曲线、4 个分组（Wealth / Population / ColonistMood / Debug）。

## 四、口径陷阱（必须写进 SDD 的约束）

| # | 陷阱 | 正确做法 |
|---|---|---|
| 1 | `WealthTotal`（建筑×1.0）≠ `PlayerWealthForStoryteller`（建筑×0.5） | **UI 展示用 `WealthTotal`；难度/平衡相关沿用 `PlayerWealthForStoryteller`**，两者不可混用 |
| 2 | `WealthBuildings` **已包含地板** | 不要再加 `WealthFloorsOnly`，否则重复计算 |
| 3 | `WealthPawns` 含全部玩家派系 pawn | 想拆「殖民者/奴隶/动物」需自行遍历 `mapPawns` |
| 4 | 财富缓存 5000 tick（约 83 秒） | 交易/生产后 UI 财富不即时更新；需主动 `ForceRecount` 或接受延迟 |
| 5 | `fixedWealthMode` 难度下财富由时间曲线决定 | 与真实资产脱钩，MOD 需特殊处理或标注 |
| 6 | `ThingDef.BaseMarketValue` 是**属性**，读写走 Stat 系统 | 直接赋值会改 statBase |
| 7 | `Tradeable` 价格**每个实例只算一次**（private 缓存） | 改价需重建 Tradeable 或 Patch |
| 8 | `ResourceCounter` 只统计 `CountAsResource` 的物品 | **不能当全量库存** |
| 9 | `StatPart_Quality` / `StatPart_Health` 倍率在 XML 里 | C# 里看到的全是默认 1f，实际倍率查 Def |
| 10 | 奴隶财富 ×0.75（`WealthFactor_Slave`） | 自建统计若拆分人群需注意对齐 |

## 五、原版完全没有、必须自建的部分

| 缺口 | 说明 |
|---|---|
| 统一经济数据模型 | 无 `EconomyManager` / `Ledger` / `EconomyUtils`（全库检索无结果） |
| 收支流水 / 账本 | 无交易历史、无「今日收入/支出」 |
| 市场价格波动 / 供需 | 全库零实现（已验证） |
| 殖民地层级产出统计 | 只有 pawn 级 `ThingsCrafted` 等计数，**无殖民地账本** |
| 库存价值聚合 | `ResourceCounter` 只计数量不计价值 |
| 成本 / 利润核算 | 无原料成本追踪 |
| 批量估值缓存层 | 无专用缓存（只有 `StatWorker` 通用 `temporaryStatCache`） |
| 经济时间序列 | 除 4 条财富曲线外，无收入/支出/产量曲线 |
| 信用 / 货币发行 | 无，只有 Silver 实物货币 |
| 商人经济 AI | 无动态定价、无库存需求响应 |

## 六、公开资料佐证

| 来源 | 结论 |
|---|---|
| RimWorld Wiki - Silver | 白银是「**commodity currency**（商品货币）」，被所有商人按 **100% 价值**接受；交易菜单中恒置顶且单独分隔；**不能直接买卖**，只作为结算媒介 |
| RimWorld Wiki - Market Value | 原版取值规则：>200 时四舍五入到 5 的倍数，<10 才显示小数 —— 对应 Def 中 `roundToFiveOver=200` |
| Wiki / 社区共识 | 无动态市场、无供需、无价格指数；商人库存为**定时重置**（`Settlement_TraderTracker.NextRestockTick`），非价格响应 |

## 八、对「经济系统中心 SDD」的直接建议

### 8.1 定位建议

建议把经济中心定位为 **「殖民地资产的观测与记账层」，而非「模拟市场」**：

- **贴合原版哲学**（参考 `DebugOutputsEconomy` 的 21 张表）：主线走
  **产能 → 库存 → 财富** 的链路，回答「我们有什么、从哪来、值多少、趋势如何」。
- **避免硬套现实金融**：原版无市场、无价格信号、无货币发行。
  若要做「动态价格 / 供需」，属于**纯 MOD 原创机制**，需单独立项并评估与
  `TradeUtility` 固定公式的冲突（会破坏原版难度平衡）。

### 8.2 可复用 / 需自建 分派

| 层 | 复用原版 | 自建 |
|---|---|---|
| 采集 | `listerThings`、`ResourceCounter`、`wealthWatcher` | 分类价值聚合器（按 `ThingCategoryDef` 汇总市值） |
| 估值 | `Thing.MarketValue`、`StatWorker_MarketValue` | 批量估值缓存（参照 `StatWorker.temporaryStatCache`） |
| 记账 | — | **全部自建**：收支流水、分类资产快照、产出表 |
| 曲线 | `HistoryAutoRecorderDef` + `HistoryAutoRecorderWorker`（**可扩展**） | 新增 income / expense / net / stockValue 等 worker |
| 展示 | 现有 `SystemCenters` KPI 框架 | 经济中心专属分块（建议对标 Manufacturing 的分块粒度） |

### 8.3 立项前必须先拍板的三个问题

1. **要不要做「市场动态价格」？**
   做 = 与 `TradeUtility` 固定 1.4/0.6 公式冲突，需 Patch 且会影响原版难度平衡；
   不做 = 经济中心退化为「只读观测 + 记账」，风险低、与原版零冲突。
2. **财富口径用哪个？**
   建议 UI 统一 `WealthTotal`，并在 SDD 中明确禁止把 `PlayerWealthForStoryteller` 用于展示。
3. **记账粒度？**
   日/候/月归档（对齐 PC 既有 ArchiveService 快照双轨），还是连续流水？
   涉及存档 schema 变更，需过 GATE-DATA / GATE-SAVE。
