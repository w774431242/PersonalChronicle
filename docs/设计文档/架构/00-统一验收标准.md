# 00 统一验收标准

**目的：** 将“规范符合”转为可重复、可审计的质量门槛。  
**原则：** Gate 不替代测试；Evidence 不等于结论；任一 P0/P1 失败都会阻止 Release。

## 1. Gate 结果定义

| 结果 | 含义 |
|---|---|
| PASS | 所有强制项满足，证据完整 |
| PASS WITH EXCEPTION | 仅在有效 Exception 覆盖范围内偏离，且不含未批准 P0/P1 风险 |
| BLOCKED | 存在强制项失败、证据缺失或未决架构风险 |
| NOT APPLICABLE | 明确说明为何不适用，不得留空 |

Gate 记录至少包含：变更版本、检查人/AI、日期、规则 ID、结果、Evidence 路径、遗留风险。

## 2. GATE-ARCH：架构 Gate

关联：[GOV-001](00-规范体系总纲.md#4-全局不可违反规则)、[MATRIX-001](00-规范关系矩阵.md#matrix-001-单向依赖)、[ARC-001](02-架构层-核心架构规范.md#1-arc-001-分层边界)。

```text
[ ] 变更所属层级和模块已写明
[ ] 依赖出现在允许矩阵中
[ ] 无循环依赖
[ ] Core 未引用 UI/Theme/Asset/第三方 Mod
[ ] 跨模块访问通过 Contract/API/DTO
[ ] 继承、Harmony、全局状态都有必要性说明
[ ] 失败降级和替代方案已定义
[ ] 大文件/类按 ARC-013 治理：职责单一、partial 切片或按层归位，无 god class 堆砌
[ ] 文件结构变更仅做物理切片，未改动类名/签名/契约/Save schema/翻译键
```

失败条件：出现 Core→Presentation、Core→Compatibility、UI 直接改写领域数据、未登记 Harmony、违反 ARC-013 的 god class 堆砌或契约随切片被改，或 P0/P1 违规。

## 3. GATE-DATA：数据 Gate

关联：[DATA-001](03-架构层-数据与扩展规范.md#1-data-001-四类数据边界)、[DATA-004](03-架构层-数据与扩展规范.md#4-data-004-compthingcomp-选择)、[SAVE-001](03-架构层-数据与扩展规范.md#12-save-001-存档身份与版本)。

```text
[ ] Def 只包含静态配置
[ ] Runtime State 不被错误写入 Def 或 UI
[ ] Save Data 有稳定 ID、默认值和版本
[ ] DefModExtension/Comp/Service 选择有理由
[ ] Patch 使用最小 XPath 和条件
[ ] 缓存可从权威数据重建
[ ] 不依赖显示文本作为标识
```

## 4. GATE-LOC：Localization Gate

关联：[LOC-001](05-表现层规范.md#loc-001-本地化命名空间)、[LOC-004](05-表现层规范.md#loc-004-占位符格式化和长度)、[COMP-007](04-架构层-兼容与接入规范.md#7-comp-007-第三方本地化隔离)。

```text
[ ] DefName、Translation Key、显示文本职责分离
[ ] 用户可见代码字符串全部 Keyed
[ ] DefInjected 路径与 Def 类型匹配
[ ] Key 和 Asset 有唯一命名空间
[ ] 英文/默认语言可用
[ ] 目标语言缺失时 fallback 可解释
[ ] 占位符、复数、性别/格式化参数一致
[ ] 长文本、短文本、不同字体尺寸已验证
[ ] 未修改其他 Mod 的 Key 或全局翻译
```

## 5. GATE-UI：UI 与视觉 Gate

关联：[UI-001](05-表现层规范.md#ui-001-ui-状态与领域分离)、[ASSET-001](05-表现层规范.md#asset-001-资源命名空间)、[PERF-002](05-表现层规范.md#perf-002-ui-刷新与缓存)。

```text
[ ] Window/Panel/Component 职责清晰
[ ] UI State 不持有核心持久状态
[ ] Theme Token 集中管理，颜色无散落魔法值
[ ] Asset 路径隔离且引用可解析
[ ] Normal/Hover/Pressed/Selected/Disabled 状态完整
[ ] 多语言布局不依赖固定中文宽度
[ ] Empty/Loading/Error/Unavailable 状态明确
[ ] 大列表、图表和 Timeline 有分页/虚拟化/缓存策略
```

## 6. GATE-COMP：兼容 Gate

关联：[COMP-001](04-架构层-兼容与接入规范.md#1-comp-001-兼容层隔离)、[COMP-004](04-架构层-兼容与接入规范.md#4-comp-004-harmony-升级条件)。

```text
[ ] Core 不直接依赖目标 Mod
[ ] 依赖类型明确：硬依赖/软依赖/能力探测
[ ] 目标 Mod 缺失时正常运行
[ ] 目标 Mod 存在时只执行条件适配
[ ] null、版本差异、初始化顺序有保护
[ ] Harmony Target 解析失败可安全降级
[ ] Patch 范围、顺序、冲突和回滚已记录
[ ] 中英文及目标 Mod 组合已测试
```

## 7. GATE-SAVE：Save/Migration Gate

关联：[SAVE-001](03-架构层-数据与扩展规范.md#12-save-001-存档身份与版本)、[SAVE-004](03-架构层-数据与扩展规范.md#15-save-004-迁移流程)。

```text
[ ] Save schema 版本可识别
[ ] 新字段有默认值
[ ] 缺失/未知字段不会导致启动失败
[ ] DefName/Key 重命名有别名或 Migration
[ ] 旧版本 Save 已加载测试
[ ] Migration 幂等且失败可诊断
[ ] UI/Texture/运行时缓存未写入 Save
[ ] Breaking 变更有 Changelog 和恢复说明
```

## 8. GATE-TEST：测试 Gate

关联：[TEST-001](01-基础层规范.md#12-test-001-最小测试矩阵)。

```text
[ ] 编译通过且无新增警告
[ ] XML/Def/Translation 解析通过
[ ] Vanilla 启动与核心流程通过
[ ] 目标 DLC/第三方 Mod 组合通过（如适用）
[ ] Save/Load/迁移通过
[ ] 失败 Provider 不影响核心功能
[ ] UI 关键路径和输入边界通过
[ ] 语言切换与长文本通过
```

## 9. GATE-PERF：性能 Gate

关联：[PERF-001](05-表现层规范.md#perf-001-热路径约束)、[PERF-003](05-表现层规范.md#perf-003-性能证据)。

```text
[ ] Tick/高频回调不做全库扫描、反射或无界分配
[ ] UI 重绘有刷新条件或 DataRevision
[ ] 大列表/图表有上限和降级
[ ] 日志不在热路径无界增长
[ ] 失败重试有退避/熔断策略
[ ] 提供至少一份基准或可复核指标
```

## 10. GATE-REL：Release Gate

关联：[REL-001](06-变更日志与发布规范.md#rel-001-版本与兼容声明)。

```text
[ ] 版本号、游戏版本、DLC、Harmony 范围明确
[ ] Change Summary 完整
[ ] Changelog 分类准确
[ ] Breaking/Save/Migration/Compatibility 明确
[ ] 包内目录和 About.xml 正确
[ ] 依赖与加载顺序说明完整
[ ] 已知问题、回滚和支持范围明确
[ ] 所有 Exception 仍在有效期内
```

