# 06 变更日志与发布规范

**版本：** v3.0  
**定位：** 将实现、验证、兼容、迁移和用户可感知行为纳入可审计的版本交付  
**关联：** [00-工程生命周期规范.md](00-工程生命周期规范.md)、[00-统一验收标准.md](00-统一验收标准.md)

## 1. REL-001 版本与兼容声明

每次发布必须声明：

```text
Mod 版本
RimWorld 版本范围
DLC 范围
Harmony/框架范围
硬依赖与软依赖
Save 兼容范围
Localization 变化
```

采用语义化版本作为项目默认策略：

```text
Major：破坏公共 API、Save schema、依赖方向或用户行为
Minor：向后兼容的新功能、Def、Key、Provider 能力
Patch：Bug、性能、兼容和文案修复，不改变契约语义
```

## 2. REL-002 Change Summary

每个工程变更先生成 Change Summary：

```markdown
## Change Summary
- Title: <用户可理解的变更标题>
- Scope: <模块/文件/功能>
- Reason: <动机>
- User impact: <用户行为变化>
- Rule IDs: <受影响规则>
- Compatibility: <Vanilla/DLC/第三方 Mod>
- Localization: <Key/语言变化>
- Save/Migration: <无/有，说明>
- Performance: <影响和证据>
- Tests/Gates: <结果>
- Exceptions: <EXC ID 或无>
```

Changelog 记录结果和用户可感知影响，不记录逐行实现过程；实现细节进入代码 Review、Issue 或技术记录。

## 3. REL-003 Changelog 分类

固定分类：

```text
Added          新增用户可用功能
Changed        已有行为或默认配置改变
Fixed          Bug 修复
Removed        功能/API/资源移除
Compatibility  Mod/DLC/平台兼容变化
Localization   Key、语言、翻译和布局变化
Performance    性能和资源占用变化
Breaking       需要迁移、修改依赖或影响既有接入的变化
```

没有内容的分类直接省略；一条记录只表达一个主要事实。

## 4. REL-004 用户可感知描述

推荐：

```markdown
- 修复档案事件写入去重错误，避免同一事件在存档中重复出现。
- 新增可选的工作强度 Provider 接入，不安装目标 Mod 时基础档案功能不受影响。
- 修复简体中文长标题在统计面板中被截断的问题。
```

避免：

```markdown
- 修改 ArchiveService.cs 第 132 行。
- 重构了很多代码。
```

## 5. REL-005 Breaking Change

以下至少使用 `Breaking`：

```text
删除/改变公共 API 或 Provider Contract
改变 Save schema 且旧 Save 需要迁移
修改 DefName、事件 ID、枚举持久化值
改变硬/软依赖关系
移除其他 Mod 已使用的接入点
改变用户已有内容的语义或默认行为
```

必须同时提供：影响、迁移、兼容周期、回滚和替代 API/Def/Key。

## 6. REL-006 Release 包检查

发布包必须检查：

```text
About/About.xml
Assemblies
Defs / Patches
Languages
Textures / Sounds / Materials 等 Asset
文档/许可证（如需要）
```

不得包含调试构建、临时素材、源码私密配置、未登记实验 Patch 或无效语言目录。包结构、依赖和加载顺序必须与 [00-规范体系总纲.md](00-规范体系总纲.md) 及项目实际锁定版本一致。

## 7. REL-007 回滚与已知问题

每个发布版本必须有：

```text
上一稳定版本
回滚触发条件
是否影响 Save
如何禁用可选 Compatibility
已知问题和临时规避方案
```

涉及 Save 的版本不得承诺“直接降级一定可用”，应明确备份与迁移风险。

## 8. REL-008 公共 API 演进

已发布 Contract 优先通过新增版本/接口扩展，而不是向大型接口无限追加方法。废弃 API 保留迁移窗口；删除必须先 Deprecated，再在 Major 版本移除。Provider 能力使用可探测版本，如 `archive.events.v1`。

## 9. REL-009 发布前 Gate

发布前必须完成 [GATE-ARCH](00-统一验收标准.md#2-gate-arch架构-gate)、[GATE-DATA](00-统一验收标准.md#3-gate-data数据-gate)、[GATE-LOC](00-统一验收标准.md#4-gate-loc-localization-gate)、[GATE-COMP](00-统一验收标准.md#6-gate-comp兼容-gate)、[GATE-SAVE](00-统一验收标准.md#7-gate-save-savemigration-gate)、[GATE-TEST](00-统一验收标准.md#8-gate-test测试-gate)、[GATE-PERF](00-统一验收标准.md#9-gate-perf性能-gate) 中适用项。任何 BLOCKED 都阻止 Release。

## 10. REL-010 标准 Changelog 模板

```markdown
# Changelog

## [vX.Y.Z] - YYYY-MM-DD

### Added
- <用户可感知的新功能>

### Changed
- <已有行为变化>

### Fixed
- <问题及影响>

### Compatibility
- <Vanilla/DLC/第三方 Mod>

### Localization
- <Key/语言/布局>

### Performance
- <性能结果>

### Breaking
- <迁移、API、Save 或依赖影响>

### Migration
- <旧 Save/API 的处理方式>
```

## 11. REL-011 规范体系版本

规范文档自身也采用 Major/Minor/Patch：

```text
v3.0：治理闭环、统一术语、规则 ID、生命周期和 Gate 正式建立
v3.1：新增兼容规则/专项文件但不改变既有含义
v4.0：改变层级、依赖方向、术语或验收语义
```

文档版本改变时，更新 README、规则索引和本文件的版本记录。

## 12. REL-012 发布验收

```text
[ ] Change Summary 完整
[ ] Changelog 分类准确且无空分类
[ ] 版本/平台/DLC/依赖/Save 范围明确
[ ] 适用 Gate 全部 PASS 或有效 PASS WITH EXCEPTION
[ ] Migration/回滚/已知问题明确
[ ] 发布包内容经过检查
[ ] 规则索引与文档互链未断
```
