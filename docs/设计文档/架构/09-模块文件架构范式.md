# 09 架构层：模块文件架构范式（轻量化）

**版本：** v1.0（2026-08-15）
**定位：** 新模块/新功能的文件组织范式。以「劳动模块」为模拟样板，把分散在 Domain/Application/Data/Capture/Archive 各层的劳动相关文件收敛成一套可复用的标准化结构。
**上位规范：** [08-架构层-代码轻量化方案.md](08-架构层-代码轻量化方案.md)（**[ARC-013]** 文件组织与类结构治理，全项目适用）、[02-架构层-核心架构规范.md](02-架构层-核心架构规范.md)（ARC-001/004/006）、[00-规范关系矩阵.md](00-规范关系矩阵.md)（MATRIX-001/002/003）、[07-AI开发规范.md](07-AI开发规范.md)（AI-002/003/005）。
**本文定位：** 08 的「模块落地示例」——以劳动模块为模拟样板，演示 ARC-013 的分层归位与跨层 SOP。08 是规则本体，本文是实践模板。
**适用范围：** 所有新增或修改的业务模块（劳动、生产、战斗、勋章、社交、地点、传承……）。

## 0. 为什么要这份文档

`08` 解决的是**存量 god class 怎么拆**；本篇解决的是**未来新模块怎么一开始就摆对位置**，避免再次长成 god class。

核心原则（与 `08` 一致，提前到"规划期"）：

- **单向依赖**：`UI → Application → Domain ← Data / Capture`。UI 不直读 `ChronicleGameComponent`；Data/Capture 不依赖 UI。
- **partial 为主，不引入新抽象**：单一实现的功能不上路由/Provider 注册表（扩展点优先级见 AI-003：Def → DefModExt → Comp → Service → PatchOps → Harmony）。
- **契约零改动**：接口、公共签名、Save schema、翻译键只在确实需要时变更，且需经架构评审。
- **发布同步**：每次落地立即同步发布区（dll 需重启游戏生效）。
- **UI Design System 双关**：所有颜色/字体内聚到 `UITheme`/`UIComponents`，窗口内禁止 `new Color(...)`、禁止裸 `GUI.color`，绘制态必须 `prev` 快照 + try/finally 配对恢复。

## 1. 分层契约（模块内文件归位规则）

| 层 | 目录 | 职责 | 文件命名 | 是否可 partial |
|---|---|---|---|---|
| **Domain** | `Source/PersonalChronicle/Domain/` | 纯数据模型 + 纯逻辑（无 RimWorld/UI 依赖，可离线单测） | `<Concept>.cs`（模型）/ `<Concept>Evaluator.cs`（纯函数）/ `<Concept>Def.cs`（Def 类型） | 否（小而专） |
| **Application** | `Source/PersonalChronicle/Application/` | 聚合/查询/写入编排；实现 `IArchiveService` 等接口 | `<Service>.cs`（主，partial）/ `<Service>.<Area>.cs`（按业务域切 partial） | 是（主类 partial） |
| **Data** | `Source/PersonalChronicle/Data/` | 存档持久化（`ExposeData`/`FinalizeInit`/迁移）+ 采样 + 别名 + 查询 | `ChronicleGameComponent.cs`（主，partial）/ `.Sampling/.Aliases/.Queries/.Migration` | 是（主类 partial） |
| **Capture** | `Source/PersonalChronicle/Capture/` | Harmony 捕获钩子（Postfix/Prefix），把引擎事件转成 Service 调用 | `Patch_<Target>.cs` | 否 |
| **Archive(UI)** | `Source/PersonalChronicle/Archive/` | 窗口/ITab/Dialog/ReadModel 快照 | `ArchiveMainTabWindow.<Area>.cs`（partial）/ `ITab_*.cs` / `Dialog_*.cs` / `ReadModels/SectionSnapshots.<Area>.cs` / `ReadModels/ArchiveUiDataProvider.<Area>.cs` | 是（主类 partial） |
| **Api** | `Source/PersonalChronicle/Api/` | 对外契约（`IArchiveService`/`IArchiveQueryService`/`IPersonalChronicleApi`）+ DomainProvider 扩展点 | `I*.cs` / `DomainProviders/**` | 否 |

**归位铁律**：
- 纯逻辑（如档位计算、series 归并）放 **Domain**，可离线 NUnit 覆盖。
- 跨字段聚合、写库入口放 **Application/Data**。
- 引擎事件入口放 **Capture**（只转调 Service，不写业务）。
- 展示专用数据类（只读快照）放 **Archive/ReadModels/SectionSnapshots.\<Area\>.cs**，与窗口绘制解耦。

## 2. 模拟样板：劳动模块全景文件树

以下以**当前劳动模块真实文件**为基准，标注每层归宿与归并建议。新增劳动子功能时，按此树挂接，不新建孤立文件。

```
Source/PersonalChronicle/
├─ Domain/                          # 纯模型 + 纯逻辑（可离线单测）
│  ├─ WorkIntensity.cs              # 工时强度：输入/策略/结果 + WorkIntensityEvaluator（纯函数）
│  ├─ WorkIntensityDef.cs           # Def 类型（阈值/档位配置）
│  ├─ WorkIntensityPolicySnapshot.cs# （已并入 WorkIntensity.cs，归并示例见 §4）
│  ├─ WorkplaceSnapshot.cs          # 工作场所快照（BuildingStableId/UseCount/...，IExposable）
│  ├─ WorkPrioritySnapshot.cs       # 工作优先级快照
│  ├─ WorkTimeAccumulator.cs        # 工时累计器（append-only 累加，无依赖）
│  └─ ProductionAccumulator.cs      # 产出累计器（与生产同属"劳动产出"域）
│
├─ Application/                     # 聚合/查询/写入编排（IArchiveService 实现）
│  ├─ ArchiveService.cs             # 主：字段 + 基础读写 + ctor（partial）
│  ├─ ArchiveService.Work.cs        # 劳动域：GetWorkTimeStats/GetWorkIntensity/ComputeColonyWorkRank/...（partial）
│  ├─ ArchiveService.Production.cs  # 产出域：GetProductionSummary/AggregateProductionByCategory/...（partial）
│  ├─ ArchiveService.Consumption.cs # 损耗域（劳动负向）：OnWorkplaceUsed/OnThingConsumed/...（partial）
│  └─ WorkIntensityContracts.cs     # 劳动强度对外契约/Provider 注册表接口
│
├─ Data/                            # 存档 + 采样 + 别名
│  ├─ ChronicleGameComponent.cs     # 主：ExposeData/FinalizeInit/写入口（partial）
│  ├─ ChronicleGameComponent.Sampling.cs   # SampleWorkTimeAndPlaces/AddWorkplaceUse（劳动采样）
│  ├─ ChronicleGameComponent.Aliases.cs     # SetBuildingAlias/GetBuildingAlias/SetRoomRoleAlias（工坊/住所别名）
│  └─ WorkIntensityDefCatalog.cs    # Def 目录（从 DefDatabase 取 WorkIntensityDef，Data 层缓存）
│
├─ Capture/                         # Harmony 钩子（只转调 Service）
│  ├─ Patch_BillProduction.cs       # Bill_Production.Notify_IterationCompleted → service.OnWorkplaceUsed（方案A）
│  └─ Patch_IncidentWorker.cs       # 事件 worker 钩子（劳动相关事件捕获）
│
├─ Api/                             # 对外契约
│  ├─ IArchiveService.cs            # OnWorkplaceUsed/GetWorkIntensity/... 契约
│  ├─ IArchiveQueryService.cs       # GetBuildingAlias/GetRoomRoleAlias 契约
│  └─ DomainProviders/
│     ├─ IProductionProvider.cs
│     └─ Builtin/BuiltinProductionProvider.cs
│
└─ Archive/                         # 窗口/ITab/Dialog/ReadModel
   ├─ ArchiveMainTabWindow.cs       # 主：DoWindowContents + 状态字段（partial）
   ├─ ArchiveMainTabWindow.PawnWork.cs     # 劳工六宫格绘制（工时/产出 KPI）
   ├─ ArchiveMainTabWindow.PawnDetail.cs   # 详情聚合调度（partial）
   ├─ ITab_Pawn_Chronicle.cs        # 人物档案 ITab：劳动代表卡（工坊/住所）+ ✎ 改名
   ├─ Dialog_RenameWorkplace.cs     # 通用改名 Dialog（工坊/房间角色共用）
   └─ ReadModels/
      ├─ ArchiveUiDataProvider.cs           # 主：BuildHome/BuildOverview + 通用辅助（partial）
      ├─ ArchiveUiDataProvider.Detail.cs    # BuildWorkplaceView/BuildResidenceView（劳动代表快照派生）
      ├─ SectionSnapshots.Detail.cs         # WorkplaceView/ResidenceView/MedalView（展示快照类）
```

**归并结论**：劳动模块已天然按层归位，无需大改。未来新增劳动子功能（如"劳动情绪""排班优化"）只往对应层挂文件，**不要**在 `ArchiveMainTabWindow.cs` 主文件或 `ChronicleGameComponent.cs` 主文件里堆方法——该切 partial 的切 partial。

## 3. 单文件内部规范（轻量化编码约定）

适用于所有模块文件，违反即回归 god class 苗头。

### 3.1 partial 用法
- 主类声明加 `partial`，字段**集中留主文件**（便于跨 partial 可见、避免重复声明）。
- 同一 partial 类的成员天然互相可见，跨 partial 调用**不改访问级别**。
- 扩展方法必须留在 `static` 类（如 `ArchiveCacheExtensions`），**勿误切进实例 partial 类**。

### 3.2 using 与 namespace
- 文件头 `using` 集与同模块其它文件保持一致（缺哪补哪，不冗余）。
- `namespace PersonalChronicle.<Layer>` 严格对应目录；`ReadModels` 子命名空间不跨层引用 UI 绘制。

### 3.3 注释与分隔
- 大文件内用 `// ---- <功能名> ----` 分隔块标注功能边界（便于未来再拆）。
- 公共类型/方法写 `<summary>`；涉及设计文档条款（如 `§6.9`）在注释里点明，便于追溯。

### 3.4 UI 配对恢复（Design System 双关）
- 窗口内禁止 `new Color(...)`、禁止裸 `GUI.color = ...`。
- 任何 `Text.Font` / `Text.Anchor` / `GUI.color` 改动必须：
  ```csharp
  Color prevColor = GUI.color;
  try { GUI.color = UITheme.Xxx; /* draw */ }
  finally { GUI.color = prevColor; }
  ```
- 中文行高经验值：大卡 ≥110f / StatCell ≥64f / 小字 ≥18f / Medium ≥28f。

### 3.5 防御与 null-guard
- LINQ 前过滤 `null`；UI 不直读 `ChronicleGameComponent`（经 `IArchiveService`/`IArchiveQueryService` 快照）。
- 窗口只消费 `IArchiveUiDataProvider` 快照，排序/null-guard 归属 `ArchiveUiDataProvider`。

## 4. 新增劳动子功能 SOP（跨层改动清单）

以"新增一个劳动指标 `WorkMood`（劳动情绪）"为例，演示标准跨层落地顺序（对齐 AI-005：Contract→Domain→Data→ReadModel→UI→Compat→测试）：

| 步骤 | 层 | 动作 | 产物 |
|---|---|---|---|
| 1 | Domain | 新增 `WorkMoodSnapshot.cs`（IExposable 纯数据）+ `WorkMoodEvaluator.cs`（纯函数，可单测） | 模型 + 逻辑 |
| 2 | Domain | 若需配置，新增 `WorkMoodDef.cs`（Def 驱动，AI-003 最高优先级） | Def 类型 |
| 3 | Application | 在 `ArchiveService.Work.cs` 加 `GetWorkMood(pawn)`（partial 内，不动主文件签名） | 查询入口 |
| 4 | Data | `ChronicleGameComponent.Sampling.cs` 加采样；`ExposeData` 留主文件追加 `Scribe_Values.Look(ref mood, "workMood")` | 持久化 |
| 5 | Capture | 如需引擎事件，新增 `Patch_<Target>.cs` 转调 `service.RecordWorkMood(...)` | 捕获钩子 |
| 6 | Api | `IArchiveService.cs` / `IArchiveQueryService.cs` 增契约方法 | 对外接口 |
| 7 | Archive/ReadModels | `ArchiveUiDataProvider.Detail.cs` 加 `BuildWorkMoodView`；`SectionSnapshots.Detail.cs` 加 `WorkMoodView` 类 | 展示快照 |
| 8 | Archive/UI | `ArchiveMainTabWindow.PawnWork.cs` 绘制；`ITab_Pawn_Chronicle.cs` 卡内接入 | 窗口展示 |
| 9 | Languages | `Archive.xml`（zh/en）加 `UI.WorkMood.*` 翻译键 | 文案 |
| 10 | 验证 | `dotnet build -c Release`（0 错 0 警）→ `dotnet test`（全绿）→ 同步发布区（dll + 改动的 xml）→ 重启游戏抽查 | 发布 |

**红线**：步骤 3/4/7 若发现要往主文件堆方法，先切 partial 再写；步骤 9 翻译键严格对齐设计文档「原名称」，禁擅自改名。

## 5. 反例与边界（明确不做）

- ❌ 不在 `ArchiveMainTabWindow.cs` / `ChronicleGameComponent.cs` 主文件堆新业务方法（该切 partial）。
- ❌ 不为单一实现引入 Provider 路由 / DI 容器 / 反射注册（过度设计）。
- ❌ 不在 Capture 层写业务逻辑（只转调 Service）。
- ❌ 不在 Domain 层引用 `Verse`/`RimWorld`/`UnityEngine`（破坏离线可测性）。
- ❌ 不在 UI 层直读 `ChronicleGameComponent` 或写 Save。
- ❌ 不改类名、不 bump mod 版本（纯组织/功能变更，除非契约确需演进并经评审）。
