# 10 美术资产标准化规范（AI 图像资产生成指引）

**版本：** v1.0
**定位：** 统一本 Mod 所有美术资产（图标 / 面板 / 勋章 / Thing 贴图 / 发布物料）的产生、命名、格式与验收标准，作为 AI 批量生成图像资产的唯一标准指引。
**边界：** 本规范是 [05-表现层规范.md](05-表现层规范.md) 中 ASSET-001~008 的「美术落地细则」。代码侧资源加载仍由 `UITextureLibrary`（UI 主题纹理）与 `ContentFinder<Texture2D>` 负责，本规范不替代它们，只约束「资产从何来、叫什么、长什么样」。
**引用：** 05-表现层规范（ASSET-*）、07-AI 开发规范（AI-004 资产路径禁止裸写）、勋章资产生成记录、MedalDefs.xml、MainButtonDefs.xml、Building_ConveyorSegment.cs。

## 二、RimWorld 1.6 技术约束（硬性）

| 约束 | 规则 | 说明 |
|---|---|---|
| 格式 | 默认 **PNG-24/32（带 alpha）** | 本 Mod 暂无超大世界贴图需求，**不强制 DDS**；仅未来出现 >512px 且需 mipmap 的世界贴图时再评估 DDS+mipmap |
| 路径映射 | 磁盘 `Textures/...` 即代码引用路径，**省略 `Textures/` 前缀与扩展名** | 例：`Textures/UI/ArchiveIcon.png` → 引用 `UI/ArchiveIcon`；`Textures/Medals/Medal_Labor_Model_Gold.png` → `Medals/Medal_Labor_Model_Gold` |
| 尺寸 | UI 图标/单元格建议 **64×64 或 128×128**；面板/卡片基准 **256×256 或 512×512**；勋章 **512×512（可选 1024×1024）**；Thing 单格 **128×128 倍数** | 非 2 的幂也可，但 UI 纹理务必按「最终屏显尺寸」产出，避免引擎缩放发虚 |
| 九宫格（9-Slice） | 面板/卡片/按钮类纹理**四边预留 16~32px 安全边**，中心区域纯色或可平铺，严禁整图拉伸导致边角变形 | 对应 ASSET-004；绘制代码用 `Widgets` 九宫格 API 切边 |
| 透明背景 | 图标 / 勋章 / Thing 必须 **透明 PNG（alpha）** | 背景纯绿/纯色抠图**不被引擎识别**，必须在生成阶段直接出透明底 |
| 色域 | 按 sRGB 直出，避免极端纯黑 `#000000` 整铺（与 RimWorld 深色 UI 融合差） | 深色元素最低降到 `#0E1116` 一类近黑即可 |
| 文字禁令 | **核心资产禁止烧录可读文字（中/英）** | 所有玩家可见文本由代码按本地化绘制（LOC-*）；仅装饰纹样、序号、徽记线条可烧录 |
| 缺失降级 | 任一资产缺失时 UI 必须回退到 Theme Token 颜色，不得空屏/报错 | 对应 ASSET-006；`UITextureLibrary.Get` 已返回 null 走色块 |

## 三、命名与路径规范（CANON）

### 3.1 总规则
1. 文件名**全 ASCII 下划线式**，与对应 `defName` 同源（见 C/D 类）。
2. 前缀统一 `PC_`（Personal Chronicle 资产命名空间），避免与原版/其它 Mod 裸名冲突（ASSET-001）。
3. 禁止使用中文文件名、空格、时间戳、随机串（**勋章批次已踩坑：时间戳并行撞名覆盖**）。
4. 同一概念的多分辨率/多状态，用**后缀**区分，不另起名字。

### 3.2 逐类命名模板

| 类别 | 模板 | 示例 |
|---|---|---|
| A 主图标 | `UI/ArchiveIcon.png` | `Textures/UI/ArchiveIcon.png` |
| B UI 主题纹理 | `UI/<themeId>/<element>.png` | `Textures/UI/epic/panel.png`、`Textures/UI/gothic/card.png` |
| C 勋章 | `Medals/Medal_<系>_<称号>_<Tier>.png` | `Medals/Medal_Labor_Model_Gold.png`（`<Tier>`∈Bronze/Silver/Gold） |
| D 建筑（单） | `Things/Building/<Sub>/PC_<Name>.png` | `Things/Building/Automation/PC_Conveyor_Start.png` |
| D 建筑（四向） | `.../PC_<Name>_<north|south|east|west>.png` | `PC_Conveyor_Start_north.png`（供 `Graphic_Multi`） |
| E 物品 | `Things/Item/<Sub>/PC_<Name>.png` | `Things/Item/AutoFarm/PC_GrowLightModule.png` |
| F 截图 | `About/Screens/<功能>_<视图>.png` | `About/Screens/个人档案-总览.png` |
| F 预览 | `About/Preview.png` | 512×512，Steam 创意工坊封面 |

> 当前仓库存在中文命名的勋章副本（如 `劳动勋章金牌.png`）属**历史遗留**，与 `MedalDefs.xml` 的 `iconPath` 不一致，最终以 `Medal_<系>_<称号>_<Tier>.png` 为准；中文副本归档 `_backup/` 或删除。

### 3.3 新增 element / theme 的登记
B 类新增 `<element>` 必须同步在 `UITextureLibrary` 增加 `internal const string` 键，否则代码无法引用（AI-004：除该类外不得裸写资产路径）。

## 四、视觉风格语言（Style Bible）

### 4.1 整体调性
- **主线（档案馆/人物档案）**：近现代工业编年史风。当前落地主题 **epic** = 深色金属底 + 黄铜/珐琅质感 + 细描边；并预留 **wuxia / steampunk / gothic** 三套可切换皮肤（资源缺失时自动回退纯色块，不影响功能）。
- **Reports（日报/周报/月报/季报/年报）**：羊皮纸 + 宽幅报纸版式，墨黑印刷感，与主线 UI 刻意区分。
- **设计原则**：拒绝传统时间线/dashboard 套路，追求原创信息呈现（「命运星座」式关系网络为长期方向）。AI 产图须服务于该调性，**不产出与原版 RimWorld UI 抢戏的高饱和卡通图**。

### 4.2 基准色板（草案，待从现网纹理取色校准）
| Token | 推荐值 | 用途 |
|---|---|---|
| Background | `#0E1116` | 面板底色 |
| Surface | `#1A1F29` | 卡片/单元格 |
| SurfaceElevated | `#232A36` | 浮层 |
| Border | `#3A4350` | 1px 描边 |
| Text | `#E6E9EE` | 主文字 |
| TextSecondary | `#9AA3B2` | 次级文字 |
| Accent（黄铜金） | `#C8A24A` | 强调/勋章金 |
| Accent2（钢蓝） | `#5B7FA6` | 战斗系/链接 |
| Parchment | `#E9DCC0` | Reports 纸面 |
| Ink | `#2B2419` | Reports 墨色 |

> 色值为基于现有 vanilla 深色 UI 的推荐草案；上线前用取色器从 `Textures/UI/epic/*.png` 与 `About/Screens` 校准，避免 AI 产出与现网色偏。

### 4.3 一致性细则
- **统一描边**：所有图标/面板 1px 同色描边（`Border`），禁用无描边扁平或重投影。
- **勋章系内一致**：同一「系」共享轮廓与珐琅色，仅 `<Tier>` 改变金属质感（铜哑光 → 银亮 → 金高光）；三大系珐琅色：劳动=红、战斗=钢蓝、生产损耗=赭黄、传承=青灰、团体=青铜绿、排名=紫红。
- **构图**：勋章/图标主体居中、四周留 8~12% 安全边；Thing 贴图主体占格 80% 居中，方向图保持旋转锚点一致。
- **光照**：统一「柔顶光 + 轻环境遮蔽」，禁止强镜面高光与体积光雾，确保多图拼接不突兀。

## 五、AI 生成工作流（Standard Pipeline）

### 5.1 工具与产出
- 图像生成工具以英文 prompt 效果最佳；中文概念先转英文锚点再生成。
- 输出**直接透明 PNG**，不依赖后期抠图（绿幕抠图不被引擎识别）。

### 5.2 通用 Prompt 骨架（英文）
```
<subject>, <view/pose>, flat icon / medal relief / UI panel,
dark slate background with brass enamel accents, 1px clean outline,
soft top light, no drop shadow, transparent background,
centered composition, 8% safe margin, game UI asset, consistent with RimWorld mod art
```
- 分辨率参数按 §2 尺寸表给定（如 `--size 512x512` 或工具等效项）。
- **风格锚点固定**：`game UI asset, consistent with RimWorld mod art, no readable text baked in`。

### 5.3 分类 Prompt 速查
| 类别 | 风格锚点补充 |
|---|---|
| A 主图标 | `minimalist archive book emblem, monochrome brass on transparent` |
| B 面板/卡片 | `9-slice UI panel, 32px border zone, center solid #1A1F29, ornate brass frame, transparent corners` |
| C 勋章 | `realisticphotograph of a <系> medal, enamel <珐琅色>, <Tier> metal, ribbon, studio product shot, transparent` |
| D/E Thing | `isometric-ish top-down game prop, <材质>, Vanilla RimWorld thing style, transparent, 128px` |
| F 预览 | **不 AI 生成**；用真实游戏截图缩裁至 512×512 |

### 5.4 批量防撞名（关键）
> 来自勋章批次教训（2026-08-14）：同秒并行生成时间戳撞名 → 后者覆盖前者，丢失 2 张。
- **必须串行**（每批 1 张）或生成后**立即按 §3.2 规范名重命名**；绝不保留工具原始时间戳文件名。
- 生成后做一次「文件名 ↔ defName ↔ iconPath」三方一致性校验（见 §7 Gate）。

### 5.5 后处理清单
1. 确认透明通道干净（无灰边/白边）。
2. 确认无烧录可读文字（§2 文字禁令）。
3. 确认尺寸与 §2 一致，必要时用 Imaging 工具等比重采样（勿拉伸变形）。
4. 放入正确路径，执行 §7 Gate。

## 六、常见失败模式与规避

| 失败模式 | 根因 | 规避 |
|---|---|---|
| 文件被覆盖丢失 | 并行生成时间戳撞名 | 串行生成 + 落盘即规范重命名（§5.4） |
| 引擎找不到图 | 文件名≠defName/iconPath | 生成后三方校验（§7） |
| 绿幕图不透明 | 误以为绿底可被识别 | 生成阶段直接出透明 PNG |
| 面板边角拉伸变形 | 未留九宫格安全边 | 四边留 16~32px 纯色/可平铺边（§2） |
| UI 文字错语言 | 资产烧录中文 | 文字一律代码绘制（§2 文字禁令） |
| 风格跳脱 | 每次随机 prompt | 固定 §4 + §5.3 风格锚点 |
| 色偏不统一 | 未校准色板 | 上线前从现网纹理取色（§4.2） |
| 中文副本混淆 | 历史遗留 | 统一 English defName 命名，中文副本清理（§3.2） |

## 七、验收 Gate（ART-GATE）

每次提交美术资产前，逐项核对：

```text
[ ] ART-1  资产落入 §1 分类表，路径/文件名符合 §3 模板（无中文/时间戳/空格）
[ ] ART-2  文件名 ↔ defName ↔ Def iconPath/graphicPath 三方一致
[ ] ART-3  格式为 PNG，透明通道干净（Thing/图标/勋章）
[ ] ART-4  尺寸符合 §2（UI 按屏显尺寸，面板留九宫格边）
[ ] ART-5  无烧录可读文字；无纯黑整铺
[ ] ART-6  风格符合 §4（描边/色板/构图/光照一致）
[ ] ART-7  B 类新 element 已在 UITextureLibrary 登记
[ ] ART-8  批量生成串行完成、无覆盖丢失、已规范重命名
[ ] ART-9  About/Screens 为真实截图，非 AI 图
[ ] ART-10 资产清单（§8）已更新，发布包仅含合规资产（ASSET-007）
```

结果：PASS / BLOCKED / N/A，附 Evidence（文件清单 + 取色截图）。BLOCKED 不得合入。
