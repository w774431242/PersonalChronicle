# 11 预览落地标准化规范（Preview → In-Game Landing）

**版本：** v1.0
**定位：** 把 `系统中心蓝图/*.html`、`docs/UI预览/*.html` 这类 **HTML/RUIF 预览**可复现、可验收地落地为游戏内 UI 的唯一标准流程。回答四个问题：**量什么、怎么换算、怎么排、怎么验**。
**边界：** 本规范只管「预览 → 游戏」这一段判定。玩法规则归宝典，数据归属与分层依赖归 [03](03-架构层-数据与扩展规范.md)/[02](02-架构层-核心架构规范.md)，UI 架构与主题归 [05-表现层规范.md](05-表现层规范.md)（UI-* / ASSET-*）；数据层契约与快照刷新归 [08c](08c-数据层契约与UI对接标准.md)（DL-*）。本规范不重复定义它们，只补上「预览作为输入」时的额外硬约束。
**引用：** 05-表现层规范（UI-002/006/007/008/009、PERF-001/002）、08c-数据层契约（DL-*）、10-美术资产标准化规范（ASSET 落地细则）、02-核心架构（ARC-006 Provider/Registry）。
**适用范围：** 所有以 HTML 预览为蓝本的游戏内界面（系统中心各中心、档案馆新增页、自动化面板等）。

## 0. 为什么需要这份规范（问题陈述）

在落地「终局管理系统 · 系统中心」时，同一类问题被反复提出且只能靠往复返工解决：

| 反复出现的问题 | 根因 | 本规范对应规则 |
|---|---|---|
| 「卡牌太大了」 | 预览尺寸从未被量化，落地方按「能放下」自定尺寸 | LAND-001 / LAND-002 / LAND-006 |
| 「界面不居中 / 溢出屏幕」 | 宿主窗口的默认定位被当成「居中」，且尺寸写死 | LAND-003 / LAND-004 |
| 「能不能 1:1？全屏？高分辨率？」 | 「1:1」没有定义，分辨率与 UI 缩放的换算关系没写清 | LAND-002 / LAND-005 / LAND-007 |
| 「为什么和预览差这么多」 | 引擎只有三档字体、无 CSS 特效，降级缺少登记 | LAND-007 / §5 降级表 |
| KPI 取不到值 | 预览样例数值与真实数据源未做缺口登记 | LAND-009 |

**结论：** 落地不是「照着画」，而是「把预览的**结构化硬指标**提取出来，按引擎能力换算，并按固定档位自适应」。下面把这条链路固化成规则。

## 1. 铁律（LAND-001 ~ LAND-014）

### LAND-001 先量后写（Measure Before You Draw）
落地前**必须**从预览源码反读出硬指标，禁止目测估尺寸。至少提取：

| 项 | 从哪读 |
|---|---|
| 页面容器与内容宽 | 容器选择器的 `max-width` 与 `padding` |
| 栅格列数与比例 | `grid-template-columns`（含 `repeat(n,1fr)` / `4fr 5fr` 这类比例） |
| 间距 | 容器 `gap`、卡片 `padding` |
| 字号 | 卡片内 `.big` / `.num` / `.lbl` / `.delta` 的 `font-size` |
| 断点 | 该区块相关 `@media (max-width: …)` |
| 卡高 | 由 padding + 行数 × 行高 + 进度条高推导，不取「看起来差不多」 |

产出物：**落地基准表**（见 §4 模板），随模块文档归档。

> **操作提示（本项目已验证）：** 含中文的大 HTML 用文本检索常返回 0 命中（CRLF + CJK）。请用 `Select-String -Path <file> -Pattern '<选择器>'` 定位行号后，再用 `read_file` 指定 `offset/limit` 读取该段 CSS；不要相信一次全局检索的「找不到」。

### LAND-002 「1:1」的定义（Baseline, Not Pixels）
**1:1 = 内容宽基准对齐，不是像素绝对相等。** 判定方式：

```
预览侧基准：W_p（内容宽）→ 该宽度下的一行 N 卡 → 单卡宽 c_p = (W_p − gap×(N−1)) / N
游戏侧换算：可用内容宽 W_g → 若 W_g ≥ 同档阈值 → 同样一行 N 卡（比例一致）
```

必录三项基准：**内容宽、单卡宽、卡高**。任何「1:1」的声明必须附这三项数字与来源行号。

### LAND-003 窗口尺寸：声明上限，禁止写死常数
界面窗口**不得**把尺寸写成固定常数（如 `1180×740`）。必须：

1. 只声明**上限**尺寸与依据；
2. 实际尺寸交由宿主按屏幕夹取（RimWorld：`MainTabWindow.InitialSize` 自动夹到 `屏宽 / 屏高−35`）；
3. **显式声明定位**（居中 / 贴边），不得依赖宿主默认值。

> **⭐ 已验证陷阱：** `RimWorld.MainTabWindow.SetInitialSizeAndPosition()` 先调用 `base`（居中），**随后强制改写** `windowRect.x = 0f`（`Anchor` 默认 `MainTabWindowAnchor.Left`）与 `windowRect.y = (UI.screenHeight − 35) − height`（底贴边）。**只改 `RequestedTabSize` 不会改变贴边行为**——需要居中的窗口必须自行 `protected override void SetInitialSizeAndPosition()` 且不调 `base`。

### LAND-004 内容宽度预算（Content Width Budget）
可用内容宽必须写成**显式扣减公式**并在文档登记，新增侧栏/边框/滚动条时同步更新：

```
W_g = 窗口宽 − 侧栏宽 − 间隙 − 面板内边距×2 − 滚动条宽
本工程实例： 208 + 12 + 24 + 18 = 262  ⇒  W_g = 窗口宽 − 262
```

### LAND-005 响应式三档（Tier-Aware Landing）
预览有断点，落地就必须有分档，禁止固定一档：

| 档 | 触发条件 | 行为 |
|---|---|---|
| **Tier-L** | 全部卡片能在**一行**放下（≥ 最小可读宽） | 一行 N 卡（复现预览满宽形态） |
| **Tier-M** | 否则 | 按**语义分组**，每组尽量一行 |
| **Tier-S** | 组内仍放不下 | 组内折行（不得压到最小可读宽以下） |

阈值必须可追溯（预览 media query，或由 LAND-006 的最小可读宽推导）。

### LAND-006 卡型与切换阈值（Card Form）
**同一面板只允许一种卡型**（禁止同面板混排两种卡）。卡型切换阈值由「卡内必须承载的信息」反推：

```
宽档：卡宽 ≥ 160UI点 → [数值 Medium][标签 Tiny + 附注 Tiny][右侧进度条]
窄档：卡宽 < 160UI点 → [数值 Medium][标签 Tiny] + 底部细条   （附注转悬停提示）
```

阈值不得拍脑袋：160 = 内边距 16 + 数值区 ~32 + 间隔 6 + 标签区（6 个 CJK 字 @Tiny ≈ 78）+ 条 20 ≈ 152，向上取整到档。

### LAND-007 字体档映射与「列数由文字决定」（Font Ladder）
引擎只有三档字体，映射**固定**，不得引入第四档：

| 预览字号 | 游戏字体 |
|---|---|
| 10–12px（辅助/附注） | `GameFont.Tiny` |
| 13–15px（正文/标签） | `GameFont.Small` |
| 18–22px（数值） | `GameFont.Medium` |

由此推出硬结论：**卡片列数由「最长标签的文字宽度」决定，而不是由预览的 px 比例决定。** 落地时必须按最长标签校验；CJK 字宽 ≈ 字档满宽，不得用「预览能放下」推断游戏能放下。

### LAND-008 文案不截断兜底（No Silent Truncation）
任何可能被截断的文本**必须**同时提供完整悬停提示，且提示文本**在构建期（快照/Provider）拼好**，绘制期零拼接、零分配（→ PERF-001/002）。

### LAND-009 数据缺口如实（No Fake Data）
预览中的**样例数值一律不得进入游戏**。取不到的口径：显示「—」+ 一句**原因文案**（如「无设备」「监管机制未落地」），并在模块文档登记「缺口 + 所需数据源 + 预计落地块」。

### LAND-010 结构经契约声明，UI 不特判（No Module Special-Casing in UI）
预览的分组、分区、比例等**结构信息必须经契约声明**（Def / Provider / 快照字段），UI 只按声明排版。禁止在绘制代码里出现「如果是制造中心就……」。

> 正例：`ISystemCenterDataProvider.KpiRowSizes = [4,5]` → UI 按组排版，不认识「制造中心」这个词。

### LAND-011 布局计划缓存（Layout Plan Cache）
响应式布局的「行列计划」必须缓存，键 = 可用宽 + 卡片数 + 快照版本；绘制路径零 `new` / 零 LINQ / 零重算。比例与阈值判定在快照 / Provider 侧完成，UI 只读（→ DL 契约「快照即真相」）。

### LAND-012 刷新与门控
预览里的「实时感」不得用每帧重算换。快照重建以 **tick 节流**为唯一权威门控（→ 08c / PERF-002），布局计划随快照失效重建。

### LAND-013 全文本走本地化管道
所有用户可见文本经 Keyed / DefInjected（→ LOC-001~005）。键名与预览用语**一一对应**，便于对齐审查；预览里的固定术语（如 `depends_on` / `OEE` / `AVAILABILITY`）可保留原词，但必须登记为「不翻译的契约词」。

### LAND-014 交付同步与证据
落地完成必须：编译 0 错 0 警、单测通过、发布区 dll 与 Def/语言文件哈希一致（→ 06 发布规范），并把**落地基准表 + 缺口清单 + 未做项**归档到模块文档。

## 2. 落地 SOP（七步）

| 步 | 动作 | 产出 | 判定 |
|---|---|---|---|
| 0 | 立项 | 目标模块 / 块号（如「制造中心 ① 总控 KPI」）、范围与非目标 | 一句话可复述 |
| 1 | **量预览** | LAND-001 的落地基准表（附选择器与行号） | 六项指标齐 |
| 2 | **定数据源** | 每个指标 → 原版 API / 已有 ledger / 需自研；原版 API **必须反编译核实** | 无「大概有这个字段」 |
| 3 | **定契约** | Def 字段 / Provider 接口 / 快照字段 / 键名 | UI 无特判、无硬编码 |
| 4 | **实现** | 窗口（LAND-003/004）→ 响应式布局（005/006/011）→ 卡内文案（007/008）→ 缺失态（009） | 三档各构造一次截图 |
| 5 | **Gate** | §6 清单逐条 | 未过项登记 EXC 或列入待办 |
| 6 | **同步与归档** | 发布区同步 + 模块文档（基准表/缺口/未做） | 哈希一致 |

> 步 2 是本流程最容易偷懒、代价最高的一步。本项目已踩坑：`MapPawns.AllPawnsSpawned` 是 `IReadOnlyList<Pawn>` 而非 `List<Pawn>`；`Bill` 只有 `repeatCount`/`suspended`，**没有**每单完成度；`Def.description` 可省略但空串会报错。这些只能靠 `ilspycmd -t <全限定类型名>` 取证。

## 3. 预览 → 引擎降级表（已知且被接受的差异）

| 预览能力 | 引擎能力 | 降级方案 | 登记处 |
|---|---|---|---|
| 任意 px 字号 | 仅 `Tiny/Small/Medium` 三档 | LAND-007 映射 | 本规范 |
| `border-radius` 圆角 | 无（`Widgets.DrawBox` 直角） | 直角 + 令牌色边框 | 10-美术资产 |

### 4.2 实例：制造系统中心 ① 总控 KPI（2026-09-10 实测）

来源：`系统中心蓝图/制造系统中心预览_RUIF单页统一版.html`

| 预览元素 | CSS 硬指标 | 游戏侧映射 | 依据 |
|---|---|---|---|
| 页面容器 | `#wrap{padding:14px 20px 70px; max-width:1720px}` | 内容宽基准 **1680** | LAND-002 |
| KPI 区 | `#kpi{display:grid;grid-template-columns:4fr 5fr;gap:14px}` | 9 卡：4 率卡 + 5 仪表，**同一行** | LAND-005 |
| 率卡 | `.oee-c{padding:10px 16px;gap:14px}` + `.big{22px}` + `.t{11px}` + `.bar{height:8px}` | 卡高 **52**、条高 8、`[数值][标签/附注][条]` | LAND-006/007 |
| 仪表卡 | `.gauge{padding:10px 12px;gap:11px}` + `.num{19px}` + `.lbl{11px}` + `.delta{10px}` | 同上卡型（同面板统一） | LAND-006 |
| 断点 | `@media (max-width:1320px){#kpi→1列; #oee→2列; #gauges→3列}` | 落到 Tier-M/Tier-S；本项目保持 4+5（比预览降级更整齐） | LAND-005 |
| 单卡宽 | `(1680 − 8×14) / 9 = 174px` | 窗口上限 **1960×1120**（≥ 1680 + 42，余量防超宽屏拉长卡片） | LAND-003/004 |
| 总览卡片网格 | `repeat(auto-fill, minmax(392px,1fr))`，容器 1240 → 3 列 | 同比例缩放后 auto-fill（`CenterGridColumns`），1:1 时同为 3 列 | LAND-002/005 |

**结果对照（同一 dll，随环境自动分档）：**

| 环境 | UI 点（=物理分辨率÷UI缩放） | 窗口（夹取后） | W_g = 窗口宽 − 42 | 档位 | 单卡宽 |
|---|---|---|---|---|---|
| 1920×1080 @缩放 1.0 | 1920×1080 | 1920×1045 | 1878 | Tier-L 一行九卡（宽档） | 203px（≥ 预览 174，更宽裕） |
| 2560×1440 @1.0 | 2560×1440 | 1960×1120 | 1918 | Tier-L 一行九卡（宽档） | 208px |
| 1920×1080 @1.75 | 1097×617 | 1097×582 | 1055 | Tier-M 4+5（宽档） | 259 / 206px |

> 总控中心是**路由页（无侧栏）**，故 `W_g = 窗口宽 − 42`（内边距 24 + 滚动条 18）。带侧栏的窗口（如档案馆）按 LAND-004 取 `窗口宽 − 262`。

> **结论（回答「全屏？高分辨率？」）：** 决定能否「一行九卡」的是 **UI 缩放**，不是分辨率。分辨率只决定窗口能否吃满上限；`UI点 = 物理分辨率 ÷ UI缩放`。要高密度就调低缩放（1080p→1.0、1440p→1.25），窗口会自动铺满。

## 6. 验收清单（LAND-Gate）

- [ ] **基准**：落地基准表已填，六项硬指标均附选择器与行号（LAND-001/002）
- [ ] **窗口**：无写死尺寸常数；上限来源可解释；定位显式声明且小屏四边不越界（LAND-003/004）
- [ ] **分档**：Tier-L / M / S 各实测一次；无重叠、无卡内文字溢出、无缺列（LAND-005）
- [ ] **卡型**：同面板单一卡型；切换阈值可推导（LAND-006）
- [ ] **文字**：最长标签按字体档校验；所有截断项均有悬停提示且提示零绘制期拼接（LAND-007/008）
- [ ] **缺口**：无任何预览样例数值（例外：§7.1 Dev-Fill，须能指认所属分片）；缺失项显示「—」+ 原因，且已登记缺口（LAND-009）
- [ ] **契约**：结构分组经契约声明；UI 绘制代码内无模块名特判（LAND-010）
- [ ] **性能**：布局计划有缓存；刷新走 tick 节流；绘制路径零 `new`/LINQ（LAND-011/012）
- [ ] **本地化**：全文本经 Keyed/DefInjected；契约词已登记不翻译清单（LAND-013）
- [ ] **交付**：编译 0 错 0 警 + 单测通过 + 发布区哈希一致；模块文档已归档基准表/缺口/未做（LAND-014）

**结果四态**沿用 [00-统一验收标准.md](00-统一验收标准.md)：`PASS` / `PASS WITH EXCEPTION` / `BLOCKED` / `N/A`（N/A 必须写明原因）。

### 7.1 受控偏离：开发者模式数据填充（Dev-Fill）

LAND-009 禁止把预览样例数值带进游戏。**唯一的例外通道是 Dev-Fill**（开发期用随机数填充数值以检查排版与配色），且必须同时满足四条：

| 约束 | 要求 | 反例（禁止） |
