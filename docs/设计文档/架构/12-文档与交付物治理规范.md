## 1. 适用范围与问题陈述

### 1.1 适用对象
工程内一切**人工/AI 产出的文档与交付物文本**，含：

| 类别 | 位置示例 |
|---|---|
| 规范与契约 | `docs/设计文档/架构/*.md`（规范主副本） |
| 设计 / 方案 / 调研 | `docs/设计文档/**` |
| 变更标注 | `docs/设计文档/架构/变更标注/*.md`（新落点，见 `DOC-001`） |
| 交付报告 / 审计报告 | `docs/设计文档/架构/`、`docs/设计文档/功能模块/<子系统>/` |
| 问题跟踪 | `docs/问题跟踪/*.md` |
| Changelog | `docs/changelog/**` |
| 开发参考 / 玩家文档 / UI 预览 | `docs/开发参考/`、`docs/面向玩家/`、`docs/UI预览/` |
| 集群侧规范与规则 | `.codebuddy/skills/**`、`.codebuddy/rules/**`、`.codebuddy/agents/**` |
| 模块化实装指导 / 游戏代码设计 | `docs/设计文档/功能模块/经济体系/经济需求驱动AI/**` |

**不适用**（各按既有规则）：游戏运行资源（`.dds`/贴图/`Defs`/`Languages`）、代码注释、Gate Record（`.codebuddy/audit/gate-records/`）、记忆条目（`memory-standard`）。

### 1.2 问题陈述（本规范要治的四类失效）

| 编号 | 失效 | 典型症状 |
|---|---|---|
| F1 | **新建无审批** | AI 直接落盘新文档，用户事后才发现；未提交审核 |
| F2 | **更新优先缺席** | 已有同主题文档不更新，另建新文件（v0.3→v0.9 并列、根目录散落） |
| F3 | **落点与索引失管** | 文档落在仓库根 / `docs/` 顶层；新增后 `README` 索引不登记，文档不可检索 |
| F4 | **取代关系无登记** | 新件替代旧件后旧件不加横幅、不归档，双源并存导致读者误信旧文档 |

## 2. 规则（DOC-001–DOC-010）

### DOC-001 分类与落点唯一

- **规则**：一切文档按 `docs/README.md` §命名规范 用途判定表落位；**仓库根与 `docs/` 根禁止散落**（仅允许 `docs/README.md` 与仓库根既有白名单文件）。
- **变更标注落点（2026-10-09 起）**：`docs/设计文档/架构/变更标注/`。**仓库根收口已完成**（`CHG-20261009-DOCGOV-ROOTCOLLECT`：132 份迁移，移动不改字节并以 SHA256 复核；根目录仅剩 `README.md`）——检索只需一处（`变更标注/`），无需两处并查。**污染源已缝合**：`_scripts/` 两个工具脚本原先硬编码写仓库根，已改指新落点（禁止回写根目录）。
- **判定**：新增文档路径必须命中判定表某一行；未命中 ⇒ 先改 `docs/README.md` 分类再落盘。
- **证据**：`doc-guard.ps1` 落点检查（`C1`/`C2`）。

### DOC-002 命名与编号

- **规则**：交付物文件命名沿用 [BASE-013]，统一 `A-创建日期-功能` 形态；A 域复用规则编号域。日期取**创建日**，迭代不改名。
- **文档 ID**：受治理文档应在 front-matter 带 `doc-id`（见 `DOC-005`），形如 `DOC-<域>-<YYYYMMDD>-<slug>`；同一 `doc-id` 跨迭代不变。
- **判定**：文件名与 `doc-id` 均不得复用（替代旧件须在 front-matter 声明 `supersedes`）。
- **证据**：front-matter 校验（`doc-guard` `C3`）。

### DOC-003 更新优先（默认更新，不默认新建）

- **规则**：任何"新建文档"意图在执行前，必须**先检索存量**（主题词 / 文件名 / `docs/README.md` 索引 / 主题子目录 `README.md`）。
  - 命中同主题存量 ⇒ **默认更新该文档**（文内迭代，见 `DOC-008`）；
  - 确需新建 ⇒ 必须**举证"为何不能并入"**，并在申请中列出全部候选存量文档与逐条理由；
  - 检索工具：`doc-guard.ps1 -Find <主题词>`（或等价检索），检索结论须作为申请的一部分。
- **判定**：新建申请缺失"存量检索结论"或结论为空 ⇒ 不得进入 `DOC-004` 审批。
- **证据**：申请条目中的检索清单 + 候选对比（`doc-guard` `C5` 相似度预警作为兜底）。

### DOC-004 新建前置审批门（先审核，后落盘）

- **规则**：文档**新建**动作必须先产出"**文档变更申请**"并向用户完整展示，得到明确通过后才允许落盘正文；未通过之前**只能产出会话内文本**（不写文件）。
  - 申请要素：拟路径 / 文档类型与 `doc-id` / 理由 / **存量检索与候选对比**（`DOC-003`）/ 是否取代旧件及旧件处置（`DOC-007`）/ 预计索引登记点（`DOC-006`）。
  - 用户三选一：**通过 / 修改后通过 / 丢弃**。
  - 留痕：通过的申请条目写入 `.codebuddy/doc-journal/<YYYY-MM-DD>/committed/`（未通过写 `pending/` 后丢弃），并在正文 front-matter 的 `approved` 字段记录时间。
- **例外**：同一任务内已批准文档的**后续更新**（改正文）不需要重复审批；但**改名 / 改落点 / 改 doc-id** 视同新建。
- **判定**：无对应 `committed` 申请条目或 `approved` 字段缺失 ⇒ 视为未审批，`doc-guard.ps1 -Blocking` 拦截。
- **证据**：`doc-journal` 条目 + front-matter `approved`（`doc-guard` `C3`/`C4`）。
- **优先级说明**：本规则与 `memory-standard` **v2.1 工程适配**的"先批准后落库"同源（[GOV-012]）——**严禁先写后报**；落库须**用户明确口头批准**（`approve_verbal.py` 留痕 `approval: verbal`），网关口令为可选更强门槛。

### DOC-005 front-matter 契约

- **规则**：受治理的**新建**文档正文头部必须含可机器解析的 front-matter（HTML 注释或 YAML 均可，字段名固定）：

```text
doc-id:      DOC-<域>-<YYYYMMDD>-<slug>      # 稳定，跨迭代不变
status:      new | update | supersede         # 本次落盘性质
supersedes:  <旧文档相对路径>                  # status=supersede 时必填，否则写 —
approved:    <YYYY-MM-DD HH:MM>               # 用户通过审批的时间（DOC-004）
author:      AI(<模型名>) / <工号或用户名>     # 产出者署名，见 DOC-010
```

- **判定**：字段缺失 / 取值非法 / `status=supersede` 而 `supersedes` 为 `—` ⇒ `BLOCKED`。
- **证据**：`doc-guard` `C3`。

### DOC-006 索引同步（同日登记）

- **规则**：新增文档落盘**当日**必须登记：
  1. 主题子目录 `README.md`（如 `docs/设计文档/功能模块/<子系统>/README.md`）；无主题 README 时登记 `docs/README.md`；
  2. 受治理的规范分册须同步 `docs/设计文档/架构/README.md`。
- **判定**：新增文档未被任一索引提及 ⇒ 视为**未交付**（`WARN`，`-Strict` 时 `BLOCKED`）。
- **证据**：`doc-guard` `C6`。

### DOC-007 取代、归档与退役（禁止双源并存）

- **规则**：新件取代旧件时，旧件必须当日完成以下之一：
  - 移入同级 `/`（`docs/_归档/` 为全局只读存档，只进不出）；
  - 或正文顶部加"**已被取代**"横幅（含替代件路径），并同步移除索引入口。
- **禁止**：旧件与新件同时作为有效检索入口并存。
- **判定**：`status=supersede` 的新件落盘后，旧件仍出现在任何 `README` 索引入口 ⇒ `BLOCKED`。
- **证据**：`doc-guard` `C4` + 索引 diff。

### DOC-008 同主题单文件迭代

- **规则**：同主题版本演进**默认在文内迭代**：文内维护「变更历史」段（版本 / 日期 / 摘要 / 作者），**不建 `v0.3`/`v0.4` 并列文件**。
- **例外**（需按 `DOC-004` 申请）：① 颠覆性重写且旧版需完整留档；② 受众不同（面向玩家 vs 面向开发者）；③ 交付包快照（如 `_交付包/*.zip` 的配套说明）。
- **判定**：新增文件与存量文件**标题/文件名主题相似度超阈值**且未走 `DOC-004` ⇒ `WARN`，要求人工裁决"更新还是新建"。
- **证据**：`doc-guard` `C5` 相似度扫描。

### DOC-009 双副本同步纪律（docs 主副本 → skill 副本）

- **规则**：规范正文的**人类可读主副本在 `docs/设计文档/架构/`**；skill `references/` 是逐文件副本，经 `sync_from_docs.ps1 -Source docs/设计文档/架构` 同步（含 SHA256 校验与规则引用 lint）。
- **同步前必须**：逐条比对两副本差异（**禁止单向盲覆盖**——副本侧可能存在独有条款）；对 `references/` 做快照备份。
- **同步后必须**：`EXITCODE=0`；如 lint 报 dangling 引用，先补齐定义再重跑。
- **改动范围**：在 docs 侧改规范后**必须**当日同步；在 skill 侧改 `scripts/` 工具属工具链变更，须按 `.codebuddy/audit/toolchain-registry.md` 维护纪律登记。
- **证据**：sync 输出 + 哈希一致记录。

### DOC-010 文档域验收（doc-guard 基线门禁）

- **规则**：
  1. 文档域的**客观门禁**为 `.codebuddy/audit/doc-guard.ps1`（`-Blocking` 时违规退出码 2），检查 `C1`–`C7`（见 §4）；
  2. **基线机制**：以 `.codebuddy/audit/doc-baseline.json`（**v2** 文件系统快照：相对路径 + 哈希前 16 位 + `fm` 标记）冻结改动前的存量文档集合；门禁**只拦新增、存量篡改与静默消失**，历史存量（`变更标注/` 187 份等）在基线内**不判违规**；
  3. **基线刷新纪律**：基线只允许在"存量收口轮次"结束时按用户确认刷新；**日常任务不得刷基线**（刷基线 = 绕过门禁，按 [GOV-012] 处理）；
  4. 门禁与 `audit-subagents.ps1 -Blocking` 一并作为**派发前置**与**交付终检**的执行项。
- **署名**：一切交付物（含本文档）显式署名 AI（模型 + 日期），便于区分多会话并行产物来源。
- **证据**：`doc-guard.ps1` 输出 + 基线快照 diff（零差异证明存量未动）。

| 体系 | 产物 | 与本文档域的边界 |

| `summarize` | A 类/B 类变更总结 | 属交付证据；其**落盘**受 `DOC-004` 约束（会话内输出不受限） |

| `doc-guard.ps1` | 落点 / 增量 / front-matter / 索引 / 取代 / 相似度门禁 | 本文档域的**唯一客观 oracle**；不替代 GATE-DELTA 的标注互含校验 |

## 4. 门禁项（doc-guard.ps1）

| 编号 | 检查 | 结果 |
|---|---|---|
| `C1` | 白名单外，仓库根出现**新增** `.md`（含一切文档类扩展名） | `BLOCKED` |
| `C2` | `docs/` 顶层出现**新增**文件（`README.md` 除外） | `BLOCKED` |
| `C3` | 新增文档 front-matter 缺失或 `doc-id/status/supersedes/approved/author` 非法 | `BLOCKED` |
| `C4` | `status=supersede` 时旧件未归档/未加横幅，或旧件仍在索引入口 | `BLOCKED` |
| `C5` | 新增文档与存量主题相似度超阈值（疑似重复） | `WARN`（要求人工裁决） |
| `C6` | 新增文档未被主题 `README` / `docs/README.md` 收录 | `WARN`（`-Strict` 时 `BLOCKED`） |
| `C7` | **基线内存量文档**被修改 / 消失：① 基线内文件消失 → `BLOCKED`（须取代/迁移登记或范围外声明）；② 哈希变化且基线 `fm=true` → 校验当前 front-matter 仍合法（非法 → `BLOCKED`）；③ 哈希变化且 `fm=false` → 提示（历史无 front-matter 存量，不判违规） | `BLOCKED` / 提示 |

配套前置门规则：`.codebuddy/rules/doc-write-gate.md`（alwaysApply）——在**写入动作前**强制 `DOC-003`/`DOC-004` 流程；与 `agent-cluster-frontdoor.md`（任务入口路由）作用点不同、并行生效。

**范围外声明**：`doc-guard.ps1 -ExcludeFromFile <清单>`（每行一条，`#` 注释）用于声明「并行会话在途产物 / 预先存在的无关改动」——不判违规、仅登记；**不得把本轮自己的改动写进清单**（自我豁免 = 绕过门禁，按 [GOV-012] 处理）。

**流程豁免**（不判 `C1`–`C6`，属规则边界外的对象）：`变更标注_CHG-*` 与 `变更标注/`、`docs/changelog/**`（由 GATE-DELTA / 06 发布规范管辖）；**`docs/_交付包/**`（打包产物 = 副本容器，其内文件的合规性由源侧保证，不重复受本文档域治理；2026-10-09 补）**；**`docs/_归档/**`（历史归档件，只进不出）**；**`*.archify.html`（`archify` 引擎交付件：字节被 `deliver` 收据 `sha256 + bytes` 钉死，注入 front-matter 会使收据失真 ⇒ 同「自有模板 / 副本容器」口径走流程豁免，以文件名 `.archify.html` 中缀作机器可识别标记；2026-10-11 经用户「批准 a」，Change ID `CHG-20261011-PIPELINE-VIZ`）**。配套规格源（`*.archify.json`）与浏览器证据（`*.visual-check.json`/`*.png`）非受治理扩展名，天然不判。
