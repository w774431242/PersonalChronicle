# EXC-2026-001 — 捕获层 Harmony Patch 例外（E2）

> **恢复说明**：本文件于 2026-08-19 发现丢失（工作区文件被移除），依据 2026-08-16 架构审计会话记录原样恢复。

- **Status:** Approved
- **Level:** E2
- **Rule IDs:** COMP-004, EXC-002, GOV-007
- **Scope:** `Source/PersonalChronicle/Capture/*`（全部 Harmony Patch）
- **Reason:** 勋章/战斗/社交/生产/损耗/地点等核心档案数据来自 RimWorld 原生事件（击杀、制造、吞噬、建造、派系变更、关系变更、突袭、伤害、事件执行）。这些事件**没有**可用的原生 XML/DefModExtension/Comp/GameComponent/公开 API/事件 Contract 能完整捕获，必须经由 Harmony Postfix/Prefix 钩取。符合 [COMP-004] 的"原生机制无法完成"前提。
- **Alternatives rejected:**
  - 公开 API/事件 Contract：RimWorld 原生未暴露上述事件的可订阅接口。
  - GameComponent Tick 轮询：无法定位单次事件边界，且为热路径全扫，违反 [PERF-001]。
- **Risk:** Harmony 目标方法签名漂移时 Patch 静默失效（已在各 patch 内做"签名探测 + 静默跳过 + 启动诊断"降级）。
- **Mitigation:** 所有 patch 集中在 `Capture/` 层（[COMP-001] 隔离）；目标用 `typeof(X).Method` / `nameof` 精确绑定；签名探测失败仅跳过该捕获，不影响其他功能与启动。
- **Owner / Approver:** PersonalChronicle 维护者
- **Expires:** 2027-08-15（或 RimWorld 大版本升级时复审）
- **Review trigger:** RimWorld 主版本升级、目标方法重命名、Harmony 版本升级
- **Evidence:** 编译 0 错 0 警；Vanilla 启动正常；各 patch 启动期 `CapturePatchDiagnostics` 输出绑定结果。
- **Patch 清单（14 个，均位于 `Capture/`）：**
  1. `Patch_BillProduction` — `Bill_Production.Notify_IterationCompleted`（工坊使用采样）
  2. `Patch_ThingIngested` — `Thing.Ingested`（损耗累计）
  3. `Patch_ThingDestroy` — `Thing.Destroy(DestroyMode)`（地点/物品销毁）
  4. `Patch_SetFaction` — `Pawn.SetFaction(Faction,Pawn)`（派系变更）
  5. `Patch_RoomRoleLabel` — `Room.GetRoomRoleLabel`（房间角色别名解析）
  6. `Patch_Relations` — `Pawn_RelationsTracker.AddDirectRelation` / `RemoveDirectRelation`（社交关系）
  7. `Patch_RaidLordPawnLost` — `Lord.Notify_PawnLost`（突袭领主流失）
  8. `Patch_PawnTakeDamage` — `Pawn.TakeDamage`（伤害累计）
  9. `Patch_PawnKill` — `Pawn.Kill(DamageInfo?,Hediff)`（击杀/传承）
  10. `Patch_IncidentWorker` — `IncidentWorker.TryExecute(IncidentParms)`（事件捕获）
  11. `Patch_GenRecipe` — `GenRecipe.MakeRecipeProducts`（制作产出）
  12. `Patch_GenConstruct` — `Frame.CompleteConstruction(Pawn)`（建造完成）
  13. `Patch_BuildingLabel` — `Thing.Label`（建筑别名解析）
  14. `LocationAtlasCapture` / `IncidentBattleExtension` / `CapturePatchDiagnostics` — 配套捕获辅助（非 `[HarmonyPatch]` 本体）
  15. `Patch_PawnTitleBadge_Map` — `Verse.GenMapUI.DrawPawnLabel`（地图 pawn 标签叠加职称徽章）
  16. `Patch_PawnTitleBadge_Label` — `Pawn.get_LabelShort`（殖民者列表/对话标签叠加职称徽章）
  > 注：15/16 于 2026-08-22 架构体检补登（原清单 14 项遗漏）。两者均位于 `Capture/Patch_PawnTitleBadge.cs`，
  > 同为"原生机制无法完整捕获/装饰"前提（在原生 Label 渲染点注入职称徽章文本），符合 COMP-004。

# EXC-2026-002 — 开发者测试工具反射访问私有字段（E1）

- **Status:** Approved
- **Level:** E1
- **Rule IDs:** MATRIX-003, EXC-004
- **Scope:** `Source/PersonalChronicle/Archive/DevTestButtons.cs`（`ResetDevTestState`）
- **Reason:** 开发者测试按钮生成的 `BattleObject` 需清理时，必须同步 `ChronicleGameComponent` 私有索引字典 `objectsByStableId` 与 `Objects` 列表，否则留下内部 invariant 残留。该清理属于**开发者模式专用**工具，不进入发布运行路径。
- **Alternatives rejected:** 在 `ChronicleGameComponent` 暴露公开"按谓词移除对象"API —— 会为 dev-only 场景新增公共 Service 契约，扩大 API 面且偏离 [ARC-005] 最小接口原则。
- **Risk:** 反射访问私有字段，目标字段重命名时反射返回 null（已做 null 守卫，仅跳过字典同步，不崩溃）。
- **Mitigation:** 仅在 `Current.Game != null` 且 dev 模式下执行；反射结果 null 安全降级；不影响正式功能。
- **Owner / Approver:** PersonalChronicle 维护者
- **Expires:** 2027-08-15（或重构 `ChronicleGameComponent` 索引管理时复审）
- **Review trigger:** `objectsByStableId` 字段重命名 / 索引机制重构
- **Evidence:** 代码注释已标注本例外 ID；dev 工具仅开发者模式可见。
