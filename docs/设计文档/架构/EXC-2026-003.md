# EXC-2026-003 — 车间区拒绝"因建筑占格掉格"（E2）

- **Status:** Approved
- **Level:** E2
- **Rule IDs:** ARC-007（组合优先于继承：此处有意用继承 override 改原版虚方法行为）, COMP-003（条件 Patch 与最小范围）, COMP-009（兼容失败降级）
- **Scope:** `Source/PersonalChronicle/Automation/Zone_Workshop.cs` — `RemoveCell(IntVec3)` / `Delete(bool)` / `RemoveCellExplicitly(IntVec3)` / `CanDropCell` / `HasZoneBlockingThing` / `IsErasingZonesByPlayer`
- **Reason:** 原版 `Thing.SpawnSetup` 末尾 `if (!def.CanOverlapZones) map.zoneManager.Notify_NoZoneOverlapThingSpawned(this)` 会对该 Thing 的 `OccupiedRect()` 每格调 `Zone.RemoveCell(c)` 再 `Zone.CheckContiguous()`。而 `ThingDef.CanOverlapZones` 对以下物为 false：① `building.SupportsPlants`；② `passability == Impassable`（非植物/非 CompTransporter）；③ `surfaceType >= 1`（地板/铺面）；④ `thingClass` 实现 `ISlotGroupParent`（货架等）；⑤ 显式 `<canOverlapZones>false</canOverlapZones>` —— **原版全部工作台继承的 `BenchBase` 正是第 ⑤ 条**，蓝图/框架再委托 `entityDefToBuild`。实测后果：车间被设备/墙/地板抠出空洞；被切断时 `CheckContiguous` 把不与 `cells[0]` 连通的另一半整块删掉；全被吃光时 `Zone.RemoveCell` 内 `cells.Count == 0 → Deregister()` 让整个车间消失；同时 `ZoneManager.ZoneAt(thing.Position)` 不再命中，导致 `WorkshopFloorViewProvider.BenchBelongsToBay`（设备归属）、`WorkshopStats.ScanDevices`（设备统计/清单）静默失效 —— 即"车间失去设备管理能力"。
- **Alternatives rejected:**
  - **改用 `Verse.Area` 承载车间轮廓**：确实免疫（原版无任何 "Thing spawn → 清 Area 格" 路径），但 `AreaManager.areas` 为 **private**、`Remove` 为 **internal**、`AllAreas` 只读 ⇒ 自定义 Area 入列必须 Harmony 反射；且 Area 无 Zone 的 `GetGizmos`（重命名/隐藏/删除/缩小/智能选中）、`GetInspectString`、`Designator_ZoneAdd` 拖拽基类与 `ZoneAt` O(1) 网格，设计器与 gizmo 全需自写；`WorkshopSlot.TargetZone`（`LookMode.Reference`）等引用与老档 zone→area 迁移成本高；改格还会走 `Map.pathFinder.MapData.Notify_AreaDelta` + `Region.Notify_AreaChanged`（比 `MapMeshDirty` 重）。收益不抵迁移与回归风险。
  - **Harmony Prefix 拦 `Zone.RemoveCell`**：被否 —— 原版全部掉格路径都是 `callvirt Zone::RemoveCell`，本类 override 即可截获，无需引入补丁（符合 COMP-004 的"原生机制可完成则不上 Harmony"）。
  - **XML Patch 放开 `BenchBase.canOverlapZones`**：只覆盖被改写的 Def，任何新设备（含本 mod 的 `Building_AutoFarm`，因 `Impassable` 第 ② 条命中）与第三方 Mod 仍会抠格，不达目标。
  - **Zone 掉格 + 自持"影子格集"作权威**：Zone 的视觉格与权威数据长期不一致（玩家无法理解），且设备清单/俯视图要另建一套口径，违反"归属唯一入口"。
- **Risk:**
  - 与"zone 只含空闲格"的原版不变式有意偏离；若第三方 Mod 假设车间格必为空闲格（如自行在 `zone.Cells` 上放植物/存储判定），行为可能与预期不同。
  - 水体覆盖与飞船着陆清场（`WaterBodyTracker.RemoveCellFromExistingBody` / `GravshipPlacementUtility.ClearThingsAt`）落在"被占用的车间格"上时会被拒绝（边缘情形）。
  - 放置设备仍会触发一次 `Zone.CheckContiguous()` 洪泛（原版行为，放置期一次性，非热路径）。
- **Mitigation:**
  - 拦截范围最小化：**只在"本格存在 zone 不可重叠物"时拒绝**（`HasZoneBlockingThing` 直接问 `def.CanOverlapZones`，不自行复制那 5 条规则，避免版本漂移）；其余情形完全走 `base.RemoveCell`，即原版行为不变。
  - 明确放行口：`Delete(bool)`（gizmo「删除」）与 `RemoveCellExplicitly`（自研缩格/搬迁），保证车间一定删得掉。
  - 玩家擦格放行：`Find.DesignatorManager.SelectedDesignator is Designator_ZoneDelete`（含 `Designator_ZoneDelete_Shrink` 子类），原生「删除区域/缩小区域」工具不受影响。
  - 失败降级：`Map == null` 或格越界时按"可移除"处理（走原版）；`RemoveCell` 不抛异常、不写日志，无热路径开销。
  - 读档安全：`allowCellRemoval` 为瞬时运行态、不入存档，读档后必为 false（默认恢复拦截）。
