# EXC-2026-004 — 车间覆盖层抬高渲染队列（置顶于其它 zone/区域）（E1）

- **Status:** Approved
- **Level:** E1
- **Rule IDs:** UI-0xx（表现层一致性）, COMP-003（最小范围）
- **Scope:** `Source/PersonalChronicle/Automation/Zone_Workshop.cs` — `ZoneOverlayRenderQueue`（const 3601）/ `CreateMaterial()` override
- **Reason:** 车间区需要与种植区、仓库区等**功能性 zone** 共存显示（玩家会在同一片场地上嵌套圈定）。原版渲染链：`Verse.SectionLayer_Zones.Regenerate()` 按**栅格扫描顺序**逐格 `GetSubMesh(zone.Material)`（每个 zone 颜色一个 submesh），`Verse.MapDrawLayer.DrawLayer()` 再对每个 submesh 各做一次 `Graphics.DrawMesh`；而**所有** zone（`Zone.CreateMaterial`）与区域高亮（`Verse.CellBoolDrawer`）的 `material.renderQueue` 都是 **3600** ⇒ 同队列内 Unity 按相机距离排序，并列时退化为提交顺序 ⇒ 重叠区里"谁的 submesh 先被扫到谁在下面"，与玩家圈定顺序无关，表现为车间覆盖层被其它 zone 压住、范围看不清（实机截图复现）。
- **Alternatives rejected:**
  - **调整 `ZoneManager.AllZones` 顺序**：无效 —— 叠放次序由 submesh 创建顺序（`SectionLayer_Zones` 的栅格扫描首次命中）决定，与 zone 注册顺序无关。
  - **自绘覆盖层（`MapComponentOnGUI` / `CellBoolDrawer`）**：等于放弃原版 zone 网格烘焙、自担裁剪/性能/`MapMeshDirty` 失效，成本远高于需求。
  - **不处理，改由玩家错开圈定**：违反"覆盖层应反映真实管辖范围"的可用性预期（且车间与仓库/种植嵌套是正常玩法）。
- **Risk:** 渲染队列属全局渲染排序，抬高后车间覆盖层会同时压在**所有** 3600 队列物之上（含其它 zone、区域高亮、`CellBoolDrawer` 类高亮）；若第三方 Mod 也使用 ≥3601 的队列，其相对次序由各自值决定（不做保证）。
- **Mitigation:**
  - 只抬高 **1**（3601），贴着原版 3600，绝不越过 Unity Overlay（4000）⇒ 不遮盖角色/物品/UI；原版全程序集 `renderQueue` 赋值点实测仅 `13 / 2950 / 3201 / 3600`，无冲突项。
  - 使用 `SolidColorMaterials.NewSolidColorMaterial`（`MaterialAllocator` 管理）建**独立材质**并保持原版同款颜色量化 `(Color32)color`，**不修改** `SimpleSolidColorMaterial` 的按色共享缓存材质（vanilla 自己会把共享材质写成 3600）。
  - 颜色/透明度、`Hidden`、`OverlayDrawHandler.ShouldDrawZones`（区域按钮开关）等既有行为全部沿用基类，不改观感参数。
- **Owner / Approver:** PersonalChronicle 维护者 / 项目负责人（2026-09-11 提出并要求置顶）
- **Expires:** 2027-08-15（或 RimWorld 主版本升级时复审）
- **Review trigger:** `Verse.SectionLayer_Zones` / `MapDrawLayer.DrawLayer` 渲染方式变化、`Zone.CreateMaterial` 队列值变化、RimWorld 主版本升级、第三方覆盖层 Mod 冲突报告
- **Evidence:** 权威编译 0 错 0 警；单测 212/212；发布区 dll 两区 SHA256 一致。**待实机验证**：车间与种植区/仓库区重叠时，车间琥珀覆盖层恒在最上层（移动相机/重载区域不改变结果）；关闭"区域显示"（`OverlayDrawHandler`）后车间覆盖层一并隐藏；角色/物品/UI 不被覆盖层盖住。
- **备注：** 本例外只解决**视觉叠放**。功能层面同一格在 `ZoneManager` 只归属一个 zone（`AddZoneGridCell` 后者覆盖 `zoneGrid`，但先者的 `cells` 仍保留该格 ⇒ 出现"两层都画"的现象）；若玩家把仓库/种植区压在车间之上，`ZoneManager.ZoneAt(cell)` 会返回后者的 zone，车间对这些格的 `WorkshopZoneUtility.WorkshopAt` 判定将失效 —— 属**功能口径**问题，不在本例外范围（另见车间体系遗留待办）。
