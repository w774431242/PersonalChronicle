# EXC-2026-005 — 车间归属改用"自持格集"判定（不依赖 zoneGrid 反查）（E1）

- **Status:** Approved
- **Level:** E1
- **Rule IDs:** ARC-005（Contract/API 边界：归属唯一入口 `WorkshopZoneUtility.WorkshopAt` 保持不变）, COMP-003（最小范围）
- **Scope:** `Source/PersonalChronicle/Automation/Zone_Workshop.cs`（`ownedCells` / `indexedCellCount` / `OwnsCell` / `AddCell`·`RemoveCell` 增量同步 / `ExposeData` 读档重建）、`Automation/WorkshopZoneUtility.cs`（`WorkshopAt` 两级判定）、`Automation/WorkshopManageView.cs`（`IsZoneAlive` 判据）
- **Reason:** 原版同一格只能由一个 zone 占据 —— `ZoneManager.AddZoneGridCell` 让**后圈定者覆盖** `zoneGrid`，**但先圈定者的 `cells` 列表仍保留该格**（于是重叠区出现"两层都绘制"，见 EXC-2026-004）。后果：玩家把仓库区/种植区压在车间之上时，`ZoneManager.ZoneAt(cell)` 对重叠格返回那些 zone ⇒ **一切"用 `ZoneAt` 反查车间"的代码失效**：设备归属 `WorkshopFloorViewProvider.BenchBelongsToBay`、岗位站位缓存校验 `MapComponent_WorkshopManager.GetDutySpot`、以及 `WorkshopManageView.IsZoneAlive()`（该项会把"首格被别的 zone 覆盖"误判成车间已死 ⇒ 管理弹窗自动关闭）。车间既要"兼容种植/存储等功能性 zone 嵌套圈定"，就必须**自持成员判定**。
- **Alternatives rejected:**
  - **禁止跨类重叠圈定**（设计器跳过已属其它 zone 的格）：把原版"后者覆盖"的语义改差，且玩家仍可用原版 zone 工具制造重叠（先在车间上画仓库），堵不住。
  - **只改 `WorkshopAt` 不加索引**：`Zone.ContainsCell` 是 O(cells) 线性扫描，设备扫描/岗位探测会反复查询；且 `IsZoneAlive` 的误判未解。
  - **维护 Map 级反向网格**（`Zone_Workshop[]`，与 `zoneGrid` 同规模）：每图多一个指针数组（400×400 ≈ 1.3 MB），收益只是省掉慢路径的"车间数 × O(1) 哈希"；车间数通常个位数，不值。
- **Risk:**
  - 与 vanilla"格子网格 = 归属"的口径**有意不同**：重叠格会同时存在于两个 zone 的 `cells` 中（两套逻辑并行；仓库区仍会照常在该格搬运/存储）。
  - 索引是**派生数据**：若将来出现"不走 `AddCell`/`RemoveCell` 的 `cells` 批量变更且计数恰好不变"，会短暂不一致（自愈：计数检查触发重建）。
- **Mitigation:**
  - **两级判定**：快路径仍走 `ZoneAt`（无重叠时的绝对权威、O(1)、行为与 vanilla 完全一致）；仅当网格没指向车间时才回退查自持格集。
  - 慢路径**倒序遍历 `AllZones`** ⇒ 最近登记者优先，贴近原版"后者覆盖 `zoneGrid`"语义。
  - 索引**不入存档**；`ExposeData` 的 `PostLoadInit` 强制重建（`cells` 由 Scribe 直接灌入，不会经过 `AddCell`）。不新增任何存档字段 ⇒ **无 Save 迁移**。
  - `AddCell`/`RemoveCell` 均由 Cecil 复核为 `callvirt` 派发（含主要路径 `Designator_ZoneAdd.DesignateMultiCell`、`Zone.Delete`、`Zone.CheckContiguous`、`ZoneManager.Notify_NoZoneOverlapThingSpawned`、`Designator_ZoneDelete`）⇒ 增量同步可靠命中；万一漏同步，计数不一致会在下次查询触发一次 O(cells) 重建（每次 zone 变更至多一次）。
  - 归属唯一入口不变（仍是 `WorkshopZoneUtility.WorkshopAt`），调用方零改动。
- **Owner / Approver:** PersonalChronicle 维护者 / 项目负责人（2026-09-11 批准"按推荐方案"）
- **Expires:** 2027-08-15（或 RimWorld 主版本升级时复审）
- **Review trigger:** `ZoneManager.ZoneAt/AddZoneGridCell` 语义变化、`Zone.cells` 不再公开、RimWorld 主版本升级、跨 Mod 区域重叠相关反馈
- **Evidence:** 权威编译 0 错 0 警；单测 212/212；发布区 dll 与开发区 SHA256 一致。**待实机验证**：① 先用车间圈地、再在其上叠画仓库区/种植区 ⇒ 区内设备仍被车间管理面板与俯视图识别（修复前必为 0）；② 首格被别的 zone 覆盖时管理弹窗**不再**自动关闭；③ 擦掉覆盖的 zone 后归属与统计仍正确；④ 存读档后归属一致（自持格集重建正确）。
