# EXC-2026-007 — `StatPart_MarketValue` 乘算叠加顺序风险（E3）

- **Status:** **Obsolete（2026-09-20）** —— 对象随 `CHG-LCE-001` 删除（`MVS_StatParts.xml` + `StatPart_MarketValue` 整体移除 ⇒ 原版 `MarketValue` 恢复原版口径）；原「风险接受」不再适用。
- **Level:** E3
- **Rule IDs:** COMP-004, EXC-002（衍生的顺序/叠加语义）
- **Scope:** `Patches/MVS_StatParts.xml` 给 `Defs/StatDef[defName="MarketValue"]/parts` 追加 `StatPart_MarketValue`（`<priority>-1000</priority>`）。
- **Reason:** 定价通道 A（默认通道）要求「价格动 ⇒ 财富动」且**零 Harmony**。XPath 挂子 `parts` + `StatPart` 是唯一零 Harmony 路径。
  IL 事实：`StatDef.PostLoad` 用 `SortBy(parts, x => -x.priority)` ⇒ **「链尾」不是天然属性，必须显式 `<priority>-1000</priority>`**。
- **Alternatives rejected:** 运行时 `parts.Add` —— **否决**：加载顺序不确定 + 静默、不可诊断。
- **Risk:** 本 part **乘算**（`val *= applied`），与**加算**型第三方 part（如 Pawnmorpher 的 `val +=`）混合时结果为 `(base + others) * applied`，**非交换**；若第三方亦用极负 priority，则并列致序不定。
- **Mitigation:**
  1. `priority=-1000` 锁定「我方最后执行」；
  2. 四道闸门（Def 注册 / 因子可用 / 作用域 / 重入）任一不过则 **不动 `val`**（而非赋 `1f`——语义更安全，等价于零影响）；
  3. `[ThreadStatic]` 深度计数守卫 + `try/finally` 成对，异常路径必回减（GATE-PERF 实测确认无永久封锁）；
  4. 只读权威因子表（`WorldComponent_Market`），**绝不反写 `MarketValue`**。
