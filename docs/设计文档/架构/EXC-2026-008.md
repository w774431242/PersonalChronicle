# EXC-2026-008 — 启动期三条 MUST 断言的 Tier 降级（E3）

- **Status:** **Obsolete（2026-09-20）** —— 对象随 `CHG-LCE-001` 删除（`ValidateMvsAssets` 及其三条断言整体移除）；「构建期编码校验」待办转列 `CHG-LCE-001` 变更标注，不再挂本 EXC。
- **Level:** E3
- **Rule IDs:** GOV-012, AI-009；`市场经济框架_v1设计方案.md` §12.5 三条交付 MUST 断言
- **Scope:** `Source/PersonalChronicle/ChronicleMod.cs` 的 `ChronicleStartup.ValidateMvsAssets`。
- **Reason:** 运行期**无可靠的 mod 目录磁盘枚举 API**，且启动期 I/O 会拖慢加载。§12.5 的三条断言中有两条只能降级实现。
- **Alternatives rejected:** 启动期全目录遍历 —— **否决**：性能代价 + API 不可靠。
- **Risk（两条断言覆盖不足）:**
  1. **断言②「`DefInjected/<短类型名>/` 恰好一层」未做磁盘枚举** —— `DefShortName == typeof(...).Name` 的比较是**编译期恒真**（类型名写错根本编译不过），属**走过场**；规格真正担心的「目录名解析不到类型 / 多一层目录」**完全未被覆盖**。
  2. **断言③「全目录 UTF-8」以 4 个探针 Key 查 `U+FFFD` 近似替代文件级校验** —— 能抓「已加载文件编码坏」，**抓不到**「目录里有 GBK 文件但该文件根本没被加载」。
  （断言①「Def 名一致性」`LabelCap != defName` **真实有效**，不属本例外。）
- **Mitigation:**
  1. 保留运行期探针（成本零 I/O，可抓已加载文件编码坏）；
  2. **构建期脚本**做全目录 `iconv -f UTF-8 -t UTF-8` 校验（待落地，见 GATE-REL 待办）；
  3. 断言② 改为扫 `ModContentPack` 的 `DefInjected` 路径深度（待落地）。
  > 备注：原版 `DefInjectionPackage.loadErrors` / `LoadedLanguage.anyDefInjectionsXmlParseError` **只覆盖 XML 语法错误**，不覆盖「目录名解析不到类型」或「字段路径写错」⇒ 上述断言不是冗余，降级后仍需构建期兜底。
- **Owner / Approver:** 主理人
- **Expires:** v1 发布前（构建期编码校验脚本落地后收窄）
- **Review trigger:** ① 构建期编码校验脚本落地；② 出现「翻译静默错位」类故障；③ 原版提供可用的 mod 目录枚举 API。
