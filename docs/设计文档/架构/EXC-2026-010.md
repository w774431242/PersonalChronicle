# EXC-2026-010 — `Automation/` 目录内业务类与 Presentation 类混放（分层归位定向豁免）（E1）

- **Status:** Approved
- **Level:** E1（形式归位豁免：**依赖方向本身未违规**，豁免的是"文件必须落在所属层目录"这一形式要求）
- **Rule IDs:** 08 册 §1.2（层 → 目录映射）· 09 册 §1（分层目录与 namespace 对应）
- **Scope:** `Source/PersonalChronicle/Automation/` 下的 Presentation 类（共 8 文件）：
  `WorkshopManageView.cs`（1364L）· `WorkshopRosterBoard.cs`（455L）· `WorkshopScheduleChart.cs`（286L）·
  `Dialog_WorkshopShiftEditor.cs`（285L）· `Dialog_RotationEditor.cs` · `Dialog_TimeRange.cs` ·
  `Dialog_WorkshopManage.cs` · `WorkshopHandoverBoard.cs`；
  以及 `Zone_Workshop.cs:627,635`（业务类直接 `is Dialog_WorkshopManage` / `new Dialog_WorkshopManage(this)`）。
- **Reason:**
  1. 依赖方向核查（2026-09-21 车间体系审计 §1.3）：Automation → Application / Domain / Data / `Archive.UI` 均为**允许方向**，无 `✕` 单元；违规的只是"文件落在所属层目录"的形式要求。
  2. `Zone_Workshop.GetGizmos` 直接 `new Dialog_…` 是**原版 `Verse.Zone` 家族的既有惯例**（原版 `Zone_Storage`/`Zone_Growing` 同样在业务类里开对话框）；强行拆分反而偏离原生模式。
  3. 真正的跨层风险（**Effects/Capture → Automation 直读内部实现**）已由同批修复 `CHG-SHOP-AUDIT-001 · A-1` 以契约化（`Application/Effects/WorkshopBonusAccess`）闭合 —— 混放的**危害面**已消除。
- **Alternatives rejected:**
  1. **物理切片 `Automation/UI/` + namespace 改 `PersonalChronicle.Automation.UI`** —— 须改全部引用点（Zone_Workshop / ITab_WorkshopManage / MasterControl 等），且业务类 `Zone_Workshop` 仍要引用 UI 类开 Dialog ⇒ 违约形态从"同目录"变成"显式 using"，**依赖图不减少、反而新增两条命名空间级边**；同时 `Archive.UI` 共享 UI 库的 using 面被双重扩大。收益（形式）不抵回归风险。
  2. **拆出独立 `Automation.UI` 层** —— 08/09 册的分层表未定义该层；新增层须同步依赖矩阵、Gate 清单、目录范式与全部下游文档，超出本批范围。
- **Risk:**
  - 归位原则出现一个具名例外，后来者可能误读为"允许跨层混放"。
  - `Automation/` 目录规模继续增长会掩盖真实分层（UI 与业务难区分）。
- **Mitigation:**
  - **限定条件（硬）**：本豁免**仅限** `Automation/` 子系统内部；`Effects` / `Capture` / `Application` 对 Automation 的访问**仍必须走契约**（`WorkshopBonusAccess` / `WorkshopRatingShift`），不得回退为直读。
  - **新增文件纪律**：本子系统**新增** UI 类一律放 `Automation/UI/` 子目录（目录细化，**不改 namespace** ⇒ 零引用改动）；本例外只为已存在的 8 个文件"免迁移"。
  - `WorkshopManageView` 的"内容层 / 宿主层"分离已落实（内容层 1364L 宿主无关；`Dialog_WorkshopManage` 仅 101L 作宿主；`ITab_WorkshopManage` 复用内容层）。
- **Owner / Approver:** PersonalChronicle 维护者 / 项目负责人（2026-09-21 批准 —— 用户指令「进入修复阶段，一次性处理完成」，方案二选一中裁决为登记豁免）
- **Expires:** 2027-08-15（或 Automation 子系统重构时复审）
- **Review trigger:** `Automation/` 目录继续膨胀（UI 类 >12 个）· 新增对 Automation 的跨层引用绕过契约 · 工程引入 `Automation.UI` 层定义 · RimWorld 主版本升级
- **Evidence:** `docs/设计文档/功能模块/车间体系/审计-车间体系-2026-09-21.md` §1.3（A-3）；依赖方向实测（`Application`/`MasterControl`/`Domain` 对 `PersonalChronicle.Automation` 类型引用 = 0）；修复批 `CHG-SHOP-AUDIT-001` 变更标注。
