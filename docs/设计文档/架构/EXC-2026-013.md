# EXC-2026-013 — 车间排班联动：把车间类型映射的原版工作提升到最高档（E2）

- **Status:** Approved（⚠ 部分被 **EXC-2026-015** 取代 —— 见下方「备注（2026-10-03）」）
- **Level:** E2（跨模块边界写原版玩家级状态 + 以例外二次收窄既有 SDD 反向约束；可回滚、不改本 Mod 的 Save schema）
- **Rule IDs:** GOV-005（跨模块通信/边界）· GOV-006（档位常量不得是魔法数字）· GOV-007（扩展点选型：不采用 Harmony/Patch）· PERF-001（仅事件驱动低频）· MATRIX-003（写入不得经 UI 层——限定条件）· UI-004（自动/隐式行为须有可见披露与出口）· EXC-001（例外管理）· AI-003（跳过方案记录）
- **Scope:** `Source/PersonalChronicle/Automation/MapComponent_WorkshopManager.WorkEnable.cs`（扩展现有写入单点）+ `WorkshopManageView`（触发与**披露 UI**）+ 既有 Def 映射数据。**只改档位目标值，不新增写入对象类型**：

  1. **`Pawn_WorkSettings` 档位提升** —— 把 `EXC-2026-012` 的 `0 → DefaultPriority(3)` 在**车间类型 Def 映射的原版工作类型**上改为 **`→ 最高档 1`**（脚本：`GetPriority(wt) != 1` ⇒ `SetPriority(wt, 1)`；含 `0→1` 重开与 `2/3/4→1` 覆盖）。`wt ∈ {Defs/WorkshopTypes.xml 的 *WorkTypeDefNames}`（Cooking / Smithing / Tailoring / Crafting / Art / Research / PlantCutting / Construction）。
  2. **值勤类型不参与提升** —— `PC_WorkshopOperation` 仍按 `EXC-2026-012` 执行「仅 Enable（`0 → 3`）」。依据 `Defs/Automation_WorkType.xml:9-19`：值勤被顶到最高会重现「成员一直站着值勤、不去干活，产出加成链不可达」的 P0 反模式。
  3. **简单模式守卫** —— `!Find.PlaySettings.useWorkPriorities` 时**不做档位写入**（写了引擎也不读）：降级为「仅 Enable（`0 → 3`）」并保证启用。**不自动改写该全局设置**（见 Alternatives rejected 5 / Risk 1）。

  **触发时机（硬约束，沿 012 口径）**：排班/班次/班组/成员变更事件（`WorkshopManageView.OnRosterChanged`）+ 打开管理面板对账一次（`Refresh`）。**禁**每 tick、**禁**绘制路径、**禁** JobGiver 内写。

- **Reason:**
  1. 用户需求（2026-10-02，两次）：「按车间类型自动分发原版的 work，也就是将**车间工作优先度最高**」。`EXC-2026-012` 的「仅 Enable、不改档」只让工作**参与排队**，不满足「最高」。
  2. 静态取证（反编译实证，RimWorld 1.6.4871 rev590）：`Pawn_WorkSettings.CacheWorkGiversInOrder` 的排序键 = `naturalPriority + (4 - GetPriority(wt)) * 100000` —— 每档权重 10 万，远大于任何 naturalPriority（最大 1400）⇒ **设为 1 必定排到最前**，这是达成「最高」的唯一原版途径。
  3. 原版工作类型在简单模式下的 naturalPriority 实测（1.6 Core）：建造 900 · 种植 700 · 采矿 600 · 砍伐 500 · 锻造 470 · 缝纫 450 · 艺术 430 · 制作 400 · **[值勤 350]** · 搬运 300 · 清洁 200 · 研究 100 ⇒ 车间生产/研究工作长期排在杂务之后，与用户观察到的「不生效/闲置」一致。
  4. `Pawn_WorkSettings.EnableAndInitialize` 对新殖民者**只启用前 6 项**（`MaxInitialActiveWorks = 6`，按技能排序）⇒ 车间需要的工作类型在新 pawn 身上常处于关闭态，必须与档位一并处理（重开语义沿 012）。
  5. 既有 SDD 反向约束（`Pawn自驱力框架_经济驱动的应用配置.md` §5.4/§7；`原版工作系统性能成本分析_2026-09-10.md` W8）须**二次收窄适用面**；`EXC-2026-012:9` 明文排除档位变更，故不得原地扩围，另立本记录。
- **Alternatives rejected:**
  1. **修改原版 `WorkTypeDef.naturalPriority`** —— 这是简单模式下唯一有效的排序途径，但目标是**原版共享 Def**，一改则全局所有 pawn 在所有场景都受影响，且属"完整覆写原版 Def"（AI-004 禁止）。否决。
  2. **为每个车间类型复制一套 WorkTypeDef / WorkGiverDef** —— 需重写原版 bill 扫描逻辑，工程量与回归面远超收益。否决。
  3. **Harmony 补丁 `Pawn_WorkSettings.GetPriority` 绕过简单模式短路** —— 引入 Harmony（风险升级）、改原版核心取数语义。否决。
  4. **用 `mindState.priorityWork`（原版强制优先）** —— 仅 `emergency` 分支消费、需 `WorkGiver` + 目标 `Cell`、语义为"玩家强制"（`JobGiver_Work.cs:59-80`）；车间值勤是无目标 `NonScanJob`。否决。
  5. **自动改写全局设置 `PlaySettings.useWorkPriorities`** —— 影响面为**全存档全部玩家 pawn**、随存档持久化、且被本 Mod 反复重放（玩家无法持久否决）⇒ 命中 E3「不可回滚 + 全局性改写」域，须负责人显式批准。**本记录不采用**；改为「UI 常驻状态行 + 一键开启按钮」，由玩家主动触发（写入仍落 Automation 层）。否决（保留为可选升级路径，需另行登记 E3）。
  6. **把值勤类型也提到最高（含抬高其 naturalPriority）** —— 复现 012 已记载的 P0 反模式。否决。
- **Risk:**
  - **覆盖玩家档位意图**：`2/3/4 → 1` 会覆盖玩家手动排序；`0 → 1` 会重开玩家显式关闭的工作（该语义自 012 起已存在，本记录只改目标值）。缓解：仅作用于 Def 映射内的原版类型；值勤类型不提升；`WorkTypeIsDisabled` 守卫；幂等；面板披露 + 玩家可随时手动改回（下次排班结构变更会再次收敛）。
  - **简单模式下的"看起来没生效"**：引擎在该模式不读档位（`GetPriority` 恒返回 3）。缓解：**不做无意义写入**（守卫）+ 面板常驻状态行 + 一键开启出口。
  - **与优先级类 Mod 冲突面扩大**：012 的"不重排、不改档"承诺在本记录范围内失效（仅对映射内的原版类型）。缓解：范围限定 + COMP 门复核 + 面板披露。
  - **工作链重建成本**：`SetPriority` 置该 pawn 的 `workGiversDirty`（`Pawn_WorkSettings.cs:181-182`）。缓解：仅事件驱动、幂等（已是目标档不写）、只对排班相关 pawn。
  - **多图/多车间重复触发**：同一 pawn 被多车间映射覆盖时可能重复写。缓解：幂等吸收；同档内排序由 naturalPriority 决定（行为可预期）。
  - **原版行为随版本变化**：`GetPriority` 的简单模式短路 / 排序键权重 / `MaxInitialActiveWorks` 若在新版本变更，本记录前提失效。
- **Mitigation:**
  - **硬性限定**：仅 `Defs/WorkshopTypes.xml` 映射声明的**原版** WorkTypeDef；值勤类型不提升；仅排班相关人员（班组成员 / 未编组时的车间名单 / 班次显式候选池）；仅事件 + 打开面板对账触发；禁 tick / 绘制路径 / `Disable` / 重排。
  - **守卫**：`workSettings != null` → `EnableAndInitializeIfNotAlreadyInitialized()` → 跳过 `pawn.WorkTypeIsDisabled(wt)`（原版对 disabled 写非 0 会 `Log.Error`）→ `useWorkPriorities == false` 时不做档位写入。
  - **档位常量**：`1` 写成命名常量 `TopWorkPriority`（原版 `Pawn_WorkSettings` 无 `HighestPriority` 常量，最高档即 1）。
  - **写入单点**：全部写入（含未来的全局设置翻转）只在 `MapComponent_WorkshopManager`；UI 只发命令、只读状态（MATRIX-003 / UI-003）。
  - **披露与出口（UI-004 硬要求）**：车间管理面板「设置」页常驻状态行（手动模式 / 简单模式），简单模式下提供「开启手动优先级」按钮（玩家点击才改，镜像原版 `MainTabWindow_Work.cs:69-78` 的写法与通知口径）。
  - **可观测性**：映射 defName 解析失败按 defName 只告警一次（沿 012）；正常档位写入不写日志（每次排班变更都会发生，记日志只污染 Player.log）。
  - **回滚**：撤销代码即止写；无本 Mod Save schema 变更（`PlaySettings.useWorkPriorities` 是**原版**持久字段，若玩家点击开启则随原版存档保存，卸载后残留 `true`，可在原版工作面板左上角关闭）；玩家随时可手动改回任一档位。
  - **回归证据（批准条件之一）**：手动优先级模式下映射工作显示为 `1` 且优先去做 · 非排班人员零变化 · 映射外工作类型零变化 · 值勤类型仍为 `3` · 简单模式下无档位写入且面板显示提示 · 无 tick / 绘制路径写入。
- **Owner / Approver:** PersonalChronicle 维护者 / 项目负责人（2026-10-02 批准 —— 用户以「按车间类型自动分发原版的 work，也就是将车间工作优先度最高」显式授权**档位提升**；「自动改写全局『手动优先级』设置」一项已按本记录 Alternatives rejected 5 改为**玩家点击触发**，不在自动行为范围内）
