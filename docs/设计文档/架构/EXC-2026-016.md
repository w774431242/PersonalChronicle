## 背景

Phase 1（`CHG-20261003-POSTS`）已建立「按现实规模化工厂划分的岗位标准表」与岗位自动分配器，
但**只读展示**，不动任何原版工作。本 EXC 授权 Phase 2 的接管写入。

玩家诉求原文：「将原版的工作全部 copy 一份进入车间体系，然后车间自动划分岗位，
当然加入车间的 pawn 从原版工作面板中移除。」

## 授权范围（A）

> **2026-10-04 修订（CHG-20261004-AUTOHIDE · 玩家口径「加入车间即隐藏、只保留车间类型」）**
>
> - **触发面**：由「仅玩家点击面板按钮」扩为「**随排班/名册变更自动触发**」
>   （入口 `WorkshopManageView.OnRosterChanged` → `SyncVanillaWorkTakeover`；
>   该调用点本就存在，缺的是与自动隐藏的一致口径）。
> - **作用域**：由「该车间**在编班组成员**」扩为「该车间**全体成员 = 人员名单 ∪ 班组编制**」。
>   修订理由：玩家只把人放进"车间人员名单"而未编班组时，旧实现**既不接管也不隐藏**，
>   表现为"加了车间却没反应"。
> - **自动隐藏**：同一事件入口同时把全体成员写入【工作】面板隐藏名单
>   （`MapComponent_WorkshopManager.SyncAutoHideWorkTabColonists`），
>   与接管共用同一份成员并集 ⇒ 不会出现"被隐藏却仍在原版工作"的分叉状态。
> - 下列三道闸门与硬红线**全部保持不变**，仍逐条生效。

允许在**玩家主动点击面板按钮后，或随排班/名册变更自动**触发时，对**该车间全体成员**执行
`Pawn_WorkSettings.SetPriority(type, 0)`（取消勾选），且必须**同时**满足：

1. **fail-closed**：空 `defName` 一律拒绝。
2. **硬红线**：`Hauling` / `Cleaning` / `Doctor` / `Firefighter` **永不接管**
   （`WorkshopTakeover.MandatoryKeep`）。
3. **能力对等**：只有 `WorkshopPostDef.deliversOwnService = true` 的岗位所承接的工作类型可接管。
4. **强制兜底**：接管后本图仍须留有 `MinFreeWorkers`（=1）名自由工人，否则**整次拒绝**。
5. 该工作类型当前**已被勾选**（`GetPriority > 0`）；玩家本来就没勾的不认领。
6. `pawn.WorkTypeIsDisabled(type)` 为真时跳过（原版对这类类型写档位会 `Log.Error`）。

## 禁止范围（F）

- **F1** 不得对 `MandatoryKeep` 四项做任何写入。
- **F2** 不得在**未达能力对等**时接管（"接管了但车间没人能做" = 净损失）。
- **F3** ~~不得在**自由工人下限不满足**时接管~~ —— **2026-10-03 降级为「提示」**：
  实机发现该闸门造成 **100% 误拒**（3 人全部进车间 ⇒ 自由人 = 0 ⇒ 每次整次拒绝，
  而"全员进车间"恰是本功能的目标用法 ⇒ 原版工作面板毫无变化）。
  且它在硬红线面前是**重复保护**：`MandatoryKeep`（搬运/清洁/医疗/灭火）永不接管
  ⇒ 任何殖民者永远还剩 4 项工作 ⇒ **死锁在数学上不可能发生**。
  现改为记录 `LastTakeoverShortfall` 并在 UI 如实提示，**不阻塞接管**。
  真正的死锁条件应是"某人接管后一项工作都不剩"，硬红线使其恒不成立。
- **F4** ~~不得**自动触发**：本操作**只能**由玩家点击面板按钮发起~~ —— **2026-10-03 修订**：
  玩家的原始诉求是「**加入车间的 pawn 从原版工作面板中移除**」，而「默认关闭 + 手动点」
  在实机被判定为"没隐藏"（用户连续两轮反馈）。现授权**随排班/名册变更自动接管**
  （挂在既有的 `WorkshopManageView.OnRosterChanged` 路径上，**不新增触发点**）。
  **仍然禁止**：tick / 绘制路径 / 读档副作用触发。自动触发**幂等**（已为 0 的跳过、台账首记优先），
  且拒绝原因（硬红线 / 自由人兜底不足）静默跳过，玩家要看原因可手动点「接管」按钮。
  **一键解除出口不变**，且必须始终可用。
- **F5** 不得还原**玩家自己改动过**的档位：还原闸门要求「当前仍为 0」且「原值 ∈ 1..4」。
- **F6** 不得与降档台账混用（见下）。

## 与降档台账必须分账（关键）

`workshopWorkDemotion`（降档）把档位写成 **4**，其还原闸门是「当前值**仍为 4** 才还原」；
本 EXC 的接管写成 **0**，会被降档闸门判为「玩家已改动」而**丢弃且永不还原**。
⇒ 两者语义互斥，**必须独立台账** `workshopWorkTakeover`，还原闸门为「当前值**仍为 0**」。

## Alternatives rejected

1. **不设兜底**（沿用 Phase 0「不设兜底」裁决）—— **拒绝**。那次针对"降档"（仍勾选、仍可做），
   本次是"取消勾选"（彻底做不了）。全员进车间 + 原版全禁 ⇒ 殖民地**连取消勾选这个自救动作都做不到**
   （没人能去做）。已由单测 `FreeWorkerFloor_RejectsWhenEveryoneIsInWorkshop` 钉死。
   （⚠ 2026-10-05：其中的"降档"对照组已随降档通道移除而失去现实对应，本条的**结论不受影响**。）
2. **一次性 fork 出车间专属 WorkTypeDef**（用户字面说的"copy 一份"）—— **拒绝**。
   等于 fork 整个工作系统（30+ `WorkGiver` 需重绑/重写），原版一升级就漂移，
   风险高一到两个数量级。改用"岗位声明 `coveredWorkTypeDefNames` 映射原版"。
3. **接管 + 自动兜底工作**（车间自己保证有搬运工）—— **推迟**。当前阶段车间尚无送料 Job
   （`WP_MaterialHandler.deliversOwnService = false`），先靠硬红线保护，待送料 Job 落地后再评估。
4. **全局开关式接管**（改设置项，一键接管全图）—— **拒绝**。作用域过大、粒度不可控；
   改为**按车间 + 玩家逐次点击**。
