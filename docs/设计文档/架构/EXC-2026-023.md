- **状态:** Approved
- **提出:** 2026-10-04（实机红字：`MapComponent_MealSchedule.ApplyToAll` 抛 `NullReferenceException`）
- **关联变更:** CHG-20261004-MEALSCHEDULE-C
- **风险等级:** **E1 低**（把一个**抛异常的空实现**改为不执行；不新增数据写入面）
- **触发 Architecture Review:** 是（Harmony = Yes）

## 背景

1.6 中 `Pawn_WorkSettings.SetPriority(WorkTypeDef, int)` 的 IL（实测）末段是：

```
priorities.set_Item(w, priority);
workGiversDirty = true;
if (priority != 0) return;
pawn.jobs.Notify_WorkTypeDisabled(w);     // ← priority == 0 分支必经
```

而 `Verse.AI.Pawn_JobTracker.Notify_WorkTypeDisabled(WorkTypeDef)`（public instance void）
在 1.6.4871 里是**未实现桩**：方法体抛
`System.NullReferenceException: The method or operation is not implemented.`

⇒ **任何把单个工作类型档位清零（`SetPriority(w, 0)`）的调用都会抛异常。**

实机证据（`Player.log`）：

```
Exception in Verse.AI.PawnJobTracker: System.NullReferenceException: The method or operation is not implemented.
   at Verse.AI.PawnJobTracker.Notify_WorkTypeDisabled()
   at Verse.Pawn_WorkSettings.SetPriority(WorkTypeDef w, Int32 priority)
   at PersonalChronicle.Automation.MapComponent_MealSchedule.ApplyToAll()
```

影响面不止三餐作息：**车间接管通道与降档还原同样使用 `SetPriority(x, 0)`**，此前也会抛同一异常。

> ⚠ **2026-10-05 修订（`CHG-20261005-NODEMOTE`）**：上句中的"**降档还原**"用词**有误且已过时** ——
> 降档还原写的是 **4**（`LowestPriority`），不是 0；且该通道已被玩家裁定整体移除
> （`EXC-2026-015` Status → Superseded）。**当前的准确表述是**：本 Mod 中会调用
> `SetPriority(x, 0)` 的**只剩接管通道**（`TakeOverVanillaWork` / `ReleaseVanillaWork` 的还原路径），
> 二者同样受本 EXC 的异常修复覆盖（`Notify_WorkTypeDisabled` 短接）。
> 本修订只更正描述，**不改变本 EXC 的结论与实现**。
>
> ⚠ **2026-10-05 二次修订（`CHG-20261005-SETTINGS-REMOVE2`）·"只剩"亦不准确**：
> 上句「`SetPriority(x, 0)` 的**只剩接管通道**」遗漏了**离班停工链**
> （`MapComponent_WorkshopManager.OffShift.cs` → `DisableForCrew`），它自 `CHG-20261005-OFFSHIFT`

> 离班停工链（**已补登记 `EXC-2026-026`，E2**）。
> 两者都走同一 `SetPriority` 路径 ⇒ **同样受本 EXC 的异常修复覆盖**（结论不变）。

## 已排除的替代方案

| 方案 | 排除原因 |
|---|---|
| 改用 `Pawn_WorkSettings.Disable(w)` | 其 IL 就是 `SetPriority(w, 0)`，同一路径 |
| 改用 `DisableAll()` | 它会 `priorities.SetAll(0)` 清掉**全部**工作类型档位，绝不能用于"只清一个" |
| 反射直写 `priorities`（private `DefMap`） | 绕过公开 API 写玩家核心数据，违反 GOV-007「先用原生扩展点」，且需长期维护私有字段名 |
| **Harmony 把桩补成 no-op** | ✅ 选中：改动面最小、语义正确、连带修好所有同路径调用点 |

## 授权范围（A）

允许 `Prefix` 跳过 `Pawn_JobTracker.Notify_WorkTypeDisabled` 的原版方法体（桩），使其成为
**真正的 no-op**，不新增任何数据写入。

## no-op 为何是正确语义（不是掩盖问题）

- 该方法原意是"工作类型被禁用 ⇒ 中断正在跑的相关 Job"。1.6 引擎自身留成桩，
  说明它**没有走这条路径**（否则玩家每手动取消一个工作类型都会崩）。
- PC 的产品语义是**不打断正在跑的 Job**（餐段到点只影响"下一个 Job"的选择）⇒ 与 no-op 一致。
- 补全后，**玩家在工作面板手动取消勾选**同样不再触发红字（该路径也走 `SetPriority(x,0)`）。

## 硬约束

1. 仅 `Prefix` 返回 `false` 跳过，**不得**改写 `SetPriority` 本体或 `priorities`。
2. 不得借此补丁改变任何**启用**路径（`priority > 0`）的行为。
3. 调用侧仍保留 `try/catch` 兜底（`MapComponent_MealSchedule.ApplyToAll`），
   使"将来出现别的抛异常路径"不会中断整批写入、也不刷屏。

## 回滚

删除 `Source/PersonalChronicle/Capture/Patch_PawnJobTracker.cs` 即可完全回滚，
无存档字段依赖。
