# EXC-2026-024 · 为自定义时段类型补 `JobGiver_Work.GetPriority` 优先级

- **状态:** Approved
- **提出:** 2026-10-04（实机红字：用餐时段生效后每帧 `ThinkNode_PrioritySorter GetPriority` 抛 `NotImplementedException`）
- **关联变更:** CHG-20261004-MEALSCHEDULE-D
- **风险等级:** **E2 中**（改动"工作链取 Job 的优先级数值"，但仅在原版**会抛异常**的分支生效）
- **触发 Architecture Review:** 是（Harmony = Yes）

## 背景

`RimWorld.JobGiver_Work.GetPriority(Pawn)` 把时段类型**硬编码**为 5 个分支，末行是
`throw new NotImplementedException()`（Build 1.6.4871 IL 实证）：

| 时段 | 优先级 |
|---|---|
| `Anything` | 5.5 |
| `Work` | 9 |
| `Sleep` | 3 |
| `Joy` | 2 |
| `Meditate` | 2（仅 Royalty） |
| **其他任何 `TimeAssignmentDef`** | **抛异常** |

PC 的「用餐」时段（`PC_Meal`）是第 6 种 ⇒ 玩家把某小时涂成「用餐」后，
`pawn.timetable.CurrentAssignment` 即为它 ⇒ **工作链每次排序都抛**。

实机表现：`Player.log` 每帧一条
`Exception in Verse.AI.ThinkNode_PrioritySorter GetPriority: System.NotImplementedException`。
该异常被 `ThinkNode_PrioritySorter.TryIssueJobPackage` 内的 try/catch 吞掉并**按优先级 0 处理**
⇒ 不崩溃但工作节点被降权，工作链决策被静默劣化。

## 授权范围（A）

允许 `Prefix` 在 `JobGiver_Work.GetPriority` 之前判定：若当前时段**不是**原版 5 种之一，
则直接给出结果并跳过原方法。

| 情形 | 优先级 | 理由 |
|---|---|---|
| 原版 5 种时段 | 放行（`return true`） | 行为逐字不变 |
| `PC_Meal`（用餐） | **9**（= Work） | 是"该时段要执行的正事"，且 PC 餐段规则靠它驱动 `PC_MealBreak` 档位 |
| 其他未知时段（其他 mod 后续新增） | **5.5**（= Anything） | "可工作、优先级中性"，最不改变原版行为的兜底 |

## 硬约束

1. **Prefix only**：不得改写原方法体（异常路径下 Postfix 根本不会执行）。
2. `pawn == null` / `workSettings == null` / `timetable == null` **一律放行**，
   保留原版的优先级 0 出口（`EverWork` 为假等语义）。
3. `TimeAssignmentDefOf.Meditate` 仅 Royalty 激活时非 null ⇒ 比较必须 null-safe。
4. 不得在本补丁中改变**启用/禁用**任何工作类型（那是 `Pawn_WorkSettings` 的职责）。

## 已排除的替代方案

| 方案 | 排除原因 |
|---|---|
| 放弃「用餐」时段类型（回到只有 Work 表一列） | 用户明确要求作息表里可划"吃饭"时段；且不修则**任何 mod 新增时段类型都会踩同一个坑** |
| 给 `ThinkNode_PrioritySorter.GetPriority` 补 no-op | 那是 `JobGiver_Work.GetPriority` 的调用点之一，异常在**被调方**；补错层 |
| 捕获并吞掉异常（Postfix/try） | 异常在原方法内抛出，Postfix 不执行；且吞掉后优先级恒为 0，反而更糟 |

## 回滚

删除 `Source/PersonalChronicle/Capture/Patch_JobGiver_Work_GetPriority.cs` 即可完全回滚，
无存档字段依赖。

## 验证

- 编译 0 错 0 警。
- 静态取证：`JobGiver_Work.GetPriority` 的 5 分支 + `throw`。
- **实机待验证**：把某小时涂成「用餐」并等到该小时，Debug log 不应再出现
  `PrioritySorter GetPriority` 异常，且该时段殖民者仍能正常被分配工作。
