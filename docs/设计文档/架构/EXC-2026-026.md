## 2. 授权范围（A）

允许在**既有 60-tick `MapComponentTick` 的内层「游戏小时变更」门控**下（每游戏小时最多一次），
对**离班**班组成员在**班次覆盖的工作类型**上调用 `Pawn_WorkSettings.SetPriority(wt, 0)`，
且必须**同时**满足：

1. **触发路径受限**：只允许挂在 60-tick tick 链上，由小时变更做内层门控；**不得**在绘制路径、
   读档副作用、或每 tick 路径触发。
2. **仅限已指派班次的班组**：`crew.AssignedShifts` 非空（未指派班次的班组本链完全不动作）。
3. **仅限"离班"状态**：当前游戏小时**不在**该班组**任一**已指派班次的时间窗内
   （`Domain.WorkshopTime.InRange`，左闭右开、`start == end` = 全天、跨午夜）。
   **在班时本链不写任何值**——在班档位由既有的 `EnableWorkTypes` / `SyncVanillaWorkSettings` 承担。
4. **写入范围封闭**：严格等于
   `shift.TargetZone.WorkshopType.WorkTypeDefNamesOf(shift.TaskType)` **∪** `{PC_WorkshopOperation}`
   （后者是值勤工作类型）。不得写入该集合以外的任何工作类型。
5. **幂等**：只写当前 `GetPriority(wt) > 0` 的类型；已是 0 的跳过。
6. **必须做 M1 退让**：写 0 **之前**先 `ChronicleGameComponent.DemotionLedger.Discard` +
   `DiscardTakeover`。理由：接管闸门是「当前值仍为 0 才还原」⇒ 若写 0 后台账仍有记录，
   玩家点「解除接管」会把档位还原成 X，即**离班期间被重新启用**（错的）。退让后台账无记录 ⇒ 误还原不可能。
7. **跳过不可用对象**：`pawn == null || pawn.Dead || pawn.workSettings == null`。

## 6. 可逆性与降级

- **部分可逆**：把某人移出班组 / 删除班次指派 ⇒ 下一次小时门控后本链不再对他写 0。
  但**已经写下的 0 不会被本链还原** —— 还原由互补链承担：
  在班后 `EnableWorkTypes` / `SyncVanillaWorkSettings` 写回（值勤 3 / 映射类型 1）。
  ⚠ **若某班组被整体删除指派，其成员档位会停在 0**（无自动还原）——玩家需在工作面板手动勾回。
  这是取消退出权后的已知代价。
- **降级**：`map == null` ⇒ 直接返回；无 `ChronicleGameComponent` ⇒ 返回；无车间 / 无班组 /
  班组无指派班次 / 该班次无 `WorkshopType` ⇒ 该层 `continue`（不抛异常）。
- **fail-closed**：写入集合取不到（`names == null`）时，`managed` 只剩 `PC_WorkshopOperation`
  ⇒ 只可能影响值勤类型，不会误伤其它工作类型。

## 7. 已知代价

1. 不喜欢"离班即停工"的玩法**无法再通过设置关闭**（原退出权已按 PM 裁决移除）。
2. **未做 `MandatoryKeep` 显式守卫**（F1 为 Def 级软约束），属**间接保护**，已如实登记；
   建议后续补一个显式守卫以把 F1 从"约束"升级为"代码保证"。
3. 写 0 会置该 pawn 的 `workGiversDirty`（工作链重建成本，与 EXC-2026-012/013 同性质）；
   缓解：只在小时变更时跑一次、只写当前 > 0 的类型、只写封闭集合内的类型。
