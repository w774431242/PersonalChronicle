## 1. 事项 A：`Patch_PowerNetTick`（P3）

### A.1 目标与方法

| 项 | 值 |
|---|---|
| 目标方法 | `RimWorld.PowerNetManager.PowerNetsTick()`（**`public` 无参**，Cecil 实证）—— ⚠ **2026-10-07 实装期变更，原为 `PowerNet.PowerNetTick()`** |
| 补丁类型 | **Harmony Prefix**，返回 `false` 等价于 `__runOriginal = false` |
| `HarmonyId` | 统一前缀 + 独立子 ID（`GOV-007`；**不得** `UnpatchAll`） |
| 文件 | `Source/PersonalChronicle/Capture/Patch_PowerNetTick.cs` |

**★ 挂点变更的理由（实装期发现，已 Cecil 取证）**：`PowerNetsTick` 的**全部内容**就是一个转发循环
（`for (i...) allNets[i].PowerNetTick();`，IL 仅 40 行）⇒ 接管它**不丢失任何原版行为**，且带来三点实质好处：
① **性能** —— `MapComponent_PowerGridSim` 的查找从「每 net 每 tick」降为「每 tick 一次」；
② **粒度对齐** —— 安全阀判据（本图分段设备数 / 优先级覆盖 / 定值修改）**本来就是 map 级**；
③ **锁存可行** —— 整图接管必须配整图锁存：若按 per-net 锁存，「被锁存的那张网」会**没有任何人 tick 它**
（我们 `return false` 后原方法整段不跑），而「自行调用原方法」被 `SDD` §5.3 明令禁止。
**代价（知情接受）**：接管期间第三方挂在 `PowerNet.PowerNetTick` 上的补丁不执行 ——
这正是「接管」的语义；缓解靠让位出口②（`letGoCached`）。

### A.2 理由（为什么非 Harmony 不可）

原版 `PowerNetTick` 内**硬编码**了甩负荷逻辑（每 20 tick 随机关掉全网 `max(1, RoundToInt(count × 0.05))` 台耗电设备，IL_018A–IL_024E）。`AI-003` 风险升序的前 5 级（原生 Def / DefModExtension / Comp / Service / Provider / PatchOperations）**均无法替换**该硬编码行为 —— 没有任何 Def 钩子或可注册服务点存在。⇒ 只能 Prefix 接管。

**被跳过的方案（`GOV-007` / `AI-003` 要求记录）**：

| 被跳过方案 | 结论 | 原因 |
|---|---|---|
| 不接管（保留原版随机 5%，仅观测/告警） | ❌ 否决 | `REQ-Grid-012` 的目标就是**取代**随机甩负荷；PM 裁决 #7 已定「默认接管」 |
| 只挂 Prefix 不设 `__runOriginal = false` | ❌ 否决 | 原版随机 5% 仍在跑 = **等于没做**，且形成双重随机（Power Priority 的坑） |
| Harmony Transpiler | ❌ 否决 | 不可回滚；上游用「第 N 个 call」定位极脆 |
| 强转自有 `PowerNet` 子类 | ❌ 否决 | 第三方 `new PowerNet` 即 `InvalidCastException`（Battery Overhaul 的坑） |

### A.3 授权范围（A）

仅允许在 `PowerNetTick` 的 **Prefix** 内、**安全阀为假**（即接管生效）时，**1:1 重建原方法的两条分支**：

1. **分支实为三条**（`SDD` §5.3 修正三）：
   - **A₁ 盈余/中性**：收集 `!PowerOn && FlickUtility.WantsToBeOn && !IsBrokenDown` 的设备；按 `max(30, 200 / count)` 节流，`TicksGame % V == 0` 时开启 `max(1, RoundToInt(count × 0.05))` 台；每开一台须满足 `gain + stored + EnergyOutputPerTick + 1e-07 ≥ 0`；**末尾调用 `ChangeStoredEnergy(CurrentEnergyGainRate() 原值)`**。
   - **A₂ 轻度缺口**（`V_2 + V_0 < 0`，`V_2 = (电池数>0 && stored ≥ 0.1) ? stored − 5 : stored`）：**只调 `ChangeStoredEnergy`，不开关任何设备**（**E′**）。
   - ⚠ **`ChangeStoredEnergy` 的入参必须是 `CurrentEnergyGainRate()` 的★原值（单位 Wd/tick）**——**不得**传 `NetWatts`（那是 `PowerGridReading.NetWatts` 的输出，**单位 W、已除以 `WattsToWattDaysPerTick`，与原值差约 60000×**，误传会导致**能量虚增**，恰是 D′ 要防的失效）。
2. **缺电分支**（`stored + gain < -1E-07` **或** `ElectricityDisabled`）：
   - `TicksGame % 20 == 0` 时收集 `PowerOn && EnergyOutputPerTick < 0` 者；
   - 按**负载优先级降序 + 瓦数降序**有序关停（取代原版随机）；
   - **不得**调用 `ChangeStoredEnergy`（与原版一致）。
3. **必须尊重 `Map.gameConditionManager.ElectricityDisabled(map)`**（太阳耀斑）。
   ⚠ **取证修正（2026-10-07）**：它是**方法**（`public bool ElectricityDisabled(Map map)`），
   不是属性 —— 原版 IL 里以 `callvirt` 带一个 map 参数调用（IL_0026–002C）。
   照属性写会**编译失败**（这是好消息：立刻暴露；坏消息是它说明「照着感觉写 IL」不可靠）。

### A.4 禁止范围（F）

- **F1** ⚠ 安全阀为真时**不得**接管 —— 必须 `return true` 让原版完整执行。
- **F2** 安全阀判据必须 **≤ O(1)**（内存读）；**不得**扫 `listerThings` / `powerComps` 全表。
- **F3** **不得复用** 原版 `static` 暂存表 `PowerNet.partsWantingPowerOn` / `potentialPowerOnParts` / `potentialShutdownParts`（第三方可能同时使用）⇒ 自建实例态缓冲。
- **F4** **不得**在缺电分支调用 `ChangeStoredEnergy`（会与原版语义分叉）。
- **F5** 替代逻辑抛异常时**不得**静默：必须记一次结构化 Warning 并**回落原版逻辑**（`SDD` §5.3）。
- **F6** **零 Transpiler**；不得 `UnpatchAll`。
- **F7** 不得在 Prefix 内做**运行期**反射调用（`GATE-PERF` 热路径红线）。
  ⚠ **豁免（2026-10-07 实装期登记）**：`PowerNet.ChangeStoredEnergy(float)` 是 **`private`**（Cecil 实证
  `[private] Void ChangeStoredEnergy(Single extra)`）⇒ 存能面（D′）**无法直接调用**。
  允许在**静态构造期绑定一次委托**（`Automation/PowerNetEnergyWriter.cs`），运行期只走委托（零反射）。
  **绑定失败 ⇒ 整个接管让位**（`Available == false` ⇒ Prefix 直接 `return true`）：
  「接管而不写存能」会造成**电池冻结**（无报错、无视觉异常），代价远大于退回 vanilla 甩负荷。
  被否决的替代：运行期 `MethodInfo.Invoke`（违反 F7）；用公开 API 复刻（充电路径要复刻同样是 private 的
  `DistributeEnergyAmongBatteries`，偏差会静默改变电池行为）。

### A.5 安全阀精确谓词（**两条"走原版"出口**）

> **⚠ 实装期更新（2026-10-07 · `CHG-20261007-GRIDP3B`）**：三出口的**位置**已调整 —— 出口①（零配置）与出口③（整图锁存）留在宿主 `MapComponent_PowerGridSim.ShouldYieldPowerNetTick()`；**出口②（让位）移到 `Capture/Patch_PowerNetTick.Prefix`**。
>
> **原因**：宿主属 Runtime/Data 侧，而兼容层探测在 `Compatibility` —— `SDD` §3.2 的依赖图**没有** `Runtime → Compatibility` 这条边；`Capture → Compatibility` 是外层内聚方向，不引入新跨层依赖。
>
> **同处还有第四个前置检查**：`PowerNetEnergyWriter.Available`（存能面绑定失败 ⇒ 绝不接管，见 A.4 F7 豁免）。
>
> **兼容层已实装**（§7.1.4 三件）：`Compatibility/PowerMods/PowerModDetector.cs`（纯逻辑、零副作用、可离线测）/ `PowerModAdapter.cs`（只读能力位）/ `PowerModDiagnostics.cs`（结构化日志）。
>
> **packageId 为工坊 `About.xml` 实测值**：Power Priority `tastytoes745.powerpriority` · Power Controller `azuraal.powercontroller` · Quality Power `ToxicYui.qualitypower` · Logic Switch `Borsh.LogicSwitches` · Active Circuits `dame.activecircuits` · Battery Overhaul `manh354.BatteryOverhaul`。挂点经本地反编译产物核实：**Power Priority 与 Power Controller 都挂 `PowerNet.PowerNetTick`** —— 我方接管 `PowerNetsTick` 后该转发循环整段不跑 ⇒ 两家补丁全部失效 ⇒ **必须让位**（比 §7.1.3 初稿的「Postfix 仍会被调用」更严重，因为初稿假设我方也挂 `PowerNetTick`）。
>
> **未闭环**：`SDD` §7.1.2 要求「让位 + UI 明示」，当前**只有日志明示**（`[PersonalChronicle][Compatibility] power grid: take-over yields to third-party mod, ...`）⇒ UI 明示与 UI 四页同批。

```text
① 让位出口（`GATE-ARCH` N3 补，求值在前）：
   若 ( letGoCached == true )      // 加载期探测到接管竞争者
       ⇒ return true

② 零配置出口：
   若 ( gridDeviceCount == 0 && priorityOverrides.Count == 0 && 无定值修改 )
```

- `gridDeviceCount` = 本图**我方分段设备实例数**（`MapComponent` 内计数器，钩子为 **`PostSpawnSetup` 自增 / `PostDeSpawn` 自减**，**不扫 `listerThings`**）。
- `letGoCached` = 加载期一次性判定的 **`readonly`** 缓存（探测谓词 = PackageId + 版本 + 挂点签名三态，见 SDD §7.1.1）；**让位面覆盖 Power Priority 与 Power Controller 两家**（后者亦占 `PowerNetTick` 的 Postfix，见 SDD §7.1.3）。
- ⚠ **`partitionRecords`（含 `Orphaned` / `Merged` 残留）不参与任何出口的判据** —— 它只是玩家输入的存档，不是「玩家正在使用本子系统」的证据。
- 语义保证：**零配置玩家感觉不到本 Mod 的存在**；**装着竞争 Mod 的玩家也不会撞上我们的接管**。

### A.5.1 异常语义（**先算后置位**）

- **禁止**「由 Prefix 自行调用原方法」（会**重入补丁链**，可能递归）；正确做法：异常路径**不置 `__runOriginal`**（保持 `true`），由 Harmony 调原版。
- 替代逻辑的副作用（`PowerOn` / `ChangeStoredEnergy`）**统一推迟到全部计算成功之后**执行 ⇒ 不存在半开。
- 失败日志**节流**（同 net 连续失败只记首条 + 每 N 分钟汇总）；连续失败 ≥ 3 次 ⇒ 该 net **锁存为不接管**，直到地图重载或手动重置。
- 锁存状态须经 SDD §7.2.3 的观测面可查（`COMP-011`）。

### A.6 可逆性与降级

- **主回滚（不需写代码）**：删除 `Capture/Patch_PowerNetTick.cs` 类文件 ⇒ 发版（PatchAll 反射扫描，删文件即不申请）。工程同型先例：`Capture/Patch_ItemFlowIngredients.cs` 自注「删除本文件即回滚」。
- **次回滚**：设置开关（`Settings/SettingsCatalog.cs`）关掉接管 ⇒ 运行时走安全阀原版路径。
- **降级**：探测失败 / 签名不符 / 目标缺失 / 运行期异常 ⇒ 逐级回落到原版行为（`SDD` §7.2.1）。

### A.7 已知代价

1. 接管期间**行为面完全由我们承担** —— 原方法有 211 行 IL、两条分支与一个存能调用，重建不完整会产生**无报错的隐蔽故障**（已知最严重者：电池冻结 / 设备开不回来）。缓解：`SDD` §5.3 的 **A′/B′/C′/D′** 四条硬要求 + §9.2 的 **P3-7~P3-11** 五条专测。
2. `PowerNetTick` 是**每 net 每 tick** 执行的路径，Prefix 判据的复杂度会被放大到全图。
3. 与 Power Priority / Power Controller 同装时需让位（`SDD` §7.1.2/§7.1.3）。

## 2. 事项 B：新增独立补丁类 `Patch_PowerIncidentCulprit`（P2）

> **⚠ 2026-10-07 PM 裁决 ④ 后本事项的对象已变更（本节即变更后的正式表述）**：

### B.1 变更性质

新增 `Source/PersonalChronicle/Capture/Patch_PowerIncidentCulprit.cs`：
`Prefix`（只读快照）+ `Postfix`（比对 + 经 Runtime 受控写回）同属**一个** `[HarmonyPatch]` 类。

**它为什么仍是一次例外登记**：① 新增 Harmony 补丁**类**（`EXC-2026-001` 台账逐类登记）；
② 该类的 Postfix **会改变世界**（诱导 culprit 网的主断路器跳闸），不是只读捕获。
⇒ 登记义务与「语义扩展」等重，但**回滚对象从「代码块」变成「整个类文件」**。

### B.2 授权范围（A）

1. **触发受限**：仅在 `IncidentWorker.TryExecute` 内，且**仅当**事件真的触发（`__result == true`）**且**观测到储能显著跌落；
2. **动作受限**：仅允许把 **culprit 网的主断路器**经 `CompPowerCircuitBreaker.TryTrip(TripReason.ShortCircuit)` 置为跳闸；**不得**直接改 `TransmitsPowerNow`（写回唯一入口，`SDD` §5.4A ③）；
3. **识别方式**：**不得用 defName / label / 翻译文本**做任何判断（`GOV-009`）⇒ 完全靠「含电池的网储能显著跌落」这一**物理观测量**识别，**不认事件类型**；
4. **定位通道**（`SDD` §7.3.2 / §B.6 修法）：`Prefix` 对 `AllNetsListForReading` 中**含电池**的网快照 `CurrentStoredEnergy()`；`Postfix` 比对 ⇒ 跌落须**同时**越过**绝对门 `0.5 Wd`** 与**相对门 25%** 才认定；**定位失败 ⇒ 不动作**；
5. **类隔离**：本类与 `Patch_IncidentWorker` **互不读写对方状态**（各自的缓冲均为私有）；
6. **本类自带完整 Patch 档案**（见文件头）：Patch Target / Patch Type / Reason / Alternative / Compatibility Risk / Execution Order / Failure Behavior / Rollback 八段逐条写明。

### B.3 禁止范围（F）

- **F1** 本类抛异常**不得**影响任何其它补丁（含 `Patch_IncidentWorker` 的战果捕获）—— 整类 `try/catch`，异常路径**不写回**、不留状态。
- **F2** 不得新增第 6 个 `DoShortCircuit` 补丁（已有 5 家）。
- **F3** 不得改挂 `IncidentWorker_ShortCircuit.*`（Circuit Breaker 已占 P=700/800，会入同挂点竞争）。
- **F4** 不得用 defName / label / 翻译文本做任何判断。
- **F5** 定位必须是 O(nets) 且**只在事件发生时**（低频）；不得进 tick 路径。**另有一道 O(1) 前置门控**：本图无 `MapComponent_PowerGridSim` ⇒ 零扫描直接返回（"零配置玩家无感"）。
- **F6** 快照缓冲**必须在 Postfix 结束（含异常路径）后清空** —— 它持有 `PowerNet` 引用 = 对 Map 的强持有（`ARC-008`）。

> **取证目标**：「确认 Zzztt 造成的能量跌落**可被 `CurrentStoredEnergy()` 观测到**。若不可观测，须改回 B.4 的备选方案，届时本 EXC 的 F3 须一并修订。」
>
> **取证结论：✅ 可观测性成立，F3 无需修订**（不改挂 `IncidentWorker_ShortCircuit`）。证据（Mono.Cecil，`Assembly-CSharp.dll`）：
> - `IncidentWorker_ShortCircuit::TryExecuteWorker` 在**同一方法体内**同步调用 `ShortCircuitUtility.DoShortCircuit(V_0)`（`IL_001C`）⇒ 其 **Postfix 时点抽干已发生**；
> - `ShortCircuitUtility::DoShortCircuit` 在 `IL_0054` 调用 **`DrainBatteriesAndCauseExplosion`**（前置 `IL_002E` 要求该网有电池）；
> - **`PowerNet::CurrentStoredEnergy()` 实时读 `CompPowerBattery.get_StoredEnergy`**（逐电池求和、跳过 `StunnedByEMP`），**非缓存**。
>
> **⚠ 但取证暴露两件原方案没算到的事，修法已定**：
> 1. **culprit 未对外暴露**（`TryExecuteWorker` 只返回 `bool`，culprit 是局部变量、`DoShortCircuit` 入参不回传）⇒ 定位只能靠**推断**，无法直取。
> 2. **★ 判据缺可计算输入** —— 「刚发生显著跌落」需**前值**，而 **Postfix 只有后值** ⇒ 照 B.2.4 字面实施**算不出判据**。
>    **修法**：在**同一个独立补丁类内加一个 Prefix**（不新增补丁类/挂点），进入时对 `AllNetsListForReading` 做一次 `CurrentStoredEnergy()` 快照存入**复用缓冲**，Postfix 用它比对。O(nets) 且**只在事件发生时**（符合 F5「低频」）。
>
> **附带确认的两个好性质（无需额外处理）**：① 若第三方用 Prefix 拦掉 `DoShortCircuit` ⇒ 抽干不发生 ⇒ 无跌落 ⇒ **我方不动作** —— 正确降级，且**无需探测第三方**；② 无电池的网有 `Any<CompPowerBattery>` 前置 ⇒ 不会被误判为 culprit。
