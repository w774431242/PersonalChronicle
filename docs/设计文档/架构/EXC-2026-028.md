## 1. 授权范围（A）

允许在**已签订有效经济合同之后**，对**该岗位所需工作类型**写入启用档位，且必须**同时**满足：

1. **类型受限**：仅限合同岗位声明的必需类型（`WorkshopTypeDef.WorkTypeDefNamesOf(shift.TaskType)` 的解析结果）；空 `defName` 或无法解析一律拒绝（fail-closed）。
2. **不可写清单（2026-10-12 范围变更）**：原为 `Hauling` / `Cleaning` / `Doctor` / `Firefighter` **四项既不禁用也不启用**；现**收窄为 `Doctor` / `Firefighter` 两项**（用户 2026-10-12 裁决「红线纳入合同解锁」，`CHG-20261012-ECON-LABOR2`）。
   - 原因：合同岗位确实会需要搬运 / 清洁（例：`vanilla:Hauling:…:Haul` 搬运合同）；排除它们会让合同在 FA-11 复核（要求 `GetPriority > 0`）处**必然失败**并当场终止（`WorkTypeUnavailable`，实机 `Player.log` 实证）。实装点：`Domain/PawnEconomy/Employment/WorkOwnershipRules.cs`（`NeverManaged`）。
   - 边界不放宽：本通道**永不写 0**（禁用方向仍只属 `EXC-2026-016` / `EXC-2026-026`）；只认领玩家关闭态（§1.4 不变）；退出按所有权还原（§2 不变）。
   - ⚠ **与 `EXC-2026-016` 的关系变更**：`EXC-2026-016` 的 `MandatoryKeep` 仍是**四项**，且自 `CHG-20261005-REDLINE` 起允许"**有在岗专属岗位**"时接管并写 0 ⇒ 本通道与它**不再是同一条红线**，同一（Pawn, 工作类型）可能出现两份台账。跨台账互踩按用户 2026-10-12 裁决**「合同避让（fail-closed）」**处置 —— ⚠ **该避让判据本轮尚未实装**（见 `变更标注_CHG-20261012-ECON-LABOR2` 遗留项）。
   - ⚠ **未实装避让期间的**可观测后果（2026-10-12 ARCH 席复核订正，原稿"当场终止"**不准确**）：合同**不会**因格位被写 0 而当场终止 —— FA-11 复核只在**签约点**执行，而退出判据 `CanStillWork` 只看 `WorkTypeIsDisabled`、**不看 `GetPriority`**（`Economy/EconomyEmployment.cs:336-344`）⇒ 真实表现是「活跃合同 + 该工种档位 0」的**静默滞留**，一直持续到合同到期或件数耗尽。终值取决于两条通道的写入次序（接管先/合同后 ⇒ 玩家原值可能被吞；合同先/接管后 ⇒ 可能泄露一个非 0 档位），属**一次性、次序相关的错终值**，非数据损坏、无周期抖动。
3. **初始化前置**：`pawn.workSettings != null && pawn.workSettings.Initialized` 为真；否则拒绝。**禁止**调用 `EnableAndInitializeIfNotAlreadyInitialized`（会批量把 6 类设为 3，属越权）。
4. **只认领玩家关闭态**：仅当 `GetPriority(type) == 0` 才写入（玩家已打开的档位不由本系统认领）。
5. **能力禁用不绕过**：`pawn.WorkTypeIsDisabled(type)` 为真时拒绝（原版对这类类型写档位会 `Log.Error`）。
6. **签约前置**：未签约不得写入；每次只写一笔合同所需的类型，**禁止**全量勾选。
7. **先记账后写**：写入前必须先落台账（`economyWorkOwnership`：`PawnKey / WorkTypeDefName / WrittenPriority / OriginalPriority / AppliedTick`），首记优先。

## 2. 还原规则（与写 0 通道同构）

- 还原闸门：**只还原本系统写入且未被玩家改动**的项 —— `当前档位 == 台账 WrittenPriority` 才写回 `OriginalPriority`（通常为 0）。
- 玩家在合同期内手动改动过 ⇒ **保留玩家新值**并丢弃该台账项，不覆盖、不重写。
- **禁止** tick 无条件重刷档位；写入幂等（已是写入值即跳过）。
- 退出/离岗/合同取消/制度退出时释放该 Pawn 的台账项；死亡/离图保留履约权益由 M11 处理，不在此通道。

## 3. 禁止范围（F）

- **F1** 不得**以取消/禁用为目的**写 `SetPriority(type, 0)` / `Disable`（主动取消方向只属 `EXC-2026-016` / `EXC-2026-026`）。
  **澄清（2026-10-08，依 GATE-ARCH P1-2）**：§2 的「按台账还原」写回 `OriginalPriority`（本通道恒为 0）**不属本项禁止范围** —— 它是把本通道自己写入的值退回原状，闸门为「当前档位 == 台账 `WrittenPriority`」，玩家改动过一律保留；本项禁止的是**主动**关闭玩家仍在使用的档位。
- **F2** 不得覆盖玩家已有的非零档位（只在 0 上写）。
- **F3** 不得在**不可写清单**上写入（2026-10-12 起为 `Doctor` / `Firefighter` **两项**；原为含 `Hauling` / `Cleaning` 的四项）。
- **F4** 不得对未签约 Pawn 写入，或不经合同全量勾选工作类型。
- **F5** 不得在 tick / 绘制 / 读档副作用路径写入。
- **F6** 不得使用本通道之外的第二份台账（避免与 A/B 台账混用导致还原闸门误判）。
