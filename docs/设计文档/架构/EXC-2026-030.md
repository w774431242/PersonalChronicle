## 1. 偏离对象

`docs/设计文档/功能模块/经济体系/经济需求驱动AI/M10-再生产与公有机构运行/10-再生产与公有机构运行_代码设计方案.md` §4（`:46-48`）：

> 「可完成在制与已授权未开工**互斥**，已授权计划与**相同订单/出口键关联**；开工从未开工移到在制，完工从在制移到库存，交付才减少对应未交付量。」

本批实现（`Source/PersonalChronicle/Domain/PawnEconomy/Production/ProductionAuthorisation.cs`）：

```text
EffectiveNotStarted = max(0, 账内授权量 − 该品类观察到的在制量)
```

即：**按品类**收敛，而非按「计划 ↔ 工单」键逐条移出。

## 2. 为什么要偏离（理由 + 证据）

1. **被关联对象尚不存在**：§4 的键关联要求把「已授权计划」与「订单/出口键」绑定，而 M7 订单域与出口域**尚未实装**（`CHG-20261009-ECON-M10-AUTH` §1 已裁定：`ConfirmedUndeliveredDemand` / `AuthorisedUndeliveredExports` 保持显式 Unknown）。
2. **不做会比做更危险**：若只把账内授权量直接计入覆盖而不与观察在制收敛，同一批量会被**两个桶各扣一次**（在制桶 + 未开工桶）⇒ 净缺口被低估 ⇒ 该补的货不补。
3. **本收敛是 §4 意图的最小实现**：它保证「同一量不被两个桶重复扣减」，只是粒度停在品类；**保守方向**（宁可少授权、不重复生产），不产生重复生产或重复付款。

## 3. 影响面与边界

| 项 | 说明 |
|---|---|
| 受益 | 补货公式不再因品类级重复扣减而低估缺口 |
| 风险 | 品类内**无关工单**的在制量也会抵减本账授权量（口径偏保守）；已有界（账 ≤16、读数 ≤32 品类） |
| 不涉及 | 不改公式 `RestockPlanner`、不改 Zzztt/排班/工单、不建第二执行器、不写钱 |
| 未知语义 | 账不可读 ⇒ 读数 Unknown（绝不填 0）；空账 ⇒ Known(0)（账即权威） |

## 4. 缓解与到期条件

- **缓解**：读数 UI 如实标注该输入已接线、且需求/目标/出口三项仍 Unknown（`PC_PEA.Overview.NotWiredInputs`）；本批**不得**对外表述为「补货评估可用」。
- **到期/退出条件**：当 M7 订单域或出口域落地并引入「计划键 ↔ 工单键」关联时，改为逐键移出，本 EXC 归档并更新 `变更标注` 说明。
- **2026-10-10 进展（如上表）**：工单侧键关联已落地（授权 → 真实工单 → 完成核销），本 EXC 收窄为"**尚缺订单/出口侧的键**"——
  剩余偏离面从"整个收敛是品类级"缩小到"授权与需求/出口之间仍是品类级"。回滚面相应收窄：
  `Ledger.RecordDelivery` 停用即退回到本 EXC 原始形态。
