# RimWorld Mod Engineering Standard v3.0

本目录是面向 RimWorld 1.6 Mod 项目的统一工程规范体系。v3.0 不是在 v2.0 末尾追加说明，而是对原有规范进行全局重构：治理文件负责定义“规则如何生效”，分层文件负责定义“具体工作如何执行”，所有规则通过稳定的规则 ID 互相引用。

## 使用顺序

1. 先阅读 [00-规范体系总纲.md](00-规范体系总纲.md)，确认优先级、依赖方向和冲突裁决。
2. 按任务读取 [00-统一术语与定义.md](00-统一术语与定义.md) 与 [00-规范关系矩阵.md](00-规范关系矩阵.md)。
3. 需求与设计文档阶段遵循 [00-需求与SDD规范.md](00-需求与SDD规范.md)（REQ-* / SDD-*）。
4. 按变更类型读取 01–07 分层规范；规则编号以 [00-规则编号索引.md](00-规则编号索引.md) 为唯一索引。**任何文档的新建 / 更新先读 [12-文档与交付物治理规范.md](12-文档与交付物治理规范.md)**（DOC-001~010：更新优先、新建审批门、落点与索引同步）。
5. 开发过程遵循 [00-工程生命周期规范.md](00-工程生命周期规范.md)，交付前执行 [00-统一验收标准.md](00-统一验收标准.md)。
6. 任何偏离规范的实现必须先登记在 [00-规范例外与变更管理.md](00-规范例外与变更管理.md)。AI 必须遵守 [07-AI开发规范.md](07-AI开发规范.md)。
7. PersonalChronicle 的 Provider、Read Model、事件与接入层映射见 [附录-项目架构实施映射.md](附录-项目架构实施映射.md)。

### 收录标准（本目录只收以下三类）

| 类型 | 判定 | 放置位置 |
|---|---|---|
| **体系规范**（治理 + 分层） | 定义"规则如何生效 / 工作如何执行"，带规则 ID | 根目录，`NN-` 数字前缀 |
| **工程约定** | 构建 / 发布路径约定、开发手册（项目专属，非跨项目规范） | `工程约定/` |

**不收**：功能设计文档与子系统专项契约（→ `设计文档/功能模块/<子系统>/`）、方案/报告/讨论稿（→ `设计文档/` 或 `性能/`）、Changelog（→ `changelog/`）、UI 预览稿（→ `UI预览/`）、外部游戏资料（→ `参考清单/`）、过程性 EXC / Gate 记录（归档到 skill `references/history-archive/`）。

> **同步说明**：`scripts/sync_from_docs.ps1` **只同步本目录顶层 `.md`** 到 skill `references/`：先把顶层 `Gate-Record-*.md` / `EXC-*.md` 归档到 `history-archive/`，再逐个 `Copy-Item` 并做 SHA256 校验（不一致退出码 2）。`工程约定/` 是项目专属内容，保留为主副本、不同步进 skill，以控制 skill 体积。

## 规范性说明

- 本体系适用于 RimWorld 1.6 项目；具体 API 行为仍以项目锁定的游戏、DLC、Harmony 和编译引用版本为准。
- 规则 ID 是跨文件引用的稳定契约，不得因排版或文件移动而改号。
- 示例中的 `MyMod`、`MyMod_`、`MyMod.` 是占位命名空间，项目必须替换为唯一且固定的 Mod 标识。
- “必须/不得”是强制规范；“应/建议”是默认方案；偏离默认方案时仍需满足 [EXC-001](00-规范例外与变更管理.md#exc-001-例外先登记) 的例外流程。
