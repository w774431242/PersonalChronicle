# 变更标注 · CHG-20261006-EVKEY

## 背景与定级修正（重要）

本批处理上游复核报出的 **EV-01**：`ArchiveUiDataProvider.KindLabelLocal` 以
`"PersonalChronicle.UI.Ev" + kind.ToString()` **拼键且无回退**，而 `ChronicleEventKind` 枚举有 **9** 个值
（`Domain/ChronicleEventDef.cs:10-29`：Other/Death/Battle/Craft/Join/Built/Social/**Leave**/**RoleChanged**），
键族当时只有 **7** 个 ⇒ 缺键时返回**裸 key**。

**上游给出的"可达裸 key 显示"在本批复核中被事实性修正**：`KindLabelLocal` 的唯一消费链是
`KeyEventView.TypeText`（`SectionSnapshots.Detail.cs:516`）→ `PersonnelArchivePanel.DrawKeyEventStream`
（`PawnOverview.cs:261`）—— 而 **`DrawKeyEventStream` 全仓 0 调用者**，其缓存镜像 `cachedKeyEvents`
亦无读取者（"人生时间轴 / 足迹 / 里程碑 / 关键事件流"四区块同族未接线）。

⇒ 该缺陷实为「**构建层可达、展示层不可达**」，修复前玩家可见暴露面 = **0**，
正确定性为**潜伏/防御性缺陷**（非"当前可见的裸键"）。本批修复仍保留：成本极低，
一旦该区块接线或出现新消费者即刻兑现价值。

## 一、键族补全 + 缺键回退（LOC-001 / UI-008）

| 项 | 内容 |
|---|---|
| 新增键 | `PersonalChronicle.UI.EvLeave`（中「离档」/ 英 `Left`）、`EvRoleChanged`（中「身份变更」/ 英 `Role Changed`） |
| 文案来源 | 枚举注释 `ChronicleEventDef.cs:21`（**离档**：离开/被俘/死亡移出殖民地）、`:26`（**身份变更**：自由↔奴隶↔囚犯）；英文对齐 `Defs/Chronicle_Events.xml:87/96` 的 `<label>`（`Colonist Left` / `Role Changed`） |
| 回退 | `KindLabelLocal` 增加 `CanTranslate()` 判存在 → 缺失落 `EvOther`，**防未来新增 kind 再漏** |
| 判存在的写法 | **必须用 `CanTranslate()`**，不可用 `Translate() == key` 比较 —— DevMode 伪本地化会给缺键加变音符使该比较失效（工程同类注记见 `ArchiveUiDataProvider.LifeHealth.cs` 的 LabelKey 分支；`docs/问题跟踪/待修复问题.md` FIX-001 有同类验收口径） |

**拼键点穷举**：全仓 `"PersonalChronicle.UI.Ev"` **前缀拼键仅 1 处**（本处）；
`MasterControl/Population/PersonnelArchivePanel.Labels.cs:256-268` 的 `ChronicleEventTypeLabel` 走
`def.LabelCap` + `EvOther` 回退，**不裸 key**（但它是死方法且其 LabelCap 路径无 DefInjected 覆盖 —— 见 §四）。

## 二、时间轴字形 / 配色补齐（同批发现的 N-04）

`PersonnelArchivePanel.EventTypeToGlyph` / `EventTypeToColor` 的 `switch` 也只有 **7 个 kind**，
Leave / RoleChanged 静默落 default（「•」+ `TimelineOther`）—— 而这两个函数**有活消费者**：
制造中心 ⑤ 事件流（`Manufacturing/UI/ManufacturingEventsPanels.cs:92/101` 经
`PersonnelArchivePanel.EventTypeToGlyph/EventTypeToColor` 取字形与色）⇒ **玩家可见的呈现无区分度**。

处置（本文件 `:275-277` 的注释明确要求"新增 kind 时必须同时补符号与配色"）：

| kind | 字形 | 配色 | 说明 |
|---|---|---|---|
| `Leave` | `←` | 落 `TimelineOther`（显式列出） | 符号取**基础箭头**（Arial 覆盖率高于 `⇥`/`⇄` 一类 Arrows 扩展区） |
| `RoleChanged` | `↔` | 落 `TimelineOther`（显式列出） | 同上 |

`EventTypeToColor` 中**显式列出**两个 case（而非依赖 default），以维持本文件
"两函数共用 kind 分支、必须成对维护"的契约。

## 三、明确不做（非目标 / 范围外）

1. **不新增专用主题令牌** `TimelineLeave` / `TimelineRoleChanged` —— 需同步改动主题系统
   （`UITheme.Palette` + 三套主题预设值），属设计决策，另批处理（本批以字形区分代替）；
2. **不动** `ArchiveUiDataProvider.KindWeight`（default=10）与 `EventGlyph` —— 其消费区块
   （关键事件流）当前**未接线**，补权重等于预设一个未经设计决策的排序口径；
3. 不处理本批复核新报的 N-01 / N-02 / N-03（见 §六）；
4. 不新增/修改任何第三方或原版键；不改存档结构；无 Harmony。

## 六、残留与风险（照实登记）

1. **本批复核新报的 3 项 P3（本批不处置，登记备查）**：
   - **N-01**：`PawnOverview.cs` 的"人生时间轴 / 足迹 / 里程碑 / 关键事件流"四区块**均无调用者**，
     `cachedKeyEvents` / `cachedMilestones` 无读取者 ⇒ 该组 UI 未接线（或已成死代码）。
     需产品侧确认"待接线"还是"已废弃"（前者则排期接线，后者则清理 + 同步悬空注释）。
     ⚠ 此项**直接决定 EV-01 的实际严重度**（见 §背景）。
   - **N-02**：`PersonnelArchivePanel.Labels.cs:256-268` 的 `ChronicleEventTypeLabel` 为**死方法**，
     其 `def.LabelCap` 路径**无 DefInjected 覆盖**（`Languages/` 全库无 `ChronicleEventDef` 注入）
     ⇒ 若将来接线，中文界面会显示英文 label，且与 `Defs/Chronicle_Events.xml` 头注释
     "labels 是 dead copy、UI 从不读 Def label"直接矛盾。
   - **N-03**：`_scripts/audit-keyref-integrity.ps1` 对前缀字面量只校验"存在**任意**匹配键"，
     **无枚举↔键逐值断言** ⇒ 这正是 EV-01 长期漏网的机制原因。建议为该脚本增加
     "枚举值 ↔ 键族"逐值校验（或建登记表注明同步义务）。
2. **字形渲染未实测**：`←`(U+2190) / `↔`(U+2194) 在 RimWorld 字体下的实际渲染需实机确认（首选基础箭头即为规避缺字形风险）；
3. **「身份变更」宽度未实测**：64f × `GameFont.Tiny` 下是否被 `TruncateToWidth` 截断，需实机复核；
4. **本批未部署**：发布区（`RimWorld\Mods\殖民地综合管理系统`）尚未同步本次 DLL 与语言文件（另一变更 `CHG-20261006-TABUNIFY` 的部署时点早于本批编译）⇒ 需再跑一次 `deploy-to-game.ps1` 并重启游戏。
