## 1. 实现（4 步引导 · 窗口内自锚 · 零跨帧缓存）

| 项 | 内容 |
|---|---|
| **入口** | 教程窗（`Window_NewcomerGuide`）底栏改为**双按钮**：左「知道了」/ 右**「开始引导」**（RUIF `WindowFmt.FooterButtonRect` 等分槽，主按钮取最右 = `Dialog_MessageBox` 范式）。点它 → 找宿主总控中心窗口 → 关自己 → `StartTour()` |
| **步骤** | ① 内容区（"每张卡 = 一个中心"）→ ② 页头「新手教程」按钮 → ③ 主题控件 → ④ 居中收尾（建议第一站：划车间 → 工作台 → 工单） |
| **锚点机制** | **本帧自锚**：各控件绘制点画完后调 `ReportTourAnchor(id, rect)`（窗口局部坐标）；`DrawWindowContentsCore` 帧初 `BeginTourFrame()` 清标记、**最末端** `DrawTourOverlay()` 读锚点 ⇒ 同帧闭环、不缓存任何控件引用。锚点缺失（控件不可见）⇒ 该步**自动降级为居中气泡**，不崩不错位 |
| **遮罩与高亮** | 四块半透明遮罩围出"洞"（RUIF `Draw.Box`）+ 呼吸描边（`Draw.Border`）+ 四角 L 框（RUIF `Shapes.CornerFrame`）；洞矩形夹进窗口，**绝不画到容器外** |
| **动画** | ① 遮罩淡入（200ms）；② 高亮描边**呼吸**（与 RUIF `PulseAlpha`/`FlashAlpha` 逐值同式 `min+(1−min)(0.5+0.5·sin4t)`）；③ 气泡**淡入 + 从下方 6px 滑入**（每步 160ms）；④ 进度点：当前步走 RUIF `StatusAtoms.PulseDot` 呼吸，其余静点 |
| **控件** | 气泡用 RUIF 按钮原子：`ButtonAtoms.PrimaryButton`（上一步 · 首步禁用 / 跳过 / 下一步→末步变「开始探索」） |
| **时钟** | **BCL 时钟**（`DateTime.UtcNow.Ticks`）派生秒数 —— 绘制路径**禁用** `Time.realtimeSinceStartup`（工程铁律/ECall 隔离） |
| **状态** | 全部是**实例字段**（`tourActive` / `tourStep` / 三个时刻戳 / 锚点表）⇒ UI 瞬时态、不入存档、窗口关闭即消失、**无静态可变状态** |
| **交互抑制** | IMGUI 中先绘制的控件先吃点击 ⇒ 引导期在各绘制点判 `tourActive` 抑制：中心卡片跳转、页头「新手教程」按钮点击（仍正常绘制）。不抑制就会出现「点气泡按钮却进了中心详情页」 |

## 2. 关键取舍与已知边界

1. **范围 M1 = 只引导本窗口内元素**。「引导玩家去游戏里划区 / 点主按钮栏」需要**跨界面锚点**（各模块登记自己的屏幕矩形 + 坐标空间换算），属独立变更；本轮④步以**居中气泡**文字引导到游戏内动作，不假装高亮。
2. **内容区锚点用视口矩形**而非单张卡片：卡片在滚动内容里，逐卡上报需要"组内局部坐标 → 窗口坐标"换算（RimWorld `BeginScrollView` 的坐标系），风险大于收益；"整块列表区"已足够表达该步语义。
3. **不锁全局输入**：引导不改变窗口的输入语义（只抑制被引导页面上的两处跳转），玩家可随时「跳过」。
4. **RUIF 源码 ≠ 已发布 DLL**（再次踩到）：`StatusAtoms.PulseAlpha` 在源码工作副本里有、**已发布 DLL 未导出**（与 `ButtonAtoms.FullWidthPad` 同类）⇒ 呼吸 alpha 按**逐值同式**本地实现（纯算术、零版本依赖），`PulseDot`/`Shapes`/`Draw`/`ButtonAtoms`/`Measure` 均为 DLL 已有成员。

### 3.2 用户实证事故修复（同日第二轮：key 泄漏 + 弹窗化）

**事故（用户截图）**：页头按钮显示原文 `PersonalChronicle.UI.Guide.Button` —— 原始 key 泄漏到界面。
**根因（本地复现，非推断）**：上一版本变更在 `Languages/{zh,en}/Keyed/Guide.xml` 插入的 XML 注释里写了**连续两个短横**。XML 规范禁止注释内出现该序列 ⇒ **整个文件解析失败**（`An XML comment cannot contain '--' … Line 9`）⇒ 该文件**全部**键回退为 key 名（不止按钮那一处，只是界面上只暴露了它）。
**修复**：
1. **重写两份 `Guide.xml`**：注释全部规范化（并在注释里留下事故说明，防止再犯）；**删除旧七节静态正文的 25 个键**（S1…S7.Title/L1/L2/L3 + Title + Close，用户明确「不要上一版内容」）；新增 `Guide.Ask.Title/Body/EscHint/Later` 与 `Guide.Tour.EscHint`。
2. **`Window_NewcomerGuide` 整体改写为确认弹窗**：内容 = 询问「开启新手教程？」+ 正文（约一分钟、不改数据）+ **「引导过程中随时按 ESC 或点跳过退出」提示**；底栏 = 「以后再说」/「开始引导」。
3. **引导期接管 ESC**：`StartTour()` 置 `Window.closeOnCancel = false`（防引擎直接关窗）、`StopTour()` 恢复；`DrawTourOverlay` 首段检测 `KeyDown + Escape` → `Event.current.Use()` + `StopTour()`；气泡进度点行右端常显 `ESC 退出`。
**验证（全部本地可复核）**：
- XML 合法性扫描（`Languages/**/*.xml` 全量）→ **ALL XML OK**；
- `Guide.xml` 键对称 → **zh=20 / en=20，KEYS SYMMETRIC**；
- 代码引用 ↔ 文件键双向核对（正则提取 cs 里的 `PersonalChronicle.UI.Guide.*`）→ **引用 20 = 文件键 20，缺失 0、孤儿 0**；

**教训（写进语言文件约定）**：XML 注释里**绝不允许**出现连续两个短横；分隔线用 `===`。新增语言键后必须跑「XML 合法性 + 键对称 + 代码↔文件双向核对」三件套（本次已形成可复制的 PowerShell 校验）。
