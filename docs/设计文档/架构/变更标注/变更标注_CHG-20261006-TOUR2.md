# 变更标注 — CHG-20261006-TOUR2

> 用户反馈（2026-10-06，截图 + 文字）：「新手引导太短、不够详细、过程中有些内容缺失无反应。

## 1. 为什么必须换架构（v1 → v2）

| 诉求 | v1（窗口内引导层）为什么做不到 | v2 的做法 |
|---|---|---|
| 引导「划车间 / 放设备 / 加工单」 | 这些操作必须**关掉总控中心**回游戏世界做，而 v1 的引导层画在总控中心窗口内部 ⇒ 窗口一关引导就消失 | 引导层改为**独立全屏透明窗口** `Window_TourOverlay`：关掉总控中心后它仍在栈上继续引导 |
| 详细 | 4 步 | **13 步**（注册表 → 页头 → 主题 → 划车间 → 放设备 → 加工单 → 回看板 → 左轨 → 右轨 → 页签/画布 → 其它中心 → 回注册表 → 收尾） |
| 「有些内容无反应」 | v1 在引导期**抑制**了卡片跳转等交互（怕玩家误触），玩家点了没反应 | v2 **不抑制任何交互**，改为"允许操作 + 完成条件自动推进"；「跳过本步」始终可用，绝不卡死 |
| 「空白/无内容」 | 锚点缺失时只能居中气泡，玩家看不到"该看哪里" | 新增**车间地图高亮**（`Zone_Workshop.cells` 包围盒 → `UI.MapToUIPosition`）+ 每个关键步骤都有条件提示行 |

## 2. 实现要点

1. **独立引导层** `Window_TourOverlay`：全屏透明（`doWindowBackground=false / drawShadow=false / doCloseX=false`），
   `absorbInputAroundWindow=false` 且除自身按钮外**不消费事件** ⇒ 玩家照常划区、建造、切换标签页。
   `closeOnCancel=false` + 自绘 ESC 分支 ⇒ 引导中按 ESC 退出引导而**不会**顺手关掉别的窗口。
2. **跨窗口锚点**：`TourAnchorRegistry`（**受控静态例外**，类注释写明生命周期与零开销短路）——
   总控中心在绘制时把**屏幕坐标**（`windowRect.x + local.x`）写入表；引导层每帧 `BeginFrame()` 重建。
   锚点缺失 ⇒ 自动降级为居中气泡（不崩、不错位）。
3. **完成条件（Gate）**：`WorkshopExists`（`Zone_Workshop`）/ `DevicesPlaced`（`IBillGiver`）/
   `BillsWithIngredients`（`recipe.ingredients.Count > 0`）/ `ManufacturingDetail` / `RegistryView`。
   满足即自动推进；未满足时「下一步」禁用并显示条件行，「跳过本步」仍可用。
4. **可访问性**：地图车间包围盒由 `UI.MapToUIPosition`（Cecil 核实存在：`Verse.UI::MapToUIPosition(Vector3) -> Vector2`）
   逐格映射取 min/max，按（`Zone.ID` + 格数）缓存，避免每帧 O(格数)。
5. **只读探针**：总控中心暴露 `TourShowsRegistry` / `TourShowsManufacturingDetail`（`internal` 只读属性），
   引导层据此判断"玩家到了没"，不改动任何业务状态。

## 10. 用户实机反馈的第二批修正（同日，两图）

### 10.1 「按 ESC 先退出了管理系统、要按第二次才关引导」（用户实证）

**现象**：第一次 ESC 关掉的是**总控中心**，引导层留着；第二次 ESC 才退引导。

**根因（Cecil 取证）**：
- `Verse.Window::InnerWindowOnGUI` 的 IL 显示：引擎在**每个窗口自己的 OnGUI 里**按 `KeyBindingDefOf.Cancel.KeyDownEvent` 判定，并在满足条件时 `callvirt Window::OnCancelKeyPressed()`（`IL_0306`），随后自行 `Event.Use()`（`IL_032B`）。
- 也就是说"谁收到取消键"取决于**各窗口自带的那段分支**：引导层原先把 `closeOnCancel = false`，于是引擎**跳过**它、继续落到仍为 `true` 的总控中心 ⇒ 一次 ESC 只关了下层窗口。
- 另外 `RimWorld.MainTabsRoot::HandleLowPriorityShortcuts -> EscapeCurrentTab` 是**低优先级快捷键**路径，会在事件未被消费时再关一次标签页。

**修法（已落地）**：
1. 引导层 `closeOnCancel = true`（**声明接管**取消键）+ `public override void OnCancelKeyPressed()`：在"当前事件确实是那次 Esc KeyDown"时 `Event.current.Use()`（掐掉低优先级路径），然后 `Close()`；
2. **删除**绘制循环里自检 ESC 的分支（唯一入口，避免双路径）；
3. 语义不变：ESC = 只退引导；总控中心与其它窗口不受牵连。

### 10.2 「应该自动跳转到该位置去继续引导」（用户要求）

进入新步骤时**替玩家走一步**（每步只做一次，`lastNavigatedStep` 记步号；「上一步」回退会重新导航）：

| 步骤 | 自动动作 | 用到的 API（均已 Cecil 核实） |
|---|---|---|
| S3 划车间区 | 打开**建造菜单** | `MainButtonDefOf.Architect` + `Find.MainTabsRoot.SetCurrentTab(def, true)` |
| S4 放设备 | 打开建造菜单 + **相机对准车间**（车间 `cells` 中点） | `Find.CameraDriver.JumpToCurrentMapLoc(IntVec3)` |
| S5 加工单 | **相机对准车间内第一个工作台**（并把它框成高亮目标） | 同上 + `WorkshopZoneUtility.WorkshopAt` 过滤 |
| S6 回看板 | **自动打开总控中心**（按窗口类型找 `MainButtonDef`，不写死 defName） | `DefDatabase<MainButtonDef>.AllDefsListForReading` + `tabWindowClass` |

配套：S3 的高亮目标从"整块车间"细化为 **S5 用工作台方框**（`MapBench`），文案同步改写为"建造菜单/相机已经替你打开/对准"（zh/en 各 4 条，去掉会原样显示的 `**` 强调符）。

### 10.3 「这一步无法进行划区，因为无法点击」（用户实证，第三图）— P0

**现象**：走到 S3（划车间区），建造菜单已打开，但**地图上拖框划区完全没反应**。

**根因（IL 取证）**：`Verse.WindowStack::GetWindowAt(Vector2)` 的实现**只判断 `windowRect.Contains(pos)`**（不看 `absorbInputAroundWindow`、不看 `layer`），
而它的消费者之一是 **`Verse.CameraDriver::CameraDriverOnGUI`**（另有 `WorldCameraDriver` 与 `WindowStack.HandleEventsHighPriority`）。
⇒ 引导层是全屏窗口时，鼠标永远落在它的 `windowRect` 内 ⇒ 相机驱动认为"鼠标在窗口上" ⇒ **地图交互（拖框划区、点建筑）被整体屏蔽**。
这条路径与"窗口内按钮点击是否有效"（那取决于事件是否被 `Use()`）**完全无关** —— 所以总控中心/建造菜单里的按钮能点，地图不能。

**修法**：给"必须在地图上动手"的步骤加 `MapInteractive = true`（S3 / S4 / S5），并把引导层在**这些步骤缩成右下角的"气泡小窗"**
（`windowRect` = 气泡矩形，`ApplyStepWindow` 统一切换；同时这些步骤**不画遮罩**，否则会把气泡自己压暗）：

- 鼠标落在地图上时 `GetWindowAt` 返回 null ⇒ **划区 / 放置 / 点工作台恢复正常**；
- 其余步骤（纯阅读 + 点窗口内控件）仍保留全屏遮罩 + 挖洞 spotlight（窗口内点击本就有效）；
- 气泡高度与窗口尺寸**共用同一算式** `MeasureBubbleHeight`（LAND-002：不得"算一套画一套"）；
- 切换统一走 `step != lastWindowAppliedStep` 一处判断，覆盖 Begin / 自动推进 / 下一步 / 上一步四条路径。

**代价（如实登记）**：S3/S4/S5 三步没有全屏压暗与挖洞高亮 —— 目标改由**相机对准 + 文案**指引（见 §10.2）。这是"可操作性 > 视觉效果"的取舍。

### 10.4 「这一步无法点击」（第四图：S6 点不动总控中心卡片）— 与 10.3 **同一根因的另一半**

**现象**：S6（"回头看结果"，气泡在屏幕中央）时，点「制造系统中心」卡片毫无反应。

**根因**：10.3 只修了"地图被屏蔽"那一半。`GetWindowAt` 的消费者除了 `CameraDriverOnGUI`，还有 **`WindowStack.HandleEventsHighPriority`** —— 全屏 `windowRect` 让鼠标"永远落在引导层上"，**下层窗口的鼠标事件同样被拦**（这也解释了更早那张图里"建造菜单命令列点不出来"）。

**结论（引擎层面互斥）**：**遮罩必须全屏**（窗口必须覆盖整屏），**可点击必须不全屏**（窗口不能覆盖鼠标下的目标）⇒ 二者不可兼得（在不引入 Harmony / 不用 `UIRoot` MonoBehaviour 绘制的前提下）。

**定案**：引导层**恒为"气泡小窗"**（右下角，`ApplyStepWindow` 只设小窗矩形），并且：
- 移除全屏遮罩与挖洞的默认启用（保留 `fullScreenMaskEnabled = false` 开关，注释写明"将来若改为在 `UIRoot` 的 MonoBehaviour 上绘制（不产生窗口）可直接启用"）；
- 高亮职责整体转交 **相机对准 + 文案**（S4/S5 文案里的"高亮/方框"已改为"屏幕正中就是"）；
- 气泡自身仍是可点窗口（鼠标在气泡上时点击被气泡接收，符合直觉）。

**收益**：从"点哪都不行"变为**一切可点**（地图、建造菜单、总控中心卡片、气泡按钮）；代价是全程没有压暗 spotlight —— 这是"能继续引导"的前提。

### 10.5 「怎么没有下一步」（第五图：按钮整行消失）

**现象**：S0 气泡里只有标题 / 正文 / 进度点 / 「ESC 退出」，**「跳过本步 / 上一步 / 下一步」三颗按钮不见了**。

**根因**：**宽度算式不一致** —— `ApplyStepWindow` 用 `min(380, screenW − 20)` 作为窗口宽度并据此算窗口高度；
而小窗形态下 `DrawBubble` 的 `screen` 就是窗口本身，它又按 `screen.width − 20` 取气泡宽度 ⇒ **比定窗口时窄 20px**
⇒ `Text.CalcHeight` 折行更多 ⇒ 绘制用的总高 > 窗口高 ⇒ 底部按钮行被 `GUI.BeginGroup` 裁掉。

**修法（双层）**：
1. 根因：小窗形态下 `bubbleWidth = screen.width`（与 `ApplyStepWindow` **逐值一致**），高度仍走同一个
   `MeasureBubbleHeight` ⇒ 窗口高与内容高严格相等；
2. 防御：进度点行与按钮行的 `y` 改为**从气泡底边反推**（`bubble.yMax − pad − btnHeight` 等），
   即使将来文本测量与渲染有一两像素出入，也**永远不会**把「下一步」裁出窗口。
