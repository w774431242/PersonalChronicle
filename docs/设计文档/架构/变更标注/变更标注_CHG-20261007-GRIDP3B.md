# 变更标注 · CHG-20261007-GRIDP3B

## 1. 目标

实装电网 SDD 的 **P3-8 兼容层探测**（审计计划中唯一标注为 **P1 风险**的未实装项），
并把它接进安全阀出口②（让位）。

此前 `letGoCached` 是一个**从未被赋值的死字段** ⇒ 出口② 恒不成立 ⇒ 与 Power Priority / Power Controller
同装时会**双重甩负荷**（且 P3-2 无法验收）。

## 2. 关键裁决

1. **出口② 的位置从宿主移到 Capture 层**：`MapComponent_PowerGridSim` 属 Runtime/Data 侧，
   而兼容层在 `Compatibility` —— `SDD` §3.2 的依赖图**没有** `Runtime → Compatibility` 这条边。
   `Capture → Compatibility` 是外层内聚方向，不引入新跨层依赖。⇒ 删除 `letGoCached` 死字段。
2. **探测判据是三态**（`SDD` §7.1.1）：`packageId` 命中 **∧** 挂点核验通过 —— 防「目标改版后
   类型还在但挂点漂移」的**误让位**（玩家会白白失去调度功能）。
3. **packageId 全部实测**（工坊 34 个电力 Mod 的 `About.xml` 逐字读），不凭记忆：
   `tastytoes745.powerpriority` / `azuraal.powercontroller` / `ToxicYui.qualitypower` /
   `Borsh.LogicSwitches` / `dame.activecircuits` / `manh354.BatteryOverhaul`。
4. **挂点经反编译核实**：Power Priority 与 Power Controller **都挂 `PowerNet.PowerNetTick`**。
   我方接管 `PowerNetsTick` 后该转发循环整段不跑 ⇒ 两家补丁**全部失效** ⇒ 必须让位。
   （`SDD` §7.1.3 初稿写「Postfix 仍会被调用」，那是假设我方也挂 `PowerNetTick`；实装挂点变更后
   该论据更强，已写进 EXC。）
5. **纯逻辑与静态构造分离**：`[StaticConstructorOnStartup]` 类的**任何静态成员访问都会触发静态构造**
   ⇒ 在单测环境里会调 `ModLister`（Unity API）并崩溃。⇒ 全部纯逻辑（`Detect` / `Summarize`）
   放在 `PowerModDetector`，`PowerModAdapter` 只负责「调用一次 + 持有 readonly」。
6. **探测失败必须可见**：失败项**也进清单**（标 `ProbeFailed`，`Confirmed == false`），
   由诊断层记一条结构化 Warning。初版把它 drop 掉 ⇒ 失败被静默吞掉，
   而「该让位却没让位」正是最难查的那类（本工程已登记同型教训）。
