# 变更标注 · CHG-20261007-GRIDP3C

## 1. 修的缺陷

**实机 PM 报告**：断路器跳闸后，面板同时出现两条互相矛盾的文本 ——

```
未接入电网                                    ← 原版 CompPower 输出（断路器已断开）
本段负荷: 1,800 W / 额定 1,200 W              ← 我方输出（跳闸**前**的旧读数）
已跳闸: 速断
```

## 2. 根因

跳闸 ⇒ `TransmitsPowerNow = false` ⇒ 网重建 ⇒ 该断路器的 `CompPower.PowerNet` 变为 `null`
⇒ `GridTickDriver.AssembleSegments` 在 `net == null` 时 `continue`（如实不刷新读数）
⇒ 但 `lastLoadWatts` **保留跳闸前的数值**，而 `BuildInspectText` 照旧渲染它。

⇒ 违反 `LAND-009`（与「不编一个 0 W 出来」是同一条要求：**显示的必须是真实当前状态**）。

## 3. 修法（保信息 + 不撒谎）

| 动作 | 位置 |
|---|---|
| 新增 `tripLoadWatts` 快照字段（派生态，**不入存档**，与 `lastLoadWatts` 同规） | 字段区 |
| 跳闸时：快照 `lastLoadWatts` → `tripLoadWatts`，然后把 `lastLoadWatts` 复位 `-1` | `TryTrip` |
| 合闸时：两者一并复位（等下一个保护节拍重新测量） | `Reclose` |
| 重新测量时：若快照仍在（说明已恢复），作废它 | `ReportProtectionReading` |
| 跳闸态显示：**额定 + 跳闸时负荷 + 原因**，不再显示过时实时值 | `BuildInspectText` |

⇒ 跳闸诊断信息（跳闸那一刻多少 W）**保留**，但明确标注为「跳闸时」，不再是伪装成当前值的旧数字。

## 4. 未闭环

| # | 项 |
|---|---|
| 1 | 实机核对（需重启后触发一次跳闸，看面板是否只显示「跳闸时负荷」） |
| 2 | UI 批次其余项（五页 / 让位明示 / Settings 开关）—— 见交付报告的架构障碍说明 |

## 5. 回滚

单文件 + 两语言键，回滚即还原 `BuildInspectText` 与 `TryTrip/Reclose/ReportProtectionReading`；
`tripLoadWatts` 是派生态 ⇒ 回滚不影响任何存档。
