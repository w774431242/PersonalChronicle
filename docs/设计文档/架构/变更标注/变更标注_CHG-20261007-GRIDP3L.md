# 变更标注 · CHG-20261007-GRIDP3L

## 1. 本批是什么

「曲线」这一件的**最底层依赖**：把环形缓冲导出成曲线绘制需要的形状。

## 2. 入场条件已闭环（实测）

原以为需要自绘折线（可能触及「组件方向必须引用 RUIF」的红线）。实测 `Archive/UI/RuifBridge.cs` 已提供：

| 桥接方法 | 底层 | 用途 |
|---|---|---|
| `TryLineChart(Rect, float[], bool dots, bool grid)` | `RUIF.Charts.LineChart` | **单序列折线**（本项所需） |
| `TryAreaChart(Rect, float[])` | `RUIF.Charts.AreaChart` | 面积图 |
| `TryLineChartMulti(Rect, float[][], Color[], ...)` | `RUIF.Charts.LineChart` 多系列重载 | 多序列 |

⇒ 曲线**经 RuifBridge 走 RUIF**，不自绘，不违规。

## 3. 为什么顺序必须钉死（有反向对照）

`RUIF.Charts.LineChart` 收 `float[]`，**数组顺序即时间轴**。若导出写成"最新在前"，
曲线会**左右镜像** —— 而镜像的曲线看起来"就是一条曲线"，只是方向反了，**肉眼极难发现**。
⇒ 用例 `CopyValuesTo_IsOldestFirst` 专钉这一点。

另一处语义：缓冲短于窗口时**右端对齐**（保留最近点）—— 理由是"一段缺尾巴的古老历史"比"一段短一点的近期曲线"更糟。
