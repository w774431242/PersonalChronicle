## 二、关键判定

- **合成判决而不是两套并列规则**：`InterruptionVerdict`（§5 阶段定格 × §4 规定处置）成为所有失败记录的**唯一判决入口** —— 已结算 / 让路 / 适配未知三类零记录；只有「未结算且推进不完整」且该类规定要记账时才写一条。
- **依赖方向**：Automation 只上报事实（不判类、不记账），经济层经既有方向（Economy → Automation）在 Tick 中取走并定格；无反向调用、无静态可变状态、无新 Harmony；Automation 引用的原因码常量属既有 Capture → Automation → Domain 允许链。
- **不为车间事实新建持久化字段**：事实队列与退避账同为会话内状态（与既有 M9 口径一致）；读档代价 = 极少数未取走事实丢失，不涉及金额 / 权利 / 凭据 ⇒ **Save schema 与 Migration 均为「无」**。
- **不可回收货只记一条对账类记录，绝不自行「修复」**：购买完成失败且放回失败时，记一条 TransactionUnknown（对账类）把差异留在明面；不补钱、不删货、不改 M11 账目。（把该行提升为 SettlementPhase.ReconciliationRequired 会冻结整个结算账本，超出本批范围，登记为未做。）
- **不重复记账**：全工程 `RecordAttemptFailure` 现仅两处调用入口（ResolvePurchaseAttempt / ResolveWorkshopInterruption，同一判决文件），均先过合成判决；车间侧冷却内不重复记（MayAttempt 门）—— 一次中断在判决层至多一条是结构事实。
- **不重复付款**：本批零钱物副作用 —— 不放款、回滚路径行为不变、结算行阶段语义不变。
