## 3. 缺陷与教训登记

| ID | 问题 | 根因 | 处置 |
|---|---|---|---|
| `D-V21-1` | release-clerk 同步脚本首跑"报成功但实际未生效" | **CRLF 文件的 `(?m)$` 匹配坑**：.NET 正则 `$` 匹配 `\n` 前，行尾 `\r` 被算入行内容 ⇒ `[^\r\n]*$` 必然失败（首次仅无锚点的标题替换生效） | 改用 Python 整节重写（`newline=''` 保留换行 + `find` 锚点，避开正则锚点） |
| `D-V21-2` | 同脚本引入 `\r\r\n` 畸形换行（列表项间出现多余空行） | PowerShell here-string 内容为 CRLF + 脚本只归一了目标串未归一替换串，写回时二次转换 | 同上（Python 处理并清理 `\r\r\n` / 三连空行） |

> 教训：**跨 CRLF/LF 的 Markdown 定点替换，优先用 Python `newline=''` + `find/subn`**，不要用 PowerShell `-replace '(?m)^...$'`。
