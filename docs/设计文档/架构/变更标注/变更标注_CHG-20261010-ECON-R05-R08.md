## ECON-R06｜P1 欠薪没有有效重试入口 — **完成 · CodeVerified**

**复现（修复前）**：新工资支付**只**由 `ReportCraftIteration` 触发；支付失败后即使注资也再无机会到账 —— 证据已 Replay、单件上限不再接受新证据；旧 `Service.SettlePayables()` 位于 `LegacyFeesAllowed=false` 的**不可达分支**（`EconomyRuntime.GameComponentTick` 的 `if (!LegacyFeesAllowed || ...) return;`，已核实）。

**修改边界**：
- 新增 `RetryOutstandingPayables(Pawn, int)`：按 `Employment.ReadObligationsFor(PayeeKey)` 取未付应付账，逐条走既有 `TrySettlePayable`；
- 挂在 `OnPlanPublished`（设计认可的自然决策点，也是 M9 日额推进所在），**早于** `NewCommitmentsAllowed()` 制度门 —— **履约补付不是新承诺**，关制度不能吞掉既欠工资；
- **有界**（单次 ≤ 16 条）·**幂等**（命令 id `"wage:" + obligationId` ⇒ 重试永不重复支付）·失败即静默留待下次（资金不足不标失败，注资后自动到账）；
- 只补**剩余额**（`AmountMinor - PaidMinor`），与部分支付语义一致；合同终止不清应付（按 PayeeKey 读取，与合同状态无关）。

**针对性验证**：编译 0 错 0 警；全量 **1192 通过 / 0 失败 / 1 跳过**（`R05-R08.trx`，零回归）。
**剩余限制**：需真实 Pawn/地图 ⇒ **无离线测试面**；"工作完成时支付失败 → 之后注资 → 无需再做一件工作也能到账""退出或读档不丢应付""重试不重复支付"须游戏内验证（**GameVerified 未达**）。"读档恢复触发"依赖读档后首轮计划发布（非专门的读档钩子）；离图 Pawn 的应付账**保留但不重试**（`TryGetPlanningPawn` 拿不到 Pawn ⇒ 跳过），其生命周期清理属 R08 未完成项。

## ECON-R07｜P2 购买退避阻断求职及衣物 — **完成 · CodeVerified**

**复现（修复前）**：`OnPlanPublished` 中 `if (!MayAttempt(PawnId, "Purchase", "Food", now)) return;` ⇒ 食品动作退避把**后续衣物与 SeekWork 一并跳过** —— 没钱导致购买失败时，获得收入的路径反被延迟（越没钱越买不成 ⇒ 越求职不得）。

**修改边界**：改为 `if (MayAttempt(...)) { ...食品链... }` —— **只跳过被退避的动作**，衣物链与求职段照常推进。退避键本身已含动作类（`RetryKey(pawnKey, actionClass, reason)`），故隔离只需去掉整链 `return`。

**针对性验证**：编译 0 错 0 警；全量测试零回归（既有计划链测试未受影响）。
**剩余限制**：无离线测试面；"食品退避期间仍可签约""食品库存补充后只解除相关动作退避"须游戏内验证（**GameVerified 未达**）。报告提到的"买不起与永久无报价不应进入同一种短时重试策略"**未做** —— 当前 `ResolvePurchaseAttempt` 的判决分类未改（属 R09 报价粒度收口范围）。

## ECON-R08｜P2 退出条件不完整 — **部分完成 · CodeVerified**

**复现（修复前）**：`QueryContractExit` 的 `institutionOpen` 只读报价策略（`Open && PublishesWage`），**未读制度开关**；`positionAvailable` 只看区域存活（`IsAlive`），**不核对班次是否还在**。

**修改边界**：
- `institutionOpen` 增读 `QueryInstitutionMode().Desired` —— 玩家**主动关闭**才按清退语义释放存量合同；**仅"未就绪"（`AllReady=false`）不清退**（那是"不能签新的"，不是"旧的要撤"）；
- `positionAvailable` 增读 `HasShiftRecord`（新增私有 helper）：只判**班次记录是否存在**，**不**用 `FindShift`（它含 `InTime` 检查 ⇒ 时段外只是"现在不能开工"，用它判定会让夜班合同每个白天被误退一次）。

**针对性验证**：编译 0 错 0 警；全量测试零回归。
**未完成（如实登记）**：① **岗位租约**未建立 ⇒ 退出时无租约可释放（依赖 R05 的租约落地）；② **Pawn 能力禁用**未纳入退出判据（需能力↔工作类型的权威映射）；③ **无地图 Pawn 的生命周期清理**未设计；④ **玩家改写优先级**触发退出复核未接；⑤ "显式释放工作类型"沿用既有 `Terminate` + `ReleaseWorkTypes` 路径，**未新增独立清退语义**。以上均为报告 R08 验收项，须与 R05 的租约一并收口。

## ECON-R05｜P1 签合同没有占用岗位或预留工资 — **部分完成 · CodeVerified**

**复现（修复前）**：`TrySignForOpportunity` 的签约后处理只写合同并 `ApplyWorkTypes`，**不检查其结果** ⇒ 工作类型一个都没启用时，仍返回成功，留下"签了却去不了"的幽灵合同（与验收第 4 条"工坊不可执行时不留下幽灵合同"直接冲突）。

**修改边界**（本批只做了可证明的最小修复）：新增 `AllTypesUsable` 复核 —— 签约后按**原版工作优先级 > 0** 逐类型验证执行前提真的成立（**不**用 `ApplyWorkTypes` 的返回计数：玩家已手动开启的类型不计入 `applied` 但仍满足前提）；前提不成立 ⇒ `Employment.Terminate(合同)` + `reason = "WorkTypesNotEnabled"` 并返回失败。

**未完成（如实登记，均为报告 R05 验收项）**：
1. **岗位竞争裁决**（"两人争一个空位只成功一个"）—— 需在 data 层新增"按 `PositionKey` 枚举活跃合同"的只读入口（`EmploymentSaveData` 现仅暴露 `ReadContractsFor(pawnKey)`/`Count`，`ContractRow.PositionKey` 已存在但无按岗位查询）；
2. **工资预留**（"余额只够一人时不签两份保证支付合同"）—— 需机构公共账户余额查询 + 预留语义设计；
3. **岗位租约**（班次占用登记/释放）；
4. **旧体系隔离**（新字符串合同 ↔ 旧 `EconomicContractId` long 合同的明确映射或隔离）。
5. **"一次提交内复核空位/能力/报价版本/实际资金，提交失败统一撤销"**的原子提交语义未建立（当前是顺序检查 + 局部回滚）。

**剩余限制**：`AllTypesUsable` 需真实 Pawn ⇒ 无离线测试面。
