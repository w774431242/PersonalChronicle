## 四、设计决策（如实记录）

1. **「应用」按钮文案**：要求"提交入口收敛为卡脚一个「应用」"，但硬红线同时要求"只走既有键"且不得新增裸键 ⇒ 采用**原版既有 `Confirm` 键**（zh「确定」/ en「Confirm」）作卡脚提交按钮，语义=确认并应用本卡草稿。**未新增任何语言键**。
2. **分页 vs 虚拟化（台账/库存无界）**：选择**分页**（每页 100 行；行数 ≤100 的页签零视觉变化）。理由：分页同时给"测量"与"绘制"一个成本上界（原实现每 60 tick 全量重测全部行）；分页栏用 `<` `>` 图标按钮 + `n / m` 数字（无语言依赖、零新增键）；不引入新持久状态。
3. **行卡片 vs 说明行**：数据行卡片化；`HintRowVerb` 说明行保持次要色文本（信息层级：说明是分区层、不是列表项）。
4. **破坏性按钮色调**：`Terminate` / `Withdraw` / `Cancel` 三个动词 → `ButtonTone.Danger`（其余 Default）；统一视觉语言的"危险"语义，不动任何命令。
5. **草稿（draft）为会话态**：政策编辑不写数据、不进 Save；提交成功或失败都清除草稿并刷新快照（失败走既有「修改被拒绝 · 错误码」消息——保持"过期修改会被拒绝"的既有语义，不做静默 rebase）。
6. **机构卡保持不变**：机构页卡片为已交付样板，本批只迁出 `CardStackGap` 定义、删除其未用属性，不改其绘制细节。
