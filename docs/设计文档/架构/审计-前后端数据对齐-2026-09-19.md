## 4. 🔴 已修复：`Weight01` 索引错位（**本轮唯一代码改动**）

**位置**：`Application/SystemCenters/Builtin/BuiltinEconomyProvider.FlowGraph.cs:161-169`

```csharp
// 旧（错）：snapshot.Edges 是**过滤后**的子集，却用它的下标 i 去取**未过滤**的入参 edges
for (int i = 0; i < snapshot.Edges.Count; i++)
{
    EconomyFlowEdge e = snapshot.Edges[i];
    float baseline = edges[i] != null ? edges[i].Baseline : 0f;   // ← 张冠李戴
    e.Weight01 = baseline / maxFlow;
}
```

**为什么必然错**：边循环在 `:145-149` 对"一端被封顶截掉"的边 `continue`，在 `:136` 对超过 `MaxFlowEdges` 的边不纳入
⇒ **只要有一条边被跳过，其后所有边的权重整体错位**。

**影响链**（前端拿到的数字是错的）：
`edge.Weight01` → `EconomyInventoryChainPanel.cs:358-362`（**下游 TOP3 排序**）+ `:253`（**链路条宽**）
⇒ 表现为"**看起来完全正常，但顺序和长度是错的**"，无任何报错。

**修法**（零分配、结构上不可能再错位）：第一遍把 `e.Baseline` 存进 `Weight01` 作占位，第二遍**只遍历 `snapshot.Edges` 自身**就地归一化。

**验证**：编译 0 错 0 警 · 单测 400 通过 · 双区 dll MD5 一致 · GATE-DELTA PASS。

## 6. 复核方法（可重跑）

- 三向对齐：字段名 + `.字段名` **双形态**全仓检索（避免 substring 误命中）；同名字段按类限定防串味；对 `List<T>` 额外查"是否只被 `Add` 而无人遍历"。
- 派生/硬编码：`\* 100f` · `+ "%"` · `Mathf.Round` · `.Sort(` · `.Sum(` · `new Color(` · `Translate(` · 中文字面量正则 `"[^"\n]*[一-龥][^"\n]*"`（排除注释行）。
- 真实性：先读 `SystemCenterDataRegistry.cs` 定位注册面，再逐个 Provider 查字面量赋值，并对"本可从哪个原版 API 取"给出处；确无 API 的标注"官方无此字段"（合规）。
- ⚠ 计数类结论为**关键词命中数 + 逐文件审阅**的粗估，不是精确行占比；`文件:行号` 均为实测。
