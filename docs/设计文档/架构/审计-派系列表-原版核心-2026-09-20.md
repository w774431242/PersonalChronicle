## §3 发现清单

### P1-A（记录级证伪）：「PlayerColony 的 FactionDef 是 hidden=true」**不成立**，且写入 6 处载体

- **四重证据**：Core/Odyssey XML 无 `<hidden>`（§1-10）· 预览数据集玩家派系理由**不含**「隐藏派系」（HTML:442）· 项目自己的派生脚本就写着 `"hidden": False`（`_scripts/extract_faction_rules.py:54`）· "任何以 `def.hidden` 为输入的过滤都不可能滤掉 PlayerColony"（逻辑闭环）。
- **旧因果不可考**：`BuiltinEconomyProvider.FactionStatus.cs` **未入库**（`git status` = `??`，无历史版本）⇒「旧规则为何滤掉玩家殖民地」**无法从 git 追溯**；候选（旧规则用运行期 `Faction.Hidden`、或走了别的可见集）**均未取证**，不得当作事实引用。
- **可证实版本（正稿）**：> 「原版 `PlayerColony.def.hidden = false`（Core 未设置、默认 false）。玩家殖民地曾被列表排除**与 `def.hidden` 无关**；真实排除条件待补证。现行 `f.def.hidden && !f.IsPlayer` 里的 `!f.IsPlayer` 只对『def.hidden=true 的**第三方**玩家派系』起兜底作用。」
- **更正载体（6 处）**：①`Source/…/BuiltinEconomyProvider.FactionStatus.cs:94-98` ②EN `MVS.xml:410-411` ③ZH `MVS.xml:424-425` ④`Change-Annotation-CHG-MVS-ITEMFLOW-001.md:300` ⑤`SDD_物品级产消读数.md:259-262` ⑥`审计-经济中心五面板-2026-09-20.md:84`。
- **建议追加**：实机复验「点击玩家殖民地行 → 选中保持」归档为更正凭据。

### P1-B（前审计更正）：物品级 ② 实测「两层断死」→ **一层**

解析器条件 `!f.def.hidden`（`SystemCenterReadModelProvider.cs:538`）对 `def.hidden=false` 的 PlayerColony **不构成拒绝** ⇒ 原「永远选不上/点了复位」**不成立**（可显式选中且保持；「默认选中不会落到它」仍成立——回落链优先可画像派系）。**剩余唯一门 = 画像门禁** `IsEconomicallyModeled` 显式排除 `FactionDefOf.PlayerColony`（`FactionProfileAdapter.cs:171-173`）⇒ `TryGetProfile` false ⇒ 市场面板未建模早退（`MarketPanel.cs:73-84`）⇒ ② 读数无出口。**根问题收敛为一条设计冲突：『玩家殖民地想看实测』 vs 『6 规则门禁排玩家』**（待裁决）。

### P2-A：11 个 hidden 派系的行集偏离**未登记** + 三处「31=可见数」误述

- 预览「全部」= 31 行（含 11 hidden 作不可贸易行）；我方排除 11 hidden ⇒ 恒到不了 31/31，副标分母 = 运行期非 hidden（+玩家）实例数。11 个 hidden 已逐个对齐（Core 4：Ancients/AncientsHostile/Mechanoid/Insect；Ideology 2：Beggars/Pilgrims；Royalty 1：OutlanderRefugee；Biotech 1：Sanguophages；Odyssey 1：Salvagers；Anomaly 2：HoraxCult/Entities）。
- 「31=可见数」误述 3 处：`FactionStatus.cs:32-34`（"可见派系约 31 个"）· `changelog/v1.4.x_2026-09-18_…五面板1比1落地.md:84` · 对照清单 §3-6/§3-9。
- 语言包注释自引 `9 / 31` 例子（EN:154 / ZH:161）——我方永不输出该分母，注释误导。

### P2-B：`TechRank` 缺 `Archotech` 且与 `TechLevelRank` 分叉

`FactionStatus.cs:275-287`（Animal..Ultra + default 0）漏 **Archotech**（枚举第 8 值已证）；而同 partial 类的 `TechLevelRank`（`BuiltinEconomyProvider.cs:352-365`）已有 `Archotech=6` ⇒ **Archotech 派系：科技列显示「远古科技」但不高亮、色点 Flat，同屏 KPI 却满档**。两映射近重复已分叉（违反 `TechLevelBridge` 自述纪律）。

### P2-C：`EconomyPanelChrome` 副标截断无悬停 —— 对本面板的**异常态**不可接受

本面板副标 = `N / M` + 「市场因子待启动」/「存档来自更新的版本 · 只读降级」（`ComposeSub` 绘制期拼接）。bar.width≈377 ⇒ sub 上限≈128px：正常态可接受；**叠加状态词后中段被吞且无悬停可查**——而该副标是「因子未就绪 vs 未接入/只读」的唯一可区分出口（Provider 注释明言"必须可区分"）。一处收口修 `C:165-167` 四参重载即惠及五面板。

### P2-D：色点实际渲染 = **纯红** ≠ 登记「琥珀」；同文件两映射对 Warn 分歧（主复核）

`DotToneForTech(Medieval)→Warn` → `ToneColorOr(Warn)` = `UITheme.Warn` = **Epic(1.000, 0.000, 0.000) 纯红**（`UITheme.cs:453`）；而 `ToneColor(Warn)` = `UITheme.Threat` = 橙(0.878,0.494,0.196)（`UITheme.cs:459`）。⇒ ① 与对照清单 §4-5 登记口径「Medieval 琥珀」**不符**；② Animal→Dead(深红) 与 Medieval→纯红 为**两个近红**，"一眼分组"目的被削弱；③ `ToneColor`/`ToneColorOr` 对同一 tone 给出不同色，另有 5 处调用点（市场×3 / FactionDetail×2）依赖。
