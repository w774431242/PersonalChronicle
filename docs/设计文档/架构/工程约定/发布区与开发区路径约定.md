# 发布区与开发区路径约定

本约定于 2026-10-05 修订；发布包内容、清理和体积要求见 [发布区发布规范准则](发布区发布规范准则.md)。

## 发布区（游戏实际加载的 mod 目录）
```
E:\SteamLibrary\steamapps\common\RimWorld\Mods\殖民地综合管理系统
```
- 游戏从此目录加载 mod，其中 `Assemblies\PersonalChronicle.dll` 是运行中的 dll。
- **改 bug / 加功能后，必须把开发区编译产物同步到此目录，否则游戏仍跑旧 dll。**
- 当前名称：殖民地综合管理系统；版本：0.1；packageId：`colony.integratedmanagement`。
- 原 `Mods\PersonalChronicleVer0.1` 仅保留为旧版，默认部署、同步与审计不再指向它。

## 开发区（源码与编译产出目录）
```
E:\SteamLibrary\steamapps\common\RimWorld\11\殖民地综合管理系统
```
- `Source\` 源码；`Assemblies\PersonalChronicle.dll` 由 `run_csc.ps1` 直接编译输出到此。
- 注意：此目录**不是**游戏加载处。它只是开发工作区。
- 开发区已从 `11\PersonalChronicle` 迁入上述中文目录，源码、Git、备份与发行材料均已迁移。旧目录受当前会话占用，仅保留“开发区已迁移.txt”提示，不再用于开发。
- 内部 `Source\PersonalChronicle`、项目文件名、程序集名和类型命名保持兼容；开发区名称与发行目录名称均为“殖民地综合管理系统”。

## 同步规则
- dll 变更：编译到开发区 `Assemblies\` 后，通过 `_scripts/deploy-to-game.ps1` 同步当前 DLL 与运行资源；部署备份只写开发区 `_backups/release-deploy/`，不得把 `.pdb`、`.bak_*`、`.locked_*` 留在发布区。
- 资源目录（`Defs\` `Languages\` `Textures\` `Patches\` `Fonts\`）有修改时同样部署并核对逐文件哈希；历史核对结果不能证明当前一致。
- 已上传条目的目标工坊 ID 必须保留，部署脚本绝不从开发区复制该文件；新账号首次创建新条目时，开发区和新包都不带旧 ID。预览图、截图和字体许可证按发行白名单同步并保留。
- 切勿反向：不要把发布区旧 dll 覆盖开发区新 dll。

## 历史教训（2026-08-25）
- 曾误以为 `11\PersonalChronicle` 是发布区，导致发布的 dll 是旧版（缺 `Patch_RoomRoleLabel`/`Patch_BuildingLabel` 等修复），表现为"patch 静默不生效、日志里 PC 只有 1 条 patch"。
- 用户提供的 HugsLib 日志（`Active Harmony patches` 中 PC 仅 `Patch_BillProduction` 一条）即源于此：发布区加载的是旧 dll。
- **铁律**：每次修复后，先确认发布区 `Assemblies\PersonalChronicle.dll` 的修改时间/哈希与开发区一致，再让用户重启验收。
