# PersonalChronicle 发布区发布规范准则

生效日期：2026-10-05。适用范围：本项目开发区向游戏加载目录部署，以及从该目录提交 Steam 创意工坊内容。本文是 [06-变更日志与发布规范](../06-变更日志与发布规范.md) 中发布包检查的项目细则。

## 1. 路径与职责

| 区域 | 路径 | 职责 |
|---|---|---|
| 开发区 | `E:\SteamLibrary\steamapps\common\RimWorld\11\殖民地综合管理系统` | 源码、构建、测试、规范、日志、清单与历史归档 |
| 发布区 | `E:\SteamLibrary\steamapps\common\RimWorld\Mods\殖民地综合管理系统` | 当前版本的游戏运行资源、玩家说明与发布展示资源 |
| 部署回滚备份 | 开发区 `_backups\release-deploy\` | 被覆盖的 DLL 与资源；不得放入发布区 |
| 发布区历史归档 | 开发区 `_backups\release-cleanup_<时间戳>\` | 清理时的历史文件、SHA-256 清单及清理报告 |

开发区是源码与构建产物的维护源；发布区是本地游戏加载位置。不得将发布区整个目录反向覆盖开发区。工坊上传使用发布区，不能选择开发区或备份目录。

## 2. 发布内容白名单

| 路径 | 允许内容 |
|---|---|
| `Assemblies/` | 当前运行 DLL；当前本项目为 `PersonalChronicle.dll` |
| `About/` | `About.xml`、`PublishedFileId.txt`、`Preview.png`、`Screens/` 下明确用于展示的图片 |
| `Defs/`、`Patches/` | 当前有效的 XML，含子目录 |
| `Languages/` | 当前有效的语言 XML，含 Keyed 与 DefInjected 子目录 |
| `Textures/` | 当前需要的 PNG/JPG，含子目录 |
| `Fonts/` | 当前需要的字体及配套许可证文本；许可证必须随字体保留 |
| 根目录 | `README.md`，以及确有发行需要的许可证文件 |

新增 DLL、资源类型或顶层目录，必须先说明用途并更新此白名单及部署范围。DLL 依赖以 `About.xml` 为准；不得为了省事复制其他 Mod 或游戏程序集。

当前发行名称为“殖民地综合管理系统”，版本 0.1，packageId 为 `colony.integratedmanagement`。原 `Mods/PersonalChronicleVer0.1` 与旧 ID `3780570854` 只作为旧版保留。

新账号首次创建新条目时，开发区和新发布目录不携带旧 `About/PublishedFileId.txt`。上传成功后，目标目录保留游戏写入的新 ID；清理和后续部署不得改变它，部署脚本也不从开发区复制 ID。预览图和截图属于发布展示资源，不按历史文件清理。

## 3. 禁止进入发布区的内容

- 所有备份目录：`_backups/`、`_backup/`，以及完整历史发布包。
- 历史副本与占用绕行文件：`*.bak`、`*.bak_*`、`*.locked_*`、`*.old`、`*.orig`；如有特殊同名运行资源，先核实用途。
- 调试符号及编译中间文件：`*.pdb`、`bin/`、`obj/`。
- 源码、测试、工具、开发文档、日志、取证数据和临时素材：`Source/`、`Tests/`、`_scripts/`、`docs/`、`.git/`、AI 会话缓存等。
- 已删除功能遗留的 DLL/XML/资源。资源退役须有明确清单并检查引用，不能仅凭时间戳判断。

Git 忽略规则只控制版本管理，不能证明发布目录干净。发布前必须实际枚举整个目录，不能仅检查本次复制的文件。

## 4. 备份与清理规则

先归档，验证归档，再移除发布区副本。归档必须在开发区内，并保持原相对路径；每个文件记录大小和 SHA-256。全部归档校验成功后才开始逐文件删除；发现源文件变化立即停止。清理后，保留文件的数量与 SHA-256 必须与清理前一致。

本项目使用 `_scripts/clean-release-history.ps1`：

```powershell
Set-Location 'E:\SteamLibrary\steamapps\common\RimWorld\11\殖民地综合管理系统'
& .\_scripts\clean-release-history.ps1         # 默认仅预览
& .\_scripts\clean-release-history.ps1 -Apply  # 归档、校验、清理
```

该工具只识别 `_backups/` 内文件、`.bak` / `.bak_*`、`.locked_*` 和 PDB。其他未知文件、旧资源或新增备份命名必须另行核实，不会自动删除。脚本拒绝 packageId 不匹配、开发区与目标互相包含、发布区含链接等情况。

归档目录内：

- `files/`：历史文件，保持发布区相对路径。
- `archived-files.csv`：历史文件路径、字节数与 SHA-256。
- `retained-before.csv`：保留文件路径、字节数与 SHA-256。
- `cleanup-report.json`：目标、归档位置、前后体积及校验结果；仅成功完成才生成。

备份保留与到期处置在开发区进行，不得通过放回发布区实现回滚留档。需要回滚时只恢复明确版本所需的运行文件，并再次核对哈希。

## 5. 部署规则

1. 确认目标 `About.xml` 的 packageId 与开发区一致。涉及运行 DLL 的部署应先退出 RimWorld。
2. 完整部署使用 `_scripts/deploy-to-game.ps1`，默认备份写开发区 `_backups/release-deploy/deploy_<时间戳>/`。日常不得使用 `-SkipBackup` 绕过回滚留档。
3. `_scripts/sync_release.ps1` 是指定文件的局部同步工具；其 DLL 备份同样写开发区。局部同步结果不能代替完整发布包检查。
4. 部署采用递归枚举，必须包含 Defs 与 Languages 子目录；核对复制数量、文件大小和哈希。
5. 当前部署脚本同步运行资源、`About/Preview.png`、`About/Screens/` 与根目录 README，不自动删除目标中的旧资源。精确文件采用 LiteralPath，禁止通过递归匹配带入开发目录中的同名 README。工坊 ID 由目标上传端维护。
6. 禁止用目录镜像清空发布区；删除旧文件必须先列清单、归档，并保护工坊 ID、预览图、截图和字体许可证。

## 6. 体积核验与上传门槛

发布前记录全目录字节数、文件数量、顶层目录占比及最大文件，并确认没有任何禁止内容或未说明的额外文件。

2026-10-05 清理基线：

| 状态 | 文件数 | 字节数 | MiB |
|---|---:|---:|---:|
| 清理前 | 4,518 | 1,255,002,076 | 1,196.863 |
| 历史及调试文件 | 4,377 | 1,224,186,050 | 1,167.475 |
| 保留发行内容 | 141 | 30,816,026 | 29.388 |

MiB 按 1,048,576 字节计算，十进制 MB 按 1,000,000 字节计算。不得混用单位解释工坊显示值。

以本次约 29.39 MiB 为基线，本项目采用以下排查阈值：总大小超过 50 MiB，或比上一发行基线增加超过 20%，必须先解释增量来源并记录资产清单，再上传。这是本项目的体积治理阈值，不是 Steam 技术限制。合法资源扩充时同步更新基线，不能静默忽略异常增长。

在开发区执行体积与 DLL 核验：

```powershell
$publish = 'E:\SteamLibrary\steamapps\common\RimWorld\Mods\殖民地综合管理系统'
$files = @(Get-ChildItem -LiteralPath $publish -Recurse -File -Force)
$bytes = ($files | Measure-Object Length -Sum).Sum
'files={0}; bytes={1}; MiB={2:N3}' -f $files.Count, $bytes, ($bytes / 1MB)
$srcHash = (Get-FileHash -LiteralPath '.\Assemblies\PersonalChronicle.dll' -Algorithm SHA256).Hash
$dstHash = (Get-FileHash -LiteralPath "$publish\Assemblies\PersonalChronicle.dll" -Algorithm SHA256).Hash
if ($srcHash -ne $dstHash) { throw '发布 DLL 与开发区不一致' }
& .\_scripts\clean-release-history.ps1  # 待归档数必须为 0；仍需检查其他禁止内容
```

## 7. 上传前后检查

- 上传前：编译与适用测试通过；项目适用 Gate 无 BLOCKED；依赖、版本、语言、存档兼容及 changelog 按上级规范核验。
- 发布包：禁止内容为零；packageId、工坊 ID 正确；所有部署文件与选定构建一致；展示资源及字体许可完整；体积变化有说明。
- 实机：重启 RimWorld 后核对加载、日志与本次修改涉及的界面/功能；部署成功与哈希一致只证明文件同步，不能代替实机验证。
- 上传后：核对工坊页面版本、更新时间与体积；必要时验证实际订阅副本。清理本地目录不会自动改变已经上传的工坊内容，必须重新提交更新。
- 发布证据：在开发区保留构建/部署日志、清单、哈希、体积统计和实机结论。若未做实机或工坊核验，明确记录“未验证”。
