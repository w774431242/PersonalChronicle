# Personal Chronicle · 开发者手册（Developer Guide）

> 面向想要**读懂、二次开发、贡献代码或与其他 Mod 集成**的开发者。
> 玩家向说明请看根目录 `README.md`。
>
> 版本范围：RimWorld **1.6** / net48 / C# 9.0 / Harmony。代码基底 v1.2.0。

---

## 0. 一句话定位

Personal Chronicle 是一个**事件采集 + 领域建模 + 只读档案 UI** 的殖民地档案馆 Mod。它在游戏运行时通过 Harmony 补丁捕获 `加入 / 死亡 / 制造 / 建造 / 战斗 / 社交` 等事件，沉淀成领域对象，持久化进存档，再以「Read Model 快照」喂给纯展示用的 UI 层。

架构关键词：**单向分层、契约接口、数据驱动、UI 零硬编码**。

### ⚠️ 发布区与开发区（最高优先级陷阱）

| 目录 | 角色 |
|---|---|
| `e:\SteamLibrary\steamapps\common\RimWorld\11\PersonalChronicle` | **开发区**（源码 + 编译产物）。游戏**不**从此加载。 |
| `E:\SteamLibrary\steamapps\common\RimWorld\Mods\PersonalChronicleVer0.1` | **发布区**（游戏实际加载的 Mod 目录）。 |

**`run_csc.ps1` / `dotnet build` 只把 dll 输出到开发区 `Assemblies\`，不会自动进发布区。** 你改完代码、编译成功，**必须手动把 `PersonalChronicle.dll` + `.pdb` 复制到发布区 `Assemblies\`**，否则游戏跑的是旧 dll——表现为「修复无效、Harmony patch 不生效、日志 patch 数异常」。

> 历史教训：曾因发布区是旧 dll（缺 `Patch_RoomRoleLabel`/`Patch_BuildingLabel`），HugsLib 日志里 Personal Chronicle 仅 1 条 patch，误判为代码 bug。铁律：**每次修复后，先核对发布区 dll 的修改时间/哈希与开发区一致，再让用户重启验收。**

## 2. 构建与运行

### 2.1 依赖
- RimWorld 1.6（程序集 `Assembly-CSharp.dll` 等，位于游戏 `RimWorldWin64_Data\Managed\`）
- Harmony（`0Harmony.dll`）
- .NET 8 SDK（用于 `csc.dll` 编译；无需 Visual Studio）
- 无第三方 NuGet 业务依赖（仅 `Microsoft.NETFramework.ReferenceAssemblies` 辅助编译）

### 2.2 编译
推荐（一键，含响应文件避免命令行过长）：
```powershell
# 仓库根
.\run_csc.ps1
# 实际调用 _scripts\compile_with_sdk.ps1（.NET 8 SDK csc.dll + .rsp）
```
或标准 SDK 方式：
```bash
dotnet build Source/PersonalChronicle.csproj -c Release
```
- 产物：`Assemblies\PersonalChronicle.dll`
- `csproj` 中 `RimWorldPath` / `HarmonyPath` 可按机器覆盖（默认指向 Steam 库）。

### 2.3 部署到发布区
```powershell
$pub = "E:\SteamLibrary\steamapps\common\RimWorld\Mods\PersonalChronicleVer0.1\Assemblies"
Copy-Item Assemblies\PersonalChronicle.dll $pub\ -Force
Copy-Item Assemblies\PersonalChronicle.pdb $pub\ -Force
```
建议先备份旧 dll（如 `PersonalChronicle.dll.bak_<时间戳>`）。资源目录（Defs/Languages/Patches）通常已与开发区一致，改动时同样复制对应文件，**切勿反向覆盖发布区特有资源（如多出的 Textures）**。

### 2.4 启动验证
进入游戏 → 主界面底部出现「档案馆」按钮即成功。调试：`ChronicleSettings.DebugLiveCount` 等。

## 3. 分层架构与依赖

单向依赖（编译期）：

```text
   Archive (UI) ──▶ Application ──▶ Domain ◀── Data (持久化)
        │                                    ▲
        │                                    │
        └────────────────────────────────────┘
                     Capture (Harmony) ──▶ Domain
                          │
                          ▼
                        Api (门面，对外)
```

- **UI 不碰 Domain**：只读 `Application` 构建的 **Read Model 快照**（§4.3）。
- **Application** 编排 Domain 对象、查询、构建快照；不直接写存档。
- **Domain** 是核心模型，无外部依赖；Data/Capture 都向它写入。
- **Capture** 通过 Harmony 拦截原版方法，把游戏事实翻译成领域事件写入 Domain。
- **Api** 把上述能力收敛成一个对外门面（`IPersonalChronicleApi`），供其他 Mod 集成。

## 4. 各层详解

### 4.1 入口与生命周期
| 文件 | 职责 |
|---|---|
| `ChronicleMod.cs` | `Mod` 子类（组合根）。构造时持有静态单例、恢复 UI 主题、装配 `ArchiveService`（同时实现 `ArchiveService`/`WorkIntensityService`/`WorkTimeCaptureService` 三接口）、注册四个内置域提供方、构建 API 门面。 |
| `ChronicleStartup`（`[StaticConstructorOnStartup]`） | **Harmony 注入点**：`new Harmony("PersonalChronicle.Archive").PatchAll(Assembly.GetExecutingAssembly())`。与 `ITab` 注入两个独立 try 块，互不阻断。启动校验事件类型键与 Def 是否漂移。 |
| `ChronicleSettings.cs` | `ModSettings`：`EnableRecording` / `MaxEventsPerPawn` / `ThemeId` 等，经 `ExposeData` 持久化。 |
| `ChronicleLog.cs` | 集中日志 `[PersonalChronicle][Category]`，7 类（Capture/Archive/Provider/Save/Compatibility/Ui/Mod）。 |

> **PatchAll 的硬规则**：`[HarmonyPatch]` 标注的类**必须是 `public`**。`PatchAll(Assembly)` 默认只扫描 `public` 类型；`internal` 的 patch 类会被**静默跳过**（日志无任何报错，最难排查）。新增/改动 patch 时务必检查类可访问性。

### 4.2 `Archive/`（UI 层）
命名空间 `PersonalChronicle.Archive`，呈现令牌在 `PersonalChronicle.Archive.UI`。

| 关键文件 | 作用 |
|---|---|
| `ArchiveMainTabWindow.cs`（+ 多个 `.partial`：`Home/Overview/Pawn*/WeaponDetail/EventDetail/Location/Shell/Cache`） | 主窗口骨架与各视图绘制。导航状态 `MainView{Home,Overview,PawnDetail,...}`，由 `Defs/MainButtonDefs.xml` 的 `tabWindowClass` 引用。 |
| `ArchiveUiStyle.cs` | 兼容壳：把历史 `ArchiveUiStyle.*` 转发到 `UITheme`（令牌）+ `UIComponents`（组件），约 120 处调用零改动。 |
| `ReadModels/SectionSnapshots.*.cs` | **Read Model 快照类**（`ArchiveSectionSnapshot` + Detail/Home/Overview/Event/Career）。UI 只读这些，不直接碰 Domain。 |
| `UITheme.cs` / `UIComponents.cs` / `ArchiveUiStyle.cs` | 设计系统两层：**令牌（颜色/字号）** + **组件（卡片/按钮/可点击卡）**。禁止在窗口内散落 `GUI.color = new Color(...)`。 |
| `ITab_Pawn_Chronicle.cs` / `ITab_Pawn_Career.cs` | 注入到每个 humanlike Pawn 的 inspect 标签页（六宫格档案 + 职业档案）。 |
| `ChronicleInspectTabInjector.cs` | 启动时把 ITab 注入所有 humanlike `ThingDef`（遍历 `DefDatabase`，幂等、失败隔离）。 |
| `Dialog_*.cs` | 各类弹窗（改名/授勋/资格/方向/工坊列表等）。 |

**UI 规范（来自项目实践）**：
- 所有颜色/字号走 `UITheme` 令牌，绘制态改变 `GUI.color` 必须配对恢复。
- 中文行高经验值；窗口只消费 Read Model 快照，不在窗口内排序/null-guard。
- 玩家可见文本全部走翻译键，UI 零硬编码。

### 4.3 `Application/`（应用服务层）
- `IArchiveService` / `IArchiveQueryService`：查询 + 写入口。
- `ArchiveUiDataProvider.*`：把 Domain 聚合根**投影成 Read Model 快照**（按视图拆文件：Detail/Home/Overview/Event/Career）。
- 编排 `WorkIntensityService`（强度五档，阈值由 `WorkIntensity.xml` 驱动）。

### 4.4 `Domain/`（领域模型）
- 聚合根：`PawnObject` / `ThingObject` / `BattleObject` / `PlaceObject` 等。
- 事件模型：`ChronicleEvent` + `ChronicleEventDef`（数据驱动，缺翻译键优雅降级为类型名）。
- 值对象：强度评级、社会关系、健康残值等。
- 仓储接口 + 域提供方契约（`IArchiveProvider` 及子接口，见 §4.7）。
- 命名约定：命名空间 `PersonalChronicle.Domain.*`，大量 `partial` 类按职责拆文件（如 `PawnObject` 拆成生涯/战斗/社交/足迹等 partial）。

### 4.5 `Data/`（持久化）
- `ChronicleGameComponent`（继承 `GameComponent`）：存档载体，通过 `ExposeData()` + `Scribe_*` 序列化全部领域对象进存档。
  - 拆 partial：`Aliases`（改名别名）/ `Battle` / `Qualification` / `Queries` / `Sampling`（活读统计）/ 主文件。
  - Schema 版本当前为 3，老档自动无损迁移。
- `WorkIntensityDefCatalog.cs`：强度阈值目录（Def 驱动）。
- 中途加装存档：读档时自动把当前在场人口建档（reconcile 兜底），缺的是加装前历史。

### 4.6 `Capture/`（Harmony 采集层）
21 个文件、23 处 `[HarmonyPatch]`。每个文件聚焦一个原版拦截点，**仅在事件发生的那一刻记录**。

| 关键 Patch | 目标 / 作用 |
|---|---|
| `Patch_BillProduction` | `Bill_Production.Notify_IterationCompleted` — 制造完成 |
| `Patch_GenRecipe` | `GenRecipe.PostProcessProduct` — 配方产出（⚠ 2026-09-20 更正：目标一直是 `PostProcessProduct`；`MakeRecipeProducts` 由新文件 `Patch_ItemFlowIngredients` patch） |
| `Patch_ItemFlowIngredients` | `GenRecipe.MakeRecipeProducts`（Prefix）— 物品级产消：配方原料消耗（2026-09-20） |
| `Patch_ItemFlowMining` | `Mineable.DestroyMined` — 物品级产消：采矿产物（2026-09-20） |
| `Patch_ItemFlowPlant` | `Plant.PlantCollected`（Prefix）— 物品级产消：收获/砍伐产物（2026-09-20） |
| `Patch_GenConstruct` | `Frame.CompleteConstruction` — 建造落成 |
| `Patch_PawnKill` | `Pawn.Kill` — 死亡（含死因/凶器关联） |
| `Patch_PawnTakeDamage` | `Pawn.TakeDamage` — 战斗伤害（战斗履历） |
| `Patch_ThingDestroy` | `Thing.Destroy` — 物品销毁 |
| `Patch_ThingIngested` | `Thing.Ingested` — 消耗 |
| `Patch_Relations` | `Pawn_RelationsTracker.Add/RemoveDirectRelation` — 社交关系 |
| `Patch_SetFaction` | `Pawn.SetFaction` — 阵营变更 |
| `Patch_RaidLordPawnLost` | `Lord.Notify_PawnLost` — 袭击战损 |
| `Patch_IncidentWorker` | `IncidentWorker.TryExecute` — 事件（战役） |
| `Patch_RoomRoleLabel` | `Room.GetRoomRoleLabel` — **房间改名反映到原版信息面板**（public） |
| `Patch_BuildingLabel` | `Thing.get_Label` — **建筑别名反映到原版 UI**（public） |
| `Patch_PawnTitleBadge` / `Patch_SkillRecord_Learn` | 头衔徽章 / 技能学习 |

**签名漂移防护范式**：多个 patch 内含「缓存签名探测」——目标方法签名在原版更新后漂移时，`[HarmonyPatch]` 会静默跳过；代码在启动时显式探测并 `Log.Warning`，便于第一时间发现采集断点。

### 4.7 `Api/`（对外集成门面）
第三方 Mod 集成入口，全部 `public`。

| 公开类型 | 作用 |
|---|---|
| `PersonalChronicleApi`（静态类） | **门面获取入口**：`PersonalChronicleApi.TryGet(out var api)`。api 为 null（未加载/未初始化）时返回 false，调用方须优雅处理。 |
| `IPersonalChronicleApi` | 聚合门面：含 `ApiVersion` + 多个 Capability 子接口（`Events`/`Pawn`/`Thing`/`Battle`/`Place`/`Relation` 等）。 |
| `IArchiveEventSink` | 事件写入契约（`TryRecord(ArchiveEventInput)`）。 |
| `IArchiveQueryService` | 只读查询契约。 |
| `IArchiveProvider` / `IArchiveProviderRegistry` | 域提供方契约与注册表。内置四提供方（`BuiltinProduction/Battle/Relation/PlaceProvider`，priority 0）；**第三方可注册更高 priority 覆盖**。 |
| `DomainProviders/`（IRelation/IProduction/IPlace/IBattleProvider + `*Capabilities` 静态类） | 各域的提供方接口与能力枚举。 |
| `ArchiveEntityRef` / `ArchiveEventInput` / `CaptureResult` / `ApiVersion` | DTO 与版本协商（`api.Supports(major, minor)`）。 |

**集成示例（第三方 Mod）**：
```csharp
if (PersonalChronicleApi.TryGet(out var api) && api.Supports(4, 1))
{
    api.Events.TryRecord(new ArchiveEventInput { /* ... */ });
}
```

## 5. 数据流（端到端）

```text
[游戏事件]  ──Harmony──▶  Capture 补丁
                            │ 翻译成领域事件
                            ▼
                       Domain 聚合根（PawnObject/ThingObject/...）
                            │ 写入
                            ▼
                  Data: ChronicleGameComponent.ExposeData（存档持久化）
                            │ 查询/编排
                            ▼
                  Application: ArchiveUiDataProvider → Read Model 快照
                            │
                            ▼
                  Archive (UI): 只读快照渲染（主窗口 / ITab / 弹窗）

第三方 Mod ──▶ Api.IPersonalChronicleApi ──▶ (写入 IArchiveEventSink | 读取 IArchiveQueryService)
```

**契约边界**：Capture→Domain、Application→Domain、Api→Application 之间都以**接口/快照**解耦，UI 永不直接持有 Domain 对象。

## 6. Defs（XML 定义）

`Defs/` 下 12 个文件，均为数据驱动：

| 文件 | 定义 |
|---|---|
| `Chronicle_Events.xml` | `ChronicleEventDef` — 事件类型、文案翻译键、关联维度 |
| `ArchiveCategoryDefs.xml` | `ArchiveCategoryDef` — 四大分类（人物/物品/战役/地点） |
| `MainButtonDefs.xml` | `MainButtonDef` — 主界面「档案馆」按钮（引用 `ArchiveMainTabWindow`） |
| `WorkIntensity.xml` | 强度五档阈值（UI 零硬编码，改这里调档位） |
| `HealthValuation.xml` | 健康残值三维评分权重 |
| `MedalDefs.xml` / `QualificationDefs.xml` / `ProfessionalSkills.xml` | 授勋 / 资格 / 职业档案 |
| `RecipeDefs.xml` / `ThingDefs.xml` / `ThingArchivePolicy.xml` / `SocialRelationPolicy.xml` | 配方 / 物品 / 物品归档策略 / 社交关系策略 |

**新增一类事件的标准路径**：①`Chronicle_Events.xml` 加 `ChronicleEventDef`；②Capture 加对应 `[HarmonyPatch]`（public）；③Domain 加事件模型；④Application 快照接入；⑤翻译键补齐。

## 7. 翻译体系

- 目录：`Languages/ChineseSimplified/Keyed/`、`Languages/English/{Keyed,DefInjected}/`
- 命名约定：
  - UI 文本：`PersonalChronicle.UI.*`
  - 事件文本：`PersonalChronicle.Event.*`
  - Def 注入：`DefInjected/ArchiveCategoryDef`、`DefInjected/MainButtonDef`
- 所有玩家可见文本走翻译键，**不写死字符串**；缺失键优雅降级（不崩溃）。

## 8. 扩展点与二次开发

1. **新增采集事件**：见 §6「标准路径」。
2. **覆盖域提供方**：实现 `IArchiveProvider` 子接口，通过 `IArchiveProviderRegistry` 注册更高 priority。
3. **外部 Mod 写/读档案**：经 `PersonalChronicleApi.TryGet` 拿 `IPersonalChronicleApi`。
4. **UI 主题**：`UITheme.Apply(ThemeId)`；新增主题在 `ChronicleSettings` 注册。
5. **强度/评级调参**：改 `WorkIntensity.xml` 等 Def，无需改代码。
6. **ITab 注入**：`ChronicleInspectTabInjector` 已覆盖所有 humanlike 种族（含 modded），新增标签页 = 在组合根 `ChronicleMod` 的类型列表里加一项（顺序敏感：注入器逐类型 Insert(index 1)，实机按列表逆序铺开，故视觉顺序与传入顺序一致）；注入器不引用任何业务域，避免 Archive↔Economy 循环。

## 9. 已知技术边界（Known Boundaries）

| 项 | 说明 |
|---|---|
| LE-1 god class | `ArchiveMainTabWindow.cs` 较长，靠 partial 拆视图；新功能优先下沉到 Application/Read Model。 |
| LeftTick 离开字段 | 放逐 / 卖奴等离开路径 defer，暂未全覆盖。 |
| 热点路径采集 | 出生等热点暂不新增 Patch，靠 reconcile（读档补漏建档）兜底。 |
| 历史不追溯 | 启用前已发生的事件无法回溯（RimWorld 不保存历史事件流）；要全量请新开档。 |
| 发布区同步 | 见 §1 陷阱——编译产物必须手动进发布区。 |

---

## 10. 开源贡献指南

- **分层纪律**：新增代码放入正确层；UI 不得直接引用 Domain；跨层一律走接口/快照。
- **契约优先**：扩展点通过接口与 Def 暴露，避免硬编码到具体类。
- **Harmony 可访问性**：所有 `[HarmonyPatch]` 类必须 `public`（见 §4.1 铁规则）。
- **日志规范**：统一走 `ChronicleLog.[Category]`（前缀 `[PersonalChronicle][Category]`），不要散用 `Log.Warning`。
- **翻译**：任何玩家可见字符串加翻译键，中英双语。
- **提交前自检**：①编译 0 错 0 警；②手动同步 dll 到发布区；③游戏内验收（含 HugsLib 日志确认 patch 数符合预期）。
- **文档**：功能落地同步更新 `docs/` 与玩家 README。
