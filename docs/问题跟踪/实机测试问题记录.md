## 🟢 问题一 · 职业档案 ITab 底框过大溢出，导航 tab 被移出屏幕（已修复 v1.2.0）

| 项 | 内容 |
|---|---|
| 类型 | 前端 / UI 布局 |
| 模块 | `ITab_Pawn_Career`（职业档案人物档案页） |
| 状态 | 🟢 已修复 |
| 发现时间 | 2026-08-24 |
| 提交时间 | 2026-08-24 |
| 提交版本 | dll `D2CA6059`（v1.2.0） |
| 修改文件 | `Source/PersonalChronicle/Archive/ITab_Pawn_Career.cs`（构造器、`FillTab` 高度逻辑） |

**现象**：职业档案 ITab 底框过大溢出，内部被拉伸，顶部「总览/履历/勋章/资格」导航 tab 按钮被挤出屏幕外不可点。

**代码定位**：
- 构造器 `size = new Vector2(TabWidth, TabHeight)`，`TabWidth=640f / TabHeight=720f`（第 33-34、86 行）。
- `FillTab`（第 125-179 行）高度自适应：
  ```csharp
  float w = Mathf.Min(TabWidth, Verse.UI.screenWidth - 24f);
  float paneTopY = PaneTopY;
  float h = Mathf.Min(TabHeight, Mathf.Max(320f, paneTopY - 8f));
  if (Mathf.Abs(size.x - w) > 1f || Mathf.Abs(size.y - h) > 1f) size = new Vector2(w, h);
  ```
- `DrawSubTabs`（第 191-250 行）绘制 4 子页导航栏，位于 `outer.y` 顶部。
- `body` 区：`Rect body = new Rect(outer.x, y, outer.width, outer.yMax - y - UITheme.SpaceXs);`（第 171 行）。

**根因**：高度 `h = Min(720, Max(320, paneTopY - 8))` 仅做了「顶栏被遮」方向的约束，未做底边缘双向约束。当信息栏被其他 mod 撑高或 `PaneTopY` 在某些场景返回异常大值时，`size.y` 算大，面板从 `PaneTopY` 向上展开后底边缘仍超出屏幕底 → 底框溢出拉伸、导航栏被推/被遮。

**前后对比**：
| | 修复前 | 修复后 |
|---|---|---|
| 高度上限 | `Min(TabHeight, Max(320, paneTopY - 8))` 仅顶约束 | 双向约束 `Min(paneTopY - 8, screenHeight - bottomMargin)` |
| 导航 tab | 溢出屏幕外不可点 | 始终落在可视区内可点 |

**修复**：高度上限改用屏幕物理高度双向约束，避免底框溢出（见进度表验证项）。

**验证**：net48 编译 0 错；高度改双向约束（`screenHeight - paneTopY`）；dll `D2CA6059`；发布区 hash 一致。

| 提交版本 | dll `D2CA6059`（v1.2.0） |
| 修改文件 | `Source/PersonalChronicle/Application/ArchiveService.Career.cs`（`RecipeRelevance`）、`ReadModels/ArchiveUiDataProvider.Detail.cs`（`BuildQualRows`） |

**现象**：玩家实际制造约 20 个物品，但总览「资格状态」里「专业等级」一行悬停显示经验进度为 0（XP 没累积 / 或展示为 0）。

**代码定位**：
- 悬停文本：`ArchiveUiDataProvider.Detail.cs` 第 796-799 行 `BuildQualRows`：`xp = skillData.xp`（第 778 行），`level = skillData.level`（第 777 行），`practiceCount = skillData.practiceCount`（第 779 行）。
- `xp` 写入：`ArchiveService.Career.cs` `ApplyProfessionalProgress`（第 184-283 行）：
  ```csharp
  float relevance = RecipeRelevance(skillDef, recipe);
  if (relevance <= 0f) continue;   // ← 关键：不命中白名单则跳过，xp 不累加
  ...
  skillData.xp += xp;
  skillData.practiceCount++;
  ```
- 相关度判定 `RecipeRelevance`（第 309-333 行）：双白名单空→1.0；`practiceRecipeDefNames` 命中→1.0；`practiceWorkTypeDefNames` 命中 `requiredGiverWorkType`→0.5；否则→0（不获 XP）。

**根因**：`RecipeRelevance` 原有匹配口径过窄——仅认 `practiceRecipeDefNames`（配方白名单）与 `practiceWorkTypeDefNames`（WorkType），未覆盖玩家实际制造配方关联到的 `workSkill` / 配方 `sourceSkills`，导致大量制造 `relevance=0` → `xp` 恒 0、`practiceCount` 不增、`level` 维持 0。

**前后对比**：
| | 修复前 | 修复后 |
|---|---|---|
| 匹配口径 | 仅 recipe 名 + WorkType | 增 `workSkill` / `sourceSkills` 匹配回退 |
| XP 累加 | 白名单外制造 relevance=0，xp 恒 0 | 命中技能链路后正常累加 xp/practiceCount |
| 悬停展示 | 经验进度 0 | 显示真实累计 xp |

**修复**：`RecipeRelevance` 增加对配方 `workSkill` 与 `sourceSkills` 的匹配分支（口径与专业技能方向对齐）。

**验证**：编译 0 错 0 警；`RecipeRelevance` 增 `workSkill`/`sourceSkills` 匹配；dll `D2CA6059`；发布区 hash 一致。

## 🟢 问题七 · 三卡改名对话框按钮被裁切（已修复 2026-08-25）

| 项 | 内容 |
|---|---|
| 类型 | 前端 / 窗口尺寸计算 |
| 模块 | `Dialog_RenameWorkplace`（房间/工坊/类型三卡改名对话框共用） |
| 状态 | 🟢 已修复 |
| 发现时间 | 2026-08-25 |
| 提交时间 | 2026-08-25 |
| 提交版本 | dll `DBAA68…` |
| 修改文件 | `Source/PersonalChronicle/Archive/Dialog_RenameWorkplace.cs`（构造器 `winHeight` 计算） |

**现象**：点击三卡（房间/工坊/类型）弹出的改名对话框底部「确定/取消」按钮被窗口底边裁切，UI 组件错乱。

**代码定位**：`Dialog_RenameWorkplace.cs` 构造器 `winHeight` 用 `WinW = 420f`（窗口外宽）计算 hint 高度：
```csharp
float hintH = Mathf.Max(16f, Text.CalcHeight(this.hint, WinW) + 2f);
winHeight = TitleH + FieldH + 6f + hintH + 8f + ButtonH + 10f;
```
而 `DoWindowContents` 中 hint 实际绘制宽度 `inRect.width`（≈ `WinW - 2*PanelPadding`），更窄。

**根因**：构造器 hint 宽度（`WinW=420`）> 实际绘制宽度（扣内边距），hint 预估行数偏少 → 实际内容总高 > 预计算 `winHeight` → 底部按钮溢出窗口被裁切。

**前后对比**：
| | 修复前 | 修复后 |
|---|---|---|
| hint 计算宽度 | `WinW`（420，含内边距） | `WinW - 2*UITheme.PanelPadding`（与实际 `inRect` 一致） |
| 窗口高度 | 无安全余量 | 底部追加 `+16f` 余量 |
| 底部按钮 | 被裁切 | 完整显示 |

**修复**：hint 计算宽度对齐内边距 + 底部追加安全余量：
```csharp
float innerW = WinW - 2f * UITheme.PanelPadding;
float hintH = Mathf.Max(16f, Text.CalcHeight(this.hint, innerW) + 2f);
winHeight = TitleH + FieldH + 6f + hintH + 8f + ButtonH + 10f + 16f;
```

**验证**：编译 0 错 0 警；dll `2822A4…`→`DBAA68…`；发布区同步 hash 一致。重启游戏验收：对话框完整显示标题+输入框+提示+按钮。

**现象（用户实机反馈 + 截图）**：ITab 工坊卡已显示自定义房间名「中央厨房」（mod 自定义名生效），但 RimWorld 原版房间信息面板（右键房间→信息）仍显示「厨房」。

**初步诊断 —— 先排除"是不是 bug"**：
- `SetRoomName(pawnId, role, name)` 写入的是 mod 自己的 `RoomNameOverrides[pawnId:role]` 字典（per-pawn+roomType 粒度），**只影响 mod UI 展示**（ITab 卡片、工坊弹窗）。
- RimWorld 原版房间名来自 `Room.Role.LabelCap`（游戏世界状态），mod 档案层是只读记录，**不应反向改游戏世界**。
- 因此"原版面板不变"本身**是预期行为**，不是数据层 bug。

**进一步追查 —— 方案 B 其实已实现过**：
- `Patch_RoomRoleLabel`（Harmony Postfix on `Room.GetRoomRoleLabel`）本就拦截原版房间名，按 `pawnId:role` 查 `RoomNameOverrides` 覆盖 → 即"让原版 UI 也显示 mod 自定义名"的方案 B 早已落地。
- 那为何截图仍显示「厨房」？**根因**：该 patch 只从 `Room.Owners` 取 `pawnId`（卧室/囚室有 owner），而**工坊类房间（厨房/工坊/温室）无 `Owners`** → `pawnId` 为 null → 跳过 `RoomNameOverrides` 查询分支 → 原版名不被覆盖。
- 对比：ITab 工坊卡走的是 `GetRoomName(pawnId, role)` 直接查字典（不依赖 `Room.Owners`）→ 所以 mod 侧生效、原版侧不生效，形成"半生效"假象。

**首次修复（已废弃）**：当 `Room.Owners` 为空时 fallback 到 `Find.Selector.SingleSelectedThing as Pawn`。
- **原生 API 诊断（反射探针，加载 Assembly-CSharp v1.6.9676）证实失败根因**：
  - `Room.GetRoomRoleLabel()` 确为**无参数实例方法**——方法签名内拿不到 pawn 上下文。

- 当 `pawnId` 为空（工坊无 owner）时，遍历 `RoomNameOverrides`，命中 key 以 `:role.defName` 结尾的首个非空值 → 即"任意给该类型房间起过名的殖民者的昵称"。

**需求（用户 2026-08-27）**：游戏环境有上百个 mod，自定义字段面板应**启动一次扫描全部 mod 自动注册**，按 mod 来源分类、可钻取细分；增删 mod 后下次启动自动更新。同时保留第三方 mod 主动 `RegisterExternal` 的通道。

**方案要点**：
1. **扫描范围**：仅 `StatDef` + `NeedDef` 可零代码泛化扫描（两者有统一取值接口 `pawn.GetStatValue(statDef)` / `pawn.needs.TryGetNeed(needDef).CurLevelPercentage`）。第三方自定义能力系统（非 Stat/Need，如 Combat Extended 的 burstShotCount）无统一接口，仍走 `RegisterExternal` 主动注册——两者并存。
2. **Label 策略**：自动注册字段的 Label 直接用 `Def.LabelCap`（游戏当前语言，无中文翻译键），符合用户选择「用 StatDef.label 原语言」。
3. **来源分组**：`sourceId = statDef.modContentPack.PackageId`；核心包（Ludeon.RimWorld* / rimworld）归 `SourceVanilla`；对话框按 `SourceOrder` 分组、可钻取（既有 `Dialog_OverviewFields` 二级钻取 UI 复用）。
4. **排重**：`KnownVanillaStatDefs` 集合跳过本 mod 已硬编码的 vanilla 字段对应的 StatDef defName，避免重复列出。
5. **启动期刷新（天然支持增删 mod）**：`All` 为静态列表，每次游戏启动由 `ChronicleStartup` 静态构造器（DefDatabase 已填充）调用 `ScanExternal()` 重新构建——**无需持久化缓存或 hash 检测**，增删 mod 后下次启动自动反映。

**代码变更**：
- `OverviewFieldRegistry`：
  - 新增 `KnownVanillaStatDefs`（硬编码 vanilla StatDef defName 排重集）
  - 新增 `ScanExternal()` → `ScanStatDefs()`（遍历 `DefDatabase<StatDef>.AllDefs`，key=`stat:<defName>`，getter=`p.GetStatValue(statDef)`，BarMax=0 不画比例条）+ `ScanNeedDefs()`（遍历 `DefDatabase<NeedDef>.AllDefs`，key=`need:<defName>`，getter=`TryGetNeed(needDef).CurLevelPercentage`，Unit=`%`，BarMax=1）
  - 新增 `ResolveSourceId(ModContentPack)`：核心包→`SourceVanilla`，否则→`PackageId`
