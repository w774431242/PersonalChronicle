## FIX-001 · 健康残值估值因子乱码

| 项 | 内容 |
|---|---|
| 状态 | closed（2026-08-31 落地） |
| 发现 | 2026-08-31 实机截图 |
| 类型 | 本地化降级失败（与已修的问题十七同类，健康残值专链） |
| 界面 | 档案馆主窗口 → 人物详情 → 总览 →「健康残值 · 资产折旧」事件行 |
| 复现 | DevMode 开启；殖民者有原版 Hediff `Malnutrition`（开局挨饿即可）；打开该人物总览 |

**实机原文**

```text
估值因子（正/负）：
未知 PèrsònàlChrònìçlè.UI.HèàlthVàlùàtìòn.Evènt.Màlnùtrìtìòn -25银 [永久旧伤]
```

该行四段：`未知`（无 onset tick）+ 变音伪翻译键 + `-25银` + `[永久旧伤]`。标题 / 三维条 / 残值结论等已有 Keyed 的文案正常。

**涉及文件**

- `Source/PersonalChronicle/Domain/HealthValuation.cs`（`EmitHediffEvent`）
- `Source/PersonalChronicle/Domain/HealthValuationKeys.cs`（`EventPrefix`）
- `Source/PersonalChronicle/Application/ReadModels/ArchiveUiDataProvider.LifeHealth.cs`（`ResolveEventDescription`）
- `Source/PersonalChronicle/Archive/ArchiveMainTabWindow.HealthValuation.cs`（行拼接）
- `Languages/ChineseSimplified/Keyed/Archive.xml`、`Languages/English/Keyed/Archive.xml`（仅 6 个 `Event.*` 白名单）

**根因**

```text
pawn 有 Hediff Malnutrition
  → EmitHediffEvent 拼键 Event.{defName}（Keyed 未收录）
  → Translate() 缺译；DevMode 下对拉丁字母变音（a→à e→è i→ì o→ò u→ù c→ç）
  → ResolveEventDescription 用「译文 ≠ 原键」判成功，跳过 HediffDef.label
  → 上屏 = 「未知」+ 伪翻译键 + 「-25银 [永久旧伤]」
```

细节：

1. 键按全部 `isBad` Hediff 动态拼接。原版 + 第三方数量开放，不可能为每个 defName 预写 Keyed。现有白名单只有 Scratch / Bite / BadBack / Frail / Cataract / HearingLoss，没有 Malnutrition。
2. `ResolveEventDescription` 假设缺键时 `Translate()` 原样返回 key。同仓库其它处已用 `key.CanTranslate()`（`OverviewFieldRegistry.TryTranslate`、`StatBreakdown`、`ProfessionalBonusView`），本函数仍用字符串相等，伪翻译下假阳性。
3. `RawTick` 写死 `-1L`（1.6 无稳定 onset tick）→ 每行前缀「未知」。
4. `Malnutrition.tendable == false`（靠进食恢复）被打成永久旧伤 −25 银，语义错误。

正确展示应是原版 `HediffDef.LabelCap`（简中 Core：「营养不良」）。

**修复方向（落地时按此做，现在不动代码）**

1. 降级与 `OverviewFieldRegistry.TryTranslate` 对齐：`CanTranslate()` 为真才用 Keyed；否则 `HediffDef.LabelCap`；再不行 `SanitizeDefNameForDisplay`。禁止用「译文是否等于原键」。
2. 不要为全量 Hediff 补 Keyed。`Event.{defName}` 只作可选覆盖，默认走原版 Def 标签。
3. 无 onset tick 时不输出「未知」前缀。
4. 饥饿 / 成瘾等瞬时 Hediff 不进「永久旧伤」；按 chronic / tendable / 是否可消退分档，或排除出事件流。
5. 回归：DevMode + 挨饿殖民者，该行必须是当前语言的 LabelCap，不得出现 `PersonalChronicle.UI.HealthValuation.Event.*` 或变音拉丁串。

**预期对比**

| | 现状 | 修复后 |
|---|---|---|
| 无 Keyed 的 `Event.Malnutrition` | 变音伪翻译键 | `HediffDef.LabelCap`「营养不良」 |
| 降级检测 | `translated != labelKey` | `CanTranslate()` |
| 日期 | 每行「未知」 | 无 tick 则省略日期 |
| 饥饿 Hediff | `[永久旧伤] -25银` | 不进永久旧伤 / 不进事件流 |

**关闭条件**：按上面 1～4 落地；DevMode 截图验收通过后，将本条移入「已关闭」。

## FIX-002 · 社会关系网络连线几何错误

| 项 | 内容 |

| 界面 | 档案馆 → 人物详情 → 社会关系 →「关系网络」 |

| 样式预览 | [`UI预览/社会关系网络连线方案.md`](../UI预览/社会关系网络连线方案.md)（方案 A/B/C/D，落地时按字母换） |

**现象（截图）**

- 母亲「好汇恬」与本人之间出现金色双向箭头，不像一条竖线。
- 朋友「卜救源」「和心黎」的线在母亲卡片旁拐出菱角，看起来像接到母亲而不是接到本人。
- 丈夫「叶日艇」横线相对能看，但仍从卡心穿出。

**涉及文件**

- `Archive/ArchivePanelBase.cs`（`DrawOrthogonalLink` 五段 Z）
- `Archive/ArchiveMainTabWindow.PawnSocial.cs`（画线时机：中心点，先线后卡）
- `Archive/ArchiveMainTabWindow.Shell.cs`（转发 zoom）
- `Archive/ArchiveMainTabWindow.PawnDetail.cs`（`GridSlotsFor` 家谱槽位，布局本身可用）

**根因**

`DrawOrthogonalLink` 在两卡**中心**之间画 Z：

```text
竖(我.x) → 45°切角 → 横(midY) → 45°切角 → 竖(对方.x)
radius = 10 * zoom
```

| 相对位置 | 几何后果 | 截图对应 |
|---|---|---|
| 同列（母 0,-1，sx=0） | 横段长度 0；两段切角在同一竖线上折返 | 好汇恬↔尹陟菁 缝里金色箭头 |
| 同排（夫 -1,0，sy=0） | 竖段退化，线从中心出发 | 叶日艇横线穿卡 |
| 对角（友 -1,-2） | midY 落在母亲那一行；竖段走本人 X | 卜救源的线像接到好汇恬 |

`Widgets.DrawLine` 的 45° 短边在 2.5px 金线上就是菱角/箭头。布局网格没有错，是连线算法在轴对齐与「中间还有人」时没有塌缩、没有走间隙。

**修复方向（落地时按预览文档勾方案，现在不动代码）**

1. 端点改为卡片**边中点**，禁止从中心出发。
2. `sx==0` / `sy==0` 只画一条直线，禁止切角。
3. 对角走间隙中线，不要用两中心的 midY（会穿中间卡）。
4. 废弃五段 Z 切角。默认采用预览 **方案 B（正交 L）**；用枚举切换 A 直连 / C 家谱 / D 无连线。
5. 线色按 `SocialRelationTier` 走 `UITheme`，先线后卡。

**关闭条件**：同屏父母+配偶+外圈朋友时，母子为干净竖线、夫妻为干净横线、朋友不经过母亲卡；方案字母可一处切换。

## FIX-004 · 考试书籍「不像书」：无法选取 / 无法存储 / 无法阅读

| 项 | 内容 |
|---|---|
| 状态 | closed（2026-09-01 落地，发现即修） |
| 发现 | 2026-09-01 订阅者反馈 |
| 类型 | Def 契约缺失（`thingClass` / `thingCategories` / `comps`）→ 功能静默失效 |
| 涉及文件 | `Defs/ThingDefs.xml`、`Application/ArchiveService.Qualification.cs`（`QualityOf`） |
| 影响面 | 52 个考试书籍（`PC_Exam_Textbook / SkillBook / TheoryBook / ResearchDoc` 及 12 方向变体） |

**现象（订阅者原话要点）**

书无法选取、不会加入书架无法存储、小人右键点击无法阅读。

**根因（决定性取证）**

```text
书架 BookcaseBase（Core/Buildings_Furniture.xml）
  fixedStorageSettings.filter.categories = <Inherit="False"><li>Books</li></li>
  → Inherit="False" 是玩家不可编辑的硬约束
  → mod 书籍无 thingCategories=Books ⇒ 永远进不了书架（手动改不了）

mod 52 个考试书籍 ThingDef
  thingClass = Thing         → 最底层基类，无任何 Comp 插槽
  无 <thingCategories>       → 存储过滤器中不可见
  无 <comps>                 → 无 CompQuality、无 CompProperties_Book
  ⇒ 命名/图标是书，底层零对接原版书本系统
```

连带的代码层缺陷：
`ArchiveService.Qualification.cs` 的 `QualityOf()` 调 `thing.TryGetComp<CompQuality>()`，
而 `Thing` 类无 Comp 插槽 ⇒ **恒返回 null ⇒ 所有书按 Normal 计**，
论文引用「按品质排序取最好的 2 本并加权」的设计**永久失效**（不报错，只是不生效）。

**关键技术取证（反射 Assembly-CSharp，未靠猜测）**

- `Book : Verse.ThingWithComps`（public）；`CompProperties_Book : CompProperties_Readable`，**`doers` 字段在基类**。
- `BookOutcomeProperties_GainSkillExp.skills : List<SkillDef>` —— 可精确指定阅读给哪个技能。
- **comps 继承是「追加」不是「覆盖」**：`XmlInheritance.allowDuplicateNodesFieldNames` 虽不含 `comps`，
  但递归进 comps 后每个 `<li>` 是 list element 会被追加 ⇒ 子 Def 只写自己的 `CompProperties_Book`，
  父 Def 的 `CompQuality` / `Forbiddable` 自动保留（反证：原版 `TextBook` 只写 `CompProperties_Book` 却仍有品质）。
- 可复用原版 RulePack：`Namer_TextBook` / `Description_SkillBook` / `Namer_Schematic` / `Description_Schematic` / `Namer_Novel` / `Description_Novel`；
  纹理可复用 `Things/Item/Book/{Textbook,Schematic,Novel}/...` 的 `_Open` / `_Vertical` 变体。

**修复（纯 XML，C# 零改动）**

1. 新增抽象父 Def **`PC_ExamBookBase`**（对齐原版 `BookBase`）：`thingClass=Book`、
   `CompProperties_Forbiddable` + `CompQuality`、`thingCategories:Books`、`inspectorTabs:ITab_Book`、`stackLimit=1`、`MaxHitPoints=60`。
   - 刻意**省略** `thingSetMakerTags` —— 否则考试书籍会泄漏进原版战利品 / 奖励池。
   - 刻意**不设** `DeteriorationRate`（=0）—— 避免书籍腐朽导致论文流程卡死。
2. 52 个书籍 Def 改挂 `ParentName="PC_ExamBookBase"`，各自只追加 `CompProperties_Book`
   （按类型复用原版 RulePack 与 `_Open` / `_Vertical` 图形），`doers` 用 `BookOutcomeProperties_GainSkillExp` + 方向→技能映射：
   Engineering / Manufacturing / Weapons → Crafting，Agriculture / Forestry → Plants，AnimalHusbandry → Animals，
   Medicine → Medicine，Mining → Mining，Research → Intellectual，Cooking → Cooking，Art → Artistic，Management → Social；
   通用版 Textbook / SkillBook → Crafting，TheoryBook / ResearchDoc → Intellectual。
3. **C# 零改动即修复品质失效**：`Book` 是 `ThingWithComps`，`TryGetComp<CompQuality>()` 自动读到品质。
4. 附带设计增值：阅读 → 原版技能经验 → 经既有 `Patch_SkillRecord_Learn` 分流职业 XP，读书真正接入职业成长闭环。

| 类型 | Def 契约缺失（无 `CompQuality`）→ 与 FIX-004 同根因 |
| 涉及文件 | `Defs/ThingDefs.xml`、`Capture/Patch_GenRecipe.cs`、`Application/ArchiveService.Qualification.cs`、`Domain/Qualification/ExamScoring.cs` |

**现象（静态推断，待实机确认）**

`PC_Exam_PracticeKit` 及其 12 个方向变体（共 13 项）`thingClass=Thing` ⇒ 无 `CompQuality`。
其 Def 描述自称「**实践考试专属固定道具**……供考官核验制造水平」，但实践考试的及格线正是**品质硬门槛**：

```text
ApplyForPracticalExam: MinQuality = "Excellent"、RequiredCount = 3、TargetRecipeDefNames = 空(接受任何制造)

玩家按设计意图制造 PracticeKit：
  Patch_GenRecipe: product.TryGetQuality(out qc) → 无 CompQuality ⇒ false ⇒ quality = null
  RecordExamProduced: ProducedCount++，但 quality 为 null ⇒ 不进 ProducedQualities
  ⇒ CountAtLeast([], "Excellent") = 0，永远 < RequiredCount(3)
  ⇒ 制造到 MaxProduced(=2×3=6) 后 Passed=false / Finished=true ⇒ 考试必失败
  ⇒ ScorePractical 在 producedQualities 为空时直接 return 0f ⇒ 0 分

即：越是按道具语义去造 PracticeKit，越必然 0 分失败，且无任何提示。
```

**修复方向（待 PM 决策，未动代码）**

1. 给 13 个 PracticeKit 改 `thingClass=ThingWithComps` 并补 `CompQuality`，使其制造可产出品质档位。
2. 或反过来：若设计上实践考试应考「原版物品制造水平」，则应在 UI / 描述中明确告知不要造 PracticeKit，
   并把 `TargetRecipeDefNames` 从空改为明确白名单，避免玩家被道具描述误导。
3. 建议 `RecordExamProduced` 在「已产出但品质始终为空」时给出明确提示（当前是静默走到 MaxProduced 才失败）。

**关闭条件**：制造 PracticeKit 可产出 Excellent 及以上；或 UI 明确引导 + 白名单生效，玩家不再被误导。

### 1. Baal 系列 Mod（BAL_ 前缀）→ 派系生成 NullReferenceException

| 项 | 内容 |
|---|---|
| **状态** | ✅ 已确认（用户实机复现 + 日志证据） |
| **触发条件** | 世界生成（开局随机生成派系）时 |
| **现象** | `Error in WorldGenStep: System.NullReferenceException`；游戏开局地点文字错乱、派系生成失败 |
| **根因** | Baal 系列 Mod 的 `FactionDef.memeWeight` 引用了未定义 / 加载失败的 MemeDef（`BAL_Structure_*`、`BAL_Meme_*` 等）→ `MemeWeight.meme = null` → `IdeoUtility.GenerateRandomMemes` → `IsMemeAllowedFor(null, ...)` NRE |
| **日志证据** | Player.log：`Could not resolve cross-reference to RimWorld.MemeDef named BAL_Structure_ThirdFireMaterialism` / `No RimWorld.MemeDef named BAL_Meme_SocialistStatePower found`（BAL_ 前缀批量出现） |
| **影响范围** | 仅第三方 Mod 之间；**与 PersonalChronicle 无关**（本 Mod 无 FactionDef / MemeDef） |
| **解决方案** | ① 禁用 Baal 系列 Ideology 内容 Mod（首选 `Baal.CultureAndFaith`）；② 或更新 / 修复 Baal Mod 缺失的 MemeDef 定义 |

### 排查方法论备忘

- **先查日志 def 加载错误**：`Could not resolve cross-reference ... (wanter=xxx)` 是定位 XML 引用缺失的最直接证据
- **二分禁用**：先禁用整系列（如 Vanilla Expanded 全家桶），确认排除后再逐个加回
- **注意运行期堆栈 vs 加载期错误**：NRE 堆栈只显示触发点（原版 `IdeoUtility`），真正的根因在 Def 加载期（第三方 Mod 引用了不存在的 def）
