# 车间岗位与作息衔接修复（0.1）

## 修复内容

- 生产岗位优先寻找本人排班车间的可执行设备工单，复用原版 WorkGiver_DoBill / JobDriver_DoBill，覆盖原版与 T1 智能设备。
- 继续遵守工单暂停、目标库存、人员与技能限制、材料、供电、可达性和设备预约；不生成假工单、不实现无人生产。
- 无可执行工单时等待 300 tick 后结束任务，交回原版工作链重查。待命位置逐人检查预约和可达性，避开设备操作格；没有安全站位时交回原版。
- 操作员工取消旧的岗位落地豁免。在上班和餐后返岗时启用映射工作并落地岗位，不需要每日打开管理面板。
- 手动岗位优先于自动岗位，岗位页与运行时共享候选名单及分配器；技术员工按维护映射执行原版任务，其他非生产员工不被待命任务抢占。
- 工作必须同时满足有效排班与当前管制作息；PC_Meal、Sleep、Joy、Meditate、PC_Idle 禁止重新接入车间岗位。在编员工的餐段/休息时段还阻止普通科研、搬运、清洁等工作绕过守卫；进食、患者身份、紧急治疗与灭火保留。
- 自动车间任务在边界最多 60 tick 内收尾。最小连续值勤时长不再延迟饭点或下班；夜班使用地图本地时间与统一跨日排班口径。
- 用餐仍由现有用餐工作与原版 Ingest 驱动，吃饱不强塞食物、缺食时保留退避；不会中断正在进食、睡眠、玩家强制任务、征召或紧急医疗/灭火等服务。
- 真实原版岗位任务在开始/结束时登记考勤，地图轮询作读档自愈；重复登记不重置起点。短工单也能登记。待命只计 PC_WorkshopStandby，不伪装成生产工时。
- 未交付独立替代服务，因此 implementedWorkTypeDefNames 保持空、deliversOwnService 保持 false，避免接管禁用原版服务。

## 实机验收步骤

1. 重启游戏载入部署后的 DLL。准备至少两个生产员工与多台有有效工单的 T1 设备；检查实际取料、加工和产出。
2. 缺料时确认显示“在车间待命，等待可执行岗位任务”；补料或释放设备后，待命结束可重新取工单。
3. 饭点前开始长工单；进入管制作息“用餐”后，最多 60 tick 内停止自动车间任务，未吃饱且有可达食物时执行进食；吃饭本身不中断。
4. 餐后仍在班次内，返回岗位；进入睡眠/娱乐/摸鱼时不被叫回车间。下班后不再接该班的自动车间任务。
5. 检查 20→08 夜班跨午夜、午夜饭点及 08:00 收工；检查固定班、班组和轮岗。
6. 检查技术、物料、科研等岗位原版任务；手动强制工作、征召、救火及治疗仍可执行。
