**与计划的偏差（3 处，均已核实）**：

1. **层数：8 → 11（全部）**。v2 初稿把柱网/管廊/通道/支持功能区当"装饰"要砍；实测确认它们就是"车间俯视框架"本体，且不与真实数据冲突（框架固定、数据填格），故全部落地。
2. **缩放：clamp [0.70,1.25] → 双轴 contain + 用户缩放**。用户要"1:1 还原框架"，而浏览器就是 `width:100%` 等比铺满；加 clamp 会让宽屏下画布缩水、反而不像。实机反馈「缺少缩放功能」后改为：视口高另外受可见区 85% 约束（**100% = 整图可见**），并在其上叠加用户缩放（滚轮/工具条，0.6–3.0）+ 拖拽平移。
3. **进度口径**：`Bill` 无完成度（已核实）→ 用 `JobDriver_DoBill.workLeft / RecipeDef.WorkAmountTotal(null)`，**标「近似」并写进 tooltip**；原版没有的"缺料"态不画（图例只列真实 4 态）。

## 4. 坐标与缩放（**v2 新增：真实地图坐标，不用预览的 rx/ry**）

预览里的 `rx/ry` 是**手写样例布局**；游戏内必须用**真实地图坐标**，否则"画出来的位置和玩家基地不符"（v1 §11 已列为风险，v2 直接改掉）。

**M1 投影规则**

```
取车间 zone → 包围盒 bound = (minX,minZ)-(maxX,maxZ)（含 1 格外边距）
地图格 → 设计坐标：  dx = (cell.x - bound.minX) / max(1, bound.w) * 960
                    dy = (cell.z - bound.minZ) / max(1, bound.h) * 545      ← 注意 z 轴向下，与画布一致，无需翻转
设备 = 落在 zone.cells 内（或 `WorkshopZoneUtility.WorkshopAt(thing.Position, map)` 命中的）IBillGiver 建筑
机箱矩形 = 以设备中心格为中心、按 MW×MH（设计单位）向四周展开（保持预览的 140×76 观感）
人员 = Members 中当前在地图上者，取其真实 Position 投影；不在岗者画在设备旁固定偏移位
```

**缩放（LAND-005/006）**：可用宽 `W_g = 窗口宽 − 42`（本窗口无侧栏），可用高 `H_g = 窗口高 − 133`（页头 56 + 间隙 12 + 内边距 24 + 标题条 33 + hazard 8）。

| 档 | 条件 | 行为 |
|---|---|---|
| Tier-W | `W_g / H_g ≥ 1.9231` | 按高适配：`canvasH = H_g`，`canvasW = H_g × 1.9231`，水平居中 |
| Tier-H | 否则 | 按宽适配：`canvasW = W_g`，`canvasH = W_g / 1.9231` |

**实现：双轴 contain + 用户缩放（实测修正）**
- 视口高 = `min(宽 / 1.9231, 可见内容区 × 85%)`；基准缩放 `fit = min(viewportW / 1500, viewportH / 780)` ⇒ **100% 永远 = 整图装进视口**（首屏就能看全框架，不会一开就被裁）。
- 用户缩放是在 fit 之上再乘系数：`k = fit × zoom`，`zoom ∈ [0.6, 3.0]`。
- 交互：**滚轮以鼠标为锚点缩放**（±10%/格）；**放大后左键/中键拖拽平移**（平移量按"内容超出视口的部分"夹取）；工具条 `- / % / + / 重置`。
- 视图态是窗口瞬时字段（`FloorPlanViewState`），不入存档（GATE-UI）。
- 可读性靠**文字档位**兜底（机名用 `Tiny` 而非 `Small`，见 §1 字号行）；`k < 0.8` 不画锚栓、`k < 0.6` 不画工人圆点；所有文本走 `TruncateToWidth` + 悬停 tooltip（LAND-008）。

**实测两例**（按 UI 缩放：`1920×1080 @1.0` → 内容 1878 宽、视口高 775；`@1.75` → 内容 1055 宽、视口高 447）：

| 环境 | W_g | 视口高 | fit | 100% 时 k | 备注 |
|---|---|---|---|---|---|
| 1920×1080 @UI缩放1.0 | 1878 | 775 | `min(1.25, 0.99)` = 0.99 | 0.99 | 上下留白，整图可见 |
| 1920×1080 @1.75（当前） | 1055 | 447 | `min(0.70, 0.57)` = 0.57 | 0.57 | 整图可见；想看机箱文字用 `+` 放大 |

## 6. 状态机

```csharp
// Domain/Manufacturing/EquipmentStateResolver.cs —— 纯函数，可离线单测
public enum EquipmentState { Run, Idle, Fault, Off, Starved }   // 5 态，键用 name（语言无关）

public static EquipmentState Resolve(bool brokenDown, bool powerOn, bool hasBill)
{
    if (brokenDown) return EquipmentState.Fault;
    if (!powerOn)   return EquipmentState.Off;
    return hasBill ? EquipmentState.Run : EquipmentState.Idle;
}
```

| 态 | 判定 | 期 | 颜色（令牌） |
|---|---|---|---|
| Fault | `CompBreakdownable.BrokenDown` | ★ | `UITheme.Dead` |
| Off | `!CompPowerTrader.PowerOn`（无 comp 视为通电） | ★ | `UITheme.Dim` |
| Run | 有 `AnyShouldDoNow` 的工单 | ★ | `UITheme.Alive` |
| Idle | 通电但无工单 | ★ | `UITheme.Info` |
| **Starved** | **原版无出口** → 显示「未接入」 | ☆ M2 | `UITheme.Warn`（图例标注未接入） |

**M1 图例只列 4 态 + 1 条「缺料（未接入）」的灰项** —— 缺口如实（LAND-009），不画一个永远不亮的灯。

| 悬停 | `TooltipHandler.TipRegion` 内容 = 设备名 / tier / 功率 / 状态 / 工单 / 操作员 / 近似进度 | **必须**走 `Mouse.IsOver` 输入门禁，禁裸判 `rect.Contains` |

| 缩放/平移 | **M1 不做**（自适应已保证可读；加了反而与窗口滚动视口冲突） | M2 若做：滚轮 0.6–2.0 + 中键平移 |

## 8. 性能

| 手段 | 做法 |
|---|---|
| 静态层烘焙 | L0/L0b/L1/L11 合成 1–3 张 `Texture2D`，key = `车间 zone id + bound 哈希`；只在换车间/zone 变形时重建 |

| 布局计划缓存 | 画布尺寸/缩放/机箱矩形一次算好存列表，绘制路径零 `new`、零 LINQ（同 ① 的 `EnsureKpiRowPlan` 范式） |

## 12. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 车间 zone 过大（跨半张地图） | 缩放系数 < 0.7，文字挤成一团 | k < 0.7 自动降级为「灯 + 2 字缩略名 + tooltip」；或在 M2 引入"逻辑分区" |
| 车间 zone 未划 | 无空间单元 | 空态：提示「未划车间区」，并给出「用全部工台包围盒兜底」的降级视图 |
| 近似进度引起误读 | 玩家以为卡住了 | LED 旁标 `≈`，tooltip 写明「近似：分子取当前 workersLeft，分母为额定工时」 |
| `workLeft` 受技能修正 | 进度长期不到 100% | 分母改用 `recipe.WorkAmountTotal(stuff)` 的上限估计，并在 clamp 到 [0,1] |
| Zone_Workshop 与预览的"逻辑分区"语义不同 | 视觉与预期不符 | M1 明确只画真实 zone；M2 再引入 ZoneDef 逻辑分区（那时才需要 Def） |
| 大车间设备多（>60） | 帧率 | §8 上限降级 |

## 13. 一句话总结

**M1 只做「把原版已有对象换个视角画出来」**：以既有 `Zone_Workshop` 为空间单元、以真实地图坐标投影、以 4 态派生驱动 LED，用 8 个图层（不是 12 个）在制造中心详情页的 ① 下方复刻 `SECTOR C-3` 的**可读性**；`ZoneDef`/岗位/带宽/缺料这些**要动存档的东西全部推到 M2**——先让玩家看见，再让它变成机制。
